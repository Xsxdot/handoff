## 首轮发现：无入站防火墙的 Linux NAT 会因 conntrack 冲突打不通（如实记录）

首轮拓扑未加 INPUT 防火墙：双方都收集到 srflx，但 ICE 10 s 后 Failed，A 打 INFO
`p2p 打洞失败，继续走 relay`（reason=ice_failed），业务经 relay 正常——**降级行为正确**。nat-a wan0 抓包：A 的 STUN 映射是
`198.51.100.11:55000`，但 A 发往 B 的检查却从 `.11:38855` / `.11:40691` 发出；B 的首个检查 `.12:44623 > .11:55000` 先于 A 的
任何出站到达 nat-a。根因：INPUT 为 ACCEPT 时，这条未经请求的入站在 netfilter 里被**确认**成 conntrack 条目，占住了
`(.12:44623 ↔ .11:55000)` 元组，A 随后的出站映射与之冲突，MASQUERADE 被迫换端口（同时到达时退化成端点相关映射）。
家用路由器的 WAN 入站缺省丢弃（filter INPUT DROP 发生在 conntrack 确认之前），未经请求的入站不会留下条目——
加上该规则后同一拓扑 602 ms 打通。改进方向（双方同步起跳，DCUtR 式 RTT/2 对齐）落 roadmap。
