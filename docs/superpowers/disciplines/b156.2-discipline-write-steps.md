# charter-implement 纪律块新版本写入步骤（B156.2.9 / 欠账 #10 运行期半边）

> **本步骤归协调者本人执行，不派发给任何 executor。**地点：协调机（权威账本在本机
> `~/.handoff`）。时机：B156.2.9 分支合入 feature/b156-workbench 之后、下一次派发
> implement 节点之前。这是对在跑系统的配置变更，动手前向用户报备一句（理由：代码与
> 数据分开回滚，岔口七方案 A）。
> 命令行为依据（源码出处，非记忆）：`cmd/discipline.go:65` get 打印 `<name> v<N>`
> 首行；`:79` put 读文件全文为正文；`:88/:92` PutDiscipline 返回
> `{"name":"...","version":N}`。`internal/ledger/disciplines.go:43-67` 版本=当前
> 最大+1、只插不改；`:20` 正文上限 64KiB；`:1-5` 派发自动取最新版并记进
> DispatchSnapshot。以上 CLI 行为本卡未真机实跑（执行器禁用 handoff CLI），以第 5 步
> cmp 回读兜底真伪。

## 步骤

1. 取当前正文并记版本：
       handoff discipline get charter-implement > /tmp/ci-current.txt
   `head -1` 应为 `charter-implement v<N>`，记下 N；剥离首行得纯正文：
       tail -n +2 /tmp/ci-current.txt > /tmp/ci-body.md

2. 合入两个片段（正文从仓内种子文件逐字复制，不得改写）：
   片段 A 追加到含「收尾纪律」条目的末尾；片段 B 追加到含「边干边落台账」的红线条目
   末尾。结果存 /tmp/ci-new.md。**任一锚点找不到（正文漂移）就停**：把
   `head -20 /tmp/ci-body.md` 贴给协调者裁决换锚，禁止即兴近似。

3. 机械校验（四条全过才准 put）：
       diff /tmp/ci-body.md /tmp/ci-new.md                          # 只许两处新增块，零删除零改写
       grep -c "执行中偏差如实记入 ledger 收尾段" /tmp/ci-new.md     # 期望 ≥1
       grep -c "两层各管各的，互不替代" /tmp/ci-new.md               # 期望 ≥1
       wc -c /tmp/ci-new.md                                         # 必须 < 65536（64KiB 上限）

4. 写入新版本（不可变版本化，旧版永不改写）：
       handoff discipline put charter-implement /tmp/ci-new.md
   记下返回 JSON 里的版本号（应为 N+1）。

5. 回读比对（roundtrip 逐字节，b229 integrate 同款）：
       handoff discipline get charter-implement | tail -n +2 | cmp - /tmp/ci-new.md && echo BYTE_IDENTICAL
   且首行版本为 v(N+1)。不一致即停，排查后再试。

6. 生效确认：无需重启——下一次 implement 节点派发自动取最新版并把版本号写进
   DispatchSnapshot（disciplines.go:1-5）；派发事件里 discipline_version 应为 N+1。

7. 回滚：真正的回滚是把旧正文再 put 一遍（cp /tmp/ci-body.md 为草稿后走同一校验
   流程），产生 v(N+2) 内容=旧文；应急单次派发可用 `--discipline-override <角色名>`
   临时换块（语义是换名字不是回版本）。旧版本行永远在库可审计。

8. 向用户报备一句话模板：「B156.2.9 的纪律文本已写入运行期：charter-implement
   v(N+1)（新增收尾偏差上报义务与台账边界澄清），代码在 feature/b156-workbench，
   数据变更可单独回滚。」
