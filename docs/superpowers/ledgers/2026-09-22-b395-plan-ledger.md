### 3.3 根因闭合

1. 触发：SSE 单行 >1MB（`bufio.Scanner: token too long`，`api.go:857-858`）→ 反复断连重连。
2. 丢失：`/event` 无重放语义（`adapter.go:1111-1117`）。断连间隙 opencode 侧产生的 `permission.asked`（对应 `call_00_OZ79...`）**永久丢失**，adapter 从未收到。
3. 无恢复：claude/codex/grok/opencode 四家都**没有**「重连后重新发现挂起权限」的路径。提问有（`rediscoverPendingQuestions`，`resume.go:213`，走 `GET /question`），权限**没有**——`reconcile.go:12-13` 与 `adapter.go:1123` 的旧注释断言「无按会话拉取未决权限 id 的可用端点」，据此 `ReconcileOutcome.Pending` 恒 0。
4. 永挂：opencode 阻塞在该权限上 → 会话永不 idle → 无回合终态事件 → 对账也救不了（`reconcileTurnEnded` row1：`CompletedMS==0` → 判「未结束」不补发，`reconcile.go:159-161`）→ 任务停在 `running` 直到 2h `stallTimeout`，而 `scanStalled` **只追加 stalled 事件、不改状态、不修复**（`watchdog.go:16-17, 217-227`）。
5. 人工收口：`10:49:14 恢复操作：人工强制收口`（`resume --force`）→ `10:50:13 archived`。今晚同型 ≥3 次。

## 4. 等待窗口归属与「谁清掉了它」

- `Segmenter.open[part]`（`timing.go:63`）与 `runState.permTiming`（`adapter.go:298`，`permID→{part,paused}`）都是**进程内、按任务运行态持有**，不是按 SSE 连接持有；断连不清理它们（`SubscribeEvents` 只重连连接）。
- 所以「响应 0 长度」的真实含义有两种：**(a)** 权限与 tool part 到达顺序错位/丢失，窗口从未（或已）打开——**应答仍会到达 opencode**（`RespondPermission` 先转发、后 `Resume`，`adapter.go:740-767`），所以 (a) 本身不致挂；**(b) 权限事件整体丢失**，adapter 连转发都没发生 → opencode 永久阻塞 → 挂。**本卡永挂的是 (b)**；(a) 是同一次断连的可观测伴随症状（两次同秒 WARN）。
- 30 分钟上界为何没判死：`hostapi.DefaultTurnTimeout=30m`（`driver.go:46`）只作用于**协调者唤醒回合**的子进程（`hostapi.Host.RunTurn`，由 `opencode/coordinator.go` 调），**完全不覆盖派发出来的 executor 任务**。派发任务走 `opencode serve` + SSE 订阅（`adapter.Start/subscribeLoop`），**在 adapter 层没有任何按回合的墙钟上界**；唯一上界是 2h `stallTimeout`（`config.go:483`），且它只唤醒不修复。⇒ spec §3 Q3 答案：上界只覆盖「回合进程」，不覆盖「等待权限」。

## 5. 决定性新事实：`GET /permission` 存在且列出挂起权限

旧注释「无可用端点」**已过期**。本机 opencode 1.18.31：

```
$ opencode --version
1.18.31
$ curl -s -u opencode:<pw> http://127.0.0.1:<port>/permission
[] [HTTP 200]
$ curl -s -u opencode:<pw> http://127.0.0.1:<port>/doc   （OpenAPI）
GET /permission -> permission.list | List pending permissions
```
OpenAPI 响应 schema（`#/components/schemas/PermissionRequest`）与 SSE `permission.asked` 的 properties **同形**：
`id`(^per)、`sessionID`(^ses)、`permission`、`patterns`、`metadata`(object)、`tool{messageID,callID}`、`always`。
另有 `GET /api/session/{sessionID}/permission`（`v2.session.permission.list`）与 `POST /permission/{requestID}/reply`。

⇒ 可以像 `rediscoverPendingQuestions` 一样，用 `GET /permission` 重连后重问未决项；`testdata/perm_bash.json` 等已是同形抓包，可直接做序列化边界夹具。

**版本风险（已声明）**：sample 抓包是 1.18.15（`replay_spike_test.go`），本机 1.18.31 才有 `GET /permission`。修面必须对 404 优雅降级（保留旧 Warn + 人工兜底），不得因端点缺失把恢复打断。
