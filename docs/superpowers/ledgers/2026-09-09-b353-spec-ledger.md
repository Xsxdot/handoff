## 读数

- 任务 wait 的可交付策略已有名字：`internal/client/delivery.go#WaitDeliveryPolicy`。假集合 = progress / approver_decision / approver_disabled / tickets_voided / ticket_answered / permission_auto_allow / permission_reuse。`delivery_failed` 与 `stalled` **不在假集合**（B233.7 缝测 `TestWaitDeliveryPolicy` 锁 delivery_failed 必须可交付）。`isDeliverable` 是它的包内别名（`internal/client/client.go`）。
- `handoff wait` 走该策略。`handoff card wait` 不走：`cmd/card_wait.go` Follow 回调对每条卡事件 `enc.Encode` 一行（约 :98–100）。stdout 一行 = 一次主会话唤醒（`cmd/wait.go` 约 :399 自述）。

- 账本自动化消费者 `internal/agentd/wakeconsumer.go#automationWakeEvent`：task_mirrored 只叫醒 question / permission_request / completed / failed / turn_failed；`delivery_failed` / `stalled` / `approval_dropped` 走 default 不唤醒。房间用户消息与 needs_human 会醒。
- proto 注释（`internal/proto/proto.go`）：`delivery_failed` 存在的理由是「唤醒协调者去执行 handoff resume」（约 :61–65）；`permission_auto_allow` 明写不得唤醒 wait（约 :78–80）；`approver_decision` 明写不唤醒（约 :67–69）。
