## 3. 两处自我更正（先前写错、已更正到卡上）

1. **「连接池=1」不成立**：`SetMaxOpenConns(1)`/`SetMaxIdleConns(1)` 只在 SQLite 回退分支（`internal/ledger/store.go:57-66`，注释为 SQLite 文件锁的单写者语义）；线上 DSN 是 `postgres://`（`dialectPG`），连接池是 database/sql 默认。
2. **「跨回合持事务」不成立**：`keystone.Wake`、消费轮、回合执行体（`wakeCoordinatorRoundID`）全是「短事务 → 跑回合 → 短事务」；`withLedger`（`ledgerapi.go:69-79`）只做 nil 检查。

推论（停顿现象）：CLI **直连账本**（每个命令首行打印 `账本库已打开 dialect=postgres target=postgres://…`），故「两台 CLI 卡数分钟 + agentd HTTP 秒回 + 重启 agentd 无效」只能解释为 **DB 侧对客户端不可用**。机制仍未定位（候选：某客户端长事务/锁、DB 主机资源竞争、连接饱和），拆出本卡另立。

## 4. 用户裁定（2026-09-22）

- **不做 A**（唤醒拆成「只做决定」+ 重活改派发）：等于把一次超时扩成一套新工作流；协调者这一轮的「读、想、决定要不要点火」本身就超过两分半（真机：判断该续接还是该重建用了约五分钟，尚未动手）。
- **做三处**：① 墙钟用 hostapi 既有 30 分钟上界；② 超时后继续 `Resume` 同一 session（`Launch` 只留给真正的 `Session not found`）；③ 简报只带本轮新事件，去掉「醒来第一件事：读卡」。
- **失败收口**：到点杀进程、会话留着、恰一次落「需要人」，下一轮仍续接同一 session。
