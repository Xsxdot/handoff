## 2. 本机 CLI 核实

### 2.1 二进制身份

~~~text
opencode path:    /Users/xushixin/.opencode/bin/opencode
opencode version: opencode v2.0.12

opencode2 path:    /Users/xushixin/.opencode/bin/opencode2
opencode2 version: opencode v2.0.12
opencode2 file:
  #!/bin/sh
  exec "$(dirname "$0")/opencode" "$@"
~~~

这证明 opencode2 可以只是 wrapper，而 opencode 也可能已经是 V2。文件名不能充当协议身份；解析器必须返回实际路径与 major。

opencode2 serve --help 实测为 “Start the v2 API and web server”，支持 --hostname、--port、--cors、--service、--stdio。

opencode2 run --help 实测支持 --standalone、--server、--continue、--session、--fork、--model、--agent、--format default|json、--file、--title、--thinking、--auto。

### 2.2 一次失败探针

首次 shell 探针误用 zsh 特殊变量 path，覆盖了命令搜索路径，后续 file、sed、opencode2 均报 command not found。该输出不代表软件缺失；修正变量名后重跑得到 §2.1 结果。此失败保留在台账，防止把环境自损误判成产品事实。

### 3.1 端点与事件

| 探针 | 实测 |
|---|---|
| GET /api/info | 返回 version、pid、urls、paths；version 为 2.0.12 |
| GET /api/session | 返回 session page |
| POST /api/session | 只给 title 即创建空 session；cost/tokens 为零；无模型调用 |
| GET /api/event | SSE 首帧为 server.connected；live-only |
| GET /api/session/{id}/permission | 返回空 data 列表 |
| GET /api/session/{id}/form | 返回空 data 列表 |
| GET /api/session/{id}/message、/inbox | 路由存在 |
| GET /api/plugin | 返回当前插件与 active/failed 状态 |

当前 V2 bundle/官方契约中核实到的相关事件包括：

- permission.asked、permission.replied
- form.created、form.replied、form.cancelled
- session.execution.started、succeeded、failed、interrupted
- session text/tool/step 事件

V2 client 文档明确事件订阅为 live-only，无 replay/自动重连承诺。由此推出 adapter 必须先订阅并收到连接事件，再提交 prompt；断线要 fail-closed。

### 3.2 探针中未采用的路径

- opencode2 api --server 在密码保护 serve 上的 preflight 未带有效鉴权，探针失败；它不进入产品设计。
- GET /api/tool 返回 404；插件是否加载以 GET /api/plugin 的 active 状态核实。

## 4. 双宿主插件探针

在隔离的 ~/.config/opencode/plugins/ 写入临时插件并启动 V2：

1. 顶层 import { Plugin } from "@opencode/plugin"：干净 V2 2.0.12 报 package not found，加载失败。
2. 改成无顶层 runtime import 的 default object（含 id/setup/server）：加载成功。
3. 在未调用的 V1 server() 内惰性 await import("@opencode-ai/plugin")：V2 仍加载成功。
4. 在 setup 中使用 ctx.tool.transform(editor.add(... JSON schema ...))：插件仍为 active。

GET /api/plugin 观测到：

~~~json
{
  "id": "b397.probe",
  "source": {"type": "local", "path": "<isolated-home>/.../b397-probe.ts"},
  "features": {"server": true},
  "state": {"status": "active"}
}
~~~

结论：一份 import-free default object 加 V1 lazy import 可作为双宿主载体；两份内容按 PATH 覆盖同一落点不是必要条件，且会造成双版本抖动。V1 最低 1.18.29 来自官方 object-form plugin 兼容界线，最终实现仍须在该版本真机锁定。

## 5. 鉴权探针

opencode2 auth list --standalone --format json 在隔离 HOME 中执行成功且输出可解析 JSON；该命令没有发模型请求。二进制静态内容表明 auth.json 是 legacy credential migration 来源，V2 会导入到自己的存储。

因此：

- “文件存在”不能证明 V2 当前 Ready。
- V2 toolchain 应在任务有效 HOME/env 下跑有时限的原生 auth list。
- 有连接 / 空列表 / 超时或坏 JSON 必须分别表达 Ready / NoCreds / AuthUnknown(ProbeFailed)。

## 7. 修订裁决

1. 双源码改为单文件双宿主。
2. 新增共享语义解析闸；execution contract 定义使用方接口、maintenance 实现、CLI 注入；
   opencode/opencode2 是协议身份，不是文件名。
3. opencode2 首版只声明 Execution；不新增 coordinator、OneShot approver、Profile、Skills。
   静态 capability 与 runtime readiness 分开，V1 协议入口仍逐次过 major 闸；共用 Skills
   由现有 OpenCode provider 管理，不要求实际二进制一定是 V1。
4. discipline 沿用 StartReq.Discipline → turn.RenderPrompt，不造 V2 专属映射。
5. env 可从 opencode2 显式回落 opencode；approver 不回落。
6. V2 权限由 manager 唯一裁决；V1 保持 adapter-owned；名称分支改成 authority/capability。
7. SSE 先订阅后 prompt，断流不重连假成功。
8. 冷恢复后移，但 Reap/ProcHandle 与重启扫孤儿保留在 MVP。
9. 多字段表单使用按 field id 的 JSON object；不做猜测型转换。
10. 后续项进入 roadmap，避免 Out of Scope 成为孤儿。
