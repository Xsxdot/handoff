## 四、基线红与跨契约冲突（已按协调者裁决登记）

**冲突**：`internal/client/execution_test.go#TestProductionHTTPClientCallersAreGatewayOnly`（B233.3 冻结条 25，`docs/superpowers/specs/b233.3-contract.md:170`：生产源码 `.HTTPClient()` 只允许出现在 `internal/agentd/forward.go` 与 `forward_ws.go`）在**本卡基线上已红**，原因是 B369 Ticket 0 的 `internal/mobilecore/core.go:155`（`cl.HTTPClient().Do`）与 `internal/mobilecore/proxy.go:38`（`Transport: cl.HTTPClient().Transport`）取用了 `client.HTTPClient()`。而 breakdown §3.3 ③ 要求 `go test ./internal/relay/... ./internal/client/... -count=1` 保持绿——在当前基线上不可满足。

原始输出：

```text
--- FAIL: TestProductionHTTPClientCallersAreGatewayOnly (0.01s)
    execution_test.go:158: 生产代码不得再取 HTTPClient 拼请求（网关 forward 除外）: internal/mobilecore/core.go, internal/mobilecore/proxy.go
FAIL
FAIL	github.com/Xsxdot/handoff/internal/client	9.507s
FAIL
```

另：`B369 contract §3.3` 明文冻结 `internal/mobilecore/proxy.go` 用 `Transport = cl.HTTPClient().Transport`（`b369-contract.md:189`），因此这是两张冻结卡的正面冲突，本卡无权自裁。

**协调者裁决（工单 `9f6bd37f-1ab6-4cf2-a329-5b6ce13cb9d4`，2026-09-19）**：

1. 本卡不改冻结守卫、不停工；把冲突如实写进 plan「基线事实」节（已记卡待用户裁决是否把 mobilecore 纳入允许清单）。
2. plan 与验收只对本卡新增代码负责：本卡新增文件不得再出现**除 `.HTTPClient()` 之外**的新违规，也不得改那条守卫测试。
3. 若实现需要 transport，把 Core 已持有的 client 字段按现状 `core.go` 的写法透传，不新造取用点。

**据此的设计决定（记台账）**：程序化兑换**不经 `client.HTTPClient()`**——`core.Pair` 已为每台在线机起回环反代，兑换改为对**回环源**发 `GET /console?ticket=...`（普通 `http.Client` + `CheckRedirect=ErrUseLastResponse`，`Proxy:nil`），反代照旧用 `cl.HTTPClient().Transport` 选路。这样新文件 `session.go` **零 `.HTTPClient()` 调用**，守卫的违规文件集合保持 `{core.go, proxy.go}` 不变（不新增违规文件）。`IssueAuthTicket`（领票）走既有类型化方法，也不触 `HTTPClient`。
