## 四、关键判断（计划的事实依据）

1. **发言权缺口（本卡最重岔口）**：控制台 actor=roomUserActor=`web:<host>`（sessionsapi.go/roomsapi.go 两处一致）；B358.4 拍板①后 owner 必须统一记法（user:/agent:），`validSessionOwner` 拒绝 `web:`；`sessionWriters`=显式成员∪席位（service.go:108）；**AddSessionMember 无任何生产入口**（无 HTTP 端点、无 CLI flag——B358.4 拍板②显式不做项+核对义务；B358.5 的 send 测试用 facade.AddSessionMember 直注成员，session_test.go:41/262）。⇒ 生产里控制台（web:<host>）永远不在 Members，对任何会话发言=403 ErrNotWriter。计划处置：403 渲染为可行动错误（组件反例断言），补员路径立待拍板（候选=gateway 增 POST /api/sessions/{id}/members，越界本卡文件集）。
2. **回复编辑框划出**：`handleRoomSend` req 无 reply_to（roomsapi.go:323-327）；reply_to 生产面缺口已立 B365（b358.5-plan §岔口 11.5）。控制台引用条=只渲染+点击跳转（历史事件里的 reply_to），回复编辑不入本卡。
3. **会话 tab 宿主=wb 组标签体系**：真仓 tabbar 的 tab=组（TabBar.tsx 头注释），组标签=焦点内容名。会话行开 tab=`wb.openOrFocus({kind:'session',…})`→新组；多开=多组；可关=组关闭；◫=place 到焦点工作 tab 右列。tabTitle/dedupKey 需增 session 分支（tabs.ts），持久化需 parseContent 增 session case（persist.ts，否则重载丢整份布局）。
4. **会话 tab 的 BaseDir**：Tab.base 必填且 parseBase 白名单 kind∈{workspace,home,scratch}——用 `{key:'session:<id>', kind:'home', path:'', label:'会话', projectName:'', machine:''}`（过 parseBase；title 冗余进 TabContent.title——会话标题不可改名，无 stale 风险）。
5. **fixture 路径裁定**：breakdown 写 `web/testdata/RoomsFixture.json`，真码 import 是 `./testdata/RoomsFixture.json`（= `web/src/api/testdata/`）——沿真码路径，计划按 `web/src/api/testdata/RoomsFixture.json` 落字。
6. **旧 API 导出去留**：fetchRooms/fetchInbox 随 RoomPanel 退役成无消费导出，但 `/api/rooms` 列表与 `/api/inbox` 端点仍在（gateway 保留）、其 Go 金样本（TestRoomSummaryGoldenProjection/TestInboxItemGoldenThreeOrigins）仍在——TS 侧类型与函数**保留**（契约镜像对称），只删 UI 族；fetchRoomMessages/sendRoomMessage/markRoomRead 被会话房间直接复用。
