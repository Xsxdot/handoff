## 3. 根因链（spec §1 的出处索引）

1. 三个写入点只入库不发布（上表 1-3 行）→ 实时流无关单事件；
2. `/ws/events` 实时流只承载 Publish（handlers.go 注释「审计类在服务端只入库不 Publish」）；补发仅订阅建立时一次；
3. watermark = MAX(source_seq)，缺口以下永不重拉（mirror.go:104）；
4. OpenTickets 开单镜像在（permission_request 会 Publish——`manager.go:2163`）、关单镜像缺 → 幽灵单。

反证排除「信封身份/版本因素」：c99a527d 的 2 条 ticket_answered 能进卡流，说明类型本身过镜像闸，唯一差异是到达通道（重放 vs 实时）。
