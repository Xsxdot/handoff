## 4. 真 sed 实测（本机 BSD sed，POSIX getopt 聚簇行为）

```
$ printf 'a\nb\nc\n' > f377
$ sed -ne '1p' f377      → a        （≡ -n -e）
$ sed -ne'1p' f377       → a        （脚本粘连在簇上）
$ sed -nE '1p' f377      → a
$ sed -n -e '1p' f377    → a

$ bash -c "sed -en '1p' f377"      exit=0 out=[a,b,c] err=[sed: 1p: No such file or directory]
$ bash -c "sed -e n '1p' f377"     exit=0 out=[a,b,c] err=[sed: 1p: No such file or directory]
```

读数：`-ne` 与 `-n -e` 同形；`-en` 与 `-e n` 同形（`e` 的实参是 `n`，`1p` 落成文件名）——故簇里的 `n` 必须在带参字母之前才算旗标。本机无 GNU sed（`command -v gsed` 无输出），GNU 侧假设（`-l` 必带实参）留待实现轮在 linux-01 复核。

- **定级 L1**：改动落在单子系统 `internal/permgate`、不碰契约面；plan 增量为零（spec「实现决定」三条已含全部决定，另写 plan 只会复述）；验收一眼可核（表驱动正反用例 + 真机两条假设复核）。

## 9. 复审 2 修复台账（2026-09-18，B377 review-2）

### 漏洞（真机复现）

GNU sed 的 `-l` 必带实参（行宽），既可粘连（`-l1`）也可取下一词元（`-l 1`）。旧簇分支
只在簇尾为 `l` 时跳过簇内剩余字符，没吃下一词元，于是 `sed -nl 1 'w /tmp/out' f` 的
`1` 被当位置脚本、真脚本 `w /tmp/out` 被当输入文件——真机写文件而门静默放行。

```
$ sed --version | head -1
sed (GNU sed) 4.9
$ printf 'hello\n' | sed -nl 1 'w /tmp/sedtest_out' /dev/stdin; echo "exit=$?"
exit=0
$ ls -la /tmp/sedtest_out
-rw-r--r-- 1 root root 6 ... /tmp/sedtest_out
$ printf 'a\n' | sed -nl 1 'e touch /tmp/sedtest_e' /dev/stdin; echo "exit=$?"; ls -la /tmp/sedtest_e
exit=0
-rw-r--r-- 1 root root 0 ... /tmp/sedtest_e
```

独立写法 `-l 1`（不走簇分支）是同一漏洞的第二个入口，已知旗标 case 把 `-l` 当无参旗标：

```
$ printf 'a\n' | sed -n -l 1 'w /tmp/sedtest_standalone' /dev/stdin; echo "exit=$?"; ls -la /tmp/sedtest_standalone
exit=0
-rw-r--r-- 1 root root 2 ... /tmp/sedtest_standalone
```
