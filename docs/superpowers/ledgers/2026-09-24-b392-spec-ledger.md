## 2026-09-24 设计裁决

1. **同一实例**：默认配对面、会话面和 Close 必须共享同一 `*mobilecore.Core`；另建 Core 会分裂 Pair 机器表与活动会话。
2. **薄适配**：适配器只编排 `Activate → Origin` 与 `ActiveMachine → Session`，不复制 S2 协议。
3. **一致性锁**：绑定层用一把私有锁覆盖整个切机及“活动机校验 + 取 cookie”，防并发切机时 A 请求读到 B cookie。
4. **失败闭合**：空 cookie、错机、未激活、兑换失败均 error；绝不 `("", nil)`。
5. **真竖切**：验收集合必须使用真实 Core；网络对端可 fake，Core 不可 fake。
6. **生产守卫**：默认生产组合被改回占位或第二 Core 时必须有测试打红。
7. **平台边界**：Go 交付真实 cookie 与调用顺序；`WKHTTPCookieStore` / `CookieManager` 实际写入归外部壳真机接缝，仓内 fake 不冒充。
8. **公开面不变**：保持 B386 后七函数，不新增 Token/Dial/Credential 或完整 cookie DTO。

## 2026-09-24 独立审阅后的规格修正

独立只读审阅指出：L2 判级忽略了“实现并对接既有 gomobile 跨语言契约与平台 cookie jar”，按 charter 规则应判 L3。修正为 **L3 轻档**：B369 契约与 S2 实现均已冻结，B392 只有一个适配实现链，不需要子卡扇出；批准后走 contract → breakdown 轻档。
