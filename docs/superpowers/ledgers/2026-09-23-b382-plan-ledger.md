## 4. 判断（本节点作出的裁决与理由）

- 登记事件载荷只记 `branch`：「谁/何时」由既有 `card_events.actor` / `created_at` 承担，
  与 spec §5 的「谁、何时、哪条」一一对应，不新增字段。
- 登记分支的 `WorkBranchInfo.Target/TaskID` 取空：spec §5 的 CLI 形状是
  `card work-branch <卡号> <分支>`（无 target 参数），登记不携带来源机；后果是任何带
  非空目标机的派发都会命中现状跨机闸（要求登记分支已发布 origin）——按 spec §4 故事 5 /
  §6 接缝 3 这是想要的「沿用现状闸」，详见 plan §0 P1。
- 登记写入口返回 `(applied bool, error)`：有快照时仍落事件（审计），但不生效；
  返回 applied 让 CLI 能在 stderr 给「留痕但不生效」的提示，避免静默 no-op（spec §5「不报错」）。
- 生效范围判据用「是否存在非审阅 dispatched 快照」而非「快照 branch 是否非空」：
  与 spec §3「还没有过非审阅 dispatched 快照时生效」逐字一致；`WorkBranch` 现有
  `info.Branch==""` 的写法把两种情况混在一起，重构时拆开。
