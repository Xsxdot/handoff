## 用户澄清（2026-08-29 第二拍）

小队 = 部门，成员载体 = 同等能力的员工。领任务是小队领，不是预绑某个载体。
某个载体空出名额时：先看排队里有没有**含该载体**且该成员政策位还有空的协调者小队；有则给协调者；没有再给执行者小队。
协调者（以及任何小队）不会死等某个成员：grok 没位就用 opencode；成员都没位才排队，谁先空出来用谁。
不抢占在跑任务。

否决上一拍「全局让路」（协调者在等 grok 时堵死 opencode 上的执行者）——那是现状 `drainQueuesOnce` 失败即 return 的形态，本卡要改掉。

默认（用户未反驳则冻结，不另开岔口）：
- 成员并发 0/留空 = 不限，只受载体物理上限（沿用现有词）。
- 存量小队的队级 MaxConcurrency 废弃不翻译到各成员（旧语义是队总帽，翻译会放大并发）。
- 多个成员同时有位时，登记顺序只作决胜，不构成等待绑定。
- 多个同角色小队抢同一空位：沿用就绪度 → 卡优先级 → 入队序。
