## 3. P5 核对（minSdk 21 × EncryptedSharedPreferences）—— 本节点亲验

直接下载 Google Maven 的 `security-crypto` AAR 读其 `AndroidManifest.xml`：

```
security-crypto 1.0.0         minSdkVersion="23"
security-crypto 1.1.0-alpha06 minSdkVersion="21"
security-crypto 1.1.0-alpha07 minSdkVersion="21"
security-crypto 1.1.0         minSdkVersion="21"     ← 最新 release（maven-metadata lastUpdated 2025-07-30）
```

`1.1.0` 的 `classes.jar` 仍含 `androidx/security/crypto/EncryptedSharedPreferences.class` 与 `MasterKey*.class`；
`javap` 显示 `EncryptedSharedPreferences` 与 `MasterKey` 均已标 `@Deprecated`（contract §8.4 已认账弃用）。

**P5 判定（build 期）**：钉 `androidx.security:security-crypto:1.1.0` → `minSdk 21` **不冲突**，manifest merger 不会因该库报错。
**P5 残余**：`MasterKey` 内部实现用 `KeyGenParameterSpec`（API 23），API 21–22 的**运行时**行为本节点无法验证且属 spec 明确 OOS（Android 真机运行时另开卡）；计划在 T1 保留「命中 manifest merger 冲突即暂停回 coord」的闸。

## 4. AndroidX 依赖 minSdk 实测（本节点亲验，决定能否保 minSdk 21）

下载各 AAR 读 manifest：

| 库 | 版本 | minSdk |
| --- | --- | --- |
| androidx.appcompat:appcompat | 1.8.0（最新） | **23** |
| androidx.activity:activity | 1.13.0（最新稳定） | **23** |
| androidx.core:core | 1.19.1（最新） | **23** |
| androidx.lifecycle:lifecycle-runtime | 2.11.0（最新稳定） | **23** |
| androidx.appcompat:appcompat | 1.7.1 | 21 |
| androidx.core:core | 1.13.1 | 19 |
| androidx.activity:activity | 1.9.3 | 19 |
| androidx.lifecycle:lifecycle-runtime | 2.8.7 | 19 |
| androidx.security:security-crypto | 1.1.0 | 21 |
| com.journeyapps:zxing-android-embedded | 4.3.0 | 19 |

**结论**：contract 冻结 `minSdk 21`（条 41）与「最新 AndroidX 全线」互斥；但**钉一档 minSdk≤21 的近期版本即可同时满足 minSdk 21 与常规 appcompat/activity/lifecycle**。计划据此钉版（§5）。zxing 4.3.0 的 POM 只依赖 `com.google.zxing:core:3.4.1`（纯 Java），其 `classes.jar` 内**无 `androidx/appcompat` 引用**（`rg -a -l` 亲验）→ 不额外抬 minSdk。

另亲验 `security-crypto:1.1.0` 的传递依赖 `com.google.crypto.tink:tink-android:1.8.0`：POM `packaging=jar`，Maven Central 有 2.3MB jar、无 `.aar`（`curl -I` → 404）→ 无 `AndroidManifest`/`uses-sdk`，不抬 minSdk。`androidx.collection:1.4.2`、`androidx.annotation:1.8.1`、`org.jspecify:jspecify` 亦为 jar。

## 6. 判断与决定（写明理由）

1. **构建 self-bootstrap**：无全局 gradle → 计划第一步下载 `gradle-8.13-bin.zip` 到 `/tmp` 解压，用它 `gradle wrapper --gradle-version 8.13` 生成并提交 wrapper；此后一律 `./gradlew`。
2. **依赖消费方式**：核心 AAR 在 `dist/mobile/handoff-mobile.aar`（gitignored，尚无），用 `settings.gradle.kts` 的 `dependencyResolutionManagement.repositories.flatDir { dirs(rootDir.resolve("../../dist/mobile")) }` + `implementation(name="handoff-mobile", ext="aar")`；壳构建前必须先跑 `./mobile/build.sh android`。
3. **minSdk 21 保真**：钉 appcompat 1.7.1 / core-ktx 1.13.1 / activity-ktx 1.9.3 / lifecycle 2.8.7 / security-crypto 1.1.0（全部 minSdk≤21），不用最新线。
4. **UI 选型**：经典 View + XML（`AppCompatActivity` + `WebView`），不引 Compose（省编译器插件版本对齐风险）；contract §9.6 允许子卡定。
5. **可单测设计**：`WebviewSessionBinder`/`PairEntry` 依赖**端口接口**（`SessionCore`/`CoreGateway`/`CookieStore`/`WebviewNavigator`/`SecretStore`），平台实现在 `ui/`（`CookieManager`/`EncryptedSharedPreferences`）→ JVM 单测用假端口锁调用序/cookie 逐键/fail-closed，不引 Robolectric（breakdown §5.2 明说 ESP 单测不可用、以接口替身锁语义）。
6. **applicationId**：`dev.gosuper.handoff.mobile`（对齐 `desktop` 的 `dev.gosuper.handoff.desktop`）。
7. **明文回环（P6甲）**：`android:usesCleartextTraffic="false"` + `network_security_config` 仅对 `127.0.0.1` `cleartextTrafficPermitted="true"`。
8. **cookie 值序列化边界**：手拼 Set-Cookie 头是高危点 → 纯函数 `buildSessionCookieHeader`；对含 `;`/空白/控制符的 value fail-closed（不加 setCookie、不 load），补一条含特殊字符的断言。
9. **日志凭据卫生**：`Pair` 失败**不记录异常消息**（`DecodePairBundle` 错误可能含相关上下文），只记类别；cookie 只记长度。
