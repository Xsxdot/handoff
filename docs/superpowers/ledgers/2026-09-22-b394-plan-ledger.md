## 2. 根因取证

### 2.1 实现面（亲读源码）

`internal/agentd/wakeconsumer.go:206` 的 `automationWakeEvent(ev proto.LedgerEvent)
(keystone.WakeEvent, bool, error)` 是唯一唤醒判据：

```go
206: func automationWakeEvent(ev proto.LedgerEvent) (keystone.WakeEvent, bool, error) {
207: 	switch ev.Type {
...
237: 	case ledger.EvNeedsCleared,
238: 		ledger.EvDecisionOpened, ledger.EvDecisionAnswered:
239: 		return keystone.WakeEvent{
240: 			Kind: keystone.WakeTaskTerminal, Card: ev.CardID,

242: 		}, true, nil
243: 	case ledger.EvNeedsHuman, ledger.EvSeatBearingMissing:
...
```

`EvNeedsCleared` 在 `:237`（与 `EvDecisionOpened`/`EvDecisionAnswered` 同 case）被映射为
`WakeTaskTerminal`，`yes=true` ⇒ 唤醒。它为何留：`docs/superpowers/specs/b353.md:104`
明写「本期把后两者补上，并保持 `needs_cleared`」；`b353-contract.md:90` 条目 40 冻结
「`needs_cleared` 产生 `keystone.WakeTaskTerminal`」；`b353-contract.md:125` §6-4 拍板
「过多时后续可收紧」。

```text

internal/ledgerstep/node.go:371:  n.St.ClearNeedsHumanFrom(cardID, n.actor())  // actor = "node:"+Name
```

三种 actor 来源：

- CLI `card needs --clear` → `ledgerActor()` = `cli:<USER>@<host>`（`cmd/ledgercli.go:44`）；
- Web 抽屉清标 → `web:<RemoteAddr>`（`internal/agentd/ledgerapi.go:589`）；
- 环节自动撤标 → `node:<节点名>`（`internal/ledgerstep/node.go:371`，`ClearNeedsHumanFrom` 只撤自己那条）。

**关键事实**：协调者会话在回合内清标（skill 明写 `handoff card needs <id> --clear`）用的是
`ledgerActor()`，**不携带席位身份**（`card_seat.go` 的 `cli:<cli>#<session_id>` 只用于 bind/
rebind/step/房间发送）。因此账本上无法用 actor 区分「协调者自己清」与「真人清」——两者都是
`cli:<user>@<host>`。

### 2.4 契约面（先读契约）

- `docs/superpowers/specs/b358-contract.md:396` 规则 31：
  「系统结构事件（入群/移出/归档/席位变更/needs_human）不唤醒任何人。」
  ——列了 `needs_human`，**未列** `needs_cleared`。
- `docs/superpowers/specs/b389-contract.md:193`（§3.5.1）：
  「`automationWakeEvent` 把 `EvNeedsHuman`（及 `EvSeatBearingMissing`）移出唤醒映射」
  ——只动 `needs_human`，`needs_cleared` 原样留。
- `docs/superpowers/specs/b353-contract.md:90` 条目 40：`needs_cleared` → `WakeTaskTerminal`（冻结）。
- `docs/superpowers/specs/b353-contract.md:60` 条目 15：`card wait` 对 `needs_cleared` 编码 stdout（展示面，另路）。

⇒ **判定**：`needs_cleared` 的唤醒映射是 b353 冻结、b358 规则 31 未覆盖的缝；它作为
`needs_human` 的状态翻转（注意力平面），被唤醒即构成「账务动作叫醒自己」。收口需
**改文档（契约）**：把 `needs_cleared` 纳入 b358 规则 31 的不唤醒清单，并取代 b353 条目 40。
