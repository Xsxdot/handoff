### 2.2 挂死发生在 CLI 自身收尾路径（决定性证据）

对挂死会话开 CLI 自身 DEBUG 日志（`--print-logs --log-level DEBUG`）：

```text
... message=loop session.id=ses_f45bc164affebNHHlbcxaGAxC5 step=1
... message="exiting loop" session.id=ses_f45bc164affebNHHlbcxaGAxC5
（到此为止；无 "disposing instance"，进程不退出，stdout 0 字节）
```

对照健康续接（同时序 DEBUG）：

```text
... message="exiting loop" session.id=ses_f3b5c0a22ffeFIPAeAWcK3M6YE
... message="disposing instance" directory=/root/.handoff/tmp/.../goprobe
（随后退出，stdout 918 字节）
```

即：**回合本身跑完了（`exiting loop`），卡死在 CLI 的实例销毁/进程退出段**，
且这一刻 stdout 还没吐出任何 JSON（该构建的 `--format json` 输出在收尾时才落盘）。
从 shell 侧对挂死进程发 SIGQUIT 期望 goroutine dump：`stderr 0 字节`——进程连信号处理都
不在正常态（Bun 运行时，`/proc/<pid>/wchan=ep_poll`，state=R/S，CPU 约 0.3 核持续）。

进程 fd 现场（挂死时）：

```text
fd0 -> /dev/null
fd14 -> /root/.local/share/opencode/log/opencode.log
fd15/16/17 -> opencode.db / -wal / -shm
fd23/25 -> pipe:[...]（自建管道）
无子进程、无网络连接
```

`strace -f`：主线程长期停在 `epoll_wait`/短 `poll(...,500ms)` 循环 + 周期 `SIGPWR`
（Bun 运行时正常现象），**无任何 db/网络/文件读写**——是运行时空转，不是 IO 阻塞。

## 4. 红色回路（本节点已跑，两条都成立）

### 回路 B：resume 不返回时唤醒链必须有限返回（缝 = keystone.Service.Wake）

现状读码：`keystone.go:144-152` 调 `runner.Resume(ref,prompt)`，`coordinatorRunner.Resume`
（`server.go:1216-1218`）用 `context.WithCancel(context.Background())`，**无超时**；
`Wake` 亦不设 ctx 期限。⇒ 一个不返回的 Resume 会把 `Wake` 永久钉住。
回路形态：假 `Runner.Resume` 阻塞到 ctx 取消，给 `Wake` 一个带 deadline 的 ctx，
断言 `Wake` 在 deadline 附近返回并落 `Escalated`/可行动错误。今天永挂 ⇒ 必红。
（本节点只写形态，测试代码归 plan T1，不在此实现。）

### 回路 C：reproduce 挂死（真机，计划 T0，非本节点跑）

`opencode run --format json -s <被污染会话> </dev/null` 零输出不退出，`gtimeout/timeout`
到点杀进程组。agent 可跑（秒级触发构造 + 分钟级观察窗）。修面落地后应能有限返回。

## 6. 关键代码事实：协调者隔离 HOME 缺模型定义

`orchestration/coordinator_home.go:133 NewCoordinatorPrepareHome` → `Prepare`（`:40-125`）：
只写 `.handoff/config.yaml`（handoff 配置投影）、`AGENTS.md`、`skills/`、并从主 HOME
拷**单个凭据文件**（`copyMissingCoordinatorCredential`）。**不写 opencode 的
`opencode.jsonc`（provider/model 定义所在）**。

亲验：造一个「协调者形状」隔离 HOME（auth.json + AGENTS.md + .handoff/config.yaml），
用主配置的同一 model 起回合：

```text
$ HOME=<coordhome> opencode run -m commandcode/deepseek/deepseek-v4.1-flash -- "reply ok"
exit=1  ProviderModelNotFoundError: Model not found: commandcode/deepseek/deepseek-v4.1-flash.
```

⇒ 这正是「重建也没兜住」的可行动候选：`rebuildAfterResumeFailure` 在隔离 HOME 里
`launchRound` 时，若该 HOME 没有模型 provider 定义，重建**快速失败**（不是挂死），
于是落 `needs_human: 协调者唤醒失败：resume 与重建均不可用`。
