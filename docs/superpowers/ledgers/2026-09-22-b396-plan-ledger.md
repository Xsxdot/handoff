## 2. 根因（证据驱动，全部亲跑）

### R1（决定性）：`waitForTurnEnd` 不把 `archived` 当终态 ⇒ 节点回合永不返回 ⇒ 槽位与运行锁永不释放

`card dispatch --step` 的 409「该卡已有环节在运行」判据**只在进程内存里**：

```text
internal/agentd/cardstep.go:129  if !s.claimCardStep(cardID) {
internal/agentd/cardstep.go:130      return fmt.Errorf("%w: %s 的 %s 节点正在运行", errStepInFlight, cardID, req.Step)
internal/agentd/cardstep.go:285  func (s *Server) claimCardStep(cardID string) bool { ... s.cardStepFlight[cardID] ... }
internal/agentd/cardstep.go:33-34 var errStepInFlight = errors.New("该卡已有环节在运行")
internal/agentd/ledgerapi.go:532  case errors.Is(err, errStepInFlight): → http.StatusConflict
```

判据**只看 `cardStepFlight[cardID]` 是否存在**，不看账本运行锁、不看租期、不看持有者存活。

槽位只在节点 goroutine 返回时释放：

```text
internal/agentd/cardstep.go:240-244  go func() {
    defer s.releaseCardStep(cardID)          // ← 唯一释放点
    s.runStepFn(context.Background(), runner, cardID, req.Step)  // ctx=Background，永不取消
}()
internal/agentd/cardstep.go:295  func (s *Server) releaseCardStep(cardID string) { delete(s.cardStepFlight, cardID) }
```

`runStep` → `StepRunner.Run` → `NodeStep.RunOnce` → `N.Await` → `waitForTurnEnd`
（`internal/ledgerstep/runner.go:431`）。而 `waitForTurnEnd` 的终态集合只有
`completed`（带 final_text）与 `turn_failed`/`failed`：

```text
internal/ledgerstep/wire.go:53-82   switch event.Type {
    case proto.EventTypeCompleted: ...
    case proto.EventTypeTurnFailed, proto.EventTypeFailed: ...
    }   // archived 落到 default：不返回，继续 for 循环再 wait
```

`archived` 是**可交付**事件（`internal/client/delivery.go:WaitDeliveryPolicy`
对它是 true），所以 `WaitEvent` 会把 archived 交回；`waitForTurnEnd` 忽略它、再次
`wait`。任务已归档后不再产出任何事件，`wait` 永久阻塞（ctx=Background 不取消）
⇒ `Run` 永不返回 ⇒ `cardStepFlight[cardID]` 永不 delete ⇒ 同卡同节点此后永远 409。

### R2（为何不自愈）：账本运行锁被续租，且 409 根本不读它

```text
internal/ledger/runlock.go:29  RunLockTTL = 5 * time.Minute
internal/ledger/runlock.go:31  RunLockRenewInterval = 2 * time.Minute
internal/ledgerstep/runner.go:209-235  go func() { ... case <-beats: RenewRunLock(...) ... }()
internal/ledgerstep/runner.go:154-160  defer ReleaseRunLock(cardID, r.RunHolder)
```

Run 不返回 ⇒ 续租 goroutine 一直活着、每 2 分钟把 `expires_at` 推后 5 分钟
⇒ 账本运行锁也永不过期（「25 分钟后仍拒」吻合：进程没重启，槽位与锁都在）。
即便账本锁过期也不救：409 判据读的是内存槽位，不读 `card_run_locks`。

### R3（触发链复现，缝级红回路实跑）

本节点在基线（未改任何生产代码）实跑，复现「任务归档但同卡同节点仍 409」：

```text
$ go test ./internal/agentd/ -run TestB396ArchivedTaskReleasesCardStepSlot -count=1 -timeout 60s
--- FAIL: TestB396ArchivedTaskReleasesCardStepSlot (2.98s)
    b396_archived_step_test.go:129: 等待条件超时
FAIL
```

用法：假目标机每连接只回一条 `archived` 事件（外部 done 的形态）；第一次派发
在飞时第二次派发 409（正确）；归档后本应释放槽位，但 `waitFor` 等不到
`cardStepInFlight=false` ⇒ 红。更早的进程级探针同时证实：等待期日志反复
`wait 事件返回 ... type=archived` 后接续重连，`runner.Run` 3 秒不返回。
