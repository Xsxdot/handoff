## 4. Swift 消费方式的探针（决定性事实）

探针文件在临时目录。用真实 XCFramework 直接 `swiftc -typecheck`：

1. `import Handoff_Mobile` → **FAIL**：`no such module 'Handoff_Mobile'`。
2. 桥接头 `#import <Handoff-Mobile/Handoff-Mobile.h>` + `-import-objc-header` → **PASS**。
   （另：`Bridging-Header.h` 里 `#import <Handoff-Mobile/Handoff-Mobile.h>` 可编译全七符号与
   `BindMachine` 属性。）

Swift 实际可见签名（由 `let x: Int = BindPair` 的编译错误反推，原始）：

```
BindPair          : (String?, NSErrorPointer) -> Bool
BindMachineCount  : () -> Int
BindMachineAt     : (Int) -> BindMachine?
BindOrigin        : (String?, NSErrorPointer) -> String
BindSessionCookie : (String?, NSErrorPointer) -> String
BindSwitchMachine : (String?, NSErrorPointer) -> String
BindClose         : (NSErrorPointer) -> Bool
// NSErrorPointer = AutoreleasingUnsafeMutablePointer<NSError?>?
```

**判定**：这七个 C 函数在 Swift 里**不是 throwing**（`try` 会触发
`no calls to throwing functions …` 警告）。壳必须显式检查末参 `NSError`（`var err: NSError?; …; if let e = err`）。

## 5. Xcode 工程生成方案探针（已被否与已通过）

**XcodeGen/Tuist/xcodeproj gem 全不存在**（§2）。故方案为「提交手写 `.xcodeproj/project.pbxproj`」。

探针 A：`objectVersion = 56`、逐文件 `PBXFileReference` + `PBXBuildFile`。`xcodebuild build/test` 通过，
但每加一个 `.swift` 都要改 pbxproj（易错）。

探针 B（**采纳**）：`objectVersion = 77` + `PBXFileSystemSynchronizedRootGroup`（Xcode 16+ 同步文件夹），
`fileSystemSynchronizedGroups` 挂到两个 target。加源码文件**零改 pbxproj**。
踩坑：`Info.plist` 若放在同步文件夹内会被当资源复制，报
`Multiple commands produce …/HandoffMobile.app/Info.plist`——故 `Info.plist` 移出同步文件夹到
`mobile/ios/Support/Info.plist`（`INFOPLIST_FILE = Support/Info.plist`）。修正后：

```
$ xcodebuild -project HandoffMobile.xcodeproj -scheme HandoffMobile \
    -destination 'platform=iOS Simulator,name=iPhone 17' \
    -derivedDataPath build CODE_SIGNING_ALLOWED=NO test
exit=0 ; ** TEST SUCCEEDED **
Test case 'ShellTests.testBindCallableFromTestBundle()' passed (0.002s)
app/Frameworks/Handoff-Mobile.framework  ← 在 .app 内
```

其它已验证事实：

- `xcodebuild -list` 会为 target **自动生成 scheme**（磁盘上无 `.xcscheme` 也能 `-scheme`）；
  无需提交共享 scheme（干净拷贝副本直接 `-scheme` 构建通过）。
- `-derivedDataPath` 必须与 `-scheme` 同用。
- 部署目标 15.0 可链（framework minos 13.0）；`CODE_SIGNING_ALLOWED=NO` 对 build 与 test 都生效。
- 嵌入（`.app/Frameworks/Handoff-Mobile.framework`）：`PBXCopyFilesBuildPhase`（`dstSubfolderSpec = 10`），
  即使 framework 是静态库，也能满足契约 §4.9 条 46「产物内含 framework」的读法。
- 无签名模拟器 `.app` 的 `Frameworks/` 目录存在 framework 拷贝，`lipo -info` 显示 app 二进制 fat。

**崩溃排障（重要）**：初版 app 无 UIScene 生命周期，测试启动即崩：
`EXC_BREAKPOINT`，栈顶 `___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption_block_invoke`。
加 `Info.plist` 的 `UIApplicationSceneManifest` + `SceneDelegate.swift` 后测试通过。
→ **iOS 27 必须采用 UIScene**（结论入 plan）。

## 6. 平台 cookie API 亲核（Xcode 27 SDK 头 + macOS Foundation 探针）

SDK 头 `Foundation.framework/Headers/NSHTTPCookie.h`：

- `NSHTTPCookiePropertyKey` 常量集**不含 HttpOnly**；`@property (readonly, getter=isHTTPOnly) BOOL HTTPOnly;`
  → **客户端无法经 `HTTPCookie(properties:)` 设 HttpOnly**。
- `NSHTTPCookieSameSitePolicy` + `NSHTTPCookieSameSiteLax`（iOS 13+）可设。
- `WKHTTPCookieStore.h`：`getAllCookies:`（有 completion）、`setCookie:completionHandler:`、
  `deleteCookie:completionHandler:`、`deleteAllCookies`（**无 completion**）。

`HTTPCookie(properties:)` 行为探针（`swift` 跑，读回属性）：

```
A 只给 name/value/path/domain      → secure=false session=true httpOnly=false
B 显式 .secure=false (Bool)        → secure=TRUE  ← 反直觉
C 显式 .secure=false (NSNumber)    → secure=TRUE
D 显式 .secure=0                   → secure=TRUE
E 加 .originURL(http)              → secure=false
F originURL + .secure=false        → secure=TRUE
G .discard=true                    → secure=false session=true
H .sameSitePolicy=Lax              → secure=false sameSite=lax
String(describing:) 显示 rawValue l
```

**判定**：要得到 `Secure == false`（契约条 26），必须**完全不传 `.secure` 键**（传任何值都会
变成 Secure cookie）。`isSessionOnly` 默认 true（无 Max-Age/Expires，条 29 达成）。
`HTTPCookieStringPolicy.sameSiteLax` 在 iOS SDK 下编译通过（已 `swiftc -typecheck`）。

**契约条 27（HttpOnly == true）在当前平台不可达成**——列 plan 残余落账，不静默判 pass。

## 8. 判断与决定（落 plan 的）

1. **工程生成**：提交 `mobile/ios/HandoffMobile.xcodeproj/project.pbxproj`（objectVersion 77，
   同步文件夹），配 `Support/Info.plist`、`HandoffMobile/Bridging-Header.h`。已验证可 `xcodebuild` 无 GUI 复现。
2. **Swift 消费**：桥接头（非 module import）；`SWIFT_ENABLE_EXPLICIT_MODULES = NO` 必需，
   否则报 `no module named 'main' declared in module map file … Handoff-Mobile.framework/Module…`。
3. **UI 选型**：UIKit + UIScene（契约 §「单 UIViewController」形态 + iOS 27 scene 强制）。
4. **cookie 构造**：不传 `.secure`；传 name/value/path/domain/sameSite；`discard` 可选。
5. **清罐确定性**：`getAllCookies` → 逐个 `delete` + `DispatchGroup` → notify（因 `deleteAllCookies` 无回调）。
6. **安全存储**：Keychain `kSecClassGenericPassword` + `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`，
   不设 `kSecAttrSynchronizable`。
7. **测试注入**：定义 `BindCore` / `CookieJar` / `OriginLoader` / `SecureStore` 协议，单测用假实现，
   不依赖 Go 核网络行为；`BindCore.machineAt` 回 `MachineView` 结构体（隔离 gomobile 类型）。
