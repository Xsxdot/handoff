## 四、放弃的尝试与判断

1. **「session send 无 flag 时探环境席位」（currentSeatIdentity 环境半边）**：放弃。理由：无 flag 必须确定性等于人形态（ledgerActor）；环境残留键把发言静默变成席位身份是「惊喜形状」，且 session wait 的 member 即显式参数——身份显式性对称。见 plan 定稿点 2。
2. **「owner 复用 ledgerActor()」**：放弃。B358.4 拍板①明文 CLI 同原则（统一记法前缀校验），cli:<user>@<host> 是机器位审计 actor 不是成员身份。
3. **「S5 顺手删 room send 的 kind=user 拒 flag 守卫行」**：放弃。守卫行在死面（旧房间一律 ErrReadOnly）内，删它无验收判据要求、且 TestRoomSendUserRejectsSeatFlagsWithoutSideEffects（存活不得误改清单）注释明言「CLI flag 层先拒」。废止的落点 = 新族不带旧规则。见 plan 岔口 2。
4. **「session send 加 --kind」**：放弃。breakdown §3.6 ③ 两形态 kind 恒 user；发言自由 = kind 不再分权，会话聊天面无第二 kind 用例。
5. **「session send 加 --reply-to」**：放弃（不加）。breakdown §3.6 ③ 验收无此项，gateway 半边同样无 reply_to——回复寻址目前无任何生产面，属跨卡缺口申报（plan 岔口 5），不静默扩面。
6. **「join 归档判据写 ErrReadOnly 文案」**：判据字面偏差。实际哨兵 = ledger.ErrBadState（文案「会话 %s 已归档」）—— breakdown §3.6 ③ 的「归档会话 send/join → 非 0 退出 + ErrReadOnly 文案」对 join 半边按实际哨兵修正为「已归档」文案（send 半边确为 ErrReadOnly）。plan 验收按实际行为写，字面修订回写建议归协调者（同 B358.2 plan 拍板①先例）。
7. **「校验函数跨包复用 validSessionOwner」**：放弃（不重构 agentd）。cmd 不得 import agentd；改 agentd 属越界（B358.4 文件）。cmd 本地复制 6 行前缀校验 + 注释指认 gateway 对应物，漂移风险由两侧测试各自钉住；统一归后续重构卡（plan 岔口 6 申报）。

## 五、计划的定稿点（写进 plan §岔口，供协调者审查）

1. **`session create` owner 载体 = 必填 flag `--owner`**（统一记法前缀校验；审计 actor=ledgerActor()）——B358.4 拍板①「flag 或参数，plan 定稿」的落点。
