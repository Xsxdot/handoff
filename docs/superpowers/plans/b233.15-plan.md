## 1. 目标、冻结行为与接缝

一个事实：`internal/agentd` 里不再有 git/工作区实现；git 实现主体在 `internal/workspace`，agentd 与 cmd 只经具名能力消费，`gitRun`/`gitProbe`/`gitRunNet`/`gitExec` 不出包。

| 接缝 | 入口符号（迁移后） | 本卡必须锁住的行为 |
|---|---|---|
| S1 工作区能力面 | `workspace.Capability`（七方法，`internal/workspace/capability.go`）← `Manager.Dispatch` / `Stop` / `Done` / `compensateWorkspace`（经 `Manager.SetWorkspace` 注入） | 脏工作区拒发（`ErrDirtyWorktree`）、仓库不可用（`ErrRepoUnusable`）、Stop 留存、Done/补偿回收语义与今天逐字一致；nil 能力失败闭合（`ErrWorkspaceUnavailable`）。 |
| S2 文件与条目 API | `workspace.ReadFile/WriteFile/ListDir/CreateEntry/CopyEntry/RenameEntry/DeleteEntry/SearchInDir/MarkIgnored` ← `Server.handleWorkspace*` 与 `Server.resolveWorkspace` | 路径逃逸闸、原子替换、条目建/复制/改名/删、目录内搜索、ignore 标注的 HTTP 行为与文案零变化。 |
| S3 审阅素材 | `workspace.Diff` / `workspace.DiffRange` / `workspace.Branches` / `workspace.RunCmd` / `workspace.DiffBaseFor` / `workspace.TaskDiffTarget` / `workspace.TruncatedNotice` / `workspace.ManualBranchExists` ← `Server.handleTaskDiff` / `handleTaskBranches` / `handleTaskRun` / `handleTaskFile` | diff 三连点/两连点、`run` 超时与输出护栏、分支列举与缺省基准推导不变。 |
| S4 新收具名能力 | 基线决议 `ResolveDefaultBaseBranch`/`ResolveDispatchBase`/`ResolveBaseline`；分支尖/删已建分支 `BranchTip`/`DeleteBranch`；分支列举 `Branches`；本仓工作树枚举 `ListWorktrees`/`ClassifyWorktree`/`FindWorktree`；工作树移除 `RemoveWorktree`/`PruneWorktrees`；仓库根探活 `MainWorktreeRoot`/`TopLevel`；克隆与登记前置校验 `EnsureRepoUsable`/`OriginURL`/`CloneRepo`；工作树探测 `ProbeWorkspaces`；预览元数据 `OriginURL`/`HeadBranch`；结果引用提交 `ProbeCommit`；bundle `BundleRange` ← `Manager.Dispatch`/`deleteCreatedBranch`、`reclaim.go`、`preview_owner.go`、`projectadmin.go`、`projecttree.go`、`cmd/project.go`、`bundle handler` | 每收一个能力配一条缝级断言并指回本条缝；变异：具名能力绕过 git 直接改状态 → 必须红。 |

**与 spec 字面差异的处置（不是语义偏离，逐条声明）**

1. `runshell.go` / `opennonblock_{unix,other}.go` 是 `RunCmd` 的私有闭包；spec「方案」表把 `RunCmd` 一并列入 `workspace.go` 迁移行，且「git 原语不出包」使 RunCmd 无法回调 agentd，故闭包随行。不占接缝名额。
2. `bundle.go` 内容（`BundleRange`/`widenEmptyRange`/`ErrHaveMissing`）迁入 workspace。spec §Out of Scope 说的是镜像 bundle **子系统自身不迁包**（其 HTTP handler 本就在 `server.go`），本卡只改调用点；但 bundle 体全是 git 调用，不迁就得导出 git 原语，违反语义规则 1。故保留 agentd 侧无文件、调用点改指 `workspace.BundleRange`。
3. `reclaim.go` 的**编排**（`Reclaim`/`ReclaimList`/`ForceReclaim`、错误哨兵映射）留在 agentd；仅把调用 `gitRun` 的底层助手（`repoWorktrees`/`classifyWorktree`/`parseWorktreeList`/`parsePorcelainStatus`/`canonPath`/`findEntry`/`worktreeEntry`）迁入 workspace，符合 spec「接缝 4 本仓工作树枚举 ← reclaim.go」。
