# B438.2 子卡 plan：移动端打洞直连（S7）

> 卡 B438.2（父卡 B438，L3）· 节点 charter:plan · 依据父卡 plan `b438-plan.md` §5.4 · 基线 = B438.1 合入父卡分支后的提交
> 状态：**已批准 2026-10-19**（协调者：按 1–6 执行；Android 回前台至多晚 30 s 重升级认可为已知差异；mac-pro 只用工具链与模拟器，跑完关模拟器，在役 agentd 不动）

## 0. 偏离与自主决定（相对父 plan §5.4）

1. **不新增 relay 导出方法，F3 不扩冻结**。§5.4 预留了「需要时在 relay 加『复位退避并尝试』导出方法」。现状读数：`Core.Resume`（`internal/mobilecore/core.go:209-243`）每次都经 `c.dial` **新建** relay Dialer，并调用旧 Dialer 的 cleanup（`stopMachine`，`core.go:468-478`，即 `Dialer.Close`）。新 Dialer 的退避状态从零开始，首个请求 `ensureTunnel` 就会起一次升级。所以「回前台不等退避、立即重升级」已经由现有生命周期满足，不需要新的导出面。属于父 plan §10「执行者可自行决定」中的实现细节：没有改冻结项，只是没用上预留的扩展口。
2. **Android 前后台语义**：Android 壳不调 `BindResume`，只有 iOS 的 `ConnectCore.swift:59` 调用它。Android 进程在后台存活时，直连死亡走 B438.1 的回落路径（watchDirect → relay），回前台后的重升级靠 `directDeadRetry`（30 s）加下一个请求触发。这与 spec S7「回前台后重新升级」同语义，只是有至多 30 s 延迟。本卡不改 Android 壳（改壳超出 §5.4 边界）。该延迟写进交回物，作为已知差异。
3. **测试缝**：把 `DefaultDial` 拆成包内 `dialWith(p2p relay.P2POptions) DialFunc`，`DefaultDial = dialWith(生产选项)`。竖切用 `dialWith` 注入 vnet `Net`。这不是假缝：生产路径恰好就是 `dialWith(缺省)`，并由 T-wire 断言钉住（见 §3）。

## 1. 改动边界

- `internal/mobilecore/core.go`：`DefaultDial` 带 `relay.WithP2P(relay.P2POptions{Enabled: true, STUN: config.DefaultP2PSTUN()})`。新增 import `internal/config`，依赖图因此增加 config/proxycfg/yaml，交回物写明。移动端没有配置文件，打洞恒开，STUN 用缺省列表。不加 `WithP2PStartDelay`：移动 Dialer 是长生命周期的，不是一次性 CLI。
- `internal/mobilecore/*_test.go`：新竖切测试。
- `mobile/go.mod|go.sum`：仅在需要时 tidy。
- **不动**：`mobile/bind`（导出面冻结，`TestBindExportedSurfaceIsFrozen` 原样绿）、Android/iOS 壳、relay、p2p。

## 2. 实现步骤

1. 先红：T-wire（生产 `DefaultDial` 构造的 Dialer 开启打洞）。断言方式选可观察行为：用 vnet 世界跑 `dialWith(DefaultP2POptions 加 Net 注入)` 的竖切，再加一条静态断言，钉住 `DefaultDial` 与 `dialWith(mobileP2P(nil))` 同源（包内函数 `mobileP2P(net) relay.P2POptions`，生产传 nil）。
2. 绿：`dialWith` + `mobileP2P`。
3. 竖切 T-S7（vnet，见 §3）。
4. `go build ./...`、`go test ./internal/mobilecore/ ./internal/relay/ ./internal/p2p/`、`cd mobile && go test ./...`。
5. mac-pro 工具链（只读用户目录，**不碰在役 agentd「macbook-pro」**）：同步分支到 mac-pro 的隔离临时目录（`git clone` 本地 bundle 到 `/tmp/b438.2-<ts>`）后执行：`PATH=$HOME/go/bin:/usr/local/go/bin:$PATH go test ./bind/ -run TestGomobileSurfaceHasNoSkips -v`（非 SKIP），`./build.sh android`，`./build.sh ios`。
6. Android 模拟器取证（mac-pro 上的 AVD `Medium_Phone_API_36`）：在模拟器上跑一个 `gomobile`/`go test` 交叉产物，打印 `anet.Interfaces()` 与 `p2p.Gather` 的 host 候选类型和地址族（不打候选串）。取证产物与原始输出落 `docs/superpowers/evidence/b438/b438.2-*.md`。
7. 前后台：iOS 模拟器或 Android 模拟器上跑真 App 需要真 relay 形态机器，而本卡禁碰生产 relay，在役 agentd 也不能动。所以前后台在 Go 层由 T-resume 覆盖（见 §3）；模拟器 App 级前后台标「未验」并写明原因。

## 3. 测试

- **T-S7 竖切**（`internal/mobilecore`）：vnet 世界（`p2ptest.New`，两侧端口受限锥 NAT）＋测试内 multi-CONNECT splice relay（照 relay `countingRelay` 形状，约 80 行，内联在 mobilecore 测试里，与既有 `startFakeRelay` 同风格；relay 内部测试夹具因包内测试导入环无法复用）＋真 `relay.Listener`（`WithListenerP2P`，Net = world.B）。Core 用 `New(dialWith(mobileP2P(world.A) 加 STUN=world.STUNURL()), log)`，执行 `Pair` → 回环反代发 HTTP。断言：①先经 relay 成功；②INFO `p2p 直连已建立`；③此后经回环反代的 N 个请求，relay app 隧道字节零增长，且上游看到的 RemoteAddr 是 vnet 直连地址。
- **T-resume**：直连建立后 `Core.Resume` → 旧 Dialer 关闭（旧直连会话关闭日志）→ 新请求成功 → 新 Dialer 再打一条 `p2p 直连已建立`，且不需要等待退避，时限 ≤ 升级预算加余量。
- **T-wire**：静态钉生产选项：`mobileP2P(nil).Enabled == true`、`STUN` 等于 `config.DefaultP2PSTUN()`、`Net == nil`。
- **既有**：`TestPairVerticalSlice` 等原样绿。fake relay 不认识信令会话：信令 CONNECT 会被 fake relay 的 E2E/app-yamux 终结，读不到应答就按 EOF 处理，判作对端不支持，业务不受影响。这条也正好反证旧对端兼容。
- **泄漏**：`Core.Close` 后无 p2p goroutine 残留（沿用 relay 测试的 goroutine 栈检查口径）。
