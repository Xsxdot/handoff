## 0. 本卡干什么（一段话）

390×844 紧凑视口下收口四面信息架构与一组 a11y 硬闸：①设置 tab 缺省呈现 Web 设置中心
（会话打开方式/提醒/显示与可访问性/关于），执行机与扫码配对降为二级页，w-40 左栏在 compact
移除；②卡 tab 缺省单列扫描（复用 CardItem），「⚑ 需要你」聚合置顶，看板横滚与八列表格在
compact 不作为扫描面；③卡抽屉 13 块重排为「工作项→当前动作→证据」三层分组；④会话
「⋯」叠加抽屉在 compact 改为群聊|详情两态语义切换；⑤项目列表 compact 缺省折叠、位置为
状态摘要；⑥§1.6 五处 hover 功能入口在 compact 常驻可达；⑦覆盖层后的后台内容包
aria-hidden + inert（mobile-home/mobile-dir/FullPageCover 盖住的常驻工作台、卡抽屉盖住的
卡列表），抽屉焦点移交。桌面布局零回归；原生配对、相机、Keychain/Keystore、壳内
TalkBack/VoiceOver 不在本卡。

**验收判据是卡级法定契约**（plan 必须逐条覆盖，映射见 §7）：

> 390×844 下卡列表、设置中心、会话详情、项目列表均无页面级横向滚动和不可达内容。设置默认
> 先呈现 Web 设置（会话打开方式、提醒、显示与可访问性、关于），执行机与扫码配对作为二级
> 页面，不把原生壳能力当作本期设置首页；卡列表保留「需要你」聚合与单列扫描，卡详情按工作
> 项→当前动作→证据分层，会话用语义化的群聊/详情切换，项目列表保持项目优先、位置为状态信
> 息。回复、关闭、项目操作等不得依赖 hover，主要触控目标满足移动尺寸，覆盖层后的后台内容
> 对读屏与键盘不可达；完成键盘、200% 缩放和浏览器读屏走查，桌面布局不回归。原生配对、相
> 机、Keychain/Keystore 及壳内 TalkBack/VoiceOver 验收不在本卡。

## 2. 岔口裁决（spec 指定归 plan 的开放点 → 决定 + 理由）

### 岔口 1：`sub` 参数名与 SettingsPage 注入统一（spec §3/§6.4/§8）

**决定：参数名就叫 `sub`；SettingsPage 增加 `compact?: boolean` / `sub?: string | null` /
`onSubChange?: (key: string | null) => void` 三个可选 prop，compact 分支渲染新建的
`SettingsHub` 组件；桌面 JSX body 逐字节不动；SettingsPage 全程不感知 router hook。**

- 词表 `SettingsSub = 'machines' | 'pairing' | 'discipline' | 'automation' | 'env' | 'update'`，
  常量与类型定义在 useMobileNav.ts（对齐 MOBILE_TABS 先例——URL 词表归导航模型所有）；非法
  值派生为 null（落设置中心）。**不与桌面 SectionKey 并型**：桌面词表含 general 无 pairing，
  compact 相反，强并一个类型会让桌面深链词表吞进 pairing。
- 注入统一的落点：compact 深链 = Shell 从 useMobileNav 读 `nav.sub` 经 props 注入（组件不碰
  router）；桌面深链 = window.location.search 直读（:42-50 原样保留，独立单测继续可渲染）。
  两套来源「统一」在组件边界——SettingsPage 自身永远只有 props 与 window 两种输入，不出现
  第三种 router 读取路径。spec §6.4 的倾向（改接 props）按此落成。
- 为什么 compact 分支是独立 SettingsHub 而非在 SettingsPage 内联展开：hub 形态（四分区就地
  呈现 + 二级入口行 + 二级页全宽）与桌面双栏（w-40 nav + 内容区）没有任何共享 JSX，塞进同
  一个 return 只会增加桌面回归面；共享的是**二级页组件与数据**（MachinesPage 等 + tree/
  desktopState/latest 从 SettingsPage 传入），组件级复用已经保证单一来源。

**理由**：grep 全仓确认 `sub` 参数零消费、零撞车；词表白名单派生使 `/?sub=bogus` 自愈成中心
首屏；SettingsPage 桌面 body 不动是「桌面双栏零改动」的最强保证。

### 岔口 2：卡详情三层分组的视觉形态（spec §2.3/§6.1/§8）

**决定：同页重排 + 三层分组标题（不用折叠组）；compact-only；块序定死如下。**

- 三层标题：`工作项` / `当前动作` / `证据`，`<h2>`（text-xs font-semibold text-muted-foreground，
  上缘 border-t 分隔），data-testid = `card-tier-work` / `card-tier-action` / `card-tier-evidence`。
- 块序（全部 13 块单页可达，零新增零删除操作面）：
  1. **工作项**：状态列 chips（:652-656，"这是什么状态"的状态地图）→ 验收判据与已验标识
     （:701-749）；
  2. **当前动作**：CardAttention needs/decisions 答复（:905-907）→ 环节动作/转移状态（:909-914）
     → 关联执行行与 ↗ 及其展开的工单答复（:824-903 整块）→ CoordinatorPanel（:643，叫机器人/
     打开终端）；
  3. **证据**：Timeline+评论（:916-926）→ 附件管理（:751-786）→ 并入本卡（:788-796）→ 关系
     （:798-809）→ 子任务（:811-822）→ 元数据 dl（:658-699）→ 协调者席位（:645-650）。
- 两个归属裁定：spec 把「关联执行行与 ↗」（当前动作）与「关联执行实况展开/工单答复」（证据）
  分列两处，实测它们是**同一个 aria-expanded 行块**——整块归当前动作，不拆（拆开会把一个
  展开交互劈到两组，DOM 序锁反而失真；工单答复随行展开，天然「两步内可达」）；状态列 chips
  spec 未指派，归工作项组（它是卡的完成定义语境，与验收判据同族）。
- **档位裁定：三层分组只在 compact 生效**（CardDrawer 新增 `compact?: boolean` 缺省 false）。
  依据是 spec §5 的更强约束「本卡在桌面侧的净改动只有 FullPageCover 覆盖期 inert」——桌面
  560px 抽屉不是 §1.3 的病人（「390 窄面里扫描成本最高」），桌面块序一字不动也保住
  CardDrawer.test 全部既有用例作为「13 块零丢失」的证据。合并区 mergeRef/initialSection 滚动
  定位与块序无关，compact 下照常工作。

**理由**：折叠组会引入 13 块 × 展开态的管理面与「点开才能扫」的第二跳，把扫描成本换了个形
式（spec §6.1 自警）；分组标题 + DOM 序重排让「验收断言三层标题 DOM 序」成为一行查询；
compact-only 是桌面净改动承诺的直接推论。

### 岔口 3：hover 五处的 compact 呈现形状（spec §2.6/§8）

**决定：全部行内常驻——同一枚钮、同一 aria-label、同一位置，只改可见性策略与触点尺寸；
桌面类名逐字节保留（ProjectTree.tsx:688 B369.7 双档先例的同款写法）。**

| # | compact 形态 |
|---|---|
| 1 | SessionChat 回复钮：`compact ? 'opacity-100 …' : 现状串`（focus 现身路径保留无害） |
| 2/3/4 | ProjectTree 三钮：`compact ? 'block' + p-1.5 : 'hidden … group-hover:block' + p-0.5`（机器行两钮 right-14/right-6 位置不变，27px 宽的钮不重叠） |
| 5 | TaskRow ×：compact 去 `opacity-0`/`translate-x-1`/`group-hover:*`，常驻 `opacity-100 translate-x-0`；**标签 span :1390 compact 同步去 `group-hover:opacity-0`** |

**理由**：验收口径是「不得依赖 hover」——hover 仍可显形、触屏与键盘有同等路径即达标；行内
常驻与桌面同位同钮（B369.7 岔口 2 的同款裁决），diff 最小且桌面守卫断言可逐字节写。不做
「行内展开」形态：390 行宽里再藏一层展开钮是给扫描加深度。

### 岔口 4：inert 与 pointer-events-none 是否叠加（spec §2.7/§6 归 plan 开放点）

**决定：叠加，沿 WorkbenchPage.tsx:310-313 先例三件套（aria-hidden + inert + 覆盖期
pointer-events-none）。**

**理由**：inert 的兼容底线是 iOS Safari/WebView 15.5+、Chrome 102+（spec §6.3）；旧内核降级
时 aria-hidden 仍摘读屏树、pointer-events-none 仍兜住指针命中，真正兜不住的只剩键盘 Tab——
如实记为已知降级（= 退回现状，不白屏）。三件套写法在仓内已有事件层兼容证据（TerminalTab
:378-380），不是新发明。**每处覆盖的机制矩阵见 §4**——其中会话详情态与卡抽屉背景不完全是
这个形状，那里有单独理由。

### 岔口 5：会话群聊|详情两态的 aria 语义（spec §2.4「aria 语义归 plan」）

**决定：role="tablist"/"tab" + aria-selected 翻转，两态内容用 `hidden` 属性翻转可见性、
**保持挂载**。**

- compact 头部渲染 `<div role="tablist" aria-label="会话视图">` + 两枚 `role="tab"`
  （aria-selected，data-testid=`session-view-chat` / `session-view-detail`）；群聊容器与详情
  容器各为 `role="tabpanel"`，`hidden` 属性随激活态翻转。桌面「⋯」抽屉（:109-122）与
  `drawerOpen` state 原样，一字不动。
- 两块内容都保持挂载：群聊隐去 = `hidden`（display:none）而非卸载——SessionChat 的草稿/
  回复引用条/@ 联想全是内部 state，卸载即丢；群聊无 canvas/WS（轮询在 SessionTab 层），
  display:none 无 B280 式副作用。已知代价：隐藏期间聊天 scrollTop 归零（浏览器行为），回
  群聊后落在顶部——如实记录，不为此造滚动恢复。
- 详情态占满会话内容区（SessionDetail 直接放内容区，flex-1 min-h-0 overflow-y-auto），五块
  全宽；归档流程（ConfirmDialog）与拉卡流程（JoinCardDialog）接线原样。

**理由**：spec 把它定性为「同层切换、不是导航层级」（§3）——tablist 语义精确表达「同层两
视图」；aria-selected 翻转与 hidden 翻转都是 jsdom 可锁的结构断言；「详情态盖住的群聊不可
达」由 display:none 直接满足（不可见+不进读屏树+不进 Tab 序），无需再叠 inert（被盖面根本
不渲染盒子）。

### 岔口 6：卡列表次级控制行的形状（spec §2.2「形状归 plan」）

**决定：compact 头部三行、全部常驻不折叠。**

- 行 1（主控）：「工作项」标题 + 健康灯 + `⚑ 需要你 N`（ml-auto，min-h-11）；
- 行 2（词表）：状态 chips 逐值横排（可换行）；
- 行 3（次级控制行）：项目 select + 工作流 select + 搜索框（flex-1 min-w-0）+「+ 新建」+
  （showOpenInBrowser 时）从浏览器打开；看板/列表切换**不渲染**。
- 全行控件统一 `min-h-11`（44px 触控），行容器 `data-testid="cards-controls-secondary"`。

**理由**：390 宽下 select/search/新建四个控件一行放得下（select ≈110px + input flex + 钮），
常驻比折叠少一次点击；「⚑ 需要你」置顶与 spec §2.2 措辞逐字对齐；chips 单独成行因为它是最
高频的筛选，与次级配置（项目/工作流）不同频。

## 3. 补充裁决（非岔口，但实现者需要定案才能开工）

### 3.1 a11y 硬化的档位范围

**决定：CardDrawer 的 aria-modal + 焦点移交 + 背景 inert 全部 compact-only。**
桌面卡抽屉是 560px 侧板、看板左半仍可见可点（双栏是设计形态）——对「背后可达」的面板贴
`aria-modal="true"` 是向读屏谎报，且给看板加 inert 会废掉桌面双栏。spec §1.7 的病句「卡列表
在抽屉后仍可达」的病人是 compact（92vw ≈ 全盖）。SessionTab 同理：桌面「⋯」抽屉逐字节不动
（§2.4 明文），硬化只发生在 compact 两态（岔口 5）。**焦点移交范围 = CardDrawer**（§4 行
「焦点移入抽屉、关闭归还触发钮」唯一指名面）；mobile-home/mobile-dir/FullPageCover 是导航
面不是对话框，不做焦点移交。

### 3.2 会话打开方式「焦点任务现场」的解析链

**决定：`sessionOpenMode: 'chat' | 'scene'`（缺省 chat）；消费点 = Shell.openSession（仅
compact 读偏好，桌面 openSession 不读）。scene 档 = 尽力解析该会话在跑任务并跳进任务现场，
解析不到静默回落群聊态。**

- 解析链（零新增端点）：会话挂卡（SessionSummary.cards，会话列表载荷已有）→ 逐卡
  `fetchCardDetail(card_id)`（既有端点）→ `task_states` 行 ∩ Shell 任务流取第一个在跑行
  （isRunningRow 口径同 CardDrawer:268-271，**抽到共享模块 `web/src/app/cards/taskRun.ts`**，
  CardDrawer 改 import，行为零变化）→ 命中即 `openTaskTui(null, taskId)`（compact 下经
  enterDetail 收口 URL，返回条语义不变）。
- 体验细节：点行后群聊 tab 照常先开（openOrFocus + 下钻不等待解析），解析回来才跳；用 ref
  记「最近一次 openSession 请求序号」，迟到的解析结果序号不匹配即丢弃（防跳转劫持）；任何
  一步失败/无数据 → 留在群聊态，不弹错不空转。
- 为什么必须异步解析：SessionSummary 无 task id、Task.executor_session 全仓零消费（grep 复
  核）、会话详情 nodes 也不含 task id——card detail 的 task_states 是唯一现成的会话→任务桥，
  这是「不造新端点」约束下唯一诚实的落法。解析是尽力而为不是承诺，回落路径就是现状，故最
  坏情况 = 现状。

### 3.3 触控基线的收口规则

**决定：次级目标 ≥24 用「compact 根节点触点基线类」一次收口；主动作 ≥44 逐枚点名。**

## 4. a11y 硬闸模型（覆盖面 × 机制矩阵，实现者照表施工）

| 覆盖层 | 被盖面 | 机制（覆盖期） | 条件 | 焦点移交 |
|---|---|---|---|---|
| mobile-home（:1034）或 mobile-dir（:1125） | 常驻工作台容器（Shell.tsx:911，新增 `data-testid="workbench-underlay"`） | `aria-hidden={covered}` + `{...(covered ? { inert: true } : {})}` + 类 `pointer-events-none`（沿 WorkbenchPage 三件套） | `covered = (compact && !nav.detail) \|\| fullPageRoute`（:565-566 恒 desktop） | 无（导航面） |

- 写法统一用 WorkbenchPage 的展开式（`{...(x ? { inert: true } : {})}`），aria-hidden 用

- jsdom 全锁面：aria-hidden/inert 属性随覆盖状态翻转（getAttribute 断言）、焦点落点与归还、

  普通 div 会改 flex 子项拓扑，包进 `contents` 包装则布局零变化（包装盒不生成）。回退预案见
  §9。

## 9. 风险与回退（每段独立 revert；依赖 T2←T1，回退按逆序）

1. **T7 inert 条件写错把活面 inert（最高危）**：`nav.detail` 翻转瞬间把下钻中的工作台锁死。
   缓解：T7 的「detail 态三件套全部移除」反例锁 + B369.6 断点谱系全绿；回退：covered 常量改
   `false` 一行即整体停用（属性式闸，无结构残留）。
2. **T7 旧 webview 内核 inert 不生效**（spec §6.3）：降级表现 = 键盘 Tab 重新可穿（aria-hidden
   仍在、pointer-events-none 仍兜指针）——已知降级不是回归，卡台账记录即可；不为此造 polyfill。
3. **T4 display:contents + inert 的兼容边角**：若实测（真机/浏览器）出现包装失效——回退：去
   `contents` 类改普通 `<div className="flex min-h-0 flex-1 flex-col">` 包裹（布局等价：main
   flex-col 的子项拓扑经包装后 header/横幅/单列的 flex 行为不变，唯一绝对定位后代锚点仍是
   main），两者都不行再退为仅 aria-hidden（键盘面降级，如实记录）。
4. **T2 SettingsHub 与桌面 SECTIONS 双源漂移**：缓解——二级页组件单一来源（hub 只做编排不做
   内容）、入口行与桌面 nav 的 update 红点共用 updateAvailable 计算；漂移风险仅限文案层。
5. **T2 scene 档跳转的迟跳劫持**：缓解：ref 序号守卫 + 失败静默回落；最坏情况 = 现状（群聊
   态）。若 review 认为异步跳转不可接受——回退：scene 档降级为「仅落群聊态 + 台账记录」，
   偏好控件保留（验收只要求四分区在场）。

## 10. 明确不做（继承 spec §5，逐条 + 本卡新裁定的边界）

- **原生配对、相机、Keychain/Keystore、壳内 TalkBack/VoiceOver**：pairing 二级页只承载 web 侧
  说明语义，不接相机与端点。
- **B369.9 的终端面**：单焦点终端投影、WorkbenchPage/终端窗格内容形态不做；underlay 加 inert
  是覆盖层 a11y 闸，不是终端面改动。
- **桌面交互形态重构**：设置双栏、卡看板/列表、会话「⋯」抽屉、项目缺省展开全部逐字节保留；
  桌面侧净改动 = underlay 覆盖期三件套（布局无感）。
- **FlowsPage/Codegraph 移动适配**：B369.7 隐藏+解释不翻案。
- **账本写入面**：`/api` 零新增；卡详情操作复用既有 move/评论/裁决/答复入口。
- **pad 专属优化**：统一模型对 pad 档自然生效，不做专属布局。
- **Overlay 基座自身的背景 inert**：Overlay 已有 aria-modal+焦点（仓内最佳先例），看板/工单弹
  层打开期的 FullPageCover/mobile-home 背景不另加闸（不在 spec §2.7 覆盖面清单内）；如要做
  应另开卡。
- **mobile-home/mobile-dir/FullPageCover 的焦点移交**：它们是导航面不是对话框；焦点移交仅
  CardDrawer（§3.1）。
- **会话两态切换进 URL**：不新增导航参数（spec §3 明令）；`hidden` 保挂载的 scrollTop 损失
  不做滚动恢复。
- **a11y 偏好开关（文本缩放等）**：spec §2.1 ③明令不造平行机制。
- **CardDrawer 状态列 chips（:652-656）触点化**：span 指示器非交互目标，不动。
