# B233.6 实现计划：工作流接入共享派发、事件转发与旧编排退役

## 0. 计划边界与冻结选择

本计划只覆盖卡 B233.6，目标基线是 `cards/B233.1-charter-7`。本节点只写计划，不修改运行时代码；S0—S3 是后续实现阶段在本计划内串行执行的任务段，不能拆成外部子卡。

已冻结选择：

| 决策 | 本计划采用的行为 |
| --- | --- |
| P1 | 保留 `card_tasks` 五列和 `LinkTask(cardID, target, taskID, purpose, actor string) error` 五参数入口；`TaskLink.Node`/`Attempt` 从同卡 `EvDispatched` 快照投影，不给旧行猜值。 |
| P2 | mirror reconcile 每轮重新取得 link 投影；Node/Attempt 投影改变时取消旧订阅并以新身份重订阅。 |
| P3 | `task_mirrored` 的 `node`/`attempt` 在 store 层写入 envelope；source 身份仍只在 `card_events` 的 `source_target/source_task/source_seq` 列。 |
| P4 | StepRunner 继续通过 typed `WaitEvent` 取得节点终态正文；mirror 继续通过 `StreamEventsOnce` 和 ledger watermark 观察事件；两套游标互不推进。 |
| P5 | 不扇出；S0 → S1 → S2 → S3 在本文件中串行完成。 |

协调者已明确 S3 不扩展 `internal/ledger/api/api.go`、`internal/agentd/ledgerapi.go`、`internal/proto/ledger.go`：进程内消费者从 `autoLedger.EventsFromAsc` 取得 store 已写入的原始 envelope，HTTP DTO 的 `proto.LedgerEvent.Payload json.RawMessage` 原样透传。该决定使冻结验收行可在既有 wire 边界内闭合，没有需要退回再议的冻结验收行。

### 3.4 缺陷族、序列化边界与接缝覆盖

- 状态/生命周期：一次 task、重复派发、Transport 成功后 ledger 写失败、重启恢复分别有机内断言或“未验证，需真机”标记；远端孤儿回收、relay/直连切换、executor 重启是后者。
- 错误/可观测性：transport、receiver、link、snapshot 四类错误都带上下文并非静默；结构化 logger 不得以成功日志掩盖部分成功。
- 跨平台/安全：不读 HOME、不拼 shell/harness，不绕过 squad admission；HomeDir 只透传已解析值。
- 幂等/竞态：锁“一次 transport + 一个 task ID + 一个 snapshot”；并发 check→action 的 TOCTOU 属真机项。
- 类型/枚举：S1 不加枚举；事件复用值不能由 S1 当 pass。
- 序列化链路完整清单：`DispatchOpts → client.Dispatch JSON → handleDispatch → Manager.Dispatch`、`DispatchResult → DispatchSnapshot JSON`。测试穿过真实 HTTP/JSON；可空 HomeDir、Receiver、Node、Attempt 分别区分缺失/空串/非空。
- 测试 → 缝：新增主测试入口是 `Server.startCardStep`/`StepRunner.Run` 的工作流声明缝，调用链穿过 `ViaTemplate`；HTTP 断言入口是 `Client.Dispatch`。
- 缝 → 测：`ViaTemplate` 一次调用、`startCardStep` admission、`Client.Dispatch` JSON、`Manager.Dispatch` receiver binding、原子“RecordDispatch→LinkTask”事务 snapshot 五条缝各有上述测试断言；内部 helper 测试只可附加，不能替代它们。

```go
	SourceSeq int64
	Type string
	Payload []byte
	CreatedAt time.Time
}

type Options struct {
	Holder string
	Tick time.Duration
	LeaseTTL time.Duration
	Source Source
	LocalSource Source
	IsSelfTarget func(string) bool
}
```

`card_tasks` 仍只有既有五列；`TasksOf`/`AllTaskLinks` 将同卡 `EvDispatched` payload 按 `(Target, TaskID)` 匹配后填充 `TaskLink.Node`/`Attempt`。没有匹配快照、快照缺键或是旧 plain dispatch 时，Node/Attempt 保持空值，不从 task ID、target、purpose 或相邻事件猜测。新的 workflow dispatch 同时写非空 Node/Attempt；Attempt 就是返回 task ID。

`AppendMirroredEvent` 的 envelope 字节序列固定为：

```json
{"node":"review","attempt":"task-attempt-1","task_type":"question","payload":{"ticket_id":"task-attempt-1:q1"}}
```

source 三元组 `(source_target, source_task, source_seq)` 只作为 store 去重列；不得复制进 envelope、覆盖原 payload 或新增 cursor 文件。空 payload 必须编码为 JSON `null`，并与字段缺失区分。

### 5.2 当前 attempt 闸的精确行为

保留 `automationWakeEvent` 的任务类型映射，但在 `consumeAutomationEventsOnce` 把 `EvTaskMirrored` 交给它之前增加当前 attempt 检查：

1. 从该 card 的 `autoLedger.EventsFromAsc([]string{cardID}, fromSeq, limit)` 读取现有事件页，沿 `Seq` 继续读到尾部；解析 `EvDispatched` 的 `DispatchSnapshot`。
2. 只记录 `Node != ""` 且 `Attempt != ""` 的最新（最大 `Seq`）快照；同一 Node 的最新 Attempt 是当前 attempt。旧 plain dispatch、缺 node/attempt 的历史快照只作为不可路由兼容数据，不能猜成当前 workflow attempt。
3. 解包 `task_mirrored` 后，envelope 的 Node/Attempt 缺失或为空时不唤醒；Node 没有当前 dispatch 或 Attempt 与当前值不相等时只推进本次事件的已见集合，不 wake、不写 verdict、不写 acceptance；相等时才进入既有 `automationWakeEvent`。Malformed envelope 要返回带 seq/card/type 的错误。
4. `question`/`permission_request` 仍映射 `WakeTicket`；`completed`/`turn_failed`/`failed` 仍映射 `WakeTaskTerminal`，但这些结果绝不直接产生 pass/acceptance。`progress`、`approver_decision`、`approver_disabled` 不唤醒。
5. 当前 attempt 检查只使用 card ledger 事件与 envelope payload；source identity 的 `(target, task, seq)` 由 S2/store dedup 保证，S3 不增加或复制这些字段。

建议的私有解码边界必须保持可判定的缺失/空值语义：


## 6. DAG、真机清单与最终验收

### 6.1 串行 DAG

```text
S0（协调者执行：文件白名单、图入口、validate）
  → S1（共享派发：唯一 task/attempt、receiver wire、DispatchSnapshot）
    → S2（TaskLink 投影、task_mirrored envelope、source 去重/watermark）
      → S3（typed Reply、当前 attempt 消费闸、WaitEvent 与 mirror 分层、旧编排退役）
```

S1 交付唯一 task/attempt 与 Node 快照给 S2；S2 交付带 source identity、Node/Attempt 的 card event 给 S3；S3 只消费这些载体，不新增 wire/API。任一实现者不得跳过前置任务，也不得把 S0 的协调者验收派给执行者。

### 6.2 必须在真机/集成环境执行而不能由本计划虚报通过的清单

1. 真实远端 task 在 Transport 成功后、LinkTask 或 RecordDispatch 失败时的孤儿回收。
2. agentd、executor、协调者在 waiting_answer、终态、relay/直连切换窗口中的重启恢复。
3. PG/SQLite 并发 lease、唯一 source 三元组、watermark 与 projection-change cancel/re-subscribe 的实际锁行为。
4. TCP/WS/relay/直连下 `StreamEventsOnce` 的断线重连、300ms→10s 退避和事件不丢失。
5. 真实 AskResponder/RespondPermission 对合法、错 task、错 ticket、重复 answer 的送达与拒绝。
6. 消费者在批次失败、attach 暂缓、needs-human 升级和重启后的 cursor/seen 不自激、不丢事件。
7. 跨平台 HomeDir/receiver/executor 权限及不依赖 shell/HOME 的真实启动。

这些项目在实现阶段只能标“未验证，需真机”，不能用 fake transport、httptest 或图结果写成 pass。
