## 2. 已核验平台事实（出稿时亲跑；执行者按此写，勿凭记忆）

> 每条都有出稿台账 `docs/superpowers/ledgers/2026-09-28-b417.2-plan-ledger.md` 的原始读数。

1. **XCFramework 形状**：`dist/mobile/handoff-mobile.xcframework` 两 slice：
   `ios-arm64`、`ios-arm64_x86_64-simulator`；framework 名 `Handoff-Mobile.framework`；
   二进制是**静态库**（ar archive，fat）；Mach-O `minos 13.0`；导出 `_Bind*` 与 `_OBJC_CLASS_$_BindMachine`。
2. **Swift 消费方式 = 桥接头，不是 `import`**：`import Handoff_Mobile` 会失败
   （`no such module`），因为 modulemap 里模块名字面是 `Handoff-Mobile`（含连字符）。
   必须用 `#import <Handoff-Mobile/Handoff-Mobile.h>` 的 bridging header。
3. **必须关显式模块**：target 设 `SWIFT_ENABLE_EXPLICIT_MODULES = NO`，否则报
   `no module named 'main' declared in module map file '…/Handoff-Mobile.framework/Modules/module.modulemap'`。
4. **七函数在 Swift 里不是 throwing**（末参是 `NSErrorPointer`）：
   ```swift
   BindPair(_: String?, _: NSErrorPointer) -> Bool
   BindMachineCount() -> Int
   BindMachineAt(_: Int) -> BindMachine?
   BindOrigin(_: String?, _: NSErrorPointer) -> String
   BindSessionCookie(_: String?, _: NSErrorPointer) -> String
   BindSwitchMachine(_: String?, _: NSErrorPointer) -> String
   BindClose(_: NSErrorPointer) -> Bool
   ```
   必须 `var err: NSError?; …; if let e = err { throw e }`，**不要写 `try`**。
5. **iOS 27 必须采用 UIScene**：无 `UIApplicationSceneManifest` 时 App 启动即
   `EXC_BREAKPOINT`（`UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`）。
6. **Info.plist 不能放进同步文件夹**：会被当资源复制而报
   `Multiple commands produce …/HandoffMobile.app/Info.plist`。放 `Support/Info.plist`。
7. **cookie 构造坑（承重）**：`HTTPCookie(properties:)` 里**只要出现 `.secure` 键**（哪怕
   值是 `false`/`0`），得到的 cookie `isSecure == true`。要满足契约条 26（`Secure == false`）
   必须**完全不传 `.secure`**。`isSessionOnly` 默认 true（条 29）。`sameSitePolicy` 可设
   （`.sameSiteLax`）。
8. **HttpOnly 客户端不可设**：`NSHTTPCookiePropertyKey` 无 HttpOnly 键，`HTTPOnly` 是只读属性。
   契约条 27（`HttpOnly == true`）**当前平台不可达成**——见 §9 残余落账，不得静默判 pass。
9. **`deleteAllCookies()` 无完成回调**；`getAllCookies` / `delete` / `setCookie` 有 completion。
   要「清罐完成再注入」的确定序，用「枚举全部 → 逐个 `delete` + `DispatchGroup` → notify」。
10. **scheme 无需提交**：`xcodebuild` 会由 target 自动生成 scheme。
11. **同步文件夹**：`objectVersion = 77` + `PBXFileSystemSynchronizedRootGroup`，后续 task
    新增 `.swift` **不用改 pbxproj**（已实测）。
12. **`@testable import HandoffMobile` 可用**得靠 app target Debug 的 `ENABLE_TESTABILITY = YES`。
13. **模拟器 Keychain 需签名宿主**：`CODE_SIGNING_ALLOWED=NO` 的未签名 App 无 keychain
    entitlement，`SecItemAdd/Delete/CopyMatching` 全数返回 `errSecMissingEntitlement(-34018)`；
    测试须以 ad-hoc 签名跑（`CODE_SIGNING_ALLOWED=YES CODE_SIGN_IDENTITY=-`）。签名后仍有平台
    差异：**未设 `kSecAttrSynchronizable` 的条目回读为 `0`（非 nil）**——条 13 判据须表述为
    「不存在 Synchronizable==true」（不得云同步），不能断言键为 nil。（修订，见 Task 3）

### 4.4 内部锁声明（占位符扫描节）

内部锁默认非法；以下每条给出「从声明缝构造不出该断言 + 为什么」：

1. `MachineListModel.enter`：契约条 32 要求「点击离线机**不触发** `SwitchMachine`/`load`」——
   断言的是「**不**进入 S3」；从 S3（`CookieBridge.enter`）构造只会得到「已进入」，
   构不出「未进入」。生产调用方是 `MachineListViewController`，故测 `MachineListModel.enter`。
2. `ExpiryDetector.isExpired`：条 34 的过期由 webview 的 `WKNavigationDelegate` 回调经 401 状态码
   观测（拆解 §2.4 澄清 3）；这是 UIKit 生命周期事件，从任何声明缝都构造不出，故把判据抽成纯函数单独测。
3. `ErrorClassifier.classify`：条 35 要求按「失败调用点」归类且不解析文案；分类是 S3/S4 的内部实现点，
   从缝入口只能观察到最终 `ShellError`，故并测分类函数与缝错误路径。
4. `SourceGuardTests`：条 3/4/31/36/37 是**源码负向**断言，非运行时行为；无任何缝能表达
   「源码里不出现某符号」，故以静态扫描锁。

无其它内部锁；无误用「更短/更纯/无 IO」当理由的降格。

  import Foundation
  import Security

  // 安全存储缝（I2）。生产 = KeychainSecureStore；测试可注入假实现。
  protocol SecureStore: AnyObject {
      func save(_ value: String) throws
      func load() throws -> String?
      func delete() throws
  }

  struct KeychainError: Error { let status: OSStatus }

  // Keychain 实现（I2 / contract §4.3 条 11/13）：
  // - kSecClassGenericPassword；service/account 固定；
  // - kSecAttrAccessible = kSecAttrAccessibleWhenUnlockedThisDeviceOnly；
  // - 不设 kSecAttrSynchronizable（不跨设备同步，条 13 负向）。
  // 存的是**原始 bundle 字符串**（条 10/11），不解析、不改写。
  final class KeychainSecureStore: SecureStore {
      private let service: String
      private let account: String

      init(service: String = "dev.handoff.HandoffMobile.pairbundle",
           account: String = "pair_bundle") {
          self.service = service
          self.account = account
      }

      private func baseQuery() -> [String: Any] {
          [kSecClass as String: kSecClassGenericPassword,
           kSecAttrService as String: service,
           kSecAttrAccount as String: account]
      }

      func save(_ value: String) throws {
          let data = Data(value.utf8)
          try delete()   // upsert：先删旧值
          var q = baseQuery()
          q[kSecValueData as String] = data
          q[kSecAttrAccessible as String] = kSecAttrAccessibleWhenUnlockedThisDeviceOnly
          // 负向（条 13）：不写 kSecAttrSynchronizable。
          let status = SecItemAdd(q as CFDictionary, nil)
          guard status == errSecSuccess else {
              Log.shell.error("Keychain 写入失败 status=\(status, privacy: .public)")
              throw KeychainError(status: status)
          }
          Log.shell.info("Keychain 写入配对串成功 bytes=\(data.count, privacy: .public)")
      }

      func load() throws -> String? {
          var q = baseQuery()
          q[kSecReturnData as String] = true
          q[kSecMatchLimit as String] = kSecMatchLimitOne
          var out: CFTypeRef?
          let status = SecItemCopyMatching(q as CFDictionary, &out)
          if status == errSecItemNotFound { return nil }
          guard status == errSecSuccess, let data = out as? Data else {
              Log.shell.error("Keychain 读取失败 status=\(status, privacy: .public)")
              throw KeychainError(status: status)
          }
          Log.shell.debug("Keychain 读回配对串 bytes=\(data.count, privacy: .public)")
          return String(data: data, encoding: .utf8)
      }

      func delete() throws {
          let status = SecItemDelete(baseQuery() as CFDictionary)
          guard status == errSecSuccess || status == errSecItemNotFound else {
              throw KeychainError(status: status)
          }
      }
  }
  ```

  // 配对缝（contract §3.2）：扫码与粘贴**归一**到 pair(bundleJSON:)。
  // 成功 → 原始 bundle 写安全存储 + 核登记机器；失败 → 不落存储、不进列表（I1/I2）。

  final class PairingService {
      private let core: ConnectCore
      private let store: SecureStore

          self.core = core
          self.store = store

      // 唯一配对入口。仅去首尾空白，其余逐字透传给 Go 核（条 10），

      // 任一步失败抛 ShellError.pairing，调用方不得进列表（条 8/9）。
      func pair(bundleJSON raw: String) throws {
          let bundle = raw.trimmingCharacters(in: .whitespacesAndNewlines)
          Log.shell.info("配对入口载荷 bytes=\(bundle.utf8.count, privacy: .public)")
          do {
              try core.pair(bundle)

              throw ShellError.pairing(String(describing: error))
          }
          do {
              try store.save(bundle)
          } catch {
              Log.shell.error("配对串写入安全存储失败")
              throw ShellError.pairing(String(describing: error))
          }
          Log.shell.info("配对成功且已持久化")
      }

      // 启动路径（I2 条 15/16）：有存储 → Pair(stored) 返回 true；无 → false。

      func pairFromStoredBundle() throws -> Bool {
          guard let stored = try store.load() else {
              Log.shell.info("无已存配对串：走配对屏")
              return false
          }
          try pair(bundleJSON: stored)
          return true
      }
  }

  import Foundation
  import WebKit

  // 导航加载缝（测试可注入假 loader 断言「失败不 load」）。
  protocol OriginLoader: AnyObject { func load(origin: String) }

  final class WKWebViewOriginLoader: OriginLoader {
      private let webView: WKWebView
      init(webView: WKWebView) { self.webView = webView }
      func load(origin: String) {
          guard let url = URL(string: origin) else {
              Log.shell.error("origin 非法，放弃导航")
              return
          }
          webView.load(URLRequest(url: url))
      }
  }

  // cookie 罐缝：生产包装 WKHTTPCookieStore，测试注入假实现。
  protocol CookieJar: AnyObject {
      func allCookies(_ completion: @escaping ([HTTPCookie]) -> Void)
      func delete(_ cookie: HTTPCookie, completion: @escaping () -> Void)
      func set(_ cookie: HTTPCookie, completion: @escaping () -> Void)
  }

  // 为什么清罐用「枚举 + 逐个 delete」而非 deleteAllCookies()：
  // deleteAllCookies 无完成回调，无法保证「清完再注入」；逐个 delete 有 completion，
  // 用 DispatchGroup 汇聚成确定性完成信号（contract §3.4 以可观测不变量为准，机制归子卡）。
  final class WebKitCookieJar: CookieJar {
      private let store: WKHTTPCookieStore
      init(store: WKHTTPCookieStore) { self.store = store }
      func allCookies(_ completion: @escaping ([HTTPCookie]) -> Void) { store.getAllCookies(completion) }
      func delete(_ cookie: HTTPCookie, completion: @escaping () -> Void) {
          store.delete(cookie, completionHandler: completion)
      }
      func set(_ cookie: HTTPCookie, completion: @escaping () -> Void) {
          store.setCookie(cookie, completionHandler: completion)
      }
  }

  // 壳注入 cookie 的固定属性（contract §3.4）。name 与 agentd auth.go:29 对齐（条 31）。
  enum ShellCookie {
      static let name = "handoff_session"
      static let domain = "127.0.0.1"
      static let path = "/"

      // 平台坑（已核）：显式传 .secure（任何值）会让 isSecure 变 true——
      // 要 Secure=false（条 26）必须**不设** .secure 键。
      // HttpOnly 客户端不可设（只读属性，无 property key）→ §9 残余。
      static func make(value: String) -> HTTPCookie? {
          let props: [HTTPCookiePropertyKey: Any] = [
              .name: name,
              .value: value,
              .path: path,
              .domain: domain,
              .sameSitePolicy: HTTPCookieStringPolicy.sameSiteLax,
          ]
          return HTTPCookie(properties: props)
      }
  }

  // CookieBridge —— 拥有唯一 WKWebView 与其 httpCookieStore，实现 I3 承载调用序。
  // 被「机器列表屏·进入」（MachineListModel ← MachineListViewController）调用。
  // 单槽：任何时刻一罐只装一机 cookie（I3）。
  final class CookieBridge {
      let webView: WKWebView
      private let core: ConnectCore
      private let jar: CookieJar
      private let loader: OriginLoader

      // 生产装配：本类拥有 webView 与其 cookie store。
      convenience init(core: ConnectCore) {
          let config = WKWebViewConfiguration()
          let webView = WKWebView(frame: .zero, configuration: config)
          self.init(core: core,
                    jar: WebKitCookieJar(store: config.websiteDataStore.httpCookieStore),
                    loader: WKWebViewOriginLoader(webView: webView),
                    webView: webView)
      }

      // 测试缝：注入假 jar / 假 loader。
      init(core: ConnectCore, jar: CookieJar, loader: OriginLoader, webView: WKWebView = WKWebView()) {
          self.core = core
          self.jar = jar
          self.loader = loader
          self.webView = webView
      }

      // I3 承载调用序：SwitchMachine → 清罐（等完成）→ SessionCookie → 注入（等完成）→ load。
      // 任一步失败：completion(.failure) 且绝不 load（条 21）。离线直接拒绝、不触碰核（条 32）。
      func enter(machine: String, online: Bool, completion: @escaping (Result<Void, ShellError>) -> Void) {
          guard online else {
              Log.shell.error("拒绝进入离线机器 name=\(machine, privacy: .public)")
              completion(.failure(.offline(machine)))
              return
          }
          Log.shell.info("进入机器 name=\(machine, privacy: .public)")
          let origin: String
          do {
              origin = try core.switchMachine(machine)
          } catch {
              Log.shell.error("切机失败 name=\(machine, privacy: .public)")
              completion(.failure(ErrorClassifier.classify(.switchMachine, machine: machine, online: online)))
              return
          }
          clearJar { [weak self] in
              self?.inject(machine: machine, origin: origin, completion: completion)
          }
      }

      private func clearJar(completion: @escaping () -> Void) {
          jar.allCookies { [weak self] cookies in
              guard let self else { return }
              guard !cookies.isEmpty else {
                  Log.shell.debug("cookie jar 已空")
                  completion()
                  return
              }
              let group = DispatchGroup()
              for c in cookies {
                  group.enter()
                  self.jar.delete(c) { group.leave() }
              }
              group.notify(queue: .main) {
                  Log.shell.debug("清罐完成 count=\(cookies.count, privacy: .public)")
                  completion()
              }
          }
      }

      private func inject(machine: String, origin: String,
                          completion: @escaping (Result<Void, ShellError>) -> Void) {
          let value: String
          do {
              value = try core.sessionCookie(machine)
          } catch {
              Log.shell.error("取会话 cookie 失败 name=\(machine, privacy: .public)")
              completion(.failure(ErrorClassifier.classify(.sessionCookie, machine: machine, online: true)))
              return
          }
          guard !value.isEmpty, let cookie = ShellCookie.make(value: value) else {
              Log.shell.error("会话 cookie 为空/不可构造 name=\(machine, privacy: .public)")
              completion(.failure(.exchange(machine)))
              return
          }
          jar.set(cookie) { [weak self] in
              guard let self else { return }
              Log.shell.info("cookie 注入完成并导航 name=\(machine, privacy: .public)")
              self.loader.load(origin: origin)
              completion(.success(()))
          }
      }
  }
  ```

## 7. 缺陷族对抗结论（iOS 专项，对照拆解 §5.1/§5.3）

1. **生命周期/状态机中断**：Go 核为 `AppComposition` 单例，Scene/VC 重建不重复建核
   （条 38）；`Close()` 只在 `applicationWillTerminate`（条 39）。清罐/注入的异步中间态用
   DispatchGroup 串成严格序，回调未完成即不 `load`（条 19/21，`testClearNeverCompletesMeansNoLoad`）。
2. **静默失败/误导报错**：四类错误（pairing/offline/exchange/expired）都有 UI 标题+提示+重试；
   任一步失败不 `load`（反面断言）；401 → 过期错误态而非空白（条 33/34）。日志不记凭据（条 18）。
3. **跨平台假设**：明文回环 → ATS 最小放行 `NSAllowsLocalNetworking`（P6甲）；IP host cookie 由
   `HTTPCookie(properties:)` 接受（已实测创建成功，`domain=127.0.0.1`）；`SameSite=Lax` 可设。
   **未验证项**（真机/竖切）：`WKHTTPCookieStore` 对 host-only/非 Secure/IP cookie 的**真实接受回路**、
   ATS 对 `http://127.0.0.1:<port>` 的放行效果（§9）。
4. **假红/假绿**：假 jar 真持可查询 `cookies` 集合，删后为空、注入后仅一机；断言统一调用序
   （`CallRecorder`）；失败路径断言**未 load**、离线断言**未 switchMachine**。换 webview 封装只要
   序与属性不变仍绿（锁的是行为非帮手）。
5. **门禁绕过**：只调七函数（SourceGuard 正则 + 负向断言）；Keychain 不 `Synchronizable`（测试断言 +
   探针）；无自建 HTTP/Dial/ticket；不解析 bundle（SourceGuard）。
6. **序列化边界**：bundle 是整体字符串，壳只 trim 透传，`PairingServiceTests` 断言存/取逐字节相等
   （条 10/17）；cookie value 来自绑定面，`ShellCookie.make(value:)` 用平台 API 构造、不手拼串，
   `testInjectedCookieAttributes` 断言 value 逐字等于返回（条 30）；cookie 属性逐键断言（条 23–30）。
7. **枚举新值过白名单**：壳不引入跨进程枚举；错误分类 `switch` 无 default 吞值（穷举四类）。
8. **承重安全属性有测试锁住**：一罐一机/清罐序、fail-closed、凭据不落日志/不云同步、cookie 逐键、
   value 不伪造——均有能变红的测试或源码 guard。

## 9. 残余落账与未决点（必须显式认账；不得静默判 pass）

1. **契约条 27（注入 cookie `HttpOnly == true`）在 iOS 平台不可达成**：`NSHTTPCookiePropertyKey`
   无 HttpOnly 键，`HTTPCookie.HTTPOnly` 只读。plan 的 `ShellCookie.make` 只设可设属性；
   `testInjectedCookieAttributes` 不为条 27 判 pass。**需协调者裁决**：接受「客户端注入 cookie 非
   HttpOnly」并回写 contract §4.5 条 27（或改由服务端 Set-Cookie 路径），不得由执行者自改冻结物。
2. **`WKHTTPCookieStore` 真实接受回路未验证**：host-only / `Secure=false` / IP host cookie 经
   `setCookie` 后能否被 `getAllCookies` 读回、能否随 `http://127.0.0.1:<port>/` 请求发出。
   归父卡 I 的模拟器竖切（拆解 §6.3 / contract §8.3）。
3. **ATS 放行未验证**：`NSAllowsLocalNetworking` 是否足以让 `http://127.0.0.1:<port>` 在 WKWebView 加载；
   归父卡 I（拆解 §6.5）。
4. **模拟器 Keychain 行为与真机差异**：`WhenUnlockedThisDeviceOnly` 在模拟器不体现锁语义；
   归真机（拆解 §6.4；本卡只锁属性设置与往返）。
5. **P5（Android 专属）不适用于本卡**：`EncryptedSharedPreferences`/minSdk 冲突是 B417.1 的问题；
   本计划不涉。
6. **`mobile/README.md` 旧读数订正（P7）**：归父卡 I / 协调者；本卡只写 `mobile/ios/README.md`，
   不改 `mobile/README.md`（越界）。
7. **扫码真实运行未跑**：`QRScannerViewController` 在模拟器无摄像头（`isCameraAvailable=false`），
   扫码路径的归一由 `PairEntry` 与粘贴共用、经 `PairingServiceTests` 覆盖；相机运行归真机（OOS）。
