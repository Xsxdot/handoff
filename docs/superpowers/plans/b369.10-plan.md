## 0. 本卡干什么（一段话）

原型在盘（`0dbe57a1`，12 张移动屏 + 2 张桌面镜像），本卡按 spec §1 的三类差距清单做消费侧重组（`/api` 零新增）：①键条 8 键浅色扩为原型 12 键暗色 + Ctrl 粘滞（翻案 B369.9 两处口径，逐条记台账）；②项目 tab 列表层升格逐位置芯片 + 主点击进详情（有因翻案 B369.8 折叠主通道），新建移动项目详情面（locbar 位置平级 + 工作树卡双动作 + 终端会话区 + 建工作树）；③任务现场加 Shell 层钉顶裁决横幅（切三段不丢）+ compact 审阅面全宽；④会话首页「需要你|全部」chips + 行内成员横排/群主行；⑤群聊顶部「本会话的卡」横排；⑥卡详情双跳行 + 验收区行式（整卡语义保持）；⑦FileTab compact 只读化 + FileTree compact 行式；⑧设置 hub 行文对齐（就地呈现保留）。全部 compact 增量以 prop 注入隔离，桌面 JSX 逐字节不动；两处对已落卡验收口径的翻案（键条横滑、折叠主点击）与全部无法落地偏离逐条落卡台账。

## 2. 岔口裁决（spec §3.3 指定归 plan 的八条 → 决定 + 理由）

### 岔口 1：项目详情 URL 参数名与返回链

**决定：参数名 `project`，值为 `ProjectNode.project_id`；挂 `tab=projects` 语境；导航语汇五处增量，全部沿 `dir` 的既有纪律同形。**

- 派生：`nav.projectId: string | null`——`compact ? params.get('project') : null`（桌面恒 null，与 sub 同款 `:107` 写法）。project_id 是不透明 id 无法白名单，非法值自愈 = 树上反查不到 → 详情层不渲染、列表照常（与 dir「键失效 → 覆盖层不渲染」同款，`Shell.tsx:188-191` 先例）。
- 新 setter `setProject(key: string | null)`：开 = push `/?tab=projects&project=<id>`（fresh URL，projects tab 上无其他合法参数，幂等形态；同 setDir 开侧 `:205-208`）；关 = replace strip project 留其余参数（同 setDir 关侧 `:195-203`）；桌面直通 no-op。埋点 `shell.mobile_nav.project_open/project_close` 对齐既有纪律。
- **与 `dir` 的叠加与逐级返回链**（覆盖层 z 序天然成立：mobile-dir 在 main 层、详情层在 mobile-home 内，见岔口 2）：
  - 列表 → 详情：`setProject(id)`（push）。
  - 详情 → 浏览文件：详情面双动作走 `onOpenDirectory(base)` → `nav.setDir(base.key)`——**setDir 开侧改为携带 project**（`p` 构造时保留现 URL 的 project 参数；dir 与 project 同属 projects tab，不互斥）。
  - 浏览文件 → 返回：`setDir(null)` strip 模式天然保留 project → 回详情。
  - 详情 → 打开终端/点任务 → 下钻：`enterDetail` **随行 project**（`:163-165` dir 随行的同款三行，紧随其后加 `const project = params.get('project'); if (project) p.set('project', project)`）。
  - 下钻 → 返回条兜底：`exitDetail` **保留 project**（`:181-183` 留 tab/dir 的同款补一项）。
  - 详情 → 返回列表：返回钮 `setProject(null)`（replace）。
- normalize ③ 增一条：`!isCards && p.has('project') && p.get('tab') !== 'projects'` → delete（`dir` 清理 `:275-278` 的同款，多 `!isCards` 前置——因为 /cards 宿主的 `project` 是看板筛选、合法消费中）。
- **openCard 保留条件收紧（本岔口唯一一处既有行为修正）**：`:223-225` 的无条件 `project` 保留改为 `location.pathname === '/cards'` 时保留、否则 delete。理由：保留条款的注释 rationale 是「从带 project 参数的**看板**点开卡」——/cards 宿主；新增 `/` 宿主 project 详情参数若被无条件带进 `/cards?project=…` 会静默改写用户的看板筛选。这不是翻案（`useMobileNav.test.tsx:170` 既有用例是 /cards 场景，行为不变），是把保留条款精确到它的注释语义上，正反两用例都补（§5 T1）。
- 词表/类型：`projectId: string | null` 入 `MobileNav` 接口与文件头 URL 语汇注释（`/`：tab/detail/dir/from/sub/project）；`MobileFrom`、`SETTINGS_SUB_KEYS`、enterDetail/exitDetail 返回链语义零改动。

### 岔口 2：项目详情面组件形状 + 终端会话区数据口径

**决定：新建 `web/src/app/tree/MobileProjectDetail.tsx`（本卡唯一新组件文件）；在 mobile-home 的 projects 分支内以 absolute 覆盖层呈现（ProjectTree 保挂载在下层）；终端会话区数据口径取存量 `fetchPtySessions('all')`，不用 `wb.openedItems`。**

### 岔口 3：Ctrl 粘滞的 handler 复合方式

**决定：候选 A——terminalInput.ts 增加可选链式入口（粘滞合成复合进既有 handler）；否掉候选 B（状态外提、TerminalTab 自挂第二路监听）。两者都不新增 terminal\* 文件，无须回 spec。**

- **理由（排除法）**：`terminalInput.ts:14-16` 文件头的处方原文就是「将来若有别处要用这个钩子，**必须改成本模块转发**，而不是各挂各的」——链式入口正是这条处方的落地形态；候选 B 要在 TerminalTab 再挂一路 host-capture keydown，与 xterm 的 textarea 监听、terminalInput 的 host capture（`:282-287`）形成**注册序耦合**（同元素同阶段按注册先后跑，先后关系是隐式时序不是显式契约），且把键盘事件琐务散进 746 行的 TerminalTab。A 的代价只是 terminalInput 多一个可选参数与若干行，测试 harness 现成（`terminalInput.test.ts` 合成事件）。
- **合同形状**：`installTerminalInputFix(term, host, label, hooks?: { stickyCtrl?: { armed(): boolean; consume(): void } })`。custom handler（`:217`）keydown 分支**最前**增一段：`hooks?.stickyCtrl` armed 且 `ev.type === 'keydown'` 且 `ev.key.length === 1` 且为字母（`/[a-z]/i`）且无 alt/meta 修饰 → `preventDefault + stopPropagation`、`term.input(String.fromCharCode(ev.key.toLowerCase().codePointAt(0) - 0x60))`（Ctrl-D=EOF、Ctrl-R=反搜…大写按小写合成）、`consume()`、`return false`。armed 期间非字母键（Enter/方向/物理 Ctrl-C）一律不拦，原路径不动。单字符判据复用既有「不误伤真按键」的保守方向。
- **armed 状态归属与解除**：state 住 `TerminalTab`（每终端独立，切 tab/关 tab 天然复位）——`ctrlArmedRef + state`；TerminalTab 把 `{ armed: () => ctrlArmed, consume: () => setCtrlArmed(false) }` 传给 `installTerminalInputFix`，把同一 state 经 props 给 MobileKeybar。解除时机：合成动作完成后（系统键盘字母 = terminalInput `consume()`；键条组合 = TerminalTab onKey 内合成后自清）；再点一次 Ctrl 键位解除（MobileKeybar toggle）。
- **键条键 × 粘滞的组合**：在 TerminalTab 的 `onKey` 处理器（`:702-707`）里做（它持有 armed state，MobileKeybar 保持不认识 xterm）：armed 且键为方向 → 发 CSI 修饰序列 `\x1b[1;5A/B/C/D` 并解除；armed 且其他键 → 原序列原样（|、~、⌫、Tab 等不是「打不出的组合」，不放大语义）。系统键盘字母的组合在 terminalInput 内（上段）。两条路径都只走 `term.input`（合流纪律不变）。
- **Ctrl-C 保持直发 `\x03`**（spec §2.1 法定）：'ctrl-c' 键位不经 armed 判据，armed 与否都直发且不解除 armed。
