### T7.2 实现：room.go + rebind + dispatch 指针 + client.Inbox（内部实现步骤，不配独立红绿）

**Interfaces**

- Produces（本卡新导出符号，均入图，见 T7.4）：
  - cmd：`openRoomService() (*collab.Service, *ledger.Store, error)`、`dispatchPointerBody(id, nodeLabel string) string`、`roomPointer`（seam var）+ `swapRoomPointer(fn) func()`；命令闭包 `roomListCmd.RunE`/`roomReadCmd.RunE`/`roomSendCmd.RunE`/`roomInboxCmd.RunE`/`cardRebindCmd.RunE`
  - client：`func (c *Client) Inbox(ctx context.Context) ([]proto.InboxItem, error)`
- Consumes：见 T7.1 Interfaces 表（逐字）。

**行为语义（实现前读三遍）**

1. `openRoomService` 是 CLI 侧组装点（target.json assembly 登记点语义）：`openLedger()` → `collab.New(ledgerapi.New(st))`。房间命令族共用，调用方 `defer st.Close()`。
2. `room send` 默认 `--kind user`（flag 默认值 `proto.RoomMsgUser`），actor=`ledgerActor()`；输出 `{"ok":true,"seq":<n>}`。
3. `room read` 每行 `#<seq>\t<actor>\t<body>`；`--after` 直通 `History.beforeSeq`（排他）。

// Inbox 拉取待回复收件箱（B156.2 C7）：room inbox 走 agentd HTTP /api/inbox
// （breakdown 岔口三裁决——ticket 源判据 Hub.Watchers(taskID)==0 是 agentd
// 进程内快照，CLI 本地重算会让所有等待工单全量误上浮）。三源聚合在服务端
// 编排单元（C6），本方法只做传输与解码，不含业务判断。
func (c *Client) Inbox(ctx context.Context) ([]proto.InboxItem, error) {
	resp, err := c.do(ctx, http.MethodGet, "/api/inbox", nil)
	if err != nil {
		return nil, fmt.Errorf("连接 agentd %s 失败（它在运行吗？可先执行 handoff status 确认）: %w", c.baseURL, err)
	}
	defer resp.Body.Close()
	if resp.StatusCode != http.StatusOK {
		return nil, c.httpError("拉收件箱", resp)
	}
	var out []proto.InboxItem
	if err := json.NewDecoder(resp.Body).Decode(&out); err != nil {
		return nil, fmt.Errorf("解析收件箱: %w", err)
	}
	return out, nil
}

## 4. 缺陷族对抗审查结论（逐族）

| 族 | 设问 | 结论 |
| --- | --- | --- |
| 生命周期/状态机中断 | 派发指针写在 `ViaTemplate` 成功之后——若 dispatch 失败（含中途 release 回滚）指针不写，账本无半状态；指针写失败不打断派发（判据二锁）。room inbox 依赖 agentd 在线——agentd 不可达时 `client.Inbox` 报 ErrUnreachable（client.go:437），CLI 返回非零，不静默；C6 未落地前 /api/inbox 不存在会 404，`httpError` 报错可见，不误判成功 | 无静默孤儿 |
