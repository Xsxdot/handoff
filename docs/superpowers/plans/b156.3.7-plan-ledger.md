### 追加 Task C，并显式扩张有界文件集

复核时按对方卡线的实测教训核了一条本卡没有的判据，缺口属实，故追加 Task C（正文见
plan §4）。要点：

- **缺口**：`ensureSchema` 的 DDL 分 PG / SQLite 两块写。同一张表在两块里各写一遍时，
  合并冲突**只会在其中一块报出来**，另一块被 git 静默合上——它把注意力精确地吸到安全
  的那一半。而本卡 Task A 的 PG 腿无 DSN 时 `t.Skip`，所以「一个方言有表另一个没有」
  在日常 `go test ./...` 里**恒绿**，要等真 PG（很可能是生产建表）才炸。
- **判据形状**：不写「registry 表在不在」（只保护写判据那天想到的那一张），写
  **两个方言的表名集合相等**——以后任何人往任一块加表漏掉另一块都当场翻红，判据不用改。
- **不用行号当判据**：PG 264–269 / SQLite 339–344 只做定位，行号会漂（B228 那 500 个
  行号漂移就是这么来的）。
- **牙齿证明**：变异复验必做——从 PG 支删掉 registry 建表语句，测试必须翻红并点出
  「只在 SQLite 有：registry」。这条**无条件跑、不依赖 DSN**，正是 Task A 的 PG 腿
  覆盖不到的那半。

**扩张是协调者做的，不是执行者越界**：原有界文件集只含 `registry_pg_test.go` 与
`registry.go`，Task C 需要动 `store.go`（一次行为保持的提取重构）并加一个新测试文件。
按纪律「确需越出有界文件集就是拆解错了、要停下提问」，此处由我作为拍板者当场扩张并
写明范围与理由，实现票照此执行不必再问。等价性自证要求写在 Task C 验收里（搬运行之外
无字符改动，用 `git diff` 自证）。
