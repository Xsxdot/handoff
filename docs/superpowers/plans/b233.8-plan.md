~~~go
func (m *Manager) bindApproval(taskID string, snap executor.PolicySnapshot) executor.ApprovalClient {
	if snap.TaskID == "" {
		snap.TaskID = taskID
	}
	return approval.NewClient(taskID, snap, approval.Hooks{
		Log:             m.log,
		Store:           m.st,
		Hub:             m.hub,
		JudgePermission: m.judgePermission,
		ShouldConsult:   m.shouldConsultApprover,
		Decide: func(ctx context.Context, permission, summary string) approval.ConsultDecision {
			if m.approver == nil {
				return approval.ConsultDecision{Err: errors.New("审批者不可用")}
			}
			d := m.approver.Decide(ctx, permission, summary)
			return approval.ConsultDecision{
				Approve: d.Approve, Reason: d.Reason,
				ElapsedMS: d.ElapsedMS, Err: d.Err,
			}
		},
		CountConsultFailure: m.countApproverFail,
		ResetConsultFailure: func(id string) {
			m.apMu.Lock()
			defer m.apMu.Unlock()
			delete(m.apFails, id)
		},
		AutoAllow:          m.autoAllowPermission,
		TransitBestEffort:  m.transitBestEffort,
		NoteDeliveryFailed: m.NoteDeliveryFailed,
	})
}
~~~

### 2.3 生产实现行为映射

将现有 taskApprovalClient 的每个方法逐一迁移为 Client 方法，只有依赖访问方式改变：

| 旧方法 | 新方法必须保留的行为 |
| --- | --- |
| PolicySnapshot | 返回绑定 snapshot；NewClient 只补空 TaskID。 |

| Await | 先读 Store 已落答案；没有终态才调用 Hub.WaitAnswer；WaitAnswer 出错时再读 Store，若答案已在取消窗口落库则返回它，否则保留原 context/error；成功答案按原 gateDecision 语义映射。 |

## 8. 缺陷族对抗审查

### 8.1 d_orchestration（logic）

- **生命周期/状态机中断**：Ticket、Await、Ack 仍以 Store 为权威；context 取消后重读 Store 的窗口由 `TestClientAwaitReadsStoreAfterCancel` 锁住；未验证真实 agentd 重启、孤儿 waiter、任务目录回收，列真机清单。
- **静默失败/误导报错**：Hooks 缺失、CreateTicket/AppendEvent/MarkDelivered/Decide 错误必须保留原错误或返回 pending/deny，不得返回 allow；新增 Client 测试逐条检查工单、事件、delivered_at 与 allow 的对应关系；日志必须含 task/ticket/native/cause。
- **跨平台假设**：迁移只在进程内使用 Store/Hub/Hook，不启动外部进程、不解析新 OS 路径，因此本卡无新增平台假设；Approver 与文件系统的真实差异列真机清单。
- **假红/假绿**：internal/approval/client_test.go 的直接入口锁 Client 内部安全分支，但 Manager/SQLite/Dispatch/Continue/Resume 接缝另由 agentd 测试锁定；不能只测空壳、深 mock 或旧类型存在。
- **门禁绕过**：唯一生产组装仍是 Manager.bindApproval；新包无 agentd 回边、无旁路 Store 写入；同 task/version/fingerprint/送达门槛、TaskID namespace、重复请求均有真实 Store 负例。

### 8.2 d_execution（boundary）

- **生命周期/状态机中断**：adapter 只持有注入 client，不能替外部会话做恢复/清扫；冷/热 Resume 只在机内断言请求 Approval 非 nil，真实 executor 重启和 session 回收未验证，列真机清单。
- **静默失败/误导报错**：executor.Authorize 错误必须 reject；RespondPermission 失败必须 optional-report delivery failure，不能 AckDelivered/AckExecuted；缺 reporter 只能 Error 日志，不能伪造成功；既有 OpenCode 负例测试锁住每个窗口。
- **跨平台假设**：OpenCode HTTP/SSE、CLI、信号与 session 恢复未因迁包获得跨平台证明；Linux/macOS/Windows 真机分别抽查，机内 fake 不推广。
- **假红/假绿**：adapter 测试使用 ApprovalClient 契约形状和真实 authorizeNativePermission，不依赖旧 concrete type；真实 permission.asked、非 2xx 与 ack 顺序机内可验，外部服务真实响应未验。
- **门禁绕过**：internal/executor/opencode 不 import agentd/permgate、不写 Store；BindApproval 只替换对应 task client，跨 task 绑定隔离由现有测试与 Client.NoteDeliveryFailed task 校验覆盖。

## 10. 真机清单（本计划不声称已验证）

以下由协调者在 acceptance/真机环境执行，机内测试结果不得写成真机绿：

1. 真实 OpenCode 分别走 Dispatch、Continue、冷 Resume、agentd 启动热恢复，记录 Start/Resume 的 Approval 非 nil，并确认 Continue 的新 PolicySnapshot 作用于真实 serve。

5. 至少一个非 OpenCode harness 真实派发权限与提问，确认仍走 handlePermission/handleQuestion/waitQuestion。
6. 在实际支持的 Linux、macOS、Windows 平台抽查 scope、HOME、权限 URL、进程/session 恢复；一个平台的绿不得推广。
7. 真实 POST /api/tasks 与 CLI handoff dispatch 各走一次，确认旧生产入口仍可创建任务。
