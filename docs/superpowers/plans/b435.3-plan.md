## 6. 风险对抗补充（本稿新增，不在拆解 §5.3）

- **通知与 attach 暂缓**：消费循环的 attach 暂缓分支会提前 `return` 整轮——Q6 甲的调用点在逐事件循环里、早于任何批次处理，同一轮已读到的事件在 return 前都已过通知器；未读到的下轮再读。执行者在 `…SecondRoundNoResend` 里加一个 attach 暂缓变体（或在台账写明为何无须）。
- **handled 集增长**：与 `automationSeen` 同量级（每事件一项）；执行者可按游标裁剪 `seq <= cursor` 的项，须测试锁住「裁剪后不重发」（认领已终局兜底）。
- **通知自身是房间消息**：它回到同一消费循环 → `roomMessageWakeEvents` → `Recipients` 显式分支 → 驻场者地址 → 零 Wake（C-231），且源类型不在三类之内，不会再生通知——`…CardCreatedExactlyOne` 两轮后消息数仍 1 即锁住无回环。
