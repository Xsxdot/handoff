# B358.8 走查反馈修复批：会话页 8 项交互缺陷——实现计划

- 父卡：B358；spec：`docs/superpowers/specs/b358.8.md`（唯一需求来源）

## 0. 本卡干什么（一段话）

acceptance 真机走查产出 8 项会话页交互缺陷：左侧会话列表拖不出分屏、回复与 @ 无快捷入口、

## 2. 共享基建复用判断（spec #1 指定 plan 轮回答）

**结论：复用 workbench 既有拖拽机制，不另起炉灶。**

- `paneDrop.ts` 的五区投影（`dropZoneAt`）与 `WorkbenchPage` 的落点高亮（`drop-left/right/top/bottom/center` 遮罩）是内容无关的——新 MIME 挂进白名单即自动获得「可放置视觉提示」，spec #1 的提示要求零成本满足。
- `placeSource` 已覆盖「边缘=新列/上下分格（分屏）、center=填充空格或替换占位、组内多格」全部布局迁移语义；会话 drop 无需改 `tabs.ts` 布局模型。
- 复用入口（新增/改动点）：
  1. `paneDrop.ts`：`DRAG_SESSION_MIME = 'text/handoff-session'` + `readDragSession`（解析 `{sessionId,title}`，两字段非空字符串，坏载荷返 null——与 `readDragTab` 同款纪律）。
  2. `SessionSidebar`：行加 `draggable` + `onDragStart` 写 MIME 载荷、`effectAllowed='move'`。
  3. `WorkbenchPage`：pane `onDragOver` 的 MIME 白名单加 `DRAG_SESSION_MIME`；`placeFromDrop` 加会话分支（见 §3.1，含**全局去重前置**——`placeSource` 的 `kind:'new'` 不查重，必须由 drop 分支先查，否则破坏 tabs.ts「一会话一 tab」去重不变式）。
  4. `TabBar`：组标签 `tab-surface` 的 onDrop 加会话 MIME 分支 → 新回调把会话作为**该组新 tab**打开（spec「拖到已有 tab 组内则作为该组新 tab」的直达落点；组标签 tab=组，语义正对）。

## 3. 逐条落点

### 3.1 #1 左侧会话列表拖拽分屏

改动文件：
- `web/src/app/workbench/paneDrop.ts`：`DRAG_SESSION_MIME`、`readDragSession`
- `web/src/app/rooms/SessionSidebar.tsx`：session-row 可拖 + dragstart 载荷 `{sessionId, title}`；拖动中行降低透明度作拖源提示
- `web/src/app/workbench/WorkbenchPage.tsx`：onDragOver 白名单 + `placeFromDrop` 会话分支 + `onDropSession` 传给 TabBar；`import { sessionBase } from './useWorkbench'`
- `web/src/app/workbench/TabBar.tsx`：组标签接收会话投放；props 增 `onDropSession?`（不传不挂分支，既有调用面零波及）

实现要点：
- drop 分支去重前置：先在 `api.wb` 里按 `dedupKey` = `session:<id>` 找已开 tab——已开在别的组 → `api.place({kind:'tab', groupId, tabId}, target)` 移动过去；已开在本组 → 仅激活；未开 → `api.place({kind:'new', base: sessionBase(sessionId), content:{kind:'session', sessionId, title}}, target)`。
- 落点语义与既有 tab 拖拽一致：左右边缘=新列分屏（走查主诉求）、上下边缘=列内分格、center=填空格/替换占位；拖到 TabBar 组标签=该组内 `api.open(content, sessionBase(id), groupId)`（openTab 语义：组内去重、填空格、无空格追列）。
- 归档会话照常可拖开（只读态由 SessionChat 既有横幅表达，不在拖拽层拦截）。

测试计划：
- `paneDrop.test.ts`：readDragSession 正例 + 缺字段/错型/空串反例。
- `SessionSidebar.test.tsx`：dragstart 后 dataTransfer 含会话 MIME 与正确载荷。
- `WorkbenchPage.test.tsx`：会话 MIME 投到窗格右缘→新列出现会话 tab；投到已有 tab 的窗格 center→去重移动不复制；落点高亮在会话拖动时出现。
- `TabBar.test.tsx`：会话 MIME 投到组标签→该组新增会话 tab。
- `Shell.test.tsx`：仿任务拖放先例做一条左栏会话行 → 工作台窗格的穿越集成。

### 3.2 #2 回复快捷入口 + @ 输入联想

改动文件：
- `web/src/app/rooms/SessionChat.tsx`：MessageRow hover 回复钮；回复态 + 引用条；@ 联想面板
- `web/src/app/rooms/sessionModel.ts`：候选筛选与 token 替换提为纯函数（`mentionCandidates(members, typed)`、`applyMention(draft, token, identity)` 之类），便于缝级单测

实现要点：
- 回复：气泡容器 `group` 化，hover 时气泡右侧出现「回复」钮（aria-label 含 `#{seq}`）；点击设 `replyTarget`，输入框上方渲染引用条（被引用消息 actor + body 摘要 + 取消 ×）；发送后清 replyTarget。**不发送 reply_to**——`sendRoomMessage` 契约不动，发送半边归 B365；replyTarget 只持有 seq，为 B365 接线留缝（在代码注释里写明缝位，勿自创 wire 字段）。
- @：草稿末尾存在进行中 token（`/@[^\s]*$/`）时弹候选面板；候选 = `summary.members` 中 identity 非空者（空座「无人推」不进候选），行渲染 identity + kind 词表标签（复用 `memberStatusLabel` 风格）+ card_title；按输入片段大小写不敏感筛选；↑↓ 移动、Enter/Tab 选中、Esc 关闭、点选插入——把进行中 token 整体替换为 `@<identity>`（完整统一记法，与 `segmentBody`/send 的 mentions 提取逐字兼容，既有 @ 着色零改动）。归档态不弹（输入框已 disabled）。
- 面板渲染在输入框上方（footer 内 absolute 或前置块），带 data-testid。

测试计划：
- `SessionChat.test.tsx`：hover 出回复钮→点击进回复态→引用条内容正确→可取消；发送后请求体**不含** reply_to（反例锁，防提前接 B365 半边）；键入 @ 出候选、继续输入实时筛选、Enter 插入完整 token、插入后 mentions 提取与高亮联动；空座成员不进候选。
- `sessionModel.test.ts`：候选筛选（空串/无命中/大小写）与 token 替换纯函数。

## 7. 与 spec 的冲突 / 需用户裁决点

1. **#7「当前登录用户」前端不存在（真缺口）**：控制台身份 = 服务端注入 `web:<host>`（`roomUserActor`），而 owner 校验只认 `user:<name>/agent:<name>`（B358.4 拍板①明确 web: 是机器位不配当成员身份）；即便加 whoami 只读端点也只能拿回 `web:<host>`，填进 owner 仍 400。本 plan 按可执行半边实现：**localStorage 记忆上次 owner + 成员候选下拉**，第二次起零输入，首次使用仍需输一次。若要求「第一次就零输入且创建者即群主」，需拍板推翻拍板①（owner 词表放宽或 owner 缺省=actor 的后端语义改动）——请用户裁决，默认按记忆方案执行。
2. **#5 的「+」来源是推断**：现码中 tab 组标题右侧无可见「+」按钮（两个新建入口均 sr-only）；真机所见加号判定为 `TabTypeIcon` 对 session 内容缺省渲染的 Plus 图标。若走查截图所指另有控件，需回看截图（B358 卡 note seq 13796）再校准落点。
3. **#3 抽屉内容范围**：spec 只点名成员（含群主标识）/会话卡/归档入口；现码「⋯」切到的详情态还含任务节点、timeline 两节。为不回退既有功能，本 plan 让抽屉吞下全部五块、chat↔detail 双态退役。若用户要保留独立详情态，请说明。
4. **#1 center 落点语义**：拖到已占窗格 center = 替换该窗格（与 workbench 既有 tab 拖拽行为一致，spec 判据要求一致）；「作为该组新 tab 打开」由组标签投放与空格填充承载。若期望 center=追加新格，会偏离 workbench 既有语义，需拍板。
