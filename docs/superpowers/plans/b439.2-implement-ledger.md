## 偏离与自主决定

1. **池数据源注入方式（自主决定，落在 plan §12 权限内）**：plan §7.1 写「`NewPool` 数据源参数」，
   但池在 `agentd.NewServer` 构造、账本在 `cmd.setupLedger` 之后才打开，构造期拿不到设备表，
   无法在构造签名里传源。实现改为 `Pool.SetSource(TargetSource)`（`NewPool` 签名不变），
   由组装点在 `SetLedger` 后注入；行为与 F5 一致（有源走设备表、无源走活配置、For 不发网络、
   实例判等不变）。属 §12「内部命名 / 局部私有函数」。
2. **控制台先加的行可被自登记接管（自主决定）**：plan §4.3 严格写「异 instance_id → 冲突」，
   未区分空 instance_id。控制台新增的机器行没有实例 id（`AddMachineReq` 无该字段）；若空
   实例行也判冲突，「控制台加机 + 该机自登记」永远撞名，S4 与 S3 互斥。实现取：`RegisterDevice`
   对 `instance_id==""` 的既有行**接管**（写真实实例 id 与连接块），仅在两侧实例 id 都非空且
   不同时判冲突（F4 的「同实例更新 / 异实例拒绝」在自登记对自登记时逐字成立）。属 §4.3 缝内
   实现细节。
3. **新增账本方法 `DeviceTargets()`（自主决定）**：plan §7.1 枚举的池读方法是 `DeviceTarget(name)`；
   快照源每轮刷新需要一次性读出全部行（含凭据），逐名调用会 N+1 次查询。新增批量池专用读
   `DeviceTargets()`，仍是「凭据只经池专用读方法出现」（F8）。属 §12 内部实现补充。
4. **S8 保留字判定复用 `config.ValidateSelfName`（自主决定）**：plan 要求「保留字条目不导入」。
   不新增 config 导出面，复用既有词法校验——保留字、含空白、含 `/` 的条目名一律不导入并 WARN。
   属 §12 局部实现。
5. **机器列表保持「本机在第一条」并去重（自主决定）**：设备表会含自名行；`probeMachines` 仍
   先放本机行，再从 `pool.Names()` 中跳过与 `cfg.Name` 相同的名字，避免本机出现两次。属 §12
   局部实现/测试组织。
6. **`SetDeviceSource` 同时切换池源（自主决定）**：一个注入点同时设 `Server.deviceSource`
   与 `Pool.SetSource`，避免两处状态漂移。属 §12 内部实现。

未做（留给 WU3）：S6 旧别名拒收、S7 存量 `''` 每轮 WARN 与健康面计数（plan §8）。
