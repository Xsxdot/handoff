## 0. 本卡干什么（一段话）

phone 档（`viewport==='phone'`，≤767）下，给常驻工作台加一层**单焦点投影**：工作台任意时刻至多一个窗格可见 = 布局焦点格（`wb.activeGroupId` 组的 `focus[column,row]`），非焦点列/窗格以**样式/属性闸**（absolute 叠层 + `z-0 pointer-events-none` + `aria-hidden` + `inert`，后台组先例原样下沉）压入不可达层——不卸载、不 `display:none`、不捏尺寸，xterm/WS 全常驻。可见键条随焦点唯一化（≤1，始终属于看得到的终端），键位集与事件路径零改动。组内多窗格时在焦点窗格头新增紧凑切换入口（原生 select，只写 wb 焦点），跨组切换走既有 TabBar。桌面与 pad 的既有渲染逐字节不动；布局模型（tabs.ts groups/columns/panes/sizes/focus）零改动；`/api` 零新增。键行为与 IME 的自动化止于既有合成事件锁，真浏览器/真输入法/真读屏走查按分级归验收节点，webview 内归壳阶段。

**验收判据是卡级法定契约**（plan 必须逐条覆盖，映射见 §6）：

> 390×844 紧凑视口进入项目终端或任务现场终端时，只显示当前焦点窗格与一条共享特殊键栏，不保留并排桌面窗格、不产生页面或键栏不可发现的横向滚动；后台终端连接继续常驻，返回或切换不重连、不丢状态。键栏和真实系统键盘都必须完成 Esc、Tab、Shift+Tab、Ctrl-C、方向键与真实中文 IME 组合输入的浏览器行为验收；隐藏工作台不进入无障碍焦点序列。桌面多栏与 pad 的既有行为不回归，单焦点投影不得把 pad 展开态误收窄；原生 WebView 壳测试留到壳阶段。

## 2. 岔口裁决（spec §3.3 指定归 plan 的四条 → 决定 + 理由）

### 岔口 1：组内窗格切换入口形态

**决定：焦点窗格头部渲染「窗格切换」原生 `<select>`（`data-testid="pane-switcher"`、`aria-label="切换窗格"`）；渲染条件 = `singleFocus && 本窗格是本组焦点格 && tabCount(group) ≥ 2`；option = 本组非空窗格按列序行序枚举（过滤 `tab === null`，空槽不占位），label = `tabTitle(tab.content, tab.base.label, taskName)`（与窗格标题同口径），value = `tab.id`；onChange 唯一动作 = `api.activate(group.id, tabId)`。跨组切换走既有 TabBar（role=tablist，TabBar.tsx:131）不新增。落点 = 窗格头 `:362-385` 内、标题与 × 之间，类 `shrink-0 rounded border bg-background px-1 py-0.5 text-xs`；select `onClick` stopPropagation（防冒泡进窗格 onClick 触发冗余 activate）。**

- 语义四条逐条对上：①非空窗格两步内可成焦点——组内 = select 两步（点开+选中），跨组 = TabBar 一步 + select 一步；②只写 wb 焦点（api.activate），零布局操作；③入口在 compact chrome 层——焦点窗格头是唯一保证非 inert 的窗格 chrome（焦点层 z-10 无三件套）；④空槽不占切换位，BlankTab 是焦点格内容不是切换目标（焦点落在空槽时窗格头照常渲染「空窗格」，组内还有别的非空窗格则 select 照常在场）。
- 否掉 spec 候选「键条行左侧『窗格 N/M』钮」：键条只存在于终端窗格（keybar prop 只传给 TerminalTab），非终端焦点格（file/session/TUI/空格）没有键条 → 入口随内容类型消失，违反①。
- 否掉「分段控制」：组内窗格数无界（列数无界 × 每列 2 格，桌面持久化可恢复出多列），390 宽装不下 N 无界的按钮排；原生 select 是唯一不随 N 溢出的形态，且触屏上是系统级 picker（iOS/Android 原生滚轮），无自造触控面。
- 桌面/pad 零接触：select 挂 `singleFocus` 门槛，两档渲染树逐字节不变。

### 岔口 2：投影叠层的 className 具体形状

**决定：列、窗格两层同时叠层（组层先例四件套原样下沉），锚点链 = 列容器加 `relative` → 列 div `absolute inset-0` → 窗格 `absolute inset-0`；焦点/非焦点的可见性对 = `z-10` ‖ `z-0 pointer-events-none` + `aria-hidden` + `inert`（展开式）。**

| 层 | 非投影档（现状逐字节） | 投影档·焦点 | 投影档·非焦点 |
|---|---|---|---|
| 组容器 `:306-314` | （现状不动，visible 判据不变） | `absolute inset-0 … z-10` | `… z-0 pointer-events-none` + aria-hidden + inert（后台组先例） |
| 列容器 `:316` | `flex min-h-0 flex-1 overflow-hidden bg-border` | 追加 `relative`（叠层锚） | 同左（投影档统一加） |
| 列 div `:321` | `flex min-w-0 min-h-0 flex-1 flex-col` + style | `absolute inset-0 flex min-w-0 min-h-0 flex-col z-10` | 同左但 `z-0 pointer-events-none` + `aria-hidden={!colFocused}` + 展开式 inert；**style flexGrow/flexBasis 保留**（absolute 下无几何意义，保 DOM 最小差） |
| 窗格 `:323-341` | `relative flex min-h-0 flex-1 flex-col bg-background` | `absolute inset-0 flex min-h-0 flex-col bg-background z-10` | 同左但 `z-0 pointer-events-none` + `aria-hidden={!paneFocused}` + 展开式 inert |
| GroupDivider `:390` | `visible && 非末列` | 条件追加 `&& !singleFocus`（phone 组内不渲染） | 桌面/pad 现状 |

- 焦点判据：列层 `group.focus[0] === columnIndex`；窗格层 `group.focus[0] === columnIndex && group.focus[1] === row`——与 `:294` 同源；`singleFocus` 下对**所有组**统一应用（背景组祖层已 inert，双层叠加无害且代码路径唯一，不出现第二套规则）。
- GroupDivider 的条件渲染不违反「禁结构分支」：它本就随 `visible` 条件插拔（后台组先例）、自身无终端内容、摘除不触任何重挂；禁的是**列/窗格两层承载 TerminalTab 的树**分叉。
- 理由：三层全尺寸（inset-0）→ FitAddon 量全宽、PTY 按全宽 reflow（spec §2.4 几何语义，195px 挤压的 TUI 修复为全宽可用）；跨档只翻类/属性零重挂（§2.1 纪律）；与组层先例完全同构（z 对/三件套写法逐字一致），审查面最小。

### 岔口 3：键条钮触控尺寸收口

**决定：不做收口。** 现状 ≈26px（py-1 + text-xs 16px 行高 + 边框）≥ 24px 次级目标基线，达标；键条侧两个真病灶（多条键栏、键栏内横滚）都由投影修复，与钮尺寸无关。MobileKeybar 的类改动会同步落 pad（`keybar={compact}` 对 pad 生效），为一个达标值引入 pad 形态 churn 不值。若真机走查反馈误触，另立触控小卡（键条形态问题，不属投影）。键位集、事件路径、`overflow-x-auto` 容器类全不动。

### 岔口 4：拖放 handler 在投影层的去留

**决定：保留。** phone 投影下不摘除窗格的 `onDragOver/onDragLeave/onDrop`（:327-336）与窗格头 `draggable`（:364-369）。摘除只有两条路——条件渲染两套树（**禁**，§2.1 纪律）或条件 props 展开（为触屏永远不触发的路径引入第二形态：html5 DnD 触屏本不触发 dragstart，死路径无害，可读性反而降）；保留使「DOM 形状与 React key 路径不变」的验收不变式免于例外，桌面行为逐字节不动。spec §6 风险 1「拖放路径保留不拆」据此落成。

## 3. 补充裁决（非岔口，实现者需要定案才能开工）

### 3.1 投影入参：`singleFocus`，不是 `compact`

WorkbenchPage 新增 `singleFocus?: boolean`（缺省 false，语义 = phone 档单焦点投影）；Shell 在 `:963` 挂载处传 `singleFocus={viewport === 'phone'}`（`viewport` 已在 `:135` 在手）。**门控只看视口档，不看 `nav.detail`**——覆盖期与下钻态同构，投影是视口级门控，避免进出下钻的尺寸抖动（spec §2.1 原句）。为什么不能沿用 spec 字面的 `compact`：`isCompactViewport` 含 pad（useShellViewport.ts:26-28），传 compact 会把 pad 一并收窄，直接违反验收「单焦点投影不得把 pad 展开态误收窄」；spec §2.6 引 `Shell.tsx:869` 是「props 下传」**机制**先例，不是命名裁决（§11 修正 1）。WorkbenchPage 不自读视口（文件头边界同款：布局归 tabs.ts，视口归 Shell）。

### 3.2 「单键条」的可锁语义：可达性唯一，不是实例唯一

投影后每个终端窗格**仍各自挂着**自己的 MobileKeybar（keybar={compact} 不动、键条不搬家，spec §2.2）——非焦点窗格的键条在 inert 层内不可见不可达。因此自动化断言写**可达性**而不是全页实例数：

```ts
const reachable = (el: HTMLElement) =>
  el.closest('[inert]') === null && el.closest('[aria-hidden="true"]') === null
// 断言：getAllByTestId('mobile-keybar').filter(reachable) 恰好 1 条（焦点格是终端时）
```

jsdom 里实例还在（这正是 keep-alive 语义），可达数 ≤1 才是「共享单键条」的可机械化的真义。同理「只显示焦点窗格」= 可达的 `workbench-pane` 恰好 1 块。

### 3.3 三把变异锁（怎么写成测试）

| 锁 | 场景 | 断言（失败即变异被捕获） |
|---|---|---|
| **卸载即红** | Shell 375 下钻态、两终端两组（工作树行「在此打开终端」点两次） | `getAllByTestId('pty-host')` 长度恒 2；TabBar 切组前后两节点身份都保留（`.toBe(host1)` / `.toBe(host2)`）。任何「非焦点=条件渲染卸载」的实现让长度掉 1 或节点换新 → 红 |
| **跨档同节点** | 同场景，`innerWidth` 375 → 768 → 1024 + `dispatchEvent(new Event('resize'))` | 三次跨档后 pty-host 节点恒等（样式闸不变式的直接锁）。结构分支跨档必重挂 → 红（spec §6 风险 3 的执法条款：落红即回 spec，不得静默带过） |
| **结构分支即红** | WorkbenchPage 组件级，singleFocus 双格/双列 | ①两窗格都在 DOM（`workbench-pane` length 不减）；②非焦点格 `aria-hidden==='true'` + `hasAttribute('inert')` + 类含 `z-0 pointer-events-none`；③非焦点格类**不含** `hidden`/`invisible`/`opacity-0`（词边界匹配）且 `style.display === ''`——`display:none`/`visibility`/`opacity-0` 任一实现转红；④焦点层 `z-10` 无三件套；⑤GroupDivider 不在场（`queryByRole('separator')` null）；⑥`act(activate)` 切焦点后三件套随焦点翻转 |

三把锁分布：结构分支即红在 T1（组件级，§5）；卸载即红 + 跨档同节点在 T2（Shell 级，pty-host 要经 renderContent 才存在）。

## 8. 风险与回退（每段独立 revert）

1. **投影类串条件写错把桌面/pad 窗格叠层（最高危）**：cn 拼接错条件会让非 phone 档 absolute 化。缓解：T1 桌面类串逐字节断言 + T2 pad 反例锚 + 既有拖放/后台组用例；回退：revert T1 commit（投影整体消失，属性闸无结构残留）。
2. **inert 双层（列+窗格）旧内核降级**：与 B369.8 同口径——aria-hidden 摘读屏、pointer-events-none 兜指针，键盘 Tab 可能残留为已知降级（= 退回现状不白屏），台账记录、不造 polyfill。
