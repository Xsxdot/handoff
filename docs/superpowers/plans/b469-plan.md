## 稿首批准基线与实施待审

1. **原工单载体与等待准入**：复用任务原 permission/question 工单；在任务发起/关联会话处记录显式唯一审批责任归属及版本，不广播resident，不纳入组织者。合法挂卡席位优先，push/pull各守原契约；否则任务发起会话驻场者按print续轮或桌面门铃+session wait；否则可见needs_human给人。归属只管通知，不限制合法回答者，原CAS保留。未挂卡任务执行机侧发布/镜像与独立投递记录一并交付。等人事实持久化后退出回合、释放准入，不占满 30min 回合/槽位。P0 验证现有 Runner 回合实际何时结束；失败阻塞 S3，不换成 hostapi 自身权限桥。
2. **解析器**：推荐固定版本 `mvdan.cc/sh/v3/syntax` 解析受支持 POSIX/bash 输入，按 AST 判命令位置、参数、替换、重定向；不继续扩充手写分隔器。未知 shell/不支持语法/截断保守走原门禁。新增依赖版本/许可证及实际输入方言在 U2 开工前核实；若该库不支持真实输入，回报证据再拍板。规范化是规则匹配的**硬依赖**，不是共享文件施工排序。
3. **可信管理来源**：CLI 主令牌也可得到 `user:<console_user>`（`internal/agentd/identity.go:34-60`），不能证明人类；web 设备戳也只可候选。推荐持久规则写入要求已验证登录会话下的一次显式确认，绑定规则草案摘要和单次 nonce/期限；模型/普通 CLI actor 不可自证确认。CLI 可查看/准备草案，创建/撤销须走同一可信确认通路；现有认证能否满足由 P0 核实，不足则阻塞持久授权并回提案。
4. **生命周期与复用**：采纳“新裁决必见撤销、已原生投递不追杀”；到期与撤销同等处理。规则派生 grant 复用前读取来源版本/有效期/撤销，读取失败不得复用。已批准“本任务相同请求批准”继续现有同任务同指纹人工复用且不加新门禁并以“本任务相同请求批准”明确提示；独立人工 grant 不被某条规则撤销连带抹除。未来授权与传输重放幂等分开。
5. **分类、审计、UI**：采用 spec 有限分类及求值顺序；普通 push/部署是本期新增分类，不能靠现有黑名单 Reason 猜。registry 保存当前快照；规则 CAS 与不可变事件同事务，历史/命中/去重待办由事件投影。UI 只在现有工单加入显式保存确认、历史/原因/撤销；实施前按 prototyping-in-brainstorm 从 `prototypes/base/` 分支展示并确认形态。
6. **冻结**：先冻结语义原子断言；新增 wire 的准确字段/枚举/错误与投影清单由首段真实消费者形成后提交协调者审查。现有 `keysclient.Runner.Launch/Resume` 无 ctx，`internal/keysclient/keysclient.go:60-71` 与 `server.go:1581`；`hostapi.Host.RunTurn` 已冻结。S3 不预定改签名；任何影响 launch/resume、卡席位及驻场共用路径须重新审查并分别回归。

## 需冻结的外部承诺（原子语义提案）

新增跨进程面由真实消费者形成准确schema后审查；一条单独可判pass/fail，未拍板不能作为后续共同基线。

1. 分类枚举包含spec五类可覆盖限制；普通push/deploy不映射成既有黑名单ID。
2. 永不可覆盖集命中不被规则改写出口。
3. 多限制请求只有全部所需条件/覆盖满足才可规则授权。
4. 未知/缺失必需条件不能自动授权。
5. 本任务相同请求批准不写规则。
6. 模型/CLI actor/device字段不能自证可信人类确认。
7. 规则保存失败不批准本次请求。
8. 保存成功、原生投递失败分别报告。
9. 规则变更与不可变审计同事务提交。
10. CAS冲突不能静默覆盖。
11. 撤销提交后开始的新裁决不使用旧规则。
12. 到期规则不授权新裁决。
13. 规则来源grant的FindReuse复核撤销与期限；人工来源沿现行复用不收紧。
14. 已投递原生动作不因撤销追杀。
15. 四类原因在wire/展示可区分且未知原因保守处理。
16. 同请求/事实版本去重不丢待办及历史。
17. 原任务工单承载回答，通知收件人按显式优先级确定，合法回答权不受其限制。
18. push唤醒与pull待办订阅保持各自契约。
19. 缺可达责任归属产生可见needs_human。
20. 等人事实落盘后释放回合准入。

既有契约：`keysclient.Runner` Launch/Resume（无ctx）、`hostapi.Host.RunTurn`、proto审批上下文与registry CAS；未计划修改这些现存签名。新增分类/规则/原因/归属DTO、未知枚举处理、CLI/web手写投影与错误白名单在第一段真实wire前列全并端到端断言，不能两端各测替代。
