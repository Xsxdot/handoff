## 设计判断记录

1. **CLI 走 HTTP 不直连**（D1）：三条硬约束同向——target.json 冻结方向缺
   d_cli→d_scheduling；契约 §8「组装点之外不得 new 他方具体类型」（适配器不可复制到
   cmd）；breakdown §四-5「gateway 端点与 CLI 写命令最终都汇入 scheduling.Service
   单一入口，不存在旁路」。与 ledgercli.go 直连惯例的差异理由写进了 cmd/squad.go 文件头。
2. **读面三方法**（D2）：Carriers()/Squad() 是冻结签名不能改；gateway 需要 registry
   版本做 CAS 编辑回路 → 新增 SquadRows/CarrierRows（版本行）+ QueueSnapshot（全局
   清队位次）。排序比较器提取 queueLess 防 PopReady/position/快照三副本漂移。
   position 对损坏行从「静默跳过」改为「整队报错」，与 PopReady 同判（行为差异已在
   plan D2 声明；position 只产日志位次，风险≈0）。
3. **PUT 子资源路径**（D3）：GET/PUT /api/squads 是契约原文；PUT 细化为
   /api/squads/carriers/{name} 与 /api/squads/squads/{name}（显式子资源，不做 body
   判别式隐式分型）；expect 走 query 且必填（缺席 400，不许「没带就当 0」的静默语义）。
4. **Healthy 不进登记面**（D5）：PutCarrier 会把 false 静默翻真（本期无探测手段），
   wire 输入若收 healthy 字段就是恒假承诺——不收，登记即健康。
5. **card coordinate 归属**：breakdown K3 验收明文含 `handoff card coordinate <卡号>`，
   但 launch 端点 handler 归 K4——K3 以冻结路径 + stub 服务端测命令级形状，wire 形状
   在本 plan Produces 写死供 K4 逐字消费（跨卡审计点名项）。
6. **carrier 无 CLI 命令是引导缝**：契约 §11 CLI 面只有 squad 族；首个载体的登记只能
   经 Web（K6）或直接 API。岔口四指路文案指向 `handoff squad create`（可建空队）成立，
   成员补挂走控制台。移交注记，不在本卡自造 `handoff carrier` 面。
