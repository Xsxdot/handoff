# B409.3 计划：card wait 快照使用限域后的未决工单读面

**阶段**：L3 重档子卡 plan；本稿只交接实现，不含实现或验收结论。

**适用基准**：已批准 B409 r2（`docs/superpowers/specs/2026-09-24-ledger-read-performance.md`，`16498397`）；`docs/superpowers/specs/b409-breakdown.md` 的 S1-U3；`docs/superpowers/specs/b409-contract.md`。
**工作单元**：B409.3，S1-U3「card wait 建连快照」。**依赖 B409.1** 提供并通过审查的 `OpenTickets` 限域读结果。本卡不改 B409.1 的账本实现。

## 交付目标

`handoff card wait <id>` 建连时仍先输出一行 `card_snapshot`，内容只包括所选卡或当时子树成员的未决工单与 needs 标记；随后沿现有卡/子树成员集合继续 wait。热读消费 B409.1 优化后的 `ledger.Store.OpenTickets` 结果，不在 CLI 重放或折叠 `task_mirrored` 事件。当前对外 JSON 字段、NDJSON 行序、脚本可观察的错误/超时及实时事件行为保持兼容。

U3 只证明 CLI 快照的成员过滤、状态语义、序列化及对 B409.1 读面的消费正确。S1 的 API/Web/card wait 联合演示和 p95 ≤2s 由 S1 集成负责；全三档 PostgreSQL 增长矩阵及最终 p95 由 B409.7/U7 与协调者验收负责。U3 通过不能表述成 S1、B409 或昨晚不可用根因已通过/已查明。

## 已核实的生产路径、契约与边界

- 真实入口是 `card wait` 命令 → `runCardWait`（`cmd/card_wait.go`）。它打开账本、验证根卡、取 `MaxSeq`，生成 `members` 函数（默认仅根卡，`--subtree` 调 `Store.Subtree`），冻结本次快照用的成员列表，再调用 `encodeCardWaitSnapshot`。该编码函数目前依次读取 `Store.OpenTickets` 与 `Store.NeedsReasons`，按成员集合过滤后 `json.Encoder.Encode` 一行 `card_snapshot`。随后 `Store.Follow` 仍使用动态 `members` 与相同 `start` 跟随事件。执行者须以真实源码为准，保留快照初始成员和实时订阅动态成员的区别。
- 当前快照 wire 在 `cmd/card_wait.go`：顶层键为 `type/card_id/subtree/from_seq/members/actionable/needs`；未决工单行为键为 `card_id/source_target/source_task/ticket_id/task_type/payload`；needs 行为 `card_id/reason`。空 `actionable`/`needs` 是数组 `[]`，`payload` 是 `json.RawMessage`。不得改字段名、字段有无、原始 payload、快照先于实时事件的顺序或 `from_seq` 含义。
- B380 `b380-contract.md` C-2 冻结 `Store.OpenTickets()` 的业务语义：按账卡、target、task、ticket 身份重放；`ticket_answered`、`tickets_voided` 及 `completed/failed/archived` 正确关单，终态集合只用于工单关闭，不得并入订阅退出判定；同名 ticket 不得跨 task 串单。`OpenTickets` 结果顺序及 `/api/cards` 计数一致性属于 B380/B409.1 读面责任，CLI 不重算或改口径。
- B156.2 `b156.2-contract.md` §1.1 冻结账本多路 `Follow` 只交付成员卡事件、无卡项目事件不进入该等待流。本卡只读快照并保留既有 Follow 起点、动态成员和事件过滤；不改 `Follow`、`WaitDeliveryPolicy`、`needs_human` 实时唤醒，也不把协作房间逻辑搬入 CLI。B156.2 的 collab/LedgerClient 房间契约不是此 CLI 卡快照的新接口授权。
- 不新增对外 Store/HTTP/CLI 接口，不新增 DTO，不改 B409 S1 摘要 wire。`NeedsReasons` 仍使用现有 ledger 读面；若实测需扩大该读面或更改共享接口，先停下回报协调者，不能在本卡单方面加新缝。

实现文件限于：

- `cmd/card_wait.go`：只调整建连快照如何消费 B409.1 已有结果、局部过滤/序列化或必要的私有辅助函数；不自建账本折叠，不改事件流语义。
- `cmd/card_wait_test.go`：真实 CLI/SQLite 集成夹具与输出契约测试；如需小型测试辅助，留在本文件/`cmd` 包。

不得改 `internal/ledger/taskstate.go`、账本 schema/投影、`internal/agentd`、Web、B358/session wait、`internal/agentd/wakeconsumer.go` 或其他子卡文件。B409.1 对 `OpenTickets` 的签名与完整业务结果须继续兼容；若 B409.1 实施改变此边界，先暂停并交协调者协调。

## 工作顺序

1. **核对 U1 交付与当前调用形状。** 等 B409.1 实现、独立 review 与交接证据完成后，确认 `Store.OpenTickets` 的既有方法/调用方式、结果语义与 SQLite/隔离 PG 契约；不得提前 dispatch 或以 mock 替代其生产实现。记下消费点实际拿到的成员票据集合以及 B409.1 的行/字节证据。
2. **先锁现状，再改接线。** 在 `cmd/card_wait_test.go` 中以 `runLedgerCLI` 走真实命令，先钉住根卡模式与 `--subtree` 模式的首行快照、紧随其后的实时事件行、当前成员过滤与 wire；若测试揭示基线行为与本计划不符，回报协调者，不先改行为凑计划。
3. **让 CLI 只消费 U1 结果。** 保留 `encodeCardWaitSnapshot` 的单一职责：拿 U1 的 `OpenTickets` 结果，按 `snapshotIDs` 选出卡/子树票据；`NeedsReasons` 继续按当前结果筛成员；仅把所选行编码为既有结构。CLI 不读取/解码镜像事件，不复制 B380 规则，不因性能目标改变票据关闭语义。检查错误分支：任一快照读失败必须返回错误，不输出看似成功的空快照，也不开始 Follow。
4. **锁定序列化和反例。** 以真实命令 stdout 的 JSON 行断言：第一行的全部键、字段类型、`from_seq`、成员 ID、source 三元组、ticket ID/type 和 payload 内容；`actionable`、`needs` 的空值仍为 `[]` 而非 `null`/缺键。加入只属于无关卡/兄弟卡的 open ticket 与 needs，确认根卡快照不泄漏；子树包含子卡但排除非子树卡；已答、voided、已终态票据不得出现。用 B380 真实镜像样本覆盖状态与 task 身份，避免仅靠构造映射测过滤。
5. **验证增长不变量，不重复 U1 的账本验收。** 沿用 B409 r2/U1 已批准三档隔离样本与固定 open-ticket 集合：基线约 21,270 events、9,337 `task_mirrored`、约 6.31 MB payload；第二档加至少 20,000 条无关非镜像事件；第三档镜像行数和 payload bytes 至少翻倍。U3 核对 card wait 的成员快照结果和 stdout 字节保持同一业务结果；DB 到应用的读行/读字节边界由 U1 的实际观测负责，不能把输出恒定冒充数据库传输恒定。只使用合成隔离数据。
6. **定向验证并交棒。** 运行 `go test ./cmd -run 'TestCardWait|TestB353CardWait|TestB389NeedsHumanStillActionableInCardWait|TestB409CardWaitSnapshot' -count=1` 及包编译；记录真实命令、退出码和失败原文。实现按 Charter implement/review 纪律继续；S1 联合 API/Web 演示由协调者集成，不在 U3 本地测试中冒称完成。

## 成功条件、关键反例与验收责任

**U3 成功条件**

- `card wait <id>` 的首行维持既有 `card_snapshot` JSON 契约，只含根卡的 open tickets 与 needs；`--subtree` 只含调用时该子树成员；成员和字段在真实 CLI JSON 编码链中可读且无误。
- 后续实时事件仍以原游标/成员过滤到达；快照仍排在事件之前；审计事件过滤、默认一次性退出、`--follow`、超时和终态行为无变化。
- open ticket 集合与 B380 的打开/答复/作废/终态序列一致；B409.1 增长时镜像历史增大不使无关镜像 payload 再被 CLI 全量解码或输出。
- 账本查询失败显式报错，不伪装成 `actionable: []`；编码失败按当前命令错误路径返回。

**必须变红的关键反例**

- 把 sibling/其他卡的 open ticket 或 needs 输出到根卡快照；`--subtree` 丢掉子卡或包含子树外卡。
- 同 ticket ID 在不同 task/target 间串联；`ticket_answered`、`tickets_voided`、`completed`、`failed` 或 `archived` 后仍残留未决票据。
- JSON 键消失/改名，空数组变成 `null`，`payload` 被二次编码成转义字符串或被丢弃，`from_seq` 错位，快照晚于实时事件。
- 以另一个全流事件查询/本地重放替代 `OpenTickets`，或者在查询失败时写出空成功快照。
- 数据集只增无关镜像历史且固定 open ticket 集合时，ledger→CLI 应用传输仍随全部历史行/字节增长；该项由 U1 读面证据与 U3 消费路径共同检查。

**验收责任分层**

- U3 执行者：本计划的 `cmd` 集成测试、真实 JSON 行/成员语义与错误分支；交付 U1 依赖 SHA/结果和本卡原始命令输出。
- U1 执行者/审查者：OpenTickets/OpenTicketCounts 与事件重放 oracle 等价、PG/SQLite 一致、实际 DB 行数/字节边界、三档种子有效。
- 协调者：合并 U1/U2/U3 后验收 S1 真实 `/api/cards`、Web、`card wait`、远端失败语义和全链路 p95 ≤2s；U7 提供最终增长矩阵回归。U3 单测、SQLite 结果、输出尺寸或 U1 单卡通过均不能替代 S1 集成验收。
