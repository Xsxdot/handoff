## 0. 本卡干什么（一段话）

390×844 紧凑视口下，把 Shell 的三个互不同步的导航 useState（`mobileTab`/`mobileDetail`/`fileDrawer`）
收编进一个以 URL 为唯一事实源的 hook（`web/src/app/shell/useMobileNav.ts`）：任何导航动作 = 写 URL，
任何 UI 呈现 = 读 URL。修四件事：①会话→卡身份进卡 tab 卡详情（不直接跳任务现场）；
②卡详情的明确「进入现场」动作才进任务现场，返回条按 `from` 回来源（会话或卡）；
③`/cards?card=<id>` 直达与从会话进入同状态；④ProjectTree 四个死入口逐个处置
（隐藏+解释，或给移动可达结果）。桌面路由行为零回归；原生壳不在本卡。

**验收判据是卡级法定契约**（plan 必须逐条覆盖，映射见 §5）：
「390×844 紧凑视口以单一导航状态驱动 URL、底栏 tab 与详情层。会话顶部的卡身份入口只进入
「卡」tab/对应卡详情，不直接跳任务现场；卡详情中明确的「当前节点等你裁决/进入现场」动作才进入
任务现场。卡详情深链保留 card id 与来源，任务现场返回来源卡或来源会话，直接访问 /cards?card=<id>
与从会话进入得到同一状态；Flows、Codegraph、项目卡等入口要么有移动端可达结果，要么在紧凑视口
主动隐藏并给出解释，不能留下死按钮。桌面路由行为不回归；补自动化测试并在 390×844 浏览器实走
会话→卡详情→任务现场→返回。原生 Android/iOS 壳不在本卡。」

## 2. 三个开放岔口的裁决（spec §3.3 → 决定 + 理由）

### 岔口 1：统一导航参数的宿主路径

**决定：双宿主。卡 tab 与卡详情宿主 `/cards`；其余导航参数宿主 `/`。**

- `/cards`（pathname 本身即「卡 tab」的表达）query：`card=<id>`、`project=<name>`（皆既有）+
  `from=session-<id>|card-<id>`（新增；compact 写入，桌面不消费、不渲染、不报错）。
- `/` query：`tab` ∈ `sessions|cards|projects|settings`（缺省 `sessions`）、`detail=1`（工作台下钻态）、
  `dir=<baseKey>`（目录覆盖层）、`from=…`（任务现场返回来源，仅 `detail=1` 时有消费者）。
- 派生规则：`pathname === '/cards'` ⇒ tab=`cards`；否则读 `tab` 参数。任务现场终态形如
  `/?tab=<tab>&detail=1&from=<来源>`（`tab=cards` 出现在 `/` 上仅限 `detail=1` 期间——
  它只被返回条兜底读取；hook 的规范化负责把「`/` 上 `tab=cards` 且无 `detail`」replace 成 `/cards`，
  不留第二形状）。

**理由**：① `/cards?card=` 是桌面既有深链（CardsPage.test:167/185 已锁），双宿主让 compact 与桌面
共用同一 URL 语汇，「直达 == 会话进入同状态」零翻译落地；若全挂 `/?tab=cards&card=X`，初载
`/cards?card=X` 需要一次改写迁移，且同一状态出现两种 URL 形状。② CardsPage 按 `location.search`
读参数、与 pathname 无关，双宿主对它的既有消费零改动。③ `tab/detail/dir` 是 compact 专属概念，
挂 `/` 使桌面 URL 不被污染（不消费即免疫）。采纳 spec 的倾向，并把倾向落成了可执行的派生规则。

### 岔口 2：项目行「工作项」紧凑视口的触屏可达形态

**决定：行内常驻。** compact 下项目行右侧簇常驻渲染「工作项」图标钮（无 hover 也可见可点），
「代码图」钮不渲染；桌面维持 `hidden group-hover:flex` 逐字节不变。载体是 ProjectTree 新增可选
prop `compact?: boolean`（缺省 `false` = 桌面行为，既有 ProjectTree 消费方与测试零改动）。

**理由**：验收口径是「项目行工作项入口可点且卡 tab 打开」——行内常驻零额外点击直达；
「展开区内」形态要先展开项目，多一层发现成本，且空位置/无任务项目的展开区没有兜底承载位；
行内常驻与桌面 hover 形态同位同钮（同一 `aria-label="打开 <项目> 工作项"`），只改可见性策略，diff 最小。

### 岔口 3：解释文案的落点与措辞

**决定：项目 tab 底部入口行（`border-t` 那行）下方一行 muted 文案，仅 compact 渲染。**

- `data-testid="mobile-nav-note"`，样式 `px-3 pb-2 pt-1.5 text-[11px] leading-4 text-muted-foreground`，
  措辞定死：**「流程与代码图暂未适配移动端，请在桌面宽屏使用。」**
- 一行覆盖全部三类被藏入口（底栏「流程」、底栏「代码图」、项目行「代码图」），不逐入口重复。

**理由**：spec §2.4 要求「用户都能在同一视口内读到一句它为什么不在、去哪用」——底栏行下方是
用户刚扫过入口行的位置，同视口可达；逐钮 title/tooltip 在触屏无 hover 不可达；文案挂在同一个
`compact` prop 缝上渲染，与入口隐藏同条件，永不脱钩。

## 3. 统一导航模型（实现者开工的地基）

### 3.1 hook 契约

新文件 `web/src/app/shell/useMobileNav.ts`（非 `terminal*` 前缀，P3 约束不涉及）。
命名仅为契约示意，签名可微调，**行为契约不可打折**：

```ts
export type MobileFrom = `session-${string}` | `card-${string}`

export function useMobileNav(opts: { compact: boolean }): {
  // 读（compact 下从 URL 派生；桌面下从内部 useState 派生——同一 API 两种存储）
  tab: MobileTab            // pathname==='/cards' ? 'cards' : params.get('tab') ?? 'sessions'
  detail: boolean           // params.get('detail') === '1'
  dirKey: string | null     // params.get('dir')
  from: MobileFrom | null   // 当前 pathname 上的 from（/ 与 /cards 各读各的）
  // 写（compact 下写 URL；桌面下写内部 state、URL 一字不动）
  setTab(t: MobileTab): void                          // t==='cards' → navigate('/cards')；否则 '/?tab=t'
  enterDetail(ctx?: { from?: MobileFrom | null; tab?: MobileTab }): void
  exitDetail(): void                                  // 清 detail+from，留 tab/dir（无 from 兜底返回）
  setDir(key: string | null): void                    // 开=push '/?tab=projects&dir=k'；关=replace 清 dir
  openCard(cardId: string, from?: MobileFrom): void   // push '/cards?card=<id>[&from=…]'
  closeCard(): void                                   // replace：strip card+from、保留 project
  normalize(gate: { ledgerEnabled: boolean; ledgerLoading: boolean }): void
}
```

- **桌面直通**：`compact === false` 时三个状态走 hook 内部 useState（初值同现状：
  `sessions`/`false`/`null`），所有 setter 只写 state、URL 一字不动——这就是「桌面路由行为不回归
  可被既有测试直接锁住」的机制（spec §2.5）。hooks 规则上无条件调用，分支在值层不在 hook 层。
- **fileDrawer 的拆分**：compact 由 `dirKey` 派生——`dirKey ? findBaseByKey(treeState.data, dirKey) : null`
  （树未加载或键失效时为 null，覆盖层不渲染、URL 残参自愈）；桌面沿用既有 useState（写点
  Shell.tsx:546/1100 原样）。Shell 内合成单一 `fileDrawer` 变量供下游读点（:725/:742/:767/:1060-1085/:1090），
  下游无感。
- **写入的 push/replace 纪律**：前进类（setTab/openCard/enterDetail/setDir 开）push；
  返回/取消类（exitDetail/返回条分派/closeCard/setDir 关）replace；`/tasks/:id` 跳板与规范化改写
  replace（跳板是瞬态路径，不留历史格）。compact 的 `backToWorkbench`（Shell.tsx:482）改为 no-op：
  其全部调用方随后都经 nav setter 落完整 URL，pathname 由 setter 收口，`/tasks` 跳板由 enterDetail
  的 replace 处理；桌面分支原样。
- **normalize 契约**（收编 Shell.tsx:173-177 的账本 effect，replace 语义防历史堆积）：
  ① compact && !ledgerLoading && !ledgerEnabled && (tab ∈ {sessions, cards} 或 pathname==='/cards')
  → 改写 `/?tab=projects`；② `/` 上 `tab=cards` 且无 `detail` → replace 成 `/cards`；
  ③ 无消费者的残参（`dir` 在 tab≠projects 时、`from` 在无 `detail` 时）清除。
- **埋点**：统一 `console.debug('shell.mobile_nav.*', {…})`——`tab_select`/`detail_enter`/`detail_back`/
  `dir_open`/`dir_close`/`card_open`/`card_close`/`normalize`，替换既有
  `shell.mobile_tab.select`/`shell.mobile_detail.back`（已核实无测试断言旧事件名）。

### 3.2 收编后的关键行为（与现状的差异面，逐条对应验收）

| 动作 | compact 下的 URL 终态 | 与现状差异 |
|------|----------------------|-----------|
| 点底栏 tab | `/?tab=<t>`（t=cards 时 `/cards`） | 现状不写 URL |
| 点会话行（openSession） | `/?tab=sessions&detail=1` | 现状仅 setState |
| 点会话卡身份行 | `/cards?card=<id>&from=session-<sid>`，卡 tab 高亮、退出下钻 | 现状 URL 变了没人消费（死） |
| 卡抽屉 ↗（jumpToTask） | `/?tab=cards&detail=1&from=<urlFrom ?? card-<选中卡>>` | 现状终态恒 `/` |
| 协调者「打开终端」 | `/?tab=cards&detail=1&from=card-<选中卡>` | 现状无来源 |
| 返回条 from=session-<id> | `/?tab=sessions&detail=1`（openOrFocus 幂等重建会话 tab，仍在下钻态） | 现状回底栏首页 |
| 返回条 from=card-<id> | `/cards?card=<id>`（抽屉经既有 URL effect 重开） | 现状回底栏首页 |
| 返回条无 from | `/?tab=<tab>`（现状行为） | 不变 |
| 项目 tab → 目录 | `/?tab=projects&dir=<key>` | 现状仅 setState |
| 直达 `/cards?card=<id>` | 卡 tab 高亮 + 抽屉打开（CardsPage 既有 URL effect） | 现状深链死 |

关键裁决注记：**返回条的 `from=card-<id>` 分支不带 `from` 落 `/cards`**——`from=card-Y` 的任务现场
意味着卡详情原本无 `from`（Y 是直接深链进入），返回来源卡的来源链到此为止，没有「来源的来源」
可恢复；`from=session-S` 分支同理只回会话。spec §3.2 的「重开抽屉」语义按此落。

## 7. 风险与回退

1. **`dir` URL 化遇旁路（最可能的降级点）**：BaseDir 反解依赖树加载，树刷新瞬间可能空窗（覆盖层闪没）；
   overlay 基座 z-index 交互（mobile-dir 与 mobile-home 同 z-30、靠 JSX 顺序压制）不改 z 轴，理论无冲突，
   但若实测出现不可收编的抖动——**回退：`dir` 参数单独降级为 hook 内部 state**（`setDir` 签名不变、
   不写 URL），Shell fileDrawer 读点回接 useState（一处改）。验收判据不含 dir 深链，剪的是
   「URL 化完整性」不是功能。
2. **URL 同步环/双写竞态**：CardsPage 的 seam 写与 URL→state effect（213-216）、TaskDeepLink 与
   enterDetail 的导航次序——缓解：所有 URL 写幂等（写前比对 target 参数）；若 drawer 双向同步不可收编，
   回退：抽屉选中态回内部 state，URL 只在「入口动作」（会话进入/深链/返回分派）时写——深链同态与
   返回分派两条验收仍成立，仅「board 点击后刷新不丢抽屉」降级，并在卡台账记录降级决定。
3. **参数名撞车**：`from/tab/detail/dir` 落地前 grep 全仓 query 消费复核（本轮实测：`from` 零消费方；
   `?ticket=`、`?project=`（各自 pathname 上）不冲突）。
4. **任务现场 `tab=cards` 残留形状**：由 normalize ② 兜底（`/` 上 tab=cards 且无 detail → replace 成
   /cards）；若实测出现第三种残留形状，扩 normalize 契约而不是放宽派生规则。
5. **整卡回退**：T1-T5 各自独立 commit；依赖关系 T2←T1、T3←T1，回退按逆序 revert，单段回退不牵连
   其他段的文件面（T3 与 T2 文件面交叠仅 Shell.tsx 的 projectTree JSX 与测试文件）。
