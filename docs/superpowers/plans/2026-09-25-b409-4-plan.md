# B409.4 计划：S2 会话/房间列表、未读与详情限域投影

**阶段**：L3 重档子卡 plan；本稿只交接实现，不含实现或验收结论。

**批准基准**：B409 r2 `docs/superpowers/specs/2026-09-24-ledger-read-performance.md`（2026-09-24 用户批准）；`docs/superpowers/specs/b409-breakdown.md` 的 U4；B156.2 `docs/superpowers/specs/b156.2-contract.md` §3.3–3.4、§3.4.1、§4「房间生命周期与读模型」；B358 `docs/superpowers/specs/b358-contract.md` 会话摘要、详情、timeline 与未读冻结；B358.9 的控制台身份/member 水位规则。

**工作单元**：B409.4 / S2 剩余的会话与房间列表、member unread、last activity、session detail 投影。已验收的单房间历史读取作为 Wave 0 基线 B0 回归，不在本卡重复实现。

## 交付目标

移除打开会话与房间列表、查看会话详情时对全局 `card_events` 的全量读取和应用层筛选。用户打开工作台后，应看到与现有金样相同的会话/房间行、成员与席位、活动时间、预览、未读、详情节点和 timeline；项目筛选、归档、终态沉底、并入只读及 lease 活性判断保持冻结语义。账本查询按所需 session/room/card/游标范围取数，读取失败仍为可见错误，不得拼成合法空列表或零未读。

本卡证明 S2 剩余用户故事的生产查询与 UI 链路。单测或 SQLite Store 测试只证明局部，不算 S2 故事完成；PostgreSQL 隔离数据、真实 agentd API 与 Codex 内置浏览器验收均须完成。U7 再负责 B409 r2 的完整三阶段增长矩阵和全部故事最终回归。

## 已核实的生产路径与边界

- `GET /api/sessions` → `Server.handleSessionsList`（`internal/agentd/sessionsapi.go`；控制台身份由服务端注入）→ `collab.Service.ListSessionsContext`（`internal/collab/sessions.go`）→ 当前调用 `LedgerClient.ListSessions`、`ListAllCards`、`room.ReadAllEventsContext(ctx, ..., 0)`，再计算 needs、member cursor 未读、每个 summary 的活动/预览与成员/卡投影。Web `fetchSessions` 由 `web/src/app/shell/Shell.tsx` 的 `usePoll` 驱动，在工作台 `/` 的 `SessionSidebar` 展示。
- `GET /api/sessions/{id}` → `Server.handleSessionDetail` → `SessionDetailContext` → 当前读全部 cards 与全局 events，再投影 summary、节点及 timeline。浏览器通过 `SessionTab` 打开详情与会话内容；HTTP 详情错误须保持错误响应，不得冒充空详情。
- `GET /api/rooms?project=&limit=&cursor=` → `Server.handleRoomsList` → `collab.Service.ListRoomsPage` → `listRooms`（`internal/collab/service.go`）。当前读项目卡列表和 `ReadAllEvents` 全流，为卡房间、project 群、global 计算 last activity/preview/unread，再读去重后的绑定 lease 并排序/分页。随后 `roomsapi.go` 的 `enrichRoomAttachments` 仅给本页作投影，并按 B374 规则后台刷新远端 attach；此 attach/分页协议不是本卡优化目标，须保持不阻塞主列表的既有行为。
- 未读的唯一进度状态是 `internal/collab/cursor` 的按 member、room 持久水位；`MarkRead` 单调推进。`Unread` 与 `ListSessions(member)` / `ListRoomsForMember` 汇总必须读同一游标语义，命中条件为 `room_message.seq > cursor`。游标仍归 collab，不能搬进 ledger 或与 session delivery cursor 混用。
- 历史窗口已由 B0 落地：`HistoryContext` → `LedgerClient.RoomMessagesBeforeContext` → `ledger.Store.RoomMessagesBeforeContext`，最近 200、按 seq 升序、`beforeSeq` 排他、房间隔离、context 取消及错误/空结果分开。保持此签名、语义和实现，不另建历史切片，也不改 `EventsFromAsc`/`Follow` 全流语义。
- Web 中真实会话工作台路由是 `/`；`/rooms` 是 API 路径，不得当作浏览器页面验收路由。UI 需要经过实际工作台 sidebar、session tab 与房间切换。

**当前根因证据**：上列源码中的 `ListSessionsContext`、`SessionDetailContext` 和 `listRooms` 把全量账本事件交给 collab 再筛选；本计划以此为待修复路径，不将其外推为 2026-09-23 20:00–22:00 生产故障的已证根因。

## 改动边界

- 协作与组装：`internal/collab/sessions.go`（session list/detail summary、node、timeline、needs 投影）、`internal/collab/service.go`（room list、last activity/preview、unread 聚合及单 room `Unread`）。会话/房间归属、member cursor、lease/只读/终态规则和错误语义留在 collab。
- 账本查询：`internal/ledger/rooms.go` 与必要的 `internal/ledger/store.go` 方言 schema/index、`internal/ledger/api/api.go`、`internal/collab/client/client.go`；对应 `internal/ledger/*_test.go`、`internal/ledger/api/*_test.go`。ledger 仅按存储字段/room/card/session id/event kind/seq 水位限域读取或聚合；不得判断 member 是否属于房间、卡是否进某 session、哪类 room 应展示、terminal/read-only/live 等业务规则。禁止 collab 直连 SQL、禁止改变既有 `LedgerClient` 方法含义、禁止从全流接口伪造范围查询。
- HTTP 与序列化：仅在生产接线或错误/取消测试需要时改 `internal/agentd/sessionsapi.go`、`roomsapi.go` 及其 handler tests。维持身份服务端注入、`/api/sessions` 与分页 `/api/rooms` 的既有 JSON、状态码与 B374 cursor/page 语义；不改 `internal/proto` wire。
- Web：仅触及 `web/src/api/rooms.ts`、session/sidebar/workbench 消费点及其测试中必要部分；不得引入新的 UI 空/错误状态混淆或破坏原生 `/` 工作台路径。历史组件由 B0 覆盖，仅回归。
- 不触及：CLI、`Pending`/`Mentions`/`Consume`、`session wait`/`wakeconsumer`、消息写入/寻址、卡片业务状态、remote attach 缓存/刷新策略、通用 metrics 系统及无关 event store。
- 若需要持久派生投影或 schema 迁移，必须可从 `card_events` 幂等重建、具备水位与失败可见性；如果无法在本卡边界内证明原子性与恢复，不做静默双写，停止并交协调者评估是否调整拆卡/U7 责任。

## 实现顺序

1. **执行前核依赖与接缝。** 以实现分支真实源码和 B156.2/B358 金样复核上述路径、事件字段、房间身份（`card_id` 优先；无卡消息按载荷 `Room`）及 cursor 读取。对照 U5 plan，列出本卡若要新增的每个 `LedgerClient` 读方法及生产消费者：若 U5 也依赖同一个新公开方法/DTO，在任一消费者实现前回 contract 冻结该最小接缝；不能把一个尚未批准的接口藏在实现细节里。没有共享新面就不造 contract。计划集独立审计若否决边界，先修计划，不开始实现。
2. **先用独立金样锁住现状。** 扩展 `internal/collab/readmodel_test.go`、`sessions_test.go` 与相关测试，以手工预期/独立的简化事件 oracle 覆盖：多 session/多 room、一个 member 与另一 member 游标、卡/项目/global、归档、终态、并入、空座、租约存在/过期、needs_human/cleared、群与卡 room 消息、preview 截断与 activity 时间。包含属于另一个 session/card 的相邻事件，确保不会串投影；同时覆盖读错与取消不可变成空列表。先执行定向测试确认新范围断言在现有全流读上按预期暴露无关事件读取或传输随账本无关增长。
3. **完成受限的 ledger 读面。** 为所需 room/card/session/type/seq 范围提供可由 collab client 调用的读能力；按实现选定只读查询或可重建 projection，但不要更改全流方法语义。列表热读应一次批量取其真实范围，不能变成每个房间各自重扫全表；session detail 只装配该 session 与其当前卡成员相关事实。测试观测数据库实际返回的行数与 payload 字节，证明加入无关事件后返回给 collab 的无关历史行/字节不会随全局流线性增加；仅断言 JSON 最终值、读取 SQL 文本或 `EXPLAIN` 不够。
4. **保持 collab 单一业务判断点。** 用 ledger 范围读结果还原现有 S2 summary/detail/room rows：列表顺序、过滤、LastActivity（会话 UpdatedAt/卡 UpdatedAt 作为既有回退，最新消息时间可覆盖）、按最新 seq 的 preview、needs 状态、members/cards/seats、lease `live`、ReadOnly 与 terminal sink、按 member cursor 聚合 unread。每成员游标快照只取一次，不按 session/room 重复读游标；room list 的一次性 unread 聚合不重复读取消息全流。lease 查询失败不能伪装成合法 offline，missing/expired 按现有冻结语义处理。所有 ledger/cursor/lease 读错误沿现有 HTTP 错误路径可观察传播。
5. **贯通真实 API、编码和 UI。** 用真实 `LedgerClient` facade、SQLite integration fixture 与 `httptest` 经过 `/api/sessions`、`/api/sessions/{id}`、`/api/rooms`，断言返回行/summary/timeline 的 wire 与 B358 金样同义；项目/member 隔离和页边界不串数据，未知 session 仍 404 且错误带 id，查询失败仍错误而非 200 空值。测试请求取消会终止支持 context 的数据库读取。Web/API 测试穿过 fetch 解包到 `Shell`/session-sidebar 消费者，区分加载中、真实空、查询失败/断连，并保持已缓存行的既有展示策略；不把组件 mock 结果写成真实数据库证据。
6. **SQLite 与隔离 PostgreSQL 对同一金样对照。** 本地 SQLite 跑同组结果和负例；`LEDGER_TEST_PG_DSN` 必须由协调者确认指向专用、可丢弃的验收库，不得对共享/生产 ledger 写 synthetic rows。PG 上核同一输出、游标边界/排序、失败/cancel 语义以及真实查询返回 rows/bytes；缺 DSN 或无法确认隔离时，局部 SQLite 开发可继续，但 U4 的 PG/E2E 验收保持阻塞。
7. **完成 S2 真实增长与端到端验收。** 在隔离 PG 中按 B409 r2 构造固定 S2 会话、room、card、lease、member cursor 样本：阶段 ①基线约 21,270 个 events、9,337 个 `task_mirrored`、约 6.31 MB 镜像 payload；阶段 ②只再加至少 20,000 个无关、非镜像 events，目标 session/room/card 和所有可见结果完全不变。记录确实落入账本的事件/镜像数、payload bytes、查询返回 rows/bytes及数据库版本。对 `/api/sessions`、`/api/rooms` 每组分别记录首请求，再做 5 次预热与 100 次计入样本；用 nearest-rank 报 p50/p95/max、错误数与响应字节，失败不剔除，S2 目标 p95 ≤2 秒。Codex 内置浏览器走实际 `/` 工作台，分别在两种种子下完成 100 次硬刷新/导航，量到 session list 首次可见和打开目标 session/切换 room 的可见时间，保存构建版本、PG 版本、浏览器/服务/DB 位置及原始读数。不得经 SuperDev，不得用 `/rooms` 当页面地址；B0 的历史首屏只重跑回归，不重新计入本卡成果。U7 仍负责完整第三阶段（在阶段②基础上镜像行数及 payload 字节至少双倍）和 S1–S5 全入口最终性能矩阵。
8. **交棒。** 报告实际跑过的命令/退出码、SQLite 与隔离 PG 结果、API/浏览器原始样本、seed 实测行/字节、未通过与未能覆盖项、依赖 U1 的接入 SHA。U4 实现按 Charter review 独立双轴审查；由协调者集成和验收 S2 全故事。局部 tests 或本卡 PASS 不可称 B409 完成，也不确认历史 20:00–22:00 故障根因。

## 成功条件与必须为红的反例

**成功条件**

- `/api/sessions` 含全部会话（含归档）并保持创建序；member 未读、NeedsHuman、LastActivity、Preview、Members 与 Cards/seat 投影逐项等于 B358 语义。Session detail 的 Nodes 与 Timeline 仍只含该会话和其当前成员卡对应的节点/结构事实。
- `/api/rooms` 对项目筛选返回指定项目的卡房间和 project 群并恒有 global；全部非终态房间在前、终态卡沉底，各组活动降序稳定；preview 是最大 seq 的消息；LastActivity 的 fallback、Live、ReadOnly、Attach 与 B156.2/B374 语义不变。成员未读与 `Unread`/`ListSessions(member)` 对同一 member cursor 完全一致。
- 空数据可显示真实空结果；API/SQL/cursor/lease 错误可观察且不会伪装成空行/零未读；context 取消不继续耗费已放弃请求的数据库读取。
- 从 collab 进入 ledger 的读仅包含当前列表/detail 真正需要的数据；+20k 无关事件下查询返回行/字节不随无关 event 总量线性增加。隔离 PG 的当前规模和 +20k S2 API/UI 样本达到 p95 ≤2s；同金样在 SQLite/PG 语义一致。
- 已验收的 S2 B0 历史契约新鲜回归仍绿：recent-200、升序、exclusive beforeSeq、room isolation、取消、真空与失败分开。

**必须为红**

- 删除/移动 member room cursor 后，另一个 member 的 unread 改变，或 `MarkRead` 倒退游标、把已读消息仍计入或把命中 seq 排除。
- 一个 session 的消息、needs、nodes 或 timeline 泄到另一个 session；房间 filter 错把 `card_id` 非空的事件归到 payload `Room` 指定房间；终态/并入卡排序或只读标志被抹掉。
- 只增加无关 event 就使 collab 接收全部 payload/全局 event rows，或逐房间发起等价全流扫描。
- SQL/cursor/lease 失败时 handler 回 `200 []`、`Unread=0` 或详情显示真空；取消后查询仍继续；跨方言结果、last seq、空与缺省字段不一致。
- 只在 fake `LedgerClient` 或 SQLite 局部 Store 测试通过、未跑真实 PG API/内置浏览器与可复核增长样本，却宣告 S2 完成。
