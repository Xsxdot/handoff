# B409.5 计划：S3 收件箱消费与 session wait 限域恢复

**阶段**：L3 重档子卡实现计划；本稿只交接实现，不含实现或验收结论。

**批准基准**：B409 r2 `docs/superpowers/specs/2026-09-24-ledger-read-performance.md`；U5 `docs/superpowers/specs/b409-breakdown.md`；已批准 r2 `docs/superpowers/specs/2026-09-24-session-reliable-mentions.md` 与前置冻结契约 `docs/superpowers/specs/2026-09-24-session-reliable-mentions-contract.md`；物理读面增量 `docs/superpowers/specs/2026-09-25-session-bounded-candidate-read-contract.md`；B156.2 inbox/read-consume；B358 `docs/superpowers/specs/b358-contract.md` 的寻址、`MessageWakeTargets`、`Store.Follow` 与 wakeconsumer 边界。

**工作单元**：B409.5 / U5 / S3。要交付有效正文 `@` 寻址、限域 Pending/Mentions/Consume 与同房间回复清理，以及由共享 delivery cursor 驱动的 `session wait` / `--follow` 断线续收。它不拥有 S3 最终故事验收，也不拥有 B409 全量增长矩阵。

## 交付目标

让收件箱消费和会话监听只读取当前 member、room 与 seq 范围真正需要的消息事实。CLI 发送正文中的有效 `@` 与桌面端写入相同的 `mentions` 寻址字段；消费查询保留 B156.2 的未消费语义；监听以共享账本 `session_delivery_cursors` 在同一身份、跨机器地补收停听期间的定向消息。积压按 r2 发一条既有冻结格式的摘要，实时段沿用现有 `SessionWake` JSON；stdout 成功即交付并随后推进 cursor，不增加逐条 ack，也不承诺识别“已输出但模型未处理”。

局部 Store、collab 或 CLI 测试只能证明各段行为，不能关闭 S3。S3 独立故事完成仍需真实 CLI、共享 PostgreSQL 与跨机器停听/重挂链路；B409 最终三阶段增长矩阵及 S1–S5 全入口集成由 U7/协调者负责。

## 已核实的生产链与边界

- **发送及寻址**：`handoff session send` → `cmd/session.go` 的 `sessionSendCmd` / `sessionMessageMentions` → `collab.Service.Send` → `sendToSession` / `RecordRoomMessage`。CLI 目前已有正文 token 编译及显式 `--mention` 合并入口；实现需逐项对照 r2 金样、保留无效 token 原文但不寻址、去重和大小写，不可在 CLI 复刻接收规则。桌面入口是 `web/src/app/rooms/SessionChat.tsx` 的正文 mentions 编译；其金样是语义基准，若需改桌面行为或格式，停止回 contract，不自行改冻结输入规则。
- **唯一投递判定**：`runSessionWait` 从 `cmd/session.go` 组装 collab service 后，对 `room_message` 使用 `room.IsSessionRoom` 和 `collab.Service.MessageWakeTargets` 匹配 member，构造既有 `SessionWake` 与可选引用、未读。不得在 CLI 按会话成员广播或二次实现目标判定；`@<card>` 当前席位映射继续由现有 `MessageWakeTargets` 处理。
- **恢复与 stdout**：`runSessionWait` 的默认共享游标读自 `internal/ledger/session_delivery_cursor.go`；当前实现分页读事件、积压编码到 stdout 后调用 `AdvanceSessionDeliveryCursor`，follow 的每条唤醒也在成功编码后推进。显式 `--since` 是排他手工回放，不读写共享进度。维持 one-shot 首条唤醒后退出、backlog 一条摘要后退出、follow 连续输出、一次性 timeout 与 follow idle-timeout 的既有差异；stdout 失败不推进，cursor 读错不退化成 0，写进度失败报错且允许下次重复。
- **收件箱与清理**：`collab.Service.Pending` 合并 B156.2 定义的两类未消费事实：显式寻址 consumer 的群聊消息，以及 consumer 所绑定卡房间内未消费的用户消息（含终态/并入房间的既有覆盖）；`Mentions(member, afterSeq, limit)` 仅返回 afterSeq 之后寻址 member 且未消费的消息；`Consume(seq, consumer)` 幂等，仍以既有 `message_consumed` 事件为权威并保留原有授权/原子语义。`Send` 成功后 `consumeRoomMentions(roomID, actor)` 只清该 actor 在同一 room 的待消费提及，保持 B287 best-effort 语义，不影响其他 room、ticket 或 decision。
- **账本职责边界**：可按存储字段/room/card/member/seq 限域检索或聚合；房间成员关系、权限、会话归属、卡号到当前席位的解析以及 target 判定仍在 collab。所有有效 target 唯一由 `MessageWakeTargets` 决定。不得绕过 `LedgerClient` 让 collab 直连 SQL。
- **明确不触及**：`internal/agentd/wakeconsumer.go` 完全不改；不改变 `Store.Follow`、keystone 卡锚/唤醒、桌面消费标记或已读 cursor，不添加 `ack`、处理完成回执、并发 listener 唯一认领，不修改 B156.2/B358 冻结 wire。

## 改动边界与执行顺序

仅在上述两项 contract/seam gate 和全计划集闸均通过后开始实现。按以下顺序工作，每步保留窄反馈环：

1. **锁独立金样和红反馈**：先给 `cmd/session`、collab 收件箱服务、ledger cursor/范围读建立独立预期数据；覆盖有效/无效 `@`、显式 mentions 顺序与去重、`MessageWakeTargets` 唯一投递、reply 引用、不同 member 与 room、message_consumed 重复事件、权限失败、取消、查询错误。旧全流路径若无法证明无关行/字节不被读取，新增观测断言让其失败。
2. **限域账本读入口**：依据批准的 contract 和 U4 seam 清点，只增加消费链必需的最小 Ledger/Store 读取能力。`Pending`、`Mentions`、`Consume` 及同房间回复清理不得把 `ReadAllEvents` 全账本送入 collab；按 member/room/card/seq 限域，批量复用 consumed 状态，避免 `consumeRoomMentions` 对每一命中都触发全流重读。session wait 按 `2026-09-25-session-bounded-candidate-read-contract.md` 获取可完整覆盖显式身份 @、当前席位卡 @ 与有效同房间 reply 的候选，候选再交 `MessageWakeTargets` 唯一裁决。固定候选集时增加无关事件，须记录实际返回 rows/payload bytes；PG 同时记录 `EXPLAIN (ANALYZE, BUFFERS)`，SQLite 记录 `EXPLAIN QUERY PLAN`，证明不是每轮扫描全部事件 payload。保留 `message_consumed` 事件权威、幂等和错误/取消传播。查询失败不能伪装成无待办。
3. **贯通寻址和消费入口**：实现/校核 CLI 正文完整空白分隔 token 解析：仅整 token 的 `@` + 有效身份或卡号寻址；不修剪尾随标点；无效 token 留在正文，不生成 target；自动 token 与显式 `--mention` 按首次出现顺序去重，显式参数原有归一化语义不变。与桌面共享同一金样，不更改接收判断，也不回填旧消息。
4. **有界 backlog 与共享 cursor**：在启动时读 member 持久 cursor 和一次 MaxSeq 快照，扫描逻辑 `(cursor, MaxSeq]` 内的有界候选消息，升序、逐个交给 `MessageWakeTargets` 做权威过滤；进程内 scan watermark 与已交付持久 cursor 分开。有命中则汇总成一条冻结的 `session_backlog`，引用条只通过现有点读与同房间规则解析。空 backlog 不输出、不推进持久 cursor；有 backlog 必须整行 stdout 成功后才推进到最高已输出 hit seq。不得以扫描过无关事件为理由推进超过已输出命中的 seq。
5. **接上实时 follow 与恢复**：启动 backlog 后，one-shot 有积压即退出；否则等待首个命中并输出一个既有 `SessionWake` 后退出。`--follow` 则在 backlog 后逐条发既有 wake，成功输出后各自推进共享 cursor；重挂同身份/同共享 DB 从持久水位补拉。持续轮询用已冻结的限域读面，游标推进不跨越尚未输出的定向命中。保留 timeout 语义：`session wait --timeout 5s` 空等 30 次每次不超过 6s；follow timeout 仍表示相邻命中的 idle interval。cancel 是干净退出，查询错误不推进。
6. **实现正/反例并发/恢复细节**：单调 cursor 并发写不能回退；cursor read 失败不可当 0；stdout writer 在 backlog 或实时行写入时失败则水位不推进；stdout 成功、cursor 写失败必须可观察并允许重复；隔离 PG/SQLite 方言无行与失败分开；一个 member 的消息不泄漏给另一个；历史已处理过但尚无 cursor 的记录按 r2 仍可能首轮进入 backlog。模型已处理回执与多监听器唯一认领不属于本卡。
7. **端到端交棒**：真实 CLI producer 写入共享 PG；在 listener 停止期间投递定向消息；从另一机器以同一 member/数据库重挂，验证 backlog 与随后 follow wake、共享水位、stdout 和 cursor 均成功后不重复。验证无效 token、非目标和结构事件不叫醒，`@<card>` 仍按既有席位路径。记录 CLI/agentd/ledger SHA、数据库版本与隔离方式、原始输出、时间样本、失败和缺失证据。此真机演示是 S3 独立验收输入，不是 B409 最终验收。

允许修改的文件应限于 `cmd/session.go` 与对应命令测试、`internal/collab/service.go` 与收件箱/会话测试、`internal/collab/room` 的既有消费判据（只有冻结语义确需调整时才涉及）、必要的 `internal/ledger` 查询/cursor/facade、`internal/collab/client` 的必要接口及方言/集成测试。`internal/proto` 只在已经冻结的既有 wire 缺实现时按契约补齐，不改 JSON。桌面只在共享金样测试证明现实现不符且获得 contract 批准后才可改。不得动 `internal/agentd/wakeconsumer.go`。

## 成功条件与关键反例

**成功条件**

- CLI 与桌面 token golden 一致：`@agent:main`、`@user:sy`、`@B233.16` 自动寻址；`@agent:`、`@B23x`、`@unknown`、`email@agent:main` 不寻址且保留正文；显式参数与正文按原定顺序合并去重。
- `MessageWakeTargets` 仍为唯一寻址和席位解算入口。Pending union、Mentions afterSeq/limit、Consume 幂等及 B287 同 room/同 actor 回复清理逐项符合 B156.2 与现有金样；message_consumed 权威未变。
- 会话恢复只读 `(cursor, MaxSeq]` 内有界候选并升序权威过滤；固定候选集、增长无关事件时返回 rows/payload bytes 不随全流增长，PG/SQLite 执行计划均使用地址候选范围而非每轮全事件扫描。backlog 一行格式与冻结样例相同且不截断；follow 后每个 live hit 输出原 `SessionWake`，无包裹；无 `ack`。stdout 成功后才推进最大已交付 hit，失败不推进，cursor 写失败允许重投；无命中不推进。
- 同一共享 DB 上停听期间到达的有效 @ 能在同 member 异机重挂时补收，已成功输出的命中不会再次由 cursor 回放；新消息 follow 可连续收到。`--since` 仍为排他手工回放且不读写共享 cursor。
- 30 次 `--timeout 5s` 空等各自 ≤6 秒；one-shot 总超时与 follow idle timeout 语义各自保持。SQLite 和隔离 PG 样例语义一致；日志不含正文、token、DSN 或凭据。
- Store/client 返回给 collab 的候选 rows/bytes 不随无关事件总量线性增长；PG/SQLite query plan 不在每轮全量扫描事件 payload；错误/取消显式可见，不转为空列表、不写水位。

**必须为红的反例**

- CLI 写入 `@agent:main` 只显示在 body、mentions 为空；无效 @ 被当作 target、标点被修剪，或者有效 `@<card>` 绕过现有席位解析。
- 任一 member 能读取/消费另一个 member 的定向消息；room 消息或同 actor 回复清理跨 room；`Mentions` 把已消费条目返出；重复 Consume 再追加重复权威事实；查询失败被解释为无待办。
- 游标读错误被默认为 0 或流尾；stdout 失败却推进水位；游标写失败静默成功；水位越过 backlog 中最后一条尚未写出的目标命中；恢复后丢停听消息或成功输出后又回放。
- `--since` 修改共享 cursor，backlog 与实时 JSON shape 变更，follow 不能连续输出，timeout 变成累计/固定等待，或取消后继续查询。
- 局部 SQLite、fake client、单测绿但未走真实 CLI→PG→另一机器重挂路径，却报告 S3 完成；只测当前数据，未报告查询 rows/bytes 及无关事件增长。
- 为优化订阅改动 `wakeconsumer.go` 或扩展 `Store.Follow`，将外部会话监听混进 keystone/执行域唤醒。
