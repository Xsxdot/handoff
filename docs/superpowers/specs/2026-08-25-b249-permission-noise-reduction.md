# B249：权限判据降噪

**级别：L3 轻档** —— 第 1 条跨「执行运行」与「本机治理」两个子系统的契约面（任务临时目录的路径约定今天是 codex adapter 的私有知识，判据侧要认它就得让它成为契约）；工作量远不到流程固定成本（约 70 分钟），故轻档：契约冻结照做，实现归一轮，不扇出子卡。
**状态：已批准**（2026-08-25，用户在 spec 对话中批准；两个裁决点见「已定裁决」节）

---

## 问题陈述

对 linux-01 最近三天（2026-08-23 00:00 ~ 08-25 15:30，+08）全部 **1377 次**权限判定的全量取证（直接只读查 `handoff.db` 的 events/tickets 表与 `agentd.log`，绕开了 `handoff show` 的 `recentEventsLimit = 100` 窗口，故为全量非下界）：

| 出口 | 次数 |
|---|---|
| AutoAllow（静默放行） | 133（下界，依赖回合走到收尾汇总） |
| Consult（交廉价模型） | 1038 |
| Escalate（网关直接升级人工） | 206 |
| **实际叫醒人的工单** | **246** |

人对这 246 张工单的处置：**allow 238、deny 6**、void 1、未答 1。**6 条 deny 没有一条出于危险**，全部是方法论纠偏（「纪律块已注入 prompt，不要去文件系统找」「变异的施加位置与执行位置分家，这个实验测不出你要的东西」）。

即：**权限门今天实际扮演的是方法论纠偏通道，不是安全闸。**

叫醒人的原因分布：

| 理由 | 条数 | 实质 |
|---|---|---|
| **目标路径越出任务范围** | **171** | 落点是 `/root/.handoff/tmp/<task>`、`/tmp/opencode` 等——**agent 在写自己的台账与草稿**。其中 52 条命令主体是 `go test` / `go build` / `npm`，10 条是纯 `cat`/`grep`/`ls` |
| approver 判完再升级 | 56 | 主体是 `git commit --amend`（49 条），charter 台账纪律的**法定动作**，人每次都批 |
| 黑名单命中 `rm -rf` | 7 | 方向正确，保留 |
| handoff 自指令 | 7 | **无一条真在调用变更命令**，见下 |

Consult 的 1038 次同样以正常工作为主体：git 本地写 695（`git add <ledger> && git commit --amend --no-edit` 为大宗）、写文件 119、构建测试 69、git 只读 36。

## 现状事实（带出处）

1. **判据层与沙箱层对「任务临时目录」的认定不一致。** `internal/permgate/path.go:50` 的 `InScope` 只认 `scope.Workdir` 与 `scope.TaskDir` 两个根；`internal/agentd/manager.go:1845` 构造的 `TaskDir` 是 `<DataDir>/tasks/<taskID>`。而 codex 沙箱的可写域是 `<DataDir>/tmp/<id8>`（`internal/executor/codex/adapter.go:131` 的 `taskTmpDir`），**两者不是同一个目录**。后果：沙箱允许执行器写任务临时目录，判据却判它越界升级人工。`internal/permgate/permgate.go` 的 `Scope` 注释仍写着「两处都是 handoff 分配给该任务的空间」——第三处是后来演进出来的，注释与判据都没跟上。
2. **`Scope` 的两个根之外没有任何草稿区概念。** `/tmp/opencode` 是 opencode 自己选的草稿位置，跨任务共享，handoff 完全不知情。
3. **自指令白名单过窄。** `internal/permgate/selfcmd.go` 的只读子命令白名单只有 tasks/show/diff/fetch/status/frames/sessions/footprint/ls，未知子命令一律判命中。实测把只读的 `handoff graph resolve --doc <文档>` 误升级 3 次。
4. **廉价模型不是可靠的兜底。** 对一字不差的同一条命令有约 12% 的判定翻转率（`commit --amend` 家族 escalate 49 / approve 7）。

## 契约语义与接缝（L3）

**要定的语义：任务临时目录是 handoff 分配给任务的第三处合法空间，其路径约定归属「执行运行」子系统，判据侧按契约读取，不得复制约定。**

- **今天在哪**：路径规则是 codex adapter 的私有函数，其上有大段注释解释路径长度预算（旧形状 61 字节 + 测试子路径预算 51 = 112 > `AF_UNIX` 的 107 上限 → 压到 27 字节）。**这类知识重复两份必出事**，所以判据侧不能自己拼一遍 `<DataDir>/tmp/<前8位>`。
- **要定的接缝**：由「执行运行」子系统导出「给定任务标识与数据根，本任务的临时目录在哪」这一个查询；「协作控制」构造判据范围时调用它，「本机治理」的判据把它作为第三个合法根。
- **定不了的（归 contract 节点）**：精确签名、参数形态、放在哪个包。

**方向约束**：新增依赖方向是「协作控制 → 执行运行」，与现状一致（manager 本就持有 adapter）；**不得**引入「执行运行 → 本机治理」的反向依赖，判据包保持纯计算、不认识执行器。

## 方案

### 第 1 条：草稿落点纳入范围

**选定：任务临时目录（第三个根）纳入判据范围；`/tmp/<executor>` 这类跨任务共享目录不纳入。**

理由：任务临时目录是 handoff 自己分配的、任务专属的、沙箱已经放行的空间，判据不认它纯属演进遗漏。而 `/tmp/opencode` 跨任务共享，纳入范围等于允许并发任务互相覆盖草稿——`internal/executor/codex/adapter.go:154` 的注释已经为同一理由刻意排除了 `/tmp` 与 `$TMPDIR`。

**配套（已定：做）**：让其余三个执行器也把临时目录指向任务专属目录——codex 已经通过环境变量注入做到了（`TMPDIR` / `GOTMPDIR` / `GOCACHE`），其余三个没有。不做这一步，opencode 仍会往 `/tmp/opencode` 写，第 1 条只能覆盖越界里的一部分。

**这一步有一个必须避开的坑，实现时逐字遵守**：临时目录**必须在仓库工作区之外**。曾有过把 `TMPDIR` 指进 `$PWD`（任务工作区，即仓库内部）的配方，后果是一族「造一个非 git 目录、断言 git 操作应当报错」的用例**全部假红**——临时目录落进了 git 仓库，git 命令正常成功，前提失效。实测 9 条，且失败形态不统一（多数是「实得 nil」，`TestProjectAddRejectsNonRepo` 是 `panic: nil Context`），按失败文本筛会漏。任务专属目录（`<DataDir>/tmp/<id8>`）在 DataDir 下、worktree 之外，天然满足这条；**不要为了「就近」把它改到仓库里**。

**弃选：把 `/tmp` 整个纳入范围。** 一行改动就能让 171 条越界归零，但它让判据对「跨任务互相覆盖」完全失明，且与沙箱层的既有决定直接冲突。

### 第 2 条：法定动作与已知安全命令白名单

**选定：在命令类判定之前增设一个「已知安全形态」的自动放行档。**

覆盖两类：

- **charter 台账纪律的法定动作**：`git add <范围内路径> && git commit --amend --no-edit` 这一形态。它是纪律要求执行者每轮都做的事，三天被升级 49 次、人批了 49 次。
- **构建与测试命令**：`go build` / `go test` / `go vet` / `gofmt`、`npm test` / `npm run <脚本>`、`make`，以及纯只读命令（`ls` / `cat` / `grep` / `git status` / `git diff` / `git log`）。

**约束（写进实现，不可省）**：

1. 白名单只在**落点判定已通过**之后参与——越界仍然优先升级，顺序不得颠倒（`internal/permgate/permgate.go` 的 `judgeBash` 已经确立了这个顺序，理由是「越界是确定性事实，放在后面会被稀释成廉价模型的一次裁决」）。
2. 白名单匹配**命令的主体形态**，不是子串包含。`echo "go test"` 不得因含 `go test` 字样而被放行。
3. 命中白名单走 AutoAllow，而 `autoAllowPermission` 今天**不建工单不发事件**——本卡要求为白名单放行**补一条事件**（不建工单）。理由：`agentd.log` 的逐次记录是 Debug 级、默认不开，本次取证已实测「AutoAllow 的逐条内容取不到证」。放宽判据的同时让审计彻底消失，是不可接受的组合。

**弃选：把默认出口整个从 Consult 翻成 AutoAllow。** 数据支持「危险操作极少」，但白名单是可枚举的正向清单，默认翻转是不可枚举的负向清单——一旦执行器行为改变（换模型、换版本），后者没有任何缓冲。且本次取证只覆盖三天，不足以支撑负向结论。

### 第 3 条：自指令只读白名单补全

**选定：把只读查询类子命令补进白名单。** 判据保持「未知子命令视为变更」的保守缺省不变，只是把已知的只读子命令列全。

## 用户故事

1. 执行者在任务临时目录里写台账、跑测试、放构建产物 —— **不叫醒任何人**，且事件流里留得下痕迹。
2. 执行者按 charter 纪律执行 `git add <台账> && git commit --amend --no-edit` —— **不叫醒任何人**。
3. 执行者跑 `go test ./...` 并把输出重定向到任务临时目录 —— **不叫醒任何人**。
4. 执行者试图往 `/tmp/<共享目录>` 或工作区之外写 —— **照旧升级人工**。
5. 执行者跑 `handoff graph resolve --doc <文档>`（只读查询）—— **不再被误判为自指令变更**。
6. 协调者想知道「这一段静默放行了什么」—— 能从事件流里查到，不依赖 Debug 日志。

## 测试决定（接缝清单）

三条缝：

1. **判据范围判定**（`InScope`，`internal/permgate/path.go` 的导出符号，调用方 `judgeFileWrite` / `judgeBash` 同包可 grep 核验）——新增第三个根后，用例覆盖「落在任务临时目录内 → 放行」「落在 `/tmp` 共享目录 → 越界」。
2. **命令类判定**（`judgeCommand` 及其上游 `Judge`，同上）——白名单形态的表驱动用例，含「主体匹配 vs 子串包含」的反向用例。
3. **任务临时目录的契约查询**（新符号，由 contract 节点定签名；调用方为协作控制侧的判据范围构造点）——用例断言判据侧拿到的路径与执行器侧实际使用的是同一个。

第 3 条是本卡唯一的新建缝，其存在理由正是「不让路径约定重复两份」——它必须有生产调用方，不得只为测试而抽。

## Out of Scope

- **不改黑名单的 8 条规则**（增删规则本身不在本卡；B248 会收紧其中的绕过路径）。
- **不下线廉价模型审批者。** 白名单只吃掉可枚举的安全形态，长尾仍然交给它。等白名单稳定运行一段、Consult 计数显著下降后再评估——**本期不做，已落 roadmap**。
- **不做默认出口翻转**（见第 2 条弃选）。
- **不做任何 OS 隔离改造**（bwrap / 容器 / Landlock）—— 归 B247。本卡全平台生效，不依赖隔离能力。
- **不改执行器的权限上报形态**（如 opencode 上报哪些字段、codex 的 `/bin/bash -lc` 外壳）。本卡对执行器的改动只有一处：临时目录的环境注入。
- **不做出口分类的长期计数与看板**（Consult/Escalate/AutoAllow 的持续观测）——有价值但独立，**已落 roadmap**。

## 备注

### 与 B248 的落地顺序

B248（收紧：修 `/bin/bash -lc` 绕过黑名单）与本卡（放宽）改同一个包。**B248 必须先落地或与本卡同轮落地** —— 先放宽后收紧的中间态是净减安全。

### 已定裁决（2026-08-25，用户裁决）

1. **其余三个执行器（claude / grok / opencode）也把临时目录指向任务专属目录，四个执行器拉齐。** 取根治而非只覆盖 codex 那 63%。
2. **白名单按本 spec 第 2 条所列全量上**（法定动作 + go build/test/vet + gofmt + npm test/run + make + 纯只读），不先上最小集。依据是每一项都有三天取证数据支撑，且全都在落点判定之后才参与。

### 选档复核（定稿范围下）

裁决 1 让「执行运行」侧从零变成三处同构的环境注入，总量接近轻/重档的判据阈值（单子系统约 70 分钟）。**仍定轻档**，理由：改动高度内聚——判据侧集中在一个包（范围根 + 白名单档 + 自指令白名单 + 测试），执行运行侧是三处同构改动加一个契约导出，扇出成并行子卡的协调成本大于并行收益。「规模适中」是轻档的信号，不是重档的。

### 取证边界（诚实记录）

- AutoAllow 的**逐条内容取不到证**（逐次判定是 Debug 级，窗口内 DEBUG 行数为 0）；133 这个数字本身是下界（依赖回合走到收尾汇总，异常终止的回合会静默丢计数）。这也是第 2 条要求「白名单放行必须补事件」的直接理由。
- approver **批准**决定的理由取不到证（payload 的 reason 在 approve 时恒为空）。
- opencode 为何一次 AutoAllow 都没有，两种解释（自己预批不上报 / 汇总行丢失）**均未验证**，本 spec 不据此立论。
