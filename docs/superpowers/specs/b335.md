- **级别与档位**：**L1**。plan 增量为零：对话已冻死三件事（禁 `--target/--executor`、pass 后 push origin、未发布则保留跨机锁）。验收一眼可核。
- **状态**：**已批准**（2026-09-04 对话冻死）

- **姐妹卡**：B334 已完成；B336 不在本卡。

## 问题陈述

有 runner 小队时，协调者再 `--target` 等于替 Admit 点名机器，会触发「工作分支粘在上一台」的跨机锁。用户要的日常路径是：Admit 选闲着的 runner 成员；节点 pass 后执行机把工作分支推 origin；下一台 fetch 再干。`--base` 不是日常逃生口。

## 方案

1. 节点 `override.squad` 非空时，`card dispatch --step` 的 `--target` / `--executor` 由代码拒绝（HTTP/startCardStep），不是纪律劝告。Admit 选机器/CLI/HOME。`--model` 仍可一次性覆盖。
2. 节点 pass 且有工作分支：在持有该分支的那台机 `git push origin <branch>`。失败 → needs_human。成功落 `work_branch_published`。
3. 下一轮若目标机与上次不同：已发布则放行，base=工作分支、`LocalBaseBranch=false`（对端 fetch origin）；未发布则保留现有跨机锁（安全网）。日常不走协调者 `--base`。
4. 空小队不默认 runner（现状保持）。

## 用户故事

1. 作为协调者：对 charter 派发列带 `--target linux-01` 被拒，文案点名小队。
2. 作为 runner 成员：A 机 implement pass 后分支在 origin；B 机 review/下一节点能 fetch 续上。
3. 作为安全网：没 push 成功就跨机，仍被锁，转 needs_human。

## 测试决定

1. `startCardStep` ← CLI/HTTP `--step`：squad 节点带 Target 或 Executor → 错误；不带则 Admit。
2. `Dispatcher.ViaTemplate`：未发布跨机仍拒；发布后跨机放行且 LocalBaseBranch=false。
3. `NodeStep` pass：Publish 失败 → needs_human；成功 → 事件。

## L1 plan

1. `startCardStep`：squad 非空且请求点名机器/执行器 → 释放槽位并拒。改满员排队夹具里误带的 Executor。
2. `WorkBranchPublished` 事件；ViaTemplate 用它决定跨机锁 vs origin 续接。锁文案保留 git push，写明日常不用 `--base`。
3. pass 后 `PublishWorkBranch`（经任务 `git push origin <branch>`）；失败 needs_human。skill 补一句：有 runner 禁止 `--target/--executor`。
