## 问题陈述

B267 把终端仿真器对「你是谁 / 背景什么颜色 / 光标在哪」这类提问的自动回答**一律扔掉**，避免刷新或重连时把旧回答当成用户敲的字。程序因此永远在猜。

B270 之后，切 tab 不再卸仿真器，这条路上几乎不再放旧录像。刷新和重连仍会先灌一盘旧录像。活着的提问今天仍然全丢。

谁：在工作台终端里跑 shell 或 TUI 的人。  
通道：仿真器看见输出里的提问 → 本地生成回答 → 经现有数据通道写回程序。  
要变的事实：**放旧录像时闭嘴；真人提问时把回答送回去。** 没有旧录像（新开的终端）第一次提问也要答。

## 方案

**推荐（对话已冻结）**

- 建连时服务端告诉前端「旧录像有多少字节」。0 = 没有旧录像。
- 正在灌这盘旧录像时：DA / OSC 颜色 / CPR / 窗口报告仍然扔掉。
- 灌完之后、以及从来没有旧录像时：这些回答送回程序。
- 焦点报告 `[I]` / `[O]` **继续按 B270 一律不送**（切 tab 不让 TUI 参加进出焦）。
- 回答仍走现有数据通道，不在程序旁边另雇一个人当场答。迟到了可能掉在提示符上——本期接受。

**弃选**

- 维持全丢：等于本卡不做。
- 在 PTY 宿主里解析提问并本地回答：延迟更好，但要学会跟画面一致的答案，本期不做；真机若活查询经常赶不上再开卡。
- 把「刚接上的第一段」都当成旧录像：新终端第一次提问也会被扔掉。
- 缺「旧录像长度」时当成 0（没有旧录像）：旧服务端会在刷新时重新喷乱码。缺字段时维持今日全丢。

## 用户故事

1. 新开一个终端，提示符上的程序问颜色 / 终端类型，能收到回答，不靠猜（允许偶发迟到）。
2. 刷新或重连同一个还在跑的会话：旧录像灌进去时，提示符上**不**再冒出 `>0;276;0c` / `rgb:…` 这类字。
3. TUI 里切走再切回：仍能输入、滚轮仍按页（B270 不回退）。
4. 焦点报告仍然不上送：切 tab 不会把 TUI 打成失焦。

## 实现决定

- 「有没有旧录像」以建连那一帧里的长度为唯一依据。长度为 0：不进入闭嘴窗口。长度 > 0：从开始灌到灌完这些字节为止闭嘴；灌完立刻恢复活查询。
- 闭嘴只针对设备回包（DA / OSC 颜色 / CPR / 窗口报告）。用户按键、鼠标报告、Option 当 Meta、行首行尾，一律照旧上送。
- `[I]` / `[O]` 不并进「活查询要答」。B270 的一律不送继续有效。
- 不改 TERM、不改环形缓冲怎么存，只在建连时把「这盘有多长」说清楚。
- 旧服务端不带这个数字：活查询继续全丢，避免刷新喷字。

现状读数（本工作树，合同复核）：

- 建连帧只有 `since` / `truncated`，不说 backlog 多长：`internal/proto/pty.go` 的 `PtyControl`。
- 有 backlog 才写一帧二进制，没有则下一段就是活的：`internal/agentd/pty_ws.go` 灌 backlog 那段。
- 前端不论有没有 backlog，attached 之后都把下一帧当回放：`web/src/app/workbench/TerminalTab.tsx` 里 `replayingBacklog = true`。
- 设备回包一律不上送：同文件 `onData` 里 `isTerminalHostResponse`。
- `[I]` / `[O]` 一律剥掉：同文件 `takeLeadingFocusReport`。注释里「活着的必须上送」已过期，以 B270 正文和本卡为准。

## 测试决定（接缝）

1. **建连帧带旧录像长度** ← 工作台 PTY 客户端  
   长度为 0 时不进入回放闭嘴；大于 0 时灌完这些字节才结束。缺字段时行为与今日相同（活查询也丢）。现状生产调用：建连第一帧。

2. **`TerminalTab` 的 `onData`** ← 仿真器  
   回放闭嘴窗口内，设备回包不上送；窗口外上送。`[I]` / `[O]` 在窗口内外都不上送。用户按键始终上送。

变异：把「长度为 0 也当回放」或把活着的设备回包改回全丢，缝 2 对应用例必须转红。
