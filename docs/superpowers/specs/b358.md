# B358：会话即工作单元——房间锚点从卡翻转到会话

- **卡**：B358
- **级别与档位**：**L3**。跨会话子系统（`d_collab` 的锚点翻转）× 账本域（席位与投影） × 控制面（唤醒路径）× CLI（room 命令族）× 控制台（`d_web` 内容面）。选档：**重档倾向**——会话模型重做与前端内容面各自远超流程固定成本、可并行；contract/breakdown 复核后定稿。
- **状态**：**已批准**（用户 2026-09-12：「我觉得可以，就这么定吧」——形态与过程两支北极星走查定稿，spec 按定稿范围进入实现；对话裁决逐条见台账）
- **取代**：B156.2 的房间制模型（卡:房间 1:1、消息 kind 白名单、书写者矩阵）由本卡显式废止。B275 的会话面板**形态**保留（三态面板、微信行式列表、详情页），被翻转的是它底下的锚点模型。
- **不动**：B307 的三颗按钮与席位身份（坐下 / 叫机器人 / 换绑）、席位权威在卡（`cards.driver_session`）、执行者不入群不写账、"合 main 永远人工"。
- **北极星**（用户 2026-09-12 指定，实现与验收一律对照它们）：形态 = `prototypes/b358-session-groups/pages/sessions.html`；过程 = `prototypes/b358-session-groups/pages/flow.html`（会话生命线 / 消息投递 / 升级三档 / 席位与换绑）。走查要点见 `prototypes/b358-session-groups/README.md`。
- **台账**：`docs/superpowers/specs/b358-ledger.md`

## 1. 问题陈述

房间这个功能做出来了，但它没有成为注意力面。四条实据（2026-09-12 读数，出处见台账）：

1. **锚点错了。** 卡:房间 = 1:1，于是本机账本有 **326 个房间**——给每张卡开了一间会议室。抽查最近在跑的 `B233.13 / B233.14 / B233.16`：**一间一条消息都没有**；整个 B233 只有一条，还是人自己写的交接备注。
2. **没有生产者。** 房间的产出义务只写在仓内 `skills/handoff/SKILL.md`（「协作房间纪律」节，:578 起）；而日常真正在驱动流程的 charter 套件（`~/.agents/skills/` 14 个 skill + 7 份 `charter-*` 纪律块）里「房间/room」**命中 0**。纪律没接上，系统也察觉不到它没接上。
3. **没有消费者。** 裁决的选项按钮在卡抽屉里、不在房间；房间消息不渲染 decision / refs / mentions；收件箱只给列表打「需要你」高亮、不渲染条目。叙事、要办的事、卡状态分居三面，用户只能巡场。
4. **升级链缺中间层。** 今天只有「协调者 → 人」（房间叙事 kind + Decision + needs_human）。而群房间在 `internal/collab/room/room.go#VerifyWriter` 里**只有 `user` 一种 kind 可写**——协调者在项目群里向"主 agent"汇报，今天要么冒用人的身份，要么根本写不进去。

**目标（用户 2026-09-12 原话的组织模型）**：董事长（人）→ CEO（主 agent）→ 总监（协调者，每卡一个）→ 团队（执行者）。人与主 agent 聊需求与方向；主 agent 拆卡、出 spec；handoff 叫起协调者推进 spec 之后的节点；协调者处理不了的问主 agent，主 agent 处理不了的问人；人能看到主 agent 与协调者的往来记录。**人的注意力只落在关键问题上。**

## 2. 方案总览

五件，互为表里：

1. **会话（群）= 工作单元**：房间锚点从卡翻转到"人 / 主 agent 开的一场会话"；卡是会话里的工作项，一卡同时只挂一个会话。**进群 ≠ 配人**（用户裁决）：拉卡进群只建讨论面，配不配协调者、谁配，仍在卡上按 B307 的三颗按钮。
2. **投递寻址化**：一条消息的接收人由**发送者写下的寻址**决定，与"群里有谁"无关——`@` 只唤醒被 @ 的，回复只唤醒原作者，无寻址的发言**不唤醒任何人**。系统永不按成员集合投递。
3. **成员模型**：人 / 主 agent 会话 / 群里各卡的协调者。协调者席位仍锚在卡上，卡进群时该卡当前席位以成员身份出现；**`@卡号` 解析到"那张卡的当前席位"**，换绑后依然找得到。
4. **三面分工**：会话列表 = 谁需要我（needs_human 等标签）；群聊面 = 说话（不分 kind，各自以自己名义）；**会话详情页 = 结构与状态**（成员、成员状态、协调者派发的任务节点、会话 timeline）。结构信息不进聊天流。
5. **升级三档**（用户 2026-09-12 裁决）：协调者自决**填补级**（spec 未覆盖的实现选择、顺手小修、新问题落新卡）；**@主 agent** 仅在**推翻级**（实测证伪 spec 商定、要动范围/验收判据/契约语义、超轮僵局、不可逆动作的提案）；**人** 掌三道人工门（spec 批准、验收结论、合 main）。配合姿势：**推只在升级那一刻，拉随时可行**——主 agent 定时巡场看有没有跑偏，不被每个动作叫醒。

### 弃选记录（含理由）

- **保留卡房间、在其上加功能**：现状已被 326 间空房证伪；会议室该按"一件事"开，不该按"一个零件"开。
- **kind 白名单续用**（escalation / deviation / closing / relay / reply / user / pointer）：分类官僚且没有生产者，书写者矩阵还是升级链缺中间层的直接原因。**发言自由**——身份仍执法（谁说的可查），但不再管"你说的是哪一类话"。
- **把 `@` 立成待办对象**：否（用户裁决）。`@` 只是提醒——"你有一条消息"。机械出口留给 `needs_human`（卡级标记，聚合到会话列表当标签），不另造队列与超时策略。
- **结构事件写进群聊流**：否（用户裁决）。全量里程碑会让群退化成日志流，正是要防的淹没；结构信息归详情页。
- **进群即配协调者**：否（用户裁决）。群是讨论面、卡是工作单元，两者解耦；B307 刚统一的入口不动。
- **`@all` / `@here`**：否。要叫几个人就写几个 `@`，扇出只允许存在于发送者的显式意图里。
- **把主 agent 落成账本里的一等身份（跨卡角色 + 专属收件箱）**：否。用"群成员 + `@`"这一套已能同时表达"总监问 CEO"与"CEO 问董事长"，且人自己当群主时零改动——**用更少的机制表达更多的东西**。
- **主 agent 内部对话面（handoff 自己跑的对话）**：本期不做（见 Out of Scope）；本卡只支持"外部会话"形态（你在 Claude / Codex 桌面端或 CLI 开着的那场对话）。

## 3. 用户故事

1. 作为董事长：早上打开 handoff，第一屏是**会话列表**；哪个会话有 `needs_human` 就有标签，点进去在群聊里读协调者的原话，需要我拍的就在原地答。
2. 作为人：我开一个会话，跟主 agent 聊需求与目标；聊完它建卡或把已有的卡拉进来（进群不配人）；我确认后按三颗按钮之一安排谁来推。
3. 作为协调者：我推完 implement，判断是填补级——落账、继续，**一个 `@` 都不发**。
4. 作为协调者：我发现 spec 选的方案跑不通（推翻级），在群里 `@` 主 agent，附上"商定 vs 实测、影响半径、选项与推荐"。
5. 作为主 agent：我只在**被 `@`** 时醒来；醒来看到的就是 `@我的那条 + 它引用的那条 + 未读数`，不看整群噪声；我判不了就往上一级 `@` 人。
6. 作为主 agent：我定时巡场（拉）——看会话列表标签、看详情页的成员状态与派发节点、看卡的状态；**不被每个动作叫醒**。
7. 作为人：我在群里**回复**协调者某条消息，只唤醒它一个；群里其他人只看到未读角标，不会被吵醒。
8. 作为人：我要找推进某张卡的人，`@B233.14` 就够了——不用知道现在是谁在坐，换绑之后依然对。
9. 作为接手的人 / agent：我读群史 + 详情页 timeline（谁进群、谁换绑、卡何时收口）就能接上现场。

## 4. 契约语义与接缝（L3：定语义，不定签名）

### 4.1 会话

- **锚点**：一场会话由人 / 主 agent 开（不再由卡派生）。会话有群主（人 或 主 agent 会话身份），群主是升级终点。
- **群 ↔ 卡**：一个会话可装多张卡；**一张卡在同一时刻只挂一个会话**（否则协调者两个东家，`@` 与归属都答不上来）。
- **成员**：派生，不新增成员表——人与主 agent 是显式成员（外部会话身份），群里各卡的**当前席位**是它的协调者成员。
- **生命周期**：显式归档；卡的终态**不等于**会话结束（讨论面可能还在用）。归档后只读。旧 326 个卡房间只读归档、不迁移内容。
- **谁能拉卡进群**：人与主 agent；协调者不能（它只管自己那张卡）。

### 4.2 消息与身份

- **落点**：群里发言落为**群事件**（无卡），可带卡引用锚（点了跳卡）；卡的账（派发、裁决、验收、`needs_human`）仍归卡 timeline，两边互不灌。
- **身份仍执法**：`actor` 必须可验证（人 = 会话身份；agent = 席位身份）。废止的是**按 kind 分权限**，不是身份本身——账本要能回答"这句话谁说的"。
- **废止**：`internal/collab/room/room.go#VerifyWriter` 的 kind 书写者矩阵、`KindAllowed` 的 kind 白名单、卡:房间 1:1 的 `Resolve` 语义。B156.2「卡会话默认静默」随之改为：**群默认安静（无寻址不唤醒），但结构轨迹在详情页可查**。

### 4.3 投递语义（本卡核心契约）

- **唤醒的必要条件**：一条消息的寻址命中该成员。寻址有两类来源：**显式 `@`**（可多个）与 **`reply_to`**（隐式寻址原作者，一人）。
- **无寻址发言**：落账、进未读，**不唤醒任何人**。
- **`@卡号`** 解析为"那张卡的当前席位"（席位权威仍在卡），换绑后依然成立。
- **系统结构事件**（卡进群/移出、协调者入群、换绑、卡收口或终止、`needs_human` 亮起）：不唤醒任何人，归详情页 timeline。
- **扇出禁令**：任何"按成员集合"的投递都是缺陷。现状两处必须改（都是现状读数，contract 复核）：
  - `internal/agentd/wakeconsumer.go#automationWakeEvent` 首行 `ev.CardID == ""` 直接不唤醒——群消息今天**谁都不醒**，`@` 在群面是哑的；
  - 同文件 `#decodeHumanRoomMessage` 分支：卡房间的人类消息**无条件**唤醒本卡协调者，`mentions` 在唤醒路径里根本没被读。这条规则的形状是广播，多成员群里就是扇出源。
- **唤醒载荷最小化**：协调者 / 主 agent 被唤醒时只带「寻址命中那条 + 它引用的那条 + 未读数」；其余靠它自己按需读（拉）。推送只给定向消息。
- **外部会话的订阅通道**：人与主 agent（外部会话）需要一条只收"寻址命中我"的订阅通道；形态（扩既有 wait 的事件类型，或另立一条）归 contract 定签名。

### 4.4 详情页投影

- **成员与成员状态**：状态只报**可证实的**（沿用蓝图 §5「看板不说谎」）——能续租的成员报精确态（工作中 / 监听中 / 离线），续不了租的外部会话只报「最后活跃 X 前」，**不报在线**。今天的已知债在此核销：`RoomSummary.Live` 生产恒 false、`driver_leases` 三法零生产消费（`docs/roadmap.md` 记债）。
- **协调者派发的任务节点**：从既有任务挂账与镜像投影（`card_tasks` / `task_mirrored`）聚合，不新增执行域依赖。
- **会话 timeline**：结构事件（4.3 末条那批）+ 席位变更。

### 4.5 取代与保留

- **取代**：B156.2 的房间锚点、kind 白名单、书写者矩阵、卡会话只读规则（改由会话归档承担）。
- **保留**：消息即账本事件（append-only、可对质）、`@` 的恰好一次消费语义（`Pending` / `Consume`）、未读游标、attach 到任务的入口、B275 的前端形态。

## 5. 实现决定（决策级，只写用户可见的名字与边界）

1. **会话页是一等公民页面**（2026-09-12 用户裁决）：不占工作台 tab 条、不挂面包屑、不带右栏文件树，整块中央区归它（与工作项页同构），入口在左栏底部 dock。**左栏保留项目树**（全局导航），会话列表是中央区的第一栏。看板保留为卡视图（诊断与批量操作入口），工作台（终端标签）不变——`attach` 从会话跳进工作台 tab。
2. **群聊面**：不分 kind、以自己名义说话；回复渲染成引用条，可点跳转；同一消息可被多条回复，**不折叠线程**。
3. **详情页**承载成员、成员状态、协调者派发的任务节点、会话 timeline 四块。
4. **成员状态取值**：工作中 / 监听中 / 最后活跃（不报在线，除非可续租）。
5. **旧房间**：326 个卡房间只读归档，内容不迁移。
6. **升级的三档边界**见 §2.5；判据写进协调者与主 agent 的纪律，不由频率兜底。
7. **消息挂群不挂卡**；带卡引用锚（点了跳卡）。
8. 对外文案去官僚化：不再出现「开卡即绑 / 一键拉起」一类旧词（B307 已定），也不再出现「协调者类消息 / relay 消息」一类 kind 名。

## 6. 测试决定（接缝清单）

每缝 = 符号 + 调用方；假缝禁令逐条核过。

1. **会话子系统入站门面**（现有 `internal/collab` 门面与其 api 层）：调用方 = 控制面 HTTP 端点、CLI room 命令族。断言全部会话语义：锚点解析、群↔卡唯一性、成员派生、归档只读、身份执法（非成员不能发言）。
2. **投递判定缝**：`internal/agentd/wakeconsumer.go#automationWakeEvent`（现有符号，调用方 = 自动化事件消费循环）。断言：无寻址不唤醒；`@` 命中才唤醒；`reply_to` 命中原作者；`@卡号` 解析当前席位；系统结构事件不唤醒。**加源码级守卫**（先例 `internal/agentd/pointer_gate_test.go#TestPointerRouteAbsentFromSource`）：唤醒路径必须以"寻址命中"为必要条件，写不出别的形状。
3. **席位身份缝**：`internal/proto/seat.go#ValidateSeat` 与席位出示函数（调用方 = room send 出示、投递解析）。断言：换绑后 `@卡号` 仍命中新席位；旧席位出示被拒。
4. **控制台契约层缝**：`web/src/api/rooms.ts`（调用方 = 会话面板三态与详情页）。双侧金样本（`internal/proto/rooms_fixture_test.go` / `rooms.test.ts`）同步锁新增投影。
5. **详情页投影缝**：成员状态与派发节点投影的装配点（调用方 = 详情页组件）；成员状态的"可证实"判据逐条断言（续租成员报精确态、外部会话只报最后活跃）。

## 7. Out of Scope

**永不做**：`@all` / `@here`；任何按成员集合的投递；执行者入群或写账；聊天面内跑执行者会话与展示其工具调用（B156.2 原判保留）。

**本期不做、后续要做（须落 `docs/roadmap.md`）**：

- **主 agent 的内部对话面**（handoff 自带载体）。本卡只支持外部会话形态；内部形态涉及"聊天面承载 agent 会话"与 B156.2 原判的关系，要单独定性。
- **成员状态的心跳写入路径**：本卡只要求"不报不可证实的"；精确态若要覆盖外部会话，需单独设计续租与超时。
- **多人时代**：多人类成员、登录与权限体系、线程、已读回执、在场状态、消息搜索（B156.2 已记）。
- **会话模板与 routines**、goal 驱动自主推进（B156.4 四期）。
- **历史翻页**（B289 残余）、**富文本渲染**（B275 残余）。

**本期不做**：B156.2 的跨卡残余四条（carrier wire 载体、租约三法消费方等）中与本期无关的部分；codegraph 与架构还债（另有归属）。
