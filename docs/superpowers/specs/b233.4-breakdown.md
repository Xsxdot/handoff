## 4. 缺陷族对抗审查

项目清单：`docs/superpowers/specs/2026-08-21-handoff-instantiation-checklist.md` §3（五族 + 序列化边界 + 枚举白名单 + webview 候选）。顶部**没有**「基线版本：charter@\<commit\>」——对不上基线标注，本拆解按项目清单加严，并并入基线追加「承重安全属性」。清单债不在本卡改实例化协议。

### 4.1 通用五族

**生命周期 / 状态机中断**

- Prepare 内部失败：`rollbackWorkspace` 自己收已建 managed 树，不交给 Dispatch defer（现状注释，保持）。
- Dispatch 在 executor 接管前失败：`compensateWorkspace` + `TriggerCompensate` → 回收 managed。接管后崩溃：树留给 Stop/Done/reclaim，不得由补偿抽空运行中任务。
- Stop 中途崩溃：若已 `transit(failed)` 但未走到回收——本卡 Stop **本就不回收**，崩溃与成功同为留存。收口是 reclaim/gc 重入。
- Done 回收失败：既有降级 progress，不回滚 completed。重试入口是 gc，不是重发 done。
- Reclaim 幂等：树已无 → `already_absent`（既有）。
- `gitExec` 每次 `MkdirTemp` 空 hooks 目录，defer `RemoveAll`；崩溃可能留 `handoff-empty-hooks-*` 临时目录——OS 临时目录回收，不新开任务级孤儿表。**无新孤儿类型，因为**不新增进程/工单表/工作树种类。
- agentd 重启：任务行仍有 `WorkDir`/`WorktreeManaged`/`BaseCommit`；内存里的 Capability 由组装点再绑。未完成的 managed 树不会因为重启被 Stop 逻辑误删（Stop 要人触发）。

**静默失败 / 误导报错**

- Stop 报 `worktree_removed=true` 却没删 = 本卡要消灭的窗口（C-6）。
- Stop 留存成功但 CLI/Web 说「清理失败」= 误导；P3 必须改至少一侧，否则用户会去「修」一个不存在的失败。
- Prepare 失败不得返回成功 Task（既有）。
- 挂卡失败不得把建树报失败（树保留、单项 Error）。
- Done 回收失败不得假装树已无：日志 + progress；show/diff 应仍能按「树还在」或随后 reclaim。
- nil Capability 当免检 = 禁止（P2）。
- diff 在树回收后用主仓 HEAD = 历史误导素材；T4 锁右端。

**跨平台假设**

- git worktree 路径、`os.Stat` 判存在、Windows 上文件占用导致 `worktree remove` 失败：沿用既有重试，本卡不改超时。**未验证，需真机**（§5 Windows）。
- `id8` 按字节截断，任务 ID 为 UUID ASCII。**无新路径分隔假设，因为** worktree 目录名仍是 id8，不新人读路径规则。
- `OpenRoot` 读文件逃逸是内核/Go API 行为，Windows 符号链接差异 **未验证，需真机**。
- 不引入 webview 新假设。P3-(a) 只改文案字符串。

**假红 / 假绿测试**

- Ticket 0 金样本锁编码，不是「Stop 已留存」。不得把空壳当故事 2 完成。
- `TestStopRemovesManagedWorktree` / `TestStopReportsWorktreeRemoved` 的旧正向断言必须退役，否则新实现假红；若改测试仍要求删树则假绿。
- `MayRecycle` 表测绿 ≠ Stop 接线绿——T3/T6 必须穿过 `Manager.Stop`。
- 夹具可以编码「MayRecycle 返回 keep 但仍调用 Remove」的世界——反面断言是调用次数=0 且目录仍在。
- 测试锁的是调用方依赖的行为（Stop 后树在、Done 后 managed 树不在、diff 右端），不是适配器内部函数名。P1-(b) 搬家不得让这些测试无意义地红。
- 全包测试若遇沙箱 `Operation not permitted`：记原文，不归因。

**门禁绕过**

- 回收门是 `MayRecycle` + Reclaim 终态检查。Stop/Done/GC/compensate 必须问同一函数，不能 Stop 直调 `RemoveManagedWorktree` 绕过。
- 用户树：`Managed==false` 在所有触发源 keep。
- 手工树：无任务行进不了 Reclaim；`Manual==true` keep 防将来误标。
- 脏检查：new-worktree 免主仓脏；用户树/原地不免。两入口不得串成「new-worktree 也免用户树脏」。
- 读文件逃逸：所有读入口走 `ReadFile`，不另开裸 `os.ReadFile`。
- TOCTOU：Reclaim 动手前重读任务快照（既有，failed→running）。Stop 不回收，窗口从「检查终态与删除之间」变成「留存到显式 reclaim」，可接受。

### 4.2 追加设问

## 5. 真机清单（归协调者执行；机内不得写成已绿）

凡依赖真实 git worktree、运行中 agentd、人可见路径、跨平台文件占用的条目。机内 temp git 测试不是本清单的绿。

2. 对脏的用户 worktree / 原地仓库派发：拒发，用户文件仍在。**未验证，需真机。**
3. `handoff stop`：任务 failed；managed 目录仍在磁盘；CLI **不**打印「已删除」；人可进入该目录看到取消现场。**未验证，需真机。**

5. `handoff done` 之后：managed 目录消失，任务分支仍在；再 `diff` 走任务分支而非主仓 HEAD。**未验证，需真机。**
6. stop 之后再 `handoff reclaim`：managed 树被清。**未验证，需真机。**
7. 用户自带 worktree 任务 done/stop/gc：该树仍在。**未验证，需真机。**
8. 控制台建树带卡号：树建在 `worktrees/manual/...`；卡基线写下；建树函数路径无账本错误。**未验证，需真机。**
9. Web 点「停止任务」（若 P3-(a) 已改文案）：提示为留存而非「清理失败」。若 P3-(b)：本项记为已知误导，协调者改或后续卡。**未验证，需真机。**
10. executor 启动失败（如错误 executor 名）：刚建的 managed 树被补偿回收，无永久孤儿。**未验证，需真机。**
11. agentd 在 Stop 之后、reclaim 之前重启：树仍在，任务仍 failed，reclaim 仍可用。**未验证，需真机。**
12. Windows（若验收范围含）：`git worktree remove` 在文件占用下的失败是否仍只走 reclaim `--force`、Stop 是否仍留存。**未验证，需真机。**
