# B270 切 tab 后 TUI 卡死、滚轮逐行

定级 **L1**。发现自 B267 验收。本机与远程机终端 tab 都会中。

## 症状

工作台（或 home 浮窗）里 TUI 正在跑时，切到别的 tab 再回来：

1. 滚轮变一行一行（或完全不能滑）
2. 无法输入；窗口 resize 后能滑仍不能输入；只能 Ctrl+C 退出再重进 TUI

本机 B267 验收没切 tab，所以当时绿了。

## 根因

`WorkbenchPage` / `HomeWindow` 只渲染激活 tab。切走即卸载 xterm（断 WS，PTY 会话继续），切回从 `since=0` 重放环形缓冲。

重放里的 `CSI ? 1004 h` 会走 xterm `_reportFocus()`：元素没有 `.focus` 类就发 `ESC [O`（失焦）。这不是 DA/OSC/CPR，B267 过滤器放行，打进仍在跑的 TUI。TUI 按失焦处理：停键盘、常顺手关掉鼠标追踪（滚轮退回方向键，一行一格）。resize 触发 SIGWINCH，TUI 重开鼠标（能滑），但不补 `[I]`（仍不能输入）。

Ctrl+C 仍能退出：TUI 把中断当全局，不看出入焦。

## 改动

1. **后台活着**：曾经打开过的终端 tab 切走不卸载、不把画布标成看不见、不 blur、不 resize。只 `pointer-events-none` + 下层 z-index，上面的文件 tab 盖住。原先「只渲染激活 tab」切走即卸载、回来重放环形缓冲，TUI 必坏；后来藏画布/nudge 等于还是没让它在后台活。
2. **tab 按钮不抢焦点**：mousedown `preventDefault`。否则点回来时按钮抢走 textarea，xterm 再发 `[O]`，TUI 照样卡死。
3. **切回补 `[I]`**：激活后 rAF+setTimeout(0) `focus()`；若仍是 1004，再补一条 `[I]`。
4. **重放安全**（刷新仍会重放）：backlog 写入期间丢掉 `[I]` / `[O]`；回放结束后若本 tab 激活且 `sendFocusMode`，补一条 `[I]`。
5. **xterm 的 `[I]` / `[O]` 一律不上送 PTY。** 切 tab 的 blur 发生在 React 把 active 翻成 false 之前，按「仅隐藏时丢」会漏 [O]；漏出去再补 [I]，第一次能恢复、第二次关鼠标追踪。切 tab 不让 TUI 参与 1004。已经关上的追踪，交替屏下 ±1 行 nudge。

不改 PTY 宿主、不改 B268 键盘/滚轮编码、不提前做 B269 的活查询。

## 验收（整张卡）

1. 相关 vitest 绿。
2. 变异：keep-alive 改回只渲染 active → 「切走终端仍在 DOM」转红；重放时 `[O]` 改成上送 → 对应用例转红。
3. 真机：TUI 里切走再切回，能输入、滚轮仍按页；刷新后进同一会话也不卡死。

本节点该干什么一律以注入的纪律块为准。

## Plan

1. `terminalHostResponse.ts` 增加 `isFocusReport`（只认整段 `ESC [I` / `ESC [O`）。
2. `TerminalTab`：backlog 写入期间丢焦点报告；结束后按 `sendFocusMode` 补 `[I]`；`active` 变化时 focus，不把 `active` 放进建连 effect 的依赖。
3. `WorkbenchPage` / `HomeWindow`：见过的终端 tab 切走仍挂着。
4. `Shell` 把 `active` 传进 `TerminalTab`。
