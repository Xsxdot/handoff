### T3 · 协调会话：OpenCode 实装，其余不支持，Runner 退役为包装

**②意图与为什么**：今天只有 OpenCode 能拉协调者。把 `supportedCLIs` 扩名单或 Launch 失败时改走 opencode，会把「能协调」变成谎言。消费方继续持 `keysclient.Runner`，提供方是 `Coordinator`；`Host.RunTurn` 不是第三套契约。ctx 取消必须打断回合——现状 `context.Background()` 做不到。

### T4 · OneShot：Invoke 迁入 Approver，grok effort 是调用方 Limits

**①契约引用**：冻结 77–92、40–42、87–91；契约 §3 `CommandContext` 杀进程语义。

**②意图与为什么**：`OneShotArgs` 把「grok 一次性 = low effort」编进提供方默认，审批策略和原生能力缠在一起。迁到 `OneShot.Invoke` 后，argv 留各家包；Approver 传入 `Limits.Effort=low`；Codex 的 sandbox/exec 是 NativeLimits 不是 Limits 字段。审批一次性不得借用被审批任务的会话，也不解析 JSON（仍是 Approver）。

**③验收（行为化）**：

- `go test ./internal/executor/grok -run 'OneShotArgv' -count=1`：effort 空带模型 → `grok -m … -p …`；`EffortLow` 带模型 → `--effort low` 在 `-p` 之前；未知 effort（`high`）失败。
- `Approver.Decide` 生产路径调用 `OneShot.Invoke`，**零次** `OneShotArgs`（可用间谍 / 把 `OneShotArgs` 在测试中替换为 panic）。传入 grok 时 `Limits.Effort == EffortLow`。
- 未知执行者 Invoke/Decide 失败，错误列出支持名单。
- Codex 能力报告含 `sandbox=read-only` 与 `invoke=exec`；`OneShotLimits` **没有** sandbox 字段。
- `Limits.Timeout` 不出现在 argv；取消走 ctx。`Invoke` 的 ctx 取消必须打断实际进程（机内：短 ctx + 可阻塞的 stub 命令，断言进程已退出；不保证杀进程组）。
- `OneShot` 返回文本/用量/状态；测试断言 Approver 仍是 JSON 解析者（Invoke 结果不被当成 allow/deny）。
- 审批路径不出现 OpenCode session API / PromptAsync（锁既有负例）。
- 旧 `TestOneShotArgs` 在 `OneShotArgs` 删除前保持「尚未退役」或同步改为测 Invoke；不得把 grok 默认 low 改掉却仍让旧函数当权威。
- `go test ./internal/executor ./internal/executor/grok ./internal/agentd -run 'OneShot|Approver|Decide' -count=1` 命中新测试且 ok。
- 缺陷族：生命周期——ctx 取消后孤儿进程由 CommandContext/Kill 收，不新开进程组语义。静默失败——Invoke 失败必须让 Decide fail-closed（既有 Approve=false + Err），禁止报成功无输出当 allow。假绿——只测 `OneShotArgv` 编码不是完成条件，必须穿过 Approver→Invoke。序列化——argv 是手写投影，五家各一条穿过真实编码函数的断言（grok 已有属性式金样本；其余家用固定输入金样本）。枚举——`EffortLow`/`OneShotOK|Failed|Canceled` 过白名单。承重安全——ctx 取消打断进程必须能变红。

**④入口指针**：`internal/executor/oneshot_cap.go#OneShot`、`internal/executor/oneshot.go#OneShotArgs`、`internal/executor/grok/oneshot_argv.go#OneShotArgv`、`internal/agentd/approver.go#Decide`、`internal/agentd/approver.go#defaultRunCmd`、各家 oneshot 实现。有界文件集 = 上述 + 测试。删除 `OneShotArgs` 的提交切分归 plan（先改 Decide 再删表）。

## 4. 缺陷族对抗审查

项目清单：`docs/superpowers/specs/2026-08-21-handoff-instantiation-checklist.md` §3（五族 + 序列化边界 + 枚举白名单 + webview 候选）。顶部**没有**「基线版本：charter@\<commit\>」——对不上基线标注，本拆解按项目清单加严，并并入基线追加「承重安全属性」。清单债不在本卡改实例化协议。

### 4.1 通用五族

**生命周期 / 状态机中断**

- 执行：宿主重启后未实现 `Recoverer` 的 adapter（含 fake）走不存活失败路径，禁止假装恢复成功（T2）。孤儿 serve 由既有 Stop/Kill/sweep 收；本卡不新资源类型。
- 协调：现状 Launch 把 ctx 丢成 `Background()`——中途取消/重启不会打断回合。T3 把 ctx 贯穿；unix 用既有 killGroup，与 OneShot 的 Process.Kill **不是**同一条杀树（契约 §10，本卡不统一）。超时上界 `DefaultTurnTimeout` 本卡不改数值。
- OneShot：ctx 取消走 `CommandContext` 默认 `Process.Kill`，不保证杀进程组。孤儿一次性进程由该 Kill + Approver timeout 收。
- Profile：Prepare 中途崩溃可能留下半残 HOME——下一次 Prepare/Verify 必须可重试且不得把半残标成功（T5）。不新开 HOME GC 守护进程。
- Skills：Install 中途一家失败继续；基准副本若写失败才全盘失败（现状语义，P3-(a) 保持）。
- **无新孤儿类型，因为**不新增进程表/工单表/临时目录种类；用的是既有 HOME、既有 CLI 子进程。

**静默失败 / 误导报错**

- 不支持的能力必须 `errors.Is(ErrCapabilityUnsupported)`，禁止改走另一家（T1/T3）。hostapi「未实装」不得再当权威形状。
- `BaselineReport` 支持 ≠ 已接线（C-8）。Dispatch/Launch/Decide/Install 必须真正调能力面。
- Prepare 文件写成 ≠ EngineOK ≠ Verified（T5）。
- Decide 在 Invoke 失败时必须 fail-closed（既有 Approve=false+Err），禁止「没输出也当允许」。
- skill 内嵌内容为空必须拒绝（既有 cmd 守卫）。
- Codex 限额期失败写成「不支持执行」= 误导；T7 归因模板 + 真机清单分开记。
- OpenCode 真机改走付费模型 = 本卡禁令，失败必须贴原文。

**跨平台假设**

- 本卡不新引入 webview。路径一律 `filepath`。
- 协调杀树：unix 进程组 vs 其它平台直接子进程——沿用 hostapi，不在本卡「统一」。Windows 协调取消 **未验证，需真机**。
- OneShot 不杀进程组：Windows/POSIX 都只 Kill 直接子进程；有孙进程时 **未验证，需真机**。
- skill 老软链迁移依赖 unix unlink 不跟随；Windows 不得回退到「目录软链到基准副本」（B84 已踩）。
- grok 注册仍走符号链接能力探测（`adaptersForWithProbe`），本卡不改成按 GOOS 写死。
- claude 凭据在 Keychain：Profile 必须报不足，不得假装文件拷贝在 Linux/Windows 上也成立。

**假红 / 假绿测试**

- Ticket 0 金样本锁编码，不是行为；不得把「空壳存在」当故事 1 完成。
- `supportedCLIs` 仍只认 opencode 会让「claude Launch 失败」假绿——必须锁 `errors.Is(ErrCapabilityUnsupported)` 且零次兜底。
- 夹具可以编码「Profile.Prepared 但引擎起不来」——EngineOK 与真机执行走 §5。
- Codex 限额夹具若写成 NativeLimits 缺失，会把限额失败假绿成能力缺失——报告与真机归因分开。
- 测试锁的是调用方依赖的行为（Invoke 被 Decide 调用、Launch 不兜底、allow ⊆ 快照），不是 Bundle 内部字段顺序（P2 换实现不应无意义地红）。
- 全包测试若遇沙箱 `Operation not permitted`：记原文，不归因；T7 要求无沙箱环境复跑。

**门禁绕过**

- 免审 ⊆ 快照：OpenCode 已有 233.1；第二家（P5）必须同一条。只改 client 不改第二家 taskenv = 绕过。
- 同一规则入口：各家只经自己的 Adapter/Profile/Skills，禁止 Manager 另开 switch。
- `StartReq.Approval==nil` 不得解释成全部免审（233.1 已锁；本卡其它家若仍 nil，保持旧行为但不得新开「全 allow」）。
- Skills.Remove 无 Authorized 不得删。
- Profile 凭据 standalone 不得变成拷会话库。
- TOCTOU：Prepare 检查与写入之间并发第二任务写全局规则——用「全局规则与 Overlay 分文件」缓解；窗口接受项 = 不以锁文件做跨进程互斥（本卡不新分布式锁）。真机并发见 §5。
- CLI `skill install` 与将来其它安装入口必须共享 Skills，不另开路径表。

### 4.2 追加设问

**序列化边界**

- 新字段：`OneShotReq`/`OneShotReply`/`ProfileReq`/`ProfileReport`/`SkillSite`/`CapabilityReport` 主要是进程内接口，不是跨语言 wire。CLI 打印 `SkillSite` 是一处手写投影（`cmd/skill.go`），T6 必须用真实 Install 返回值断言打印字段，而不是只测内部 struct。
- argv 是手写投影：五家 oneshot 编码函数各有金样本；grok 已有空 effort / low / 无模型三条。必须有一条穿过 Approver→Invoke 的回归（T4），「两端各自绿」不够。

- 本卡默认不新增 proto.EventType / Ticket 字段。若有人想把 CapabilityReport 塞进 HTTP——**先退回 contract**。

**枚举新值过既有白名单**

- 新字面值：`Cap*` 五类、`Harness*` 五名、`EffortLow`、`CredentialStandalone`/`CredentialMainHomeSync`、`OneShotOK|Failed|Canceled`、`Skill*` 五态。流经点：Registry.Require、OneShotArgv effort switch、Profile 凭据策略、CLI skill 状态打印、hostapi `supportedCLIs`（不得把 Harness* 全写进去冒充协调）。
- `Ticket.Kind` / `EventType` / `ApprovalStatus` 不新增。CapabilityName 不得流入 Ticket.Kind。
- Codex NativeLimits 六条是报告词表，不是 EventType。

**承重安全属性（必须能变红）**
