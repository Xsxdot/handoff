# home 基准终端浮窗设计

**形态基准**：`prototypes/desktop-console/` 里的 `HomeDock` / `HomeWindow`
（08-14 新增，用户当场确认）。这是**新形态**，不是还原——原型此前根本没有
悬浮按钮这个东西（`grep 悬浮|fab|floating` 零命中），现在实现里那个按钮是
[shell-calibration spec §2.5](2026-08-12-w4-shell-calibration-design.md) 参照 Orca
新发明的。本文给它一个真正的形态。

---

## 1. 问题

现在右下角悬浮按钮点开只有「新终端」一项，点了之后调的是
`wb.openTerminal(HOME_BASE)`——**它开出来的就是中央工作区的一个普通 tab**，
只是基准目录是 `$HOME` 而不是某个工作树。

后果有两个，第二个才是真问题：

1. home 终端和工作树 tab 混在同一条 tab 条上，看不出哪个不属于当前目录。
2. **它们跟着中央工作区的目录切换走。** 中央 tab 组是按「当前选中目录」组织的，
   而 home 终端不挂在任何目录上——它被塞进一个它不属于的容器里，
   于是「我刚才那个 ssh 到 devbox 的终端去哪了」变成一个需要翻找的问题。

home 终端的典型用法恰恰是**跨目录长期驻留**（ssh 到别的机器、跑一个盯着的命令、
查点东西），这和中央工作区「跟着我正在看的目录走」的组织方式是冲突的。

---

## 2. 形态裁决

**home 终端跑在一个独立浮窗里，与中央工作区完全无关。**（用户 08-14 裁决，
在原型里点过确认。）

三个已定的点：

| 问题 | 裁决 | 理由 |
|---|---|---|
| 在哪渲染 | 浮窗，不是中央 tab | 见 §1，它本就不属于任何目录 |
| 开多个怎么办 | **一个浮窗，内含 tab 条** | 多浮窗要管堆叠/焦点/位置记忆，且很快会遮满中央区 |
| 关浮窗等于什么 | **收起，不杀会话** | 与 PTY 已确立的「切基准不杀、点 × 才杀」同一口径 |

### 2.1 三个层次

```
圆钮（常驻右下角）
  └─ 小面板（点圆钮展开）——清单入口，不是内容容器
       ├─ 已开终端列表（每项带存活点）
       └─ 新终端 ⌘T
  └─ 浮窗（点列表项或新建时出现）——内容容器
       ├─ 标题栏（可拖 · 右上角「收起」）
       ├─ tab 条（每 tab 一个 × · 条尾 +）
       └─ 终端内容 + 右下角拉伸角
```

**小面板与浮窗是两样东西，不要合并。** 小面板回答「我开过哪些、还活着几个」，
浮窗回答「其中一个现在在干什么」。合并的话，浮窗收起后就没有任何入口能看到
「还有三个会话活着」——而这恰恰是收起不杀这条口径成立的前提。

### 2.2 圆钮上的角标

圆钮右上角显示当前存活的 home 终端数（0 时不显示角标）。这是浮窗收起后
**唯一**的存活提示，不能省。

### 2.3 收起 vs 关闭（这条最容易做错）

| 操作 | 位置 | 行为 |
|---|---|---|
| 收起 | 浮窗标题栏右上角 | 浮窗消失，**所有会话继续活着**，角标保持，再打开是原样 |
| 关闭单个会话 | tab 上的 `×` | 该 PTY 会话真的结束，tab 消失 |
| 关闭最后一个会话 | 同上 | 浮窗自动消失（没内容了），角标归零 |

**不提供「关闭浮窗并杀掉全部」这个操作。** 一次误点毁掉几个长跑会话，
而收益只是省几下点击。

### 2.4 尺寸与位置

浮窗可拖（标题栏）、可拉伸（右下角）。最小 360×200。位置与尺寸在会话内保持，
**本轮不做跨刷新持久化**——PTY 会话本身能跨刷新恢复（`usePtyRestore`），
但窗口几何存哪儿是另一个决定，不在本轮夹带。

## 3. 与既有代码的边界

### 3.1 必须拆开的：tab 归属

home 终端目前走 `useWorkbench` 的 tab 模型。本轮要给它一套**独立的状态**
（一组 tab + 当前激活 + 浮窗开合 + 几何），不复用中央工作区的 tab 组。

**红线：不要改 `WorkbenchPage` 的 `renderContent` 签名。** 这条是 W4 交接文档
点名的红线，PTY 那期已经扩过一次，再动会把冲突面放大到整个工作台。
浮窗是 Shell 层的兄弟节点，不经过 WorkbenchPage。

### 3.2 PTY 尺寸同步与会话存活（**08-14 出计划时核实，本节已更正**）

本节初稿把成本估高了。读代码后确认了两条既有事实，实现时**以下面这版为准**：

**① 尺寸同步是免费的，不要额外接。**
`TerminalTab.tsx:143` 已经挂了 `ResizeObserver` → `fit.fit()`，:134 又有
`term.onResize(({cols,rows}) => handle?.resize(cols,rows))`。只要 `TerminalTab`
渲染在浮窗内部，拉伸浮窗就会自动重算行列并上报服务端。

👉 **不要**在浮窗的拉伸回调里再调一次 resize——会和 ResizeObserver 打架，
产生可见抖动。（初稿曾写「浮窗拉伸结束后要重新 resize 该 PTY」，那是错的。）

**② 「收起不杀」也是免费的。**
`TerminalTab` 的 cleanup 里写着「只断连接，不发 DELETE：服务端会话继续跑」
（:149）。所以卸载 = 断连接、会话在服务端活着，收起不需要任何会话侧处理。

**真正要写的只有杀会话这一半**：`×` 要显式调 `deletePtySession`
（`api/client.ts:259`），语义与中央 tab 的 `beforeCloseTab` 保持一致，
**失败不许静默吞掉**——吞了的话用户以为关了、服务端其实还留着一个 shell。

走查项 5 已经钉住过一个相关的坑：**恢复输出时 `truncated` 要先清屏**，
别在浮窗里重犯。

### 3.3 不支持 PTY 的对端

现有实现用 `ptySupport.supported('') !== false` 决定要不要渲染圆钮。这条保留
——**说实话而不是给个死按钮**是走查项 9 立的规矩。

### 3.4 安全边界原样保留

浮窗里**只有终端，没有文件浏览**。`FloatingNewPane` 文件头写的理由仍然成立：
以 `$HOME` 为根浏览文件，等于让控制台会话（刻意做得比主令牌弱的凭据）读到
`~/.handoff/config.yaml` 里的主令牌与 `~/.ssh/`，弱凭据当场提权成强凭据。
home 基准的文件浏览需要单独设计（排除清单 / 显式授权根），不在本轮。

## 4. 明确不做

- 跨刷新记住浮窗位置与尺寸（§2.4）
- 多浮窗、分屏内嵌 home 终端
- 浮窗里放文件 tab 或任务 TUI（§3.4 安全边界）
- 「关闭并杀掉全部」批量操作（§2.3）
- 浮窗最大化 / 吸附到边缘

---

## 5. 验收标准

1. 圆钮常驻右下角；有存活会话时带数字角标，无则不带
2. 点圆钮出小面板，列出已开终端，每项带存活点，底部有「新终端 ⌘T」
3. 点列表任一项 → 浮窗打开并激活该终端；小面板收起
4. 浮窗内 tab 条可切换、可新建、每 tab 可单独关闭
5. 拖标题栏浮窗移动；拉右下角浮窗改尺寸；尺寸变化后终端内容按新尺寸重排
   （`stty size` 与窗口一致）
6. 点「收起」→ 浮窗消失、角标仍在；再点圆钮→列表还在→点进去输出连续、
   会话未断
7. 点某个 tab 的 `×` → 该会话结束；关掉最后一个 → 浮窗消失、角标归零
8. **中央工作区的 tab 条上从不出现 home 终端**；切换左栏目录不影响浮窗
9. 对端不支持 PTY 时圆钮不渲染（不是渲染一个点不动的按钮）
10. 前端四条全绿：`npx vitest run` / `npm run typecheck` / `npm run lint` /
    `npm run build`

## 6. 已知风险

- **仍然比形态修复贵，但比初稿估的便宜。** 浮窗容器（拖动、拉伸、层级、焦点）
  确实是新造的一套东西，按新功能算不按形态修复算。但 §3.2 已更正：PTY 尺寸
  同步与「收起不杀」两项都由既有代码免费提供，不在成本里。
- **与 B81 的冲突面是实的**：B81（工作区文件写入）也在改 workbench 一带。
  建议顺序是先把 B80/B81/B83 并回 `w4-delivery`，再开本条——否则这套改动
  要在两条未合并的线之间来回对齐。
- **拖动实现要注意 pointer 捕获**：原型里用的是 `pointermove` + 一次性
  `pointerup` 解绑。真实实现里终端是个会吃事件的组件，拖动时要确保事件不被
  终端截走（原型没这个问题，因为它的"终端"只是一段静态文本）。
