## 3. 架构户口

### 3.1 不新立顶层域，不整包搬走

`d_workspace` 已是顶层 boundary 域。架构法第一条：不值得为「再拆一个工作区子系统」付第二次冻结成本。本卡：

- 不新增 `d_git` / `d_artifacts`。
- 不把 `internal/agentd/workspace.go` 整文件迁出（轻档；物理搬目录留给实现按有界文件集竖切）。
- 契约包 `internal/workspace` 归 `d_workspace`（best 容器 `k_workspace_fn` / `k_workspace_model`）。
- 接口作为能力门面定义在工作区包。消费方（编排/网关）持有 `Capability`；实现仍在 agentd，组装点绑定。第九条的 DIP 形态（接口在使用方）此处不适用：这是编排调用工作区，不是工作区回调编排。

架构法第三条：`internal/agentd` 已 oversized，`work*` 前缀族 ≥5。本卡回答：契约包是竖切的户口，本节点只落空壳；实现节点再决定哪些函数迁入，禁止一次拆散无界。

## 5. 冻结清单

每条单独可判 pass/fail。

### 5.1 能力面与边界

1. 工作区能力接口是 `workspace.Capability`，定义在 `internal/workspace`。
2. `Capability` 方法集不含 `Push`。
3. `Capability` 的任何方法都不得调用 `ledger.Store.SetCardBaseBranch`。
4. `PrepareReq` 不得声明 `CardIDs` 字段。
5. `ManualReq` 不得声明 `CardIDs` 字段。
6. `ManualTree` 不得声明 `CardResults` 字段。
7. 挂卡发生在应用调用 `CreateManual` / 建树 HTTP **之后**，不得发生在工作区函数体内。
8. `Capability` 为 nil 不得被实现方解释成跳过 `EnsureRepoUsable`。
9. `Capability` 为 nil 不得被实现方解释成跳过脏检查。
10. 本卡不新增 HTTP 路径。生产入口保持 `GET /api/tasks/{id}/diff`、`GET /api/tasks/{id}/file`、`POST /api/projects/{name}/worktrees`、`POST /api/gc`、任务 reclaim。
11. 本卡不发明第二套 git 传输协议（不新增 bundle/push RPC）。
12. 工作区能力不宣布业务 pass（不写任务 completed、不写卡列）。
13. 具体 Capability 只在登记的组装点绑定。
14. `internal/workspace` 不得 import `internal/proto`。
15. `internal/workspace` 不得 import `internal/ledger`。

### 5.2 基线身份

16. 任务基线身份是 `proto.Task.BaseCommit`，值为 40 位小写十六进制，或空（切已存在分支/老任务）。
17. `ResolveBaseline` 的 `sha` 非空且不是 40 位小写 hex 时必须失败，错误链含 `ErrBadWorkspaceReq`。
18. `ResolveBaseline` 的 `sha` 为空时 `Start` 必须是任务仓库当时 HEAD（空仓库允许 `Start` 为空）。
19. `BaseCommit` 一旦写入，事后不得改成仓库默认分支的当前尖端。
20. `IsCommitSHA("482aab1f9e12a3b4c5d6e7f8a9b0c1d2e3f4a5b6")` 为 true。
21. `IsCommitSHA("482AAB1F9E12A3B4C5D6E7F8A9B0C1D2E3F4A5B6")` 为 false。
22. `IsCommitSHA("482aab1")` 为 false。
23. `NewResultRef` 在 commit 非空且非 40 位小写 hex 时必须返回错误。
24. `NewResultRef` 允许 commit 为空（表示未知，不编造）。

### 5.3 隔离与准备

25. `Prepare` 的 repo 与 task_id 必填，否则失败。
26. `Branch` 与 `NewBranch` 同时非空必须失败。
27. `Worktree` 非空且 `NewWorktree==true` 必须失败。
28. `Base` 非空且 `Branch` 非空必须失败。
29. `Branch`/`NewBranch`/`Base`/`Worktree` 以 `-` 开头必须失败。
30. `NewWorktree==true` 不得因主仓库脏而失败。
31. 原地模式（Worktree 空且 NewWorktree false）在工作区脏时必须失败，错误链含 `ErrDirtyWorktree`。
32. 用户树模式在该树脏时必须失败，错误链含 `ErrDirtyWorktree`。
33. 用户树路径必须是本仓库工作树根，否则失败。
34. `NewWorktree==true` 时 `Prepared.Managed` 必须为 true。
35. 用户树或原地模式 `Prepared.Managed` 必须为 false。
36. `Branch` 与 `NewBranch` 都空时，分支名必须等于 `TaskBranch(taskID)`。
37. `ID8("abcdefgh-rest")` 的字节结果是 `abcdefgh`。
38. `TaskBranch("abcdefgh-rest")` 的字节结果是 `handoff/abcdefgh`。
39. `TaskBranchPrefix` 的字节结果是 `handoff/`。
40. agentd 自己的 git 调用必须带空 `core.hooksPath`，不得执行仓库 hooks。

### 5.4 结果引用与 diff

41. 结果引用含 `Repo`、`Branch`、`Commit`、`Path` 四字段（`workspace.ResultRef`）。
42. 工作树仍存在时，diff 右端必须是该工作树的 `HEAD`，仓库路径必须是 `WorkDir`。
43. 工作树已回收且 `Task.Branch` 非空时，diff 右端必须是 `Task.Branch`，仓库路径必须是 `RepoPath`。
44. 工作树已回收时，diff 右端不得是主仓库 `HEAD`。
45. `DiffRange` 的 patch 调用必须是 `git diff <base>...<head>`（三个点）。
46. `DiffRange` 的 log 调用必须是 `git log --oneline <base>..<head>`（两个点）。
47. `base` 为空或以 `-` 开头时 `DiffRange` 必须失败。
48. `head` 为空或以 `-` 开头时 `DiffRange` 必须失败。
49. `ReadFile` 对逃逸路径（`..` / 绝对路径）必须失败。

### 5.5 留存与清理

50. `MayRecycle` 在 `Managed==false` 时必须返回 `keep`。
51. `MayRecycle` 在 `Manual==true` 时必须返回 `keep`。
52. `MayRecycle` 在 `State=="waiting_review"` 时必须返回 `keep`。
53. `MayRecycle` 在 `Trigger==stop` 时必须返回 `keep`。
54. `MayRecycle` 在 `Trigger==compensate` 且 managed 非手工时必须返回 `recycle`。
55. `MayRecycle` 在 `Trigger==done` 且终态 managed 时必须返回 `recycle`。
56. `MayRecycle` 在 `Trigger==explicit` 且终态 managed 时必须返回 `recycle`。
57. `Reclaim` 对非终态任务必须失败。
58. `waiting_review` 不是终态。
59. GC/reclaim 不得删除用户树（`WorktreeManaged==false`）。
60. GC/reclaim 不得删除手工树（`worktrees/manual`）。
61. 有 `Commit` 字段不得单独构成删除工作区的授权。
62. `Stop` 不得调用 `RecycleManaged`（取消留存；显式 reclaim/gc 才清）。
63. `Done` 仅在 `MayRecycle` 返回 `recycle` 时才调用 `RecycleManaged`。
64. 派发补偿（executor 未接管）允许回收刚建的 managed 树。

### 5.6 生产入口与既成超时

65. 生产派发入口保持 `Manager.Dispatch` →（现状）`ResolveBaseline` + `PrepareWorkspace`。
66. `WorkspaceGitTimeout` 本卡保持 2 分钟，覆盖 Prepare/Remove/CreateManual 整组 git。
67. `FetchTimeout` 本卡保持 2 分钟，仅覆盖基线补拉，不并入 `WorkspaceGitTimeout`。
68. `ManualNewBranch` 的字节结果是 `new_branch`。
69. `ManualExistingBranch` 的字节结果是 `existing_branch`。
70. `TriggerStop` 的字节结果是 `stop`。
71. `TriggerDone` 的字节结果是 `done`。
72. `TriggerExplicit` 的字节结果是 `explicit`。
73. `TriggerCompensate` 的字节结果是 `compensate`。
74. `RetainKeep` 的字节结果是 `keep`。
75. `RetainRecycle` 的字节结果是 `recycle`。

## 7. 三重闸门拍板记录

命中三条的决定：

1. **Capability 定义在 `internal/workspace`；本卡不把 `workspace.go` 从 agentd 整包搬走。** 回头要动编排、网关、工作区三域与目标图；后人看到新包只有接口会想「删掉并回 agentd」或反过来「一次迁完 82 个 agentd 文件」。被否方案：接口放进 `k_agentd_fn`（best 归属编排，独立是假的）；本卡整文件搬家（轻档、无界）。不做新顶层域。
2. **Stop/取消不回收 managed 树；waiting_review 不回收；Done 归档或显式 reclaim/gc 才回收终态 managed。** 反过来把 Stop 继续当清理入口，现有测试仍可能绿（今日实现就是删）。被否方案：维持 Stop 删树（残留少，但取消现场不可查）；「有 commit 就可以删」。用户树/手工树永不按任务垃圾删。
3. **工作区请求类型不含 card_ids；挂卡留在应用。** 后人看到建树 API 会想把挂卡收进 Capability「一次做完」。被否方案：`PrepareReq`/`ManualReq` 带 CardIDs。233.3 负责传输不再挂卡；本卡只冻工作区函数零写卡。

显式不做（spec 已否，此处不重复展开）：改 push 归属、通用产物平台、第二套 git 协议、首次配置。

## 11. 依赖既成行为（git 调用）

出处均为本轮读数：

- agentd git 一律 `exec.CommandContext` + `-C repo` + `-c core.hooksPath=<空临时目录>`（`internal/agentd/workspace.go#gitExec`）。不拼接 shell。
- 工作区准备/删除整组超时 `WorkspaceGitTimeout=2m`（同文件包级 var）。
- 基线 fetch 超时 `FetchTimeout=2m`，与本地 git 超时分离；同仓库 fetch 串行锁 + ref 锁竞争最多 3 次。
- `RemoveManagedWorktree` 重试 5 次、间隔 400ms；失败不降级 `--force`（force 是 reclaim 的显式旗标）。
- `DiffRange` 三连点 patch、两连点 log，见 §5.4。
