# B395 spec：SSE 断连丢权限工具等待窗口，回合永挂不自愈

**上游状态：已批准**（用户 2026-09-22 决定：与 B396 一并优先修）
**级别：L2 单子系统**（`internal/agentd` 的 opencode 权限桥 + SSE 消费；必要时触达 `internal/hostapi` 的回合上界）
**入口节点：debug**（先根因后修：环路在哪一段丢、为什么没有兜底，必须落到 file:line）
**上游证据**：B395 卡上的 agentd 日志原文（同秒两条 WARN）与"帧文件 20 分钟零产出"的对照；今晚同型至少三次（B390 计划轮、B393 第三轮与第四轮）。

## 1. 问题

SSE 断连重连时，一条权限门（permission_request/应答）与它对应的「工具等待窗口」对不上：

```
10:29:09.179 WARN opencode 权限请求未找到对应工具等待窗口  task=… perm=per_0c6…
10:29:09.191 WARN opencode 权限应答成功但未找到工具等待窗口  task=… perm=per_0c6…
```

⇒ executor **等一个永远不会回来的工具结果** ⇒ 回合永挂、**不自愈**（帧文件 20 分钟零产出），只能人工 `resume --force` 收口。今晚已咬三次，每次都要人。

## 2. 范围

**做**：让"权限应答找不到等待窗口"不再导致回合永挂——重连后能重建等待窗口/重问未决项，或让该回合**有上界退出**并落可见失败（needs_human + 账本行）。
**不做**：不动权限门的裁决语义（谁能批、批什么、复用/白名单等）；不动 B394 已收口的判据白名单；不手改线上状态。

## 3. 待查（先取证再改）

1. 两条 WARN 的发出点（grep 原文）与权限桥实现：等待窗口是**按 SSE 连接生命周期持有**还是**按任务/会话持有**？断连时它被谁清掉了？
2. 断连期间到达的 `permission_request` 有无重放/缓冲路径？（日志自称 `/event 无重放语义` ⇒ 是否需要重连后**重问**未决项。）
3. **为什么没有兜底**：B393 给 resume 加了有界等待，但本挂点在**工具等待窗口**——确认 `hostapi` 的回合上界（30 分钟）为何没有把这一轮判死；上界是否只覆盖"回合进程"而不覆盖"等待权限"。
4. 复现路径：能否在测试里制造"权限应答与等待窗口错位"（缝在哪、用什么替身），今天预期红。

## 4. 验收判据

1. **根因**：给出环路在哪一段闭合（file:line + 实测/日志原文）；不做完不许提修复。
2. **红色回路**：能复现"错位后回合永挂"或其触发条件；修后转绿。
3. **变异复验**：把兜底/重建去掉要重新变红。
4. **不误伤**：正常的权限门流程（请求→裁决→工具继续）不回归；权限语义不动。
5. **真机**：一次真实回合中人为断连 SSE，回合应**在有限时间内收口**（成功续跑或落可见失败），而不是永挂。
