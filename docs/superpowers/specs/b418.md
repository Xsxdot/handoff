# B418 — Android 壳清罐语义误判修复（L1，spec+plan 合体页）

## 背景（发现自 B417 真机竖切走查，2026-09-28）

真机（HONOR VER-AN00，Android 16/debug APK）走查 B417 直通竖切：扫码配对、relay 隧道、
安全存储写入、机器列表全部成功；**点进任意在线机器必败**——webview 纯白不导航，错误态
「换取会话失败，请重试」。

## 根因（logcat 23:06:05 实证）

同一帧内：`switchMachine 完成`（核心侧切机 + ticket→cookie 兑换成功）→
`E/WebviewSessionBinder 清 jar 失败 category=EXCHANGE machine=mac-02`。

`AndroidCookieStore.awaitCookieAccepted` 把 `CookieManager.removeAllCookies` 的回调布尔当
「操作成功/被拒」；Android 平台语义实为**「是否删除了任意 cookie」**——`false` = 罐本就为空，
净罐目标态已达成，不是拒绝。全新安装首次进入任意机器时罐必然为空 → 回调必 false →
清罐必抛 `CookieRejectedException` → `WebviewSessionBinder` fail-closed 不导航 → **每台机器都进不去**。

单测 `AndroidCookieStoreTest` 以「平台返回 false 替身」把这条错误语义钉成了绿
（夹具编码了不存在的平台世界；真机一跑即现形——B417 验收清单「平台 cookie store 行为」条
的正主）。

## 修复设计（改动边界：`mobile/android/app/src/main/.../AndroidCookieStore.kt` + 对应单测）

1. `clearHost`：等待删除回调时 **false 与 true 都放行**（false = 无 cookie 可删 = 净罐已达成）；
   回调无结果（null）仍 fail-closed。
2. `setCookie`：**保持现状**——回调 false = 写入被拒 = 真失败，继续 fail-closed
   （I3 序「注入失败不导航」承重不变）。
3. 单测：删除两处钉错语义的断言（`removeAllCookies返回false_抛错`、
   `清罐返回false_进入错误态`），代之以新语义断言（false 放行并 flush、binder 继续
   注入并 load）；`setCookie false` 两条测试原样保留。
4. 类头注释同步改语义说明。

不改动：`WebviewSessionBinder` 的 I3 序与 fail-closed 结构、绑定面、Go 核。

## 验收判据

1. 局部：`./gradlew :app:testDebugUnitTest` 全绿（新语义单测）。
2. 真机复验（B417 竖切续验）：全新安装 APK → 扫码配对 → 列表 → **点进在线机器 →
   webview 加载已认证控制台（非白屏、非登录页）**；重试路径可用。
3. 回归：切机 A→B→A、离线机不可入、日志卫生照 B417 清单继续走。
