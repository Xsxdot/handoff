## 定级理由

跨子系统，并对接已有执行面 Stop / Reclaim：

- **账本**：`PurposeRounds` / `ReviewRounds` 的返回值必须包含「已派出但未挂账」的轮次，否则重试仍用首轮名
- **编排**：`Dispatcher.ViaTemplate` 在 Transport 成功、本地落账失败（含写闸关闭）后必须记耗费轮次并触发补偿
- **传输 / 执行**：补偿走既有 `Client.Stop` + `Client.Reclaim(force)`，不删分支（B77 / 用户选 B）
- **两处生产装配**：CLI 裸 `card dispatch` 与 agentd `startCardStep` 都必须把补偿钩子接到 Dispatcher 上（`--step` 不在 CLI 里装配 Dispatcher，走本机 agentd）

选轻档：一张卡、一条失败缝，拆并行子卡会把「计数」和「停 task」拆散。契约冻结与拆解照做，实现一轮收口。

本节点该干什么一律以注入的纪律块为准。

## 问题陈述

谁：协调者（CLI 裸模板派发）和本机 agentd（`card dispatch --step` / 控制台节点）在共享派发成功之后，本地账本没挂上这笔 task。

条件：B233.6 已把 `RecordDispatchAndLinkTask` 做成同一事务，挂账失败回消 `EvDispatched`，不重派第二个 task。B39 补偿只在 **executor 尚未接管** 时删树+删新建分支。Transport 已经返回成功时 executor 已在跑，B39 不走。`PurposeRounds` 只数 `card_tasks` 挂账行，回滚后仍是 0，重试仍用首轮名。`reclaim` 按 B77 永不删分支。裸 `handoff dispatch` 本来就没挂账。

通道：现有 `Dispatcher.ViaTemplate`。不新造命令、不新造 HTTP 路径、不新造事件类型。

要变的事实：

1. Transport 返回了 task id，但快照+挂账没落成（事务回滚或写闸关闭）：账本记下「该卡该 purpose 已耗费一轮」，`PurposeRounds` / `ReviewRounds` 下次挂号能看见。重试走 `cards/<卡>-<purpose>-2`（审阅走 `…-review-N+1`）。首轮成功路径仍无后缀，存量命名不变。
2. 同一失败点 best-effort 停掉那个 task，并强制收回它的 managed 工作树。不删分支。补偿失败不替换落账原错。
3. 不写 `EvDispatched`，不写 `card_tasks`。镜像、WorkBranch、当前 attempt 闸都当这次没派成。裁决轮次 `CountRounds` 不因此增加。

## 方案

原则：分支是协调者可能还想看的现场（用户选 B，守 B77），挡路用**改名**解决，不用删分支。未挂账的 running task 必须停，否则执行器白跑、磁盘白占。B233.6 的「失败不当成功」不动：没有 `EvDispatched`、没有挂账。

**耗费轮次（挂号）**

Transport 已经返回 task id，且本次没有成功提交快照+挂账事务（落账错误或写闸关闭），就记一笔结构化的「该卡 × 该 purpose 已耗费一轮」。这笔事实：

- 在回滚事务**之外**另写，失败不得被那次回滚清掉
- `PurposeRounds(card, purpose)` / `ReviewRounds` **必须是加法**：`count(TasksOf 中该 purpose) + count(该卡该 purpose 的耗费记录)`。ViaTemplate 挂号只问这两个函数，禁止另读一份计数。禁止 `max(挂账, 耗费)`，禁止成功挂账后删改或忽略耗费，禁止「有挂账就只数挂账」。1 次耗费 + 1 次成功挂账 ⇒ 计数 2 ⇒ 第三次分支 `-3`
- 不是 `EvDispatched`，不是 `card_tasks` 行，不进入 WorkBranch，不让 B349 身份闸把它当成当前派发
- 只增不减；不计入 `CountRounds`（那是裁决封顶）
- 无论随后 Stop / Reclaim 成不成功，都先记（否则补偿失败时重试仍撞首轮名）
- 耗费写入自己失败：只进日志，**不**替换落账/写闸原错，补偿钩子仍要调。此窗口与崩溃窗口同类，本卡不保证「重试必改名」，但不得因此少停 task
- Transport 自己失败：不记。那次要么没建出 task（Prepare 在 CreateTask 前失败），要么 B39 已在执行机上补偿

落点（表、列、函数名）归 contract。人读审计走现网派发失败出口（节点 `haltForHuman` / CLI 返回落账原错）。耗费是 PurposeRounds 可读的**非叫醒**事实：禁止新造事件类型，也禁止写成 `EvNeedsHuman` / `EvDispatched` / `EvTaskMirrored` / 任何使 `cardWaitEventActionable` 或 `automationWakeEvent` 为真的既有类型。卡侧未知类型今日默认不 Encode，禁令仍成立——真正会叫醒 follow 的是复用 `EvNeedsHuman`。

**补偿（停 task + 收树）**

同一失败点，经注入钩子 best-effort：对 Transport 返回的 task id 先 `Stop`，再 `Reclaim(force=true)`。Stop 按现状留树，所以必须再 reclaim；force 是因为未挂账的工作没有卡身份，脏树也收。不删分支。不改 Stop / Reclaim 的既有语义（不把「删分支」塞进 reclaim）。

钩子与 Transport 同形：ledgerstep 不做网络，CLI 与 agentd 各自接到与这次 Transport 相同的目标机客户端。生产两处装配必须注入；测试允许 spy。钩子为 nil 时仍记耗费轮次、打日志、不 panic。

补偿失败（网络、脏树之外的 reclaim 错）只进日志，带 task id。返回值永远是落账/写闸原错，不把补偿错或耗费写入错顶上去，也不因此重派第二个 task。

Stop 成功或 409（已终态）之后**必须**再打一次 `Reclaim(force=true)`——Reclaim 硬要求终态，只在 Stop 2xx 时才收树会在并发终态窗口留下 B233.4 留存的 managed 树。Stop / Reclaim 404 视为无对象可收（软成功）。`target==""` 与这次 Transport 走同一套本机客户端解析，不得把空 target 当成「不用补偿」。

**重试**

下次 ViaTemplate 看见 `PurposeRounds>=1`（或审阅 `ReviewRounds>=1`），按现网规则取 `-2` / `review-N+1`。残留的首轮分支还在目标机上也不挡。新工作树 checkout 的是新名字。

### 弃选

- **A 删未动尖端的新建分支、复用首轮名**：与 B77 reclaim「不删分支」和用户选 B 相反。执行器若已提交，B39 那把尺也会留下分支，重试仍撞名。否决。
- **C Transport 前写 pending**：覆盖崩溃窗口，但是新事实、新恢复路径。用户未选。否决（本期）。
- **按「未挂账」全机扫描 Stop**：裸 `handoff dispatch` 本来就没挂账，会误杀。否决。
- **把孤儿写成 `EvDispatched` 或 `card_tasks`**：B233.6 刚禁止的假成功；镜像与身份闸会把已 Stop 的 task 当成当前派发。否决。
- **只改名不停 task**：执行器继续跑，卡上看不见。与卡标题「自动回收」相反。否决。
- **扩 `mirrorSkip` / 改 `WaitDeliveryPolicy` 假集合**：本卡不新造事件，这两处无增量。
- **让 agentd Dispatch 在分支已存在时自动改名**：会改所有派发（含非卡），且撞名发生在 Prepare，CreateTask 尚未发生——不是本卡这条缝。否决。

## 用户故事

1. 作为协调者，模板派发 Transport 已成功、本地挂账失败：命令仍报落账原错；那个远端 task 被 Stop，managed 树被强制收回；卡上没有派发成功快照、没有挂账。再派同一 purpose，新分支是 `cards/<卡>-<purpose>-2`，不再撞 `already exists`。这次成功之后再派，第三次是 `-3`，不回头撞 `-2`。
2. 作为 `card dispatch --step`，写闸在 Transport 之后关闭：同样记耗费轮次、同样补偿；节点失败仍走现网 haltForHuman；再派审阅则 `review-N` 跳过已耗费的那一号。
3. 作为本机空 target 派发，同一条缝同样成立（不是「只有 `--target` 远端」才收）。

## 契约语义与接缝

- **跨子系统规则**：卡模板派发「Transport 已受理、账本未挂账」时，账本负责耗费轮次（挂号权威），执行面负责停 task 与收树（既有 Stop / Reclaim），编排只在 ViaTemplate 这一处把两件事串起来。ledgerstep 不 import client / agentd。
- **流向**：task id 只从这次 Transport 返回值进入补偿钩子，不从账本反查「未挂账 task」（全机扫描已否决）。
- **允许的契约增量**：Dispatcher 增加与 Transport 同档的补偿钩子（语义：target + task id → Stop；成功或 409 后再 force reclaim）。`PurposeRounds` / `ReviewRounds` 语义扩大为挂账行计数与耗费计数的**和**（不是 max、不是替代）。不新增 HTTP 路径、不新增事件类型、不把耗费写成可动作既有类型、不改 Stop/Reclaim 的请求/响应形状、不删分支。
- **冻结物**：B233.6 落账事务回滚仍成立；B39 `executorStarted` 守卫仍成立；B77 reclaim 不删分支仍成立；B349 身份闸仍只认 `EvDispatched`。B233.6 plan §6.2 项 1「远端孤儿回收标真机」由本卡接手为机内可测行为；跨机真机仍等收尾统一闸。
- **依赖方向**：编排 →（注入）传输；编排 → 账本。禁止账本去调 Stop。

## 实现决定

- 补偿收口在 `ViaTemplate` 的落账失败 / 写闸关闭出口，不在 Transport 内部、不在 B39 defer。落地时改掉 `dispatch.go` 仍写着的「远端 task 的回收属于真机项」注释。
- 用户可见：挂账失败后同 purpose 再派，分支名带 `-2`（或审阅号 +1）；无新 flag、无新命令。失败文案仍是落账/写闸原错。
- Stop / Reclaim 文案与退出码维持现状；补偿是派发失败路径上的副作用，不单独打一条「回收成功」给 wait。

## 测试决定（接缝清单）

1. **`Dispatcher.ViaTemplate` × 注入的补偿钩子**（`internal/ledgerstep/dispatch.go#Dispatcher.ViaTemplate`）：Transport 返回 task id 之后，落账失败或写闸关闭 → 钩子被调用恰好一次，参数为这次的 target 与 task id；无 `EvDispatched`、无 `TasksOf` 行；返回值 `errors.Is` 落账/写闸原错。Transport 失败 → 钩子 0 次、耗费轮次不变。钩子返回错误 → 仍记耗费轮次，返回值仍是落账原错。耗费写入失败 → 钩子仍调用一次，返回值仍是落账/写闸原错。禁止只测内部 helper 不穿过 ViaTemplate。
2. **`Store.PurposeRounds` / `ReviewRounds` × `ViaTemplate` 挂号**（`internal/ledger/events.go#Store.PurposeRounds`、`internal/ledgerstep/dispatch.go`）：一次耗费之后，同 purpose 第二次 Transport 收到的 `Branch` 为 `cards/<卡>-<purpose>-2`；审阅为 `…-review-(n+1)`。**加法正例**：1 次耗费 + 1 次成功挂账之后 `PurposeRounds==2`（审阅同理），第三次 Transport 的 `Branch` 为 `…-3` / `…-review-3`。成功挂账的首轮仍无后缀（回归 `TestViaTemplateSecondRoundGetsNumberedBranch`）。`CountRounds` 不因耗费增加。WorkBranch 在只有耗费、没有成功快照时仍是 not found。
3. **生产装配 × 钩子非空**（`cmd/card_dispatch.go` 裸模板 Dispatcher；`internal/agentd/cardstep.go#startCardStep`）：两处生产装配注入的补偿必须非 nil。CLI `--step` 不在此列（它不装配 Dispatcher）。钩子的生产实现穿过真实 `Client.Stop` / `Client.Reclaim`（可用 fake HTTP）：Stop 成功或 409 之后必有一次 `Reclaim(force=true)`；404 软成功、不顶替落账错；`target==""` 打到与 Transport 相同的本机客户端。不得只 spy ViaTemplate 侧的函数指针。

禁止只测「计数 +1」的纯函数、不穿过 ViaTemplate 挂号。

## Out of Scope

- **本期不做、后续要做**：崩溃窗口（Transport 成功之后、耗费轮次落盘之前进程死去——重试仍可能撞首轮名）；耗费写入失败后重试仍可能撞首轮名（仍必须 Stop）；补偿网络失败后仍在跑的孤儿（人 `stop` / `reclaim`）；B233.8 迁包；跨机真机（仍等全部 B233 收尾卡之后统一闸）。
- **永不做（本卡）**：删任务分支；按未挂账全机扫描；Transport 前 pending；新 wait 命令；新 HTTP 路径；新事件类型；把耗费写成 `EvNeedsHuman` 或其它可动作既有类型；改 `WaitDeliveryPolicy` 假集合；扩 `mirrorSkip`；把孤儿写成 `EvDispatched` / `card_tasks`；`PurposeRounds = max` 或成功后作废耗费；改 B39 `executorStarted` 守卫去删已接管的树；改 Stop 为自动删树。
