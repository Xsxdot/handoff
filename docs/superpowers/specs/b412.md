# B412 看板合并视图按工作流配置归列

**级别 L2**（单子系统：web 工作项页 cards 模块；不动契约、不发新 wire 字段）｜**状态：已批准**（用户 2026-09-27 对话批准；D1/D2 为用户当场裁决）｜2026-09-27

## 问题陈述

工作项页（`/cards`）看板在「全部工作流」视图（默认视图）下不读工作流配置的看板列映射，全部卡按默认老映射归列：

- `web/src/app/cards/CardsPage.tsx:153-157`：layout 只在顶部「工作流」筛选器选中单条流时采用它的 `def.board`（三元 `workflow ? selectedWorkflow?.def.board : undefined`）；「全部工作流」传 `undefined`。
- `web/src/app/cards/columns.ts:14-22`：落 `undefined` 后回退 `defaultBoardLayout`，其状态映射只认 7 个中文老状态（待办/已出spec/已出 spec/进行中/待审阅/待合并/已完成/终止），未知状态一律落 fallback「进行中」。

可见后果：charter 当前版本（v12）配置里 spec→沟通中、review/acceptance/integrate/图对账→审核中、finish→结束、待办→代办；而看板把 spec/contract/breakdown/plan/implement/review/acceptance/integrate/图对账/finish 全部堆进「进行中」，「沟通中」「审核中」恒空。配置页逐项配好的映射在看板上不生效（用户 2026-09-27 报告的原始现象）。

已排除项（2026-09-27 排查）：配置持久化正常（PG 账本 charter v12 的 `definition.board` 与配置页逐项一致）；卡钉在 v12；「结束」列为空是终态卡默认不拉取（`IncludeTerminal` 仅 `all=1`），与映射无关。

## 方案（含弃选与理由）

- **D1 落列版本 = 流的当前版本**（用户 2026-09-27 裁决）：卡的列归属用其工作流**当前版本**的 board 映射；卡钉住的版本继续只用于**动作面**（抽屉里可派发的节点集、门），不用于列归属。
  - 弃选「按卡钉版本落列」：账本现有 4 张卡钉 v7/v9（charter v9 及更早的定义没有 board），按钉版本会把它们堆回默认映射——那张 v9 的 spec 卡仍停在「进行中」，与单流视图（一直用当前版本）打架。
  - 推论（本 spec 定）：呈现面与动作面分版本——呈现（看板列归属、节点标签显形、抽屉列胶囊）随流当前版本；动作（可派发节点）随卡钉版本。这消除「同一张卡在看板与抽屉列不一致」。
- **D2 合并视图列集合 = 固定默认五列**（用户 2026-09-27 裁决）：代办/沟通中/进行中/审核中/结束，不随各流列名合并或漂移。
  - 弃选「各流列名并集」：用户否决——看板列骨架应稳定，列数不因配置变动。
- **D3 列名越界兜底**（据现状定）：某流 board 的映射目标不在默认五列时，该状态落 fallback「进行中」。配置页「节点编排」表只提供「节点→看板列」下拉、没有列名输入（`web/src/app/flows/FlowsPage.tsx` 节选），列名正常不可改；此条只在直连 API 传自定义列名时可达，是防御性兜底。

3. 作为协调者，我在顶部选中某一条流时，看到的仍是该流自己的列与映射（现状行为不变）。
4. 作为协调者，我点开一张卡，抽屉里高亮的列胶囊与它在看板上的列一致。
5. 作为协调者，我在「全部工作流」视图看到的列恒为代办/沟通中/进行中/审核中/结束五列，不随工作流配置增减列。
6. 作为协调者，我看板上的卡数量不因本次改动丢失：任何卡都落在某一列（找不到映射的落「进行中」）。

## 实现决定

- 改动收口在前端工作项页 cards 模块的纯逻辑层与页面组合层；**不动后端**（五列校验、flows/flow 接口的补默认布局行为均保持）。
- 列归属解析按卡逐张进行：每张卡用其 `workflow` 的当前版本 board 解析归属列；解析不到（流已删/改名，或 flows 未加载完成）落默认映射——与现状同形的诚实兜底，不新增请求（flows 列表已带 `def.board`）。
- 合并视图列集合恒为默认五列；单流视图沿用该流当前版本的列（含自定义列名），现状不变。
- 呈现面（看板列归属、卡上节点标签显形、抽屉列胶囊）随流当前版本；动作面（抽屉可派发节点集）保持卡钉版本——B392 已定纪律不破。
- 节点标签的显形判定（多对一列才显示节点名）随新的列归属自动变化，不写死列名（沿用现有派生方式）。

## Out of Scope

- **永不做**：合并视图列集合随各流列名并集/漂移（用户 2026-09-27 否决）；为列归属引入后端字段或新接口。
- **本期不做**：配置页新增列名/列序编辑入口（现状 UI 无此能力，维持）；改后端 `validateBoardLayout` 的五列约束；列表视图的列呈现（按状态显示，不涉列）；钉旧版本卡的迁移提示（用户已定「落列随当前版本」，无需提示）。
- 以上无「后续要做」项，无需落 roadmap。
