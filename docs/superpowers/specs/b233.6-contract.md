## 2. 接缝类型与事件 envelope

### 2.1 尝试身份

`attempt` 是一个节点派发返回的执行任务身份，定义为该次 `Transport` 返回的 `taskID`。同一工作流节点重新派发必得新的 task ID，因而得到新的 attempt；不另造自增回合号、不用卡列状态推导 attempt。

这使迟到事件的匹配条件成为 `(card_id, node, attempt, source_target, source_task, source_seq)`：旧 attempt 的 task/source identity 不得推进新 attempt。普通不带工作流节点的直派 `node` 为空；其 `attempt` 仍可记录为 task ID，但不得触发工作流路由。

### 2.2 派发快照与挂账投影

Ticket 0 已在以下既有类型落形状：

```go
// internal/ledger/tasks.go
type TaskLink struct {
    CardID    string    `json:"card_id"`
    Node      string    `json:"node,omitempty"`
    Attempt   string    `json:"attempt,omitempty"`
    Target    string    `json:"target"`
    TaskID    string    `json:"task_id"`
    Purpose   string    `json:"purpose"`
    CreatedAt time.Time `json:"created_at"`
}

// internal/ledger/events.go
type DispatchSnapshot struct {
    // 现有字段保持不变……
    Node    string `json:"node,omitempty"`
    Attempt string `json:"attempt,omitempty"`
}

// internal/ledger/mirror.go
type MirroredEvent struct {
    Target, Task string
    Node, Attempt string
    SourceSeq int64
    Type string
    Payload []byte
    CreatedAt time.Time
}
```

`DispatchSnapshot.Node` 来自 `TemplateDispatch.Node`，`DispatchSnapshot.Attempt` 来自同一调用的 `taskID`。`TaskLink` 是查询投影：新实现必须能把该节点/尝试关联给镜像；存量裸挂账允许两个投影字段为空。`LinkTask` 的旧签名保留，避免非工作流 card dispatch、历史测试和存量数据被强制迁移。

### 2.3 账本镜像 payload

新写入的 `card_events.payload` 固定为以下紧凑 JSON 形状，键顺序按现有结构化拼装冻结：

```json
{"node":"review","attempt":"task-attempt-1","task_type":"question","payload":{"ticket_id":"task-attempt-1:q1"}}
```

原始卡号不复制进 envelope：卡号来自 `card_events.card_id`；源事件身份来自 `source_target`、`source_task`、`source_seq` 三列；`task_type` 是原 task 事件的 `proto.EventType` 字面值；`payload` 是原事件 payload，空 payload 写 `null`。旧镜像事件没有 `node`/`attempt` 键，消费者须按缺省空值读取。

本轮金样本测试：`internal/ledger/taskstate_test.go#TestAppendMirroredEventWorkflowEnvelopeGolden`，锁定上述字节结果。

### 2.4 事件所有权

- 执行域拥有 `proto.Task`、`proto.Ticket`、原始 task 事件、Ask 答案投递状态与审批事实。
- 账本只拥有卡、工作流业务事件、弱挂账与镜像 envelope；`EvTaskMirrored` 不更新任务状态、不创建第二张 ticket 表、不伪造 `EvReviewVerdict` 或 `EvAcceptanceRecorded`。
- 工作流消费镜像事件时必须同时检查 `node`、`attempt` 与 source identity；不能只按 card 或 task type 推进。
- `completed` / `turn_failed` 只说明执行回合事件，不能直接转成节点业务 pass；节点 pass 仍来自 `NodeStep` 的裁决路径，卡验收仍由 `RecordAcceptance` 所属业务流程形成。

## 4. 共享派发接线与退役边界

### 4.1 允许的调用链

```text
card dispatch --step / Server.startCardStep
  → ledgerstep.StepRunner.Run
  → StepRunner.dispatchNodeWithGate
  → ledgerstep.Dispatcher.ViaTemplate
  → ledgerstep.Transport
  → client.Client.Dispatch
  → agentd.Manager.Dispatch
  → proto.Task + task event stream
```

事件回流：

```text
proto task events
  → ledgermirror.DefaultSource / NewLocalSource
  → Mirror.subscribe
  → Store.AppendMirroredEvent
  → card_events(task_mirrored)
  → workflow/card event consumer
```

回复链：

```text
card event consumer
  → client.Client.Reply(taskID, ticketID, answer)
  → agentd reply endpoint
  → Manager.RelayAnswer（无等待者时）
  → AskResponder.RespondAsk 或审批 client / RespondPermission
```

禁止新增 `WorkflowSendAnswer`、独立 InteractionService、第二条 task event bus、工作流自己的 ticket/approval 表。`Send` 仍可作为执行域非 OpenCode 适配器的既有内部兼容路径，但工作流契约不以它回答 Ask。

### 4.2 旧路径退役

节点 runner 不得：

- 从工作流节点自行拼 `HOME=<...> <executor>`、harness argv 或执行器默认参数；
- 从节点侧解析默认载体、选择机器、创建审批请求或生成纪律正文；
- 用执行完成事件直接写 `EvReviewVerdict`、业务 pass 或卡验收；
- 通过 `WaitEvent` 的协调者本地 cursor 代替 Mirror watermark；
- 按 card_id 或节点名单独消费事件而忽略 attempt/source identity。

`HomeDir`、`DisciplineText`、`DisciplineVersion` 等现有输入继续由组装点准备后透传；本卡只要求节点复用该输入，不扩展它的来源或语义。

## 5. 冻结清单

每条均为可独立判定的原子断言。

1. `TemplateDispatch.Receiver` 为空时必须保留 B233.5 的默认载体语义。
2. 非空 `TemplateDispatch.Receiver` 必须原样进入 `ledgerstep.DispatchOpts.Receiver`。
3. `ledgerstep.DispatchOpts.Receiver` 必须原样进入 `client.DispatchOpts.Receiver`。
4. `client.DispatchOpts.Receiver` 非空时必须沿既有 POST `/api/tasks` wire 发送 `receiver`。
5. `TemplateDispatch.Node` 必须是工作流节点名，普通直派必须为空。
6. `Dispatcher.ViaTemplate` 必须只调用一次已注入的 `Transport`。
7. `Transport` 返回的 `taskID` 必须成为本次 attempt 身份。
8. 同一次派发的 `DispatchResult.Task` 必须等于 `DispatchResult.Attempt`。
9. `DispatchSnapshot.Node` 必须等于本次 `TemplateDispatch.Node`。
10. 新 `DispatchSnapshot.Attempt` 必须等于本次 `Transport` 返回的 task ID。
11. 存量 `dispatched` payload 缺少 `node` 时不得回填猜测值。
12. 存量 `dispatched` payload 缺少 `attempt` 时不得回填猜测值。
13. `TaskLink.Node` 只能来自对应派发快照投影，不能从 task 事件正文猜测。
14. `TaskLink.Attempt` 只能来自对应派发快照投影，不能按卡当前状态猜测。
15. 存量裸挂账的空 `Node` 不得进入工作流节点路由。
16. 存量裸挂账的空 `Attempt` 不得匹配新节点尝试。
17. 新镜像 envelope 必须含 `node` 键。
18. 新镜像 envelope 必须含 `attempt` 键。
19. 新镜像 envelope 的 `task_type` 必须等于源 `proto.Event.Type` 的字面值。
