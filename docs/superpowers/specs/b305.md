## 问题陈述

谁：把任务派给 `--executor agy` 的协调者。

通道：handoff 用 `agy --input-format stream-json --output-format stream-json`（print/headless）。B304 把 `handoff-safety-gate` 写进 `workdir/.agents/hooks.json`，假定 agy 会读它。

今天发生的事（B304 真机，linux-01，agy **1.1.24**，隔离 agentd `127.0.0.1:17777`，未碰生产 `:7777`）：

1. **发现路径错了。** strace：print/stream-json 只 open `$HOME/.gemini/config/hooks.json`（以及 ENOENT 的 `antigravity-cli/hooks.json`、`$HOME/.gemini/hooks.json`），**从不** open `workdir/.agents/hooks.json`。`trustedWorkspaces` 写成精确路径也不读。`hooks_manager` 默认 `loaded 0 named hooks from 0 hooks.json file(s)`。adapter 写的 workspace 文件对 headless 是死门。
2. **`$HOME` 可隔离。** `HOME=/tmp/fake` 且 `$HOME/.gemini/config/hooks.json` 存在时：`appDataDir` 跟新 HOME，`loaded 1 named hooks from 1 hooks.json file(s)`，用户真正的 `~/.gemini/config/hooks.json` 不被创建。
3. **hook allow 挡不住原生 print-mode 确认。** `tool_confirmation_manager.go:188` soft-deny；`permissionOverrides` 无效。未进 `settings.permissions.allow` 的命令（如复合 `echo && git`）在 hook 已 allow 之后仍 `user denied permission`。
4. **`--dangerously-skip-permissions` / `toolPermission: always-proceed` / `command(*)` 会让 hook deny 失效。** deny hook 仍开火，命令照跑（`uname -s` → `Linux`）。不能当门。
5. **能同时「任意前缀放行」和「hook deny 生效」的组合：** `toolPermission=request-review`（缺省）+ `permissions.allow: ["command(go)"]`（以及 `command(echo)` / `command(git status)`）。deny → `tool call denied by pre-tool hook`；allow → `go env GOVERSION` 真跑出 `go1.26.1`。`command(uname)` 前缀对 deny 不老实（仍跑），禁止列入 allow。

B304 spec 的「agy 只能读工作区 `.agents/hooks.json`」和「永不做：把 agy hooks 写进用户全局 settings」是当时的错误前提。本卡用**任务级 HOME** 满足「不污染用户全局」，不写 `~/.gemini/config/hooks.json`。

## 定级理由

只改 agy adapter 的进程环境与任务目录物料。不新增 HTTP，不改 Adapter/Reaper 签名。计划写出来不会只复述本页（agyhome 布局、oauth 拷贝、allow 前缀清单、禁 `command(*)`），所以不是 L1。对面仍是外部 CLI，不值得 L3 冻结。

## 方案

推荐：**任务级 HOME + 原生前缀 allow + 继续写 workspace hooks（B304 生命周期不动）。**

1. 每个 agy 任务在 `taskDir/agyhome` 建私有 HOME。`Start` / 冷 `Resume` 给 agy 进程注入 `HOME=<taskDir>/agyhome`（只加在 executor 的 env，不改 agentd 自己的 HOME）。
2. 把用户 `$HOME/.gemini/antigravity-cli/antigravity-oauth-token`（及若存在的 `.orig-google-oauth`）**拷贝**进任务 HOME 对应路径。禁止 symlink 整份 `antigravity-cli`（会把用户的 `settings.json`、可能存在的 `command(*)` 带进来，踩第 4 条）。拷贝失败 → Start/冷恢复失败，带路径。
3. 写 `$HOME/.gemini/config/hooks.json`，内容与 B304 的 workspace `handoff-safety-gate` 相同（同一 `permission-hook --sock`）。`WriteTaskEnv` 在 startProc 之前写完（顺序已是 Listen → WriteTaskEnv → startProc）。
4. 写 `$HOME/.gemini/antigravity-cli/settings.json`：`permissions.allow` 为**显式命令前缀清单**（见实现决定），**禁止** `command(*)`、禁止 `toolPermission: always-proceed`、禁止 argv `--dangerously-skip-permissions`。缺省即 `request-review`。
5. 继续按 B304 写/Restore `workdir/.agents/hooks.json`（已跟踪 skip-worktree、未跟踪 exclude、sidecar）。headless 不读它；TUI/未来版本可能读；测试夹具仍锁这条缝。
6. `RestoreTaskEnv` **不**写用户真正的 `~/.gemini/`。任务级 `agyhome` 留在 0700 的 taskDir 里，随任务目录生命周期，不必单独卸全局钩。

弃选：

- 写用户 `~/.gemini/config/hooks.json`：污染交互式 agy；并发任务抢同一 named hook；B304 已否决「全局 settings」。HOME 隔离给出同一发现路径且不污染。
- `--dangerously-skip-permissions` 或 `always-proceed`：uname 在 deny hook 之后仍执行。门开了等于没门。
- `command(*)`：agy 把它当「静默放行一切」；deny / exit 1 / 空 stdout 都拦不住。二进制里也有「matching every command and silently auto-approving…」的修复说明。
- 不再写 workspace `.agents/hooks.json`：打断 B304 已合入的 Restore/skip-worktree 测试与文档。双写便宜。
- 改 Adapter 签名 / 改 permgate：本卡只动 agy 物料与 argv/env。

## 用户故事

1. 干净仓库、agy 1.1.24 headless。派 `--executor agy` 后，不在用户 `~/.gemini/config/` 留下 `hooks.json`。任务 `agyhome` 里能看到 `handoff-safety-gate`，进程 env 含 `HOME=…/agyhome`。
2. 模型要跑 `go env GOVERSION`（或任何 `command(go)` 前缀）。协调者收到 `permission_request`；`--approve` 后命令真执行，回合有非空产出。
3. 同一前缀下协调者 `--deny --reason …`：agy 侧是 `tool call denied by pre-tool hook`，命令不执行。
4. argv **没有** `--dangerously-skip-permissions`；任务 `settings.json` **没有** `command(*)`、没有 `always-proceed`。
5. Stop/Reap 之后：B304 的 workspace hooks 还原照旧；用户全局 hooks 文件仍然不存在（我们没写过）。

|---|---|---|
| A | `agy.WriteTaskEnv` | `Adapter.Start`、冷 `Resume`。本卡扩展：在 `taskDir/agyhome` 落下 hooks + settings + oauth 拷贝。测试直调。 |

假缝禁令：不要为拷贝 oauth 抽纯函数占缝。oauth 存在性从缝 A 的夹具断言。

边界型：agy 1.1.24 对 `$HOME/.gemini/config/hooks.json`、`command(go)` 与 `command(*)` 的行为以 linux-01 真机为准（台账）。机内测试锁的是我们写出的文件/argv/env 形状，不假装能在无 agy 的机子上跑 CLI。

## 实现决定

- 任务 HOME 目录名 `agyhome`（taskDir 下，用户不可见）。
- 任务 `settings.json` 的 allow 前缀（精确字符串，禁止再加 `*` 通配）：
  `command(go)` `command(git)` `command(echo)` `command(make)` `command(npm)` `command(npx)` `command(pnpm)` `command(yarn)` `command(node)` `command(python)` `command(python3)` `command(pip)` `command(pip3)` `command(cargo)` `command(bash)` `command(sh)` `command(ls)` `command(cat)` `command(grep)` `command(sed)` `command(find)` `command(mkdir)` `command(chmod)` `command(head)` `command(tail)` `command(rg)` `command(gofmt)` `command(handoff)`
- **禁止**列入：`command(*)`、`command(uname)`（1.1.24 上 deny 不生效）。
- 不改 `WriteTaskEnv` 签名。
- 不传 `--sandbox`、不传 `--dangerously-skip-permissions`、不传 `--mode accept-edits`（文件写若真机 soft-deny，本卡真机清单里记一笔，不在未验时加会破坏 deny 的旗）。

## 验收判据（整张卡）

1. `go test ./internal/executor/agy -count=1` 绿，且新断言有牙：WriteTaskEnv 后 `taskDir/agyhome/.gemini/config/hooks.json` 含 `handoff-safety-gate` 与当前 `perm.sock`；`settings.json` 含 `command(go)`、不含 `command(*)`、不含 `always-proceed`；`managedTaskTmpEnv` 的 env 含 `HOME=<taskDir>/agyhome`；`agyArgv` 不含 `--dangerously-skip-permissions`。
2. `go build ./...` 绿。
3. 真机（隔离实例，不碰生产 `:7777`）：dispatch agy → 工单 `run_command: go env GOVERSION`（或等价 `go` 前缀）→ approve → 产出含 `go` 版本串；另一次 deny → 命令未执行。用户 `~/.gemini/config/hooks.json` 全程不存在。
4. 本节点该干什么一律以注入的纪律块为准。

## Out of Scope

- 永不做：写用户全局 `~/.gemini/config/hooks.json`；argv 加 `--dangerously-skip-permissions`；`command(*)`；`always-proceed`。
- 本期不做：matcher 扩到 `call_mcp_tool` / `browser_*`（B304 OOS）；Windows PreToolUse 真机；`command(uname)` 的原生 deny 漏洞（agy 自己的例外，记 roadmap）；并发两个 agy 任务抢同一 workdir（B304 OOS）；把用户 `settings.json` 整份搬进任务 HOME。
- 不重开 B304 的 sidecar/skip-worktree/exclude 行为。
