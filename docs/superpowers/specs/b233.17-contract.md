## 2. 契约语义：编译期封界（缝 2）

**允许的方向**（架构法：接口归使用方、类型跨缝走词表包、行为经具名能力/接口）：

- 公开包保留：构造（`NewManager` / `New` / `NewCapability` / `NewClient`）、DTO、错误哨兵、包内公开契约类型（`workspace.Capability`、`scheduling.Carrier`/`Squad`/`Binding`/`IgnitionRequest`、`orchestration.ApproverDecision`、`approval.Hooks`/`ConsultDecision`）。
- 实现细节（Manager 内部方法、git 原语、scheduling 内部读模型、approval 请求裁决实现）进 `internal/<包>/internal/`。
- `cmd` 只 import 公开包；gateway 生产不 import 嵌套路径，也不 import 具体 `*Manager`/`*scheduling.Service` 绕过接口（已有接口字段承接）。
- **禁止**：新开顶层域、新开跨机协议、借封界改错误哨兵/文案/超时/HTTP 路径/事件类型。

**编译期锁的处置（落 implement，本节点冻语义）**：`orchestration` 与 `approval` 的「实现满足使用方接口」断言目前在实现包内。实现搬进 `internal/<包>/internal/` 后：

- `orchestration`：断言 `var _ agentd.OrchestrationClient = (*Manager)(nil)` 会因 import 嵌套而落在嵌套包——保留在嵌套包合法（它 import 公开 gateway），**但** `cmd` 构造具体 `*Manager` 时类型不再公开。故实现节点必须让公开包重新导出实现别名或构造器（如 `orchestration.NewManager` 返回满足 `OrchestrationClient` 的具体类型），**这是实现期接线，本节点只冻结「gateway 生产不得 import 嵌套路径」这条缝**。
- `workspace`：`Capability` 是公开包的接口，`gitCapability` 是实现；断言 `var _ Capability = gitCapability{}` 若随实现进嵌套包，则嵌套包 import 公开 `workspace`，断言合法。`NewCapability` 留公开包。
- `scheduling`：`*Service` 是否进嵌套由 plan 定；若进，`agentd.scheduling_client.go` 的断言 `var _ SchedulingClient = (*scheduling.Service)(nil)` 需改为对公开构造返回值的断言。
- `approval`：`*Client` 断言同 workspace 处置。

**本节点不实现上述迁移**；§7 冻结清单标「实现期判据」的条目不得被本节点宣称已过。
