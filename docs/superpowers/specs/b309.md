## 问题陈述

谁：把任务派给 `--executor agy` 跑分的协调者。

B308 部署后登录与复合 `pwd && git status` 已过原生门。sq-bug-001 任务 `5530b65b-2096-432e-b091-ca0533151746`：命令放行，stdout 却是

`/root/.handoff/tasks/5530b65b-…/agyhome/.gemini/antigravity-cli/scratch` + `fatal: not a git repository`。

随后在任务目录乱翻，`view_file` 读 `spec.json` 被原生 `read_file` soft-deny，回合空输出 `turn_failed`。bug/review/acc 同一形态。

现状读数（linux-01，agentd `c51b6313+dirty1`）：

- shim `dir=/root/.handoff/worktrees/5530b65b`（`StartProc` 已把 `Dir` 设成 worktree）
- stream-json `init.cwd` 也是该 worktree
- 工具 `run_command` **没有** `Cwd` 参数，实际执行目录是任务 HOME 下 `antigravity-cli/scratch`
- `agyArgv` 不传 `--add-dir`（agy 1.1.24：`Add a directory to the workspace (repeatable)`）

隔离 HOME 之后，headless agy 的工具工作区跟 OS cwd 不是一回事；不登记 workspace 就落到 scratch。B308 正则实验：`--add-dir` 后日志 `workspaceDirs=[ws]`。

## 方案

推荐：**`agyArgv` 在 `RepoPath` 非空时追加 `--add-dir <RepoPath>`。** Start 与冷 Resume 共用。不改 HOME 隔离、不加 skip-permissions、不靠模型自己填 `Cwd`。

弃选：只设进程 `Dir`（5530b65b 已经设了，不够）；`trustedWorkspaces`（B305：不影响 hooks 发现路径，也不替代 workspace 登记）；prompt 里写「请 cd 到 worktree」（模型不保证）。

## 用户故事

1. `pwd && git status` 的 stdout 以派发 worktree 为 cwd，且能看见 `.git`。
2. argv 仍无 `--dangerously-skip-permissions`；allow 仍是 `command(*)`。

## 测试决定

缝：`agy.agyArgv`（`StartProc` / 冷 Resume 组 argv）。`RepoPath` 非空时 argv 含 `--add-dir` 与该路径；空则不含。已有「禁止 skip-permissions」断言保留。

## 实现决定（即 plan）

1. `agyArgv`：`RepoPath != ""` 则 `--add-dir` + `RepoPath`。
2. `TestAgyArgv` 锁这一条；注释写清 scratch 与 OS cwd 不是同一扇门。
3. 不部署生产，除非另说。

## Out of Scope

- 永不做：为看见 worktree 而取消任务 HOME；argv skip-permissions。
- 本期不做：给 `read_file(taskDir)` 开原生 allow（读 `spec.json` 被拒是 cwd 错了之后的次生）；matcher 扩 MCP/browser；B306 token 写回。
