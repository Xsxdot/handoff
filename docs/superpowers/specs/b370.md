# B370 镜像身份闸降级判定：能判定才拦

状态：**已批准**（2026-09-14，用户原话「批准，进 contract」）  
定级：**L3**　档位：**轻档**　路由：contract → breakdown →（单轮）implement → review → acceptance → finish  
卡：B370　日期：2026-09-14  
台账：`docs/superpowers/ledgers/2026-09-14-b370-spec-ledger.md`  
来源：2026-09-14 真机「卡流全静默」排查（debug 节点）；同日 mac-02 换版止血已完成

## 定级理由

改动跨两个领域：`d_cli`（`cmd/card_wait.go` 的卡流消费）与 `d_gateway`（`internal/agentd/wakeconsumer.go` 的自动化消费），且修订的是 B349 冻结的跨子系统消费规则正文，并要落一处共享实现（依赖边归 contract 声明）。选轻档：两处消费点承载同一条规则，拆并行子卡会把规则拆散——同 B353 的选档理由。

## 问题陈述

谁：协调者主会话（`handoff card wait --follow <卡>`）与小队自动化（agentd 事件消费循环）。

条件：B349 冻结「缺 node/attempt、或没有当前派发快照的 `task_mirrored` 不得叫醒」（`docs/superpowers/specs/b349.md:79`）。

要变的事实：现网全部镜像都落进这条闸的拒绝侧——全库 4289 条 `task_mirrored` 中带 `node` 键的为 0（台账 §1）。于是两条消费链 100% 静默：卡流不吐行、自动化不唤醒；且丢弃只落 Info/Debug 日志。2026-09-14 实测：卡 B369 上三条 `permission_request`（16:13 / 16:16 / 16:20）没有任何人被叫醒。

诊断：闸把「**无从判定**是不是当前尝试」与「**确凿是**旧 attempt」按同一种结果处理（丢）。而前者在现网是常态——836 条挂账里只有 13 条能投影出身份（台账 §3）。防护对象的量级远小于被误伤的量级。

## 方案

原则不变：身份闸仍写在**消费点**，仍在账本之上，不扩 `mirrorSkip`、不下沉成账本派生查询。改的是**判定方向**：只在能证明迟到时才拦。

**身份缺失或为空**（缺 `node`/`attempt` 键，或键值对为空串）时的判定表：

1. 能定位该 task 的派发快照，且快照带工作流身份 → 与该节点最新合格快照比对：**相等 = 放行**；不等 = 丢（防迟到保留）。
2. 能定位快照，但快照无工作流身份（裸派发 / 旧派发 / 旧写入者）→ 无从判迟到 = **放行**。
3. 找不到该 task 的派发快照 → 无从判迟到 = **放行**（相对 B349 的 `!found` 反转）。

**身份非空**的路径按 B349 正文保留不变：envelope 的 node/attempt 均非空、attempt 等于当前 `snapshot.Attempt`、`source_task` 等于该 `Attempt`、`source_target` 与当前 `Target` 相等（两边都空算匹配），缺 `source_task` 仍闭集拒绝；`!found` 仍不叫醒。

### 弃选

- **一律放行（身份为空即按类型表交付，不查快照）**：旧 attempt 事件会重新叫醒，B349 要防的噪声回流；「能判定才拦」只多一次账本读，不省这笔钱。
- **保持 fail-closed，只把丢弃升级成显性告警**：解决「不知道它哑了」，不解决「它哑了」——卡流依旧不吐行。
- **把判定下沉成账本派生查询**：B349 P3 已否决（ledger 保持薄）；本卡维持。
- **往 envelope 加身份字段 / 让写入者自证版本**：B233.6 已冻「列是权威身份、不进 envelope JSON」，重复一份会漂；版本偏斜侦测落 roadmap，不在本卡。

## 用户故事

1. 作为主会话挂 `card wait --follow`：旧写入者写的、以及无工作流身份派发产生的镜像事件（提问、权限、`delivery_failed`、终态等）仍会一行一醒；只有**确凿的旧 attempt** 不叫醒。
2. 作为小队自动化：同上，且被拦下的确凿旧 attempt 仍记 `seen` 并推进游标，不打死消费循环。
3. 作为排查者：每次判定带 `reason`——「降级放行」与「按迟到拦截」都能在日志里看到是哪一条分支、依据哪个快照。

## 契约语义与接缝

- **跨子系统规则**：`task_mirrored` 是否叫醒 = B353 类型表 ∧ 身份闸；身份闸的判定正文（含降级三分支）由**一处共享实现**承载，`cmd/card_wait.go#runCardWait` 与 `internal/agentd/wakeconsumer.go#consumeAutomationEventsOnce` 调用同一实现，**禁止第二份拷贝**。
- **依赖方向**：共享实现必须位于两处消费点都能依赖、且不造成 agentd→cmd 反向依赖的位置；包名、符号名与签名归 contract。`internal/client` 当前不依赖 `internal/ledger`（台账 §4），若落点选它会新增该边，须在 target 图里显式声明。
- **判定可观测**：判定结果必须携带 `reason`（枚举），两个消费点按 reason 落日志；放行与拦截都留痕。
- **流向不变**：镜像按现 `mirrorSkip` 全量落账；`source_target`/`source_task`/`source_seq` 仍是列上权威身份；envelope 身份仍是投影。不新增事件类型、不加 wire 字段、不改 HTTP/前端契约。
- **ledger 仍不提供**「当前 attempt」派生查询（B349 P3 保留）。

## 实现决定

- 判定输入 = 事件 + **该事件所属卡**（`--subtree` 也用事件卡，B349 正文保留）+ 账本读口；输出 = 交付/不交付 + reason。
- 身份证（envelope 与列）与类型表的先后顺序不承重（B349）；实现取身份闸先行以省无谓读。
- 两份近重复的快照扫描（`cmd/card_wait.go#cardWaitCurrentWorkflowAttempt`、`internal/agentd/wakeconsumer.go#Server.currentWorkflowAttempt`）退役，取数归共享实现。
- 消费点既有行为不变：card wait 被拦则不 Encode；wakeconsumer 被拦则记 `seen` + 推进游标；默认/`--follow` 退出模型不变。

## 测试决定（接缝清单）

主缝：**共享判定符号**（新建；不写死签名，签名归 contract）——调用方 `cmd/card_wait.go#runCardWait` 与 `internal/agentd/wakeconsumer.go#consumeAutomationEventsOnce`。两者都已有夹具（`cmd/card_wait_test.go`、`internal/agentd/wakeconsumer_test.go`），缝级断言必须穿过调用方，禁止只测 helper（B353 原话）。

| 情形 | 期望 |
|---|---|
| 缺 `node`/`attempt` 键（旧写入者形态） | 交付（新） |

## Out of Scope

**永不做**：判定下沉成账本派生查询；扩 `mirrorSkip`；往 envelope 加身份字段。

**本期不做、后续要做**（落 `docs/roadmap.md`）：

- 写入者版本偏斜的显性侦测：消费者无法区分「旧构建写的缺键」与「新构建写的空值」，本期按同一形态处理；需要的是让偏斜可见，而不是让判定更细。
- 派发侧工作流身份的强制与巡检：裸派发无身份是合法形态，本卡之后不再因此静默，但「谁在不带 `--step` 派发」仍无从发现。

**其它不做**：历史 4289 条镜像不回溯唤醒（消费从不回放，账本可查）；`scripts/build-deploy.sh` 的 pipefail 自检 bug 归 B371；不动 web/控制台展示（B349 已判：控制台不是叫醒消费者）。
