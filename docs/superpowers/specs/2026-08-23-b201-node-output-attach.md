# B201：产文档节点的产出物自动挂卡

> 状态：待用户批准 · 级别 **L2** · 档位不适用

## 问题陈述

产文档的派发节点（plan、contract、breakdown）每一轮**必然**以 `needs_human` 收尾，
即使这一轮完全成功。三方约束互相锁死：

1. 执行者按纪律**不能调 handoff CLI**（`builtin/single-context.md` 第 1 条），
   所以它挂不上自己产出的文档；
2. 下一列的 gate **要那个附件**（`进 "implement" 需要 plan 附件（当前没有）`）；
3. `NodeStep.RunOnce` 在裁决落账后**直接 `routeTo`**（`internal/ledgerstep/node.go:196`），
   中间没有任何环节去挂附件。

于是 `routeTo` 必拒 → `haltForHuman`。2026-08-23 实测两次（B202 的 plan 轮 task
f2860a7f 与 ff9ed908），两次都是「裁决 pass=true，路由失败转等人」。

代价不只是多一步手工操作：

- **看板上出现假红旗**。一轮干得完全正确的节点被标成「需要你」，与真正出事的卡混在
  同一个筛选里——「需要你」这个信号被稀释了。
- **协调者要自己去找产出物在哪**。报文只说「需要 plan 附件（当前没有）」，不说
  「本节点产出的文档在 `docs/superpowers/plans/2026-08-23-b202-pty-test-root.md`」。
  今天靠人去 diff 里翻。
- **它把「节点跑通了」和「卡能往前走」永久解耦**，于是流水线上每一个产文档节点都是
  一个必停的人工闸——而这些闸没有任何裁决价值。

## 现状事实（本轮工作树读数，交 plan 复核）

| 事实 | 出处 |
|---|---|
| 裁决落账后直接路由，中间无挂附件环节 | `internal/ledgerstep/node.go:192-200` |
| 路由失败一律转等人（刻意，不硬失败） | 同上，`haltForHuman(cardID, reason, ...)` 及其注释 |
| runner 收口时手上有 `target` 与 `taskID` | `node.go:150`（`n.Dispatch` 返回）、`node.go:166`（`n.Await` 入参） |
| runner 持有账本句柄 `n.St`，已在做 move / 落裁决 / 清等人标记 | `node.go` 全文 |
| 执行者被禁止调 handoff CLI（含 `card update --attach`） | `internal/discipline/builtin/single-context.md:5` |
| 节点定义今天声明 gate（进某列要什么），但**不声明本节点产出什么** | `deploy/workflows/charter-v4.json` |

## 方案

### 采纳：节点声明产出物，runner 挂完再路由

1. **节点定义新增产出声明**，与既有的 gate 对称——gate 说「进这一列要什么」，
   produces 说「这一列产出什么」：

   ```json
   { "name": "plan", "produces": { "kind": "plan", "glob": "docs/superpowers/plans/*.md" } }
   ```

2. **`RunOnce` 在裁决落账之后、`routeTo` 之前**插入一步：取本轮 task 的改动文件清单，
   按 glob 匹配，命中唯一一个就 `--attach <kind>:<路径>` 挂上并落事件，然后照常路由。
3. **匹配不唯一时不猜**：零命中或多命中都**不挂**，走今天的路径转等人——但报文里必须
   写清**期望的 glob** 与**本轮实际新增的文件清单**，让人一眼看出该挂哪个。
   今天的报文只说「缺 plan 附件」，等于让人去 diff 里翻。

### 弃选 A：开一条窄通道让执行者自己挂

即豁免「不许调 handoff CLI」，允许执行者调 `card update --attach`。

弃因：**这是一个纪律边界问题，不是本卡的范围**。禁令挡的是「执行者自扮协调者」这个
已实测过的失败模式，为一次挂附件把它撕开一个口子，得先回答「哪些 CLI 动作算安全」。
那条讨论属于工作流纪律块重构（已记进 `docs/roadmap.md` 的划界节）。而且它多一次往返、
多一份鉴权，收益却和方案一样。

### 弃选 B：gate 放行，改由后续节点自己找文档

弃因：gate 存在的理由就是「防漏靠结构不靠记忆」。为了绕开一个必停的闸而拆掉闸，
是把结构性保证换成约定俗成。

### 弃选 C：runner 用启发式猜（本轮新增的唯一 .md 就是产出物）

弃因：无声明的猜测在「执行者顺手改了别的文档」时会挂错东西，而挂错比不挂更坏
——门会放行，下一个节点拿到一份不相干的文件。显式声明的成本只有一行 JSON。

## 用户故事

1. 作为协调者，plan 节点跑成功后，卡应当自己进 implement 列，而不是每次都停在
   「需要你」等我做一次机械的挂载。
2. 作为协调者，看板上的「需要你」应当只包含真正需要我判断的卡——一轮完全成功的
   节点不该出现在那里。
3. 作为协调者，产出物确实没找到时，报文要告诉我**期望什么**和**本轮实际产出了什么**，
   而不是只说「缺 plan 附件」。
4. 作为工作流的作者，我给一列加 gate 时应当能在同一个地方声明它的上游产出什么，
   两者写在一起才不会各改各的。

## 实现决定

1. **`produces` 是可选字段**。没声明的节点行为一字不变（今天所有节点都没声明），
   老工作流定义不必重发。
2. **挂载失败只告警不中断**，与既有的「清等人标记失败只告警」同款理由：裁决已落账，
   为一次收尾动作失败把整轮判成错误，会让人看不出发生了什么。挂载失败后照常尝试
   路由——门会拒，于是自然退回今天的行为。
3. **改动文件清单复用既有的 task diff 通道**，不新开数据面。具体端点由 plan 决定。
4. **挂载动作的 actor 是节点自己**（与落裁决、清标记同一个 actor），事件流里能看出
   这个附件是节点挂的还是人挂的。
5. **glob 只匹配本轮新增/修改的文件**，不扫全仓——否则一份历史同名文档会被误挂。

## 测试决定（接缝清单）

最高可测缝是 **`NodeStep.RunOnce` 的 Outcome 与账本副作用**——挂载发生在它内部，
且它已有完整的测试夹具（`node_test.go` 里 Dispatch/Await 都是可替换的缝），
不需要起 agentd、不需要真派发。

必须覆盖：

1. 声明了 produces 且唯一命中 → 附件已挂、卡**进了下一列**、Action 是 pass
   （这条是本卡的核心行为反转，今天必然是 needs_human）；
2. 声明了 produces 但零命中 → 不挂、转等人、**报文里同时含期望 glob 与实际文件清单**；
3. 声明了 produces 但多命中 → 同上，且报文列出全部候选；
4. **未声明 produces → 行为与今天逐字一致**（老定义不回归）；
5. 挂载本身报错 → 只告警、仍尝试路由（不把成功的一轮判成 error）。

第 4 条是防回归的主网：本卡改的是一条所有节点都要走的公共路径。

## Out of Scope

- **附件对下一个节点的工作树是否可达**。挂上的是路径，下一个节点的执行者能不能读到
  那个文件，取决于它有没有在卡基线上——那是 **B205** 的范围（正在 implement），
  本卡不碰。两者叠加才是完整链路：B201 让附件挂得上，B205 让附件读得到。
- **豁免执行者调 handoff CLI**（见弃选 A）。归工作流纪律块重构。
- **产出物的内容校验**（挂上的 plan 是不是一份合格的 plan）。那是 review 节点的活。
- **补挂历史卡的缺失附件**。本卡只改往后的行为。
