## 4. 子卡清单与依赖 DAG

### `B233.8-impl`｜共享 ApprovalClient 迁包与旧实现落点退役

**①契约引用**

引用 `docs/superpowers/specs/b233.8-contract.md` §2–§8、F01–F18、§9 C-1–C-5；Ticket 0 当前提交 `2eb03fec` 的 `internal/approval/client.go` 骨架与 `codegraph/diffs/cards-B233.8-charter.json` 视图。逻辑侧入口是 `internal/approval/client.go#Client`、`internal/agentd/approval_client.go#Manager.bindApproval`；边界侧入口是 `internal/executor/approval.go#ApprovalClient`、`internal/executor/opencode/adapter.go#Adapter.BindApproval` 与 `#Adapter.authorizeNativePermission`。

**②意图与为什么**

使 ApprovalClient 的生产实现归属于图已冻结的 `internal/approval`，让 agentd 只负责把自身能力组装成 Hooks；这样 `internal/agentd` 不再拥有审批实现命名类型，OpenCode 三条冷/热生命周期注入仍共享同一 client，且非 OpenCode 的旧权限/提问入口不被误删。实现意图是物理搬迁与接回，不改变审批状态、事件、工单、快照、hash、Ack 时序、入口路径或权限权威归属。

**③验收（行为化）**

缺陷族对抗审查（本卡每个触及子系统逐族回答）：

`d_orchestration`（logic）：

- **生命周期 / 状态机中断**：审批请求或 Manager 在工单创建、等待、Ack 中途重启时，权威事实仍在 Store；实现必须保留既有任务恢复、未送达重投、终态作废与 `transitBestEffort` 语义。测试要覆盖 context 取消后从 Store 读出已落答案的窗口；真实 agentd 重启、孤儿 waiter 与任务目录回收未验证，列入真机清单。
- **静默失败 / 误导报错**：Hooks 任一生产能力缺失、Store 创建/事件/送达标记失败、Approver 错误/超时都不得返回 allow 或伪造成功；错误必须保留原始原因并沿现有日志/状态通路可行动。测试必须反面断言“返回 allow 但没有工单/事件/送达标记”不会发生。
- **跨平台假设**：新包不启动外部进程、不自行解析 OS 路径；scope、task dir、tmp dir 由现有 snapshot/Manager 提供，故实现侧无新的平台路径假设，**无，因为**本卡只迁移进程内审批逻辑。Approver/文件系统实际平台差异仍归真机清单。
- **假红 / 假绿测试**：只测 `NewClient` 空壳或直接深 mock Store 不能过验收；必须由 `Manager.bindApproval` 真实组装，并让 `approval_client_test.go` 的 grant/事件/ack 反面断言可变红。`go test` 的 fake adapter 只能锁契约形状，不能替代 OpenCode 真机行为。
- **门禁绕过**：唯一生产组装是 `Manager.bindApproval`，所有 Store/Hub/状态写入经既有 Manager 注入能力；不新增旁路写路径。并发请求的“检查可复用 grant → 形成决定 → 标记送达”要复用 Store 现有幂等条件并有竞态/重复请求负例；本卡不声称改变 TOCTOU 语义。

`d_execution`（boundary）：

- **生命周期 / 状态机中断**：OpenCode adapter 或宿主进程在 native permission 等待/回传中重启时，client 不能替它回收外部会话；`ApprovalClient` ref 与 Store 工单负责可恢复事实，adapter 的真实进程/会话清扫必须真机验证，不能用 fake runState 推断无孤儿。
- **静默失败 / 误导报错**：`executor.Authorize` 错误必须回传 reject；RespondPermission 错误必须上报 delivery failure 且不产 Delivered/Executed Ack；缺 optional reporter 时只能记录能力缺失，不能报“已送达”。机内已有测试需锁住每个反面窗口，真实 CLI 错误文本仍未验证。
- **跨平台假设**：OpenCode 的 HTTP/SSE、权限 URL、CLI 启停、信号和会话恢复是外部现实；Linux、macOS、Windows（若为支持平台）不能互相推广结果，**无，因为**本卡不改 adapter 协议实现，但迁包后的真实接线仍需逐平台清单。
- **假红 / 假绿测试**：手写 permission 事件只能验证 adapter → interface → reporter 形状；必须保留录制回放/真实样本与“权限已询问但没有事件重复/没有错误 Ack”的反面断言。单测锁的是 adapter 依赖的 `ApprovalClient` 行为，不锁具体 `taskApprovalClient` 类型，因此替换实现不应无意义翻红。
- **门禁绕过**：adapter 不 import `agentd` / `permgate`、不写 Store；所有权限裁决仍从注入 client 进入。`BindApproval` 只替换对应 task 的运行态 client，需测跨 task 绑定失败/隔离；检查与 RespondPermission 间的外部并发窗口属于真实 OpenCode 行为，未验证。

追加设问：

- **序列化边界**：本卡不新增 wire 字段、事件字面值或枚举；但迁移会移动既有手写 JSON。文件清单是 `internal/approval/client.go`（ticket/event payload marshal）、`internal/agentd/manager.go`（既有 ticket/question payload 解码与发射）、`internal/store/store.go`（Ticket/ Event JSON 原样落盘读取）、`internal/executor/opencode/adapter.go`（消费 ApprovalResult/Ack，不自拼 Store JSON）及列出的测试。验收必须有一条穿过 Store 的 payload 回归；因没有新增可空字段，本卡不伪造“缺失 vs 零值”新语义。
- **枚举新值过既有白名单**：不命中新增枚举，**无，因为**本卡只迁移既有 `allow`、`deny`、`pending`、`formed`、`delivered`、`executed`、`gate` 与既有事件类型；测试/静态检查确认不添加新 switch/白名单取值。
- **承重安全属性有测试锁住**：命中任务隔离、同任务/同版本/同指纹复用门槛、仅真实送达后可复用、Ack 顺序和 fail-closed；每项都必须有能变红的 Store/Manager/client 测试，尤其用不同 task、不同 version、未送达 allow、并发重复请求作为负例。不能以实现代码“恰好如此”代替测试。
- **webview / 平台表现差异**：不命中，**无，因为**本卡没有 `d_web` 文件、浏览器 API 或 webview 事件；OpenCode/宿主平台差异仍按 `d_execution` 真机清单处理。

**④入口指针**
