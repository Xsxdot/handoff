## 5. 冻结清单

每条单独可判 pass/fail。

### 5.1 选路与池

1. 具名 target 的生产选路必须经 `targetclient.New`（CLI 一次性）或 `Pool.For`（agentd 常驻）。
2. 本机空 target 允许 `client.New(addr, token)` / `targetclient.NewLocal`，不得为它造假 relay 配置。
3. 直连 `Target{Addr:"10.0.0.2:7777"}` 经 `New` 得到的 `BaseURL` 必须是 `http://10.0.0.2:7777`。
4. relay `Target` 经 `New` 得到的 `BaseURL` 必须是 `http://localhost`。
5. Addr 与 Relay 皆空时 `New` 必须返回 `ErrNoEndpoint`。
6. relay token 长度小于 32 个 hex 字符时 `New` 必须失败。
7. `Pool.For` 在配置里的 `Target` 整体 `!=` 缓存条目时必须关掉旧隧道并重建。
8. `Pool.For` 返回的 client 由池持有；调用方不得关它的隧道。
9. `Warm` 成功不得被解释成对端 agentd 可达。
10. `NewLocal` 不得把本机 client 写入 `Pool.entries`。

### 5.2 能力面

11. `ExecutionClient` 必须定义在 `internal/client`。
12. `ExecutionClient` 不得包含 `HTTPClient` 方法。
13. `ExecutionClient` 不得包含工作区 / 卡 / 机器 / PTY 方法。
14. `*client.Client` 必须实现 `ExecutionClient`。
15. `*client.Client` 必须实现 `Transport`。
16. 跨机 Ask 回程必须走 `ExecutionClient.Reply`。
17. 跨机审批回程必须走 `ExecutionClient.Reply`。
18. 本卡不得把 `executor.ApprovalClient` 四方法暴露为新的跨机 HTTP 面。
19. `Dispatch` 必须保持 `Dispatch(ctx, DispatchOpts) (*proto.Task, error)` 且走 `POST /api/tasks`。
20. `Reply` 必须保持 `Reply(ctx, taskID, ticketID, answer) error` 且走 `POST /api/tasks/{id}/reply`。
21. `Continue` 必须保持现签名且走 `POST /api/tasks/{id}/continue`。
22. `Stop` 必须保持现签名且走 `POST /api/tasks/{id}/stop`。
23. 同一 `ExecutionClient` 方法在本机、直连远端、relay 远端的成功语义必须相同。
24. 本机 / 直连 / relay 允许的差异只许出现在失败诊断（目标不可达、隧道断开）。

### 5.3 裸 HTTP

25. 生产源码中 `.HTTPClient()` 调用只允许出现在 `internal/agentd/forward.go` 与 `internal/agentd/forward_ws.go`。
26. 新的执行/审批/事件调用路径不得取 `HTTPClient` 拼请求。
27. `Client.wsDialOptions` 必须把 `HTTPClient` 设为本 client 的 `hc`。
28. 该 `http.Client.Timeout` 必须为 0。

### 5.4 可交付策略归属

29. `WaitDeliveryPolicy` 是任务事件消费策略，不是传输过滤。
30. `isDeliverable` 必须与 `WaitDeliveryPolicy` 同值。
31. `FollowEvents(..., all=true, ...)` 必须仍能交付 `progress`（传输不得因策略丢帧）。
32. `WaitDeliveryPolicy(progress)` 必须为 false。
33. B233.1 冻结 17–26 的可交付词表本卡不得放宽。
34. 本卡不新增 `EventType` 字面值。
35. 被策略跳过的事件不得推进 `WaitEvent` 的 cursor。

### 5.5 写请求与库重试

36. `Client.do` 对单次调用只执行一次 `hc.Do`。
37. `Dispatch` 发出的请求不得带 `Idempotency-Key` 头。
38. `Dispatch` 发出的请求不得带 `X-Idempotency-Key` 头。
39. 若实现节点为派发加幂等键，键名不得等于 `Idempotency-Key` 或 `X-Idempotency-Key`（否则 Go Transport 会把 POST 当可重放）。
40. 写请求（派发）若发生网络重试，重复请求必须仍只产生一个任务。

### 5.6 失败诊断与游标

41. 直连拿不到 HTTP 响应必须是 `ErrUnreachable`。
42. `context.Canceled` / `DeadlineExceeded` 不得被包装成 `ErrUnreachable`。
43. `ErrTunnelDisconnected` 与 `ErrUnreachable` 不得 `errors.Is` 互认。
44. `WaitEvent` 重连必须携带本机 cursor 作为 `from_seq`。
45. Ask / 审批请求身份跨机稳定：继续遵守 B233.1 `NamespacedTicketID`。

### 5.7 relay 握手（本卡不改字节）

46. `CONNECT` 控制帧 `Encode(Frame{Type:Connect, Node:"devbox", Credential:"c"})` 的字节必须是 `{"type":"CONNECT","node":"devbox","credential":"c"}`。
47. `CONNECT_OK` 控制帧 `Encode(Frame{Type:ConnectOK, Account:"acc1"})` 的字节必须是 `{"type":"CONNECT_OK","account":"acc1"}`。
48. `Register`/`Connect`/`Registered`/`ConnectOK`/`Error` 的字面值必须分别是 `REGISTER`/`CONNECT`/`REGISTERED`/`CONNECT_OK`/`ERROR`。
49. `DerivePSK("tok","acc1","devbox", salt=32×0x01)` 的 32 字节必须是 `f9b8a53c508f2adac984c2bd61fb3c059b30ed379c2556b64b0dd8b6833d0250`。
50. `relayYamuxConfig` 的 `KeepAliveInterval` 必须等于 `yamux.DefaultConfig().KeepAliveInterval`（30s）。
51. `relayYamuxConfig` 只许把日志改成 `io.Discard` + `Logger=nil`，不得改保活开关或 backlog。
52. 本卡不得改 token 派生、Noise 套件或控制帧 JSON 键名。

### 5.8 挂卡与工作区边界

53. 传输路径不得写入卡账本。
54. 建树响应不得表示「传输层写了卡」。
55. 工作区能力本体不在本卡（B233.4）。

## 7. 三重闸门拍板记录

命中三条的决定：

1. **能力 client 不升格为新顶层子系统；`ExecutionClient`/`Transport` 落在 `internal/client`，`*Client` 继续当兼容聚合门面。** 回头要动 CLI、gateway、图的结构树；后人看到「能力 client」会想拆包或立 `d_capability`。被否方案：本卡改 `best.json` 立新域并拆 `internal/client`（轻档并不并行开发）。不做新顶层域。
2. **跨机审批回程走 `ExecutionClient.Reply`，不把进程内 `ApprovalClient` 暴露成新 HTTP 面。** 反过来加一套审批 REST 不会让现有测试变红，但会变成第三条协议栈（spec 已否）。被否方案：把 `PolicySnapshot/Request/Await/Acknowledge` 映射成跨机端点。
3. **`HTTPClient()` 只留给网关原样搬运；`ExecutionClient` 不含该方法。** 后人看到转发基座会想「上层都取 Transport 更方便」。被否方案：把 `HTTPClient` 放进能力接口。
4. **wait 可交付集合是应用策略（`WaitDeliveryPolicy`），传输必须仍能见到被判 false 的类型。** 反过来在 WS 层丢 progress，现有 `all=true` 测试会红，但若有人只改默认 wait、不改 all，默认路径能绿着把规则塞回传输。被否方案：在拨号/解码层按类型丢帧。
5. **Dispatch 不得带 `Idempotency-Key` / `X-Idempotency-Key`。** 加上去不会立刻有业务测试变红，但 Go Transport 会把 POST 当可重放（`isReplayable`）。被否方案：用这两个标准头当派发幂等键。实现若要幂等，必须用不会触发库重试的键名（见移交 plan）。
6. **本卡不改 relay 握手字节（控制帧 JSON、HKDF info、Noise 套件、yamux 保活）。** 被否方案：重写隧道协议（spec 已否）。金样本锁派生与帧，避免「逐字节一致」只活在声明里。

显式不做（spec 已否，此处不重复展开）：重写 relay 协议；传输层继续挂卡或过滤业务事件；为跨机另建交互协议栈；本期做工作区能力本体（B233.4）；本环境发明 relay 拓扑。
