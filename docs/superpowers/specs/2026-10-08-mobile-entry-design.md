# 移动端入口与完整设置改版

状态：已批准（2026-10-08）；用户确认入口稿、补齐设置稿后明确要求 gpt-6-luna 子 agent 实现。级别：L3 轻档，一次本地实现与集成，不拆子卡。修订：v1。

## 问题与方案

当前原生壳使用默认启动图标与朴素配对/机器列表，每次启动恢复配对后仍进入列表。移动设置把大量项目勾选铺在首页。本轮采用已批准的黑白/靛蓝视觉：品牌启动、扫码优先的未配对页、一次性选择当前机器、完整分组设置与独立项目可见性页。

视觉基准：`docs/design/mobile-entry/entry-approved.png` 的启动、未配对、首次选择机器三屏；设置以 `docs/design/mobile-entry/settings-approved.png` 的四屏取代入口稿中简化的设置。逻辑尺寸 390×844；平台系统栏由原生平台管理。已有产品标志复用 `desktop/build/appicon.png`。

## 全部必交故事

- S1：Android/iOS 冷启动呈现真实 Handoff 品牌；没有配对时进入欢迎页，扫码为主入口、粘贴为备用。无摄像头时粘贴仍可完成配对，配对失败不保存半态。
- S2：配对完成且没有当前机器时，选择在线机器并进入已认证工作台；成功加载后才保存选择。离线机器可见、不可进入。以后冷启动恢复同一台机器，不再次选择。
- S3：设置首页顶部展示壳当前机器与更换入口。更换打开原生选择器；成功进入 B 后保存 B，取消/失败仍保留 A。当前机器离线/失效时保留选择，并给重试及去设置更换入口；禁止静默选另一台。
- S4：设置完整保留工作方式、提醒角标、显示、排序、项目可见性、执行机与配对、执行纪律、自动化、Env 文件、检查更新、关于。移动首页分组，工作方式与显示各为二级页，项目勾选另为三级页；桌面能力与所有既有选项的含义保持一致。
- S5：新 UI 不破坏既有 cookie 清罐、配对归一、导航/生命周期、键盘布局、离线守卫与无凭据日志纪律；两端与 Web 从真实生产入口接入，不能交付成另一个演示 App。

## 架构边界与接缝

Android/iOS 壳权威保存本机当前机器，Web 只呈现壳提供的非敏感上下文，不成为选择权威。配对 bundle 继续由现有 Keychain/Keystore 保存；当前机器名字使用 app-private 偏好，与凭据独立。恢复、进入与切机全部复用现有绑定/cookie 桥接，不改变 Go/gomobile 导出面。

Web 设置保留现有 prefs/storage/service API，只调整导航与形态。原生上下文通过两项 DOM data 属性和一次通知事件呈现，更换请求只是一条精确同源导航链接；不存在原生对象接口。精确消费语义见 `2026-10-08-mobile-settings-shell-contract.md`。现有冻结约束仍以 `b417-contract.md` 为准；其中旧执行环境、基线仅是历史读数，不代表当前环境。

当前事实：Android `pair/StartupController.kt:38` 恢复成功进入 MachineList；iOS `RootViewController.swift:19` 恢复后展示机器列表。Web `SettingsPage.tsx` / `SettingsHub.tsx` 已存在移动设置子导航，`GeneralPage.tsx` 承载排序、隐藏与项目勾选。基线为 3e52eb462b7e0213db4c4b8988db91dd3083e84c；具体位置由执行计划再次核实。

## 验证与权限

从两端真实启动/进入协调者、Web 设置生产组件验证成功与反例：A 离线且 B 在线仍不得自动切 B；切机失败不得覆盖 A；401/主框失败不得记成成功；设置所有旧入口可达；偏好修改与项目全选/全不选实际生效。两端编译和相关测试后做跨模块全量回归；可用模拟器/设备的截图与原稿同状态对比，无法运行的环境如实标未验。

本地实现与可逆验证已获授权。执行者可选内部函数/资源组织；不得改变配对 wire、绑定面、安全存储、服务 API、设置存储范围。发现这些边界需变化，回协调者裁决。
