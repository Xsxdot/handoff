## 问题陈述

谁：把任务派给 `--executor agy` 的协调者；同一仓库里随后打开交互式 `agy` / IDE 的人；配了 `approver.executor=agy` 的廉价审批者。

通道：agy 只能读工作区 `.agents/hooks.json`（不像 claude 可以把 settings/mcp 放进 0700 的 taskDir）。审批者走 `executor.OneShotArgs`。

今天发生的事（round-5 审查，对照 `feat/agy-executor` HEAD）：

1. `WriteTaskEnv` 把含本机 `handoff` 绝对路径和 `perm.sock` 的 `handoff-safety-gate` 写进 `workdir/.agents/hooks.json`，靠 `info/exclude` 把 porcelain 抹干净。exclude 盖不住**已跟踪**文件。Antigravity 项目普遍提交这份文件。第一次 dispatch 留下 `M .agents/hooks.json`：后续派发 409；`git add` 可能把 sock/二进制路径提交进仓库。
2. 同时 `ensureGitExclude(workdir, ".agents/")`，把 skills/rules/workflows 的未跟踪文件从 `git status` / `git add .` 藏掉。规则写到 common `info/exclude`，`--new-worktree` 任务永久改主仓，任务结束不回滚。
3. `Stop` / Start 失败 `rollback` / `Reap` 都不撤 `handoff-safety-gate`。原地任务归档后 `perm.sock` 已删，交互式 agy 碰到挂钩工具会按秒重试直到 86400s 墙。
4. `OneShotArgs` 把 agy 的取值旗 `-p` 抄成 claude 的布尔旗：`agy -p --model <m> <prompt>`。官方文档（https://antigravity.google/docs/cli/headless）示例全是 `agy -p "prompt" --model ...`。带模型时 `-p` 吃掉 `--model`，廉价裁决答错题。`oneshot_test.go` 把错误 argv 锁成金样。

## 定级理由

只改 agy adapter 的工作区物料生命周期、oneshot argv、SKILL/README 口径。不新增 HTTP，不改 `executor.Adapter` 五动作签名，不改 permgate。计划写出来不会只复述本页（sidecar 字段、skip-worktree、exclude 回滚），所以不是 L1。不值得为「agy 读 workdir hooks」付 L3 冻结成本——对面是外部 CLI，本侧是已有 adapter 的内部实现。

## 方案

推荐：**安装和卸载成对**。协议迫使物料进 workdir，所以不能学 claude 把文件放到 taskDir 就完事；taskDir 只保存**恢复所需的原文**。

1. `WriteTaskEnv` 在改 hooks 之前，把「文件原先在不在、原文字节、workdir、hooksPath」写进 `taskDir/agy-hooks-restore.json`。然后合并写入 `handoff-safety-gate`（保留既有 named group 的现行为不变）。
2. 已跟踪：`git update-index --skip-worktree -- .agents/hooks.json`，让任务期间 `git status` / `git add` 看不见 sock 路径。失败则先 Restore 再让 Start 失败。
3. 未跟踪：只 exclude `.agents/hooks.json`，**禁止**再 exclude `.agents/`。`ensureGitExclude` 失败打 Error 日志，不再静默 return。把「本轮追加了哪一行」记进 sidecar。
4. `RestoreTaskEnv(taskDir)`：读 sidecar；workdir 已不存在则 Info 日志后成功返回（`--new-worktree` 已回收）；按 sidecar 还原原文或删除我们新建的文件；清 skip-worktree；删掉本轮追加的 exclude 行；删 sidecar。缺 sidecar 视为无事（幂等）。
5. Start 的 `rollback`、`Stop`、`Reap` 都必须调用 `RestoreTaskEnv`。Reap 只有 `taskDir`，这正是 sidecar 落点。Kill 失败也要尝试 Restore，错误合并返回。
6. oneshot：与 grok 同形，取值旗放 prompt 正前、其它旗在 `-p` 之前：`agy --model <m> -p <prompt>` / `agy -p <prompt>`。改测试金样。注释写明为什么顺序不能抄 claude。
7. SKILL：agy 与 claude 并列写进「拒绝理由同帧送达」。README 两语：写明 Stop/rollback/Reap 会卸钩；exclude 只针对 `.agents/hooks.json` 且任务结束回滚；不要再写「exclude 让 git status 干净」而不提已跟踪文件走 skip-worktree。

弃选：

- 已跟踪就拒绝 Start：Antigravity 仓库的主路径，等于宣布 agy 执行器不能用在目标用户的项目上。
- 把 hooks 写到 `~/.gemini/antigravity-cli/`：污染整机所有 agy 会话。
- 只 restore、不加 skip-worktree：任务期间 `git add .` 仍可能提交 sock 路径。
- 继续 exclude `.agents/`：藏掉执行者自己新建的 skills/rules，git 兜底当没改。

## 用户故事

1. 仓库已跟踪 `.agents/hooks.json`。派一次 agy 任务并 Stop/失败回滚/Reap 之后：该文件内容回到派发前（不含 `perm.sock`），`git status --porcelain` 为空，index 上没有残留 skip-worktree。
2. 仓库原先没有 `.agents/hooks.json`。同一生命周期之后：该文件不在工作区（我们建的要删），exclude 里没有 `.agents/`，本轮追加的 `.agents/hooks.json` 行已撤。
3. 任务进行中：已跟踪文件的修改对 `git status --porcelain` 不可见；未跟踪文件不让 `.agents/skills/` 被 exclude 藏掉。
4. `approver.executor=agy` 且配了 model 时，argv 为 `agy --model <m> -p <prompt>`，`-p` 的值是审批文案不是 `--model`。
5. 协调者按 SKILL 不会去事件流里找 agy 的 `deny_guidance_relayed`。

## 测试决定（接缝清单）

接缝越少越好。本卡三条：

| 缝 | 符号 | 生产调用方 |
|---|---|---|
| A | `agy.WriteTaskEnv` / `agy.RestoreTaskEnv` | `Adapter.Start`（写）、`Adapter.Start` 的 rollback / `Adapter.Stop` / `Adapter.Reap`（恢复）。Restore 为本卡新建，导出给同包 Adapter 调，测试可直调。 |
| B | `Adapter.Stop` / Start rollback / `Adapter.Reap` | manager 停任务、启动失败、无内存态兜底回收。测试从 Adapter 入口构造（newRun 或 mock startProc 失败），不断言私有帮手。 |
| C | `executor.OneShotArgs` | `internal/agentd/approver.go` 已有调用。改金样。 |

假缝禁令：不要为了测 exclude 解析抽纯函数占接缝名额。exclude/skip-worktree 的行为从缝 A 的 git 仓库夹具断言。

边界型：agy CLI 的 `-p` 词法以官方 headless 文档为准，锁在 `OneShotArgs` 的返回 argv 上，不在本机装 agy。
