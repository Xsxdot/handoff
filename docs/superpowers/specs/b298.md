## 定级理由

缝 1 单落 `d_orchestration`（`Done` / `Stop` / `compensateWorkspace` 收口时删该任务缓存）。
缝 2 跨 `d_cli` + `d_gateway` + `d_protocol` + `d_orchestration`：新建由 `handoff gc`（可 `--target`）调用的跨进程动作，预览/执行的 wire 不能靠现有 `ReclaimListResp` 表达缓存字节。定级两问：跨子系统且动契约层 → **L3**。

CLI 与编排是同一条用户故事的前后段，不扇出并行子卡 → **轻档**。轻档不许跳契约冻结。

不改 `TaskTmpDir` 的路径形状。`d_web` 不消费。残留 managed 工作树复用 `reclaim` 语义，不另发明脏树规则。

不是 L1：收口点、两处布局、短号、预览/执行/`--force`、老 agentd、批处理失败，三行写不完；验收也不是一眼。

一度用 B286「不新增 HTTP 才留 L2」为「会新增端点」辩护，审查指出先例切的是反面（C1）。「不扇出子卡」只说明轻档，不能把级降到 L2。

## 问题陈述

谁：在协调者机器上敲 `handoff` 的人，看着执行机（尤其 linux-01）的磁盘被 handoff 自己堆满。
条件：任务已经 `done` 或 `stop`（或派发期 `failed`）；任务私有 tmp/gocache 和偶尔没删掉的 managed 工作树还在 DataDir 里。
通道：该机 agentd。协调者经 CLI（可 `--target`）打过去。
要变的事实：

1. 一个任务一旦结束，它的任务私有 tmp/gocache 立刻从那台机器消失；`handoff attach` 仍能读到 `render.log`。
2. 任务表里已经堆着的终态缓存，人可以先看将释放多少、再确认清掉。顺带把 `reclaim` 能收的残留 managed 工作树一起收。

不是：手删 DataDir；不是把任务记录从库里抹掉；不是清空整个 `tmp` 根；不是控制台设置页上的一个分区。

## 方案

### 1. 任务结束时丢掉该任务的缓存

三处收口，各自在现有「尽量删 managed 工作树」之后，再删这个任务的两处缓存叶子：

- `Manager.Done`
- `Manager.Stop`
- `compensateWorkspace`（派发失败补偿，必须点名接上，漏接不会被编译器提醒）

两处叶子：

- 现役：`TaskTmpDir(DataDir, id)` → `<DataDir>/tmp/<id8>`
- 遗留：`<DataDir>/tasks/<完整id>/tmp`

只 `RemoveAll` 这两片叶子。`render.log`、`frames.jsonl`、`proc.json`、任务目录本身、分支、SQLite 行，全部不动。

禁止把等值于 `filepath.Join(DataDir, "tmp")` 的路径当作删除目标。

短号：该 id8 上**自己以外**若还有任一非终态任务，现役叶子本轮不删（自己正在进入终态不算占用者）。遗留布局按完整 id，无此问题。Done/Stop/补偿与 `gc` 共用这一条。

失败只记日志，不阻断归档/中止/补偿——与工作树清理失败同款。残缓存的重试入口是 `gc`，不是重发 `done`。

非终态（含 `waiting_review`）不删。

### 2. `handoff gc`：先看，再清

打的是**目标 agentd 那一台**的 DataDir，`--target` 与 `reclaim` 相同。不复用 `reclaim` 这个名字。

收树循环在 **agentd 这条 gc 能力内部**调 `Manager.Reclaim` / `ReclaimList`。CLI 不逐个 `POST` 单任务 reclaim。

默认预览（不删）：

```
handoff gc [--target <名字>] [--json]
handoff gc --force [--target <名字>]     # 仍是预览；脏树从「将跳过」改为「将强删」
```

`--yes` 才动盘：

```
handoff gc --yes [--force] [--target <名字>]
```

`--force` **只**作用于脏的残留 managed 工作树，含义与 `reclaim --force` 相同。缓存删除不依赖它。`gc --force` 单独出现不加 `--yes`，仍是预览。

执行内容，且仅此：

1. 按任务表**终态行**计算两处缓存叶子，存在才 `RemoveAll` 该叶子（幂等、去重）。磁盘上没有任务行的孤儿目录本期不扫。
2. 残留 managed 工作树：净/prunable 收；脏树无 `--force`、判不出、非 managed = **本行 skip**，不得因这一行 error 中止其余缓存删除与其余树。

不改任务状态，不追加状态迁移事件，不删分支，不删任务目录，不碰用户自建工作树，不碰 `repos/`，不碰 `agentd.log`。

判定在执行当下重算（两次 CLI 不共享上一份预览快照）。两次之间新变成终态的，本轮可清；变成 running 的，本轮不清。动手前重读快照，与 `Reclaim` 同一条。

### 3. 不做前端

本期没有设置分区，也不改开发机详情。

## 弃选

| 弃选 | 理由 |
|---|---|
| 只做命令、结束时不删 | 命令会忘；linux-01 从 150G 长出来就是因为归档从不释放缓存 |
| 只做结束时删除、不做命令 | 已经堆着的不会因以后归档而消失；已 completed 再 done 不会重试清理 |
| 把缓存删除塞进 `reclaim` | B77 非目标写明不删任务侧文件 |
| 清空整个 `<DataDir>/tmp` 或扫无任务行的孤儿短号 | 会删到进行中任务的 TMPDIR（含 claude `perm.sock`） |
| 按保留期删整棵任务目录 / `render.log` | 排查素材 |
| 设置页「清理」分区 | 一次性删盘不是持久配置 |
| 自动 TTL 后台扫 | 无声删盘 |
| 顺手轮转 `agentd.log` | 另一件事 |

## 用户故事

1. 我 `done` 一个刚跑完 `go test` 的任务。那台机器上这个任务的 gocache 没了；`handoff attach` 还能把回合正文翻出来。
2. linux-01 已经 150G。目标机 agentd 已含本卡之后：我跑 `handoff gc --target linux-01`，看到将释放的缓存字节与将跳过的脏工作树。再跑 `handoff gc --yes --target linux-01`，终态缓存叶子没了，净的残留工作树没了，脏的还在，退出 0。确认可丢后 `handoff gc --yes --force --target linux-01` 才丢脏树。
3. 对端 agentd 还没有 gc：命令打出「该 agentd 过旧，升级后再跑 gc」，退出 0；不说任务不存在，也不打印一份空预览假装没东西可清。
4. 一个还在 `waiting_review` 的任务：它的缓存还在，我可以 `continue` 再跑测试。
5. 我不会在控制台设置里找到清理按钮。

## 契约语义与接缝

语义（不定签名，签名归 contract）：

- 清理是**纯资源动作**：不改任务状态、不删库记录、不删分支。
- 预览与执行是**同一个判定函数**；`--yes` 当下重算。状态不变时，执行删除集合等于预览的「将删除」集合。
- `--force` 只对脏 managed 工作树有意义；缓存的删除条件里没有它。`gc --force` 不加 `--yes` 仍只读。
- 删除目标只允许任务表终态行算出的两处叶子。路径若等值 DataDir 下的 `tmp` 根，视为实现错误，必须拒绝，不得删。
- 短号删除权：该 id8 的非终态占用者集合（不含正在进入终态的自己）非空 → 不删现役叶子。Done/Stop/补偿/`gc` 同一条。
- 预览字节按将删除路径**去重**后求和；两终态任务共用 id8 时同一目录只计一次。
- 单台机器一次。跨机是多次 CLI 调用。
- 鉴权：gc 的预览/执行走与 reclaim 相同的既有 API 鉴权入口，禁止另开未鉴权表面。
- 老 agentd（预览与执行端点皆 404，或等价探测）：人读「该 agentd 过旧，升级后再跑 gc」，**退出 0**。禁止译成任务/资源不存在；禁止空预览冒充「无可清」。
- 批处理：脏树无 `--force` / 判不出 / 非 managed = skip 并出现在报告里，不是失败。缓存 `RemoveAll` 失败必须出现在人读和 `--json` 里，不得只进 `agentd.log`。
- 退出码：预览恒 0（拿不到列表才非零，同 reclaim 列表）。`--yes` 仅当存在「本应删除却失败」的项时非零。「脏树被跳过」不是失败。
- `--json` 必须含将释放字节；缺席与零可分。不得复用没有字节字段的 reclaim 列表体顶替。

接缝（符号 + 调用方）：

1. **编排收口删缓存** — 存量 `Manager.Done` / `Manager.Stop` / `compensateWorkspace`。调用方是归档、中止、派发失败补偿。本卡给这三处加上叶子删除。堵住泄漏的最高缝。
2. **批量预览/执行** — 新建、由 `handoff gc` 经 client 调用的 agentd 能力（gateway 暴露、orchestration 判定，内部调 `Reclaim`/`ReclaimList`）。调用方是 CLI。拖历史的最高缝。

不另开第三条「工作树」缝。假缝禁令：不把「算一下某目录字节」抽成对外符号。

## 实现决定

- 命令名：`handoff gc`。无参 / 仅 `--force` = 预览；`--yes` 执行；`--force` 脏树；`--target` / `--json` 与 `reclaim` 同形。
- 结束时删除是 best-effort；失败不要求人立刻跑 `gc`（那是历史堆）。
- CLI 预览必须打出字节量。
- 用户自建工作树（`WorktreeManaged=false`）当不存在。
- 目标机 agentd 需含本卡之后，`gc` 才清得到盘；未升级走「过旧」诊断，不是本卡的清盘失败。

## 测试决定

1. 缝 1：三处收口各自 → 两处叶子被删、`render.log` 仍在、收口成功不依赖删除成功。非终态走不到这条删除。短号被其他非终态占用时现役叶子保留。补偿路径漏接必须能被测试抓住（点名 `compensateWorkspace`）。
2. 缝 2：
   - 预览列出终态缓存字节且不删；`--yes` 后那些去重叶子不在、进行中的还在。
   - 一净一脏无 `--force`：净树与终态缓存都清掉、脏树仍在、退出 0。
   - 有 `--force` 才按 reclaim 语义丢脏树。
   - 老 agentd 双 404：文案含「过旧」，退出 0，不是空预览。
   - 删除目标若算成 DataDir `tmp` 根：拒绝，进行中任务的 tmp 还在。
   - `--json` 含字节字段，缺席与 0 可分。
   - CLI：无 `--yes` 不动盘；仅 `--force` 不动盘；`--yes` 才删。

每条缝至少一支缝级断言；上列负例属于缝 2 的调用方行为，要能变红。全量测试不在本节点。

## 验收判据（整张卡）

1. 新归档 / 中止 / 派发失败落 `failed` 的任务，目标机上不再留下它的任务私有 tmp/gocache（短号碰撞且有其他非终态占用者除外）；`attach` 仍可读。
2. 对已堆着缓存的、已升级的机器：`handoff gc` 预览给出去重后字节量；`handoff gc --yes` 之后终态叶子消失，非终态的还在；一净一脏无 `--force` 时脏树仍在且退出 0。
3. 未升级机器：`handoff gc --target …` 报过旧、退 0，盘上不变。
4. 用户自建树不动。任务状态、分支、任务目录、`agentd.log` 除被删叶子/被收 managed 树外与手清前一致。
5. 设置页五个分区无新增。
6. 本节点该干什么一律以注入的纪律块为准。

## Out of Scope

永不做（本卡口径）：把清理做成设置页独立分区；无声后台按 TTL 删盘且不可预览；`RemoveAll` 整个 DataDir `tmp` 根。

本期不做、后续要做（已落 `docs/roadmap.md`）：

- 开发机详情上展示 DataDir 占用，并提供与 CLI 同语义的预览/确认清理。
- `agentd.log` 轮转或截断。
- 按保留期删除整棵任务目录 / `render.log`。
- `reclaim` 无参批量收树（今天仍是一任务一次）；本卡只在 gc 能力内部调单任务回收。
- 磁盘上没有任务行的孤儿 tmp 目录（任务表只增不删，本期只清表内终态叶子）。
