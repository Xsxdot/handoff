## 问题陈述

谁：全队每台 agentd 上替执行者裁决权限请求的「廉价模型审批链」。

现状（读数，由执行节点复核）：

1. 审批链是**每台机器自己的 config.yaml** `approver:` 段（`internal/config/config.go:212-229`：`executor` 候选有序表、链级 `model`、候选级 `models`（B405）、单候选 `timeout`、`blacklist`）。四台机器要四份，各自维护、各自漂移。
2. 候选只能是**本机**执行器：启动时从本机适配器绑定 OneShot（`cmd/agentd.go:207`、`:641-676`），整条审批路径里没有「机器」这个概念（`internal/executor/oneshot_cap.go:40-47`）。本机没装/没登录某个执行器，就用不了它。
3. 配置启动时读一次，改链要重启 agentd（`cmd/agentd.go:162`）。
4. 跨机通道已有：target 客户端池按设备表的名字取连接（`internal/agentd/devicesource.go`、`internal/targetclient/pool.go:151`），但对端没有任何「跑一次 OneShot」的端点。

要变的事实：全队只配**一条**审批链，链上每一环 = (机器名, 执行器, 可选模型)。任何一台机器上的任务要裁决时，按顺序逐环尝试：本机环就地跑，他机环请那台机器的 agentd 用它自己的执行器裁决；某环不可用/超时/出错就试下一环；全部失败照旧升级人工。

谁能观察到：`handoff approver show` 看到同一条链；任务事件历史里每次候选尝试的审计记录写明在哪台机器、哪个执行器、什么模型、结果如何。

## 方案

**甲（采纳）：链是共享账本里的一条全队实体，环按全局机器名引用设备表，他机环经新增的「代他机裁决」端点执行；裁决提示词的构造与裁决解析都在执行环的那台机器上做。**

- 链存共享账本的版本化注册表（`registry`，kind 专属一种），CAS 写入；每台 agentd 裁决时读当前链（可短时缓存），改链不重启即生效。
- 环里的机器名经设备表解析：名字 == 自名 → 本机直接跑，否则经 target 客户端池调对端。
- 对端端点是**窄接口**：入参是权限请求原文、任务背景摘要、执行器名、模型、时限；对端用自己的审批逻辑（同一份提示词模板、nonce 生成与校验、JSON 裁决解析）跑本机 OneShot，回 approve/escalate/error + 理由 + 耗时。它不接受任意提示词——不把对端变成通用 LLM 代跑口。
- 对端用自己的执行器环境（env 文件、登录态、默认模型），这正是「他机有、本机没有」的价值所在。

弃选：

- **乙：只把链配置共享，各机仍只跑本机执行器**（链里的机器名只是「这一环只在那台机器上生效」）。实现小，但做不到「前一台不可用再试下一台」——卡的原话是逐台尝试，乙只是同步配置，不是跨机链。
- **丙：发起方构造提示词、对端只做通用 OneShot 代跑**。对端变成持 token 即可跑任意提示词的通用口；nonce 与解析分处两端，版本漂移时更难诊断。窄接口把审批语义收在一个函数里。
- **丁：链挂在设备表各行的 `attrs` 里（每台机器写自己的「排第几」）**。顺序是全链属性，拆到各行要靠 rank 字段拼回，改顺序要改多行、无法 CAS 原子化。设备表 `attrs` 留给真正按机器的属性（B438 端点候选）；本卡对设备表只消费「按名找到一台机器」。

## 落位三问

① **读写谁的权威数据**：全队审批链是一份独立权威状态（一条有序链 + 链级时限），写者是 CLI，读者是各机 agentd 的审批编排。它落共享账本的版本化注册表（与载体/小队同一原语，账本不解释 body），规则所有者是**审批编排领域**（orchestration 的 Approver）——它定义链的形状与校验；账本只承诺版本化 + CAS（第一条、第五条）。设备表照旧归设备表领域，本卡只读。
② **谁消费**：同进程内由审批编排消费（经注入的链读取口，不直接碰账本表）；他机消费走**新增跨进程契约面「代他机裁决」端点 + client 方法**（第四条），发起方经 target 客户端池取对端 client，池仍是唯一选路判据。CLI 经账本读写接口。
③ **同步还是异步**：代他机裁决是同步请求-应答——调用方（被阻塞的权限请求）必须立即拿到 approve/escalate 才能放行或升级，失败要立即转下一环，不能接受最终一致（第十二条）。读链是同步读（带短缓存）。

## 目标架构与接缝语义

- **审批编排领域（orchestration，既有，扩展）**：规则所有者。链的形状 = 有序环（机器名、执行器、可选模型）+ 链级单环时限；校验规则在此定义一处，CLI 写入与 agentd 读取共用。Approver 的逐候选尝试循环不变，候选从「本机执行器名」泛化为「环」；环的执行方式由注入的执行口决定：本机环 → 本机 OneShot（今天的 `decideWithCandidate`），他机环 → 远程裁决口。**提示词构造、nonce 校验、裁决解析只有一份实现**，本机环与对端端点共用。
- **账本（ledger，既有原语）**：链落版本化注册表一个专属 kind，账本不解释 body。不新建表，不改 devices 表。
- **设备表（ledger devices，B439，只读消费）**：经 target 客户端池按名取对端连接；名字 == 自名的判断用 B439 的唯一自名判据，不另立。
- **agentd（既有，新增端点）**：「代他机裁决」端点，鉴权沿用对端 token；收到请求即用本机 Approver 的单环裁决逻辑跑一次，回结构化结果。端点不碰任务、不建工单、不写事件——审计由发起方落在任务事件流里。
- **client（既有，新增方法）**：对应端点的调用方法；旧版对端回 404 时归一为「对端不支持」错误，由编排按候选失败处理。
- **cmd**：`handoff approver show|set` 命令；agentd 组装点注入链读取口与远程裁决口。
- **依赖方向**：orchestration → {链读取口, 远程裁决口}（接口注入，不反向依赖 agentd/ledger/targetclient）；agentd 端点 → orchestration 的单环裁决；cmd 组装。审批编排不直接读 `devices` 表。

**需冻结的承诺（交 plan 写条件节）**：「代他机裁决」请求/应答的 wire 形状与版本降级语义（旧版 404 = 该环不可用）——它是新的跨机兼容承诺，新旧版混跑期间两端必须对得上。

## 首故事选择

单卡单轮交付，不扇出：五个子系统的改动量都小，主体是一条新端点 + Approver 候选泛化，拆子卡的固定成本（约 70 分钟/卡）高于收益。

实现顺序的首段 = **S2 竖切**：发起方 Approver 经远程裁决口调另一个 agentd 组装点的真实端点，对端用 fake OneShot 裁决。它验证承重未知「单环裁决逻辑能否原样搬到端点后面、发起方审计是否还能拿到对端的模型/耗时」。S1（共享链存取）、S3/S4/S6（失败与回落）跟进。

## 实现决定

- 用户可见名字：命令 `handoff approver show`、`handoff approver set -f <文件>`、`handoff approver clear`（清除共享链 → 各机回落本地配置）；链文件为 YAML，形态：

  ```yaml
  timeout: 60s          # 单环裁决时限：连上对端之后等裁决的上限，超时即转下一环
  candidates:
    - machine: linux-01
      executor: codex
      model: gpt-6-luna # 可省略：用该机器上该执行器的默认模型
    - machine: mac-mini
      executor: claude
  ```

- 审计：每次环尝试的审批决定事件新增 `machine` 字段（附加，旧消费者忽略）；失败原因区分「机器不可达 / 对端不支持 / 对端无此执行器 / 超时 / 裁决无效」。
- 时限分两段（r2 修订）：
  - **连接时限**：他机环的拨号/建连有独立的短时限（秒级，具体值由 plan 定，不进链文件），对端不可达即快速失败、转下一环。理由：Tailscale 对端掉线时拨号会一直挂起，若与裁决时限共用 60s，执行者一个任务几十个权限请求每次都白等。
  - **裁决时限**：链文件的 `timeout` 只约束「连上之后等对端裁决」（本机环即 OneShot 调用本身）。发起方对远程调用施加这一时限，不信任对端自己收口。
  - 审计失败原因区分「不可达」（连接时限内连不上）与「超时」（连上后裁决超时）。
- 执行器在对端是否可用**只在裁决时判**（对端无此执行器 → 该环失败转下一环），写链时不校验——写链的机器不知道对端装了什么。
- 黑名单（`approver.blacklist`）**本期仍是本机配置**：它是 permgate 在审批链之前的本机硬拦截，与链的跨机执行无关（见 OOS）。
- 共享链从未读到时的回落顺序：本地 `approver:` 链 → 无则直接升级人工（S6）。
- 控制台不加编辑入口：B160 已把审批链列为安全链、不进通用设置页（`docs/superpowers/specs/2026-08-19-b160-general-settings-design.md:58`）。
- 对端端点只接受审批语义的参数，不接受任意提示词（方案甲第三点）。

## 测试决定（真实入口与风险）

- 竖切 S2：两个 agentd 组装点（各自 fake OneShot、各自 token）经真实 HTTP，发起方任务权限请求 → 对端裁决 → 发起方审计含 `machine`。
- 核心方法：链校验（表驱动：空链、重复环、未知机器、时限）；环执行口的失败归类（不可达/404/无执行器/超时/解析失败 → 转下一环）；回落顺序（S6）。
- S5：既有审批链回归测试原样全绿（B376/B405 的钉不改）。
- 真机：**一律隔离实例**（独立 datadir/端口/配置/repo_root，`sync.auto=false`，连测试库或隔离 schema，不碰共享账本与 mirror_lease）；在役 agentd 二进制与进程不替换、不重启。场景：隔离实例 A（Mac mini）任务触发权限请求，链首环指向隔离实例 B（linux-01）→ B 裁决；再停掉 B → 转第二环。

## Out of Scope

- **永不做**：对端代跑任意提示词的通用 OneShot 端点；审批者有权「拒绝」（审批链只有 approve/escalate，fail-closed 不变）。
- **本期不做、后续要做**（落 `docs/roadmap.md`）：
  - 黑名单全队共享（今天各机本地；共享需 permgate 支持热更新）。
  - 控制台查看共享审批链（只读展示；编辑仍不进控制台）。
  - 环的健康探测与跳过（如记住「linux-01 最近 5 分钟不可达」直接跳过，省去逐次等时限）。
  - 自动审批规则识别「cd 到任务工作树 && … > "$TMPDIR/x.log"」：属 permgate 静态规则（不经审批链），已在 roadmap（B439 协调者条目），单独建卡，不并入本卡。
