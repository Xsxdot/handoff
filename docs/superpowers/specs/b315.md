## 问题陈述

B308–B314 在同一条缝上补症状：agy headless 有原生确认和 PreToolUse 两道门，原生 allow 又是名单。`command(*)` 之后 `write_file` 再拦；matcher 点名工具，PreToolUse 名对不上就进不了 handoff。HOME 与 workspace 各写一份 gate，`--add-dir` 打两次。

B305 禁 `--dangerously-skip-permissions` 的依据（hook deny 失效）已被 B308 canary 证伪：deny hook + skip-permissions，文件不存在。该旗只跳过原生确认。

## 方案

原生通放用 `--dangerously-skip-permissions`；PreToolUse matcher 为 `*`，所有工具进 hook；否决只在 handoff。不写 `always-proceed`。gate 只写任务 HOME，不再写入 workspace `.agents/hooks.json`（避免 `--add-dir` 双开火）。B310/B314 重放回写保留作断线兜底。

弃选：继续列 `write_file(*)`（下周还有下一个名字）；只加 skip-permissions、matcher 不改（未挂钩工具 handoff 瞎）；matcher 点名表扩 `write_file`（仍是名单）。

## 用户故事

1. `replace_file_content` / `write_file` 工作区内写入经 hook 到达 handoff，范围内自动放行，文件真的改到。
2. hook deny 时命令和写入都不执行。
3. 同一 `step_N` 只打一次 PreToolUse（HOME 一份 gate）。
4. argv 有 `--dangerously-skip-permissions`，settings 无 `always-proceed`。

## 测试决定

缝：`agy.agyArgv`、`agy.WriteTaskEnv`、`agy.permTextAndRequest`。

## 实现决定（即 plan）

1. `agyArgv` 恒带 `--dangerously-skip-permissions`；禁止 `always-proceed`。
2. PreToolUse matcher 精确 `*`；gate 只写 `taskDir/agyhome/.gemini/config/hooks.json`。
3. `permTextAndRequest`：`write_file` 当写；`view_file`/`grep_search`/`find_by_name` 带路径走范围内自动放行；未识别工具给 `PermToolOther`（Consult），不再 `Perm==nil` 升级。
4. perm.sock 大载荷已用 `json.Decoder`（`TestPermServerLargePayloadDecode` 保留）。

## Out of Scope

- 永不做：`always-proceed`；写用户全局 hooks。
- 本期不做：隔离 HOME 写文件 canary（合 main 后、不碰生产 agentd）；拆 B304 Restore 旧 sidecar 行为（仍能清历史 workspace gate）。
- 不 reopen B308/B310/B314。
