## 3. 子卡清单与依赖 DAG

### B249-I1：权限判据降噪统一实现与归一验收（唯一子卡）

#### ①契约引用

引用 `b249-contract.md` §2（任务专属临时目录）、§3（范围顺序/安全命令/自指令）、§4（白名单 AutoAllow 审计）、§5（测试交棒）；引用 spec 的“已定裁决”、B248 落地顺序和 out-of-scope。审查补充项为：把 AF_UNIX 107、测试子路径预算 51、旧形状 61/112、新形状 27/78 的完整字节账搬到 `internal/executor/tempdir.go#TaskTmpDir` 中文注释；B248 基线提醒作为实现开工门禁。

#### ②意图与为什么

让权限判据、任务专属临时目录、执行器环境和审计事件共享已经冻结的语义：任务私有临时目录是第三个合法根，但共享 `/tmp` 仍是越界；安全命令只在所有写入落点过范围门后才静默放行；每次白名单 AutoAllow 都留下可查但不唤醒人的事件；四家执行器的 Start/Cold Resume 使用同一任务临时目录且用户变量不能覆盖 handoff 管理值。

本卡必须同时处理 contract 轮审查发现的两项知识质量问题：权威注释在 `internal/executor/tempdir.go#TaskTmpDir`，并使用仓库既有中文注释风格；Codex adapter 只是直通镜像，不得继续成为唯一字节预算来源。实现轮不得以临时目录落在 `$PWD` 或共享 `/tmp` 换取测试便利，否则会使“非 git 目录应报错”和跨任务隔离测试失去前提。

#### ③验收（行为化判据）

以下每项都必须由可独立运行的命令或测试给出结果；本 breakdown 节点只提交验收提案，不把下游未运行结果冒写为已通过。

1. **范围与命令判据（逻辑域，机内闭环）**

   - `go test ./internal/permgate -count=1` 返回该包 `ok`；测试必须从 `Gate.Judge` 入口覆盖三根 `base`、任务临时目录内路径 AutoAllow、`/tmp/shared`/仓库外/前缀相似路径 Escalate。
   - 全量安全 ID（`git-ledger-amend`、`go-build`、`go-test`、`go-vet`、`gofmt`、`npm-test`、`npm-run`、`make`、`ls`、`cat`、`grep`、`git-status`、`git-diff`、`git-log`）命中后返回 `AutoAllow`、`RuleSafeCommand` 和稳定 ID；`echo "go test"`、额外 shell 连接符、wrapper/eval、未知命令不命中。
   - `gofmt -w`、`git add`、`git diff --output=<path>`/`--output <path>` 的落点均进入同一范围门；越界落点在 matcher 前返回 `Escalate`，不能因为命令在白名单而 AutoAllow。
   - `handoff graph resolve --doc <文档>` 不命中 `RuleSelfCommand`；`handoff graph dispatch` 与未知子命令仍命中并升级。
   - 反面断言必须穿过 `Gate.Judge`，不能只测 `safeCommandID`、正则或字符串表。

2. **任务目录、执行器和平台边界（边界域，机内只验契约形状）**

   - `go test ./internal/executor/... -count=1` 返回所有执行器子包 `ok`；金样本锁定 `/root/.handoff` + UUID → `/root/.handoff/tmp/<id8>`、短 ID、空 ID的 `filepath.Join` 语义。
   - 通过各家 Start 与 Cold Resume 的已有启动缝读取最终 env：`TMPDIR`、`GOTMPDIR`、`GOCACHE` 分别等于同一 `TaskTmpDir`、其 `gocache` 子目录，且 handoff 值覆盖用户同名变量，任务临时目录不在 worktree。
   - `internal/executor/tempdir.go#TaskTmpDir` 的中文注释可被 `rg` 同时检出 `AF_UNIX`、`107`、`51`、`61`、`112`、`27`、`78`，并明确“改回旧形状会使整轮测试必红”；这条验收锁知识位置，不接受只在 Codex 注释存在。
   - 机内测试只证明适配器向启动缝传递了正确形状；真实 CLI 是否实际使用变量、进程重启后目录是否可回收、Linux/Windows 的路径和环境行为均为“未验证，需真机”。

3. **审计事件与序列化链（逻辑域 + 边界消费面）**

   - `go test ./internal/agentd ./internal/proto ./internal/store ./internal/ledgermirror -count=1` 返回相关包 `ok`；真实 Manager 权限入口产生一次且仅一次 `permission_auto_allow`，范围内 write/edit 不产生该事件。
   - 将事件从 `permissionAutoAllowPayload` 经 `Store.AppendEvent` 落库后再读回，逐字段断言 `permission_id`、`permission`、`tool`、可选 `command`/`paths`、`rule`、`reason`；用可空/缺失与零值区分字段缺失和空值，不只断言事件数量。
   - AppendEvent 失败时仍尝试把 `once` 回传 executor，回传成功后才累计 AutoAllow；事件失败必须有可行动 Error 日志；不建 ticket、不改变任务状态、不 Publish。
   - `permission_auto_allow` 在 `client.isDeliverable`/backlog 过滤下不唤醒一次性 wait，`all=true` 仍可见；`ledgermirror#mirrorSkip` 不加入该事件，既有镜像消费链能读到它。
   - 新枚举值的每处既有白名单/switch 均逐一核对：`client.isDeliverable` 必须登记为不可交付，`mirrorSkip` 必须明确“不登记以保留镜像”，通用 `proto.Event`/event frame/Store 不得因未知类型丢弃；测试穿过真实 JSON/Store/client 链路。

4. **组合门禁与总回归**

   - `go build ./...` 返回退出码 0；`go vet ./internal/permgate ./internal/agentd ./internal/client ./internal/proto ./internal/store ./internal/ledgermirror ./internal/executor/...` 返回退出码 0；`gofmt -l` 对实现文件返回空输出；`git diff --check` 返回空输出。

   - **序列化边界**：产生端是 `internal/agentd/manager.go` 的私有 payload，事件类型是 `internal/proto/proto.go#EventType`，编码边界是 `internal/store/store.go#Store.AppendEvent`，通用事件帧是 `internal/agentd/eventframes.go`，客户端消费/过滤是 `internal/client/client.go#isDeliverable` 与 `internal/client/backlog.go`，镜像消费是 `internal/ledgermirror/mirror.go#mirrorSkip`。统一回归必须穿过 Manager → Store → JSON payload → client/mirror；`permission_id` 缺失与空串/零值分开断言。
