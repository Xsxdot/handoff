## 问题陈述

谁在什么条件下，通过什么关系，使什么事实变化：agentd 拉起或唤醒**叫机器人**席位时，协调者进程必须活在载体登记的隔离 HOME 里；这份 HOME 必须是协调者全套（本进程 agentd 的 handoff 配置 + 该 CLI 缺失的表内登录凭据 + 该 CLI 的规则/skill），路径必须展开成绝对路径；attach 送到门口的命令必须带着同一份 HOME。用户在房间里看到的应是协调者自己写的话，而不是只有「载体已更换」指针。

真机（本机 agentd v0.4.1，载体 `muse` / `home_dir=~/.handoff/home/muse`）五条同缝：

1. **B323** 隔离 HOME 下 `handoff` 按 `$HOME/.handoff/config.yaml` first-run 出第二份 token，对本机 agentd **401**。回合 `output_bytes` 非零，`room read` 空。`config.DefaultPath` 走 `os.UserHomeDir()`（认 `$HOME`）。
2. **B326** `copyMainCredential` 只拷表内凭据文件（opencode = `.local/share/opencode/auth.json`），注释写明「不搬运技能/规则树」；`TestWakeHomeSuppliesMainCredentialBeforeTurn` 锁的是隔离侧不得出现 `.config/skills`（不是 opencode 真树 `.config/opencode/skills`）。且供给**只在目标目录为空时**发生，占用后不再补。主环境 `~/.config/opencode` 有 `AGENTS.md` + 24 个 skill，muse 隔离侧没有。`card coordinate` 不经 `WakeHome`。
3. **B325** `attachLocator.Locate` 拼 `cli + " --session " + id`，不含 HOME。`keystone.Locate` 内存未命中时重建 `SessionRef` 只有 CLI / SessionID / Workdir，**丢掉 HomeDir**。真机：无 HOME 跑该命令 → `Error: Session not found`；带展开 HOME 则 TUI 能起。
4. **B327** `expandTurnHomeDir` **成功路径已经展开**（`TestBuildEnvExpandsTildeHomeDir` 锁在 `buildEnv` 内部）。失败时**原样返回** `~...`（fail-open）。这是字面 `~` 能再次进子进程的唯一活口。仓库下 `repos/handoff/~/.handoff/home/muse` 仍在（约 167M）是历史残骸，清理 OOS。`driveTurn` 日志的 `home_dir` 是请求原文，不是展开后的 env。
5. **B324** 冷 Resume 日志有登记串 `home_dir=~/.handoff/home/muse`（`Wake` 已 overlay 载体 HomeDir，不是「没带 HOME 字段」）。477ms 失败 stderr 38 字节 = `Error: Session not found`，随后重建并 `Pointer`「载体已更换」。热路径同一 HOME 可 `rebuilt=false`。这是会话落在错误目录（历史字面 `~/` 或默认 HOME）的用户面，不是第三处独立展开 bug。存量垃圾里的旧会话允许一次性重建。

身份：本机 `handoff` / agentd v0.4.1 `bcc424cbd`，不是测试夹具。

红色回路（机内，不依赖真人 TUI）：

- `RunTurn`：UserHomeDir 成功时 HOME 绝对、Workdir 下无 `~` 条目；UserHomeDir 失败时 **报错**，不得拉起带字面 `HOME=~...` 的子进程。
- `keystone.Service.Locate` 热路径与内存 miss 各一：`command` 含展开后的 `HOME=/` 与 `--session`。
- 协调者 Launch 之后，隔离 HOME 下 handoff 配置 token **等于本进程 agentd 正在用的 token**；占用目录里已有 first-run 残件 + 假 session 文件时，token 被覆盖、session 文件仍在。
- 协调者 Launch 之后隔离 HOME 能看见 `.config/opencode/AGENTS.md` 与 `.config/opencode/skills/`；同一 Host 上 `WakeHome` 仍不得创建 `.config/opencode/skills`。

## 方案

**一条不变式**：叫机器人的每一次无头回合和每一次 attach 命令，用的都是载体 `HomeDir` **展开后的绝对路径**；该目录在拉起前补齐协调者全套；检测（`WakeHome`）仍只搬凭据、不搬规则树。

推荐做法（实现形态归 plan，这里定语义）：

1. **展开失败即失败**，禁止把字面 `~` 交给子进程或写进 attach 命令。无头回合：进子进程 env 前展开，失败则 `RunTurn` 报错（可行动，含原串）。attach：locator 拼串前把 HomeDir 展开成绝对路径，失败则 400，不得返回不含 HOME 的 command。禁止照抄 `scheduling.RunCommand` 的未展开 `HOME=~/...`。`SessionRef.HomeDir` 存展开后的绝对路径。新日志的 `home_dir` 为展开结果（现状日志打的是请求原文，不是 env 证据）。
2. **协调者 Launch / Resume**（`coordinatorRunner`，不是 `WakeHome`）在跑 CLI 之前按**写入白名单**供给到该绝对 HOME。占用 = 补缺 + 覆盖 first-run 残件 config，不是重建整棵树。
   - **只保证这些路径**：`.handoff/config.yaml`（token = **本进程 agentd 正在用的 token**，不是哪份 yaml 方便抄哪份；DataDir / ledger DSN 若原串相对则改写为 agentd 实际在用的绝对路径后再落盘）；该 CLI 的 `.config/opencode/AGENTS.md` 与 `.config/opencode/skills/`；表内 CLI 登录凭据文件在隔离侧**缺失时**做与 WakeHome 同款的单文件拷贝（opencode：`.local/share/opencode/auth.json`），已存在不覆盖。
   - **禁写**：禁止 `RemoveAll` 整棵 HOME；禁止改写 `.local/share/opencode/` 下除上述缺失凭据文件以外的条目（含 session db）。symlink 还是 copy 归 plan。
3. **attach 命令**由服务端生成，客户端仍不得拼接。命令必须让在项目目录打开的 POSIX shell 以同一绝对 HOME 找到会话（`HOME=<绝对路径> <cli> --session <id>`；路径含空格时必须是合法 shell 赋值）。PTY `init_command` 已是打进 shell 的。
   - 内存未命中时 HomeDir **来自编制域已登记载体**，读法与 Launch 取载体相同，**禁止**走 `LaunchAdmit`（GET 状态不得占协调者名额）。
   - 填充发生在 `keystone.Service.Locate` 把 ref 交给 locator **之前**。locator 只负责把已有 HomeDir 展开进 command。谁去读载体（gateway 传入 vs keystone 新端口）归 plan，结果与禁令在此。
4. **不**把 `RoundResult.Output` 镜像进房间。凭据与 skill 齐了，协调者自己 `room send`。重建指针仍只在真正 `rebuild==true` 时落。

弃选：

- **检测时搬技能树**：否。B293 执行者干净 HOME；`WakeHome` 测试锁了不搬。全套只给叫机器人路径。
- **改终端 tab 的 env API / 新 wire 字段**：否。命令字符串自带 HOME，工作台保持原样透传。
- **镜像回合产出进房间**：否。修的是协调者能写房间，不是 agentd 代写。
- **Resume 失败不重建、不落指针**：否。真找不到会话仍走兜底链；本卡让「不该找不到」不再发生。
- **人坐下 / wait 过滤 / charter 绑小队 / inbox 解码**：否。B329 / wait 已定 / B330 / B328。

## 用户故事

1. 作为协调者，我 `card coordinate` 一张空座卡，隔离 HOME 里跑 `handoff status` 不再 401；房间里出现协调者自己的非 pointer 叙事（不只 HTTP output）。
2. 作为协调者，我往该卡房间发一条用户消息，二次唤醒 `rebuilt=false`、同一 session id，房间**没有**新的「载体已更换」指针。
3. 作为协调者，我点「打开终端」，命令里带展开后的 `HOME=`；在该目录执行能进同一会话，而不是 `Session not found`。
4. 作为协调者，隔离 HOME 里能看见主环境同款的 AGENTS.md/skills；检测按钮仍只搬凭据、不把执行者 HOME 弄脏。
5. 作为协调者，载体 `home_dir` 仍以 `~/.handoff/home/<名>` 登记；子进程与 attach 命令里不再出现字面 `~`，仓库下不再长出 `~/` 垃圾目录。

## 契约语义与接缝

不新增契约面。行为补齐：

1. **`hostapi.Host.RunTurn`**（调用方 `coordinatorRunner` Launch/Resume、`WakeHome` 检测回合）。HomeDir 含 `~` 时子进程 HOME 必须是绝对路径；`userHomeDir` 失败则返回错误，不得原样把 `~` 写进 env。测试必须经 `RunTurn` 公开面，不得只锁 `buildEnv`。
2. **`keystone.Service.Locate`**（调用方 `handleCoordStatus` / `handleCoordAttach`；下游 `keysclient.TerminalLocator.Locate`）。热路径与内存 miss 各须 `command` 含展开后 HOME 与 session id。miss 时 ref.HomeDir 在交给 locator 之前已从已登记载体填上，禁止 LaunchAdmit。locator 不负责自己读载体。
3. **协调者供给（新建行为，挂在 `coordinatorRunner.Launch/Resume`，调用方仍是 keystone `LaunchForCard` / `Wake`）**。Launch 后隔离 HOME 的 handoff 配置 token = 本进程 agentd token；规则/skill 可见；缺失的表内 CLI 凭据被单文件补上。`WakeHome` 仍不得创建 `.config/opencode/skills`。占用对照：first-run 残件被覆盖、假 session 文件仍在。

假缝：文案、日志字段名、是否 symlink 还是 copy——plan 内部锁。

## 实现决定

- 展开执法点两处：进子进程 env 前；拼 attach command 前。SessionRef / attach 命令只携带展开结果。禁止抄 `scheduling.RunCommand` 的未展开 `HOME=~`。
- 全套供给只走叫机器人承载缝，白名单 + 禁写见方案 2。不改 `WakeHome` 的「只拷凭据、空目录才拷」。
- attach 仍是一条 `init_command` 字符串，不改 PTY env 组装、不改 web 终端组件、不加 JSON 字段。夹具里的 command 例子更新归 plan。
- 合 main 门 = 本机（macOS）复跑：真机曾在本机红（attach Session not found、隔离 HOME 401）。实现机 linux-01 跑机制测试；合 main 前本机再跑红色回路与一条真机 attach/resume。存量 `~/` 垃圾不迁、不删。

## 测试决定

每条缝至少一支，机内可红：

1. `RunTurn` 两支：① UserHomeDir 成功、HomeDir=`~/handoff-home-x`、Workdir=临时目录 → 无 `~` 条目、子进程 HOME 绝对（把内部锁升到缝）。② `userHomeDir` 返回 error → `RunTurn` 报错，Workdir 下仍无 `~` 条目，子进程不得带着字面 `HOME=~...` 被拉起。变异「失败原样返回」必须打红第 ② 支。
2. `keystone.Service.Locate` 两支，禁止用「或」：① 热路径 ref 已有 HomeDir（可含 `~`）→ command 含 `HOME=/` 与 `--session`。变异：locator 丢掉 HomeDir。② 内存 miss：Locate 只拿到席位 CLI/session + 已登记载体（禁止 LaunchAdmit）→ command 同样含绝对 HOME。变异：重建 ref 不带 HomeDir。另：穿过 HTTP 的 `GET /coordinator` 或 `POST /attach` JSON `command` 含 `HOME=/` 且含 `--session`（热路径一支即可）。
3. 协调者供给：Launch 进临时隔离 HOME 后，`.handoff/config.yaml` 的 token 等于**本进程**注入的 agentd token；`.config/opencode/AGENTS.md` 与 `.config/opencode/skills/` 可见。占用对照：目录里已有 first-run 残件 + 假 session 文件 → token 被覆盖、session 文件仍在。对照：同一 Host 上 `WakeHome` 不得创建 `.config/opencode/skills`。变异：Launch 不写配置 → token 测试红。

真机（合 main 门，本机）：`card coordinate` 后隔离 HOME `handoff status` 退出 0；房间非空且无新「载体已更换」；attach 命令在该 HOME 下能解析到会话。

## Out of Scope

- **永不做**：agentd 把回合 Output 镜像进房间；第二套 TUI；检测时把执行者 HOME 做成全套。
- **本期不做**：B329 人坐下出示（发现 + `--cli/--session`）；B328 inbox 解码；B330 charter 绑 `runner`；wait 按席位过滤；hostapi 实装 grok/claude/codex 当协调者载体；清理仓库里已存在的 `~/` 垃圾（人工）；把历史 `~/` 目录里的 session 迁回展开后的隔离 HOME（一次重建可接受，不做迁移器）；Windows attach 的 `HOME=` / cmd.exe 形态。
