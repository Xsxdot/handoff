# B456 会话角色状态与接续可见性

状态：草案，待用户确认。日期：2026-10-23。定级：L3，单卡串行，不扇出。执行：本地主会话协调，具体实现交 gpt-6-luna 本地子 agent。

## 问题

用户要从会话里直接知道谁在干活、停在哪里、等谁。真实案例是 E38：审查失败后没有接上修复、修复完成后没有接上复审，都需要用户反复追问。只显示头像、卡所在列或笼统的“工作中”不能解释这些停顿。

## 方案与页面形态

在会话输入区附近增加常驻的紧凑角色栏：角色/名称、状态、时长。点开一项，看到所属卡与阶段、当前活动或等待原因、等待对象、证据发生时间与本次查询时间，并可进入既有卡详情、任务现场或对应证据。多角色收纳，窄屏不遮挡输入框。聊天仍只放人话，不把状态变化刷成聊天消息。

角色包含人、主 agent/驻场者、卡协调者及关联执行任务；执行者是任务的执行角色，不能为展示把它加入会话成员或改变寻址。保留姓名与角色两种信息，不能把同一身份的多重职责简单去重丢掉。

原型：`prototypes/b456-session-status/index.html`（分支副本，纯 mock），从导航进入 `pages/session-status.html`。形态参考已有批准的 B358 会话工作台；本轮只确认底部角色栏及展开内容。

可切换六种示例：运行、E38 待接续、后继已开始/工单已答、待人工审批、来源不可达/过期、空座/未知。原型快照随本规格保存为 `b456-prototype.patch`。复建：复制 base 到功能副本；把 B358 的 `pages/sessions-v2.html` 复制为副本 `pages/session-status.html`，`pages/sessions.html` 原名复制，`shared/styles.css` 复制为 `shared/session-status.css`；在副本根目录以 `git apply` 应用本快照（路径前缀 `-p1`）。

## 状态语义

| 展示 | 必须有的依据 | 不允许的推断 |
|---|---|---|
| 运行中 | 与当前身份/本轮任务关联的明确运行事实；展示观测时间 | 租约未过期、卡在 implement/review、消息发送成功均不能单独证明正在工作 |
| 空闲/监听中 | 来源明确报告该状态时才展示 | 无消息、无租约、查不到任务不能算空闲 |
| 等待回复/审核 | 当前未解决的问题、工单或审查状态；指明等待对象，可未知 | 历史出现过工单不能一直算待答；不确定由谁批时不能写“等你” |
| 待接续 | 当前关联任务已有执行回合完成/待审阅事实，卡未终止，也没有更晚接续事实；写清“尚未观察到下一步” | completed 是执行回合完成、任务进入 waiting_review，并非任务生命周期结束；不当成卡验收完成，不直接判故障；较新运行/继续/派发必须替代旧读数 |
| 异常 | 明确的失败、唤醒失败、交付失败或来源读取错误，附原因与时间 | 沉默时间长不能单独判异常；旧失败已恢复后不能继续盖住新状态 |
| 未知/已过期 | 不支持实时观测、缺少依据、来源读取失败或旧快照 | 缺失不补零；不拿租约到期时间冒充最后活动时间；前端轮询成功不刷新事实发生时间 |

运行、等待、失败事实若来自不同时间/任务，必须先按身份和任务关联，再按事件顺序取当前可证明结论。无法对账时显示未知或来源不完整。时长只能从对应事实的真实时间起算；未知起点显示“时间未记录”。客户端获取失败立即标明读数未更新；恢复后以新事实重算。归档会话呈历史读数，不显示实时运行承诺。

## 落位三问与架构边界

1. **读写谁的权威数据**：只读既有会话/席位、卡、执行与工单事实；不新增一份可写运行状态，不改变调度与审批。规则按 architecture-law 第五、六条在会话用例聚合，事实仍归原领域。
2. **谁消费**：浏览器会话页消费服务端只读投影，沿既有会话 API 与 client；Go DTO 与 TS 镜像一致。涉及跨进程契约，定级 L3（第四条），不因“只是展示”降级。
3. **同步还是异步**：页面读请求需要结果，走既有同步查询；不为本卡加 MQ、后台扫描器或实时长连接（第十二条）。复用既有轮询，服务端经现有领域公开面读取，不能从前端逐角色探机器。

目标依赖：事实拥有者的公开查询 → 会话详情投影 → Web API 镜像 → 会话角色栏。内部精确签名、字段和文件集在 plan 结合真实来源确定。本卡不创建调度平台，不从 collab 穿透执行器或账本持久内部，不为填状态建立无界全局事件扫描。

## 当前代码事实（现状读数，执行节点复核）

- 成员状态只看 DriverLease：`internal/collab/sessions.go:704`；有效租约不等于精确执行状态，且当前填入 last_active 的是到期时间。
- 节点是镜像历史：`internal/collab/sessions.go:737`；现有形状不能直接证明当前执行状态。
- 结构 timeline 与 needs 聚合：`internal/collab/sessions.go:779`；会话最后活动时间是房间消息维度，不能作为角色活动时间。
- 会话页已有详情与历史轮询，真实宿主为 `web/src/app/rooms/SessionTab.tsx:59`，API 消费 `web/src/api/rooms.ts:305`。沿该入口增量扩展。
- 既有公开查询支持按卡分页取事件：`internal/collab/client/client.go:70`；派发身份来源 `internal/ledger/events.go:115`，镜像携带 task 来源、源事件序与原始时间 `internal/ledger/mirror.go:64`。使用同一卡事件序列保守聚合，不为当前展示扫描全库。最新镜像只是最后观测事实，不能承诺远端进程此刻存活。
- 当前任务状态与未决工单派生的既有判例在 `internal/ledger/taskstate.go:141`、`:173`。计划优先复用该权威派生语义；若公开面不足，只增加窄查询，不在会话域另写一套不一致的审批状态机。

## 实现与测试决定

先完成 S2 的最薄真实投影，再接状态栏，其他故事围绕同一入口扩展；单个本地实现者串行完成，无需子卡。按当前关联身份/任务取事实，避免旧席位、旧 attempt 覆盖当前结果。新增查询复用有界读接口；新增 wire 键采用兼容增量，旧数据和旧服务缺键时诚实降级。正式实现由 gpt-6-luna 执行。

测试集中在真实服务投影入口和会话组件消费：至少覆盖完成→待接续→下一任务开始、等待→已答、失败→恢复、身份换绑、跨任务隔离和缺失/过期来源；Go/TS 契约双侧对齐。最终浏览器对照本原型，不能用 helper 自测替代会话入口验收。记录生产查询边界的耗时/降级原因与关联会话/卡/任务，复用项目结构化日志，禁止逐帧刷日志。新增文件写职责边界，非显然的事实优先级写原因注释。

## Out of Scope

- 本卡不做：自动续跑、自动重派、自动恢复、自动审批、自动换绑或通知催促；状态栏只解释事实。后续确有需求时另立 spec，不视作本卡承诺。
- 不做：给不可观测的外部人/agent 推测在线状态、无依据的百分比/预计完成时间、完整模型思考过程。
- 不做：全站原型刷新、全局监控大屏、重写既有会话/任务调度状态机。
