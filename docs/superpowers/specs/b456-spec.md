## 形态基准与十条规则

权威：用户提供的 `~/b456-proto-r4/`，README 入库副本 `b456-prototype-r4.md`；可预览副本 `prototypes/b456-session-status/pages/session-status.html`，快照 `b456-prototype.patch`。与 r3 冲突处以 r4 为准。页面示例全部 mock，不是接入证据。

1. 状态固定六类：运行中（绿实心点）、空闲（灰空心圈）、需要你（琥珀气泡）、等待中（蓝时钟）、异常（红三角）、未知（浅灰虚线圈）。chip 主文字只含状态名与时长，原因进入 hover/详情。
2. 不设常驻「我」。只有当前用户可处理的未决工单在最前显示「需要你处理 N」；点开待处理抽屉，批准/拒绝/回答沿用既有权限与接口，成功后刷新并跳下一张；失败保留工单及错误。
3. 需要你 > 异常 > 等待中 > 运行中 > 空闲 > 未知，同类时长长者在前。只有需要你/异常带底色。
4. chip/横幅均可点，直达所说角色的详情。异常详情有真实下一步（重新唤醒协调者、查看卡、查看日志/已有证据）；唤醒受理只说已请求，不宣称已恢复、已补发或已执行。
5. 溢出依次收紧：先折叠需要你角色 chip（首部 CTA 保留，hover 列角色），安静角色缩头像并附卡/任务末两位，去时长，最后按紧急度收进 +N。异常永不进入 +N；收纳列表保持可点与状态标识。≤650px 两行，极多异常允许自身区域换行，不裁掉异常。
6. 固定命名「协调者 · E38」「驻场者」「执行者 · T-774」，头像为协/驻/执。同一身份的不同职责分开；执行者不因展示被加入会话成员。
7. 详情按结论 → 原因 → 你可以做什么排列；最近动态默认展开，最近 3–5 条倒序一句话摘要，失败红、等你琥珀、其余灰；更多显示灰色不可点「更早的记录…」。技术细节默认折叠，放内部编号、时间和原始证据。
8. 最近动态只复用已有数据：唤醒开始/结束/失败、房间发言摘要、工单创建/回答、任务派发/回合结束/归档。没有来源就明确没有记录，不新建运行记录系统，不展示完整逐轮输入输出。
9. 无协调者不造 chip，以横幅说明；协调者没有记录显示未知；仅等待很久仍是等待中，不凭时长判异常。
10. 保留当前项目树、顶部标签、薄标题、消息区、输入框与全局额度条。角色条在 composer 上方，不更改会话寻址、调度或任务生命周期。

## 状态事实与边界

| 状态 | 所需事实 | 限制 |
|---|---|---|
| 运行中 | 当前角色/任务关联的明确开始或运行记录，带观测时间 | 席位、卡所在列、发送成功或租约都不单独证明运行；镜像事实说明观测边界 |
| 空闲 | 明确回合结束/任务归档或来源报告空闲 | completed/turn_failed 是回合结束进入 waiting_review，不是整卡完成；协调者可仍等待接续 |
| 需要你 | 当前未决、责任为当前用户且允许处理的工单 | 历史已答、自动审批中、不明责任不能冒充等你 |
| 等待中 | 未决等待，或执行回合完成后尚未观察到后继 | 说明在等谁、多久；卡终止/新任务/新轮次后旧等待解除；不凭沉默判失败 |
| 异常 | 当前未恢复的明确失败、唤醒失败或读取错误 | 带原因与事实时间；旧失败不能覆盖较新成功 |
| 未知 | 无观测能力、无记录、读取失败/缓存过期 | 不补零，不拿前端查询时间、租约到期时间充作活动时间 |

按角色身份、卡与任务关联事实；任务内 source_seq 与卡内 seq 不混作全局时间。换绑只认当前席位；同一任务继续/较新派发替代旧结束，旧任务失败不能污染新任务。时长从真实事实时间计算；零值/未来值/缺失起点显示时间未记录。轮询失败即时提示未更新，旧绿色不继续常亮；恢复重新投影。归档只读会话不承诺实时运行，不提供变更操作。旧服务缺新增字段诚实降级。

## 落位三问与架构

1. 权威事实属于会话、账本与执行任务。collab 会话用例经现有 LedgerClient 等公开面形成只读投影，账本负责已有任务/工单回放语义；不让 UI 扫执行器目录，不从 collab 穿透持久实现，不另造审批状态机。除下述用户批准的 I5 最小回合事实外，完整运行内容持久化归 B471 单独处理。
2. 消费者为既有 SessionTab → SessionChat；Go DTO 与 TS 镜像新增兼容字段。跨进程契约定级 L3。角色详情与待处理抽屉用同一投影与已有动作接口。
3. 同步有界查询，复用轮询；不新增 MQ、扫描器、长连接，不从前端逐角色探机器。对数据过多、来源异常、无法关联显式降级，不能截取旧事件却当最新状态。

## 实现与验证

审核补充 I5（2026-10-23，卡 #33162/#33171）：push 驻场者须按真实回合展示运行、空闲、异常；桌面驻场者因只有门铃/continue 深链仍为未知。原数据不能准确区分成功/失败，用户在本会话明确批准“补齐最小回合事实（推荐）”：仅复用现有事件或 Pointer 记录可关联的回合开始、成功、失败，不另建状态系统，不扩大为 B471 输入输出采集。具体冻结见 plan r1.4。禁止把 claim 已完成当成功，也不能用旧失败覆盖较新的成功；运行仍是最近明确观测，不宣称实时进程存活。

单个有界工作单元，冻结契约后由两位本地实现者分别负责后端与 Web；先以真实事件链证明结束→等待→后继，再接 UI 与处理入口。新增跨语言字段有穿透实际服务序列化链的断言，覆盖缺失与零值；测试围绕承重规则和真实消费者，做红绿、独立复跑及一次可编译变异。实现完成跑受影响测试和全量编译/类型检查，最终 review 跑全量并做浏览器/运行验收。日志只在查询失败/降级与动作边界记录关联信息，禁止逐轮正常轮询刷日志；非显然的优先级写意图注释。
