# B303 工作台 PTY 默认注入 Grok OSC 52 sink

- **卡**：B303
- **级别与档位**：**L1**。单子系统（agentd 开 PTY 时往已有 `OpenOptions.Env` 加一颗环境变量），HTTP/WS/ptyhost wire 零改动。plan 即下面三行；验收靠新开终端一眼可核。
- **状态**：已批准（2026-09-02，用户原话「自主推进吧，不用再问我了」）
- **基线**：`origin/main` @ `d063fafb`
- **发现自**：B300 真机验收（2026-08-30）。Grok 在远端 macOS PTY 默认不发 OSC 52；显式 `GROK_OSC52_SINK=1` 后用户确认复制成功。B300 已把 OSC 52 接到本机剪贴板，本卡只补「Grok 肯发」这一段。
- **台账**：`docs/superpowers/specs/b303-ledger.md`

## 问题陈述

用户在桌面工作台打开远程终端、跑 Grok，选中文字应落到本机剪贴板。B300 收了 xterm 这一侧；Grok 默认不发 OSC 52，要环境变量 `GROK_OSC52_SINK=1`。今天这条要人手 export 或改 `~/.zshrc`。

用户故事：

1. 工作台（桌面或浏览器）新建一个终端，不改远端 shell 配置，里面的 Grok 选中即可复制到本机。
2. 已有启动项（env_file / init_command）的终端同样带上，用户不必为 Grok 单独配一条启动项。

## 方案

目标机 `handleCreatePtySession` 在 `pty.Open` 的 Env 末尾**写死** `GROK_OSC52_SINK=1`：拼在 `sessionEnv()` 与 launcher `env_file` 之后，文件不能关掉它。所有经 agentd 创建的 PTY（本机、`?machine=` 转发后的目标机、桌面、浏览器）进程环境都带这一颗。Grok 以外的程序不读这个变量。

不走 `init_command`（会在屏幕上打出一行 export、进 history）。不给 `CreatePtySessionReq` 加字段。前端零改动。桌面薄壳不需要单独信号——UA 本来就不会随转发走。

弃选（已拍板）：

- **init_command 打 `export GROK_OSC52_SINK=1`**：复用现有字段、旧 agentd 也认识，但命令会打到终端里。用户否决。
- **只限桌面薄壳**：UA 不随 `?machine=` 转发，必须给请求体加标记，抬成 L3。用户否决，改为全部 PTY 写死。
- **改远端 `~/.zshrc` / 让用户每次手 export**：本卡要消掉的正是这件事。

## 实现决定（L1 plan）

1. `handleCreatePtySession` 交给 `pty.Open` 的 Env，在 `sessionEnv()` + launcher env 之后追加 `GROK_OSC52_SINK=1`（硬值；env_file 里同名键不能关）。创建成功日志带上已注入（不打别的环境变量值）。
2. 现有 Unix PTY 创建测试的探针 shell 把该变量打进 banner；无启动项、有 env_file、env_file 试图写成 0/空，三支都断言进程环境是 `1`；既有 TERM / MARK / 不写 init_command 的用例不回退。
3. 验收：隔离实例（不动生产 7777）新开终端 `echo $GROK_OSC52_SINK` 为 `1`；桌面工作台在该终端跑 Grok，选中文字本机 ⌘V 得出。未升级的远端 agentd 仍无此变量，不假装生效。

## 测试决定

接缝一条：`Server.handleCreatePtySession`（调用方：工作台 `POST /api/pty/sessions`；实现把 Env 交给 `ptyhost.Open`）。

- 探针 shell 打印 `GROK_OSC52_SINK`，HTTP 建会话后从 PTY 输出读到 `1`。
- 反面：launcher env_file 写 `GROK_OSC52_SINK=0` 仍读到 `1`。
- 既有 `TestCreatePtySessionNoLauncherFieldsUnchanged`（不写命令、TERM 仍在）继续绿。

假缝禁令：不抽「拼 env 切片」的纯函数占接缝名额。Windows 无 PTY（`ErrNotSupported`），本卡不补 ConPTY。

## Out of Scope

- **永不做**：改远端 `~/.zshrc`；让工作台普通终端依赖用户手 export。
- **本期不做**：Windows ConPTY（平台仍报不支持）。
- **本期不做**：`CreatePtySessionReq` 增加通用 env 字段或桌面标记。
- **本期不做**：给已经在跑的 PTY 补注入——重开终端。
- **本期不做**：未升级的旧 agentd 上让 Grok 发 OSC 52。
- **本期不做**：浏览器/桌面前端改动（B300 的 OSC 52 接收面已在）。

## 备注

- 现状：`sessionEnv` 钉 TERM/COLORTERM，随后 `env_file` 可以覆盖 TERM（`TestCreatePtySessionEnvFileOverridesSessionEnv`）。本卡这颗变量**不允许**被文件覆盖，所以钉在 Env 切片最后，不放进 `sessionEnv()` 中段。
- 跨机：`forwardIfRequested` 先整段转发，注入发生在**目标机**自己的 `handleCreatePtySession`。协调者本机 agentd 升级不够，跑 PTY 的那台也要升级。
- 「不影响 CLI 普通终端」= 系统 Terminal.app / iTerm 不经这条 API，不会被改；不是「handoff 工作台里开的终端分桌面/浏览器两套环境」。
- 图：`handleCreatePtySession` 现状在 agentd HTTP 面。本卡不改导出签名。未命中图时记覆盖债，不挡 L1。
