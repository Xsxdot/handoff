## 定级理由

单子系统工作：把「这台 agentd 上的卡派发」收成**本机身份**，两条镜像发现不得把本进程当远端。不新增 HTTP 路径，不改任务/工单状态机，不改 `from_seq` 开区间契约，不改 `mirrorSkip`（`approver_decision` 仍不进卡流）。

`CardStepReq.Target` 空串已经在线上；今天 ViaTemplate 把它当错误。这是既有字段语义收口，不是新契约面。CLI / 账本 / 两条镜像都是同一条身份规则的调用方，不值得为这条缝付 L3 冻结成本。

计划写出来不会只复述本页（自机判定、本机账本源、WorkBranch 等价、纪律探活），所以不是 L1。

## 问题陈述

谁：在本机 `card dispatch --step` 的协调者；挂着 `card wait` 等权限门/终态的协调者；本机 agentd 里跑 charter 节点、卡在 `waitForTurnEnd` 的编排。  
通道：空 `--target` / 空模板 target、`targets` 里的 loopback 登记名、任务镜像与账本镜像的上游 WS、本机 Hub。  
要变的事实：本机卡派发不再要求登记一台指向自己的机器；本机挂账事件进卡流不再经过「订自己的 WS」；本机任务的 WS 订阅者不再被自订二次 Publish 掐断。

现场（B268，源卡 note，2026-08-27）：

1. `charter-default` 模板 `target` 为空。空 `--target` 被拒（「目标机未定」/「未指定目标机」）。`--target 本机` 不是 `config.yaml` 的 targets 键。
2. 为绕开，登记了 `local: http://127.0.0.1:7777`。任务被当成远程机。
3. `agentd.log` 约每 20–30 秒：`镜像订阅断线 machine=local failed to read frame header: EOF`。`machine=` 是**任务镜像**（Web 控制台那条，发现间隔 30s）的日志键，不是账本镜像的 `target=`。
4. 卡流停在 `dispatched`，任务流继续走。15:12:23 一张 vitest 权限门与一次 EOF 同一毫秒。
5. 自动批的门是 `approver_decision`，卡 wait / 账本镜像本来就会 skip——**这不是本卡要修的「收不到权限门」**；标题里的权限门有一部分是预期静默。
6. grok 写完终稿仍可能不发 `completed`（执行器问题，OOS）。镜像自订 EOF 同时让 `waitForTurnEnd` 收不到终态。`resume --force` 只把 `task.state` 推到 `waiting_review` 并打 `progress`，不发 `completed`，节点不会自动过（OOS）。

## 现状读数（`main` @ `d319f92d2`）

身份与拒发：

- `charter-default` 活模板 `target` 为空串，`discipline=charter-must-override`。空是「本机」的本意，今天被当成没填。
- `ViaTemplate`：请求覆盖 > 模板缺省后若仍空，直接 `目标机未定：--target 或模板 target 至少一个`（`internal/ledgerstep/dispatch.go`）。
- `--step` 主路径：CLI `runStepDispatch` 恒拨**本机** agentd（`LocalEndpoint`），`CardStepReq.Target` 只是覆盖项。空 target 202 受理，异步 ViaTemplate 再失败。
- `resolveStepDiscipline`：空 target 跳过纪律解析、返回空产物，把失败留给 ViaTemplate（注释写明不改 202 合约）。
- CLI `targetClient("")`：`未指定目标机（--target 或模板 target 至少一个）`；名字不在 `Targets` 就 `未登记`。没有「本机」别名。
- 配置里可以登记 `local → 127.0.0.1:7777`（本机当前就是这样）。`pool.Names()` 会列出它。

两条镜像：

- **任务镜像** `internal/agentd/mirror.go`：每 30s 对 `pool.Names()` 全部 `ListTasks` + 活跃任务 `MarkForwarded().StreamEventsOnce`。事件 `AppendMirrorEvent` 后 **`hub.Publish` 同一条**。本机任务本来就已经在本机 store/Hub 里。自订等于把本机事件再 Publish 一遍。
- **账本镜像** `internal/ledgermirror`：`AllTaskLinks` 里 `registered[link.Target]` 才订。空 target 的挂账**不会**被订（`""` 不在 Names 里）——所以「只修空 target 放行、不补本机账本源」会让 `card wait` 仍然看不到任务事件。
- 账本镜像 `DefaultSource` 也是 `MarkForwarded().StreamEventsOnce`。`mirrorSkip`：`progress` / `approver_decision` / `approver_disabled`。`permission_request` 会进卡流；自动放行只打 `approver_decision` 时卡流本来就没有门。
- `from_seq` 开区间（不含）。水位来自已落账的 `source_seq`。不得改成闭区间来「补」断线。

自订如何把 WS 掐死（与现场同一毫秒对齐）：

- `/ws/events` 的 `writeLiveBatch`：live 事件 `seq <= lastWrittenSeq` 且大于重放面 → 记「乱序迟到事件，断开连接由客户端凭 cursor 重连补齐」。
- 任务镜像 `onEvent` 把**已经在本机 Hub 里的**事件再 `Publish` 一次。所有订该 task 的 WS（任务镜像自己、账本镜像、节点 `WaitEvent`、人手 `handoff wait`）都会在第一条之后立刻看到重复 seq，被当成乱序迟到掐线。客户端读侧就是 `failed to read frame header: EOF`。
- 权限门事件触发 Publish → 自订再 Publish → 同一毫秒 EOF。重连 `from_seq` 开区间会跳过已交付的那条；若掐线发生在账本镜像 `onEvent` 落库之前，卡流就缺那条。EOF 日志来自任务镜像 `subscribe` 的断线分支，节奏跟**事件到达**有关，不是每 30s 一次。`mirrorDiscoveryTick=30s` 只解释发现循环。
- `http.Server.ReadTimeout=30s` **不是**这条 EOF 的因：同文件注释写明 Hijack 会清 deadline，Go 1.26 实测 WS 不受该值约束。

节点等待：

- `awaitNode` → `pool.For(target)` → `WaitEvent`。空 target 取不到客户端。自机名字则走 loopback WS，被上面的二次 Publish 一起掐。
- `waitForTurnEnd` 认非空 `final_text` 的 `completed` 或失败终态；权限门/工单循环跳过。它等的是**任务** WS，不是卡流。

`LinkTask` / `WorkBranch`：target 是字符串。空串已有测试用法（`cmd/status_test.go`）。跨机门现网不是「字符串不等即拒」，而是析取（`internal/ledgerstep/dispatch.go:159`）：

```
hasWorkBranch && (workInfo.Target == "" || workInfo.Target != target)
```

上次目标机为空**无条件拒**，包括两边都是 `""`。这是 B192 §2.1.3 冻结的：「历史快照 `Target == ""` 时不能证明同机」。ViaTemplate 今天在空 target 处先失败，成功快照通常是登记名，所以这条短路很少被本机主路径打到。本卡一旦把新快照归一成 `""`，连续两次不带 `--target` 就是 `""` vs `""`，不改这条门则故事 3 主路径永拒。

`ModelByTarget[target]`（同文件约 233 行）在 target 归一成空串后改查 `""` 键；几乎无生产键，plan 顺手点一句，不另开缝。

自机判定现状：没有 `isSelf`。`ClassifyListen` / `localDialAddr` 只服务 CLI 拨号与辅助监听，不判断「某个 target 是不是本进程」。

## 方案

推荐：**本机身份收口 + 两条镜像不订自机 + 账本本机源。**

### 1. 空 target = 本机，合法

`ViaTemplate` 在请求覆盖 > 模板缺省之后，**空串表示本机**，继续派发，不再报「目标机未定」。

挂账、快照、WorkBranch 写入的 target：经自机判定后归一成空串。登记名 `local` 只要指向本进程，写下去也是 `""`，不要把配置键当身份。

`--target 本机` 仍是未登记名，继续拒，文案保持「未登记」。不设魔法别名。

`charter-default` 的空 target **保持空**。不要把模板改成 `local`。

### 2. 自机判定：一份纯函数，relay 永不自机

输入：本进程 `listen`、一条 `config.Target`。  
输出：是否就是本进程。

- relay 形态（有 `relay`/`node`、无直连 addr）→ 否。
- 直连 `Addr` **先去 scheme**（生产形态是 `http://127.0.0.1:7777`，`Listen` 一般无 scheme）。去完之后的 host:port 等于 `listen` 本身，或等于 `ClassifyListen(listen)` 的 loopback 变体（同样去 scheme），或 host 是 loopback/`localhost` 且端口与 `listen` 相同 → 是。
- `ClassifyListen` 对带 `http://` 的字符串会 `SplitHostPort` 失败并原样返回——判定函数不得把带 scheme 的 Addr 直接丢给它。
- 只比地址，不比 token、不比登记名。

CLI 的空 target 走 `LocalEndpoint`（已有），不必先登记。两条镜像的「要不要 WS 订它」必须调用同一份判定，禁止各抄一份字符串比法。

### 3. 任务镜像：自机从发现清单拿掉

任务镜像的职责是「让浏览器只连本机也能看见**远端**任务」。本机任务已经在本机 store 与 Hub。订自机没有收益，二次 `hub.Publish` 会把该 task 上所有 WS 掐死。

`pool.Names()` 仍可列出 `local`（升级、探活、控制台机器列表要用）。任务镜像的发现/订阅/快照门铃**跳过自机**。本地任务不得再写入 `mirror_tasks` 当成远端副本。

### 4. 账本镜像：自机/空 target 走本机源，不走 WS

卡流要看见本机挂账任务的事件。空 target 今天根本不会被订，只放行派发不够。

本机源（组装点注入，测试可换）：

- 从本机任务 store 按 `from_seq` 开区间重放。
- live：用 store 落库门铃（可与现有 frames 钩子串联，**只通知、不写账本**），再按水位从 store 读。过滤仍用 `mirrorSkip`。只 `AppendMirroredEvent`。
- **禁止 `Hub.Subscribe`**。Hub 的 `Watchers` 被钉成「有几个协调者在听」（B56，`hub.go` 注释：全仓 Subscribe 只有 `/ws/events`）。内部订进去会让本机卡任务恒 ≥ 1，无人值守漏报。也禁止为这张卡改 Watchers 语义或加一条「内部订」。
- **禁止再 `hub.Publish`**。
- **禁止**对空/自机 `machines.For` 或 `DefaultSource`。reconcile 在 For 之前分流：空串或自机 → 本机源且 `c == nil` 合法；远端才 For + WS。按现签名「先 For 再 Source」会要么对 `""` continue，要么对 `local` 再订 loopback WS。

`registered[link.Target]` 对空串不得 `continue` 丢掉。自机登记名归一成 `""` 后走同一条本机源；防御：旧挂账仍写着 `local` 时，判定为自机也走本机源、不走 WS。

远端登记名行为不变：WS `DefaultSource`。

### 5. 节点派发与等待的本机客户端

- `stepTransport` / CLI `cliTransport`：target 为空或自机 → 本机客户端（`LocalEndpoint` / 同等本机拨号），不要 `pool.For("local")` 当远端。建任务可以是本机 HTTP 短请求（B268 已证明能建出 task）；禁止的是长订阅把自己当远端。
- `resolveStepDiscipline`：空/自机不再跳过。对本机 `Status` 探能力位，走与远端相同的拒发闸。本机 agentd 就是收件方，探活失败才是真失败。
- `awaitNode` / `diffNode`：空/自机用同一个本机客户端。`WaitEvent` 继续走本机 `/ws/events`（与无 `--target` 的 `handoff wait` 同路）。任务镜像不再自订之后，这条 WS 不再被二次 Publish 掐断，不需要为节点等待再造一套进程内 WaitEvent。

### 6. WorkBranch 同一机（废止 B192 空串短路）

比较谓词改成自机等价，**去掉** `workInfo.Target == ""` 短路：

- `""`、以及判定为自机的登记名（旧绕开的 `local`）视为同一本地身份。`""` vs `""` 放行，Transport 被调用。
- 一边自机、一边真远端 → 仍走今天跨机拒发原文（含「先 push + 显式 `--base`」）。

这是对 B192 §2.1.3 / 矩阵「目标机信息缺失」行的**显式废止**（回写见 `2026-08-23-b192-contract.md` 文首修订）。新语义：空串 = 本机，不再表示「不能证明同机」。

历史缺字段快照（JSON 缺 `target` 解成 `""`）同样视作本机。B192 之后 ViaTemplate 成功路径不会写空 target，窗口窄。残留风险：上一跳其实在远端、快照却没记 target 时，本机会试图续接本地工作分支——`LocalBaseBranch` 在本地找不到该分支仍拒发（`ErrBadWorkspaceReq`），**不会**静默改用卡基线（B192 规则二仍在）。不新增快照字段来区分「缺」与「本机」。

## 用户故事

1. 协调者在本机跑 `handoff card dispatch B271 --step plan --executor grok`，**不带** `--target`。派发成功。挂账 `target` 为空。`card wait` 能收到 `permission_request`（未自动批时）和带正文的 `completed`/`turn_failed`。
2. 配置里即使仍留着 `local: http://127.0.0.1:7777`，`--target local` 也被当成本机：不出现 `machine=local` 的镜像自订，不把本机任务写入远端镜像表。
3. 下一节点仍不带 `--target`（或仍写 `--target local`）：`""` vs `""` 与 `local` vs `""` 都不报跨机。不出现「上次目标机 `""`，本次目标机 `""`」。
4. `--target linux-01` 行为与今天相同：WS 镜像、跨机 WorkBranch 拒发原文仍在。
5. `--target 本机` 仍报未登记。
6. 自动放行的权限仍只打 `approver_decision`，`card wait` 仍不醒——与今天一致，文档/skill 写明。

## 实现决定

- 空模板 / 空 `--target` = 本机。产品名是空串，不是 `local`、不是 `本机`。废止 B192「空 = 不能证明同机」。
- 自机判定纯函数：Addr 去 scheme 再比；relay 永不自机；两处镜像与 WorkBranch 共用。
- 任务镜像发现跳过自机；账本镜像对自机/空 target 用本机源（store 重放 + 落库门铃，不订 Hub，不 For，不回 Publish）。
- 节点运输与等待：`stepTransport` / `awaitNode` / `diffNode` / `resolveStepDiscipline` / CLI `targetClient` 空/自机都走本机客户端，禁止 `pool.For("")` 与 `pool.For("local")`。纪律探活不再因空 target 跳过。
- 仓内 `skills/handoff/SKILL.md` 加一句：本机卡派发不要 `--target`，不要在 `targets` 里登记 loopback 把自己当远端。`--target 本机` 不是合法键。不要复用「目标机未定」（那句是 CLI/agentd 版本 skew）。不改仓外 product-backlog skill。
- 不改 `from_seq` 开区间，不改 `mirrorSkip`，不改 `resume --force` 事件类型，不改 `Watchers` 语义。

## 测试决定

接缝清单（符号 + 调用方）。假缝禁令：不为自机判定单独导出「只给测试用的」无生产调用方函数当缝；纯函数可以是内部锁，缝是它的生产调用方。

1. **`Dispatcher.ViaTemplate` ← `StepRunner.dispatchNode` / 裸模板派发**  
   - 模板 target 空、请求 target 空 → 派发成功，快照/挂账 `target=""`。  
   - 不再返回「目标机未定」。  
   - 模板空、请求 `linux-01` → 仍是远端。

2. **自机判定 ← 任务镜像发现 + 账本镜像 reconcile + WorkBranch 跨机门**  
   - listen 无 scheme（如 `100.x:7777` 或 `127.0.0.1:7777`），target `addr=http://127.0.0.1:<port>` → 自机（B268 生产形态，必须锁）。  
   - `localhost:<port>`、通配 listen 的 loopback 变体 → 自机。  
   - target addr 去 scheme 后等于 listen 本身 → 自机。  
   - relay target → 非自机。  
   - `linux-01` 直连其它 IP → 非自机。  
   三条调用方各至少一支：发现不订自机；账本对自机挂账走本机源且 **不得** `For` / `DefaultSource`（打在分流上，不能只 mock Source 计数）；WorkBranch：`local` vs `""` **以及 `""` vs `""`** 不拒，Transport 被调用。

3. **账本本机源 ← `Mirror.subscribe`（账本）**  
   - 本机 store 追加 `permission_request`（seq=N）→ 卡上出现对应 `task_mirrored`，`source_seq=N`。  
   - 同 seq 再来一次 → 幂等，不双写。  
   - `approver_decision` → 卡上没有。  
   - 本机源路径上 **没有** `Hub.Subscribe`、**没有** `hub.Publish`。无真实 WS 协调者时该 task 的 `Watchers` 仍为 0。  
   - 连续 >16 条 `progress` 之后一条 `permission_request` 仍要落到卡上（门铃/重放不得被 Hub 16 槽丢弃冒充）。  
   这是卡流可见性的缝，不能只用「镜像跳过自机」的负例冒充。

4. **任务镜像发现 ← `Mirror.discoverOnce`**  
   - Names 含自机登记名时，不对该名 `ListTasks` / 不起 WS 订阅。  
   - 远端名仍订。  
   - 本机已有的本地 task 不会出现在 `mirror_tasks` 里当成该登记名的副本。

5. **本机客户端 ← `stepTransport` / `awaitNode` / `diffNode` / `resolveStepDiscipline` / CLI `targetClient`**  
   - 空 target 对本机探 `Status`，不再因空而返回空产物。  
   - CLI 空 target 拿到本机客户端，不再报「未指定目标机」。  
   - `--step` 主路径：`stepTransport` 空/自机建出 task（不 `pool.For("")`）；`awaitNode` / `diffNode` 用 ViaTemplate 回传的 `""` 能取到客户端。禁止 `pool.For("local")` 当本机。  
   - 未登记名仍报未登记。

6. **回归：二次 Publish 仍会掐 WS（锁住「为什么不能自订」）**  
   - 一条本机 WS 已写出 seq=N 后，再往同一 Hub `Publish` 同一 seq → 连接按今天的乱序迟到断开。  
   这不是新行为，是把 B268 现场收成锁。本卡实现不得为了让自订「能用」而删掉这条断开。远端乱序迟到仍要断开重连。

假缝：不要把 `from_seq` 开闭、不要把 `resume --force`、不要把 grok 是否发 `completed` 做成这张卡的缝。
