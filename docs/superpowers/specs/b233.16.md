## 定级理由

跨子系统：消费点分布在 **d_cli**（`cmd/` 执行命令面）、**d_gateway**（agentd 卡节点装配）、**d_ledger**（`internal/ledgerstep` 卡步编排）三处，提供方是 **d_transport**（`internal/client`，接口已于 B233.3 冻结）。本卡让这三处的生产依赖从聚合 `*client.Client` 收窄为能力接口，并按使用方声明组合面；同时按现实棘轮复核 `codegraph/target.json` 相关边 entries，属动契约层。同进程 Go 类型，不升 HTTP/MQ；单条缝（跨机执行），一轮可收口 → **L3 轻档**。

覆盖入口预判：卡 note 记「L2」。按定稿范围改判 **L3**——判据是跨域 + 动契约图 entries，不是工作量（与 B233.13 / B233.15 同口径）。

## 问题陈述

谁：CLI 协调者执行命令（dispatch / card dispatch / reply / continue / stop / wait）与 agentd 的卡节点装配、ledgerstep 的卡步编排。

条件：跨机执行能力面 `client.ExecutionClient` 已于 B233.3 冻结（`internal/client/execution.go#ExecutionClient`，六方法：Dispatch / Reply / Continue / Stop / WaitEvent / FollowEvents），但**生产零持有**——全仓 Go 只有定义文件里的实现断言与三处测试断言；上述消费点全部持有聚合 `*client.Client`，类型上无法与「本仓其它能力」区分，提供方也无法在不触达消费方的情况下重塑 `internal/client`。

通道：同进程 Go 调用链。不新造 HTTP 路径、事件类型、CLI 命令、依赖方向或传输协议。

要变的事实：

1. **跨机执行消费点的依赖声明是能力接口，不是聚合实现。** 只调执行动作的消费点持 `client.ExecutionClient`；同处也调辅助方法的消费点在**使用方包内**声明最小接口，并把 `client.ExecutionClient` 嵌入其中。
2. **聚合 `*client.Client` 只允许出现在工厂与组装点**：CLI 的目标客户端工厂、agentd 的取客户端总入口、`internal/targetclient`（选路与池）、`main.go` / `server.go` 组装处。工厂返回聚合是实现选择，不属消费依赖。
3. **行为零变化**：HTTP 路径、JSON 键、事件类型、CLI 输出、退出码、错误文案、超时值一律不动；B233.3 / B233.10 / B233.12 / B233.13 的冻结语义一字不改。
4. **契约图按现实棘轮**：`d_cli→d_transport`、`d_gateway→d_transport`、`d_ledger→d_transport` 三条既有边的 entries 按收窄后的真实符号更新（聚合符号退场、能力接口符号在场）。不新开方向、不改预算（除按现实修正 entries）。

谁能观察到：源码里消费点的签名/字段类型；编译期——把类型改回聚合会让最小替身测试**编译失败**；现有测试全绿；`codegraph check` 不新增 fail/warn。

## 范围：什么是「跨机执行消费面」

**在内**：为「一次任务/卡节点执行的完整闭环」跨机取用客户端的生产消费点——发起、回程、续接、探活（派发拒发闸前提）、等待与观察、终止与失败补偿、完成善后（推分支 / 归档 / 产出判定 / 最终报文）。

**不在内**（逐条理由见 Out of Scope）：网关原样搬运（`Transport` 面）；任务事件镜像；PTY / 预览 / 回收 / 项目 / 机器 / 会话 / 升级等非执行能力面；纯查询命令（tasks / show / diff / attach / frames 等「看」而不「执行」的入口）。

## 方案

**按消费点收窄，接口归属分两级。**

- **纯执行点**（只调六方法者）直接持既有 `client.ExecutionClient`——它是 B233.3 冻结在提供方 `internal/client` 的接口，消费方复用它，不另立副本。
- **混合点**（同处还要调 `Status` / `Attach` / `WaitArchived` / `Run` / `StopAndReclaim` / `Diff` / `Done` 者）在**使用方包内**声明自己的最小接口（架构法第九条：接口定义在使用方），并**嵌入 `client.ExecutionClient`** 而非复制其六方法——语义保持单一来源，B233.3 的冻结不被复制成第二份。
- **组合面的额外方法只允许是该消费点今日真实调用的方法**，不为未来预留、不合并「看起来相关」的面（杜绝接口膨胀）。
- **工厂与组装点保留聚合**：CLI 的目标客户端工厂、agentd 的取客户端总入口、`internal/targetclient` 的选路和池，返回 `*client.Client` 是组装合法形态；收窄发生在**消费点**的依赖声明上，不在工厂上。
- **每个消费点必须落在可注入的具名符号上**（函数参数 / 结构字段 / 具名函数），不接受匿名内联调用作为终态——否则最小替身无法替换、接缝无法核验（reply / continue 的 RunE 内联形态按此要求收敛为具名入口）。
- **图按现实棘轮**：三条入传输边的 entries 更新为收窄后的真实符号；不新开方向、不动预算。

**弃选**

- **把辅助方法加进 `ExecutionClient`。** 违反 B233.3 冻结 13（不得含工作区/卡/机器/PTY 方法）与卡 note 明令（「不把工作区/卡/PTY 塞进该接口」）。否。
- **让工厂 / 池返回窄接口。** 同一取用入口服务多种用途（执行、工作区、PTY、探活），单一窄接口装不下；且组装点持具体类型是合法形态，收窄工厂只会把组合接口堆到工厂上。否。
- **只收「纯执行点」**（用户已否）。多数执行命令是混合面（wait 要 Attach/Status、dispatch 要 Status、card dispatch 要 StopAndReclaim），只收纯点等于几乎没收，「生产持有 ExecutionClient」的完成判据不成立。
- **一次收到全消费面**（含 GC / preview / PTY / 项目 / 机器 / 事件镜像）。超出一条缝，与 B233.17 边界重叠，且事件镜像等面要另立 `StreamEventsOnce` 一类接口，属另一条缝。否。

## 实现决定（决策级落点）

- **收口层**：收窄落在**消费点**的依赖声明——函数参数、结构字段、取用入口的返回面；工厂与组装点（CLI 目标客户端工厂、agentd 取客户端总入口、`internal/targetclient`、`main.go`/`server.go` 装配）保留聚合实现。
- **依赖方向**：消费方 → 提供方不变（三条既有入传输边）；本卡不新开边、不搬包、不改预算。
- **接口位置**：执行能力接口沿用提供方冻结物；组合接口由使用方包声明并嵌入前者。
- **可测性形态**：消费点收敛为具名可注入符号（含把内联 RunE 收敛成具名入口），使最小替身可替换。
- **不写死的**：组合接口的精确命名、方法集、签名与所在文件；具名入口的精确签名；图 entries 的逐字新值——全部交 contract 冻结，本轮只定语义与边界。

## 用户故事

1. 协调者跑 `dispatch` / `card dispatch` / `reply` / `continue` / `stop` / `wait` / `wait --until-done` / `wait --follow`：stdout、退出码、HTTP 路径与今日逐字一致；收窄只发生在类型层。
2. 上述命令与 agentd 卡节点装配、ledgerstep 卡步编排的源文件里，消费点的依赖声明是能力接口；把任一消费点的依赖改回聚合 `*client.Client`，对应测试**编译失败**。
3. 用只实现该消费点所需方法的最小替身替换跨机客户端，相关用例仍能跑通——替身不需要实现 `HTTPClient`、工作区、卡或 PTY 的任何方法。
4. `card dispatch` 与 `card step` 的生命周期行为不变：探活拒发、失败补偿释放、pass 后推分支、终态归档，B229 / B233.10 / B233.13 的既有验收点全绿。
5. 契约图上三条入传输边的 entries 与源码事实一致（聚合符号退场、能力接口在场），`codegraph check` 不新增 fail/warn。

## 契约语义与接缝（L3）

**本卡定的语义（设计决定）**

1. 执行能力的接口归属不变：`client.ExecutionClient` 住在提供方 `internal/client`（B233.3 冻结 11）；消费方只复用，不复制、不改名、不改方法集。
2. 组合面由**使用方**声明并嵌入 `client.ExecutionClient`；额外方法以消费点今日真实调用为上限。
3. 依赖方向不变：仍为 d_cli / d_gateway / d_ledger → d_transport；不新增 `d_transport → *` 边，不把卡账本写入经传输。
4. 组装点持有具体实现合法；收窄是**消费依赖**的收窄，不是实现或构造面的收窄。
5. 失败诊断语义不变：`ErrUnreachable` 与 `ErrTunnelDisconnected` 的区分沿 B233.3 现状，不由本卡扩大。

**不由本卡定（contract 节点冻结）**：组合接口的精确命名、方法集与签名、落在哪个文件；`cmd` 内联 RunE 收敛后的具名入口签名；图 entries 的逐字新值。

## 测试决定（接缝清单与断言）

- **T1 编译期签名锁**：对每个收窄到具名符号的消费点，用「签名赋值断言」把参数类型钉住（`var _ func(…, client.ExecutionClient, …) error = <符号>` 形态）。类型改回聚合即编译失败——这是本卡「有牙」的主形态，不依赖字符串扫描。
- **T2 最小替身注入**：每个消费点配一个测试替身，**只实现该消费点所需的方法**，替换跨机客户端后跑通现有用例（CLI 走命令入口、agentd 走装配点、ledgerstep 走 `StepRunner` 字段）。替身不含 `HTTPClient`、工作区、卡、PTY 方法。
- **T3 机械守卫（沿用既有形态）**：扩展现有 `cmd/execution_surface_test.go` 的源码守卫，把「执行面文件不得持聚合依赖」纳入扫描（白名单只许工厂所在符号）。扫描是补充，不替代 T1/T2。
- **T4 行为不变**：`go test ./...` 全绿；现有 B229 / B233.10 / B233.12 / B233.13 定向用例逐条复跑。
- **T5 契约图**：`codegraph check` 不新增 fail/warn；三条入传输边 entries 与源码符号一致（图对账节点核）。
- 真机项：本卡为编译期类型收窄，无 wire 与行为变化，不新增真机清单；跨机执行的既有真机残余仍按 roadmap 登记。

变异检验（验收轮）：任取一个消费点把依赖改回 `*client.Client`，T1 或 T2 必须变红。

## Out of Scope

**本期不做、后续要做**

- 网关原样搬运（`Transport` / `HTTPClient`）保持不动——B233.3 冻结明许，属网关例外。
- 任务事件镜像（`internal/ledgermirror` 的 `Machines.For` / `Source`）与其它非执行能力面（PTY、预览、回收、项目、机器、会话、升级、纯查询命令）的消费点收窄——非本缝，落 `docs/roadmap.md`。
- `internal/` 按最优图物理重排、`internal/<子系统>/internal/` 编译期封界、handler 退出 assembly、预算棘轮 → **B233.17**。
- 编制入站门面与接收机自证、空 HOME 带纪律 → **B233.14**。
- 真机跨机执行验收（本卡无行为变化，不重复真机）；B233.12 残余的真机 OpenCode 会话（已在 roadmap）。
