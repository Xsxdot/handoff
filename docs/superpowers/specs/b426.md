- **级别与档位**：**L2**。单子系统（web 前端为主 + Android 壳一处清单配置，壳侧无协议逻辑、不构成跨子系统契约面）、不动契约（零 wire 变化、零新端点，全部消费既有 `/api` 投影）。定级两问逐条见 §7。

## 1. 问题陈述

用户真机走查移动端（compact 视口，Android 壳 WebView）报 7 个问题，根因排查已全部钉死（读数出处见台账）：

1. **会话筛选占两行且「全部」chip 无意义**：compact 会话页筛选写死两段式——「⚑需要你+全部+计数」chips 行 + 独立项目筛选行。「全部」chip 的点击就是「把需要你翻转回去」。
2. **项目列表页与原型不一致**：compact 项目 tab 直接渲染桌面 ProjectTree（⌘K 搜索框、树轨、worktree 计数、「流程与代码图暂未适配移动端」页脚），原型形态（`prototypes/mobile-app/pages/mobile-projects.html`：应用头 + 项目卡流）从未实现。
3. **卡状态 chip 只有待办有内容**：chip 迭代五锚点字面量（`statusVocab.ts`）做 `card.status` 严格等值过滤，但真实卡状态是工作流自定义状态名。实测 18 张卡：待办7/acceptance6/finish3/spec2——四个 chip **恒空**。桌面 header 的同组 chips 同 bug（同一处过滤逻辑），本卡双端同修。
4. **加载缓慢**：实测拆账 = 服务端 `listCards` 7 条顺序查询 × 远端 Postgres 22ms RTT ≈150ms + 前端 6 端点扇出与 2.5s 轮询 + 手机经 relay 的 RTT；relay 隧道本身常驻复用、非每请求握手（**已拆出 B427，本卡不动性能**）。
5. **卡页头部形态丑**：compact 头部三行常驻，行 3 两个下拉+搜索全挂 44px 高度；「排队中」是带边框大盒。原型 mobile-cards 移动端没有这些。
6. **会话房间头部冗余**：compact+detail 实叠四层（返回条/组标签条/窗格标题行/群聊详情切换行）；窗格标题行的 ⋯ 调桌面抽屉开启器，compact 下抽屉不渲染=点击无反应；× 关组落点不明。
7. **键盘遮挡输入框**：Android 壳 WebviewActivity 未设 `windowSoftInputMode="adjustResize"`，web viewport meta 无 `interactive-widget=resizes-content`——键盘弹出布局视口不缩，聊天 composer 与新建会话弹层输入框被盖。

## 2. 方案（逐项）

**S1 会话筛选行**：compact 筛选收成一行——「⚑需要你 N（toggle chip）+ 项目下拉 + N 个会话（右对齐）」。删「全部」chip：点已选中的「需要你」即取消回全部（toggle 语义）。桌面 `!compact` 筛选行零改动。

**S2 项目页对齐原型**：compact 项目 tab 新建移动项目列表（替换桌面 ProjectTree 的 compact 复用），形态按 `mobile-projects.html`：应用头「项目 + ＋添加项目」，下方项目卡流——项目图标（名称前两字符+底色）+ 名称 + ›，第二行位置 chips（机器名 · N 活跃 / 离线），数据从既有 tree 投影（零新端点）。点项目卡 → 既有移动项目详情下钻（保留，含其机器/任务/文件入口）；＋添加项目 → 既有添加项目向导。桌面 ProjectTree 零改动。

**S3 状态 chip 以看板五列为准**（用户裁决）：chip 标签与过滤语义改为**看板五列**（charter 流：代办/沟通中/进行中/审核中/结束），过滤复用既有看板列归桶机制（每卡按其工作流 board 布局归列，未加载/未知流走默认兜底「进行中」——与桌面看板同口径同机制）。点已选 chip 取消回全部。「代办」错字在账本工作流定义内，本卡不改词表、chip 标签与桌面看板列名逐字一致。桌面 header 同组 chips 一并切换（同一 bug 同一修；这是「桌面零改动」承诺的唯一例外，见 §8）。

**S4 卡页头部收敛**（用户裁决：次级筛选按原型收进详情）：compact 头部从三行收敛——行 1 保留（工作项 + 健康指示 + ⚑需要你 + ＋新建）；行 2 保留（S3 五列 chips）；**行 3 撤出主面**：项目/工作流筛选与搜索移到卡详情抽屉顶部（compact 抽屉顶部加筛选区，作用于背后列表，关闭后筛选保留）；「排队中」从大边框盒收成**细横条**（单行高、可展开既有队列列表，展开行为不变）。

**S5 会话房间头部收敛**（用户裁决的形态）：compact 下钻到**会话房间**时，只留一条 header——「‹返回（出房间回会话列表）+ 房间标题 + ⋯更多（右侧）」。组标签条与窗格标题行对会话房间不再渲染；SessionTab 的「群聊|详情」切换行删除。⋯更多 → 进详情态（paneDetail）；详情态左上角返回 → 回群聊；详情态 header 不渲染 ⋯。非会话 tab（终端/任务下钻）的既有 chrome 不动。已知代价（用户裁决接受）：房间内不再有多 tab 切换条，要切别的 tab 先返回出房间。

**S6 键盘遮挡**：两层各补一处——web viewport meta 加 `interactive-widget=resizes-content`；Android 壳 WebviewActivity 加 `android:windowSoftInputMode="adjustResize"`。生效后聊天 composer 与新建会话弹层随窗口收缩上浮。iOS 壳不加代码，真机走查时观察（WKWebView 对聚焦输入有原生上浮行为），不够再立卡。

## 3. 弃选与理由

- **动态实际状态 chips**（chips 随数据生成 spec/acceptance/…）：最诚实零映射，但 chip 集随数据漂移、与原型固定词表相左——用户裁决以桌面看板五列为准，弃。
- **性能优化并入本轮**：用户裁决不动，拆 B427（实测账与优化方向已在 B426 卡 note 与 B427 待接）。
- **次级筛选折叠成小入口**（漏斗图标展开）：保留能力但主面仍多控件，用户裁决按原型收干净，弃。
- **房间头部保留 TabBar 供多 tab 切换**：与用户「这些都删掉」的裁决相左；切 tab 改为出房间再进，代价已在 S5 记明，弃。

## 5. 实现决定（决策级）

- 全部改动收口在 compact 分支；**唯一双端例外是 S3 的 chip 组**（§2/§8）。
- S2 的新列表挂 tree 域（与 MobileProjectDetail 同域），Shell compact 项目 tab 的挂载点换成它；ProjectTree 不感知 compact（可移除其 compact 特判——由 plan 依实际引用裁定，不强制）。
- S3 归桶机制复用 cards 域既有看板布局解析（`columns.ts` 的归列函数族），不新增第二套映射；chips 集合随当前工作流筛选取列序（与桌面看板 displayedColumns 同源）。
- S5 的房间 chrome 判据 = compact && detail && 焦点 tab 为会话；shell 层裁剪 TabBar/窗格标题行的渲染条件，SessionTab 内删除两态 tablist、详情态自带头部返回。
- S6 只动 manifest 一行 + meta 一处；不引入 visualViewport JS 兜底（不够再立卡）。

## 6. 测试决定（真实入口与风险）

- 入口 = web vitest 组件测试（既有 1709 测的延长线）：每故事至少一条可失败断言（S3 必含「工作流状态卡归入语义桶」与「未知流兜底」两条；S1 必含「点已选需要你取消」）。
- Android manifest 与 viewport meta 无单测接缝——属真机行为，S6 证据只能来自用户设备走查（spec §4 S6 验收依据），实现轮以「配置逐字核对 + web 测试全绿」交阶段证据，最终验收补真机。
- 风险位：S3 双端 chips 改动波及桌面 header 快照型断言（若有）；S5 动 shell 渲染条件，注意终端/任务下钻回归。

## 7. 定级两问

1. **跨几个子系统契约面？** web 前端单域 + Android 壳一处清单配置（无协议逻辑，回环门禁语义不变）；无跨子系统契约面。
2. **动不动契约层？** 零 wire 变化、零新端点、零壳绑定面变化（`bind/` 导出面不动）→ 不动。

→ **L2**：plan → implement → review → acceptance → finish。
