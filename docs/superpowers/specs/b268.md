## 问题陈述

桌面端工作台 PTY 在 B267 之后，竖直滚轮按真坐标连发 SGR，Grok/OpenCode 能用。对照原生终端（Terminal.app / iTerm）还差两类体感：

1. **键盘**不像 macOS 终端：Option 不当 Meta；⌘←/⌘→ 被 xterm 丢掉；终端有焦点时 ⌘K 被左栏搜索抢走。
2. **鼠标**仍在网页层手写 `ESC[<64/65;col;rowM>`：编码写死 SGR 1006、坐标按宿主盒子均分、丢掉横滑和修饰键、Shift/Option 划词被自定义 wheel 吃掉。

谁：在工作台终端里跑 shell 或 TUI 的人。  
通道：xterm.js 的按键与滚轮 →（仅用户动作）经 WebSocket 进 PTY。  
要变的事实：按键与滚轮报告的语义跟原生终端同一条协议，不再被工作台捷径或自造序列改写。

## 方案

**推荐（已按对话冻结）**

键盘走 xterm 选项 + 现有唯一的 `attachCustomKeyEventHandler` 槽位（现状：`web/src/app/workbench/terminalInput.ts#installTerminalInputFix` 独占该槽，见该文件头。新键必须在这里转发，禁止再挂一个处理器）。

| 按键 | 行为 |
|---|---|
| Option+字母 | Meta：发出 `ESC`+字母（`macOptionIsMeta: true`） |
| ⌘← / ⌘→ | 行首 / 行尾：上送 `0x01` / `0x05`（iTerm 缺省，readline/zsh 认识） |
| ⌘K 且焦点在该终端 | **本地清屏**：清掉 xterm 可见画面和 scrollback，**一个字节都不写 PTY** |
| ⌘K 且焦点不在终端 | 左栏搜索，维持现状 |

鼠标：自定义 wheel **只补 xterm 丢掉的格数**，报告本身由 xterm 的坐标与编码产生（格子相对 `.xterm-screen` / 渲染器 cell 尺寸；按钮码带 Shift/Alt/Ctrl；横滑走滚轮 LEFT/RIGHT → SGR 66/67）。应用要了 X10 / 像素鼠标就按那种编码，禁止再写死 1006。Option+拖（`macOptionClickForcesSelection: true`）或非 Mac 上的 Shift+滚轮用于划词时，自定义 handler 放行，不拦截。

**弃选**

- 把滚轮再翻译成方向键：B267 已证 OpenCode 当输入历史。
- 继续手写死 `ESC[<64/65;…M`：假坐标花过整屏；写死编码在 1016 像素模式下会再偏一次。
- ⌘K 写成 `Ctrl+L` / 换页符上送 PTY：TUI 会当成输入，与方向键那次同类。
- 终端内 ⌘K 只「不抢搜索」、按下无效果：用户已选清屏。

## 用户故事

1. 在 zsh 提示符下按 Option+B / Option+F，光标按词跳转，不打出 `∫`/`ƒ`。
2. 在一行命令里按 ⌘← / ⌘→，光标到行首 / 行尾。
3. 焦点在终端时按 ⌘K，画面和回滚被清掉，提示符还在（PTY 里的进程不知情）；焦点在别处时 ⌘K 仍聚焦左栏搜索。
4. 在 OpenCode/Grok 的 alt-screen 里：竖直滚轮仍按指针格子翻对话；触控板横滑按横滑处理；按住 Option 拖能划词复制；不把整屏划走。

## 实现决定

- 清屏是仿真器本地动作，**禁止**因此往 PTY 写任何 CSI/C0。Alt-screen 里同样如此：TUI 可能要等自己下一次重绘才恢复画面——这是 Terminal.app Cmd+K 在 vim 里的同类表现，不另做「TUI 里禁用」。
- `0x01` / `0x05` 经 `term.input` 走现有 `onData`，与手敲合流；设备回包过滤器不得把它们当回包丢掉（它们不是 ESC 开头）。
- 工作台其它 ⌘ 键不动：⌘D 分屏、⌘T 新终端、⌘S 保存文件。Ctrl+K（删到行尾）xterm 已处理并 `stopPropagation`，不改。
- 滚轮 32 格上限保持；本卡不为「再快一点」抬上限。
- 不改 Go/PTY 宿主、不改 `TERM`、不改环形缓冲。

## 测试决定（接缝）

1. **`installTerminalInputFix`（`web/src/app/workbench/terminalInput.ts`）← `TerminalTab`**  
   ⌘←/⌘→ 经 `term.input` 发出 `0x01`/`0x05`；⌘K 调用清屏且 `onData` 无字节。现状生产调用，不是假缝。
2. **`ProjectTree` 的 window `keydown`（`web/src/app/tree/ProjectTree.tsx`）← 浏览器**  
   焦点在 xterm textarea 时 ⌘K 不聚焦搜索；焦点在别处时仍聚焦。现状生产监听。
3. **滚轮折算（现状 `altBufferWheelSgr`，图未覆盖）← `TerminalTab`**  
   同坐标连发；按钮码含修饰；横滑为 66/67；强制划词时不生成报告。调用方仍是 `TerminalTab` 的 `attachCustomWheelEventHandler`。

变异：把 ⌘K 改成 `term.input('\x0c')`，缝 1「onData 无字节」必须转红。
