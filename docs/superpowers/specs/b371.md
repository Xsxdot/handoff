# B371 build-deploy.sh 自检被打断：无 VCS 自动戳时 grep 返回 1 终止脚本

状态：**已批准**（2026-09-14，用户原话「2你做掉吧」）  
定级：**L1**（plan 增量为零 + 验收一眼可核）　路由：implement → review → finish（快道）  
卡：B371　日期：2026-09-14  
来源：B370 止血换版时实测（`docs/superpowers/ledgers/2026-09-14-b370-spec-ledger.md` 第 10 行）

## 问题陈述

谁：构建者——任何人跑 `scripts/build-deploy.sh` 出部署二进制（换版执行机时必跑）。

条件：`go version -m <产物>` 不输出 `vcs.revision` 行的环境。本机 worktree 构建实测就是这种：`go version -m /tmp/handoff-mac02` 只回 `go`/`path`/`build` 三类行，没有 `vcs.*`。

要变的事实：脚本取自动戳那一行是命令替换里的三段管道

```sh
AUTO_REV="$(go version -m "$OUT" 2>/dev/null | grep -o 'vcs\.revision=[0-9a-f]*' | cut -d= -f2)"
```

`grep` 无命中返回 1，`set -euo pipefail`（脚本第 27 行）下命令替换赋值直接终止脚本。实测：产物已产出、版本注入自检已过，脚本却在「前端产物嵌入自检」与收尾 `OK：` 之前 exit 1——构建者会误判失败（2026-09-14 换版 mac-02 时踩到，手工复核两门自检才确认产物可用）。

## 方案

把「取自动戳」这一步对「无命中」容错：无命中即视为自动戳缺失，走脚本既有的提示分支（第 106–108 行的 `if [ -n "$AUTO_REV" ]`），不终止脚本。

弃选：

- **删掉这段自检**：它防的是「自动戳指向主工作树」的版本漂移（脚本第 11–21 行写了为什么需要它）。
- **整段 `set +o pipefail`**：面过大，会让该段其它失败一并静默。

## 用户故事

1. 作为构建者：在无 `vcs.revision` 的环境里跑 `scripts/build-deploy.sh`，脚本跑完全程、打印 `OK：<产物>`，退出码 0；产物与版本戳和今天手工复核过的那份一致。

## 实现决定

- 改动限于 `scripts/build-deploy.sh` 取自动戳那一处；不动版本注入的四个 `-X` 字段，不动两门自检的判据，不动 `set -euo pipefail` 本身。
- 无命中时的行为与「自动戳存在且等于注入值」不可区分——两者都只跳过提示行。

## 计划（三行，spec 即 plan）

1. 改 `scripts/build-deploy.sh` 取自动戳的命令替换：无命中时按空值处理（对 `grep` 段容错），保持 `set -euo pipefail` 不变。
2. 验收命令：`OUT=/tmp/b371-check scripts/build-deploy.sh darwin/arm64`，断言退出码 0 且打印 `OK：/tmp/b371-check`（其后还有几行部署提醒；本机即为无自动戳环境，天然复现）。
3. 回归：断言版本注入自检仍生效（产物可 `--version` 且 revision 等于当前工作树 HEAD），以及 `go test -tags embedweb ./internal/webui/...` 仍绿。

## 测试决定（接缝清单）

缝：`scripts/build-deploy.sh` 的版本自查段——脚本无导出符号，按边界型例外记：**断言即缝**，调用方是脚本自身（构建者命令行）。断言取「退出码 + 末行 `OK：` + 产物 `--version` 的 revision 等于当前 HEAD」三条，不新增测试框架。
