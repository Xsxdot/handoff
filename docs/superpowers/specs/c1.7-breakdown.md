> 每张卡只给契约、意图、行为验收、入口指针；不写实现步骤。实现者不得因为某条验收尚未在本节点运行，就把它写成已完成。下面的命令与测试名是下游执行提案。

### C1.7-Gateway：主模块升版与同源静态挂载（`d_gateway`, boundary）

#### ①契约引用

- `c1.7-contract.md` §2 依赖与版本契约、§3 Go 静态挂载签名、§6 原子冻结清单 1—15、30。
- `2026-08-24-codegraph-host-mount-spec.md` 的“契约语义与接缝”第 1 条：FS 只给文件系统，宿主在 auth 内自行包 handler。
- 现状入口：`internal/agentd/server.go#Server.Handler`、`internal/agentd/webhandler.go#newSPAHandler`；API 参照为 `internal/agentd/codegraph.go#Server.handleProjectCodegraph` 与 `#Server.handleProjectCodegraphSource`。

#### ②意图与为什么

把 handoff 的静态服务从“只服务自有 webui”扩为“在 auth 内，以专属 `/codegraph/app/` 子路径服务 charter `graph/v0.7.0` 的 `webui.FS()`”，使浏览器得到同源的二期 viewer，同时保留根 SPA 与两条只读 API 的既有行为。主模块必须钉精确 tag，避免本机缓存或 `replace` 造成消费方与宿主形态不一致。

#### ③验收

**机内可闭环的契约形状（boundary 域只验这些）：**

- `GOSUMDB=off GOMODCACHE=<可写缓存> go test ./internal/agentd -run 'Test(Codegraph|Console|DeepLink|ApiMethod)' -count=1` 返回退出码 0；新增/调整的 route-level 用例至少独立断言：带有效会话的 `/codegraph/app/` 返回 charter index、深路径回退同一 charter index、hashed asset 命中、POST 为 405、未登录不是 HTML、根 `/` 仍是 handoff index。
- `GOSUMDB=off GOMODCACHE=<可写缓存> go test ./internal/agentd -run 'TestCodegraphRoute' -count=1` 的响应体比较必须证明 charter index 与 handoff root index 不是同一份；只断言 200 不构成验收。
- `rg -n 'github.com/Xsxdot/charter/graph v0\.7\.0|charterwebui|StripPrefix\("/codegraph/app"' go.mod go.sum internal/agentd/server.go` 能找到冻结坐标/别名/前缀；`rg -n 'replace .*charter/graph' go.mod` 无输出；`git diff --exit-code -- internal/agentd/codegraph.go` 退出 0。
- 现有 `go test ./internal/agentd -run 'TestCodegraph' -count=1` 返回 0，且 API 路由方法/路径未被改名或重挂到静态 mux。

**五族与追加设问，结论写入本卡验收：**

- 生命周期 / 状态机中断：静态请求不创建进程、工单或临时目录，因此无资源收尾动作；agentd 重启后 mux/auth 需由新进程重新装配，旧进程的路由不会残留。**重启后的真实浏览器访问、换装期间无在飞任务与无孤儿进程未验证，需真机，归协调者执行。**
- 静默失败 / 误导报错：GET 根、深路径、真实 asset、POST、未登录和根静态树分别有判据；“深路径返回 200”不够，必须比对 charter index，避免返回 handoff index 或登录 HTML。API 响应体零改动；不存在“报成功但没挂 charter”的窗口，前提由 index 内容反向断言锁住。
- 跨平台假设：URL path 由 `StripPrefix` 处理，FS 由 `fs.FS` 处理，不把宿主 OS 文件分隔符拼进 URL；Windows 交叉编译只证明编译形状，auth、webview 与真实路径行为**未验证，需真机**。
- 假红 / 假绿测试：直接测 `newSPAHandler` 不能证明 mux 注册和 auth 顺序，所以必须经 `httptest.Server` 全栈请求；必须有 charter-vs-root 的反向断言与 POST/未登录负向断言。静态只读请求的并发稳定性未由本卡负载测试证明，**需真机/协调者压测清单**；测试锁的是调用方依赖的 route 行为，不锁内部 helper 实现。
- 门禁绕过：专属 handler 必须位于 `root.Handle("/", s.auth(mux))` 内，未登录请求先得到 auth 响应；不加 CORS、第二 listener 或 token 旁路。Go mux 注册顺序、auth 包裹关系和未登录响应共同锁住检查与动作之间的路径窗口；并发权限语义**未验证，需真机**。
- 序列化边界：本卡没有新增 JSON/DTO/CLI 字段；两条既有 API 的手写响应/转发在 `internal/agentd/codegraph.go`、`internal/agentd/forward.go` 只作负向参照，不修改、不新增 roundtrip 测试。若实现试图增加 wire 字段，立即退回 contract。
- 枚举新值过既有白名单：无新增状态名、事件类型、kind 或枚举值，因此无白名单登记项；必须在 review 中保留“无，因为本卡只有 URL 前缀和 FS 依赖，不引入枚举”的结论。
- 承重安全属性：未登录不能读取 charter 静态资源是本卡承重安全属性，route-level 未登录测试必须能红；一次性 token/唯一性/隔离不在本卡新增，**无，因为本卡不产生 token、持久资源或跨任务共享状态**。

**边界域行为清单（未验证，需真机，归协调者执行）：**

1. 登录态 GET `/codegraph/app/`、深路径、hashed asset；POST 得 405；未登录得到现有鉴权响应而不是任一 HTML。
2. 根 `/` 与 `/codegraph/app/` 的 index 来源确实不同；浏览器 Network 无第二端口、CORS 或 Authorization 旁路。
3. agentd 换装/重启后重新访问仍命中专属前缀，且无孤儿 agentd/executor/临时目录；执行前确认没有在飞派发。

## 6. 跨卡对抗审查结论

1. **FS 与 iframe 前缀一致性**：Gateway 唯一挂 `/codegraph/app/`；Web 唯一生成 `/codegraph/app/?project=...`。任一方改变字符串都应使跨卡检查失败；不能靠根 SPA fallback 兜底。
2. **auth 与 same-origin 一致性**：Gateway 的 auth 包在 mux 外层，Web 不读取 cookie/token。登录态 cookie 由浏览器自然带入同源 iframe；未登录拒绝必须来自 auth，不由 TS 复制。

4. **外壳两处消费者**：fullPageRoute 不是只修中央 route；Breadcrumb 与 FileTree 两处必须同时用同一个判定，且离开 `/codegraph` 后恢复，反向测试不可省。
5. **版本与 CI 接缝**：root v0.7.0、desktop resolved v0.7.0、desktop tidy clean、Windows/install 后续 gate 全通过才算收口；只看到主模块版本或只看到本地 tidy 不能算 pass。
6. **ledger 与 target 边界**：`ledger.Store` 仍在 `target.json` 的恢复条目中；本刀的任何 target 修改都属于越界，应 fail 并退回协调者。
