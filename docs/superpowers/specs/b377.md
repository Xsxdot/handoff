# B377：permgate：sed 短选项簇 -ne/-nE 应识别为只读静默

状态：已批准（2026-09-18 会话裁决）
级别：L1（单子系统、不动契约；两判据全中——plan 增量为零 + 验收一眼可核）
选档：快道（spec → implement → review → finish；acceptance 列可跳，图对账本轮无代码图视图 diff 不走）

## 问题陈述

`sed -ne '…' f` 与 `sed -n -e '…' f` 是同一个只读形态的两种写法（本机实测输出一致，原文在台账），`sed -nE` 同理。但静默判定用整词匹配找 `-n`，簇写法命中不了；写/执行脚本站又对「含 `e` 的短选项簇」一律否决。结果是写法一换就从零审批掉进 Consult，降噪按形态漏。

谁能观察到：事件流里 `sed -ne '900,1000p' f` 这类命令照旧出工单；期望它与拆开写的形态一样零审批。

## 现状事实（基线 `cards/B376-charter-7` @ `3062a3d8`）

| 事实 | 出处 |
|---|---|
| 静默要求 `-n` 或 `--quiet` 整词命中 | `internal/permgate/permgate.go:466`（`safeCommandID` 的 sed 分支） |
| `hasToken` 整词相等、不做簇展开；另一个调用点是 gofmt `-w` 守卫 | `internal/permgate/permgate.go:789` `hasToken`、`:407` |
| `-i` 守卫已按短选项簇扫字母（`-i.bak`、`-ni.bak` 都拦） | `internal/permgate/permgate.go:804` `hasSedInPlace` |
| 写/执行脚本站已扫 `-e`/`--expression`/`-f` 与脚本里的 `w`/`W`/`e`/`s///e` | `internal/permgate/permgate.go:857` `hasSedWriteOrExec`、`sedScriptWritesOrExecs` |
| 含 `e` 或 `f` 的短选项簇一律否决（未展开，簇内 `-n` 也进不去） | `internal/permgate/permgate.go:891` 起的簇分支 |
| 已知旗标白名单没有 `--silent`（GNU 的 `-n`/`--quiet` 别名），它会被当未知长选项否决 | `internal/permgate/permgate.go:882` 的 case 列表 |
| 真 sed：`sed -ne '1p' f` ≡ `sed -n -e '1p' f`；`sed -en '1p' f` ≡ `sed -e n '1p' f`（`e` 的实参是 `n`，不是 `-n` 旗标） | 本机实测，原文在台账 |

## 方案

把簇识别收敛成一个助手：按 GNU sed 选项表扫短选项簇，遇带参选项字母（`e`/`f`/`l` 必带实参，`i` 可选粘连后缀）即停——其后字符是该选项的实参，不再是旗标；旗标段里出现 `n` 即为静默候选。两处落点：

1. 静默判定把 `hasToken(fields[1:], "-n") || hasToken(fields[1:], "--quiet")` 换成簇感知的 `hasSedQuiet`，并补上 GNU 同义别名 `--silent`（同一个选项的另一个名字；漏了它 `sed --silent 'p' f` 仍出工单，本卡目的只做一半）。
2. `hasSedWriteOrExec` 的簇分支展开：`e` 吃掉簇内其余字符（没有则吃下一词元）当脚本，交给 `sedScriptWritesOrExecs` 扫；`f` 保持否决（脚本来自文件、内容不可见）；其余旗标照旧。

不动的地方：`hasToken` 的全局语义（它是 gofmt `-w` 与 sed 静默判定共用的整词守卫，改它是扩大爆炸半径）；`-i`/`-f` 守卫与脚本站扫描本身。

弃选：只放宽 `-nE` 一类纯旗标簇、`-ne` 继续 Consult——同一个只读形态只因把 `-e` 写进簇里就被卡，正是本卡要修的噪声源，修一半等于没修。

## 用户故事

1. `sed -ne '1,20p' f`、`sed -nE '…' f`、`sed -nsE '…' f`、`sed -ne'1,20p' f`（脚本粘连在簇上）—— **零审批**（`AutoAllow` + `safe-command`）。
2. `sed -n '1,20p' f`、`sed -n -e '1,20p' f`、`sed --quiet '…' f`（现状已静默的形态）—— 不回归。
3. `sed -en '…' f`、`sed -ln '…' f`（簇里那个 `n` 是别的选项的实参）—— **不得静默**。
4. `sed -nf script.sed f`、`sed -ne 'w /tmp/out' f`、`sed -ne 's/a/b/e' f`、`sed -ne 'p' -e 'w /tmp/out' f` —— **不得静默**（写/执行面照旧拦住，与 B376 已锁的反向面一致）。

## 实现决定（即 plan）

- 改 `internal/permgate/permgate.go`：新增 `hasSedQuiet`（簇扫 + `--quiet`/`--silent`），sed 分支改用它；`hasSedWriteOrExec` 的簇分支按「带参字母后即实参、`e` 扫描脚本、`f` 否决」展开；已知旗标 case 列表补 `--silent`。
- 改 `internal/permgate/permgate_test.go`：故事 1–4 的正反表驱动用例。

验收：`go test ./internal/permgate/` 全绿；linux-01 真 sed 复核两条解析假设（`-ne` ≡ `-n -e`、`-en` 的 `e` 实参是 `n`）；反向用例在变异下（删簇扫、删 `f` 否决、删 `e` 脚本扫描）变红。

## 测试决定（接缝清单）

1. **`internal/permgate/permgate.go#Gate.Judge`**（调用方：`internal/approval/client.go#Client.Request` 经 `Hooks.JudgePermission`；生产装配 `cmd/agentd.go` 的 `permgate.New`）。缝级表驱动：故事 1/2 → `AutoAllow` + `RuleSafeCommand`；故事 3/4 → 非 `AutoAllow`。写/执行脚本的反向面（`w`/`W`/`e`/`s///e`）沿用 B376 已有用例，本卡只增簇形态；删掉簇展开或 `f`/`e` 守卫必须变红。

接缝只有一个：静默判定的出口就是 `Gate.Judge` 的裁决。

## Out of Scope

- 不改 `hasToken` 全局语义（gofmt `-w` 守卫不在本卡）
- 不认长选项缩写（`--qui` 之类；GNU getopt 允许无歧义缩写，现状与改后都落 Consult，方向保守）
- 不动 sed 之外的命令类（`rg --pre`、`git branch -M` 等已由 B376 各自收口）
- 不动 `sedScriptWritesOrExecs` 的脚本解析本身（地址族/分号/标志语义已由 B376 复审锁死）
