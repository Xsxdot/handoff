# 批：B198 / B197 / B206

> 职责：把三张互不相干的小卡钉死改法、边界与判据，一次实现一次终审。
> 边界：只覆盖这三条。不抽公共抽象，不顺手清别的死 entry / 别的模板文案。
>
> 状态：**已批准** —— 2026-08-23 用户定「文件夹数量默认藏」，并点名把 B197、B206 合成一批做。

| 卡 | 级别 | 路由 |
|---|---|---|
| B198 | **L2** | plan → implement → review → acceptance → finish |
| B197 | **L1** | bug：待办 → 进行中 → 待审阅 → 已完成 |
| B206 | **L1** | bug：待办 → 进行中 → 待审阅 → 已完成 |

三张不共享落点、实现顺序无依赖。合成一份 spec 的唯一理由：形状相同——「一处偏好 / 一句文案 / 两条哑 JSON」，改动几处，判据能在单测或 `graph check` 里钉死。

## 问题陈述

1. **B198**：左栏项目行、机器行右侧的文件夹数量（`Folders` + 数字）实测没用，要能藏，且新浏览器默认就藏。
2. **B197**：`omit_acceptance=true` 时 prompt 第 2 行变成「（本节点不注入整卡验收判据…）（这是整卡的最终验收判据…）」自相矛盾。功能不受影响，送给模型的是病句。
3. **B206**：`codegraph/target.json` 两条契约的 entries 含 `client.DispatchOpts.local_base_branch`。那是字段路径，check 比对的是容器 label，永远匹配不到任何调用。

## 方案（含弃选）

### B198 采纳：现有显示偏好加一项，默认藏

落点就是已经在用的 `handoff.tree.prefs`（左栏菜单 + 设置 → 常规）。新字段 `hideDirCounts: boolean`，**默认 `true`**。勾上时 `ProjectTree` 不把 `dirs` 传给 `RowCounts`（`dirs` 省略本来就不画文件夹段）。`RowCounts` 自身语义不变：传了 `dirs` 就画，含 0。

弃选：

- **直接删掉文件夹段**：用户说的是可隐藏，不是永久拿掉；运行中 / 待处理仍要。
- **默认显示、想藏再勾**：用户已量过「没什么用」，每个浏览器都再点一次是浪费。
- **bump `v` 到 2**：会把排序和隐藏名单整份丢掉。跟 `hideArchived` 同一招：不 bump，缺字段补默认。

### B197 采纳：只删模板尾括号，发 `charter-default` v3

模板正文第 2 行今天是：

```
验收判据：{{ACCEPT}}（这是整卡的最终验收判据；若与纪律块声明的本节点产出物不一致，以纪律块为准——例如计划类节点的产出是计划文档，不是实现代码）
```

那句尾括号是 B182 的失败缓解，B190/B196/B192/B202 四轮 plan 节点全部照样写实现；真正起作用的是纪律块红线（B200）。删掉它：omit 分支的替换值单独成句，矛盾消失；非 omit 分支也不再跟一句已被证伪的元说明。

模板是不可变版本行，只能 `template put` 追加 v3。`charter-default` **不是** `EnsureDefaultTemplates` 的出厂种子（空账本没有它），所以不走 seed 升级，避免把「生产账本导出」的模板误收成出厂件。

弃选：

- **改 Go 侧 `{{ACCEPT}}` 替换值去调和两句话**：B192 已合，冲突面消失，但仍是在修补一句不该存在的尾巴。
- **新增 `{{ACCEPT_NOTE}}` 占位符**：第二占位符只为删一句而引入，YAGNI。

### B206 采纳：两处不同修法，顺手收窄预算

entries 比对的是容器 label（`check.go#Check`：`label = Containers[callee.Container].Label` 后 `inList`）。`client.DispatchOpts.local_base_branch` 在 baseline 237 个容器里命中 0。承载 `DispatchOpts` 的容器是 `k_client_model`（label `client 实体`）。

| 契约 | 修法 | 为什么 |
|---|---|---|
| `d_cli → d_remote` | **纯删**哑条目 | entries 已含 `client 实体` 与 `client.Client`，CLI 对 `DispatchOpts` 的引用本来就被覆盖。删了对 check 零影响。 |
| `d_controlplane → d_remote` | **纯删**哑条目，不补替换 | 卡上复核原来说换成 `client 实体`，并预期 hits 从 6 降。实现时对 baseline 穷举：该方向 13 条 call 边是 `targetclient.Pool`(7，已在 entries) + `proxycfg（包级函数）`(4) + `targetclient（包级函数）`(2) = 6 条 legacy。**没有一条**落到 `client 实体` 或 `client.Client`。`cardstep.go#stepTransport` 的 `Client.Dispatch` 在源码里存在，但 baseline 里该函数零出边——补任何 client 标签都是新哑条目。hits 仍为 6，预算不动。下次 absorb 扫到这条边再声明入口。 |

弃选：

- **两处都改成 `client 实体`**：`d_cli` 侧已经有，重复条目是噪声。
- **字段级 entries**：当前机制承载不了，另开契约变更，不在本卡。
- **等 B205 合入再动**：用户点名本批做。条目修正不依赖 B205；预算按本批合入时的图收。

## 用户故事

1. 打开控制台，左栏项目行 / 机器行右侧**没有**文件夹图标和数字；运行中、待处理有信号时照常出现。
2. 左栏「显示偏好」和设置 → 常规的「显示」分组都有「隐藏文件夹数量」，默认勾选。取消勾选后文件夹数量出现，再勾上消失。刷新后保持。
3. 旧浏览器里已经存过偏好（没有 `hideDirCounts` 字段）时，排序和隐藏名单保留，文件夹数量按「藏」补上，不整份丢弃。
4. charter 流 `omit_acceptance=true` 的节点（plan 等）prompt 第 2 行只有 omit 说明，不再紧跟「这是整卡的最终验收判据」。
5. `handoff graph check` 的 target.json 不再含 `client.DispatchOpts.local_base_branch`；`d_cli→d_remote` hits 仍为 10；`d_controlplane→d_remote` hits 仍为 6（预算不动）。

## 实现决定

### B198

- `web/src/app/tree/treePrefs.ts`：`TreePrefs.hideDirCounts`；`DEFAULT_PREFS.hideDirCounts = true`；`isPrefs` 允许缺字段；加载时 `hideDirCounts: p.hideDirCounts !== false`（缺省/undefined → 藏；显式 `false` → 显示）。不 bump `v`。
- `TreePrefsMenu.tsx`、`GeneralPage.tsx`：在「隐藏已结束分组」下加一项「隐藏文件夹数量」，极性与另外两个 hide 开关相同（勾 = 藏）。
- `ProjectTree.tsx`：`dirs={prefs.hideDirCounts ? undefined : counts.dirs}`，项目行和机器行都改。目录行本来就不传 `dirs`。
- `RowCounts.tsx` 不改。

### B197

- 从现行 v2 拷一份 def，只删 `{{ACCEPT}}` 后面那对括号及其中全部文字。其余字段（executor/purpose/discipline/verdict 段）原样。
- `handoff template put charter-default --file <v3.json>`：本机账本 + `linux-01` 各一次。本 task 由协调者执行，不派发。
- `internal/ledgerstep/dispatch.go` 的 omit 替换值不改。在替换处补一句「为什么」：模板 `{{ACCEPT}}` 后面不要再跟「这是整卡的最终验收判据」——omit 值已经是完整句（B197）。

### B206

- `codegraph/target.json`：两条契约都删掉哑条目，不补 client 标签，不改 budget。
