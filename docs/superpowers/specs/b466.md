# B466 权限门：cd 子目录后 heredoc 正文被当写落点、glob 落点一律升级

- 状态：r1（bug 入口：implement 排查节 → review → finish；单子系统 `internal/permgate`，spec 即 plan）
- 执行形态：**甲 本地盯**（根因在排查中钉死，修复与反例需逐条裁决安全边界）
- 卡：B466；台账：`docs/superpowers/specs/b466-ledger.md`；分支：`fix/b466-heredoc-cd-targets`

## 偏离与自主决定

1. **卡 note 的前提有一处不成立**：`cd <相对子目录>` 本身一直可证明（`proveCDInBases` 按 Workdir 拼接）；
   拒因「cd 落点不可静态证明」是文案误导——基准已生效、但落点含展开/glob 字符时 `resolve` 返回的是同一句。
   修复把两种拒因分开写（见修复 3），不改 cd 起点逻辑。自行拍板（根因决定修法）。
2. **`node --test` 不在本卡**：它从来不在静态白名单里（无 cd 时同样 Consult），与 cd 落点无关；
   扩白名单是政策变更，另起卡（残余节）。卡 note「已知安全命令在 cd 子目录后仍走静态放行」按
   gofmt / go vet / go test / npm run 四类验证。自行拍板。
3. **「cat heredoc + 后继命令」「python3 - heredoc」仍是 Consult**：前者是闭集不认后继（cd 无关），后者是
   B451 人工清单（内联 Python 可执行任意代码，设计如此）。本卡目标是不再**升级人工**，不扩放行面。自行拍板。
4. **`compoundSilent` 的「cd 后相对参数位写一律不静默」放宽为「cd 链不可信时才拒」**：这条 B376 守卫早于
   B383 的 cd 基准解析；现在 judgeBash 已先把 cd 后的参数位写落点按基准绝对化并判范围，cd 链全 `&&` 时落点
   已被证明。不放宽则 `cd server && gofmt -w x.go` 是 Consult 而 `gofmt -w x.go` 是 AutoAllow——卡 note
   「已知安全命令在 cd 子目录后仍走静态放行」的直接要求。既有用例 `cd src && gofmt -w x.go`（B376 列为不静默）
   改为静默，替换成 `cd src; …` / `cd src || …` / 换行三条不可信链反例。自行拍板（根因同族）。
5. 既有用例 `cat <<'EOF'\necho x > /etc/y\nEOF`（B383 列为 Escalate）改期望为 Consult：cat 无重定向，正文
   打到 stdout，`> /etc/y` 不是写；原 Escalate 正是本卡修的「正文当 shell」误判。自行拍板。
6. 基准生效后的相对落点字符拒绝**新增** `(` `)`：放开 `*` `?` 之后，extglob（`@(..)`）是同族展开形态。
   over-reject，安全侧。自行拍板。
7. 正文剥离的消费者白名单取 `cat` `tee` `python` `python3` `node`（正文不被 shell 解释的消费者）；
   其余消费者（bash/sh/env/sudo/未知命令）正文照旧参与落点解析。自行拍板，取窄。

## 现象

ERP 仓卡 E40.3 的 opencode 任务（9e598686@linux-01，linux-01 bebbb425）：`cd server && python3 - <<'EOF' … EOF`
与 `cd admin && cat > test/x.test.ts <<'EOF' … EOF\nnode --test …` 被权限门判 Escalate，拒因
「cd 落点不可静态证明，其后相对写落点 "{" / "system/cs/internal/app/*.go" 无法解释」。同形但不带 `cd 子目录`
的命令不升级。

## 根因（证据见台账「排查」）

1. **heredoc 正文被当 shell 文本提取写落点**：正文只在 heredoc 闭集（裸 cat、无后继）命中时剥离。闭集不命中
   （python3 消费者、或终止符后有后继命令）时，正文里的 `=> {`、`*p`、`x > 0,` 被 `RedirectTargets` /
   `WriteArgTargets` 当成重定向落点。无 cd 时这些垃圾落点按 Workdir 拼接判范围内（无害）；`cd 子目录` 让基准
   生效后，含 `{` `*` `,` 的相对落点被判不可解释 → Escalate。
2. **cd 基准生效后 glob 落点一律不可解释**：`gofmt -w system/cs/internal/app/*.go` 无 cd 时按字面交 InScope
   （范围内），有 `cd server &&` 时 `*` 进字符拒绝 → Escalate。同一命令有无 cd 结论相反。

## 修复

1. `stripDataHeredocBodies`（heredoc.go）：**只供落点解析**剥离「数据型」heredoc 正文——定界符整词引号包裹、
   消费者命令词朴素且属 `cat/tee/python/python3/node`、所在段不接管道、所在行无括号/反引号/`[[`。
   任何解析不了的形态（未终止正文、半引号定界符、fd 前缀）原样返回整条命令（现状）。注释里的 `<<` 不算
   操作符。黑名单、人工清单、自指令、凭据守卫仍看原文。
2. `cdResolvedTargets`：基准生效后，相对落点允许 `*` `?`，条件是含 glob 的路径分量不以 `.` 开头（`.`/`..`
   只能被以 `.` 开头的模式匹配）；其余展开/转义/花括号/方括号/引号字符仍不可解释。glob 落点另按
   `filepath.Glob` 展开现存匹配，逐个交 InScope（解软链）——匹配项软链指外照样越界升级。
3. `compoundSilent`：cd 后的相对参数位写落点只在 cd 链不可信（`;`、`||`、换行）时拒静默（偏离第 4 条）。
4. 拒因分开：基准破坏仍是「cd 落点不可静态证明，其后相对写落点 %q 无法解释」；基准已生效但落点不可解释
   改为「cd 后相对写落点 %q 含展开、转义或花括号等字符，无法静态解释」。

  `cd 子目录 &&` gofmt/go vet/go test/npm run 静态放行。
