# B345 远端检测允许空 HOME（主 HOME）

- **卡**：B345
- **级别**：**L1**。plan 增量为零：wake 入口不再把空 `home_dir` 当缺参。验收一眼可核：linux-01 空 HOME 载体 detect 不再 400。
- **状态**：**已批准**（2026-09-05；编制改小队真机撞上；用户自主推进）
- **基线**：`origin/main` @ `4f70d755`
- **发现自**：B342 后登记 agy/codex 空 HOME，远程 detect 400。不 reopen B293/B342。

## 问题陈述

设置页写明 HOME 空 = 该机主 HOME。本机 detect 走 `WakeHome`，空路径合法。远程 detect 把 `HomeWakeReq` 转到目标机 `POST /api/host/wake`。`handleHomeWake` 把空 `home_dir` 和缺 `cli` 一起 400「cli 与 home_dir 必填」。2026-09-05 真机：agy@linux-01 `home_dir=""` → 400。workaround 把 HOME 写成 `~`。

现状：`internal/agentd/hostprobe.go` `handleHomeWake`；`WakeHome` 空路径回落主 HOME。

## 方案

`handleHomeWake` 只要求 `cli` 非空。空 `home_dir` 原样交给 `WakeHome`。`handleHomeProbe` 的 path 必填保持不动（探测的是路径，空 path 是另一条语义）。

弃选：远程 detect 在转发前把空 HOME 改写成 `~`（掩盖入口校验与 WakeHome 不一致）。

## 用户故事

1. 作为编制：linux-01 载体 HOME 留空，点检测得到 online 或真实 unreachable，不再 400。
2. 作为对照：`cli` 仍为空则 400。

## 测试决定

缝：`handleHomeWake` ← 远程 detect 转发的 `POST /api/host/wake`。

1. `POST /api/host/wake` body `{"cli":"opencode","home_dir":""}` 不得 400「home_dir 必填」。
2. 同入口 `cli` 空仍 400。
3. 既有远程 detect 非空 HOME 用例仍绿。

## L1 plan

1. `handleHomeWake`：只拦空 `cli`。
2. 测试锁空 `home_dir` 不再 400。

验收：测试绿；变异把空 home_dir 再拦回去则红。本节点该干什么一律以注入的纪律块为准。

## Out of Scope

- **永不做**：空 HOME 在转发层改写成 `~` 冒充。
- **本期不做**：删除载体 API；b334-probe 清理；远端协调者 TUI（B344）。
