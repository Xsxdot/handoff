# B396 spec：陈旧节点运行锁不自愈，卡被锁死无法重派

**上游状态：已批准**（用户 2026-09-22 决定：与 B395 一并优先修）
**级别：L2 单子系统**（节点运行锁：`internal/ledger` 的锁实现 + `cmd`/`agentd` 的判据面）
**入口节点：debug**（先根因后修：锁为什么没释放/没自愈，必须落到 file:line）
**上游证据**：B396 卡上的 409 原文与"机器上无任何在跑任务"的对照；触发链见卡（SSE 故障 ⇒ resume --force ⇒ done ⇒ 重派 409）。

## 1. 问题

任务已经 `done` 归档、机器上没有任何 running/pending/waiting_* 任务，但 `card dispatch <card> --step implement` 连续两次被拒：

```
409 {"error":"该卡已有环节在运行: B393 的 implement 节点正在运行"}
```

⇒ **陈旧运行锁不自愈**（持有者不存在了，锁还在），卡被锁死、无法重派——一期"主会话是发动机"的形态下，这等于把推进权锁死。

## 2. 范围

**做**：让陈旧锁自愈——归档/收口路径释放锁；或 409 判据加"持有者已死/超期"兜底；并给出能变红的测试（任务归档后同卡同节点可重派）。
**不做**：不改互斥语义本身（同卡同节点**并发**仍必须拒绝）；不动其他卡与线上状态；不手改锁数据。

## 3. 待查（先取证再改）

1. 锁的写/清/TTL：`internal/ledger/runlock.go`（或同名模块）——谁写锁、谁清锁、TTL 多长、有无 owner 字段；`done` / `stop` / 归档路径是否释放；`resume --force` 收口是否释放。
2. 409 的判据：`card dispatch --step` 的"该卡已有环节在运行"读的是哪个表/字段；是否只看"锁存在"而不看**持有者存活或是否过期**。
3. 为何没自愈：若 TTL 存在，为何 25 分钟后仍被拒（是判据没看 TTL，还是 TTL 被续期）。

## 4. 验收判据

1. **红色回路**：能在测试里复现"任务已归档但同卡同节点仍被 409"（今天预期红）。
2. **修后**：归档/收口后同卡同节点**可重派**；同时**并发**同卡同节点仍被拒（反例断言在场，不许把互斥一起放开）。
3. **变异复验**：把自愈条件去掉要重新变红。
4. **真机**：B393 卡能重新派发（就是当前被锁死的这张）。
