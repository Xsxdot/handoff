## 1. 先纠正两条我自己写错的前提

backlog B107 的初稿是我凭印象分的档，查代码后**两条是错的**，已在 backlog 就地更正，
这里记录结论，因为它们直接改变了任务的形状：

**错前提一：「`在终端中打开` 是零后端改动的纯接线」。**
`resolvePtyBase`（`pty_api.go:76`）把 `base_path` 交给 `resolveWorkspace` 之后
**返回的是工作树根 `root`**，子目录被丢弃；`proto.CreatePtySessionReq`（`proto/pty.go:44`）
只有 `BasePath`/`BaseKind`/`Cols`/`Rows`，**没有 `rel`**。所以「在这个子目录里开终端」
要加一个字段。仍然是本 plan 里最小的一条，但不是零改动。

**错前提二：「删除要确认层，因为控制台会话是刻意弱于主令牌的凭据」。**
这条前提**是假的**。`identityFrom` 的全部非测试使用点只有 4 处，3 处在
`authroutes.go`（会话自管理），1 处在 `server.go:1455`（WS 会话复验），
**没有任何一条业务路由按身份限权**；`server.go:283` 是 `root.Handle("/", s.auth(mux))`，
Bearer 与 cookie 会话走同一个 mux，其中包含 `POST /api/tasks/{id}/run`
——而它就是 `exec.CommandContext(ctx, "sh", "-c", cmdline)`（`workspace.go:1448`）。
`workspacefiles.go:11-14` 与 `pty_api.go:59-61` 的表述才是当前口径。

**这条纠正的后果**：删除确实要确认层，但理由**只是「不可逆」**，与凭据强弱无关。
不要在实现里写「防止弱凭据提权」的注释——那会把一条已被证伪的论证再传播一次。
两份 spec 口径打架这件事本身另记为 **B109**，本 plan 不修文档口径，只是不引用错的那份。

## 2. 范围：三档，本期做前两档

截图里 11 条菜单项。按「现在能不能做」分档：

| 档 | 菜单项 | 本期 |
|---|---|---|
| ① 纯前端 | `复制路径`、`复制相对路径`、`折叠文件夹` | **做** |
| ② 要补后端端点 | `新文件`、`新建文件夹`、`重命名`、`复制`、`删除`、`在文件夹中查找` | **做** |
| ③ 要改一点后端 | `在终端中打开` | **做**（加一个 `rel`） |
| ④ 结构性做不了 | `Reveal in Finder` | **不做，置灰给理由**（见 B108） |

### 2.1 一条重要的对比：文件操作在远程**能用**，Finder 才是真做不了

这两件事很容易被一起归到「远程做不了」，但它们的性质**完全不同**：

- **文件操作与终端**在远程**天然正确**——它们操作的是「代码所在的那台机器」，
  而 `machine=` 转发（`forwardIfRequested`）本来就把请求打到那台机器上。
  在 mac-02 上新建一个文件、在 mac-02 上开一个终端，正是用户想要的语义。
- **`Reveal in Finder`** 要操作的是「**人正坐着的那台机器**」的 GUI。在 mac-02 上
  `open -R` 会在一台没人看的机器上弹窗。**这一条与用什么壳无关**（B108）。

所以本期唯一置灰的是 `Reveal in Finder`，其余 10 条本机与远程一视同仁。

## 3. 服务端：一组工作树文件操作端点

现有文件类端点只有三个（`server.go:263-265`），全是读或单文件写：
`GET /api/workspaces/dir`、`GET /api/workspaces/file`、`PUT /api/workspaces/file`。
`workspacefiles.go` 的文件头明写边界：「写接口只在单个**已存在**文件上做原子替换：
**不建目录、不删任何东西**」。本期正是要突破这条边界，因此**文件头注释必须同步改**
——留着一句已经不成立的边界声明，比没有注释更坏。

### 3.1 端点表

四个新端点，全部支持 `?machine=` 转发（复用 `forwardIfRequested`，与三个既有端点同一条路）：

| 方法与路径 | 语义 | 请求体 |
|---|---|---|
| `POST /api/workspaces/entry?path=&rel=` | 在 `rel`（父目录）下新建 | `{"name":"foo.go","kind":"file"\|"dir"}` |
| `POST /api/workspaces/entry/copy?path=&rel=` | 把 `rel` 复制一份到同级 | 无 |
| `PATCH /api/workspaces/entry?path=&rel=` | 重命名 `rel` | `{"new_name":"bar.go"}` |
| `DELETE /api/workspaces/entry?path=&rel=` | 删除 `rel` | 无 |

外加一个查找端点（§5）：`GET /api/workspaces/search?path=&rel=&q=&limit=`。

**为什么用 `entry` 而不是分成 `file`/`dir` 两套**：这四个动作对文件和目录**语义一致**，
分两套会产生八个端点和一份「调用方要先知道它是文件还是目录」的负担——而前端本来就
知道（`DirEntry.is_dir`），但服务端**必须自己再判一次**（前端说的不算），于是分两套
只是把同一个 `Stat` 判断做两遍。`kind` 只在「新建」时必要，因为那时目标还不存在。

**重命名只改名，不跨目录移动**：截图里没有「移动」，`new_name` 含 `/` 一律 400。
YAGNI，且跨目录移动的确认层要复杂得多（覆盖、跨设备）。

### 3.2 路径遏制：一条红线，不许另开一条实现

**全部四个动作必须经 `os.OpenRoot` 完成**，与 `ReadFile`/`WriteFile` 同一条路
（`workspace.go:1196-1202` 写明了为什么：`EvalSymlinks` 前缀校验是「先校验后打开」
两步，中间有 TOCTOU 窗口，**恶意 executor 经 `run` 命令完全能在这个窗口里换掉链接**；
`os.OpenRoot` 的解析在单次打开内由内核完成，无窗口）。

Go 1.26 的 `os.Root` 提供了本期需要的全部方法，**都在 jail 内**：
`Create` / `Mkdir` / `Remove` / `RemoveAll` / `Rename` / `Stat` / `OpenRoot` / `FS`。
`Rename` 的两端都受 jail 约束。

**因此实现里不得出现 `filepath.Join(root, rel)` 之后直接 `os.Remove`/`os.Rename` 这类写法。**
这是本 plan 的**头号红线**：它不会导致任何测试失败，只会在某天变成一个可以删掉
仓库外文件的洞。审查必须逐个动作确认它走的是 `Root` 方法。

复制没有 `Root.Copy`：**源经 `Root.Open`、目标经 `Root.Create`、中间 `io.Copy`**；
目录复制经 `Root.FS()` 走 `fs.WalkDir`，每个条目各自 `Root` 化，**不许中途落回绝对路径**。

### 3.3 `.git` 保护要扩到新动作（可推翻的部分只有范围）

`isGitPath`（`workspace.go:1008-1024`）现在只被写文件那条路用。**四个新动作全部要挡**：
删掉 `.git` 等于毁掉工作树，重命名 `.git` 等于让工作树失联，在 `.git` 下新建文件
等于写 `.git/config`（那里能塞 `core.pager` 拿到任意命令执行——注释里已经写了这条）。

**可推翻的是范围**：`isGitPath` 现在只挡**工作树根下**的 `.git`，嵌套子模块不挡
（注释明说「不在本期范围」）。本期**沿用**这个范围，不扩大——扩大要引入子模块探测，
而子模块场景下用户更可能是有意在操作它。代价写清：子模块的 `.git` 可以被删。

### 3.4 复制的命名规则（可推翻）

`foo.go` 复制成 `foo copy.go`，再复制成 `foo copy 2.go`；无扩展名的 `foo` →
`foo copy` → `foo copy 2`；目录同理。**服务端算目标名并返回**，前端不参与。

**为什么服务端算**：撞名判断必须在目标机器上做（远程 location 时前端根本不知道
那台机器上有什么），前端算出来再上送等于多一次往返 + 一个 TOCTOU 窗口。

**为什么是「copy」这个词而不是「副本」**：跟 macOS Finder 的英文形态一致，而这个
菜单本来就是照 Orca（macOS 应用）的截图做的。若用户更想要中文，改的是一个常量。

**上限**：同名探测最多试到 `copy 99`，之后 409 让用户自己改名——不写上限的循环
在一个有一万个 `foo copy N` 的目录上会转很久。

### 3.5 删除：直删，不做回收站（可推翻）

`Root.Remove`（文件与空目录）/ `Root.RemoveAll`（非空目录）。**不实现回收站**。

**理由**：这些目录是 **git 工作树**，误删的恢复手段本来就存在且更好用
（`git checkout -- <path>` 对已提交文件、`git status` 对未跟踪文件）。
自建一层回收站要解决存哪、何时清、跨机怎么办三个新问题，而它解决的问题
git 已经解决了大半。

**代价要说清**：**未跟踪且未提交的文件删掉就没了**，git 也救不回。因此：

- 前端必须有确认层，且**确认文案要点名这一条**，不能只写「确定删除吗」；
- 非空目录的确认要**报出条目数**（服务端在 `DELETE` 前不做这件事——那要多一次
  往返；前端用已列举的内容给一个「至少 N 项」的说法，说不准就说不准，不要编）。

理由是**不可逆**，不是凭据强弱（§1 错前提二）。

### 3.6 错误映射

复用现有哨兵与映射风格，**中文错误原文原样透传**（`workspacefiles.go:205-206`
已经立了这条规矩：用户看到「不允许写入 .git 目录」能立刻明白，看到「操作失败」
只能来问）。新增哨兵：

| 哨兵 | 状态码 | 触发 |
|---|---|---|
| `ErrEntryExists` | 409 | 新建/重命名时目标已存在 |
| `ErrEntryNotFound` | 404 | 目标不存在 |
| `ErrBadEntryName` | 400 | 名字含 `/`、为空、是 `.` 或 `..` |
| 复用 `ErrPathEscape` | 400 | 路径逃逸 |
| 复用 `ErrGitDirWrite` | 400 | 命中 `.git` |

## 4. `在终端中打开`：给 PTY 请求加 `rel`

`proto.CreatePtySessionReq` 加一个 `Rel string \`json:"rel"\``。
`resolvePtyBase` 在 `base_kind != "home"` 且 `Rel != ""` 时，把 `Rel` 拼到 `root` 上，
**并且必须校验拼接结果没逃出 `root`**（`filepath.Clean` 后不得以 `..` 开头、不得是绝对路径），
再 `Stat` 确认它是个目录。

**注意这里的判据与 §3.2 不同**：这不是安全边界（`resolvePtyBase` 的注释已经写明
「这是参数校验，不是安全边界……终端里一条 `cd ~` 就出去了」），所以**不需要
`os.OpenRoot`**，失败给 400 而不是 403。**但仍然要校验**——理由和原注释一样：
防止前端传一个打错的路径，让 shell 起在文件系统某个莫名其妙的角落。

在文件上右键选「在终端中打开」时，前端传的是**它的父目录**，不是文件本身。

## 5. `在文件夹中查找`（上限取值可推翻）

`GET /api/workspaces/search?path=&rel=&q=&limit=`，在 `rel` 子树内按内容搜索，
返回 `[{rel, line, text}]`。

**实现取向**：优先 `rg --json`（存在就用），不存在回落到 Go 自己走 `Root.FS()`
遍历 + 逐行匹配。**不 shell 出 `grep`**——`sh -c` 拼接用户输入是注入面，而
`exec.Command("rg", ...)` 传参数组没有这个问题。

**三条必须有的护栏**（少一条都能让一次点击把 agentd 拖住）：

1. **结果上限** `limit`，默认 200、上限 1000；
2. **超时** 10 秒，到点返回已有结果并标 `truncated: true`；
3. **跳过 `.git` 与常见生成物目录**（`node_modules`、`vendor`、`dist`、`target`）。

**可推翻的是取值**：200/1000/10s 是拍的，理由是「一屏看不完 200 条」和
「10 秒是人愿意等的上限」。真跑起来不合适就调常量，不要改结构。

**明确不做**：正则、大小写敏感开关、按文件名搜。截图里只有一个「在文件夹中查找」。

## 6. 前端形态

### 6.1 `ContextMenu` 要扩三件事

现有 `web/src/app/tree/ContextMenu.tsx`（B95 留下的，94 行）已经处理了定位翻转、
点外部关闭、Esc、焦点。**复用它，不要重造**。但它的 `ContextMenuItem` 只有
`label` / `onSelect` / `danger`，本期需要补：

- **`separator`**：截图里 11 条分三组，分组线是形态的一部分；
- **`disabled` + `disabledReason`**：`Reveal in Finder` 在远程要置灰**并给出理由**
  （置灰而不给理由，用户只会以为是 bug）；
- **键盘上下移动**跳过 separator 与 disabled 项。

组件当前在 `app/tree/` 下而本期在 `app/files/` 用它——**移到共享位置**
（如 `app/shared/ContextMenu.tsx`）并改两处引用，别在 `files/` 下复制一份。

### 6.2 菜单项与分组（照截图）

| 组 | 项 | 文件上 | 目录上 | 远程 |
|---|---|---|---|---|
| 一 | 新文件 / 新建文件夹 | 在父目录下建 | 在其下建 | 可用 |
| 一 | 在终端中打开 | 用父目录 | 用自身 | 可用 |
| 一 | 在文件夹中查找 | 用父目录 | 用自身 | 可用 |
| 二 | 复制 / 重命名 / 删除 | 可用 | 可用 | 可用 |
| 二 | 复制路径 / 复制相对路径 | 可用 | 可用 | 可用 |

| 三 | Reveal in Finder | **置灰** | **置灰** | **置灰** |

`Reveal in Finder` **在本机也置灰**：本期不做任何一半（B108 还没定 Electron 的去留，
只做本机那半会留下一个「本机能点远程不能点」的割裂形态，且它依赖一个尚未裁决的前提）。
置灰理由文案要分别写清本机（「暂未实现」）与远程（「远程目录无法在本机的访达中打开」）。

### 6.3 `FileTree.tsx` 的边界注释要改

第 10 行现在写着「**只读**：不发写请求，不提供新建/重命名/删除」。本期正是要推翻它。
**这一行必须改**，不改就是留一句骗人的边界声明。

### 6.4 交互细节

- 新建/重命名用**行内输入**还是弹层：用**弹层**，与 B95 的编辑弹层同一套词汇。
  行内输入要处理滚动、失焦、树刷新三件事，收益只是少一次弹窗；
- 操作成功后**刷新该层目录**（`dirs.ensure` 已有能力），不整树刷新；
- 删除的确认弹层按 §3.5 写文案；
- 失败时**把服务端的中文错误原文显示出来**，不要吞成「操作失败」。

## 8. 风险

**头号风险是 §3.2 的路径遏制被绕过**：`filepath.Join` + 裸 `os.Remove` 能通过全部
功能测试，只在被攻击时才显形。因此验收里有一条**机械判据**（§9.3），不靠人眼。

**第二是「删除」的不可逆**：未跟踪文件删掉 git 也救不回（§3.5）。

**第三是搜索把 agentd 拖住**：三条护栏（§5）少一条都不行。

## 9. 验收

1. `go build/vet/test ./...` 全绿；`web/` 三件套（`vitest` / `tsc -b --force` / `vite build`）全绿。
2. **服务端用例**，每条都要能被变异咬住：
   - 新建文件/目录成功；父目录不存在 404；同名 409；名字含 `/` 400；
   - 重命名成功；目标已存在 409；`new_name` 含 `/` 400；
   - 复制文件成功且名字是 `foo copy.go`；连续复制两次得到 `foo copy 2.go`；复制目录递归成功；
   - 删除文件成功；删除非空目录成功；不存在 404；
   - **`.git` 四个动作全部被拒**（四条用例，不是一条）；
   - **符号链接逃逸被拒**（照 `TestReadFileSymlinkEscape` 的手法，四个动作各一条）；
   - 搜索命中；`limit` 生效；`.git`/`node_modules` 被跳过。
3. **机械判据（路径遏制）**：`grep -n "os\.\(Remove\|RemoveAll\|Rename\|Create\|Mkdir\)" internal/agentd/workspace.go`
   在新增代码范围内**必须零命中**——全部动作只能经 `Root` 方法。ledger 里贴出这条命令的输出。
4. **PTY `rel`**：子目录开终端成功；`rel` 含 `..` 400；`rel` 指向文件 400。
5. **前端用例**：目录/文件上菜单项集合不同；`Reveal in Finder` 置灰且有理由；
   删除确认文案含「未跟踪的文件删除后无法恢复」；服务端错误原文被显示；
   操作后只刷新该层。
6. 端到端冒烟（临时 datadir + 临时端口 + 临时 git 仓库）：建→改名→复制→删除走一遍，
   `GET /api/workspaces/dir` 前后一致。**不要动 `~/.handoff`。**
7. 真机复验由审核者做。

## 10. 明确不做

- `Reveal in Finder`（置灰，见 B108）。
- 回收站（§3.5）、跨目录移动（§3.1）、拖拽排序。
- 搜索的正则/大小写/按文件名（§5）。
- 子模块 `.git` 保护（§3.3）。
- 不动 `PUT /api/workspaces/file` 与 `/api/tasks/{id}/file` 的既有契约。
- 不顺手修 B109 的文档口径打架——本 plan 只是不引用错的那份。
