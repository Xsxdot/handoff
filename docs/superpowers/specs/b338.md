# B338 coordinate 把本机 target 名当远端，TUI 开不出来

- **卡**：B338
- **级别与档位**：**L1**。plan 增量为零：开 tab 的本机判定叠上已有 `IsSelfTarget`。验收一眼可核：`card coordinate` 对 muse@mac-02 不再 502。
- **状态**：**已批准**（2026-09-05；用户授权自主推进：先修 B338，再补被挡住的真机，有问题继续修）
- **基线**：`origin/main` @ `8a8e9352`
- **发现自**：B337 真机 / B336 合入后。不 reopen B336。

## 问题陈述

B336 冻死「本机 leader 打开控制台 PTY」。leader 载体 muse 登记 `machine=mac-02`，该键的 addr 就是本机 listen。`openCoordinatorTUI` 只用 `scheduling.IsLocalMachine`（空 / `local` / `本机` / hostname），`mac-02` 全不是，于是 502「远端载体 TUI 转发尚未接线」。agentd 已经有 `IsSelfTarget`：登记名在 targets 里且直连地址指向本进程就算本机。开 TUI 没用它。

## 方案

开协调者 TUI 时：本机别名 **或** 指向本 agentd 的 target 名 → 本机 `pty.Open`。真正的远端（linux-01 这类）仍报尚未接线。不改 `IsLocalMachine`（它是登记闸的本机别名，不是进程身份）。不接线远端转发。

弃选：改 muse 的 machine 为 `本机`（编制是用户的，代码应认 self-target）。弃选：在 `IsLocalMachine` 里读 agentd 配置（编制域不该依赖 listen/targets 进程身份）。

## 用户故事

1. 作为本机用户：leader 载体 machine=`mac-02`（addr=本机 listen）时，`card coordinate` 打开本机 PTY，不再 502。
2. 作为对照：machine=`linux-01` 且 addr 不是本机时，仍报尚未接线。
3. 作为回归：`本机` / `local` / 空串仍走本机 PTY。

## 测试决定

缝：`Server.openCoordinatorTUI` ← `launchCoordinatorRound`（生产路径，测试不走 `openCoordTUI` 桩）。

1. Listen 与 `targets.mac-02.addr` 相同 → `openCoordinatorTUI` 不报远端未接线。
2. `targets.linux-01` 指向其他地址 → 报 `远端载体 TUI 转发尚未接线：machine=linux-01`。
3. `machine=本机` 仍本机。

## L1 plan（同一文件，过 implement 门）

1. `openCoordinatorTUI`：`IsLocalMachine` 为假时再问 `IsSelfTarget`；二者都假才报远端未接线。本机 target 名打 Info。
2. 测试：上列三条，调用真实 `openCoordinatorTUI`（`openCoordTUI=nil`）。
3. 不接线 `?machine=` 转发，不改 `IsLocalMachine`，不迁 muse HomeDir。

验收：测试绿；本机 `card coordinate` 对现网 muse@mac-02 开出 PTY。本节点该干什么一律以注入的纪律块为准。
