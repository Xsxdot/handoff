# B468 账号图标：codex 与 grok 换成 OpenAI / Grok 官方图标

> 状态：**r1 待批准**（2026-10-23 出稿）。
> 级别：**L1**（单子系统：控制台；不动契约；改一个图标表 + 原型同步，验收一眼可核）。路由：implement → review → finish；本 spec 即 plan。
> 执行形态：**甲 本地盯**（判决第 5 条 L1）：本会话 subagent 实现，主会话审 diff 与浏览器验收。

## 问题陈述

用户（2026-10-23）：「把 grok 和 codex 的 icon 换一下，可以用 openai 和 grok 网站自己的 icon」。现状读数：kind 图标是自绘 16×16 单色线稿，`web/src/app/accounts/QuotaBits.tsx:13-18`（codex = 六边形内 `<>`，grok = 方框内斜线），原型同源 `prototypes/base/shared/accounts.js`；用在底栏段、使用量弹层分组、账号页分组标题与「已忽略」行、移动端节、载体行。

## 方案

- codex → OpenAI 官方标志（花形结），grok → Grok 官方标志。
- **单色内联 SVG**：沿用现有图标纪律（`currentColor` 跟随灰阶、不进彩色，`QuotaBits.tsx:6,12`），只替换两条路径；不改尺寸与其他 kind。
- 图形来源：官方标志的公开矢量版（打算取开源图标库 `@lobehub/icons-static-svg` 的 OpenAI、Grok 单色 SVG，经 cdn.jsdelivr.net 下载两份 SVG 文件，各几 KB），路径内联进代码；运行时不请求外部资源。
- 弃选：直接用两家网站的 favicon 图片——是彩色位图，暗色主题下与其余单色图标不一致，且要么外链（离线/内网失效）要么入库位图。**（待批准岔口 ①）**

## 落位三问

① 读写谁的权威数据：无数据，纯展示常量，归控制台账号组件。② 谁消费：同子系统内组件经导出的图标组件。③ 同步/异步：不涉及。

## 实现决定（L1 三行 plan）

1. 改 `web/src/app/accounts/QuotaBits.tsx` 的 `ICON_PATHS.codex`、`ICON_PATHS.grok` 为官方标志单色路径（viewBox 按来源图形换算或在 `<svg>` 上按 kind 给 viewBox）；同步改 `prototypes/base/shared/accounts.js` 同名图标。
2. 测试：`KindIcon` 对 codex/grok 渲染出非空 `<svg>` 且不含 `fill` 彩色值（只有 `currentColor`/`none`）；`cd web && npx vitest run && npx tsc -b`。
3. 验收：浏览器亮/暗两张截图（底栏 + 弹层 + 账号页分组标题）。

## Out of Scope

- 永不做：彩色或位图 logo（破坏单色纪律）。
- 不做：claude / agy / opencode-go 图标（用户未提；需要时另起卡）。
