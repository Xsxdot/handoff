本节点该干什么一律以注入的纪律块为准。

## 问题陈述

谁：远端 charter 执行者要查 `codegraph/`。

条件：平台不变量第 2 条把 `go run github.com/Xsxdot/charter/graph/cmd/codegraph` 写在已安装二进制前面。B233.28 在 linux-01（已有 `/usr/local/bin/codegraph` v0.10.1，`summary` 0.06s）上仍 `go run` 五次约 18 分钟，并考古模块缓存。

要变的事实：查图入口只剩 PATH 上的 `codegraph`；没有二进制就停下来提安装工单，不再 `go run`、不再自行安装。

谁能观察到：此后派发的任务 prompt 里平台层第 2 条不含 `go run .../cmd/codegraph`；缺二进制时执行者输出 `{"ask":"..."}`。

## 方案

改 `internal/discipline/platform.go` 的 `platformInvariantHead` 第 2 条，测试锁住新正文。

弃选：保留 `go run` 作回落——有二进制时负收益，无二进制时变成编译/权限门空转。

## 用户故事

1. 机上已装 `codegraph`：执行者只调用 `codegraph --repo . <子命令>`。
2. 机上未装：执行者输出单行 `{"ask":"本机未安装 codegraph，请安装后再继续"}` 并结束回合，等协调者安装。
3. 图查询未命中某符号：仍可 grep，记图覆盖债。缺二进制不得用 grep 代替查图。

## Out of Scope

- 不改 charter 角色 skill 的「图未命中再 grep」（那是符号未覆盖，不是缺工具）。
- 不改历史台账/plan 里的 `go run` 记录。
- 不在本卡给各机安装二进制；缺则走工单。
- 已在跑的任务 prompt 不回溯改写；新纪律在 agentd 用本提交重建后的下一次派发生效。

## 实现决定（即 plan）

1. 改 `internal/discipline/platform.go` 第 2 条：只许已安装 `codegraph`；禁止 `go run`/编译当入口；PATH 没有则 `{"ask":"本机未安装 codegraph，请安装后再继续"}` 结束回合；禁止自行安装；图未命中符号才 grep。
2. 改 `internal/discipline/platform_test.go`：Compose 产出不得含 `go run github.com/Xsxdot/charter/graph/cmd/codegraph`；必须含已安装二进制与 ask 工单。
3. 验收：`go test ./internal/discipline` 绿。
