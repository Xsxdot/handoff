本节点该干什么一律以注入的纪律块为准。

## 定级理由

一次执行的占用与身份要同时改编制域、卡节点装配、共享派发 HTTP 和跨机 wire。动已有 `POST /api/tasks` 契约。单条接缝、一轮可收口 → L3 轻档。审批事实与工作区迁包超过本卡，不纳入。

## 问题陈述

谁：一次普通派发或一次卡节点派发，最终在某台机器上跑起一个任务。

条件：B233.5/6 已经让两种入口都走载体，但卡节点会先准入一次，再经 `POST /api/tasks` 在执行机再准入一次。工作流仍把小队名当作执行 hop 的接收者，执行机可以重选成员载体。节点 goroutine 结束释放一次，任务终态再释放一次。

通道：现有 `handoff dispatch`、`card dispatch --step`、`POST /api/tasks`。不新造 HTTP 路径或 CLI 命令。

要变的事实：

1. **一次执行只占用一次容量。** 选择载体、冻结身份、路由机器、获得容量、结束后一次释放，是同一条生命周期。起源侧（卡所在的 agentd）可以为了知道打哪台机器而选择并冻结身份，但不得为这次执行占容量。
2. **执行机按冻结身份占用，不得重选。** 小队名可以出现在审计或选择输入里；执行 hop 必须携带已冻结的载体身份。执行机占用该载体（若选择来自小队，同时占用该成员政策位），不得对小队再 `Admit` 挑另一个成员。
3. **释放只发生在这次执行的终态。** 启动失败回滚这一次占用；`Done` / `Stop` 释放这一次占用。卡节点 goroutine 返回、工作流移列、镜像收流，都不得再减一次执行占用。`Continue` / `Resume` 不得再准入。

谁能观察到：同一套编制计数键在任务运行中是 +1 不是 +2，终态回到 0；任务落点的机器/CLI/HOME 等于冻结身份，不等于执行机当场重选的结果。

## 方案

编制域把「选择并冻结身份」和「占用容量」分成两件事。占用只发生在将要启动 executor 的那台机器，对象是已经冻结的载体（以及若来自小队则对应的成员位）。

卡节点起源侧：

- 仍负责纪律探活、选哪台机器发 HTTP、满员时把**派发意图**写入 `ignition_queue`（不占容量）。
- 出队后走与当场派发同一条链：选择 → 带冻结身份的共享派发 → 执行机占用。
- 不再调用执行占用的 `Admit` / `AdmitCarrier`，goroutine 结束不再 `Release` 执行占用。

执行 hop：

- 现有 `POST /api/tasks` 保留。请求必须能表达已冻结的载体身份（字段名归 contract）。
- `handleDispatch` 对冻结载体占用一次并启动任务。失败回滚这次占用；成功则留到任务终态。
- 没有冻结身份的裸派发仍在执行机当场选择+占用一次，行为与今天的单次准入对齐。

工作流：

- 继续组装目标、材料、纪律、接收者名称，调用共享派发，关联 attempt，转发事件，裁决节点。
- 不再维护另一套执行准入。小队名不再足以让执行机重选落点。

**弃选**

- **起源占用、执行机跳过准入，靠 token 证明已占过。** 起源不是跑 executor 的地方，节点结束又会提前释放；跨机还要把占用证明做成新协议。否。
- **执行机继续对小队 `Admit`，只把起源那次准入删掉。** 起源为了纪律探活必须先知道机器，执行机再选一次可以换成员，跨机落点仍不一致。否。
- **本卡同时收口审批送达和工作区迁包。** 超过轻档，且不阻塞本刀的占用不变式。否。
- **删除 `POST /api/tasks` / `Manager.Dispatch`，或全仓按 `best.json` 搬目录。** 生产入口；物理搬家仍是父卡后续。否。
- **改 `LaunchAdmit` / 协调者会话占用。** 不是一次任务执行。否。

## 用户故事

1. 我在本机对一张绑了执行者小队的卡 `card dispatch --step`。任务跑起来之后，该载体物理位和该小队成员位都只 +1；`handoff done` 之后都回到 0。不会出现跑一个任务却占两个名额。
2. 小队有两个 online 成员。起源侧选出载体 A 之后，执行机必须跑 A，不得改成 B。任务里保存的载体/机器/CLI/HOME 与冻结身份一致。
3. 卡节点在任务仍运行时结束自己的 goroutine（或失败回滚装配），占用仍由任务终态负责，不会被提前减掉。
4. 不绑小队的 `handoff dispatch`（默认或显式载体）仍然只占用一次，命令名和 HTTP 路径不变。
5. 满员时卡节点照旧排队、不起任务；轮到它时仍是「选择 → 执行机占用」，起源侧排队期间不占名额。

## 契约语义与接缝

跨子系统规则：

- **容量事实归编制域。** 只有执行机上针对冻结身份的那一次占用是权威写入。起源侧和工作流不得写执行占用。
- **身份事实在选择时冻结，之后只消费。** 机器、CLI、HOME、载体名、来源小队名（若有）构成这次执行的身份。后续 hop 不得用小队名再解析出另一个载体。
- **任务状态仍归任务域。** 占用随任务终态释放，不随卡列、节点 verdict、镜像收流释放。
- **允许的依赖方向不新增顶层域。** 编制域继续对外提供选择与占用；gateway 组装；ledgerstep 只透传冻结身份，不 import 编制实现。不新开 `d_dispatch`。
- **B233.5 / B233.6 与本卡冲突的条款以本卡为准。** 特别是：卡节点与裸派发「走同一套 Resolve→准入→绑定」不得再解释成起源和执行机各跑一遍准入；`TemplateDispatch.Receiver = 小队名` 不得再作为执行机占用键。

接缝（符号 + 调用方）：

1. **`internal/agentd/server.go#Server.handleDispatch`** — 调用方 `internal/client/client.go#Client.Dispatch`（裸 CLI 与 `stepTransport`）。执行机对冻结身份占用一次；无冻结身份的裸派发当场选择+占用一次。这是最高可测缝。
2. **`internal/agentd/cardstep.go#Server.startCardStep`** — 调用方 `card dispatch --step`。起源侧可选择并冻结身份、可把意图写入 `ignition_queue`；不得占用执行容量；goroutine 结束不得释放执行占用。
3. **`POST /api/tasks` 请求体上的冻结身份** — 调用方 `Client.Dispatch`。边界型 wire：执行 hop 必须能编码已冻结载体（及来源小队，若有）。字段名归 contract；本卡不新造路径。

假缝禁令：`OccupancyKeys` 纯编码、选择用的内部纯函数，不占接缝名额。`LaunchAdmit` 不是本卡缝。

## 实现决定

- 命令名不变：`handoff dispatch`、`handoff card dispatch --step`、`handoff done`、`handoff stop`。
- HTTP 路径不变：`POST /api/tasks`。可在现有 JSON 上增加冻结身份字段，不新增路由。
- 满员、无默认载体、禁止覆盖已绑定物理身份的错误语义保持可行动；不把二次准入伪装成这些错误。
- 任务仍保存载体身份与有效设置；事后改载体登记不得改写历史任务解释（B233.5 已冻，本卡保持）。

## 测试决定

1. **单次占用**（缝 1+2）：本机、同一编制服务，绑小队的卡节点派发成功后，`carrier/<名>` 与 `squad/<小队>/<载体>` 均为 +1；Done 后均为 0。变异：故意保留起源侧 `Admit` 时应变为 +2 并失败。
2. **冻结身份不被重选**（缝 3）：执行 hop 带载体 A 的冻结身份，即使小队另有 online 成员 B，任务的载体/机器/CLI/HOME 必须是 A。
3. **释放点**（缝 2）：任务仍非终态时结束卡节点 goroutine，占用不得被减到 0；随后 Stop/Done 才到 0。启动失败只回滚执行机那一次占用。
4. **裸派发不回归**（缝 1）：不经卡节点的载体直派仍是 +1 / 终态 0。Continue/Resume 不增加占用。

真机：本机一条小队卡节点；本机起源 → linux-01 执行的一条小队卡节点。隔离实例，不写生产占用。跨机项锁「执行机载体 = 冻结身份，且共享账本上该键 +1」。
