## 定级理由

跨子系统：工作区（`d_workspace`）、控制门面（`d_gateway`）、任务编排（`d_orchestration`）今日在
`internal/agentd` 同一个包里，目标图把它们标成三个域却无法执法——`codegraph check` 现在的两条
`anchor-off-domain` warn 说的就是这件事（域声明锚指向 `d_coordination_task` 的符号）。本卡把 git/工作区
实现搬进 `d_workspace` 的包，并按现实棘轮依赖契约（`target.json` 的预算与条目），属「动契约层」。
同进程 Go 包调用，不升 HTTP/MQ；单条缝（工作区能力面），一轮可收口 → **L3 轻档**。

覆盖入口预判：卡 note 记「L2 或 L1」。按定稿范围改判 L3——判据是跨域 + 动 `target.json`，不是工作量。

## 问题陈述

谁：agentd 进程里，编排（`Manager`）与网关 handler 需要工作区/git 能力。

条件：git 实现主体住在 `internal/agentd/workspace.go`（2838 行、73 个函数），`internal/workspace`
只有契约面；生产的 Capability 实现是同包的 `gitCapability{}`，方法体逐个回调本包函数。同包可见性
意味着任何 agentd 代码都能直接调 `gitExec`/`gitRun`/准备与回收的内部细节——「跨子系统只经能力面」
今天靠约定，不靠结构。复核结论逐字（`4485a4e7` 结构专项第 3 条）：「接口抽出不等于物理隔离；
同包可见性不能阻止绕过。」

通道：同进程包调用。不新造跨机协议、HTTP 端点、CLI 命令或事件类型。

要变的事实：

1. **git/工作区实现住在 `internal/workspace`**；`internal/agentd` 不再有这些实现文件。
2. **Capability 生产实现由 `internal/workspace` 提供**，组装点只注入——`cmd/agentd.go:219` 与
   `internal/agentd/server.go:374` 的 `agentd.NewGitCapability()` 调用消失。
3. **跨缝只经具名能力**：agentd 保留的消费点按使用方语义收口；git 执行原语（`gitRun`/`gitProbe`/
   `gitRunNet` 一类）不出包。
4. **目标图与域声明按现实棘轮**：`d_workspace` 的声明锚指向本包文件；`d_workspace→d_orchestration`
   的两条边随同域化消失；`d_workspace→d_protocol` 预算上调；`d_cli`/`d_gateway`/`d_orchestration`
   →`d_workspace` 按实际消费点上调。
5. **行为不变**：Prepare/Diff/回收/文件与条目 API 的语义、错误哨兵、错误与日志文案、超时值、
   git 命令行参数（`-C repo`、空 `hooksPath`）一字不改——这是搬运，不是改写。

谁能观察到：`internal/agentd` 源码里搜不到 git 实现（无 `exec.Command("git"` 的构造、无准备/基线/
回收主体）；`internal/workspace` 的导出面只有能力，没有 git 原语；`codegraph check` 的 fails 不增
（当前基线 0 红）；CLI/Web 的行为与文案零变化（包名用户看不见）。

## 契约语义与接缝

**允许的依赖方向变更**（语义，`target.json` 的条目与预算数字归 contract 落地）：

- `d_workspace→d_protocol`：允许并在本卡按实际边数棘轮（`proto` 是词表包，直引）。
- `d_workspace→d_orchestration`：两条边随实现迁入同域而**消失**，预算下调到 0 或删除该方向。
- `d_cli→d_workspace`、`d_gateway→d_workspace`、`d_orchestration→d_workspace`：按迁移后的真实消费点棘轮；
  已在 `d_workspace` 的容器（`k_agentd_Mirror`、`k_agentd_projectIndex` 等）的消费点属同域，不增边。
- **禁止**：新增 `d_workspace→d_transport_tunnel`、`d_workspace→d_execution_host`（本卡走注入不直引）；
  新增 `d_workspace→d_ledger`（沿用 B233.4 禁令，工作区不写卡）。

**语义规则**：

1. 工作区实现是 `d_workspace` 的私有物：跨子系统使用一律经具名能力（`Capability` 或包级具名函数），
   不导出执行原语。
2. 类型跨缝直引（`proto`），行为跨缝注入（代理解析、fork 失败文案在组装点绑定）。
3. 迁移是搬运：错误哨兵、错误与日志文案、超时值、git 命令行参数、留存判据（`MayRecycle`）语义都不变。
4. 不新增顶层域、跨机协议、HTTP 端点、CLI 命令、事件类型与序列化字段。
5. 具名能力的命名与签名由 contract 冻结；contract 落地时核验导出面与本节的语义边界一致，核不上按契约分歧
   退回 spec，不许落地时顺手改缝。

**接缝（符号 + 调用方）**：

1. **`Capability` 七方法**（`internal/workspace/capability.go#Capability`）← 生产调用方
   `Manager.Dispatch` / `Manager.Stop` / `Manager.Done` / `Manager.compensateWorkspace`（经组装注入）。
2. **文件与条目 API** ← 调用方 `Server.handleWorkspaceDir/File/FileWrite/EntryCreate/EntryCopy/EntryRename/EntryDelete/Search`
   与 `Server.resolveWorkspace`（`internal/agentd/workspacefiles.go`）。
3. **审阅素材**（diff、分支列举、审阅命令）← 调用方 `Server.handleTaskDiff` / `handleTaskBranches` / `handleTaskRun`
   与 `Manager` 的 diff 路径。
4. **新收的具名能力**（派发基线决议、删已建分支、本仓工作树枚举、仓库根探活、克隆前置校验、工作树探测）
   ← 调用方 `Manager.Dispatch` / `deleteCreatedBranch`、`reclaim.go`、`preview_owner.go`、`projectadmin.go`、
   `projecttree.go`、`cmd/project.go`。

假缝禁令：纯 import 路径重写不占接缝名额；包内白盒测试随代码迁移不占名额。

## 实现决定

- 迁移按文件整搬（上表），不重写方法体；随迁的包内白盒测试保持断言不变，只改包名与 import。
- `internal/agentd/workspace_capability.go` 的 `gitCapability` 与 `NewGitCapability` 删除；组装点
  （`cmd/agentd.go`、`server.go`）改为从 `internal/workspace` 取生产实现注入；`Manager.SetWorkspace` 接口不动。
- 代理参数与 fork 失败文案改为组装点注入，默认值保持今天的可观察行为（无代理时参数为空、无文案时不追加）。
- `RunCmdTimeout` 等被 `cmd` 引用的常量随实现迁移，调用点改指新包。
- 图产物：本分支视图 `codegraph/diffs/<分支>.json` 补迁出后的符号与边；
  `codegraph/domains/d_workspace.json` 的 lifecycle 锚改指本包符号；`target.json` 的条目与预算按实棘轮；
  `best.json` 的容器归属不动（`k_workspace_fn`/`k_workspace_model` 已在 `d_workspace`）。
- 命令名、HTTP 路径、事件类型、日志字段名不变。

## 测试决定

接缝 1（`Capability`）：agentd 侧集成测试保持绿——脏工作区拒发（`TestDispatchDirtyWorktree409`）、
仓库不可用（`TestDispatchRepoUnusable400`）、Stop 回收 managed（`TestStopRemovesManagedWorktree`）、
补偿回滚（`TestCompensateUserWorktreeRestores`）。变异：把 Prepare 的脏检查或回收判据挪出能力面 → 必须红。

接缝 2（文件与条目 API）：HTTP 级 `internal/agentd/workspacefiles_test.go` 全绿（行为不变的主证据）；
变异：拆掉路径逃逸闸或原子替换 → 必须红。

接缝 3（审阅素材）：`diffbase_test.go`、`workspace_run_test.go` 的断言不变；变异：diff 的三连点/两连点
或 `run` 的超时与输出护栏改错 → 必须红。

接缝 4（新收的具名能力）：每收一个能力配一支测试并指回本条缝（例：删已建分支后分支真不存在；
工作树枚举结果与 `git worktree list` 一致；基线决议的校验结论与新分支起点出自同一次计算）。变异：
具名能力绕过 git 直接改状态 → 必须红。

迁移完整性（非缝）：随迁的包内测试整批在新包下全绿；`go build ./...` 全量通过；受影响包的
`go test` 全绿。图侧：`codegraph check` fails 数不增（基线 0）、`codegraph validate` 通过、
抽查新符号 `codegraph sym <符号> --view <分支>` 命中。
