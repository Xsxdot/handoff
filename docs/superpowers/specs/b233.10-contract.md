## 3. 冻结身份 wire

### 3.1 入口与字段

入口保持：

```text
handoff dispatch / card dispatch --step
    → client.Client.Dispatch(ctx, client.DispatchOpts)
    → POST /api/tasks
    → Server.handleDispatch
    → Manager.Dispatch(ctx, DispatchReq)
```

`POST /api/tasks` 的本卡新增字段逐字段定义如下：

```go
// internal/client/client.go#DispatchOpts 与 internal/agentd/server.go#dispatchRequest
Carrier string `json:"carrier,omitempty"` // 冻结的具体载体名
Squad   string `json:"squad,omitempty"`   // 冻结时的来源小队名；载体直派为空
```

已有字段在冻结请求中的语义逐字段固定如下：

```text
receiver  = 原始接收者名，允许作为审计/选择输入；冻结请求不得用它重新选成员
target    = 冻结载体的机器字段，沿用本机目标归一化规则
executor  = 冻结载体的 CLI 字段
home_dir  = 冻结载体 HOME；冻结请求必须带键，空串表示显式使用目标机主 HOME
model     = 选择时形成的有效模型，不得由执行机按小队重新计算
```

三态规则：普通派发的 `HomeDir == nil` 继续表示请求未提供 HOME；冻结派发即使 HOME 为空，也必须发送 `home_dir: ""`。`carrier` 为空表示没有冻结身份；`carrier` 非空表示请求必须走冻结准入分支。`squad` 空串只表示载体直派，不得编码为 `squad//<carrier>`。

### 3.2 两条准入语义

普通派发保留既有语义：目标机从 `receiver` 或确认的默认载体解析接收者，并在目标机调用一次 `Service.Admit` 或 `Service.AdmitCarrier`。普通派发不由卡节点预先占用。

卡节点派发的新语义：

1. 起源侧调用 `Service.Select`，从小队选择一个在线载体并返回 `Binding`；该调用不得写 `sched_running`。
2. 起源侧把 `Binding.Squad`、`Binding.Carrier`、`Binding.Target`、`Binding.Executor`、`Binding.HomeDir`、`Binding.Model` 透传到既有 `POST /api/tasks`。
3. 执行机调用 `Service.AdmitFrozen(binding)`，只验证并占用 `binding.Carrier`；不得用 `binding.Squad` 再调用普通小队选择。
4. 执行机准入成功后，`Manager.Dispatch` 用同一 `Binding` 创建任务；任务的载体、机器、CLI、HOME、小队快照不得改写。
5. 执行机准入失败时，卡节点不得补做第二次选择；错误按当前错误语义上浮或由已有排队再入口处理。

### 3.3 精确新增空壳

Ticket 0 已在本轮落下列可编译空壳；实现票只能按本节语义接线，不得改名或另造同义入口：

```go
// internal/scheduling/scheduling.go
func (s *Service) Select(req IgnitionRequest) (Binding, error)
func (s *Service) AdmitFrozen(binding Binding) (Binding, error)
```

现状代码锚：`internal/scheduling/scheduling.go#Service.Select`、`internal/scheduling/scheduling.go#Service.AdmitFrozen`；二者当前均为 Ticket 0 空壳。

二者均位于既有 `d_scheduling` 域；不新增 `d_dispatch`、`d_receiver` 或第三条事件总线。`Select` 的输入使用既有 `IgnitionRequest`，其中 `Squad` 是选择范围；排队信封不保存冻结载体。`AdmitFrozen` 的输入使用既有 `Binding`，因此不复制一套身份 DTO。

### 3.4 P2 启动对账与耐久所有权

本节是本轮唯一契约增量。协调者已拍板：不新增 registry kind，不新增 reservation/attempt DTO；执行占用的耐久所有权是现有 `proto.Task` 的非终态快照。`Manager.Dispatch` 当前在 `internal/agentd/manager.go:1077–1110` 先构造 `State=pending` 的任务并调用 `Store.CreateTask`，而 `handleDispatch` 在此之前已取得执行侧绑定；实现票保持 `AdmitFrozen → CreateTask` 的顺序，不把 `CreateTask` 提前。

现有 `RecoverOnStartup` 在 `cmd/agentd.go:225–230`、HTTP 服务开始前调用；现状一次 `Store.ListTasks` 读全量任务，但其探活分支在 `internal/agentd/watchdog.go:493–495` 只筛 `running`、`waiting_answer`、`waiting_review`。P2 对账不得复用这个三态筛选：`pending` 任务也是已落盘的非终态所有者；`TaskState.IsTerminal` 的唯一终态集合仍为 `completed`、`failed`。

`sched_running` 记录按现有 `schedclient.Registry.List("sched_running")` 列出，匹配必须逐键执行：

- `carrier/<C>` 仅由至少一个 `Task` 满足 `!Task.State.IsTerminal()` 且 `Task.Carrier == C` 时持有；小队不同仍保护同一载体物理键。
- `squad/<S>/<C>` 仅由至少一个 `Task` 满足 `!Task.State.IsTerminal()`、`Task.Squad == S` 且 `Task.Carrier == C` 时持有；只同载体但不同小队不保护该成员键。
- 计数值大于零且没有对应非终态 `Task` 的单个键，必须在本次启动对账中释放到零；不得把无主键留给人工清理。
- 存在对应非终态 `Task` 的键不得因对账被释放或归一化；不得用释放成员键的成对副作用误减仍由活任务持有的载体键，反之亦然。

因此，`AdmitFrozen` 成功后至 `CreateTask` 成功前宿主崩溃，按“未落盘启动失败”处理；下次 `RecoverOnStartup` 对账看不到非终态任务所有者时，必须回收该次留下的 `sched_running` 无主键。处理完对账后，既有 handler 错误路径仍走 `handleDispatch` 当前的 defer 回滚；启动对账不是对该回滚的替代。

### 4.2 选择与单次准入

21. `Service.Select` 的选择范围是 `IgnitionRequest.Squad`。
22. `Service.Select` 返回的 `Binding.Carrier` 非空时，`Binding.Target` 非空。
23. `Service.Select` 返回的 `Binding.Carrier` 非空时，`Binding.Executor` 非空。
24. `Service.Select` 返回的 `Binding.HomeDir` 是选择时快照。
25. `Service.Select` 成功不得写入 `carrier/<name>`。
26. `Service.Select` 成功不得写入 `squad/<squad>/<carrier>`。
27. 卡节点满员时仍可将不带冻结载体的 `IgnitionRequest` 写入既有 `ignition_queue`。
28. 既有 `ignition_queue` 信封不得保存卡节点预选载体。
29. `Service.AdmitFrozen` 使用 `Binding.Carrier` 作为唯一载体选择结果。
30. `Service.AdmitFrozen` 不得按 `Binding.Squad` 重新挑选成员。
31. `Service.AdmitFrozen` 成功对 `carrier/<Binding.Carrier>` 计数加一。
32. `Service.AdmitFrozen` 在 `Binding.Squad` 非空时对 `squad/<Binding.Squad>/<Binding.Carrier>` 加一次一。
33. `Service.AdmitFrozen` 在 `Binding.Squad` 为空时不写成员键。
34. 冻结载体不在线时 `Service.AdmitFrozen` 必须失败。
35. 冻结载体已满时 `Service.AdmitFrozen` 必须失败。
36. 冻结物理身份不匹配时 `Service.AdmitFrozen` 必须失败。
37. 冻结准入失败不得回退到小队另一载体。
38. 无 `carrier` 的普通载体直派仍只占一次载体键。
39. `LaunchAdmit` 的协调者占用语义不受本卡改变。

### 4.3 任务身份与生命周期

40. 执行机成功准入后，任务 `Carrier` 等于冻结载体名。
41. 执行机成功准入后，任务 `Squad` 等于冻结来源小队名。
42. 执行机成功准入后，任务 `Target` 等于冻结机器身份。
43. 执行机成功准入后，任务 `Executor` 等于冻结 CLI 身份。

## 7. 拍板记录（三重闸门）

1. **身份选择与容量占用拆成两个 `d_scheduling` 入口。** 这是难逆转的跨编制、gateway、transport、orchestration 改动；无上下文时后人会想直接复用 `Admit`；真实取舍是拒绝「起源侧先占、执行机用 token 跳过」方案，因为跨机证明与起源 goroutine 提前释放会把占用事实拆成两套。显式不做：本卡不以 token 证明替代目标机准入。
2. **冻结 wire 同时携带 `carrier` 与 `squad`，`receiver` 退为审计/选择输入。** 这是跨机协议的难逆转字段语义；无上下文时后人会想让小队名继续作为执行机选择器；真实取舍是拒绝「执行机继续对小队 `Admit`」方案，因为它允许从 A 改落到 B。显式不做：执行 hop 不从小队名重新解析载体。
3. **任务持有的释放挂在终态成功迁移，而不是卡节点 goroutine 或镜像收流。** 这是生命周期跨 gateway、orchestration、scheduling 的难逆转归属；无上下文时后人会想在 goroutine 返回处清理临时占用；真实取舍是拒绝「起源临时占用 + 终态再补一次」方案，因为它产生 +2/提前归零。显式不做：卡列、节点 verdict、镜像终止均不触发任务持有的执行占用释放；P2 的无主键回收是启动对账的独立补偿路径。
4. **P2 以非终态 `Task` 快照作为执行占用的耐久所有权，并在启动时回收无主 `sched_running` 键。** 这是跨 scheduling、gateway、orchestration、agentd bootstrap 的难逆转生命周期裁决；无上下文时后人会想新增 reservation/attempt kind 或把 `CreateTask` 提前来覆盖崩溃窗口；真实取舍是保留 `AdmitFrozen → CreateTask` 顺序，拒绝新增持久 reservation DTO，以既有任务快照加启动对账闭合“准入后未落盘”的窗口。显式不做：不接受窄窗口泄漏交人工清理，也不把 `sched_running` 改成第三类 registry kind。该顺序若反过来写，在没有重启注入测试时既有测试未必变红，故以第 85–90 条冻结而不交给实现者顺手改写。
