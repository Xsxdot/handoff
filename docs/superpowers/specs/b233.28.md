本节点该干什么一律以注入的纪律块为准。

## 定级理由

跨 gateway 与 orchestration：任务查询/回迁、项目位置的访问规则要收进已有编排契约面，并改 best/target 对 store 的域归属。动契约层 → **L3**。工作量是扩既有门面 + handler 改走 + 图改挂，单轮可收 → **轻档**。不拆 SQLite 文件、不把登录做成编排 API。

## 问题陈述

谁：本机 HTTP 前台（gateway）还要读任务、回迁状态、查项目路径；登录和工作台也写同一份 store。

条件（`56c7a9c77`）：

1. 派发/Done/Stop/Continue/Recover 已走编排 client。**应答工单、列任务、读工单/事件、回迁 running、查改项目位置**仍直接打 `store.Store`（例如 `handleReply` 自己 `AnswerTicketApplied` / `AppendEvent`，`resumeIfIdle` 自己 CAS 改状态）。
2. 图把整个 `k_store_*` 算进 `d_orchestration`，所以登录会话、工作台偏好的 `s.st` 也算进 `d_gateway→d_orchestration` 的 76 条直调。check 绿只说明没超出这 76，不是边界封死。
3. 编排 client 已有任务生命周期、项目登记/列表、工作区透传。**没有**登录/工作台方法，也不该有。

要变的事实：

1. **任务面**：gateway 不再自己写任务库。读任务/工单/事件、应答工单、无待办后回迁 running，都经编排门面。回迁规则（何时 running、CAS 重试）归编排，不归 HTTP。
2. **项目位置**：查/改/列项目路径走编排门面上已有的项目能力，handler 不再直打 store。
3. **登录与工作台**：继续打 store，但图上不再算编排域。应然归 gateway。数字随改挂下降，不靠把 Session API 长到编排 client 上。

谁能观察到：HTTP 路径、文案、登录、工作台行为不变。维护者能观察到：任务/项目 handler 不再 import 编排内部 store；`codegraph check` 该方向预算只降不抬；登录/工作台不再出现在 `d_gateway→d_orchestration` 直调里。

## 方案

**做：**

1. 任务查询与任务状态变迁（含 reply 后回迁）收进编排门面；gateway 只调门面、转 HTTP。
2. 项目位置的剩余直打改走门面上已有项目能力。
3. 图：会话与工作台相关 store 容器/符号应然改挂 gateway 域；target 预算按重挂后的任务直调只降不抬。

**弃选：**

- 把 Session/Workbench 做成编排 client 方法：登录和工作台变成编排规则，错域。用户已否「76 全塞进 client」。
- 本期拆开 SQLite 文件：物理拆库不是收窄门面，另卡。
- 把 Hub/PullTracker 字段改成接口：类型依赖不是写库，用户同意本期可不动。

## 用户故事

1. 回答工单：落库、事件、唤醒/中继、无待办则回迁 running，对外行为与现在相同；gateway 不再自己 CAS 改任务状态。
2. 列任务、读单个任务、读工单/事件、镜像任务：走编排门面。
3. 按名查/改项目路径：走编排门面已有项目能力。
4. 登录、工作台：行为不变；图上不再计入编排直调。
5. `codegraph check`：`d_gateway→d_orchestration` 预算低于 76，且无新增 fails。

## 契约语义与接缝

- 任务状态机（含 waiting_answer → running 的回迁条件与冲突重试）在编排侧收口。gateway 不得再持一份 CAS 循环。
- 任务与项目的读写，外界只经编排契约面。允许该方向继续存在，预算随直调下降。
- 登录会话、工作台偏好不是编排契约。图上离开 `d_orchestration`；不新增编排→gateway 依赖。
- 不新增 HTTP 路径、不改命令名。

## 测试决定

接缝（符号 + 调用方）：

1. 编排门面上的任务查询/应答/回迁（HTTP 生产调用方：`POST .../reply`、任务列表/详情、工单相关 GET）。断言：gateway 测试只打门面；编排侧锁回迁规则（无待办才 running、冲突重试）。
2. 编排门面上的项目位置查询/更新（HTTP：项目管理、codegraph 按名取路径）。断言：不再直打 store。
3. 图：`codegraph check` 该方向预算下降；登录/工作台容器不在 `d_orchestration`。

假缝禁令：不为了覆盖分支把未导出纯函数当缝。
