## 问题陈述

handoff 仓是 charter 代码图（`github.com/Xsxdot/charter/graph`）唯一的真实消费者：agentd 把 charter 的 viewer 作为同源 iframe 挂在控制台 `/codegraph`，并暴露两个只读 HTTP 端点喂它数据；仓内 `codegraph/` 目录（7.2 MB：baseline / best / target / diffs / domains）是契约闸 `TestRepoContractGate` 与两条 B233.17 守卫测试的输入；执行者纪律块的平台不变量第 2 条命令执行者「查图只用已安装的 codegraph 二进制」，权限门则静默放行这些命令。上游已被删除（charter `d84d457`），go module 的 tag `v0.10.2` 只活在 git 历史里。继续保留这些消费面只剩三种后果：构建依赖一个已死的模块；控制台留一个指向不存在 viewer 的入口；每个执行者回合被纪律块逼着去找一个不再存在的二进制。

承重歧义一句话：**哪些东西属于「代码图的消费侧」要连根删，哪些是以代码图为证据出处的历史记录要原样留，删完之后原来由图承担的「架构边界执法」由谁接手。**

## 方案

**一次性连根删除全部消费面，架构边界执法回到既有源码级守卫与架构法人工清单，不建任何替代工具。**

逐面处置：

- **A** 删 `go.mod` 依赖，主模块与 `desktop/` 各跑 `go mod tidy`；删 `codegraph/` 整个目录。
- **B** 删两个端点、两处路由、SPA 挂载与日志、`charterwebui` import、`codegraph_test.go`、`TestCodegraphRoute`、测试夹具；`b23328` 清单去掉 `codegraph.go`；两处注释改写（见 J）。补一条锁：`GET /api/projects/{name}/codegraph` 走 httptest 全栈必须 404（api 子 mux 无兜底，这是现成行为，锁住即可）。
- **C** 删 `graph_gate_test.go`；删 b23317 两条读 `target.json` 的测试，**保留**同文件里不依赖图的嵌套 internal import 守卫与 handler 定义守卫；`pointer_gate_test.go` 白名单去掉六条 `codegraph-rescan` 条目。
- **D** 不动，`TestRootRejectsDeletedGraphCommand` 继续当锁。
- **E** 平台不变量删第 2 条、余下三条顺序重编号，测试同步改为「正文不得再出现 codegraph」；权限门删 `"codegraph"` id、子命令闭集、旗标表与 `safeCommandID` 分支，测试改为 `codegraph sym X` 判 Consult（未登记命令的缺省路径）。`SafeCommandIDs` 变化导致政策快照 Version 哈希变化，属预期，无 golden 断言。
- **F** 删 `CodegraphFrame.tsx`、Route、整页路由白名单项、两个回调 prop 与其全部渲染分支（项目行子钮、dock 钮、右键菜单项、紧凑态门控）、两个 API 函数、Cg* 类型族；删对应测试用例；两处夹具文案改成现行名字（`图对账`→`最终验收`，`recon`→任一非保留词如 `audit`）。
- **G** 删两个 `scripts/` 扫描器；删 `docs/codegraph-scan-recipe.md`（操作手册，对象已不存在）；**保留** `docs/codegraph-best-rationale.md` 与 `docs/2026-08-22-codegraph-batch-handover.md`（拍板记录与交接文档，是历史）；删 `deploy/workflows/` 整目录；删两份 ignore 文件的 `prototypes/codegraph/` 行；`mobile/android/README.md` 排除清单去掉 `codegraph/**`；原型基准站删 `pages/codegraph.html`、`data/graph.json`、`data/graph.js`、`index.html` dock 钮、README 两处；`docs/roadmap.md` 删去**主语是代码图数据或工具**的条目（判据：去掉代码图这个对象后该条不再有可做的事），代码图只作证据出处的条目原样留，并新增「来自 B436」节。
- **H** 账本两块 recon 纪律块无删除手段 → 落 roadmap「后续要做」；不改账本。
- **I** 不动 CI 定义；本地复跑 CI 同款命令取证。
- **J** 三处注释把「`codegraph/target.json` 已声明」改写为对架构法依赖方向的陈述，**不删架构论断本身**（它们约束的是依赖方向，不是图）。
- **CHANGELOG** `[Unreleased]` 新增「### 移除」一条：控制台代码图页、agentd codegraph 端点、权限门 codegraph 放行、纪律块查图条目一并移除，引用 B436 与用户裁决原话。

### 弃选与理由

| 弃选 | 为什么不选 |
|---|---|
| 保留权限门 `codegraph` 白名单（「反正无害」） | handoff 不再有任何代码图概念，一个指向不存在工具的放行项是误导；B376 的闭集逻辑也随之成为死代码 |
| 把 b23317 两条测试改读别的配置继续锁门面预算 | 它们锁的对象是 `target.json` 的数字，对象没了就没有可锁之物；真正有牙的源码级守卫（嵌套 import、handler 定义、指针路由）保留，这是用户「人工清单不依赖图工具」裁决的落地 |
| `deploy/workflows/charter-v4.json` 搬去 `docs/archive/` | 它是 v4 时代「待应用」的草案，账本是权威且已装 v14，没有读者；搬动只是换个地方留一份 `图对账` 命中 |
| 删 `docs/codegraph-best-rationale.md` 与批次交接文档 | 它们是拍板记录，与 `docs/` 下旧 spec/ledger 同类，按「历史文档不改写」保留 |
| 另建一个轻量「依赖方向对账」脚本接替契约闸 | 用户裁决是删除而非替换；架构法明文「对照一律是人工清单，不依赖任何图工具」 |

## 定级两问

1. **跨几个子系统的契约面？** 改动触及网关、控制台前端、权限门、纪律块、cmd 测试与文档，按架构法字面确属多个子系统。但本卡**只删不建**：不新增任何接缝、不改任何存量契约的语义、不新增依赖方向；被删的 HTTP 端点与 viewer 挂载的唯一消费者（charter webui）已随上游一起消失，contract 与 breakdown 两个节点的产出都会是空文档。
2. **动不动契约层？** 不实现、不对接任何跨仓 wire 契约；`charter/graph` 是被移除的依赖，不是被对接的契约。

判决 **L2**：plan 节点产出有实质内容（删除顺序、每面的验证命令、roadmap 裁剪判据），不满足 L1「plan 增量为零」；但不进 contract / breakdown。若用户认为应按字面判 L3 轻档，纠偏是把卡从 plan 列迁到 breakdown 列并带着本 spec，不重建卡。

## 实现决定

- **删除顺序**：先 A（依赖与数据）让编译器把所有 import 与读文件的测试一次性报红，再按 B → C → E → F → G → J 清到绿；最后 roadmap 与 CHANGELOG。顺序只服务于「让失败集中暴露」，不是分批提交的边界。
- **架构边界执法的接替者**：`TestB23317GatewayProductionDoesNotImportNestedInternals`、`TestB23317AssemblyFilesHaveNoHandlerDefs`（及其有牙哨兵）、`TestPointerRouteAbsentFromSource`、`TestB23328GatewayNoDirectStoreTaskProjectCalls` 四条源码级守卫原样保留；它们从未依赖图数据（`pointer_gate_test.go` 文件头已论证图闸看不见源码级新增调用）。
- **b23317 的 assembly 名单**：`TestB23317AssemblyFilesHaveNoHandlerDefs` 若依赖 `target.json` 的 assembly 列表，改为在测试内显式列出名单文件（现状即 `server.go` 等插线文件），由 implement 在工作树复核后定；判据是「不读 `codegraph/` 下任何文件」。
- **平台不变量**：删第 2 条后余三条重编号为 1-3；收口自查句不变。
- **权限门**：删 id 后 `SafeCommandIDs` 长度减一；不保留兼容别名。
- **前端**：不留 feature flag、不留空壳组件；`ProjectTree` 的两个回调 prop 删除后，所有以它们为门控的渲染分支与注释一并清掉（含紧凑态 B369.7 注释里对 `/codegraph` 的提及）。
- **roadmap 裁剪判据**：条目主语是代码图数据、扫描器、viewer、图覆盖债、预算棘轮 → 删；条目讨论的是别的事而以代码图为证据出处 → 留。新增「## 来自 B436 finish（2026-10-18）」一节，首条即账本 `charter-recon` / `charter-story-recon` 两块纪律块待下架、需 `handoff discipline` 增加删除或下架能力。
- **用户可见文案**：CHANGELOG「### 移除」条目引用 B436 与裁决原话；控制台不新增任何提示（入口消失即是全部）。
- **提交说明**：每个提交 footer 引用 `B436` 与用户 2026-10-18 裁决原话「直接把代码图彻底删除，handoff 里面的功能也删除」。

## 测试决定

- **真实入口**：HTTP 用 `webroute_test.go` 既有的 `consoleTestEnv` 走 httptest.Server 全栈（mux 注册、auth、方法裁决一起测）；CLI 用既有 `TestRootRejectsDeletedGraphCommand`；前端用 Shell / ProjectTree 的现有渲染测试改断言为「入口不存在」；权限门用 `safeCommandID` 表驱动；纪律块用 `Compose` 测试。
- **断言方向**：删除类卡的测试全部是**否定断言**（入口不在、命令不被放行、正文不含），每条都配有现成的肯定对照（同文件其它入口仍在），避免「全文件删光也绿」的假绿。
- **假缝禁令**：本卡不新增任何导出符号，不为测试抽纯函数。
- **全量证据**：S4 的命令清单原文与退出码进台账与 `card accept --evidence`。
