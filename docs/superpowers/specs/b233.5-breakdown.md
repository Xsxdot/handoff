### 4.1 通用五族

**生命周期 / 状态机中断**

- 准入 +1 之后、`CreateTask` 之前崩溃：计数偏高（保守，不超发）。收口靠 Release 幂等与人工/GC 类入口；裸路径必须有 T4 钩子，否则泄漏到满员。
- `CreateTask` 成功、`ad.Start` 失败：既有 transit failed + compensateWorkspace；本卡加 Release。两者都要发生，缺 Release 是假满。
- 卡节点排队：本轮不 +1（既有），agentd 重启后队列在 registry，清队再 Admit。本卡不改清队。
- agentd 重启：占用权威在 `sched_running`，内存无计数。任务行有 Carrier/HomeDir 才能在终态释放对的键；T5 没落盘则重启后不知道释放谁。
- `releaseSchedulingBinding` 空小队跳过 = 载体直派孤儿计数。T4 必须改。
- **无新孤儿进程/工单表，因为**不新增 executor 进程模型；新增的是 registry 计数与任务列。
- 半程 CAS：既有小队侧回滚。载体直派只有一级，失败不留成员键。

**静默失败 / 误导报错**

- 无默认却成功派到 `executor.default` = 报成功但没走载体。T2/T7 消灭。
- `--executor grok` HTTP 200 但实际跑载体 CLI ≠ grok = 误导。必须拒绝或帮助写清「不再选落点」。
- `ErrNoDefault` 文案必须可行动（去设置默认 / 传 `--receiver`）。具体写入口见 P3。
- 名称冲突若按载体优先静默成功 = 禁止。
- Start 失败却报占用成功 / 计数不回滚 = 假满。
- Stop 成功但 `Squad==""` 没释放 = 假满。
- show 里没有 carrier（新任务）= 绑定身份丢失。

**跨平台假设**

- 占用键与载体名是逻辑字符串，不用路径分隔。**无新路径假设，因为**不把 HOME 拼进键。
- HOME 值仍是目标机路径，由 233.2/载体登记解释；本卡只快照字符串。Windows HOME vs USERPROFILE **未验证，需真机**（沿用既有 withCarrierHome）。
- CLI `--receiver` 在 PowerShell 引号下的空串 vs 缺席 **未验证，需真机**。
- 不引入 webview 新假设，除非 P3 改 SchedulingPage。

**假红 / 假绿测试**

- Ticket 0 金样本锁编码，不是「Dispatch 已走默认载体」。不得把空壳当故事 1 完成。
- `TestEffectiveCoversParityMatrix` 的「请求压过节点」行在新语义下必须退役，否则新实现假红；若改测试仍要求覆盖物理则假绿。
- `TestSquadNodeAdmitsAndDispatchesThroughBinding` 锁的是调用方依赖的落点与计数，换 BindPhysical 实现不应无意义地红（仍要 target=载体 machine）。
- 夹具可以编码「ResolveLookup 返回 muse 但 Dispatch 仍用 default」的世界——反面断言是任务 Executor/Carrier。
- 全包测试若遇沙箱 `Operation not permitted`：记原文，不归因。

**门禁绕过**

- 物理覆盖门是 `BindPhysical`。两条入口（裸 HTTP、卡节点）必须问同一函数，不能 `bindingFor` 或 `effectiveCovers` 另开覆盖通道。
- `--executor` / body `executor` 与卡 `--executor` 是同一道门的两个表面。P10-(a) 卡表面更严（直接拒绝），仍不得在裸路径放行覆盖。
- 同名写入门是 `CrossKindConflict`，PutCarrier/PutSquad/（若有）HTTP PUT 都要经过 Service，不能 HTTP 直写 registry。
- TOCTOU：Admit CAS 与 Start 之间别人再 Admit——既有 maxCASAttempts。检查「有空位」与 +1 仍在同一 acquire 循环。本卡不改。
- 权限扩大：模型覆盖不得改政策快照（冻结 44）。本卡不改 permgate。

### 4.2 追加设问

**序列化边界**

- 新增/冻结字段：`Task.carrier`、HTTP `receiver`、`Binding.home_dir`、默认载体 `{"name"}`。
- 手写投影：`Client.Dispatch` map（`receiver` 非空才写）、`handleDispatch` 解码 `dispatchRequest`、`CreateTask` INSERT、`scanTaskRow`、CLI 若打印 carrier、Web `Task` TS 镜像。T5 列清单并加断言。
- `EncodeDefaultCarrier`/`DecodeDefaultCarrier` 已有 roundtrip；生产读写必须调用它们，不得手搭 map。
- 用可空/`omitempty` 区分缺席与空串：`receiver` 空缺席=走默认；`carrier` 空缺席=旧任务。禁止用 `"0"` 或空对象冒充。
- `IgnitionRequest` 若因 P8-(b) 加字段：队列 JSON 必须有一条穿过真实 Marshal 的测试。默认不选。

**枚举新值过既有白名单**

- `ReceiverKind`：`carrier`/`squad`。流经 Classify 与任何 switch；不得手写 `"Carrier"`。
- `KindDefaultCarrier`=`default_carrier` 是新 registry kind。`putEntity`/`List` 按 kind 分表，不进载体名空间。`current` 不得当接收者名（冻结 22）。
- 不新增 TaskState / EventType。
- `Occupancy` 键前缀 `carrier/` 与 `squad/` 已存在；空小队不得新造第三种前缀。
- HTTP 状态映射是拍板项，不是新枚举类型。

**承重安全属性（必须能变红）**

| 属性 | 锁在哪 |
|---|---|
| 无默认不得回退 `executor.default` 当接收者 | T2+T7：空 receiver + 无默认 → 失败；夹具里 default CLI ≠ 载体 CLI |
| 绑定后不可覆盖 Machine/CLI/HOME | T1+T2：overlay 不同值 → `ErrPhysicalOverride` |
| 名称冲突不猜 | T1+T2：两边都有 → `ErrNameConflict` |
| 空小队不写 `squad//x` | T1：OccupancyKeys + Release |
| 启动失败释放占用 | T4：计数回到准入前 |
| 恢复不双计 | T4：continue 零次 Admit |
| 历史任务不被活载体改写 | T3：PutCarrier 后 GetTask 仍旧 HOME/Target |
| 编制不读卡列 | T1：scheduling 包 import 负例 |
| `Task.carrier` 穿过 SQL+JSON | T5 |

**webview / 平台表现差异（项目第六族候选）**

- P3-(a)/P2 默认不改浏览器 API。**无 webview 新风险，因为**不改控件，只可能改 Task 类型可选字段。
- P3-(b) 若改 SchedulingPage：必须逐平台验「设为默认」点击，不能拿一个 webview 的绿推广。该项进 §5。
