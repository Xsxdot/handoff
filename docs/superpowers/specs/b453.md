# B453 账号与额度：手工登记账号、定时主动探测、派发看账号额度

> 状态：r1 草稿，待用户批准（2026-10-22）。
> 级别：**L3**（跨子系统：账本 registry 新增账号实体；编制/调度域准入判据改变；agentd 新增周期探测与跨机读数；执行器回合失败分类；Web 控制台新页面 + 全局底栏；对接三家外部额度接口——外部 wire 契约按「动」计）。
> 执行形态：**甲 本地盯**（判据第 1 条：验收要真机读三家真实账号额度、要在役机队升级；第 2 条：opencode-go 用量接口未验证，新接缝要在首故事里长出来）。不扇出子卡：一张卡、单分支 `cards/B453-charter-1`、按故事顺序串行实现。
> 原型：`prototypes/b453-accounts/`（fork 自 base，未入库），`prototypes/base/README.md` 已记「确认中」。验收以该原型为形态基准。
> 台账：`docs/superpowers/specs/b453-ledger.md`。事实：`b453-facts-code.md`（代码现状）、`b453-facts-orca.md`（orca 实现）、`b453-facts-providers.md`（外部接口）。

## 问题陈述

载体背后是真实的订阅账号，额度会被用完。今天 handoff 对此几乎无感：

- 载体有「限额中」一态，但只有人点「检测」、检测回合恰好撞额度时才写入（现状读数 `internal/scheduling/status.go:113-119`、`docs/roadmap.md:590`），派发前从不知道额度还剩多少；
- 同一个账号可以被多个载体共用（同 HOME、或 opencode 载体用 codex 额度），载体级的状态管不到账号级的真实池（`docs/roadmap.md:600`）；
- 任务中途撞额度只表现为任务失败，只读任务不会自动换人，分支任务停下也说不清原因（`docs/roadmap.md:986`）。

本卡把「账号」立为账本里的独立实体：人手工登记，账号所在机定时主动探测额度，派发前看账号状态跳过低额度/无额度的，只读任务撞额度自动换小队成员重跑，分支任务撞额度标无额度、停下并发工单。控制台加「◔ 账号」页和全局底栏额度条，移动端放在设置页。

## 方案（含弃选与理由）

**选：账号为账本独立实体，载体引用账号。** 账号 = 一份订阅凭据在某台机器上的落点（kind + 机器 + 凭据 HOME + 凭据条目），由人登记；载体编辑时从同机账号里选一个（可不选）。派发判据从「载体状态」移到「载体所选账号的状态」。

弃选：
- **从载体自动推导账号**（按 HOME/凭据文件归并）：同厂商多账号时推不准，用户已否（「自动推导的对于同厂商多账号不太友好」）。
- **派发失败后被动读回额度**：用户已定主动探测。
- **桌面菜单栏**：用户定「做控制台底栏了就不用做菜单栏了」。
- **探测凭据与推理凭据分填**：只在阿里 Token Plan 需要，阿里已出范围；三种 kind 的探测凭据就是 CLI 自己的登录凭据。

## 落位三问

① **读写谁的权威数据**：账号定义与最新探测读数是新的权威数据，归编制域（与载体、小队同处账本 registry，新 kind）；探测读数由账号所在机写入，调度只读；载体对账号的引用归载体记录本身（`architecture-law` 第五条）。
② **谁消费**：调度准入（同进程，导出符号）；Web 控制台与 CLI 经 agentd HTTP 契约面；跨机探测的触发与结果经 agentd 机间契约面（第四条，第 3 档）。
③ **同步还是异步**：探测是周期性的后台事实刷新，调度读最近一次读数，二者不等对方（第十二条三问全否：派发不等探测结果；探测失败不回滚派发；探测方不需要知道谁在消费）。「任务撞额度 → 标无额度」是任务收尾路径上的同步写入（下一次派发必须看见它）。

## 全部必交用户故事

> 环境：**真机** = 在役机队（mac-mini 协调、linux-01、macbook-pro）的隔离 agentd 实例 + 测试账本，最后升级机队后再做生产冒烟；**原型** = `prototypes/b453-accounts/` 对应页面与状态。

### S1 登记账号（三种 kind）
人在控制台「◔ 账号」页点「＋ 登记账号」，填：账号名（唯一、登记后不可改）、类型（opencode-go / codex / grok）、所在机器、凭据 HOME（该机路径）、凭据条目（缺省按 kind 预填：opencode-go = opencode 的 `auth.json › opencode-go`；codex = `auth.json › tokens`；grok = `auth.json › https://auth.x.ai`）、代理（可选）、探测间隔（5/10/15/30/60 分钟，缺省 15）、预警线（缺省 60%）、低额度线（缺省 80%）。保存后账号出现在列表与底栏，状态「未探测」，所在机随即探测一次。
- 编辑走乐观锁（与载体同一套 version 语义），名称不可改；删除时若有载体引用它，拒删并列出引用的载体（原型 `pages/accounts.html` 删除对话框）。
- 校验：预警线 < 低额度线 ≤ 100；凭据 HOME 必须是绝对路径或 `~` 开头；同机同 HOME 同条目重复登记拒绝。
- 关键失败：所在机离线时保存成功、状态停在「未探测」，探测失败在卡片上写原因。
- 验证：真机，三种 kind 各登记一个真实账号。原型：`pages/accounts.html` 登记对话框。

### S2 所在机定时探测，读数落账本（首故事）
账号所在机的 agentd 按账号的探测间隔读本机凭据、调该 kind 的额度接口、把读数写回账本。读数 = 每个窗口的已用百分比与重置时刻 + 套餐（planType）+ 额外额度（有则带）+ 凭据短指纹 + 探测时刻；失败写失败原因并**保留上一次成功读数**。
- 三种 kind 的接口（外部现实，执行节点按 `b453-facts-orca.md` §1 复核）：
  - **opencode-go**：`GET https://opencode.ai/zen/go/v1/usage`，`Authorization: Bearer <opencode-go API key>`，读 rolling(5h)/weekly/monthly 的 percent 与 resetsAt；401 = 凭据无效，403/EntitlementError = 无订阅。**未经验证**——首故事第一件事就是用真实账号证实；证伪时其余 kind 照做，opencode-go 记为欠交（不改走 cookie 路径、不算通过），等用户回来裁决。
  - **codex**：`GET https://chatgpt.com/backend-api/wham/usage`，Bearer `tokens.access_token` + `ChatGPT-Account-Id: tokens.account_id`；primary/secondary 窗口按 `limit_window_seconds` 归 session/weekly；`allowed=false` 或 `limit_reached=true` 直接判无额度。
  - **grok**：`GET https://cli-chat-proxy.grok.com/v1/billing?format=credits`（失败回退 `/billing`），Bearer `key` + `X-XAI-Token-Auth: xai-grok-cli`；`creditUsagePercent` → weekly，`used/monthlyLimit` → monthly，`subscriptionTier` → planType。
- 三种 kind 都**只读凭据、绝不刷新或改写凭据文件**；token 过期报「凭据已过期，等待 <CLI> 刷新（在该机执行 <CLI> login）」。
- 代理：账号填了代理就只用它；没填沿用该机 handoff 进程的出网代理环境。
- 节奏：成功后按间隔；失败按 30s×2ⁿ 退避、封顶为该账号的探测间隔；最后成功读数超过 30 分钟标「已过期」。
- 「立即探测」按钮：触发所在机马上探测一次（远程机经机间转发），返回新读数。
- 密钥不离机：账本、API 响应、日志、任务事件里只出现凭据位置与短指纹（sha256 前缀），永不出现密钥本身；HTTP 头不进日志。
- 验证：真机，三个真实账号各跑满一轮定时探测 + 一次立即探测；断网/错代理得到「探测失败」并保留旧读数；改坏凭据得到 401 文案。表驱动测试覆盖三家响应体解析（解析入口即缝上符号）。

### S3 账号状态与阈值
账号状态由读数推出，五档：**未探测**（从无读数）、**探测失败**（最近一次探测失败，旁注沿用的旧读数）、**无额度**（任一窗口 ≥ 100%，或接口明示不可用，或被任务撞额度标记）、**低额度**（任一窗口 ≥ 低额度线）、**正常**。预警线只改颜色（黄），不影响状态。
- 「被任务撞额度标记的无额度」持续到下一次**成功**探测给出新读数为止；探测失败不清除它。
- 验证：单测覆盖推导表；真机把某真实账号低额度线临时调到当前已用以下，状态变低额度、调回后复原。原型：`pages/accounts.html` 卡片各状态。

### S4 载体选账号，载体不再有「限额中」
载体登记/编辑对话框多一个「账号」下拉，只列载体同机的账号，可不选。载体详情显示所选账号与其状态。
- 载体四态去掉「限额中」：存量处于限额中的载体读作已上线；检测回合撞额度时不再把载体写成限额中——载体按已上线处理，绑定了账号的把该账号标无额度，没绑定的把额度原因写进载体的最近错误。
- 指纹比对：载体检测时，载体 HOME 里按所选账号 kind 的凭据条目算短指纹，与账号最近读数的指纹比对；不一致在载体行与编辑对话框标红（原型文案），**可以保存、不拦派发**。
- 账号代理随载体生效：载体所选账号填了代理时，该载体的任务回合与检测回合都走这个代理（覆盖执行器 env 文件与机器环境里的代理键）；未选账号或账号未填代理时与今天一致。
- 验证：真机，载体选账号、检测、故意绑错同 kind 另一账号看到标红；给账号填一个本机代理，派一个任务从任务环境读到该代理；`handoff squad list` 与 `GET /api/squads` 的载体行带所选账号名。原型：`pages/settings.html?section=automation`。

### S5 派发跳过低额度 / 无额度
凡调度为一次派发挑选载体（执行者小队选人、协调者拉起、熟练工派发、按载体点名派发），**所选账号状态为低额度或无额度的载体视同不可用**；未选账号、账号未探测或探测失败的载体照常可用。
- 小队里所有成员都因账号被跳过时，派发失败，文案点名每个被跳过的载体、其账号、状态与预计恢复时刻（最早相关窗口的重置时刻），例如「mini：账号 og-mini 无额度，预计 2h41m 后恢复」。
- 点名到某个载体（`--receiver` 等）而其账号低额度/无额度：同样拒绝、同样文案，不静默跑。
- 已在跑的任务不受影响（不中断）。
- 验证：真机，把小队中一个成员的账号阈值调低使其低额度，连续派发都落到另一成员；全部成员低额度时得到点名文案。

### S6 只读任务撞额度，自动换成员重跑
只读任务（熟练工模板任务、只读模式任务）运行中因额度耗尽失败时：
1. 判定撞额度（判据按载体执行器的失败输出分类，覆盖三种 kind 的额度错误特征：opencode-go 的额度/EntitlementError 返回、codex 的 `insufficient_quota`/`usage_limit` 类错误、grok 的额度错误；分类不确定的不算撞额度，按普通失败处理）；
2. 把该载体所选账号标无额度（未选账号的只在任务失败原因里写明额度耗尽）；
3. 原任务以「额度耗尽」结束，在同一小队里按 S5 规则另挑成员，用同一份输入重跑一个新任务，两者互相链接（时间线可见「因额度耗尽改由 X 重跑」）；
4. 发起方的 `dispatch --wait` / `wait --final` 透明跟到新任务，最终退出码与产物取自新任务；
5. 没有可换的成员时，原任务以额度耗尽失败，文案同 S5。
- 每个账号在同一次重跑链里只用一次，防循环。
- 验证：真机，用一个真实撞额度场景（或经测试注入执行器额度错误输出的隔离载体）派熟练工任务，观察换人重跑与 `--wait` 拿到新任务结果。

### S7 分支任务撞额度，停下并发工单
写分支的任务撞额度时：把账号标无额度，任务停下（不自动换人、不丢工作树），开一张待人处理的工单，写明载体、账号、撞到的窗口与预计恢复时刻、分支与工作树位置，以及「接管见 B459」。发起方的 `--wait` / `wait --final` 按 B460 规则以退出码 5 交回工单。
- 验证：真机，同 S6 的注入方式派一个分支任务，得到工单与退出码 5。

### S8 控制台「◔ 账号」页
侧栏 dock 新增「◔」图标进入账号页（视觉照 orca 设置页「AI 提供商账户」：灰阶、细边框卡片）。按类型分三组（OpenCode Go / Codex / Grok），每组一行说明与「＋ 登记账号」；组内每个账号一张紧凑卡片：账号名 + 套餐小标 + 状态短语；弱色一行 `机器 · 凭据位置 · 指纹`；各窗口紧凑横排（窗口名、细条、已用%、重置倒计时）。点开展开代理、两条阈值、探测间隔、上次/下次探测、引用它的载体；操作 立即探测 / 编辑 / 删除。
- **色彩纪律**（S8–S10 共用）：整体灰阶；彩色只落在越线的数字或状态短语本身——已用 ≥ 预警线的百分比与「低额度」为琥珀色文字，「无额度」为红色文字，探测失败为弱色「△ 原因」，未探测为弱色「··· 未探测」，正常不加标记；不用彩色药丸、色块背景；进度条细、中性灰填充，越线才改色。
- 验证：浏览器熟练工对照原型 `pages/accounts.html` 逐项核。

### S9 全局底栏额度条
控制台所有页面底部一行弱色小字（照 orca 底栏），开头「已用」，问题账号排前（无额度 > 低额度 > 探测失败 > 未探测 > 正常），最右刷新，窄屏溢出收纳为「+N」。点击弹出「使用量」弹层，有「详细 / 精简」两种模式（记住选择，缺省详细），**底栏随模式变**：
- **层级**：弹层按类型分组（OpenCode Go / Codex / Grok，组内问题账号排前）；图标只在组标题上，账号行不带图标并相对组标题缩进，两层一眼可分（精简同）。底栏不分组，每段带单色图标。
- **详细**：每个账号两行——第一行账号名、机器、最早一个窗口的「x 后重置」；第二行该账号全部窗口排在同一行（`5h ▬ 34%  周 ▬ 58%  月 ▬ 22%`，没有的窗口不占位）。底栏每段 = 图标 + 账号名 + 短细条 + 该账号最短两个窗口的「已用% 倒计时」。
- **精简**：弹层每个账号一行，只显示每周窗口的倒计时与已用%；底栏每段只显示每周窗口。
- 两种模式下问题账号都以状态短语代替数字：无额度 `无额度 <恢复倒计时>`；低额度 `低额度 · <触发窗口> <已用%>`；探测失败 `△ 短因`（有旧读数时窗口照画但降为弱色）；未探测 `··· 未探测`。
- **一切细节在 hover（触屏/键盘为点击/聚焦）时的右侧二级面板里看**：各窗口细条与「已用 x%」「x 后重置」、额外额度、失败原因与读数时刻、所在机器、使用此账号的载体、立即探测。弹层底部「使用详情」「管理账号…」进账号页。数据随账号读数自动刷新，无需整页重载。
- 验证：浏览器熟练工对照原型各页面底栏与弹层（`index.html`、`pages/board.html`、`pages/settings.html` 等）。

## 目标架构与接缝语义

- **账号实体**归编制域，存账本 registry 新 kind（纯新增 kind，不改表结构，不升 `ledgerSchemaVersion`——现状读数 `ledger/schema_version.go:19-22`；若实现需要改表则必须升版本）。账号名与载体名、小队名同一名字空间防冲突与否由 plan 定。
- **读数归属**：账号定义由人写（控制台/API）；最新读数由账号所在机写。二者是同一实体的两部分，写入互不覆盖（人编辑不抹读数，探测写读数不碰定义）——具体用同记录分字段还是分记录由 plan 定，但必须保证并发下互不丢写。
- **探测执行权**：只在账号所在机执行（凭据只在那台机器上）；协调机或任一控制台发起「立即探测」经 agentd 机间转发到所在机。所在机离线 = 读数不更新，不由别的机器代探。
- **外部接口适配**：三种 kind 各一个适配，输入为凭据位置 + 代理，输出为统一的窗口读数；适配只在 agentd 内部，按 kind 注册，新增 kind 不改调度与界面。
- **调度准入**：所有挑选载体的准入点统一经一个判据「载体可用 = 载体已上线 且 账号不在低额度/无额度」，不得在各准入点各写一份（现状读数：准入点散在 `scheduling.go:428/618/714/838/1069`）。
- **撞额度分类**：执行器回合失败的额度分类与检测链已有的额度分类收口为同一处判据（现状读数 `hostapi.classifyTurnError`），按载体执行器 + 账号 kind 判。
- **重跑链**：只读任务换人重跑是任务编排层的动作（新任务 + 链接），不在执行器适配里做；`--wait` 跟链在客户端等待逻辑里做。
- **前端**：账号 API 一组新端点 + `GET /api/squads` 载体行增加账号名；底栏挂在控制台外壳，所有页面共用一份数据源与刷新节奏。

## 首故事

**S2 + S1 的最薄后端竖切：一个真实 opencode-go 账号（mini@mac-mini 的 HOME），登记（API 即可）→ 所在机探测 → 读数落账本 → `handoff account list` 看到窗口读数。** 它最早暴露两个承重未知：opencode-go 用量接口能否用 CLI 落盘的 API key 查通（未验证）；跨机读数写回与人编辑并发的落位。后续 codex/grok 适配、调度跳过、撞额度、前端都依赖这两条结论。证伪 opencode-go 接口时首故事改用 codex 账号走同一竖切，opencode-go 记欠交待用户裁决。

## 实现决定

- 用户可见名字：账号页「◔ 账号」、底栏「◔ 额度」、状态词 正常/低额度/无额度/探测失败/未探测、CLI `handoff account list|probe`、配置项缺省 间隔 15 分钟 / 预警 60% / 低额度 80% / 过期 30 分钟。
- 载体状态词表删除「限额中」，前后端同一份词表同步删。
- 账号 kind 只收 `opencode-go`、`codex`、`grok`；未知 kind 拒绝登记。
- 账号代理的优先级：账号代理 > 执行器 env 文件里的代理键 > 机器进程环境；账号未填代理时行为与今天完全一致。
- 内部符号、文件落点、端点路径由 plan 定。

## 测试决定

- 解析：三家响应体表驱动（含 401/403/429/字段缺失/秒与毫秒时间戳），解析入口即外部缝上的符号。
- 状态推导：表驱动覆盖五档与「撞额度标记直到成功探测」。
- 准入：各准入点经统一判据的测试，含点名派发被拒文案。
- 撞额度：执行器失败输出分类表驱动；重跑链与 `--wait` 跟链用伪执行器集成测试。
- 前端：账号页、底栏、载体对话框单测锁接缝；浏览器熟练工对照原型做形态验收（含色彩纪律：同屏彩色只出现在越线数字与状态短语上）。
- 真机：隔离 agentd + 测试账本，三个真实账号（opencode-go@mac-mini、codex 与 grok 按实际登录所在机），最后升级机队后生产冒烟（`handoff account list` 读到三家读数 + 一次正常熟练工派发）。
- 密钥审计：真机跑完后在账本、agentd 日志、任务事件里搜三个账号的密钥前缀，零命中。
