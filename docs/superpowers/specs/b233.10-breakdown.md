### P2｜冻结准入成功后、任务落盘前宿主重启的占用所有权（阻塞项）

现有 `handleDispatch` 的静态顺序是“目标侧准入 → `Manager.Dispatch` 创建任务”；返回错误才走 handler defer 回滚。若宿主在这段窗口直接重启，当前 contract 没有耐久 reservation/attempt 所有权，`RecoverOnStartup` 也没有被证明能定位这笔尚无 Task 快照的占用。该行为尚未真机验证，不能把“defer 会执行”当成重启结论。

- **方案 A：** 回退 contract，冻结一个可恢复的执行占用所有权（例如带 task/attempt 关联的 registry reservation），并定义 agentd 启动对账与回收。优点是覆盖重启窗口；代价是新增持久契约、状态机和跨机一致性审查。
- **方案 B：** 回退 contract，重排生命周期为先持久 Task/attempt 快照、再执行冻结准入；启动恢复以该快照决定释放或继续。优点是复用任务状态权威；代价是改变当前 `Manager.Dispatch` 的创建/启动顺序，并扩大任务状态失败窗口。
- **方案 C：** 接受窄窗口泄漏，交给人工清理。该方案不能满足 spec 的孤儿资源设问与“终态一次释放”，本稿不建议作为实现输入。
- **本稿提案：** 先把 P2 退回 contract；在 P2 未裁决前，下面的实现卡只能作为条件性提案，不得声称生命周期闭环已冻结。

### P3｜扇出形态

- **方案 A（本稿提案）：** 保持一张跨接缝实现卡 `B233.10-impl`，在同一轮内闭合编制选择/冻结、既有 HTTP wire、执行机准入、任务快照和终态释放；原因是一次占用的事实跨 `d_scheduling` → `d_gateway` → `d_transport` → `d_orchestration`，拆开会把选择与终态释放的接缝拆散。
- **方案 B：** 拆成 `d_scheduling`、`d_gateway + d_transport`、`d_orchestration` 三张实现卡，再加集成卡。优点是域内并行；代价是至少四次固定交接，且 P2 的重启窗口无单一归属。
- 若选 B，必须重写本稿 DAG 和每张卡文件集；不能直接按本稿扇出。

## 4. 子卡清单

### `B233.10-impl`｜一次派发生命周期的跨接缝实现（条件性提案）

#### ①契约引用

- `docs/superpowers/specs/b233.10-contract.md` §1–§10、§11 C-0–C-6。
- 冻结条目 #1–#76，尤其 §4.2 #21–39（选择/冻结准入）、§4.3 #40–62（任务快照与终态释放）、§4.4 #63–76（边界与图域）。
- Ticket 0 已落空壳：`internal/scheduling/scheduling.go#Service.Select`、`#Service.AdmitFrozen`；既有 wire 金样本：`internal/client/frozen_dispatch_test.go#TestDispatchFrozenIdentityJSONGolden`。
- 执行入口：`internal/agentd/cardstep.go#Server.startCardStep`、`internal/agentd/server.go#Server.handleDispatch`、`internal/client/client.go#Client.Dispatch`、`internal/agentd/manager.go#Manager.Dispatch`。

#### ②意图与为什么

把一次执行的身份选择、冻结、执行机准入、任务快照和终态释放收敛成一条事实链：起源侧可以选择并冻结但不写执行容量；执行机只按冻结载体占用一次；Manager 只消费快照；卡节点 goroutine、工作流列和镜像不再释放执行占用；Done/Stop 的成功终态只释放一次。普通无冻结派发保留原命令与 HTTP 入口，并继续在执行机当场选择+占用一次。

实现不得通过“起源先 Admit 再 Release”伪造 Select，不得让执行机继续按 Squad 重选，不得让 Manager 解析 Receiver，不得把协调者 `LaunchAdmit` 的临时占用混进执行任务生命周期。

P2 未解决的重启窗口不是本卡可自行发明的补偿逻辑；若裁决要求新 reservation/attempt 持久事实，先退回 contract，再重写本卡文件集与 DAG。

#### ③验收（按子系统类型分流）

**逻辑型：`d_scheduling`**

- `go test ./internal/scheduling -run 'Test(B23310|Select|AdmitFrozen|Occupancy)' -count=1` 返回各测试 `ok`：Select 从小队范围返回在线成员的 Binding，但不改变 `carrier/<name>` 或 `squad/<squad>/<carrier>`；反面断言是把 Select 变成 `Admit` 后测试必须失败。
- 同一真实 SQLite facade 中，`AdmitFrozen(Binding{Squad:"workers",Carrier:"A",...})` 后 carrier 键与成员键各为 1；`Release("workers","A")` 后各为 0；`AdmitFrozen` 再次被同一满员条件调用返回 `ErrNoSlot`，且不尝试 B。
- 离线、满员、Machine/CLI/HomeDir 与载体登记不符的冻结 Binding 均返回可由 `errors.Is` 分流的错误；计数读数保持不变；小队中另一个 online 载体不得被静默选择。
- Select 成功、满员排队和 `ignition_queue` roundtrip 测试都用真实 registry 读回；队列 JSON 不出现预选 Carrier，且缺失字段与空值不被同一个零值误判。
- `go test ./internal/scheduling -race -run 'Test(B23310|Select|AdmitFrozen)' -count=1` 在并发双准入下至多一个成功，计数不超过上限；CAS 冲突返回既有 `ErrRetryExhausted`/`ErrNoSlot`，不报成功但无占用。

**逻辑型：`d_orchestration`**

- `go test ./internal/agentd -run 'Test(B23310|Manager.*Carrier|Continue.*Admit|Resume.*Admit)' -count=1` 返回 `ok`：Manager 创建任务时保留网关给出的 Carrier/Squad/Target/Executor/HomeDir/Model；Manager 不读取或解析 Receiver，不调用 Select/Admit。
- Continue、Resume 和启动热恢复前后读取同一 Task 快照；计数不增加，任务身份不变。反面断言：在 Manager 入口补一次 `Service.Admit` 时测试必须变红。
- waiting_review→Done 与 running→Stop 各使对应 registry 键从 1 变 0 一次；重复 Done 返回既有成功语义但 registry 版本/计数不再变化。当前 `handleDone` 重复释放是待修实现债，不能用 Release 的幂等性掩盖调用次数。
- 任务创建前的 workspace/plan/profile/start 任一**返回错误**路径均释放本次已取得的执行占用；错误响应仍带原始可行动原因，不能返回成功而无 Task。宿主直接重启的中间窗口不在机内结论内，见 P2 与真机清单。

**边界型：`d_gateway`、`d_transport`、`d_execution`**

- `go test ./internal/client -run '^TestDispatchFrozenIdentityJSONGolden$' -count=1` 返回 `ok`，并保留三态断言：carrier/squad 空时键缺席；HomeDir nil 时 `home_dir` 缺席；显式空串时键存在且值为 `""`。
- 新增一条穿过真实 httptest HTTP 的回归：由 `Client.Dispatch` 发送 `carrier=A,squad=S,target=linux-01,executor=opencode,home_dir=""`，服务端 `dispatchRequest` 解码后进入冻结准入/Manager，最终 Task 的五个身份字段与请求一致；直接调用 `handleDispatch` 内部 helper 不算通过。
- 同一 HTTP 回归的反面支：请求 carrier=A 但 receiver 指向小队、或小队仍有 B 时，目标端不得调用普通 Squad `Admit`；请求缺失冻结所需 `home_dir`、A 离线、A 满员、物理身份不符均返回非成功且有可行动错误，不得创建一个落到 B 的 Task。
- `go test ./internal/agentd -run 'Test(B23310|Frozen|Receiver|HandleDone|HandleStop)' -count=1` 返回 `ok`：卡节点路径只在起源选择阶段读容量、不在起源写执行占用；HTTP 执行端成功后 registry 读数为 +1，卡节点 goroutine 返回/工作流列变更/镜像收流不减；Done/Stop 后为 0。
- `go test ./internal/ledgerstep -run 'Test(B23310|Dispatch|Runner)' -count=1` 返回 `ok`：Dispatcher/Runner 只透传 Carrier/Squad/HomeDir；`Receiver` 仍可回显但不成为执行机重选器；客户端只发一条 `/api/tasks`。
- 普通无小队 `handoff dispatch` 的既有 HTTP/CLI 回归返回 200 并创建任务；直派 carrier 键 +1、终态后 0；命令名、路径和既有无冻结接收者错误不改变。真实 executor 启动与 CLI 行为未验证，列真机。

**追加缺陷族对抗审查**

`d_scheduling`（logic）：

- **生命周期 / 状态机中断：** Registry 是运行计数权威；普通返回错误由执行侧回滚，任务终态由任务快照释放，Agentd 重启不应因“仅重启”提前减计数。`AdmitFrozen → CreateTask` 直接重启的孤儿窗口尚未验证且未被现有 contract 覆盖，**有风险，因为**当前没有可见 durable reservation；按 P2 退回 contract/真机，不把它写成已安全。
- **静默失败 / 误导报错：** offline、full、physical mismatch、CAS exhaustion 必须原样分流为可行动错误；冻结失败不能返回成功，也不能改选 B；启动失败回滚失败要保留原错误并记录计数偏高风险，不能伪造归零。
- **跨平台假设：** scheduling 只比较逻辑 carrier/machine/CLI/HomeDir 身份，不解析 OS 路径和进程组，**无，因为**本域不启动外部进程；HomeDir 的真实宿主解释仍列 d_gateway/d_execution 真机。
- **假红 / 假绿测试：** 纯 `Binding` 结构单测不能证明 Select 不写键；必须使用真实 SQLite facade 读 `sched_running`，并用 A/B 冲突输入使“错误回退到 B”可变红；并发测试锁调用方依赖的唯一性，不锁私有 helper。
- **门禁绕过：** 所有执行占用写入仍经 `Service.AdmitFrozen`/普通 `Admit` 和 `Release`；不得由 gateway 手拼 `sched_running`。Select→AdmitFrozen 的检查与动作之间允许容量变化，门禁必须对指定 carrier 做 CAS，失败只能上浮/排队，不得 TOCTOU 后换成员。
- **序列化边界：** `IgnitionRequest` 队列、Binding 身份和 `OccupancyKeys` 都列入文件集；队列不保存预选 carrier，roundtrip 需区分缺席与零值。
- **枚举新值过既有白名单：无，因为**本卡不新增 scheduling kind、TaskState、EventType 或 receiver kind；既有 `carrier/squad/sched_running/ignition_queue` 字面值继续由现有常量消费。
- **承重安全属性：** carrier 物理位唯一、squad 成员位唯一、Select 不占用、AdmitFrozen 不重选、Release 不产生负数，每项都要有可变红的真实 registry/并发测试；不能只靠实现恰好满足。

`d_orchestration`（logic）：

- **生命周期 / 状态机中断：** Task 快照是终态释放读取的身份权威；Continue/Resume 只恢复同一任务，不重新占用。Store/Manager 可机内验证；宿主重启及尚无 Task 快照的 P2 窗口**未验证，需真机/contract 裁决**。
- **静默失败 / 误导报错：** Manager 收到冻结快照后若任务创建、workspace 或 adapter start 返回错误，调用方必须得到原始可行动错误且占用回滚；不能“Task 创建失败但仍报成功”，也不能吞掉 Release 失败。
- **跨平台假设：无，因为**Manager 不解析 machine、CLI 或 HOME，只保存并传递 gateway 已冻结值；HOME 实际注入由执行边界真机核验。
- **假红 / 假绿测试：** 必须从 Manager/真实 Store 读回 Task，再调用 Done/Stop；不能只测 `proto.Task` 构造或直接调用 `releaseTaskCarrierOccupancy`。重复 Done 以 registry 版本/计数不变作反面断言。
- **门禁绕过：** Manager 不解析 Receiver、不 import scheduling、不提供旁路准入；Continue/Resume 的调用方测试必须能在变异地加入 Admit 后变红。
- **序列化边界：** DispatchReq→Task→Store→Task 读回必须有穿透断言；Carrier/Squad 旧任务空值与新任务非空值分开验证。
- **枚举新值过既有白名单：无，因为**本卡复用既有 running/waiting_review/completed/failed，不新增任务状态或事件类型。
- **承重安全属性：** 同一 Task 的身份快照不可被后续载体登记变化改写；终态释放使用创建时 Carrier/Squad；一次性释放测试必须能在重复 Done/Stop 变异下变红。

`d_gateway`（boundary）：

- **生命周期 / 状态机中断：** handler 返回错误时 defer 回滚，成功后占用交给 Task 终态；card goroutine、列迁移、镜像不能释放执行占用。HTTP/远端 agentd/宿主重启的真实通路**未验证，需真机**；P2 窗口不以 defer 推广为安全。
- **静默失败 / 误导报错：** 冻结请求必须区分缺 HomeDir、offline、full、physical mismatch、Manager 启动失败；错误需要保留状态/行动原因。不存在“HTTP 200 但没有任务或没有占用”的成功窗口，需通过真实 HTTP 回归反面锁住。
- **跨平台假设：** target 归一化、远端 machine 名、CLI 和 HOME 是边界现实；Linux/macOS/Windows 的路径、权限、进程组和 webview 不可互推，机内只验 JSON/调用形状，真实平台列真机。
- **假红 / 假绿测试：** 不能只测 `dispatchRequest` 解码或直接调 `prepareReceiverBinding`；至少一支必须从 `Client.Dispatch` 穿过 httptest 到 `handleDispatch`/Task，另一支锁 goroutine 返回不释放的反面。
- **门禁绕过：** 普通 `/api/tasks`、卡节点本机 transport、卡节点远端 transport 都必须进入同一道冻结/普通分流；冻结 carrier 非空时 Receiver 不能再触发 Squad Admit。Select 与 AdmitFrozen 的 TOCTOU 由执行机 CAS 闭合，失败不换成员。
- **序列化边界：** client body map、server `dispatchRequest`、Manager 请求组装及 Task 回包逐处列入；HomeDir 缺席/空串/非空三态必须穿真实 HTTP。
- **枚举新值过既有白名单：无，因为**不新增 HTTP 路由、事件类型、TaskState 或 receiver kind；既有成功/错误状态继续走现有写回。
- **承重安全属性：** 一次 POST、冻结身份不可改、终态一次释放、卡节点不提前释放，各需能变红的 handler/registry 测试；不能用假客户端“恰好只调用一次”代替真实请求。

`d_transport` / `d_execution`（boundary）：

- **生命周期 / 状态机中断：** client 单次 POST 不负责外部 executor 回收；真实 agentd/executor/网络断开、重启、孤儿进程和临时目录由真机清单负责，**未验证，需真机**。
- **静默失败 / 误导报错：** client 非 200 必须回传服务端可行动错误；carrier A 被拒不能被 transport 静默改写成 B；真实远端错误文本和 executor 启动失败回传未验证。
- **跨平台假设：** relay、HTTP、CLI/HOME、进程组和权限模型均是外部现实，**无，因为**本卡不修改 adapter/PTY 协议；仍不得以 Linux 机内绿推广到 macOS/Windows。
- **假红 / 假绿测试：** `frozen_dispatch_test` 只锁 wire 金样，不锁真实远端行为；必须保留 HTTP 回放/httptest 的反面断言，并把真实 executor 事件通路列真机。
- **门禁绕过：** 只有既有 client→`/api/tasks` 入口；ledgerstep 不解析/准入/释放，executor adapter 不读 Registry。并发网络重试不得把一次 POST 变成二次准入；既有 client 无自动 POST 重试的事实需保持。
- **序列化边界：** `ledgerstep.DispatchOpts`→client opts→body→server decode→Task 形成一条真实回归链；缺席、显式空和非空分别断言。
- **枚举新值过既有白名单：无，因为**不新增 adapter 名、事件名或 TaskState；Carrier/Squad 是字符串身份字段，不引入 receiver 白名单值。
- **承重安全属性：** identity isolation（A 不落 B）、一次 POST/一次准入和 HomeDir 保真需要跨边界测试；不能只在两端各自构造 struct。

**依赖型子系统的逐族结论（`d_ledger`、`d_protocol`）：**

- **生命周期 / 状态机中断：无，因为**本卡不在 ledger/proto 写入新的运行状态；任务占用与终态 owner 仍归 scheduling/gateway/orchestration。

- **假红 / 假绿测试：无，因为**不新增其内部行为；字段穿越真实序列化边界的断言已归实现卡的 transport 链路，不以 proto struct 构造替代。

- **序列化边界：无新增字段，因为**`Task`、队列信封与既有 Carrier/Squad 字段沿现有形状复用；真实 roundtrip 断言归 `B233.10-impl` 的跨边界验收。

## 6. 真机清单（未验证，需协调者执行）

1. **本机小队卡节点：** 隔离 agentd、真实 SQLite/PG facade、两载体 A/B；卡节点选择 A 后确认 `carrier/A` 与 `squad/S/A` 各 +1 一次，任务快照的 machine/CLI/HOME 等于 A；Done 后各回 0。
2. **跨机小队卡节点：** 起源 agentd → `linux-01` 执行机，使用共享账本隔离实例；确认执行机消费 A 而不是小队重选 B，且 A 的计数只在执行机生命周期出现一次。
3. **启动失败窗口：** 真实 adapter 启动失败，确认请求报错可行动、任务若已落库进入既有失败语义、执行占用回到原读数；不要把起源侧不存在的占用当作回滚对象。
4. **P2 宿主重启窗口：** 在冻结准入成功到 Task 创建前、Task 已创建未启动、running/waiting_review 三个时点分别重启执行机 agentd；记录 `sched_running`、Task、executor 进程、task 临时目录，确认孤儿回收责任。当前第一时点未有冻结载体，不能判通过；须先按 P2 修订 contract 或明确失败处理。
5. **终态一次释放：** 真实运行任务分别 Done、Stop、重复 Done、Continue、Resume；读共享计数与 Task 快照，确认只有成功终态一次归零，Continue/Resume 不加一。
6. **普通直派回归：** 不绑小队的 `handoff dispatch` 继续使用原命令和 `/api/tasks`，载体只占一次，终态回零；Receiver 错误仍可行动。
7. **满员排队：** 使 A/B 都满，card step 只写既有 `ignition_queue`、起源不占执行容量；释放后出队再次选择并冻结，不能复用旧载体或静默落到另一成员。
8. **平台矩阵：** 在项目支持的 Linux、macOS、Windows 执行机分别抽查 machine 名、CLI、HOME、进程/权限清理；一个平台的 HTTP/CLI 绿不得推广为全平台结论。
