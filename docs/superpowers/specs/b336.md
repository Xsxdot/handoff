# B336 coordinate 在控制台打开载体 TUI tab，终态关闭

- **卡**：B336
- **级别与档位**：**L2**（单子系统行为，但占用/PTY/席位三条缝，plan 写不进三行）。对话已批准；本会话按 L1 快道落地最小可跑路径：开 tab、占位到关 tab、终态关 tab。席位由 TUI 进程自己 `card bind`（GROK/CLAUDE/opencode 宿主 id），agentd 不伪造 session。
- **状态**：**已批准**（2026-09-04：控制台 PTY；机器=leader 载体那台；目录=那台机项目主工作树，不是 managed worktree；人只在房间说话；TUI 里打字=接管；已完成/关闭关 tab；进程死了才重建）
- **基线**：`origin/main` @ `c8a21c44`

## 问题陈述

今天 `card coordinate` 走 `opencode run` 无头一轮就退出。Resume 失败会「已重建现场」。人要的协调者是控制台里一个活着的载体 TUI tab。

## 方案

1. `card coordinate` / 叫机器人 / `rebind --launch` 同一条：Admit 协调者载体 → 在 **载体.machine** 上 `POST /api/pty/sessions`（本机直开，远端 `?machine=`）。
2. 目录：该机项目主工作树（`resolveCoordWorkdir`），不是执行者 managed worktree。
3. `init_command` = 载体 CLI（空 HOME 不拼 `HOME=`）。可带 `HANDOFF_CARD=<id>`。不写主 HOME 的 AGENTS.md。不注入 `HANDOFF_SESSION_*`。
4. LaunchAdmit 名额占到 tab 关掉（PTY 进程死或卡到 已完成/关闭），不是 Launch 返回就放。
5. 席位：agentd **不**用 PTY id 冒充宿主 session。TUI 起来后用自己的宿主 id `card bind`。空座期间房间只出机械信号。
6. Resume：tab 还在就不当死；进程/tab 没了才再开一个。不要无头 `run -s`。
7. 卡进入 `已完成` 或 `关闭`：关对应 PTY tab，释放名额。关 tab 在 `move 已完成` 之前也可以，但终态必须关。

## 测试决定

1. launch 后编制名额未立即释放；PTY 以项目路径 + CLI init_command 打开。
2. 卡移到 已完成/关闭 → PTY 被关、名额释放。
3. 不写 HANDOFF_SESSION_*；空 HOME 不 mkdir 隔离目录。
