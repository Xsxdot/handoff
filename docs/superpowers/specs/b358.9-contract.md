## 3. 契约增量：精确签名

### 3.1 统一记法（`internal/proto/identity.go`，本分支新建）

```go
const (
    IdentityKindUser  = "user"
    IdentityKindAgent = "agent"
)

// IdentityResp 是控制台身份读缝（GET /api/identity）的响应。
type IdentityResp struct {
    Member     string `json:"member"`     // user:<name>；未配置为空串
    Device     string `json:"device"`     // 端戳；主令牌身份为空串
    Configured bool   `json:"configured"` // 本机 console_user 是否已配置
}

func MemberIdentity(kind, name string) (string, error)
func ParseMemberIdentity(raw string) (kind, name string, err error)
func ValidateMemberIdentity(raw string) bool
```

规则（冻结语义）：

1. `MemberIdentity` 只认 `IdentityKindUser`/`IdentityKindAgent`；名字非空、无首尾空白、不含 `:` 与空白字符。
2. `ParseMemberIdentity` 对空串、非 `user:`/`agent:` 前缀、残缺/非法名 fail-closed 返回错误——**禁止旧脸回落**（`web:`/`cli:` 一律拒绝）。
3. `IdentityResp` 三键**恒出、无 `omitempty`**：前端要能区分「空串」与「老 agentd 没发这个键」。

### 3.2 配置键（`internal/config/config.go`）

```go
// ConsoleUser 空 = 未配置：身份解析 fail-closed，不回落到 web:<host>。
ConsoleUser string `yaml:"console_user,omitempty"`
```

`decodeStrict` 的已知键清单同步加 `console_user`（保持错误文案可行动）。

### 3.3 agentd 身份解析唯一入口（`internal/agentd/identity.go`，本分支新建）

```go
type consoleIdentity struct {
    Member     string // user:<name>；Configured=false 时为空
    Device     string // 登录会话设备名；主令牌/无会话为空
    Configured bool
}

func (s *Server) resolveConsoleIdentity(r *http.Request) consoleIdentity
func sessionDeviceName(ctx context.Context) string // 包级函数：identityFrom(ctx).device
func (s *Server) handleIdentity(w http.ResponseWriter, r *http.Request)
```

`identity` 载体增字段（`internal/agentd/auth.go`）：

```go
type identity struct {
    session string
    device  string // B358.9 端戳；鉴权中间件随会话行装填（server.go auth 处）
}
```

规则（冻结语义）：

1. 人名取 `s.conf().ConsoleUser`；缺名或值非法 → `Configured=false`、`Member==""`、**绝不回落 `web:<host>`**。
2. 端戳取登录会话 `store.Session.DeviceName`，**在鉴权中间件查会话行时一次读出**（`identity.device`），解析器不二次查库。
3. 主令牌（CLI）身份 `identity{}`：端戳空、`Configured` 仍按配名真假——**端戳缺失不拦门**。

### 3.4 控制台身份读缝端点（`GET /api/identity`）

注册在 `Server.Handler` 的 `api` mux（`internal/agentd/server.go`），**不挂 `withRooms`/`withLedger`**（只依赖配置与登录会话，与账本装配无关）。成功 `200` + `proto.IdentityResp`。方法名 `handleIdentity`（`file#Server.handleIdentity`）。**不落账、不改状态**。

### 3.5 端戳 wire（`internal/proto/rooms.go`）

```go
type RoomMessage struct {
    // …既有字段不变…
    Device string `json:"device,omitempty"` // B358.9 端戳，只做落款
}
```

端戳**只进 `RoomMessage`**：不新建端侧注册表、不落 `sessions` 表、不入 `identity` 之外的判定面。TS 镜像 `web/src/api/rooms.ts#RoomMessage` 同步加 `device?: string`。

### 3.6 CLI 主 agent 出示（`cmd/session.go`）

```
handoff session send <session> <text...> --agent <启动身份>
```

`sessionSendActor(agentFlag, cliFlag, sessionFlag string, cliChanged bool) (string, error)`：agent 形态编码 `agent:<启动身份>`（`proto.MemberIdentity`）；与 `--cli/--session` 成对形态**互斥**；无 flag 形态仍 `ledgerActor()`（CLI 审计 actor，scope 外）。非法启动身份 fail-closed。

零改动面（冻结，防扩面）：

- `session create --owner` 已收统一记法——主 agent 建群用 `--owner agent:<启动身份>`，**不新增 create 的 `--agent`**。
- `session wait <member>` 逐字相等匹配（既有），本卡不改；主 agent 订阅自理。
- `--reply-to`、`--ref`、`--mention` 透传不变。

### 3.7 游标与写者（签名不变，只换值语义）

- `cursor.Store.MarkRead/Snapshot/Cursor(member string, …)` **签名冻结不变**；键 = 解析后的人名 `user:<name>`（新写入自然用人名；旧 `web:`/`cli:` 键随解析改造自然弃用——游标纯缓存非权威，无迁移/共存义务，**禁止半新半旧并行判定**）。
- `room.VerifyWriter(writers []string, actor string)` **签名冻结不变**；`sessionWriters` 成员集语义冻结为人名键 ∪ 席位。协调者跟进＝该派生的既有行为（回归验收，见 §5 F 组）。

### 3.8 建会话 owner 缺省（实现轮接线）

`POST /api/sessions`：`owner` 缺省 = `resolveConsoleIdentity(r).Member`；显式 `owner` 仍按统一记法校验。未配名且未显式给 owner → fail-closed（可行动报错，文案写清 `console_user`）。

## 4. 图契约面

新增符号全部落既有容器，跨域边全部落既有 entry/预算：

- `d_gateway→d_protocol`：`handleIdentity → m_proto_IdentityResp`、`resolveConsoleIdentity → n_proto_MemberIdentity`——落既有 entries「proto 实体」「proto（包级函数）」，不新增方向、不抬预算。
- `d_cli→d_protocol`：`sessionSendActor → n_proto_MemberIdentity`——既有方向，`legacyBudget` 1→2、entries 补「proto（包级函数）」。
- `d_gateway→d_gateway`（同域）：`e_http_get_api_identity → handleIdentity`、`handleIdentity → resolveConsoleIdentity/writeJSON`、`resolveConsoleIdentity → conf/sessionDeviceName`、`sessionDeviceName → identityFrom`、`resolveConsoleIdentity → proto.MemberIdentity`（跨域，已列上）。

## 5. 原子冻结清单

每条是独立可判 pass/fail 的接缝断言。本卡 Ticket 0 已可判的条目（A–E 组）由 §7 的测试锁定；F–J 组为实现节点对账条目。

### A. 统一记法（proto）

1. `MemberIdentity(IdentityKindUser,"sycm")` 返回 `"user:sycm"`。
2. `MemberIdentity(IdentityKindAgent,"opencode")` 返回 `"agent:opencode"`。
3. `MemberIdentity` 对非法 kind（如 `"web"`）返回错误。
4. `MemberIdentity` 对空名、首尾空白名、含 `:` 名返回错误。
5. `ParseMemberIdentity` 对 `""`、`"web:127.0.0.1"`、`"cli:sycm@mac"`、`"sycm"`、`"user:"`、`":sycm"`、`"user:  "`、`"cli:opencode#s1"`、`"agent:op encode"` 全返回错误（fail-closed，禁旧脸回落）。
6. `ParseMemberIdentity` 对 `"user:sycm"`/`"agent:opencode"` 往返回原 kind+name。
7. `ValidateMemberIdentity("web:127.0.0.1")==false`。
8. `ValidateMemberIdentity("user:sycm")==true`。
9. 常量逐值：`IdentityKindUser=="user"`、`IdentityKindAgent=="agent"`。

### B. 配置键 console_user

10. `console_user` 非空经 `Save`→`Load` 往返一致。
11. 空 `console_user` 经 `Save` 不写盘（`omitempty`）。
12. 未知键报错的已知键清单含 `console_user`。

### C. agentd 身份解析与读缝

13. 配名后 `resolveConsoleIdentity` 返回 `Member=="user:<name>"` 且 `Configured==true`。

17. cookie 会话路径的端戳等于该会话 `DeviceName`。

## 6. 拍板记录（三重闸门）

只记同时满足「难逆转 × 无上下文会惊讶 × 真取舍」的决定。本轮命中两条：

- **端戳载体＝`RoomMessage.Device`（随消息载荷走），不建端侧注册表、不落 `sessions` 表**。难逆转——wire 上每个房间消息都带它，改载体要动所有生产/消费点与金样本；无上下文会惊讶——「为什么设备名存在每条消息里而不是一张设备表」会被后人当成可以「顺手规范化」的设计；真取舍——被否方案是「agentd 建身份→端注册表、发言时反查」，那正是 spec 扇出禁令要扑灭的形状（按端集合投递的回潮），且端是登录会话的瞬时事实、进程外生命周期不受 agentd 管。立。

- **主 agent 出示方式＝`session send --agent <启动身份>` 显式 flag，不用环境变量/注册表**。难逆转——CLI 命令面一旦发布，收紧/换出示形态要动外部 harness 的调用脚本；无上下文会惊讶——`currentSeatIdentity` 已有 `HANDOFF_SESSION_*/GROK_SESSION_ID` 环境键先例，后人会问「为什么不沿用环境出示」；真取舍——被否方案是「复用环境键注入」：环境键是宿主会话的隐式事实，主 agent 的启动身份是它**自选自报**的（spec 决定 4「它自己出示；自选、会话内唯一」），隐式环境注入无法表达「自选」，且会在无头机器人继承父进程键时出示错身份。立。

（其余为 spec 已批准语义或确定性设计，无被否的像样方案，不立：人名只认 `console_user`、端戳取登录设备名、游标换键、协调者按派生、owner 缺省。
