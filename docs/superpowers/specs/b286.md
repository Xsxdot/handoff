### C7：CLI 短等首态，HTTP 仍 202

推荐（源卡 note 与 peer「不动异步架构」；r1 钉通道和水位）：

1. **`POST /api/cards/{id}/step` 保持 202 消防水管。** 审阅节点会阻塞到回合终态，HTTP 扛不住。本卡不把 NodeStep 整段搬进这次请求。禁止为等首态新增 HTTP、禁止订 task WS。
2. **短等通道 = 本机账本**（与 `card wait` 同路：`openLedger` + `Follow`，或等价的 `EventsFromAsc` 轮询）。**在 `CardStep` 之前**记下 `MaxSeq` 当水位。只认 `seq > watermark` 的两类首态，禁止把卡上历史 `dispatched` 当成本次成功：
   - `dispatched`：派发起来了。**stdout** 一行决议（不要打到 stderr，脚本读 stdout）。必含：目标机（空串写成「本机」，禁止「目标机未定」）、**新分支** `branch`、**起点分支** `base`（空则「无起点分支」，不要用「origin」冒充分支名）、起点短号（`base_commit` 空 →「无 sha」；非空截到 `min(7,len)`）、纪律块名。**不打**「本地 ref / origin」标签——快照没有 `local_base_branch`，POST 后再读 `WorkBranch()` 会把首轮标反。退出 0。
   - `needs_human` 且 reason 为「派发失败」（ViaTemplate 拒、工作分支跨机、审阅缺工作分支、协调者进程内基线解析失败）：**stderr** 打 `haltForHuman` 的 **comment 正文**（「本节点派发失败：\n」+ 原文），不是只打 reason 三字。**退出非 0**。
3. **超时（缺省约 20s，cmd 包内可测时长，`go test ./cmd` 必须用短超时）**：**stdout**「已受理，首态未到；进展见 card wait」，退出 0。覆盖 202 之后的 ViaTemplate 族。纪律探活已在 202 之前，不要写进超时理由。
4. **无新首态**（mock HTTP 只回 202，账本没有水位之后的两类事件）：与今天一致，退出 0，stdout 含卡号、节点名、`handoff card wait`，并锁住「已受理」字面。夹具里可以有 ledger.db，只要没有新首态就算超时。
5. **入口同步拒绝不变**：卡/节点解不开（404/400）、在飞 409、纪律探活/拒发闸 400，当场失败，不进入短等。
6. **仓内** `skills/handoff/SKILL.md` 改两处：① 441 短等首态、超时才「已受理」；② 607 按 B239+C7 重写（认领失败看卡上 comment，ViaTemplate 失败 CLI 非 0，不再说「卡上零事件 / 只看 agentd.log」）。版本 skew 那句「目标机未定」仍指 CLI/agentd 不同批，不是空 target。

执行机 fetch 导致的「基线提交在任务仓库中不存在」上限 `FetchTimeout=2min`，短于 20s 的短等**盖不住**。这族从本卡必堵清单拿掉，见 OOS。本卡必堵的是协调者进程内、远小于 20s 的那族（跨机、缺工作分支、ViaTemplate 同步拒）。

弃选：

- 给模板/节点加 `override.target=linux-01`：把个人机器名泄进公共方法论仓；同一条流要派到不同机器。C7 原题已证伪。
- CLI 在缺 `--target` 时拒发：回滚 B271。
- HTTP 改成等整个节点结束：审阅会把请求挂几十分钟。
- 只打日志不改退出码：无人值守看的是退出码，不是人眼扫 stderr。

### C8：`purpose=review` 且 pass 时，白名单外的 diff 不得 pass

推荐：

1. **触发条件**：只认 `Node.Override.Purpose == review`，且裁决解析为 pass。其它 purpose 不动。不要用节点名 `review` 当开关，也不要读模板 purpose（`RunOnce` 今天不取模板；把模板兜底加进来会改存量测试，本卡不做）。
2. **取本轮路径**：走已经注入的 `Diff`（生产 `StepRunner` 即使无 produces 也装配了 Diff，只是今天 RunOnce 不调用）。
   - `Diff == nil` 或 `Diff` 报错 → **不得 pass**，**不写** `review_verdict`，`haltForHuman("读取审阅改动失败", …)`，回合数不增加（与裁决解析失败同构）。
3. **白名单**（仓内相对 POSIX 路径，`ChangedPaths` 已剥 `a/` `b/`；不要再做 OS 分隔符转换）：
   - 前缀 `docs/superpowers/ledgers/` 与 `docs/ledgers/`（`HasPrefix`，prefix 带尾斜杠）
   - 路径恰好等于 `docs/superpowers/ledgers` 或 `docs/ledgers` 也放过
   空 diff 合法。白名单以外任何路径（含 `*_test.go`、生产代码、skill、workflow）→ 未过。rename 只要 from/to 一侧越界即未过。未跟踪未提交文件本卡看不见（现网 Diff 如此）。
4. **白名单未过**：改内存 `verdict.Pass=false` → 普通评论列出越界路径 → `RecordReviewVerdict(..., false, ...)` → 走现有 fail 路由（`ClearNeedsHumanFrom`、`routeTo(OnFail)`）。**不** `haltForHuman`。charter review 的 `on_fail` 是 `implement`。
5. **落账布尔与路由一致**：白名单未过的卡，`review_verdict.pass` 只能是 false，且事件序不得先出现 true 再改口。Diff 失败那条不落裁决。
6. **produces 校验仍在其后**：本卡不改 produces 精确匹配。review 节点没有 produces，两条路径不打架。存量 `Name=review` 且 `Override.Purpose=""` 且 `Diff==nil` 的测试（`TestReviewStepPassAndFailLoop`、`TestNodeStepWithoutProducesDoesNotInvokeOutputHooks`）继续绿：闸不触发、不调 Diff、pass 照常。

弃选：

- 允许新增测试文件（源卡曾倾向 B）：C1.11 就是加测试后自审自批。
- 只报不拒：防不住无人值守。
- 按节点名而不是 purpose：B183 已经证明模板 purpose 和节点 purpose 会分叉。
- 本卡改 charter-review skill / 模板 prompt：文字已经只读，再写一遍没有机械牙。skill 在 charter 仓。
- 把 review 分支合进工作分支当「证据」：那是把越轨合法化。
