# B417 spec：Android/iOS 原生移动壳（WebView + 配对 + 安全存储）

**状态：已批准（2026-09-28）** —— 用户指令「你自主推进，该派发的派发」授权协调者按已拍板
决策定稿并派发。拍板清单见「备注」。
**级别与档位：L3 重档**（contract → breakdown → 拆 Android/iOS 两子卡 → 父卡 integrate）。
**卡：B417**（project handoff）。**依赖：B392 已完成**（会话生产接线已并入集成线 `10ccde73`）。

## 问题陈述

B369 交付了 Web 移动形态（`web/` 响应式四 tab）与 Go 连接核（`internal/mobilecore` +
`mobile/bind` 经 gomobile 编成 Android AAR / iOS XCFramework），B392 补齐了绑定面的会话
生产接线（`SessionCookie`/`SwitchMachine` → 真实 Core）。但**当前仓库没有任何可安装的
Kotlin/Swift 原生 App 壳**——`find` 全仓零 `.kt`/`.swift`。手机用户无法安装并使用。

B417 独立补齐这个缺口：两端原生薄壳，职责四件——webview 容器、配对入口、凭据入安全
存储、webview cookie 桥接（含切机清罐）。**协议逻辑零重实现**，全部经 `mobile/bind` 七
函数调用。本卡不重开 B369/B392。

## 级别与档位

- **定级两问**：①新建壳子系统——Android Kotlin 与 iOS Swift 是两条独立工具链代码库，
  各自单一职责；且消费已冻结的 `mobile/bind` gomobile 导出面。②**动契约层**——对接既有
  跨语言（Go↔Kotlin/Swift）绑定契约，即便本侧零修改也按「动契约层」计。→ **L3**。
- **选档**：两端壳各自从零起（Gradle/Xcode 工程 + webview + 扫码 + 安全存储 + cookie
  桥接），单子系统工作量远超流程固定成本（约 70 分钟）→ **重档**。
- 结构：contract 冻结壳↔核接缝与两端共享不变式 → breakdown 拆 Android/iOS 两张子卡 →
  子卡各自 plan→implement→review → 父卡 integrate（两端构建物 + iOS 模拟器验收）。

## 方案

**主选：两端原生薄壳，落 `mobile/android/` + `mobile/ios/`（同 `desktop/` 嵌套形态）。**
壳内零协议代码，只调 `mobile/bind` 七函数；webview 加载 Go 核给出的设备内回环源
（`Origin`），页面资产由 agentd 提供（`-tags embedweb`），壳不打包前端。配对经
`handoff console --qr`（扫码）或 `--bundle`（粘贴串）。

**弃选与理由**：

1. **新开独立仓库/项目** —— 否。壳的唯一契约面是 `mobile/bind`（AAR/XCFramework，
   `mobile/go.mod` 用 `replace ../` 直接吃根模块）。拆仓把这条紧耦合交接面变成产物发布
   + 版本对齐问题，纯增成本。B369 设计 spec 第 66 行已定「新建 `mobile/` 仓内模块，
   布局先例 = `desktop/`」；桌面端控制台同在产品仓内，移动壳是它的孪生兄弟。
2. **Flutter / RN 单壳** —— 否。对 Go 核只能 FFI，引新工具链，收益仅少写一个很薄的
   壳；B369 已否。
3. **壳工程不进仓、由协调者真机侧另办**（B369 breakdown P5 原裁决）—— **本卡显式推翻**。
   P5 立的理由是「圈不出跨工具链的有界文件集、linux 工作树验不了」；本卡把壳工程纳入
   仓库与流程，用**构建闸（产可安装产物）+ iOS 模拟器走查**作为可复现验收，不再依赖
   「真机侧另办」的一次性人工操作。跨工具链无法在 linux 跑的顾虑，由「壳子卡跑在装了
   Xcode/NDK 的 macOS 执行机」承接（见「测试决定」与「备注」）。

## 用户故事

1. **首次使用**：设备无存储凭据 → 进入配对页（两个入口：扫码 / 粘贴配对串）。
2. **扫码配对**：相机扫 `handoff console --qr` 的二维码 → `Pair(bundleJSON)` → 机器列表。
3. **粘贴配对**：粘贴 `handoff console --bundle` 的一行 JSON → `Pair(bundleJSON)` → 机器
   列表。这是 B369 契约里 QR 超容量（多机 bundle 过大）的**法定退路**，也是 iOS 模拟器
   无摄像头时唯一的配对路径。
4. **机器列表**：显示已登记机器名与在线/离线（`MachineCount`/`MachineAt`）；离线机可见
   但不可进入。
5. **进入机器**：`SwitchMachine(machine)` → 清空 webview cookie jar → 注入会话 cookie →
   加载回环源 origin → 显示已认证控制台。
6. **切机**：A→B→A，任何时刻 webview 罐只装一机的 cookie。
7. **重启免重扫**：从安全存储读回 bundle 重新 `Pair`，无需重扫码。
8. **失败态**：配对串损坏 / 机器离线 / 兑换失败 / cookie 过期 → 明确错误提示 + 可重试；
   绝不加载 webview、绝不复用旧 cookie。
9. **凭据卫生**：token / cookie / 配对串不落日志。

## 契约语义与接缝（L3）

**只定语义，不定签名；签名/端点/类型归 contract 节点查现状代码落地。**

### 壳↔核接缝（已冻结，B417 只消费，不改核）

`mobile/bind` 导出面（形状由 `mobile/bind/export_surface_test.go` 逐字钉住）：

    func Pair(bundleJSON string) error
    func MachineCount() int
    func MachineAt(index int) *Machine      // Machine{Name, Origin string; Online bool}
    func Origin(machine string) (string, error)
    func SessionCookie(machine string) (string, error)   // 只返回 cookie 的 value
    func SwitchMachine(machine string) (string, error)   // 返回目标回环源
    func Close() error

**B417 不新增、不修改任何绑定面符号**；壳不得触及 `Token`/`Dial` 等绕过 cookie 闸的入口。

### 共享壳不变式（本卡新冻结；两端必须同语义）

- **I1 配对载荷**：QR 载荷 = `handoff console --qr` 输出；粘贴串 = `handoff console
  --bundle` 输出。两者是**同一份 bundle JSON**。壳不解析 bundle，整体透传给 `Pair()`；
  解码失败由核返回 error，壳不得落半态（不登记部分机器）。
- **I2 凭据持久化**：壳把**原始 bundle JSON** 存入平台安全存储（iOS Keychain，
  `kSecAttrAccessibleWhenUnlockedThisDeviceOnly`；Android Keystore 支撑的
  `EncryptedSharedPreferences`）。启动时若存在 → `Pair(stored)` → 机器列表；否则 → 配对
  页。禁止落日志、禁止云备份/跨设备同步（bundle 含各机 token 副本 = 主 Bearer 令牌集）。
- **I3 会话桥接时序**（承重）：进入/切换机器时严格按
  `SwitchMachine(machine)` → **全清 webview cookie jar** → `SessionCookie(machine)` →
  注入 cookie → `load(origin)`。次序不得颠倒；任何时刻一罐只装一机的 cookie。
- **I4 cookie 属性**：绑定面现状只导出 cookie 的 **value**（不带属性），故 name / path /
  domain / Secure 由壳按 B369 契约 §3.4 固定为
  `handoff_session` / `/` / `127.0.0.1` / `Secure=false`（明文回环）。这是绑定面只导出
  value 决定的**已知约束**，不是可选风格；contract 节点须复核 `handoff_session` 与 Path
  的现状出处并钉住。
- **I5 fail-closed**：任何绑定面 error（Pair 解码失败、机器离线、兑换失败、cookie 空值/
  过期）→ 错误 UI + 可重试；不得加载 webview，不得复用/伪造 cookie。
- **I6 零协议逻辑**：壳不构造隧道/ticket/兑换请求，不实现 bundle 编解码；一切协议在 Go 核。
- **I7 核生命周期**：Go 核为 App 级单例；启动时 `Pair(stored)` 一次；App 终止 `Close()`；
  进程被系统回收后前台重启按「启动」路径重建。

### 构建接线语义

- 核心产物由 `./mobile/build.sh android|ios` 产出到 `dist/mobile/`（已被 `.gitignore` 的
  `/dist/` 覆盖）：`handoff-mobile.aar` + `handoff-mobile-sources.jar` /
  `handoff-mobile.xcframework`。**壳构建必须先跑核心构建**，壳不提交核心产物。
- Android：Gradle 工程 `mobile/android/`（提交 gradle wrapper），依赖 `dist/mobile/` 的
  AAR；minSdk 21、compileSdk/targetSdk 36；debug 签名；产物 `app-debug.apk`。绑定类为
  `bind.Bind` / `bind.Machine`（Go 包名 `bind`，已由本机产物核验）。
- iOS：Xcode 工程 `mobile/ios/`，依赖 `dist/mobile/handoff-mobile.xcframework`
  （framework 名 `Handoff-Mobile`，模块名以 gomobile 产物为准，contract 节点核验）；无
  签名的模拟器构建；产物 `*.app`。仓内无 XcodeGen/Tuist，工程须能被 `xcodebuild` 无 GUI
  复现（提交 `.xcodeproj`，或由确定的生成步骤产出）。
- 两端各提供一条**无人工 GUI 步骤**的可复现构建命令（核心 → 壳），供 headless 验收。

## 实现决定（决策级；具体符号/文件归 contract/plan）

- 壳工程落点：`mobile/android/` + `mobile/ios/`，与 `desktop/` 同构（嵌套 module 目录
  内放 app 工程）。
- 两端壳侧 UI 极薄：**配对屏**（扫码按钮 + 粘贴输入框）+ **机器列表屏**（名字 + 在线态）
  + **webview 容器** + **错误态**。控制台内容面复用 agentd 提供的 web 控制台（B369 已交付
  移动 IA），壳不重画内容。
- 失败态文案与重试入口属用户可见决策，由 plan 定稿（contract 记录语义：错误必须可归因到
  「配对/离线/兑换/过期」四类之一）。
- 形态确认：壳侧仅两屏原生 chrome，内容 IA 由 B369 已确认的 web 移动形态承担；**不另起
  原型站**（知情决定：壳 chrome 极薄且非本卡主要风险，原型成本大于收益）。若实施中发现
  配对/机器列表形态有承重歧义，回 spec 补原型。

## 测试决定（接缝清单）

**接缝越少越好；每条缝写成「符号 + 调用方」。**

1. **构建闸（边界型）**：`mobile/build.sh android|ios`（核心产物）+ Android
   `./gradlew assembleDebug`（→ APK）+ iOS `xcodebuild`（→ 模拟器 `.app`）。
   调用方 = 协调者/CI 验收命令。缝对面是外部工具链（NDK/Xcode），边界型例外成立。
2. **iOS 模拟器端到端（边界型，最高缝）**：粘贴真实 `handoff console --bundle` 输出 →
   `Pair` → 机器列表 → 进入 → webview 加载**已认证**控制台（能过 agentd cookie 闸）。
   调用方 = 验收走查。缝对面是 agentd 的 HTTP 会话，边界型例外成立。
3. **会话桥接（新建符号 + 生产调用方）**：iOS `CookieBridge`（被「进入机器」流程调用）、
   Android `WebviewSessionBinder`（被 ViewModel 调用）。单测断言 I3 时序、I4 属性、
   I5 fail-closed。**不得是未导出/无生产调用方的纯函数**（假缝禁令）。
4. **配对入口归一（新建符号 + 生产调用方）**：扫码结果与粘贴文本归一化到同一个
   `pair(bundleJSON)` 调用（被配对屏调用）。单测断言畸形串报错、正确串透传、I2 存储
   往返。

**壳层以真机/模拟器走查为主；Go 核行为已由 B369/B392 机内测试覆盖，本卡不重复。**

## Out of Scope

- **Android 真机运行时验收**（装起来跑、切机、失败 UX）——用户已提供过 HONOR VER-AN00，
  但本期验收线只到构建物；真机运行时验收另开卡/后续期。
- **iOS 真机（非模拟器）运行**。
- **无障碍（VoiceOver/TalkBack）、IME/外接键盘**——随真机运行时验收。
- **推送通知（APNs/FCM）**——已在 `docs/roadmap.md`（「后续要做；一期架构不挡」）。
- **App Store / TestFlight 发布与签名 / 分发**。
- **cookie 轮换 UI / token 泄露处置 UI**——CLI 侧流程已成文（`mobile/README.md`）。
- **原生壳 chrome 的国际化**。
- 多机 cookie 同时在罐（单槽设计，见 I3）。
