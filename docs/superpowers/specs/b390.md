# B390 spec：唤醒消费轮在持续准入失败后静默停摆

**级别：L2 单子系统**（agentd 消费循环 + scheduling 准入；不新增跨子系统依赖）
**入口节点：debug**（bug 流铁律：无根因调查不许提修复）
**上游证据**：B390 卡上（现象、日志原文、触发链、与 B389 的边界、H1–H5 假设与红色回路设计）

## 1. 问题一句话

本机 agentd 的自动化唤醒消费在 `协调者小队 leader 准入失败: 并发已满` 反复失败后，**自 2026-09-19T23:42:19 起再无任何输出**（换版重启后依旧）；结果是 IM 寻址唤醒完全不被处理，B389 的真机验收链被堵死。

## 2. 本节点的法定动作（charter:debug）

1. **第 0 步已做**：身份钉死——被验对象是本机 agentd（`130a6634ab75`，起于 2026-09-21 15:09:19），而现象早于该二进制 18 小时 ⇒ 停摆是继承状态，不是本次换版引入。
2. **必须建红色反馈回路**（没有它不许进假设阶段）：在 `internal/agentd` 用"准入恒返回并发已满"的调度桩驱动消费轮，断言三条同时成立——(a) 按节拍重试而非一次就停；(b) 把"我停摆了"落成账本可见事件/需要人；(c) 循环不静默退出。现状预期红。
3. **按 H1–H5 逐条实验**（卡上有判据与实验设计），一次只改一个变量，失败原文优先于"我碰没碰那里"。
4. **出根因 + 分流决定**：一两行小修顺手修掉；架构级修复回本 spec 重新定级，不许在排查现场顺手动架构。
5. 收尾：清理临时诊断日志；根因、证据、分流决定落卡。

**红线**：修之前必须先有能复现该 bug 的失败测试；若代码里不存在能写这条回归测试的接缝，**那本身就是发现**，按架构债立卡，不硬塞测试。

## 3. 范围

**做**：消费循环的失败可见性（重试节拍、留痕、落"需要人"）、循环生命周期（是否退出、是否无人重启）、名额键残留的**观察面**（CLI 可看）。
**不做**：不动 B389 已收口的单卡失败路径；不改唤醒的业务语义（认领/路由/承载记录）；**不替我做共享账本的状态清理**——那属运营动作，需用户点头。

## 4. 验收判据

1. 红色回路能对这个 bug 变红，修复后变绿（变异复验：把可见性/重试去掉要重新变红）。
2. 准入持续失败时：按节拍重试 + 账本可见留痕（"需要人"），**不允许静默**。
3. 名额键残留可经 CLI 观察（是否有租约 TTL、是否能列出占用者）。
4. 真机：在该故障不再复现的前提下，B389 spec §4.3 的验收链能推进到"协调者回话、主 agent 在 IM 看到"。
