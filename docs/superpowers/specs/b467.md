## 问题陈述

B464 上线后用户走查（2026-10-23，卡 B467 note）提了六条，逐条现状与裁决：

1. **删了的账号会自己回来**。现状读数：删除只删账本里的账号定义、登录行与读数行，凭据文件不动（`internal/scheduling/accounts/delete.go:61-101`）；下一轮发现在同一 HOME 里仍扫到这个身份，以同一 id、自动名重建（`discover.go:194-224`）。各 CLI 的登出命令粒度不一（只有 `opencode auth logout <provider>` 能按条目删；codex/grok/claude 登出清整份凭据；agy 无登出），按条目删凭据做不齐。用户裁决（原话）：「在我们自己的项目里面加一个状态，忽略它，不探测不显示就行。」
2. **使用量弹层里「月」被挤到第二行**。现状读数：弹层主面板宽 376px，行内容区 329px；三窗口各最小 102px + 两段 14px 间距 = 334px，超 5px，换行（`web/src/app/accounts/accounts.css:69-72,85-98`）。
3. claude / 第三方 API key 的额度显示——刷新后已无，**不做**。
4. **opencode-go-5aa9（mac-pro 主 HOME 的 API key）与 xsxdot@gmail.com（OAuth）是同一个订阅账号却成了两个账号**。用户裁决：「如果拿不到，就先不改」。实测（2026-10-23，mac-pro，只打印键名）：key 路径 `GET opencode.ai/zen/go/v1/usage` 的 200 响应只有 `usage.{rolling,weekly,monthly}.{status,percent,resetsAt}`，**没有任何账号/组织标识**，拿不到 → **不做**（台账 §探测）。
5. **底栏不显示账号名/邮箱**（用户原话「只把账号ID/邮箱不显示就可以了」）。
6. **去掉「使用详情」入口**（用户原话「我们没有这个功能」；现状 `StatusBar.tsx:238`，与「管理账号…」指向同一处）。

## 方案

**① 忽略账号：账号定义上的一个可逆标记，取代界面上的「删除」。**

- 忽略是账号级（不是登录级）：账号领域记一条与账号同 id 的「已忽略」记录（时间、操作机器；r1.1 SC1：不写进账号定义行，旧版本二进制改写定义行不会抹掉它）；登录行、读数行、凭据文件一概不动。
- 已忽略的账号：**不探测**（定时探测跳过，「立即探测」拒绝并说明）；**不显示**在底栏、使用量弹层、移动端账号列表、载体选登录的下拉里；账号页只在底部收起的「已忽略（N）」区出现，可**恢复**。
- 发现照常扫到它的登录、照常更新登录状态（状态是事实，忽略只管展示与探测），**不会把已忽略改回来**——这正是与删除的区别。
- 仍被载体引用的账号不能忽略：与现删除同一拦法，点名哪些载体、链到「设置 · 自动化」去改。
- 载体保存时选了已忽略账号的登录（经 API/CLI 绕过下拉）→ 拒绝，文案「账号 X 已忽略，先在账号页恢复」。
- 恢复 = 清掉标记，回到原分组，下一轮由持有正常登录的机器探测。
- 弃选：「删除时可选同时删凭据」——用户先选过，后改为本方案；登出粒度各家不齐（见问题 1），做不到对每种 kind 精确删一条。
- 弃选：界面上保留「删除」与「忽略」并列——凭据还在时删除必然回来，并列只会再制造一次本卡第 1 条的困惑。删除的 API（`DELETE /api/accounts/{ref}`）保留不动，界面不再给入口。**（待批准岔口 ①，见文末）**

**② 弹层：** 三个窗口在默认字号下排在同一行（具体改宽度还是收间距由 plan 定，判据是可观察结果）。

**⑤ 底栏：** 每段只留图标 + 读数，名字移进悬停提示；颜色、字号不改（用户只要求去名字）。

**⑥ 弹层菜单：** 删「使用详情」，只留「管理账号…」。

## 落位三问

① 读写谁的权威数据：「已忽略」写账号定义——归 `scheduling/accounts` 账号领域（与改名、阈值同一处）；探测器、准入、控制台只读它。
② 谁消费：同进程 agentd 内探测器与调度准入经账号领域导出符号；控制台（另一进程）经 GET/PUT /api/accounts 契约面；CLI 经同一 API。
③ 同步还是异步：忽略/恢复是同步调用（调用方要看结果、被引用时要拒）；探测跳过是探测器下一轮读定义时生效，无新增消息。

## 实现决定

- 用户可见名字：按钮「忽略」「恢复」；区标题「已忽略（N）」；拒绝文案「不能忽略 X」「账号 X 已忽略，先在账号页恢复」；CLI 状态列「已忽略」。
- 账号定义存在共享账本的通用记录里（现状读数：`accounts.Account` 以 JSON 存 `KindAccount` 记录，`types.go:53-65`），加字段不改 DDL、不升 `ledgerSchemaVersion`。**旧版本二进制改写定义行（改名、补 label）会丢掉不认识的字段，等于悄悄恢复**——plan 须给出对策或明确要求全队同批换版（B464 已有先例）。
- 账号页、移动端、底栏、弹层、载体下拉的过滤在控制台按 API 字段做；探测跳过与载体保存校验在 agentd 侧做（不能只靠前端藏）。
- 不新增 CLI 忽略/恢复子命令（界面足够；见 OOS）。

## 测试决定

- 竖切：PUT 忽略 → GET 投影带字段 → 前端各处过滤（vitest 走真实组件）；发现 Reconcile 对已忽略账号不改标记（账号域单测，真实 Service + 内存 repo）；探测器 scan 跳过已忽略（真实 Prober + 假账号源）；载体保存校验拒绝（API 级）。
- 序列化边界：忽略字段穿过 account JSON 编码 → API 投影 → 前端模型，至少一条链路断言，区分缺省与 false。
- 真机：S2 必须在凭据真实存在的 HOME 上跑（这是第 1 条反馈的根因场景，夹具证明不了）；S7 用浏览器量真实渲染。

## Out of Scope

- 永不做：按条目删除各家凭据 / 代用户登出（粒度不齐，且是用户自己机器上的不可逆动作）。
- 永不做：登录级忽略（用户要的是账号不再出现）。
- 本期不做、后续要做：opencode-go API key 与 OAuth 同账号归并——key 接口不给身份；若日后 opencode 接口带出账号/组织标识再做（落 roadmap）。
- 本期不做：CLI 忽略/恢复子命令（有需要再加，落 roadmap）。
- 不做：底栏颜色/字号调整（用户收窄为只去名字）。
