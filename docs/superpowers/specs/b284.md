## 问题陈述

谁：在 handoff 仓里按平台不变量查图的执行者（`go run github.com/Xsxdot/charter/graph/cmd/codegraph --repo . <子命令>`）。
条件：charter C17 已把 `flow` / `tree` 合进 master，C16 纪律已教「这个方法怎么走用 `flow`」。
通道：Go module 钉版，不是 PATH 上的 `codegraph` 二进制，也不是已删除的 `handoff graph`。
今天的事实：`go.mod` 钉 `github.com/Xsxdot/charter/graph v0.9.0`（C15 tag）。该 CLI 没有 `flow` / `tree`。B277 亲跑得到 `Error: unknown command "flow" for "codegraph"`。
要变的事实：同一条 `go run` 入口能跑 `flow` / `tree`；嵌入的查看器随之换成 C17 契约方法主语（agentd 重编后才进正在跑的控制台）。

## 级别与档位

**L1。**单子系统（handoff 模块钉版），不改消费方 Go 源码，不新增 wire。plan 三行写完。验收是 `go list` + `--help` 一眼可核。

不是 L3：本仓早已对接 `github.com/Xsxdot/charter/graph`（C1.7 宿主挂载）。本期是同一 module 的 additive minor，不是新契约面。

## 方案

选定：把根模块（及 desktop 间接 sum）从 `v0.9.0` 升到 **`v0.10.0`**。零 `replace`。不恢复 `handoff graph` 别名。不改 `internal/discipline/platform.go`（已经是泛型 `<子命令>`）。

弃选：把 `go run` 写进 charter skill（C16 已否）；给各机装 `codegraph` 二进制（B276 已否）；等 GitHub Release 资产（`go run` 吃的是 git tag / module zip，不是 release tarball）。

前置（协调者已做，不在本卡改 charter 代码）：`graph/v0.10.0` 已于 2026-08-28 打在 charter `a35b9524` 并 push。该 tag 的 `go test ./...`（`cli` / `codegraph` / `webui`）本地全绿。

  1. `go list -m github.com/Xsxdot/charter/graph` 输出含 `v0.10.0`
