# B302 终端 tab 里 agent TUI 的 Shift+Enter 应换行却被当成发送

卡：B302
日期：2026-08-30
台账：`docs/superpowers/specs/b302-ledger.md`

无新页面、无布局改动，不走原型。

## 问题陈述

谁：在工作台终端 tab 里跑 Grok / Codex / Claude / OpenCode 等 agent TUI 的人。
条件：TUI 已进入 alt-screen，输入框里想写多行。
通道：浏览器/WKWebView 键盘事件 → xterm.js → `term.onData` → WebSocket → PTY。
要变的事实：Shift+Enter 被 TUI 认成「换行」；Enter 仍是「发送」。今天两者都被当成发送。

现状读数（本卡工作树，标注为现状，contract/plan 复核）：

- xterm `evaluateKeyboardEvent` 的 Enter 分支只看 `altKey`，**完全不看 `shiftKey`**：`web/node_modules/@xterm/xterm/src/common/input/Keyboard.ts` case 13（约 L100–104）写成 `result.key = ev.altKey ? ESC+CR : CR`。Shift+Enter 与 Enter 都是 `\r`。
- 工作台把控制键（含 Enter）原样留给 xterm：`web/src/app/workbench/terminalInput.ts` 文件头边界段。B268 已独占 `attachCustomKeyEventHandler` 槽位，新键必须在这里转发，禁止再挂一个处理器（B268 spec 冻结）。
- 对话 Composer 已经是 Enter 发送 / Shift+Enter 换行（`web/src/app/task/Composer.tsx`），终端 tab 没有对等处理。
- B268 做了 Option-as-Meta、⌘←/⌘→、⌘K，Out of Scope 写明不做完整 Kitty keyboard protocol。本卡只补 **一个** 修饰回车，不是上整套协议。

根因：TUI 用「带修饰的 Enter」区分换行和发送；工作台这条路径把修饰丢了，TUI 只能当成发送。

## 方案

**推荐**

在现有 `installTerminalInputFix` 的 `attachCustomKeyEventHandler`（keydown 段，与 ⌘← 同槽）拦截：

| 条件 | 行为 |
|---|---|
| `key === 'Enter'` 且 `shiftKey` 且 **当前 buffer 是 alternate**（TUI） | `preventDefault` + `stopPropagation`，经 `term.input` 上送 `ESC[13;2u`（CSI u，Shift+Enter），然后 `return false` 不让 xterm 再发 `\r` |
| 主屏（shell / zsh）上的 Shift+Enter | 不拦截，仍走 xterm 的 `\r`——不改变 shell 里沿用至今的回车语义 |
| 裸 Enter、Alt+Enter、Ctrl+Enter | 不拦截 |

`ESC[13;2u` 是当前 agent TUI（Grok / Codex / Claude Code / OpenCode）认的 Shift+Enter，不是实现完整 Kitty 协议。选它而不是裸 `\n`：zsh/readline 也把 LF 当 accept-line，主屏误发会乱；CSI u 对不认识它的 TUI 是「无动作」，比误发送好。

alt-screen 判据与滚轮同一条：`term.buffer.active.type === 'alternate'`（B267/B268 已用）。

**弃选**

- 改 xterm 自己的 `evaluateKeyboardEvent`：要 fork xterm，B 系列终端卡明确不 fork。
- 主屏也改 Shift+Enter：用户痛点只在 TUI；shell 里 Shift+Enter＝执行是常见默认。
- 上送裸 `\n`：和 `\r` 一样会被不少行编辑器当成提交。
- 新挂一个 `attachCustomKeyEventHandler`：会覆盖 B268 的槽位，⌘←/Option Meta 会丢。
- 做完整 Kitty keyboard protocol / modifyOtherKeys：B268 已裁，本卡不打开。

## 用户故事

## 实现决定

- 只改工作台输入补漏这一层。不改 Go/PTY、不改 `TERM`、不改 agent 二进制。
- 字节经 `term.input` 走现有 `onData`，与手敲合流。
- IME：② 那条「Shift 后的 input 先于 keydown」路径的 key 是标点不是 Enter，不得误伤。
- 工作台其它 ⌘ 键、滚轮、划词不动。

## 测试决定（接缝）

1. **`installTerminalInputFix`（`web/src/app/workbench/terminalInput.ts`）← `TerminalTab`**  
   在 mock/夹具终端 `buffer.active.type === 'alternate'` 时，Shift+Enter 经 `term.input` 发出 `ESC[13;2u`，且 xterm 不再另发 `\r`；主屏时 Shift+Enter **不**走这条补发。现状生产调用，不是假缝。

变异：把序列改成 `\r`，缝 1「alternate 上不是 CR」必须转红。

真机验收（acceptance，合 main 门）：在工作台终端 tab 各开一个常用 agent TUI，Shift+Enter 换行、Enter 发送。实现机可用缝 1 的单元测试当机制门，不能替代这扇真机门。
