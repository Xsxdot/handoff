# 建卡入口：项目必须显式、分支接现成端点、标题支持批量（B179）设计

> 状态：**已批准**（用户 2026-08-23 批准）
> 级别：**L2**（单子系统：web 控制台前端；不动契约层——所需端点全部已存在）
> 卡：B179 —— 「现在用web建卡没法选择项目吗？分支也只能手输？能不能做一个批量建卡」

## 1. 问题陈述

用户在控制台建卡时提出三条，逐条查证现状后，第一条比原话严重、第二条比原话轻：

1. **不是「没法选项目」，是「静默选错项目」。** `web/src/app/cards/CardsPage.tsx:144`
   写的是 `const newCardProject = project || cards[0]?.project || 'handoff'`。顶部项目筛选
   停在「全部项目」（`project === ''`）时，新卡的项目**静默取卡列表里第一张卡的
   project**——一个用户看不见、也无法预测的值。而 `NewCardDialog` 通篇不渲染项目名，
   它的文件头注释还明写「不做项目选择：项目由调用方从当前视图上下文传进来」。
   **现场铁证**：B187 建于 web，落到了 `benchmarking` 项目——那不是用户选的。
   叠加 `handoff card update` 只支持 `--title/--priority/--attach/--detach/--accept`
   （`cmd` 层 update 的 flag 集），**项目建错了不可改**，卡就永远错着。

2. **不是「分支只能手输」，是端点早就有、前端没接。** `GET /api/projects/{name}/branches`
   （`internal/agentd/projectadmin.go:846`）返回分支列表、每个分支被哪棵工作树占用、
   以及 `resolveBaseBranch` 推出的默认基线；它的注释明写「建树弹层的两个下拉都吃这份
   数据」。前端连客户端函数都封装好了——`web/src/api/client.ts:596` 的
   `fetchProjectBranches`。只有建卡对话框没接，还把占位符写死成「留空 = 项目主线」。

3. **批量建卡确实没有**，是这张卡里唯一的真新功能。

顺带查出的第四条（现状下拉的另一半缺陷）：`projectOptions` 由
`distinct(cards.project)` 算出（`CardsPage.tsx:90`）。本机已登记 9 个项目位置
（`aio` / `benchmarking` / `charter` / `handoff` / `handoff-server` / `handoff-server-v2`
/ `sq` / `super-dev` / `tk`），但卡上只出现过 3 个 project 值（`handoff`×27、
`charter`×1、`benchmarking`×1）。于是**另外 6 个已登记项目建不了第一张卡**——
它们不在下拉里，而下拉是唯一的项目来源。

## 2. 承重现状（改之前必须知道的）

| 事实 | 出处 | 为什么承重 |
|---|---|---|
| 建卡的项目由调用方传入，对话框本身不渲染也不选 | `web/src/app/cards/NewCardDialog.tsx` 文件头 + 组件全文 | 这是「静默选错」的结构性原因，不是漏写一个下拉 |
| 「全部项目」筛选下的兜底是 `cards[0]?.project` | `web/src/app/cards/CardsPage.tsx:144` | 兜底值不可预测且不可见，是 B187 落错项目的直接成因 |
| 项目下拉的候选来自现有卡而非登记表 | `web/src/app/cards/CardsPage.tsx:90` | 新项目的第一张卡建不出来 |
| `GET /api/projects` 返回 `ProjectLocation[]`（含 name） | `internal/agentd/server.go:471`；类型 `web/src/api/types.ts` 的 `ProjectLocation` | 项目下拉的正确数据源；后端零改动 |
| 前端 `api/client.ts` 有 createProject/deleteProject/patchProject，**没有列项目的函数** | `web/src/api/client.ts:565,574,583` | 唯一要新增的客户端函数，约 3 行 |
| `GET /api/projects/{name}/branches` 已存在且已封装 | `internal/agentd/projectadmin.go:846`；`web/src/api/client.ts:596` | 分支下拉是纯接线，不是新能力 |
| 该端点在项目未登记时返回 404（`GetProjectLocationByName` 未命中） | `internal/agentd/projectadmin.go:862` | 卡的 project 是自由字符串，可能没有对应的登记位置——必须有降级路径 |
| 卡的 `project` 与登记表的 `name` 在本机是同名对齐的 | 实测：卡上 3 个值全部命中登记表 9 项 | 两个下拉可以串联；但这是**惯例不是约束**，代码不能假定它恒成立 |
| 基线分支建卡后不可改，表单已写明警告 | `NewCardDialog.tsx` 文件头 + 表单说明文字 | 项目同样不可改却没有任何提示——本设计要补齐这个对称性 |

## 3. 方案

### 3.1 项目：显式可见、可选、选不出来不让建

- `NewCardDialog` 自己渲染项目下拉，候选 = `GET /api/projects` 的 name 集合 **∪**
  现有卡上出现过的 project 值（后者兜住历史上建在未登记项目下的卡），去重后排序。
- 预选规则，**三档，全部可见**：
  1. 顶部项目筛选选中了某个项目 → 预选它；
  2. 否则取上次建卡用过的项目（localStorage）→ 预选它；
  3. 都没有 → **不预选**，下拉停在空值，「建卡」按钮禁用并提示「请先选择项目」。
- 与现状的根本差别不在「多了个下拉」，而在**预选值永远显示在下拉里、用户看得见**。
  静默错配的成因是不可见，不是没得选。
- 项目下拉旁标注「建卡后不可改」，与基线分支那条警告对称。

**弃选**：给 `card update` 加 `--project`。理由——它要额外判定「这张卡派过任务没有」，
且项目牵着基线分支，两个不可改字段得一起改，范围立刻翻倍；而建错的退路本来就存在且
足够便宜：废弃重建，成本是一个 B 号，而号本来就不复用（用户 08-23 拍板）。

### 3.2 分支：接现成端点，拿不到就诚实降级

- 选定项目后调 `fetchProjectBranches(project)`，把结果渲染成下拉；
  `default` 字段作为「留空 = <真实分支名>」的占位提示，替换现在写死的「项目主线」。
- **允许自由输入**：基线分支可以是一个本地还不存在的分支名，所以形态是
  「下拉 + 可手输」（datalist），不是纯 select。
- **降级路径**（必须有，不是可选）：项目未登记 → 端点 404 → 退回纯手输，并在下拉位置
  显示一行说明「项目 X 未登记位置，分支需手输」。**不把 404 当错误弹出来**——
  给未登记项目建卡是合法动作。
- 分支列表随项目切换重取；切项目时清空已填的分支值（旧项目的分支名在新项目下无意义）。

### 3.3 批量：标题框变多行，字段整批共用

- 标题输入从 `input` 改为 `textarea`，**一行一张卡**；项目 / 工作流 / 优先级 / 父卡 /
  基线分支整批共用同一套值。
- **单张建卡是批量的 n=1 特例**，不新增入口、不新增对话框、不加「批量模式」开关。
- 容错解析：去掉行首的 `-` / `*` / `1.` 列表前缀，跳过空行，逐行 trim；
  这样从聊天记录或文档里粘一份清单进来就能直接用。
- 提交前显示「将建 N 张卡」，N 由解析结果实时算出——用户在点之前就知道会发生什么。
- **逐条提交，逐条报结果**：前端顺序调 N 次现有的 `createCard`，成功的列出卡号，
  失败的列出行内容与原因，已成功的不回滚。
  **弃选**：新增 `POST /api/cards/batch` 做事务内原子建卡。理由——账本本来就在事务内
  逐张分配号且号不复用，部分成功不产生脏数据；为原子性引一个新端点会把这张卡从 L2
  抬成跨子系统，代价不成比例。部分失败的语义是可理解的（「建了 3 张，第 4 张失败：…」）。

## 4. 用户故事

1. 我停在「全部项目」看板上点「+ 新建」，对话框里项目下拉是空的、建卡按钮是灰的，
   我必须选一个项目才能建——不会再有卡莫名其妙落到别的项目里。
2. 我上次给 `handoff` 建过卡，这次直接点「+ 新建」，项目已经预选 `handoff` 并明明白白
   显示在下拉里，我扫一眼就知道对不对。
3. 我要给刚登记的 `sq` 项目建第一张卡——它在下拉里，尽管它一张卡都还没有。
4. 我选好项目后，基线分支下拉列出了该项目的本地分支，占位提示写着真实的默认基线名；
   我也可以直接敲一个还不存在的分支名。
5. 我给一个没登记位置的项目建卡，分支那栏退回手输并告诉我为什么，建卡照常能完成。
6. 我从聊天记录里复制了 5 行想法，粘进标题框，看到「将建 5 张卡」，点一下，
   得到 5 张同项目同工作流的卡。
7. 第 3 行标题因为某种原因建失败了，我看到前 2 张的卡号和第 3 行的失败原因，
   改完那一行重试即可，不用从头再来。

## 5. 实现决定

- 全部改动落在 `web/` 子系统内：`NewCardDialog.tsx` 主体重写、`CardsPage.tsx:144`
  的兜底表达式删除（改为把当前筛选值原样传入，空就是空）、`api/client.ts` 补一个
  `fetchProjects()`。**后端零改动。**
- 项目候选取 `/api/projects` 与卡上历史值的并集，而非只取前者：卡的 project 是自由
  字符串，只认登记表会让历史卡所属的项目从下拉里消失。
- localStorage 的 key 只存项目名一个字符串；读不到或值已不在候选里就当没有，
  不做迁移、不做过期。
- 逐条建卡按输入顺序串行提交，不并发：并发会让卡号顺序与用户写下的顺序对不上，
  而 B 号的顺序是人读账本时的隐含线索。

## 6. 测试决定（接缝清单）

**接缝就一个：`NewCardDialog` 组件**（既有 `NewCardDialog.test.tsx` 已在这个缝上）。
项目/分支/批量三件事的判据全部落在它的输入输出上：给定 props 与 mock 的 API 响应，
断言渲染了什么、提交时调用 `createCard` 的次数与参数。

| 判据 | 落点 |
|---|---|
| 未选项目时建卡按钮禁用、不调 createCard | `NewCardDialog.test.tsx` |
| 预选三档优先级（筛选值 > localStorage > 空） | 同上 |
| 候选是 `/api/projects` 与历史卡值的并集且去重 | 同上 |
| 切项目会重取分支并清空已填分支值 | 同上 |
| 分支端点 404 时降级为手输且不弹错误 | 同上 |
| 多行标题解析：列表前缀、空行、trim | 同上（解析函数可单独导出直测） |
| N 行提交调用 createCard N 次、参数中标题各不相同而其余字段相同 | 同上 |
| 部分失败时已成功的卡号与失败行原因都出现在结果里 | 同上 |

第二个缝 `CardsPage` 只需一条：**断言它不再把 `cards[0].project` 当兜底**
（传给对话框的 project 在「全部项目」下是空字符串）。这条是本设计的核心回归网——
它守的正是 B187 那个缺陷。

**变异复验（验收时必做两条）**：把兜底表达式改回 `cards[0]?.project` → CardsPage
那条必须转红；把「未选项目禁用提交」的判断去掉 → 对应用例必须转红。

## 7. Out of Scope

**永不做**
- `card update --project` / 改已建卡的项目（3.1 弃选，用户 08-23 拍板；退路是废弃重建）。
- 批量建卡的原子事务与 `POST /api/cards/batch`（3.3 弃选）。
- 每行单独设字段的表格式批量（用户 08-23 拍板：一批卡几乎总是同项目同流）。

**本期不做、后续可能要做**
- 在建卡对话框里就地登记一个新项目位置（现在得先去项目页登记）。
- 批量建卡时给每行加优先级前缀之类的行内语法（等真的嫌共用字段不够用再说）。
- 卡的 project 与项目登记表的一致性校验/清理（现在靠同名惯例，代码不假定它恒成立）。

## 8. 备注

- 本 spec 不改任何后端契约，所需两个端点均已上线并已在别处被消费。
- `NewCardDialog` 的文件头注释「不做项目选择」在实现后必须一并改掉——它记录的是
  一个即将不再成立的边界，留着会误导下一个人。
