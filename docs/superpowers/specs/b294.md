卡：B294

基线：`main` @ `c1157471`

## 定级理由

跨子系统、动契约层。执行机上新建「预览会话」并经现有隧道被协调者订阅，是一条新的跨进程 wire；本机再按会话起 SOCKS 与隔离 Chromium。涉及：

- `d_cli`：协调者/执行机终端里的 `handoff preview` 命令族
- `d_gateway`：会话的 HTTP/WS 面、本机消费与拉起浏览上下文
- `d_transport`：把预览窗的 loopback TCP 经现有隧道转到执行机
- `d_protocol`：会话与事件的 wire 形状
- `d_web`：左栏任务组第四种 kind，点击不进工作台

`d_web` 只消费已存在的会话列表，不发明自己的预览真相。对接这条跨机会话契约即使 web 零改也按「动契约层」计。

选轻档：网关与隧道各自都不轻，但 SOCKS 与会话是同一条用户故事的前后段，拆并行子卡会在接缝上等对方。契约冻结照做，实现一轮收口。单子系统若在 breakdown 里超过固定成本，跨流迁重档，不重建卡。

## 问题陈述

谁：在执行机终端里跑 agent CLI（或自己）的人；同时开着一台或多台桌面控制台。  
条件：agent 画了原型静态页，或远端已经有一个 dev server 在跑；这些东西没有、也不值得先登记进 SuperDev。  
通道：执行机上的 `handoff` CLI → 该机 agentd → 协调者本机 agentd 对它的既有订阅（与任务镜像同形：协调者发起）→ 桌面左栏。  
要变的事实：人在**自己正在看的那台桌面**的左栏对应项目任务组里看到一条预览行，点一下弹出隔离 Chromium；这个窗口里的 `localhost` / `127.0.0.1` / `::1` 表示**执行机**的回环，本机不占用 5173/8080。Agent 继续用 SuperDev 点选截图，不走这条预览去操作页面。

不是路径反代 iframe：JS 在本机跑，写死的 `http://localhost:<后端端口>` 会打到笔记本（handoff 自己的 web 虽用相对 `/api`，但开发态站点身份仍是 `localhost:5173`，Host/cookie/WS Origin 都按它转）。也不是把远端端口绑到本机同号端口——多项目、本机已有 Vite、两台桌面会抢端口。

## 方案

执行机只发布会话。所有已订阅的桌面左栏出现一行。点哪台，**只在那台操作系统**上拉隔离 Chromium + 那台的 SOCKS。不自动弹窗。

### 1. 执行机：`handoff preview`

CLI 打**它所在机器**的 agentd，不携带协调者地址。

- `preview open --port <n> [--via <名单>]`：入口是 `http://localhost:<n>`。该端口必须已在 owner loopback 上监听，否则失败并带原文（agent 不得以为已经给人看了）。
- `preview open --path <工作区相对路径> [--via <名单>]`：静态页。owner agentd 在本机 loopback 起一个只服务该工作区子树的 HTTP，入口仍是 `http://localhost:<ephemeral>`，后面走同一条 SOCKS，不走 `file://`。
- `preview close <id>`：关会话。本机已拉起的 Chrome / SOCKS 随会话关闭回收。
- `preview list`：本机会话（排障用）。

成功 = 会话已落库。CLI **不等**任何桌面开窗。给 agent 的话是「预览已发到桌面，在对应项目任务组点开」。

`--via`：逗号分隔的 IP、CIDR、域名。默认**不加**。默认投影的是执行机整段 loopback（所有端口），所以后端 8080 不必声明。域名在执行机上解析。

### 2. 会话身份（执行机算，桌面自己对树）

会话带：id、入口 URL、`--via`、cwd、git origin（可空）、分支（可空）、创建时间、TTL。  
**不带**协调者树上的项目显示名。桌面用 `FromOrigin` 对 `project_id`；对不上进「未归属」。

### 3. 通知：可补拉，不只推给当时在线的

owner agentd 持久化会话，发 `preview.created` / `preview.closed`。  
协调者本机 agentd 对每台已登记开发机（含本机身份）发现 + 订阅，形态同任务镜像：活着立刻收到，重连先拉未关闭列表再跟 WS。浏览器只连本机一条 WS。

两台桌面连同一本机 agentd：同一份列表。两台笔记本各跑 agentd、都登记了这台执行机：两边都看到行；点 A 只在 A 弹窗。

关其中一个 Chrome **不**删执行机会话。会话在 TTL、`preview close`、或 owner 判定入口不可达时消失。TTL 默认 2 小时空闲（有 Chrome 附着则续命）；精确数值归 contract。

### 4. 点开：本机 agentd 拉隔离 Chromium，薄壳不动

左栏点击 → 本机 agentd（不是 Wails 壳）：

1. 为这条会话在 `127.0.0.1` 上开 SOCKS（外网连不上；鉴权/随机端口，只有这次拉起的 Chrome 用）。
2. 拉起 **Chromium 可执行文件本身**（Chrome / Edge / Arc / Brave / Chromium，本机检测），必须带：
   - 独立 `--user-data-dir`（禁止复用日常 profile，否则执行机 `localhost` cookie 与本机 Vite 互串）
   - `--proxy-pac-url` 或等价 PAC：允许名单走 SOCKS，其余 DIRECT
   - `--proxy-bypass-list=<-loopback>`（关掉 Chromium 默认「localhost 不走代理」；漏了会静默打到本机）
3. 打开会话入口 URL（`http://localhost:<port>`）。
4. 再点同一行：聚焦已有窗口，不拉第二份。
5. 找不到 Chromium：行上/点击失败给出可行动原文（去装 Chrome 或告诉检测路径），不退回 iframe、不退回系统 `open`。

不要用 `open -a "Google Chrome"`：它不能可靠地把代理 flag 交给新实例。

本机预览（`preview open` 就在协调者这台）走同一条 SOCKS，不走捷径。

### 5. SOCKS 策略

| 目标 | 行为 |
|---|---|
| `localhost` / `127.0.0.1` / `::1` 任意端口 | 隧道到 **owner** 去 dial 它自己的回环 |
| `--via` 里的 IP / CIDR / 域名 | 隧道到 owner，由 owner 去 dial；域名 owner 解析 |
| 其余 | DIRECT（本机出网） |
| 非 loopback、非名单 | 拒绝 CONNECT，不是降级到本机内核 |

不是任意 TCP 代理。不是系统代理。不是把执行机整张内网默认搬过来。

副作用（接受）：这个窗口能打到执行机 loopback 上其它服务。一期不端口拒绝名单；记 roadmap。

### 6. 左栏

挂在对应项目的 **「任务」组**，第四种 kind：`preview`。不是目录组，不是 `OpenItem`（那是工作台窗格投影），不能拖进中央。

- 行：类型图标（单独一套，不借用机器行 monitor、不借用 dispatch-task）+ 名称 + 右侧机器绿点与机器名。名称：`localhost:<port>`，有分支则 `分支 · localhost:<port>`。
- 未在本机开窗：普通行。本机已拉起 Chrome：`is-open`。不用 `is-selected` 去跟焦点窗格抢。
- 点击：开/聚焦独立 Chromium。**禁止** `onOpenTask` / 新建标签组 / 加列。
- 项目行进行中计数把活跃预览算进去。
- 搜索能按名称、机器、端口命中。
- 未对上项目：未归属组，开窗照样可以。

形态沿 B288 `TaskRow` / option-1 `.task-row`，只加 kind。不新 fork 原型站、不新开页面。这是左栏结构增量，不是新页面布局。

## 用户故事

1. 我在 linux-01 的终端里让 agent 跑 `handoff preview open --port 5173`。两台桌面左栏该项目任务组都出现一行 `localhost:5173`。我点正在看的那台，弹出隔离 Chrome，页面里请求 `http://localhost:8080` 打到 linux-01 的 8080；另一台仍是未打开态。
2. 本机已经有 Vite 占着 5173。预览窗仍然工作，因为本机没有为远端 5173 再 listen。
3. agent 打开 `prototypes/foo/index.html`（`--path`）。我点行后看到静态页，相对资源能加载。
4. 带 `--via 10.1.0.0/16,*.corp.local`。预览窗访问这些地址走执行机；`https://fonts.googleapis.com` 仍从本机出。
5. 关掉 Chrome 后行还在（会话没到期）。再点再开。`preview close` 或 TTL 后行消失，本机进程被回收。
6. 本机没装任何 Chromium：点击失败，文案告诉我缺浏览器，左栏行仍在。

## 契约语义与接缝（L3，定语义不定签名）

1. **会话所有权在 owner 机器 agentd。** 协调者不存一份自己的真相去覆盖它。关闭以 owner 为准。
2. **连接方向不反转。** 执行机不拨协调者。通知 = 协调者订阅 owner 的会话面（发现 + WS + 列表补拉）。
3. **投影的是浏览上下文的网络命名空间，不是像素，也不是本机端口号。** `localhost` 在预览窗里 = owner loopback。本机内核不为远端端口 listen。
4. **允许名单是会话字段，默认仅 loopback 全体端口。** 扩大范围只经 `--via`，会话级，不改系统代理。
5. **开窗是每台桌面自己的点击，落在点下去的那台机器的 agentd。** 多消费者互不抢会话。
6. **项目显示名不是契约字段。** 对树用 origin → `project_id`。
7. **薄壳不新增能力。** 拉 Chrome、开 SOCKS、PAC 全在本机 agentd。
8. **预览行不是工作台内容。** 不进入标签组、不进 `OpenItem`、不可拖放到窗格。

依赖方向：`d_web` → 本机 agentd 的预览只读面；本机 agentd（gateway）→ `d_transport` 既有隧道去订 owner、去拨 SOCKS 上游；`d_cli` → 所在机器 agentd 的预览写面。禁止 web 直连执行机，禁止执行机 config 里写协调者。

## 实现决定

- 复用 `targetclient` 池与任务镜像的发现/重连节奏，不新开 SSH、不新造通用 `machine_events` 账本。
- Chromium 检测失败是产品错误，不是静默降级。
- 静态 `--path` 必须落在工作区根内（realpath，与现有文件 API 同一条越界纪律）。
- 日志可记会话 id、机器、端口、via 基数、Chrome pid；禁止记 PAC 全文以外的 nonce/凭据、禁止记页面内容。

## 测试决定（接缝清单）

1. **owner 上创建/列出/关闭预览会话**（将被 CLI `handoff preview` 调用，导出在控制面）。端口未监听 → 创建失败；`--path` 越界 → 创建失败；关闭后列表不再包含。
2. **协调者消费面**（将被本机 web 与「点开」调用）：owner 上有会话时，登记了该机的协调者能列出并跟到关闭；重连只靠列表补拉仍能看见未关闭会话（禁止「只推给当时在线 WS」）。
3. **SOCKS 允许名单**（将被隔离 Chromium 的 PAC 指向；边界型，解析/拒绝入口即缝上符号）：`localhost:<后端端口>` 在 owner 上接通；非名单 host 拒绝；SOCKS 监听非 loopback 拒绝。不在单测里真拉 Chrome。
4. **左栏 `preview` kind**（`ProjectTree` 任务组，调用方 Shell）：对得上 origin 的会话出现在该项目任务组；对不上进未归属；点击回调不是 `onOpenTask` / 不是往工作台加组；本机已附着时行是 `is-open`；进行中计数含活跃预览。禁止拖放 MIME。

变异：把 SOCKS 改成「本机 listen 同号端口」→ 故事 2 抢端口转红。把点击接回 `onOpenTask` → 故事 1 中央多出 TUI 组转红。把 Chromium localhost 绕过漏掉 → 故事 1 的 8080 打到本机转红（真机）。

本节点该干什么一律以注入的纪律块为准。
