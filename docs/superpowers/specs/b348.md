# B348 删除未入队载体（清 b334-probe）

- **卡**：B348
- **级别**：**L1**。plan 增量为零：登记面补对称的 CAS 删除。验收一眼可核：未入队载体能删；入队的拒绝；b334-probe 从编制快照消失。
- **状态**：**已批准**（2026-09-05；用户自主清尾巴）
- **基线**：`origin/main` @ `47a57d7b`
- **发现自**：B334 探测残留载体 `b334-probe`（machine=`本机`，pending v1，不在任何小队）。registry 已有 `Delete(kind,id,expect,actor)`，编制域没有 `DeleteCarrier`，HTTP 没有 DELETE，设置页没有删除按钮。不 reopen B334。

## 问题陈述

载体只有 PUT。探测用的 `b334-probe` 清不掉，只能停在快照里。删除必须 CAS，且**仍在任一小队成员里的载体拒绝删除**（先改小队再删，避免小队引用悬空）。

图：`codegraph sym PutCarrier` → `internal/scheduling/scheduling.go#Service.PutCarrier`。删除与 PUT 同一域入口。

## 方案

编制域 `DeleteCarrier(name, expect)`：name 空 → `ErrInvalid`；遍历小队成员，命中 → `ErrInvalid`（文案带小队名）；否则 `repo.Delete(kindCarrier, name, expect, actor)`。找不到 → 既有 `ErrNotFound`；版本不对 → 既有 CAS 冲突。

HTTP：`DELETE /api/squads/carriers/{name}?expect=N`。`expect` 与 PUT 同纪律（缺席/非法 400）。域错误翻译：`ErrInvalid` 400、`ErrNotFound` 404、CAS 409。成功返回与 PUT 同形的 `{name, version}`（删除后的 version 语义：用请求的 expect 回显即可，客户端以快照刷新为准）。

设置页：每个载体行一个「删除」按钮，带当前行 `version` 调 DELETE；失败把服务端文案展示在该行（入队拒绝可直接读到）。不弹第二层确认——API 已挡入队载体。

弃选：硬删账本行绕过编制域（无入队检查）。弃选：入队也允许删、小队成员变悬空。

## 用户故事

1. 作为编制：未入队的 `b334-probe` 能从设置页删掉，刷新后快照没有它。
2. 作为对照：删 `grok`（在 leader/runner 里）被拒，载体仍在。
3. 作为对照：expect 与当前 version 不符 → 409。

## 测试决定

缝 1：`Service.DeleteCarrier` ← HTTP DELETE。
缝 2：`DELETE /api/squads/carriers/{name}` ← 设置页删除按钮。
缝 3：设置页「删除」← `deleteCarrier(name, expect)`。

1. 未入队载体：Delete 成功，再 Get 为 NotFound。
2. 仍在小队：Delete 返回 `ErrInvalid`，载体仍在。
3. HTTP：未入队 200 后 GET /api/squads 不再含该名；入队 400；缺 expect 400。
4. 页面：点「删除」调用 DELETE 且 query 含该行 version。

真机（协调者，不派执行者）：部署后 `DELETE /api/squads/carriers/b334-probe?expect=1`，再读快照确认消失。
