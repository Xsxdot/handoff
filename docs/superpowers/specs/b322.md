工作树：仓内分支 `fix/B322-restore-pump`

## 定级理由

主改动落 web 工作台：恢复合成层不再把 workspace 活孤儿收成新组；无 sessionId 的终端 tab 不再静默建会话。agentd 侧只修既有扇出实现——`ptySessionsAll` 跳过 `IsSelfTarget` 为真的 target——`PtySessionsResp` 形状不变。不跨契约面，不是 L3。计划写出来不会只复述本页（spawn 门、收编范围、扇出跳过、隔离验收），所以不是 L1。

## 问题陈述

谁：打开桌面端/控制台的用户（本机 agentd + 配对机）。
通道：打开控制台 → `useWorkbenchSync` 拉落盘快照 + `scope=all` 会话扇出 → `buildRestore` → 各 `TerminalTab` 挂载。
要变的事实：连续两次打开之间，中央区终端 **tab 组数不得因恢复而增长**；无 sessionId 的恢复 tab 不得在用户未点「重开」时新建 shell；`targets.local` 指向本机 loopback 时，`scope=all` 不得把本机会话列两遍。

根因（核过，见卡更正 note）：B283 挡住了远端扇出缺席误剥和跨机 home 收编。剩下的泵是：恢复把死 id 剥掉 → `TerminalTab` 无 id 即 `createPtySession` → 新会话活着但原 tab 的新 id 未必落盘 → 下一轮把活着的 workspace 会话 `appendRestoredTab` 成新组。放大器：`targets.local` 自扇出把列表计数翻倍。08:53 重启空窗不是这次 7→104 的主因。

## 方案

1. **workspace 活孤儿不再收编成新组。** 恢复 ③ 只收本机 home 会话进悬浮窗（B283 已限）。workspace 会话没有对应 tab 时留在 ptyhost，不在中央区造组。用户要开终端仍走「新终端」。
2. **静默自建改为显式 spawn。** `TerminalTab` 仅在 `spawn===true` 或用户点了「重开一个终端」时建会话。恢复剥掉 id 的 tab 走与 1008 相同的重开出口，不建 shell。用户点的新终端（`openTerminal` / 空白页点选 / 拖目录 / 左栏按钮 / 浮窗 + / 房间 attach）带运行时 `spawn: true`（不落盘，与 `incompatible` 同类）。
3. **扇出跳过本机回环 target。** `ptySessionsAll` 对 `IsSelfTarget` 为真的登记名不发起转发、不盖 `machine=local` 章。本机行仍由本地 `pty.List()` 领衔。

### 弃选

- **弃：给本机 prune 加重启空窗门控。** 认领在 listen 之前；这次爆炸发生在 agentd 一直活着的 09:11–09:55。修错窗口。
- **弃：自动 GC 无引用 PTY。** 会杀掉用户以为还活着的后台 shell。本期不做，落 roadmap。
- **弃：恢复时把所有组的 TerminalTab 改成懒挂载。** 能减挂载风暴，但不修泵本身；B270 keep-alive 仍有效。本期不做。
- **弃：bump 持久化版本清掉 132 组存量快照。** 用户布局被一刀切。修复后不再增长；存量由用户自己关组。

## 用户故事

1. 作为用户，我打开控制台、关掉、再打开，中央区终端组数不因恢复而增加（真死的会话：原 tab 留着，等我点重开）。
2. 作为用户，恢复出来没有 sessionId 的终端 tab 显示重开入口，在我点之前服务端不会多一个 shell。
3. 作为用户，我点「新终端」仍然马上得到一个新 shell。
4. 作为用户，配置里即使登记了指向 127.0.0.1 的 `local` target，会话列表也不会把本机每一条列两遍。

## 实现决定

- 收编判据收口在 `buildRestore` ③：只处理 `base_kind==='home' && machine===''`。
- spawn 是运行时字段，编码时剥掉；缺席默认不建会话（fail-closed）。
- 「重开」在无 sessionId 时也必须能建会话：本地 `forceSpawn` 进 effect 依赖。
- 扇出跳过发生在 `ptySessionsAll` 遍历 `pool.Names()` 时，用已有 `Server.IsSelfTarget`。
- 不改 `PtySessionsResp` 字段，不 bump `PERSIST_VERSION` / `DOCK_PERSIST_VERSION`。

## 测试决定（接缝清单）

| 缝 | 符号 + 调用方 | 断言 |
|---|---|---|
| 1 | `buildRestore` ← `useWorkbenchSync` | workspace 活孤儿 adopted=0、组数不增；本机 home 仍收进 dock |
| 2 | `TerminalTab` ← `WorkbenchPage` / `HomeDock` | 无 spawn 且无 sessionId：不调 `createPtySession`，出现重开按钮；`spawn` 为真：建会话并 onSession |
| 3 | `ptySessionsAll` ← `handleListPtySessions` | machines 不含本机回环登记名；远端名仍在 |

内部锁（从缝构造不出）：`openTerminal` / `newTerminal` 写入 `spawn: true`——入口是 hook 不是 TerminalTab。声明：从缝 2 喂的是 props，写不出「openTerminal 的 content 形状」。

## Out of Scope

- **永不做：** 打开控制台时自动杀掉无 tab 引用的 PTY（用户可能当后台用）。
- **本期不做、后续要做：** 无引用 PTY 的空闲回收策略（需产品闸）；控制台不挂载非当前组的 TerminalTab（性能，B270 相关）；生产机 132 组快照的人工清理指引。后者写入 `docs/roadmap.md`。
