# B469 审批规则与协调者权限统一（草稿）

- 状态：**方向已获用户批准（2026-10-23），进入 plan**。修订 r1.0，基线 `a79b42867`（2026-10-23）；事实见[台账](b469-approval-batch-ledger.md)。
- 级别：**L3**。跨权限门、审批/工单、协调者承载与 agentd API、CLI/UI 的契约。
- 批次：B458、B463、B469、B470 四卡统一设计，各自独立验收；协调者在四卡收口后统一审查（未新建父卡）。

## 问题与方案

现有任务权限请求进入静态判据→审批模型→人工流程；push 驻场协调者经 `residentpush → keystone → coordinatorRunner.Resume → hostapi` 恢复会话，其 CLI 权限事件没有进入 Manager 审批链。用户希望用带条件、来源、可撤销的授权规则减少重复打断。首版规则可以跨项目全局；明确授权的规则可覆盖指定“必须人工”限制；不得引入无限制放行。

统一审批规则权威与裁决入口，让任务与协调者以各自真实主体身份提交权限事实。规则必须有明确匹配条件、来源和撤销状态；只能在条件全部匹配时授权。失败、规则不匹配或不能证明时沿用人工升级。一次批准和保存规则是不同动作；B458 提供快捷保存动作，但不由模型自动创建长期规则。

**已实现，不重复做**：B460/B465 已将任务形态、工作树、产物目录、临时目录及只读政策交给审批模型，并透传跨机审批。B470 复用已有上下文，并核查审批理由、已有授权及规则命中信息是否足够。

弃选：继续依赖 executor 私有策略无法覆盖协调者 hostapi；只改提示词不能产生可审计、可撤销的授权事实。

## 落位三问

① **权威数据**：审批领域拥有规则形状、匹配、授权与撤销；任务状态/工单仍归任务编排；协调者会话与承载仍归 agentd/hostapi。调用方传入最小上下文，审批不反查他方内部。

② **谁消费**：权限门、任务审批和 hostapi 消费统一审批能力；CLI/UI 经应用边界管理规则。跨进程使用既有契约面扩展，不让 web/CLI 自行解释规则。共享账本版本化注册表是全局规则持久化候选，账本只存取，规则语义归审批领域。

③ **同步还是异步**：裁决与规则创建/撤销均同步返回结果；审计可走既有事件/账本通道，但不是第二条授权决策通道。

## 目标架构与实现边界

- 审批领域是规则唯一所有者；共享账本可以提供全局持久化，但不持有匹配逻辑。CLI/UI 调用审批规则管理面，权限消费者调用统一裁决面。
- 请求携带真实主体类别及其上下文。任务调用使用现有任务上下文；协调者调用使用协调者会话/carrier/工作目录事实。不得借造 task ID 复用任务链。
- 原有静态判据和人工升级仍生效。规则只能覆盖其明确列出的限制；规则匹配不能被概括为全局 allow。规则需可读、可撤销、可追溯其来源；读取/解析失败不得扩大授权。
- B463 修 shell 语义判定：区别 grep 搜索参数和命令位置，不用 `handoff` 子串扫描。不可静态证明安全时人工升级。旧 agy 故障不在本期。
- UI 仅要求行为：人工批准时可确认保存规则，查看条件/适用范围/来源/覆盖项，并可撤销；不规定新页面形态。
- 精确 schema、API 签名、兼容字段与页面布局由 plan/首故事按上述边界形成，不在 spec 抢写。

**覆盖范围已批准（2026-10-23）**：部署、push、handoff 管理命令、凭据读取、任务范围外写入均允许用户逐项创建明确规则覆盖人工审批；没有规则命中的人工审批限制转人工。已有非人工路径不因此收紧。规则保存与一次批准分开，记录授权来源与覆盖项。

## Out of Scope

- **本期不做，后续重走 spec**：旧 agy 故障专项；自动生成规则、模型自主保存规则、规则统计/学习；未经用户批准的新页面形态。
