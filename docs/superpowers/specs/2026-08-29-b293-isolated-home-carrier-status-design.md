# B293：隔离 HOME 生命周期 + 载体四态

- **卡**：B293
- **级别与档位**：**L3 轻档**。改编制域载体契约（`Healthy bool` 升格为一等状态；探测/检测/运行命令是新的跨进程操作），跨 `d_scheduling` × `d_gateway` × `d_web` × `d_execution`。单条用户旅程（登记 → 探路径 → 保存后检测 → 派发只放行已上线），不值并行子卡。签名与端点形状归 contract。
- **状态**：已批准（用户 2026-08-29：非空无凭据选方案 1；检测按钮；四态含不可达与限额中；原型形态「可以」）
- **基线**：`acc/b156.2-156.3`
- **形态权威**：`prototypes/b293-carrier-home/`（file:// 直开；设置页自动化分区）。实现与验收对照该副本的载体卡/登记弹窗，不靠文字转述 UI。入库按 B279 先例 `git add -f`。
- **台账**：`docs/superpowers/specs/b293-ledger.md`

## 问题陈述

谁在什么条件下，通过什么关系，使什么事实变化：协调者在设置·自动化登记或编辑载体时，隔离 HOME 必须有可管理的默认路径，并在改路径时告诉他这个目录能不能用；保存之后系统对该载体做一次检测，把状态写成可观察的事实；小队派发只消费「已上线」的载体。

现状（2026-08-29 读 `acc/b156.2-156.3`）：

- 载体有 `home_dir`，控制台手填，无默认、无探测、无创建、无唤起。原型占位曾写 `~/.handoff/homes/…`；本卡默认根是用户指定的 `~/.handoff/home`。
- `PutCarrier` 把 `Healthy=false` 强行改 `true`（`internal/scheduling/scheduling.go`：注释写「本期没有探测手段，未探测不得表现为不健康」）。`admitInto` 已经跳过 `!Healthy`。
- wire：`CarrierView.healthy`（`internal/proto/scheduling.go`）；`CarrierInput` 刻意不含 healthy。
- 协调者拉起已把 `carrier.HomeDir` 打进会话 spec（`internal/agentd/scheddrain.go`）。执行者任务仍走各自策略：codex 丢弃 `CODEX_HOME` 复用 `~/.codex`；grok 用任务级 `grokhome` 再软链 `~/.grok/auth.json`。健康位如果只看隔离 HOME、派发却不消费它，会对不上。
- 项目仓库默认落 `DataDir/repos/<名>`。隔离 HOME 按同一管理方式落 `~/.handoff/home/<载体名>`。

B156.3 把「CLI 限额探测 / 健康位只留形状」推进 roadmap。本卡把**状态模型与检测**提前落地；**自动查限额**仍留后续。

## 方案

隔离 HOME 仍是载体必填属性（不新开「用本机主 HOME」开关，沿用 B156.3 §4.3）。补齐生命周期：

1. 选隔离 HOME 时默认填该载体所在机器上的 `~/.handoff/home/<载体名>`（`~` 在目标机展开）。用户可改。名字还在跟着默认走时，改载体名则改默认路径；用户改过路径之后不再覆盖。
2. 改路径就探测（打到载体所在机器）：目录是否存在/是否为空、有无该 CLI 的凭据。提示三类——空（含尚不存在）或已登录：保存后将自动创建；非空且无该 CLI 凭据：不覆盖、不自动创建，可保存，状态为未上线。
3. 保存新建，或保存时 `home_dir` 变了：状态落 **未上线**，立刻自动检测一次。成功 → **已上线**；否则停在未上线，等用户点检测。
4. **检测**与创建后那一次是同一条动作，可重复。
5. **运行**只复制服务端给出的一条命令（客户端不得拼接），用户在该载体所在机器的 TUI 里自己跑，用来登录或排障。
6. 状态是一等字段，取代 `Healthy`。派发只读，不写状态。

弃选：

- **继续用 `Healthy bool`**：否。创建/登录/限额/网络失败的动作不同，一个位分不出。
- **非空无凭据拒绝保存**：否。用户选方案 1，允许保存为未上线。
- **非空无凭据当空目录覆盖**：否。不可逆，禁止。
- **已上线后网络失败退回未上线**：否。登录 CTA 会在抖动时出现。走 **不可达**。
- **已上线后网络失败仍显示已上线**：否。准入会放行，失败发生在任务里。
- **等派发时再探健康**：否。健康位和派发失败缠在一起。检测是显式动作。
- **控制台里直接拉起交互式登录 TUI**：否。运行只复制命令；检测必须有时限，不得把控制台卡在登录交互里。

## 用户故事

1. 作为协调者，我点「登记载体」并填载体名，HOME 自动变成 `~/.handoff/home/<名>`，我可以改。
2. 作为协调者，我改 HOME 路径时立刻看到探测提示：将自动创建 / 已登录 / 目录非空且未见凭据。
3. 作为协调者，我保存一个空目录或已登录目录的载体后，系统自动检测一次；过了就是已上线，不过就是未上线。
4. 作为协调者，我保存一个非空且无凭据的路径，载体仍能登记，但是未上线，不会覆盖那个目录。
5. 作为协调者，我在未上线的载体上点「运行」得到一条命令，在该机 TUI 登录后点「检测」，载体变为已上线。
6. 作为协调者，已上线的载体后来机器够不着，我点检测后看到 **不可达**，再通了再点检测回到已上线。
7. 作为协调者，我看到 **限额中** 时知道这是额度问题、不是没登录；本期可以靠检测写入这个状态，自动查限额进出归后续。
8. 作为协调者，小队里可以挂未上线/限额中/不可达的成员，但点火和拉起只用 **已上线** 的成员。

## 契约语义与接缝

本卡改编制域已冻结形状，语义如下（签名归 contract）：

**载体状态**四值，用户可见名即产品名：

| 状态 | 含义 | 进派发 |
|------|------|--------|
| 未上线 | 刚创建，或还没登录 / 凭据失效；从未成功上线过时的探测失败也停在这里 | 否 |
| 已上线 | 最近一次检测成功 | 是 |
| 限额中 | 账户到限额，已知可恢复 | 否 |
| 不可达 | 曾经已上线，现在探不到（网络、机器） | 否 |

状态由服务端持有。登记/编辑请求不得设置状态（沿用今天 `CarrierInput` 不含 healthy 的方向）。最近一次检测说明（给 UI 的那句原因）随状态一起投影，不参与准入。

**写入点**只有：创建（及 `home_dir` 变更的保存）→ 未上线；检测（含创建后自动那一次）。派发、清队、唤醒**只读**状态。

**检测如何改状态**（曾经是否已上线，以检测前的状态是否为已上线/限额中/不可达为准——后两者都算「上过线」）：

- 能跑且凭据可用 → 已上线
- 识别为额度用尽 → 限额中
- 机器/网络够不着：上过线 → 不可达；从未上线 → 未上线
- 需要登录或未见凭据 → 未上线

**准入**：按成员声明顺序，只对 **已上线** 且有空位的载体尝试原子准入。小队里没有已上线且有空的载体 → 沿用「没有健康载体」这条失败（配置/状态问题，不是满员排队）。限额中/未上线/不可达都不得被选中。

**路径探测**是只读：问某台机器上某路径相对某 CLI 是空/已登录/非空无凭据。不创建、不覆盖。

**检测**是写：在载体所在机器上，用该载体的 HOME 唤起对应执行者一次（有时限），为空白 HOME 落执行者自己的文件，并按上表写状态。

**运行命令**由服务端按载体（机器 × CLI × HOME × 模型）生成，客户端只复制。

**运行时 HOME**：该载体此后的协调者拉起与小队派发，账户/凭据以载体 `HomeDir` 为准。执行器为审批门另建的任务级沙箱可以叠在上面（grok 的任务级 `grokhome` 钉 `permission_mode` 仍合法），但凭据不得再指回机器主 HOME——除非本轮凭据来源是「主 HOME 同步」的供给动作（把主环境认证态搬进隔离 HOME）。`HomeDir` 非空时覆写进程 `HOME` 的既有规则保持（`internal/hostapi/driver.go` 的 HomeDir 赢过 env 清单）。

接缝：

1. **编制准入只放行已上线** — 存量符号 `scheduling.Service.Admit` / `LaunchAdmit`（经 `admitInto`）。调用方：`internal/agentd` 小队点火与协调者拉起。缝级断言：未上线/限额中/不可达成员被跳过；全员都不是已上线则走「无健康载体」，不得当成满员排队。
2. **登记不再把未探测写成已上线** — 存量 `scheduling.Service.PutCarrier`。调用方：`PUT` 载体的 gateway。缝级断言：新建为未上线；禁止再把 false/零值翻成已上线。
3. **路径探测** — 新建操作，调用方设置页改 HOME 路径。对面是目标机文件系统与该 CLI 的凭据落点（边界型）。断言：空/不存在、已登录、非空无凭据三类可区分，且不修改目录。
4. **检测/一次性唤起** — 新建操作，调用方创建后自动一次 + 载体卡「检测」。对面是目标机上的执行者进程（边界型）。断言：有时限；空白 HOME 被执行者落文件；状态按上表迁移；不在控制台里进入交互登录。
5. **运行命令** — 新建操作，调用方载体卡「运行」。断言：返回的命令含该载体 HOME 与 CLI，客户端不拼接。
6. **控制台编制面** — 存量设置·自动化分区（`SchedulingPage`，调用方 Settings `?section=automation`）。断言：四态、检测/运行、默认路径与三类探测提示对照原型。

假缝：路径是否等于「上一份默认」的前端判断、文案拼接，不占缝。

## 实现决定

1. 默认根目录与项目仓库同款：统一管在 `~/.handoff/home/<载体名>`，落在**载体所在机器**。用户可见的默认串就是这个；Windows 上 `~` 的展开是目标机的事。
2. 创建后自动检测一次；之后只通过「检测」写状态。派发失败不回写状态。
3. 「运行」复制命令，「检测」探状态，两按钮都在载体卡上（对照原型）。
4. 主 HOME 同步：隔离目录空、主 HOME 已有该 CLI 凭据 → 探测为已登录，保存后把认证态搬进隔离 HOME（供给动作本卡要做；不搬技能/规则树，协调者「全套 HOME」其余部分不在本卡扩范围）。
5. 执行者派发必须消费载体 `HomeDir`。codex 在载体 HOME 非空时不得再丢弃 `CODEX_HOME` 去复用用户级 `~/.codex`——那会让隔离档案与真实运行态对不上。
6. 形态以 `prototypes/b293-carrier-home/pages/settings.html` 为准。
7. B156.3 契约原文「健康位本期只有形状、登记缺省 Healthy=true」由本卡废止，在 contract 节点改冻结文本。

## 测试决定（接缝清单）

最高可测缝是编制准入（状态 → 是否放行）和检测写状态。路径探测与唤起是边界型，表驱动三类/四态迁移，真机补登录与空目录落文件。

每条缝对应上面契约段 1–6，每条至少一支缝级断言。面板内部 helper 不占名额。

## Out of Scope

- **永不做**：把「非空且无该 CLI 凭据」的目录当成空目录清空或覆盖。
- **永不做**：新开「使用本机主 HOME、不隔离」开关（与 B156.3 隔离是物种边界冲突）。
- **本期不做、后续要做**：自动限额查询（周期把已上线 ↔ 限额中，无需人点检测）。来源本卡 + B156.3 roadmap「CLI 限额探测」。
- **本期不做、后续要做**：不经检测、由派发失败或后台探活把已上线改成不可达。
- **本期不做**：B292 小队按成员载体设并发（独立卡）。
- **本期不做**：把协调者技能/全局规则树完整拷进隔离 HOME（本卡只做凭据供给与空目录唤起落文件）。
- **本期不做**：在控制台内嵌执行者登录 TUI（attach 深聊通道仍按 B156.3，本卡运行按钮只复制命令）。

## 备注

四态英文键、HTTP 路径、凭据文件按 CLI 的具体文件名，一律归 contract。探测「已登录」的判据按各执行者既有预检（如 codex 的 `auth.json`）在 contract 列成表，本 spec 只要求「有无该执行者凭据」可观察。
