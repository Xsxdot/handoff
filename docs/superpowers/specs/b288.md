# B288 工作台五处真机修整：tab 原名、拖放落点、列宽不横滑、终态进已结束、左栏层级重绘

状态：**形态基准已获用户批准**（2026-08-29，用户拍板「以原型为基准」并授权无人值守推进至合并前）。
定级 **L2**（单子系统 web，不动跨子系统契约）。发现自 B285 真机（2026-08-28）。

## 形态基准（硬规则）

样式一律**一比一对照原型代码**移植，禁止凭文字转述实现。两份原型都在本分支仓库内：

- `prototypes/base/pages/project-tree-option-1.html` —— 左栏层级 + 顶部 chrome
  （面包屑条 workspace-context + 标签栏 workspace-tabbar）的**唯一样式真源**；
  配套 `prototypes/base/design-qa.md`（左栏部分已过 QA，无未决 P0/P1/P2）与
  `prototypes/base/assets/`（静态图标，含 dispatch-task.png 供任务类图标用）。
- `prototypes/b288-workbench-ux/index.html` —— 分栏区五条形态（拖放落点、列宽、
  任务组组成、已结束、窗格标题）的形态真源；其 CSS 即落点视觉与列行为的样式真源。

实现者动手前先打开两个原型文件读样式定义，逐条对照移植；本 spec 不复述样式数值，
数值以原型代码为准（原型里的注释即设计意图）。

## 问题陈述（真机五条，现状读数 @ 4e317fe0e）

1. **任务打开后名字变成 `TUI · xxxx`**。标题生成函数对 tui 用 `taskId.slice(0, 8)`
  （现状读数 `web/src/app/workbench/tabs.ts:387`），打开前左栏明明显示任务标题。
  打开后 tab 条应继续显示任务原名，与左栏行一致。
2. **拖任务到黑底终端窗格上看不出会怎么分**。现落点指示是 `ring-primary/60` 描边加
  3px 边条（现状读数 `web/src/app/workbench/WorkbenchPage.tsx:369-387`），在黑底
  xterm 上对比不足；且拖动事件可能被终端 canvas 截走，落点根本不出现。
3. **分屏超过两列顶出窗口、必须横滑才能看全**。用户实拍三列把窗口顶出（21.49.03）。
  目标：列均分可用宽度压进窗口，容器不允许横向滚动。
4. **一堆已完成的派发混在任务列表里**。「已结束」分组今天只收「目录已被回收」的
  终态任务（现状读数 `web/src/app/tree/archived.ts:48-76` 只收 orphan），
  目录还在的 completed/failed 全部留在普通任务行里。
5. **左栏层级分不清**：项目 / 任务·目录 / 机器 / 行四种行长得差不多，折叠箭头在
  标题左侧（现状读数 `web/src/app/tree/ProjectTree.tsx:113-126`）。

## 方案

### 1. tab 与面包屑用任务原名

- tui 类 tab 的标题改为任务原名；命名口径与左栏任务行同源同值：
  `name`，空则 `plan_summary`，再空则「（无名称）」（现状读数
  `web/src/app/tree/ProjectTree.tsx:332`）。解析不到任务（已删除等）时回退现状
  `TUI · 前 8 位`。
- 标题生成仍收口在现有纯标题函数（`tabs.ts#tabTitle`），任务名由持有任务流的
  层注入解析（调用链 WorkbenchPage → TabBar），纯函数不做数据获取。
- 顶部面包屑第三段跟**焦点窗格**的内容名：tui = 任务原名，file = 文件名，
  terminal = 终端标题，无焦点内容时回落目录名。整行保持**零交互**（现状约束，
  现状读数 `web/src/app/shell/Breadcrumb.tsx:6-14`，桌面薄壳拖动区依赖它）。
- 左栏「已打开行」用同一套命名（见 5）。

### 2. 拖放落点高对比（形态真源 b288-workbench-ux）

- 三区语义不变（left / right / center，`paneDrop.ts#dropZoneAt`）；**上/下落区
  不做**——那要求列内上下叠放的中央模型，属 B264（见 Out of Scope）。
- 落点视觉 1:1 原型：半区蓝遮罩 + 4px 内边条；中央内缩描边 + 淡蓝底
  （具体数值读原型 `.pane.drop-*::after` 规则）。
- 拖动进行期间窗格内容层 pointer-events 关闭（原型 `body.dragging .pane-body`
  规则），从根上排除 canvas 截事件；拖动结束恢复。

### 3. 列宽不横滑（形态真源 b288-workbench-ux `.cols`）

- 中央区容器裁掉横向溢出：不允许出现横向滚动条，三列均分压进窗口。
- 列 flex 均分、`min-width: 0`；拖拽分隔的最小栏宽下限保留，但「容器横向滚动」
  不再是兜底出口（现状读数 `web/src/app/workbench/tabs.ts:348-349` 注释里
  「交给容器横向滚动」的路径改为继续夹紧）。
- 验收场景：窄窗口开满三列，无横滑、三列全部可见可交互。

### 4. 终态一律进「已结束」

- 口径改为：项目内**全部** completed/failed 任务进「已结束」，不再要求目录已
  回收；「任务组只留未终态 + 已打开项」。
- 「已结束」行挂在该项目的任务分组尾部（原型 `aKey = "a:" + proj` 形态），
  默认收起、搜索时旁路展开（沿用现行为）；子行右侧显示机器名。
- 打开已结束任务的基准回退语义保留（主目录优先，找不到回落当前选中目录，
  现状读数 `web/src/app/tree/ProjectTree.tsx:340-346`）。
- 数据归集仍收口在现有纯函数（`archived.ts#archivedTasks`），改口径不改调用边界。

### 5. 左栏层级重绘（形态真源 option-1 + b288-workbench-ux 任务组）

层级与样式 1:1 原型，功能全量保留：

- **项目行**：文件夹图标 + 加粗项目名 + 右侧进行中计数 + 折叠箭头在**右侧**。
- **「任务」小标题分组**：项目直属的任务列表。
  - 行构成：类型图标（派发任务用 dispatch-task 资产图标）+ 状态点 + 任务名 +
    右侧机器绿点与机器名；行可拖拽（现状能力）。
  - 组成 = 未终态任务 + **已打开项**：工作台当前打开的全部内容也列在这里——
    tui 显示任务原名，终端显示终端标题，文件显示文件名；每行带机器归属；
    点击聚焦对应 tab（由 Shell 提供聚焦回调）；既是未终态又已打开的任务只出现
    一行，用打开态样式区分。
  - 双态：已打开（浅）与当前焦点任务（深一档），1:1 option-1 的
    `is-open` / `is-selected`。
- **「已结束」行**在任务分组尾部（见 4）。
- **「目录」小标题分组**：机器行（绿点 + 机器名 + 折叠箭头在右）+ 悬停动作
  （打开主目录终端 / 新建工作树——后者是现状 hover + 的重绘，前者走 Shell
  既有开终端能力接线）；展开后是工作树子行（缩进、紧凑）。断连机器保留
  「已断开」徽标与原因透出（现状诚实展示约束，spec §8 W3a）。
- **功能保留清单**（原型没画但现状必须活着）：搜索与 ⌘K、树偏好菜单、机器行
  右键菜单、未归属分组、底部 dock 入口、任务拖拽、行计数对排序的内部使用
  （行上不再显示被原型省去的计数控件）。

### 6. 顶部 chrome（形态真源 option-1）

- 面包屑行：28px 高度、灰字、单行省略，样式 1:1 `workspace-context`；零交互
  约束不变。桌面薄壳的窗口顶条（DesktopTitleBar）**不动**。
- 标签栏：44px、底色、激活 tab 药丸面、tab 间短节奏分隔线（不是整格边框）、
  关闭钮、右端 + 钮，样式 1:1 `workspace-tabbar` / `workspace-tab`。
  **（修订 2026-08-29）这个标签栏是基线的「组标签条」**：tab = 组（group），
  激活/关闭/拖动/新建组的基线语义全部保留，只换皮；图标按该组焦点内容的种类
  映射（tui → dispatch-task 资产图标，terminal → 终端图标，file → 文件图标，
  空组 → 加号），组名沿用基线命名（自动命名的组显示焦点任务原名，修复问题 1）。

## 测试决定（接缝清单）

前端缝全部是「已导出符号 + 生产调用方」，无假缝：

1. `tabs.ts#tabTitle`（调用方 TabBar）——tui 任务原名、回退链、file/terminal 不回归。
2. `archived.ts#archivedTasks`（调用方 ProjectTree）——新口径：终态全收、任务组
   组成（未终态 + 已打开）、已结束按项目归集。
3. `paneDrop.ts#dropZoneAt`（调用方 WorkbenchPage onDragOver/onDrop）——三区语义
   回归；落点指示元素与拖动期 pointer-events 状态在 WorkbenchPage 测试断言。
4. `TabBar.tsx`（调用方 WorkbenchPage）——类型图标映射、标题来源、激活态标记。
5. `ProjectTree.tsx`（调用方 Shell）——分组结构（任务/目录/已结束/未归属）、
   机器行悬停动作、已打开行与双态、断连徽标保留。
6. `Breadcrumb.tsx#breadcrumbSegments`（调用方 Shell、DesktopTitleBar）——第三段
   跟焦点内容名与回落。

jsdom 只能钉结构/行为；**样式一比一由验收节真机对照原型执法**（截图比对），
单测不假装能断言像素。

## Out of Scope

- **中央区「总页」重构**（彻底去目录分组、单一中央区所有 tab 混开）→ **B264**。
  **修订（2026-08-29，执行轮发现）**：初版误判基线中央模型为「目录为组」——那是
  main 上的旧形态；卡基线（B281/B285 之后）的中央**已经是组/列/格模型**（组标签
  条、列内上下两格、五区落点、组拖动/关闭/新建组，见基线 tabs.ts 文件头不变式），
  本卡五条与 chrome 样式全部落在这个既有模型**之上**，不改布局语义、不删组能力。
- **薄壳 DesktopTitleBar 重绘**：桌面窗口顶条维持现状，本卡只管浏览器模式 chrome。
- **项目行悬停「工作项 / 代码图」链接**（原型有）：与 W4 §3.1 冻结决策「树不再是
  筛选的编辑入口」冲突，弃选新增；基线已有的同类悬停入口保留。
- **监控类 tab 类型**（原型 mock 的「审阅」monitor 图标）：无真实 tab 种类对应。
- **终端重命名等 tab 管理增强**：不在五条内。
