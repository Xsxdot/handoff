# 分域开发协议：契约先行的拆解流程与工作台落地

> 2026-08-21 brainstorm 定稿。适用范围：所有按「子系统=大领域、接口协作、App 层调配」组织的项目
> （tk 形态为标准形态），以及 handoff 自身的开发；工作台（B156）承载其自动化形态。
> 本 spec 只定协议与规格，不含具体实现 plan。

---

## 1. 背景与动机

两个痛，根因不同，处方不同，本协议同时治理：

**痛一：写错（「一天写代码，六天改 bug」）。**
handoff backlog 182 条实测约 70% 是缺陷修复，按根因聚成五族：
生命周期/状态机（~25 条）、静默失败/误导报错（~20 条）、跨平台假设（~15 条）、
假红测试（~10 条）、权限门禁绕过（~6 条）。五族几乎全部长在**接缝**上，
根因不是执行者理解不足或实现错误，而是**接缝行为在 plan 阶段根本没被指定**
（重启窗口谁收尾、进程换组后谁数得到、错误如何传播、平台差异下该发生什么）。
代码质量独立评估（8/10，修复全是带回归测试的根因式修复）证伪了「屎山」假设：
问题不在修法，在 bug 本可以少产生一半——欠掉的规格在真机验收时一条条变成 backlog 还回来。

**痛二：写慢（项目变大后 plan 与执行速度崩、上下文消耗巨大）。**
精确说不是「理解不足」，是「理解不可复用」：每个任务从零重建对全系统的理解，
重建成本随代码量线性上涨，且每次都付。tk 实测给出量化依据：
`system/` 总量 21.5 万行，而全部 `api/` 契约层仅 10,681 行（+README 约 1.2 万行）——
若 plan 写作者只需读契约层，上下文压缩 18 倍。

**关键前提（tk 实测成立）**：9 个子系统跨域 import 他人 `internal/` 的违规数为 **0**。
大领域边界由编译器与目录约定真实锁死，这是分域派发的地基。
**关键反例（同样来自 tk）**：nova 一个域 141,597 行，占 66%，内部按层横切
（service/ 47k、app/ 22k、processor/ 21k），小领域只存在于文件名前缀——
域内失去局部性，域 ticket 上下文下限数万行。协议必须含域内递归规则（§8），否则外层白守。

## 2. 核心判断（决策依据，验收时可回溯）

1. **上下文局部性是代码局部性的下游。** 「agent 只看域内上下文」的前提是存在编译器
   强制的边界，边界内不看外面也能被正确理解。边界没立起来之前谈分域派发是空话。
2. **补偿机制不如恢复局部性。** 扫描代码生成的知识库是无主派生物，静默漂移、
   需专人维护，且它补偿的是「代码失去局部性」——直接恢复局部性（拆包、锁边界）更便宜。
3. **mock 的可信度取决于接缝对面是谁。** 对面是自有代码：契约即全部真相，mock 便宜
   且有意义；对面是外部现实（子进程、OS、git、网络、平台）：mock 编码的是假设，
   而五族证明假设恰恰是出错的地方（例证 B49：opencode 的 question 工具一调用即死锁，
   任何手写 mock 都不会包含它）。
4. **域的尺寸本身是架构约束。** agent 开发流让巨型包的成本当场可计量
   （ticket 圈不出文件集、token 消耗上涨），拆分理由从「人的认知负担」升级为硬性红线。

## 3. 明确不做什么

- **不建常驻领域 agent。** 域 ticket 就是普通 dispatch 任务，任何 executor 领到即天然
  只需加载该域。没有 agent 编排、画像、生命周期要维护。
- **不建扫描式代码知识库。** 沉淀只允许进 §4 的三层（编译器/测试/Review 强制），
  无主派生物一律不建。
- **不做大爆炸重构。** 存量巨型域走绞杀式迁移（§8）。

## 4. 沉淀的三层栈

| 层 | 载体 | 漂移风险 | 表达什么 |
|---|---|---|---|
| 编译器强制 | `api/` 的类型、接口、嵌套 `internal/` | 零，违反即报错 | 形状：签名、数据结构、可见性 |
| 测试强制 | 契约夹具（如 Go/TS 共享 fixture）、录制回放、架构测试 | 漂移即红 | 行为样本、import 规则 |
| Review 强制 | 每域一页的领域文档（§5） | 靠 DoD 纪律 | 类型说不出的一切：为什么、不变量、时序、故障语义 |

禁止第四层（扫描产物）。三层各司其职，不互相替代。

## 5. 领域文档规格（Review 强制层）

每个大领域一份，放在该域根目录（如 `system/<域>/README.md` 或 `DOMAIN.md`）。
**目标体量一到两页**，只收稳定知识。

**必含六节：**
1. **职责与边界**——做什么、明确不做什么。
2. **契约语义补充**——`api/` 类型表达不了的：幂等性、错误语义、阻塞行为、排序约束。
3. **不变量**——必须恒真的陈述（如「事件与状态不得失配」「单写入者」）。
4. **时序与故障语义**——重启/崩溃窗口内的行为、谁负责清扫、补偿路径。五族审查（§6.1）
   直接对着本节核对。
5. **外部现实假设清单**（边界域必填，逻辑域可写「无」）——哪些假设 mock 验不了、
   必须真机；对应真机清单模板。
6. **领域词汇表**——统一语言，术语与代码标识符对照。

**禁入清单（与必含同等重要）**：实现细节、文件清单、流程步骤复述、任何随代码周更的内容。
一旦开始收易变物，本文档即滑向无主快照，宁缺毋滥。

**更新纪律**：任何改变域行为的变更，域文档更新属于同一变更的 DoD；review 时文档与代码
一起审。工作台落地后由域卡 Gate 硬化（§7）。

## 6. 分域拆解协议（流程主干）

```
拆解（五族审查）→ Ticket 0（契约落地为骨架 commit）
→ 扇出域子卡（各自出 plan、执行、域内审阅验收、更新域文档）
→ 集成卡（跨域接线 + e2e + 整体验收）→ 终审
```

### 6.0 拆解（协调者，上下文 = 契约层）

输入：需求 + 模块地图 + 各域领域文档 + 各域 `api/`。产出三样：
1. 触及域清单，每个域标**类型**（逻辑域 / 边界域，判别式见 §2.3）；
2. 各域**契约增量**——`api/` 下 dto/接口的精确 diff，精确到可编译；
3. 子卡清单 + 依赖 DAG。

拆解时执行**上下文预算检查**：若某张域卡圈不出有界文件集，即为该域需要竖切的信号——
plan 里先插竖切还债卡，再派功能卡（§8.5）。

### 6.1 五族对抗审查（拆解的一部分，不可省）

对每个触及域，对照其领域文档「时序与故障语义」节逐条设问：

- **生命周期族**：本操作中途进程/守护重启会怎样？谁负责收尾？兜底在哪？孤儿资源
  （进程/工单/worktree/临时文件）由谁、何时回收？
- **静默失败族**：每条错误路径的传播契约是什么？失败时用户看到的信息可行动吗？
  存在「报成功但没做」的窗口吗？事件会不会被吞？
- **平台族**：本改动哪些假设在 Windows / macOS 上不成立（路径、进程组、权限模型、webview）？
- **假红族**：验收判据是不是中途副产物？有没有反面断言？在负载/并发下会不会翻红？
- **门禁族**：新增的写路径/执行路径过没过权限门？门覆盖的是全部表面还是一部分？

审查结论写进契约增量与各子卡验收栏。此步是「六天」被砍掉的位置，plan failure 级强制。

### 6.2 Ticket 0：契约冻结

只做一件事：把审查过的契约增量落地为**可编译的骨架 commit**——`api/` diff + 空实现
stub，合入基线分支。域文档相关条目更新随行。此后所有域子卡基于该 commit 开分支，
契约错配在编译期爆炸而非集成时。契约是代码，文档是随行产物，顺序不可颠倒。

### 6.3 域子卡（意图层，可并行扇出）

每张 = 一个独立 dispatch 任务（独立分支/worktree）。**四段式**正文：

1. **契约**：引用 Ticket 0 的 commit + 本域相关 diff + 领域文档相关条目；
2. **意图与为什么**：要达成的行为与动机，不写实现步骤；
3. **验收**：按域类型二分——
   - 逻辑域：域内测试闭环，邻域一律 mock 其 `api/` 接口，机内可跑；
   - 边界域：机内只验契约形状（含录制回放，见下）；行为验收写成显式
     **「真机清单，归协调者执行」**（与既有纪律一致：派发的 plan 不能自己驱动 handoff）；
4. **入口指针**：相关文件入口，省探索时间。

「怎么实现」留白：域执行者在自己域内自行出 plan——这是域内上下文有界的兑现方式。
域文档更新属于子卡 DoD。

**mock 红线**：只在 `api/` 接缝 mock 一层，禁止深 mock 内部；mock 中任何关于外部现实的
假设必须对应一条真机清单项，否则等于用测试给假设盖章。边界域优先用**录制回放**
（真实报文录成 fixture 回放）替代手写 mock——现实的快照优于假设的编码，且可进 CI。

### 6.4 集成卡（收口）

跨域协作逻辑**只允许**出现在这里：顶层 App 层调配 + 路由接线 + e2e。整体验收含
边界域真机清单的执行。子卡全绿不等于完成，集成卡是必经节点。

### 6.5 终审

整分支终审 + 人工 Gate。合并进主线的决策留协调者/用户，不自动。

## 7. 工作台落地（B156 承载）

映射到现有 `WorkflowDef`/`NodeDef` 模型（Dispatch/Template/Verdict/MaxRounds/OnFail/Gate）：

**「分域开发」工作流模板**节点序列：

| 节点 | 能力配置 | 说明 |
|---|---|---|
| 拆解/契约冻结 | Dispatch=on（模板=拆解协议 prompt）、Verdict=on（判据=stub 编译绿+五族审查过）、Gate=人工确认契约 | **Decision 闭环挂此节点**：契约变更是最该留裁决记录的事 |
| 域实现 | 扇出（见缺口）；每子卡 Dispatch=on（模板=四段式域卡） | 逻辑域卡可全并行；边界域卡验收含真机清单归协调者 |
| 集成 | Dispatch=on（模板=集成协议） | App 层接线 + e2e |
| 终审 | Verdict=on + 人工 Gate | 合并决策留人 |

**已知引擎缺口：扇出。** 现模型单卡走列，无「一卡生 N 子卡、聚合后过闸」。分两步走：
- **先用 b 方案验证协议**：拆解节点直接产 N 张独立卡各走「单域实现」流，集成卡用人工
  Gate 等全齐——不改引擎；
- **子卡机制（parent id + 聚合闸）记 backlog idea**，b 方案跑通、确认协议有价值后再立项。

**域卡 Gate 增补**：「本域领域文档是否需要更新、已更新」作为过闸检查项，把 §5 的更新
纪律从自觉变成硬门。

**域健康度指标（backlog idea）**：账本记录每域 ticket 的上下文/token 消耗，趋势上涨 =
域在腐烂的早期信号，早于任何 code review。

## 8. 域内递归规则（防 nova 化）

架构自相似：**小领域之于大领域 = 大领域之于系统**。外层三件套原样下沉一层：

1. **小领域升格为真实的包 + 嵌套 `internal/`**。Go 的 internal 规则按相对路径生效：
   `<域>/internal/<小领域>/internal/...` 仅小领域子树可见——与外层同一个编译器机制，
   零新发明。每个小领域是竖片（自带 service/dao/model），对外只露薄 `api` 或 `contract.go`。
2. **跨小领域调配只许在域的 App 层**——镜像外层「跨大领域只许在顶层 App + 集成卡」。
3. **架构测试钉住 import 规则**（先例：handoff 根目录 `moduleisolation_test.go`），违规即红。

**两条过程绊线**（防「以后再说」）：

4. **升格判据**：一个文件前缀家族 ≥5 个文件、或需要自己的 dao+service 对，必须升格为包。
   写进 backend-go 模块模板，使「新小领域 = 新子树」成为缺省形态。
5. **域尺寸红线**：单个可派发上下文单元（大领域，或未竖切时的整域）超过约 2~3 万行，
   拆解节点必须拒绝直接派功能卡，先插竖切还债卡。红线动机是上下文预算，
   不是审美——它决定 agent 流的快慢与成本。

**存量迁移**：绞杀式。每张碰到某前缀家族的 ticket 附带「本家族升格为包」一步
（童子军军规），或按小领域立专门还债卡。竖切一个家族是小时级，缠死后是周级。

## 9. 落地物清单（本 spec 的后续，各自独立立项）

1. **工作流模板**：工作台内建「分域开发」模板（§7 表），b 方案扇出。
2. **skill 修订**：
   - writing-plans 伴随规则：拆解阶段强制五族审查 + 上下文预算检查 + 域类型标注
     （缺失即 plan failure，与 instrumenting-code 同级）；
   - backend-go 增补：§8 域内递归规则、升格判据、域尺寸红线、领域文档规格（§5）。
3. **backlog 新条目**（取号按 web-console 汇流点纪律）：
   - 工作流引擎子卡/聚合闸机制（idea，b 方案验证后再评估）；
   - 域健康度指标：按域记录 ticket 上下文/token 消耗趋势（idea）。
4. **试点**：下一个横跨多域的真实需求走一遍全协议（含一个边界域），以「域卡平均上下文
   消耗」「集成卡阶段新发现缺陷数」两个数验证收益。

## 10. 验收判据（协议本身的）

- 试点需求的 plan 阶段上下文 ≈ 契约层 + 域文档量级（对照：全量代码）；
- 域子卡执行期间零次跨域 `internal/` 触碰（架构测试背书）;
- 集成阶段暴露的契约错配为 0（应全部在 Ticket 0 编译期暴露）；
- 边界域子卡的真机清单在集成卡完成前全部执行完毕，无「事后补验」。
