## 1. 问题陈述

「协调者」这一个概念在现状代码里被解了四五次，每次加一层，没有一层被收回：

- **席位来源三种**：`bind`（CLI 自己坐）、`coordinate`（agentd 拉起 print 回合）、桌面端记录（B434，挂在 bind 席位上）。
- **唤醒路径五条**：账本自动化事件、房间人类消息、HTTP 手动 launch / launch_queue、跨机转交、桌面端信箱 + mod 轮询。
- **收信方四个**：agentd 唤醒消费循环、`handoff card wait`、`handoff session wait`、桌面端 mod。

每一对组合各有一套判定（现状读数全部在台账 §二、§三.1，摘要）：

| 症状 | 现状读数 |
|---|---|
| bind 席位「跳过」写了四遍，措辞与行为各异 | `keystone.go:123-126`（静默）、`wakeconsumer.go:521-539`（起始卡 bind 返回空、祖先 bind 继续上走）、`scheddrain.go:463-490`、`desktopwake.go:1053` |
| `needs_human` 三个口径 | `card wait` 可动作（`card_wait.go:235`）；`automationWakeEvent` 排除（`wakeconsumer.go:261-264`）；桌面端 bind 又开例外（`wakeconsumer.go:309` → `desktopwake.go:1043`） |
| 三份「谁被唤醒」匹配 | agentd `bySeat[DriverSession]` map（`wakeconsumer.go:366-386`）；`session wait` `target == member`（`cmd/session.go:516`）；`AddressesCard`（`collab/sessions.go:258-275`）；`card wait` 另有 `kind==user && !by_system` + 卡号过滤（`card_wait.go:249-253`） |
| **`card wait` 永远收不到会话房间消息** | 会话消息 card_id 恒为空（`collab/service.go:271`），`card wait` 按 card_id 成员集过滤（`follow.go:13-14`）→ 其 room_message 分支只对旧卡房间有效 |
| 身份记法混杂 | `session wait <member>` 设计上是 `user:/agent:`（`session.go:3,562`），寻址解析出的 target 却是 `cli:<cli>#<sid>`（`room/delivery.go:52`）；`session list` WARN「会话成员身份非统一记法」（`collab/sessions.go:393`） |
| 「coordinate」一词两义 | `card coordinate` 产生 coordinate 席位；`card coordinate --desktop` 产生的是 bind 席位（`desktopwake.go:172` 简报要求 `card bind --via launcher`） |
| **print 载体只有 opencode** | hostapi 驱动 CLI 白名单只有 opencode（`hostapi/driver.go:52`）；桌面端席位只接受 claude（`card_seat_desktop.go:32`）——两者在结构上组合不出来 |
| queue_release 两分支方向相反 | 桌面端 bind 直接放行（`scheddrain.go:479-484`）；远端 coordinate 显式失败回填（`:511-520`） |
| 「一次性回合」被误读为无状态 | `driver.go:240-249` 实为 `-s <session>` 续跑；B399 已把 resume 做成常规路径 |

后果：每多一种拉起方式就多一条唤醒路、多一组跳过规则；用户不敢在群里说话（怕 @ 错、怕扇出），协调者提问后没人叫醒它。

**根因**：「协调者」到底是账本里的一个**身份**，还是一个正在跑的**进程**，现状两者混用。席位记的是身份，唤醒逻辑却按「进程怎么拉起」分叉。

## 2. 级别与档位

**定级两问**：
1. 跨几个子系统的契约面？——寻址判定（d_collab）、席位记录与会话模型（d_ledger）、推式回合（d_keystone）、唤醒消费（d_scheduling/agentd）、桌面端桥（d_gateway）、wait 命令族（d_cli）、wire DTO（d_protocol）、控制台（d_web）。≥ 7 个。
2. 动契约层？——动：B358 冻结条目多条（§9.1）、`card wait` / `session wait` 的输出与游标（其他 agent 依赖的对外承诺）、席位模式字段（wire）、信箱来信格式（跨进程 wire，mod 是零 import 独立交付物且已装在用户机）。

→ **L3**。单子系统工作量（仅 d_collab 的匹配函数 + 默认收件人 + 守卫改写）已超 70 分钟 → **重档**：先 Wave 0，再按故事分批扇出。

**contract 需要，冻结四条缝**（都是独立工作单元共同依赖或对外承诺）：① `card wait` / `session wait` 的 stdout 形状、退出码、游标语义；② 匹配函数的判定表（含默认收件人，即 B358 条 29/30 的修订文本）；③ 席位模式字段的 wire 取值；④ 信箱来信格式（项目房间通知形态）。

## 3. 目标形态（概念表）

最终只剩这些概念：

| 概念 | 定义 | 权威位置 |
|---|---|---|
| **房间** | 传输。每张目标卡住在一场会话（既有会话模型）；每个项目一个**项目房间**（一场标了项目的会话） | d_ledger（会话本体）/ d_collab（寻址） |
| **卡** | 地址。协调者坐在卡上（既有 `driver_session`） | d_ledger |
| **席位** | 卡的协调者身份 + **驱动模式** `push` / `pull`。来源词（bind/coordinate）只作记录，不参与判定 | d_ledger |
| **驻场者** | 房间级、无席位的默认收件人。不起回合、不认领、不续租。可 `card bind` 升格为协调者，身份不变。一房间至多一名 | d_ledger（会话） |
| **组织者** | = 项目房间的驻场者 + 角色简报。项目级、无目标、自己不工作 | 不新增概念 |
| **两种驱动模式** | push：agentd 看到命中消息起一轮 print 回合（续跑同一 session，受 B399 上界与续租约束）。pull：席位持有者自己跑 wait。桌面端用信箱 + mod 实现 pull | d_scheduling / d_cli / d_gateway |
| **一套 wait** | 两个既有命令名、一套实现：`card wait <id>`（席位地址）、`session wait <session>`（房间地址，驻场者）。顶层 `handoff wait <task>` 是执行者任务 wait，不动 | d_cli |
| **一个匹配函数** | 「这条房间消息该不该送到地址 A」。push 消费循环、两个 wait、桌面端桥都调它 | d_collab |
| **默认收件人** | 人类作者的无寻址消息只送一个人：房间有驻场者送驻场者，否则送会话根卡的协调者；找别人显式 @。非人类作者无寻址不唤醒；结构行恒不唤醒 | d_collab |

三个角色：

| 角色 | 粒度 | 目标 | 住在哪 | 怎么被叫醒 | 干不干活 |
|---|---|---|---|---|---|
| 组织者 | 项目 | 无 | 项目房间（桌面端会话为驻场者） | 项目房间里寻址到它的消息（经信箱桥） | 不干：排期、建卡、开协调者、答组织类问题 |
| 协调者 | 一张目标卡（可含子卡） | 有 | 卡所在会话，print 载体或小队 | 寻址命中其席位的消息；卡自动化事件 | 点火、派发、建子卡配协调者、与子卡协调者沟通 |
| 执行者 | 一个 task | 有 | 执行机 | 派发 | 干活 |

## 4. 方案（含弃选与理由）

**采用**：上表。以下为被否的方案：

| 弃选 | 理由 |
|---|---|
| A. 协调者改 ACP / 常驻对话进程 | 卡活数周、进程活不了，终归要 resume，print 已把 resume 做成常规路径；grok ACP 实测未决请求随连接消亡、重连不重发、回合永久挂死（`manager.go:3685` `volatilePermitter` 为此而生）。ACP 只在「对面是同步在线的另一个 agent 且往返不该落账」时才值，仓库无此场景 |
| B. 只留 push，删 pull | 其他 agent（codex/opencode/任意 CLI）只能靠 `card wait` 与 handoff 交互；pull 是它们唯一入口 |
| C. 组织者开桌面端子会话当协调者 | 两套协调者传输层并存，正是现状乱源。协调者永远只有「卡 + 席位」一种形态；组织者排完期用 handoff 命令开会话选协调者 |
| D. 删 `session wait` 能力 | 驻场场景（在 handoff 不认识的 agent 里开会话、手机上经房间说话）真实。r1 曾裁「一个 `wait` 动词」，审计指出顶层 `handoff wait <task>` 已被任务 wait 占用（`cmd/wait.go:91`），改为沿用两个命令名、一套实现；删的是第二套判定与「按成员订阅」的旧形态 |
| E. 保留 B358 规则 2「无寻址不唤醒任何人」原样 | 用户裁决：每次 @ 很麻烦；但反扇出不变式必须保留。改法：寻址解析结果**恒 ≤ 1 人**。B358 受影响条目逐条处置见 §9.1 |
| F. 复活 `project:<name>` 旧房间作项目房间 | 旧房间 B358 已裁只读归档（`service.go:189`）；会话模型是现役。项目房间 = 一场标了项目的会话，旧 id 继续只读 |
| G. 桌面端保留卡级席位（B434 现状） | 组织者是项目级；桌面端拒绝无人值守建会话的限制对卡协调者是障碍、对组织者是契合。B434 的投递机制复用，角色绑定退役（D10） |
| H. wait 改走 agentd HTTP | 现状 `session wait` 由 CLI 直读账本并持有 `collab.Service`（`cmd/session.go:300`），匹配函数可进程内调用，不必改 B358 条 45/49；r1 的 HTTP 路径撤回 |

## 5. 承重决策清单

D1 **席位模式字段**：卡席位增 `mode ∈ {push, pull}`（wire 字面量英文；CLI `card bind --mode push|pull`，缺省：`card bind` = pull、`card coordinate` = push）。push = agentd 起回合；pull = 持有者自己 wait。四处 bind 跳过收成一处「pull 席位不起回合」；来源词保留为记录，任何判定不得读它。「空座沿 parent 上走」（`wakeconsumer.go:521-539`）**保留且只对卡自动化事件**（子卡无席位时其执行者事件由父卡协调者接）；房间消息不上走（寻址到无席位卡 → 不唤醒、详情页标「无收件人」）。

D2 **一套 wait**：
- `handoff card wait <id>`：命令名与既有 stdout 行格式、退出码（命中 0 / 超时 124）不变；实现改为 **卡事件流（needs_human / decision_* / task_mirrored 照旧）∪ 寻址命中本卡席位的会话房间消息（经匹配函数）**。废止其自带的 `kind==user && !by_system` 判定；修订 B358 条 49（无卡的房间消息可经寻址进入 card wait）。
- `handoff session wait <session>`：参数从成员身份改为**会话号**，含义「作为该会话的驻场者收件」：命中 = 寻址到驻场者身份 ∪ 默认收件人落到驻场者。输出沿用 `SessionWake` 键集（条 43）。旧 `session wait <member>` 形态删除。
- 两命令共用一套实现与同一匹配函数；均有界返回、`--since` 回放、`--follow` 常驻。
- 顶层 `handoff wait <task>`（执行者任务）不动。

D3 **一个匹配函数**：d_collab 唯一导出「消息 × 地址 → 命中否」，地址 ∈ {卡席位身份, 房间驻场者}。push 消费循环、两个 wait、桌面端桥四方都调它；`AddressesCard` 并入。

D4 **默认收件人**：仅对**人类作者**（`user:` 记法）且无显式 @ / reply_to 的消息：房间有驻场者 → 驻场者；否则**会话根卡**（parent 为空或 parent 不在本会话的卡）恰一张 → 该卡席位；根卡零张或多张 → 不唤醒任何人，详情页标「需 @」。显式 @ / reply_to 优先且不变。非人类作者（`agent:*`，含系统发信身份）无寻址不唤醒；`by_system` / pointer 结构行恒不唤醒（条 26 不变）。解析结果永远 ≤ 1 人。

D5 **驻场者**：新增房间级登记（身份 + 可选桌面端地址 + 可选机器）；修订 B358 条 14（驻场者是第三种成员来源，一房间至多一名）。`handoff session sit <session> [--desktop-session <id>]` / `session stand <session>`。`card bind` 升格后身份不变、驻场登记保留。

D6 **项目房间**：每项目恰一场会话被标为项目房间（账本记 project ↔ session），不挂目标卡。**按需创建归账本**：首个写入方（系统通知或 `session sit --project`）到来时惰性创建；`handoff project room <project>` 显示（不存在则创建并显示）。旧 `project:<name>` 房间不复活。

D7 **组织者** = 项目房间驻场者 + 角色简报。持久态三样：规则文件（仓内，人写，git 版本化）、记忆目录（组织者写、人可改）、项目房间游标。会话上下文允许丢，三样不许丢；恢复 = 归档旧会话、新会话 `session sit`、从游标续读。

D8 **系统通知通路**：agentd 以成员身份 `agent:handoff` 向项目房间 **Send 普通寻址消息**（`by_system=false`，`Mentions=[驻场者身份]`，无驻场者则不发、只落卡事件）。通知事件表：卡新建、卡换列、卡 `needs_human`、协调者提问（协调者自己 `session send` 项目房间，无 @ 时按 D4 落驻场者）。B358 条 31 修订：结构事件本身仍不唤醒任何人；其中 `needs_human` 额外触发一条项目房间通知。`needs_human` 不再是独立唤醒类。

D9 **组织者的回答权限**：组织类（先后、等待、基线、机器、卡间冲突）直接答回卡所在会话，署名组织者；内容类（设计、验收、范围）转问人（桌面端会话内），人答后转发。答前先查该问题有无人类回复，有则不答。

D10 **B434 处置清单**：
- **退役**：`seat_desktops` 表及其两步写入/三删除点（矛盾 10 随之消失）；`card bind --desktop-session/--machine/--via`；`card seat desktop set`；`card coordinate --desktop`；`GET/POST /api/cards/{id}/coordinator/desktop-launch` 路由与 client `DesktopLauncherOpen`；拉起器代开路径（`openViaDesktopLauncher`，`desktopwake.go:1224`）；卡级信件（「卡 X 有 N 件新事」）；控制台「用 Claude Code 坐下」「复制简报」「让拉起器代开」按钮与 `claude://code/new` composer 深链；薄壳深链通道中的 new-session 形态；skill 文本「占座」节与 CLAUDE.md 常设授权片段（改写为组织者授权）；`desktopNeedsHumanWakes` 例外分支。
- **语义替换**：`desktop_launchers` 不是改名——其「替别人开会话的 cli_session」语义退役，表改为**驻场者桌面端地址**（身份、桌面端会话 id、机器）。
- **保留**：信箱目录与原子写入；mod 与 `skill install`；`claude://code/continue?session=` 深链（组织者会话 900s 回收后仍靠它拉起）；异机投递沿既有 `transferCoordinatorWake` + `LetterUnopened` 回包（`b434-contract.md:361-373`）。信件内容改为项目房间通知形态（进 contract ④）。

D11 **房间口吻**：push 简报与驻场者角色简报都写「房间里只说重点与结果，同事口吻；思考与工具调用留在自己会话」。简报文本，不是机制。

D12 **认领、游标与跨机**：
- push 席位：沿用 `wake_claims` 认领 + B399「30 分钟上界、回合内续租」；回合在席位所在机器起（远端走既有转交）。
- pull 席位：不认领；游标键 = 地址（卡席位身份 / 房间+驻场者身份），**输出即推进**（沿用条 44 语义：交付以打印成功为准，失败不推进、下次续收）。
- 一个席位恰一种模式，同一消息不会被 push 与 pull 同时处理。
- queue_release 合成唤醒（矛盾 9）：pull 席位 → 直接放行进节点再入口（与现状桌面端 bind 同）；push 本机 → 起回合；push 远端 → 既有失败回填不变。

D13 **不处置项**：launch_queue 无首次生产者（矛盾 7）本卡不动，落 roadmap。

## 7. Wave 0 选择

**Wave 0 = S2 + S4a + 席位模式字段**：一个匹配函数（含默认收件人的无驻场者分支）、`mode` 字段、`card wait` 改按席位寻址命中、agentd push 消费循环改调同一函数（S1 复用既有 print 回合，不新写）。驻场者（S3/S4b）不在 Wave 0——r1 的 S4 隐含依赖驻场者，审计指出循环依赖，已拆。

验证的承重未知：
1. push 与 pull 能否共用一个判定而不破坏 B358 反扇出守卫（守卫改写后仍能把「>1 人」写不出来）。
2. 「pull 席位不起回合」一处判定能否覆盖四处旧跳过；「空座沿 parent 上走」按 D1 限定为卡自动化事件后，子卡无席位场景不回归。
3. 「会话根卡恰一张」在多卡会话里可判且与 `session detail` 投影一致。
4. `card wait` 从 Follow 单流改为「卡事件流 ∪ 寻址命中」后，stdout 行格式与既有 skill 文本逐字兼容。
5. 身份记法：pull 调用者出示的席位身份与寻址解析出的 target 同一记法（`cli:<cli>#<sid>`）；`user:/agent:` 只用于驻场者与作者。

依赖此结论的工作：S3/S4b/S9 驻场者（地址类型扩展）、S5–S8 组织者（建立在项目房间 + 驻场者 + 同一匹配函数上）。未覆盖的独立未知：信箱来信的项目房间通知格式（S5 前窄实验，随 contract ④ 冻结）。

**台账十条矛盾处置**：1 → D8；2 → D1；3 → D2；4 → D3；5 → 未知 5；6 → D10；7 → D13（不动）；8 → §11 后续（载体扩展）；9 → D12；10 → D10。

## 8. 目标架构与接缝语义（L3）

**子系统职责与权威状态**

| 子系统 | 职责 | 权威状态 |
|---|---|---|
| d_collab | 寻址判定唯一出口（匹配函数、默认收件人、驻场者解析） | 无持久态；读账本 |

**允许的依赖方向**：
- agentd 消费循环 → d_collab 匹配函数（既有 `roomMessageWakeEvents`（`wakeconsumer.go:337`）已依赖 `MessageWakeTargets`，扩成唯一路径）。

- 桌面端桥 → d_collab（取代 `desktopwake.go:1043` 自己的判定）。

**事件/数据流**：房间消息落账 → 消费循环与 wait 各自从游标读 → 同一匹配函数给出 ≤1 个收件地址 → push：认领、起回合 / pull：返回给调用者 / 桌面端：写信箱。卡结构事件（建卡、换列、needs_human）由 agentd 投影成一条 `agent:handoff` @驻场者的项目房间消息（D8），不再有独立唤醒类。

**内部新缝不在此抢签名**：匹配函数签名、驻场者表结构在 Wave 0 实现中成形；§2 的四条进 contract 冻结。
