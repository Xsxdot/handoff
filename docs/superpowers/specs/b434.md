## 问题陈述

用户期望的组织形态（B358 §1：董事长 → 主 agent → 协调者 → 执行者）里，协调者应当是**Claude 桌面端里的会话**——有内置浏览器、子代理、桌面端会话管理工具的完整能力，而不是被削过能力的无头回合。今天 handoff 离它差四件事，前两件是旧账，后两件是本轮真机取证新钉死的：

1. **协调者只能是 opencode 的一次性无头回合。** 能力矩阵把协调能力冻结为「仅 opencode 为真」（`internal/executor/capability.go#BaselineReport`，2026-10-16 读数 :190-213）；每次唤醒是一条 `opencode run -s <session>`（`internal/hostapi/driver.go#buildArgv` :241）带回合超时；简报原文「你是一次性回合：没有交互窗口」（`internal/keystone/keystone.go#Service.briefing` :335）。B393 / B399 / B411 整串故障长在这个形态上。
2. **人尺度席位有机制没入口。** `card bind` 能让一场 claude 对话坐下（`cmd/card_seat.go#currentSeatIdentity` 读 `CLAUDE_CODE_SESSION_ID`），keystone 与唤醒消费轮对 bind 席位不发起回合（`internal/keystone/keystone.go#Service.Wake` :123；`internal/agentd/wakeconsumer.go#resolveWakeCard` :511，注释原文「bind 靠 CLI wait」）。没有任何地方能从 handoff 把一场桌面端会话开到项目里：卡页空座只有「▶ 叫机器人」（`web/src/app/cards/CoordinatorPanel.tsx` :146）。
3. **桌面端会话闲置 15 分钟即被回收。** 桌面端日志每轮结束打 `WarmLifecycle:session … idle timeout 900s`，到点 `Idle timeout reached, disconnecting … Pausing session (idle_timeout)`（台账 16:43 读数）。进程一停，会话里挂的 Monitor 订阅、收件 socket、任何后台子进程一并消失。所以「让协调者会话自己挂 `session wait` 等 `@`」只在 15 分钟内成立；B407「主 agent 挂监听收不到 `@`」很可能就是它。常驻形态在桌面端根本不存在。
4. **桌面端没有外部建会话 API，深链也不替人按发送。** `claude://code/new?folder=&q=` 只在桌面端开一个**草稿**：q 预填进输入框，进程要到人按发送才起（台账 16:25 读数：日志只有 `setFocusedSession: sessionId=null`，无 `Starting local session`）。app 包里加载 q 后即清参数，无 autosend。云端 routines 到不了本机 agentd 与 Tailscale 内账本；桌面端本地定时任务只按时刻触发、外部写不进它的调度表（台账 16:08 读数）。

但本轮也钉死了两条**正面**事实，整个方案建在它们上面（台账 16:23、16:28、16:45 读数）：

- `claude://code/continue?session=<local id>` 深链能由外部进程把**被回收的**会话进程重新拉起（`warmed successfully in 45ms`），不弹框。
- 会话里装一个 mod（Claude Code 的 hooks 模块）后，handoff 往约定信箱写一封信，mod 在 `session.start` 后与每 5 秒的轮询里取信并 `$.prompt.submit` 提交为一轮；活着时 3 秒响应，被回收后「写信 + `continue` 深链」6 秒内回话。全程无人、无审批。

承重歧义一句话：**谁在什么条件下把一场 Claude 桌面端会话开到项目目录里并交给它开场材料，使它成为某张卡的协调者；它被回收后由谁、经哪条通道叫醒并交给它新的事；人不在电脑前时新协调者由谁开。**

## 方案

**形态只有一种：协调者是 Claude 桌面端会话。** 无头、后台（`claude --bg`）、`-p`、云端 routines 一律不作协调者载体。围绕它做四件事：

1. **人在场创建：卡页「用 Claude Code 坐下」。** 空座时与「叫机器人」并列。点击后控制面产出**拉起材料**（项目在本机的根目录 + 人尺度简报），前端编成 `claude://code/new?folder=…&q=…` 深链发出；桌面薄壳为 `claude` 这一个 scheme 开白名单通道。人点一次发送（文件夹信任每设备每文件夹只问一次，桌面端自己的对话框原文说信任后「所有未来会话，含从网页、手机发起的和定时任务，不再弹 Allow」）。新会话按简报读 skill、`card bind` 坐下并把自己的桌面端会话 id 一起记到卡上。深链发不出去时同一入口退化为「复制简报」。
2. **唤醒：写信箱 + `continue` 深链。** 卡上有事（`@卡号`、工单、`needs_human`、裁决）时，控制面把本来要经 `session wait` / `card wait` 交付的那份投影写成一封信，放进该席位的信箱；然后发 `claude://code/continue?session=<桌面端会话 id>`。会话活着则 mod 直接取信；被回收则深链先把进程拉起、mod 在 `session.start` 后取信。两种情形都由同一个 mod 用同一条逻辑处理，handoff 不需要知道它此刻活着没有。协调者会话不再需要自己挂任何订阅。
3. **无人值守创建：拉起器会话代开。** 项目里由人开过一次的一场普通桌面端会话（通常就是主 agent 会话）登记为该项目的**拉起器**；人不在时需要新协调者，控制面给拉起器写信（内容就是那份拉起材料）并 `continue` 唤醒它，它用桌面端会话管理工具开出协调者会话、把简报作为首条消息送入。拉起器本身被回收无所谓，它随时能被叫醒。没有登记拉起器 → 卡打 `needs_human(无拉起器，请在桌面端开一场并登记)`，不伪造。用户要在项目 CLAUDE.md 写一条常设授权（文本由 skill 给出），否则拉起器会把 handoff 的来信当观察数据而不执行。
4. **mod 成为 handoff 的正式交付物。** 仓内 `plugins/` 已有 OpenCode 的 `handoff-monitor.ts` 并由 `handoff skill install` 落到各家 agent（`internal/skill/plugin.go#PluginRelFile`）；Claude Code 的唤醒 mod 走同一条路：随 `handoff skill install` 安装给本机 Claude 桌面端（经用户级设置的 `CLAUDE_CODE_PLUGIN_DIRS`，本轮真机即以此加载）。

### 弃选记录（含理由）

- **常驻主 agent 会话代开（r1）**：桌面端闲置 15 分钟回收进程，常驻不存在；r2 的拉起器不要求常驻，被回收后靠深链叫醒。
- **跨会话消息 socket 推送（r1）**：桌面端会话在 bypass 权限模式下把无归属外部消息扣住等审批（台账 16:1x 探针：连得上、未送达），要改接收端设置才通；信箱 + mod 不经这条审批链，且在会话被回收时同样失效，两者没有互补性。
- **让深链 q 自动发送 / 用 mod 替人按第一下**：新建会话在人按发送前没有进程，mod 根本没有运行的地方（台账 16:25 读数）。AppleScript 模拟点击是补丁，不做。
- **`claude --bg` 后台会话当协调者**：本机已验可无人值守拉起（台账 `6184b87b`），但它不是桌面端会话，用户明确不要；另终端 CLI 未登录、版本 2.1.220 无收件 socket。
- **给 claude 开 `coordination` 能力、实现 Launch/Resume（`claude -p --resume`）**：无头一次性回合，复现 B399 形态；用户弃选。
- **云端 routines / API 触发 / GitHub 事件开会话**：开出的是 Anthropic 云端会话，到不了 127.0.0.1:7777 与 Tailscale 内账本（除非自托管环境，Team/Enterprise）。用户记忆中「GitHub 来 issue 桌面端自己开会话」就是 routine 运行后出现在会话列表。
- **桌面端本地定时任务当主路径（巡场）**：能无人值守开新会话（台账已验两次），但只按时刻触发、外部写不进调度表，延迟 = 间隔 + 几分钟抖动，且每轮都是新会话。降为拉起器缺席时的可选兜底，不进本卡范围。
- **让 keystone 对 bind 席位发起回合 / 把会话消息塞进 `card wait`**：前者是伪造，后者重蹈 B358 §3.8 否决的噪声扇出。
- **薄壳对任意自定义 scheme 放行**：只放 `claude`。

## 契约语义与接缝（L3：定语义，不定签名）

- **拉起材料由控制面产出，不由前端拼。** 材料 = 项目在**本机**的根目录 + 简报正文；「本机」按 agentd 自己登记的项目位置判断（`internal/config/listenclass.go#IsSelfTarget` 判据）。项目无本机位置 → 可读错误，前端禁用入口并显示原因。同一份材料同时服务深链、复制兜底和拉起器来信。
- **深链 wire 是外部现实**：`claude://code/new`（`folder` 绝对路径、`q` 上限 14,336 字符）与 `claude://code/continue`（`session` 为桌面端会话 id）。两条都是桌面端自己的集成面：前者是其 Finder 服务「New Claude Code Session Here」用的链接，后者是其 Linux 桌面动作「Continue Last Claude Code Session」用的链接（app 包字符串）。编码入口按边界型例外算接缝；超限拒绝不截断。
- **席位的桌面端身份**：bind 席位的 `driver_source` 仍是 `bind`，身份仍是 `cli:claude#<CLAUDE_CODE_SESSION_ID>`（`internal/proto/seat.go#EncodeSeatIdentity`）。本卡给席位增一个**桌面端会话 id**（`local_…` 形）与所在机器，由坐下的会话在 bind 时自报（它经桌面端会话管理工具读到自己的 id）；没有它的 bind 席位保持今天的语义（靠 CLI wait，不被信箱唤醒）。
- **唤醒信箱 wire（本卡新增的跨进程契约）**：信箱是本机文件目录，一封信一个文件，文件名以 CLI 会话 id 为键（前缀）；正文是人可读的来信，内容与 `session wait` / `card wait` 本来交付的投影同源（命中条 + 引用条 + 未读数 / 工单原文）。写入者是控制面（原子写），读取者是 mod（取走即删，先删后提交，重复投递以账本为准）。信箱不落账、不推进未读游标、不经 keystone。
- **唤醒路径改接**：唤醒消费轮对「有桌面端会话 id 的 bind 席位」不再跳过，而是写信 + 发 `continue` 深链；仍对「无桌面端 id 的 bind 席位」跳过、对 coordinate 席位走 keystone。深链必须在**桌面端所在机器**发出：席位记的机器 = agentd 自身时本机 `open`，否则沿 B389 的转交端点交给那台机器的 agentd。发不出（机器不可达、桌面端未装）→ 卡打 `needs_human`，信留在信箱，不丢。
- **拉起器**：每项目至多一个，是一条登记（桌面端会话 id + CLI 会话 id + 机器），由人在那场会话里用 CLI 登记；拉起请求是一封普通的信，不是 `by_system` 结构行。
- **依赖方向不新增**：web → gateway 走既有 `/api/cards/{id}/coordinator` 一族；gateway → ledger / workspace 走既有门面；写信箱与发深链是 gateway 对本机的出站 I/O，归 `d_gateway`，不进 `d_execution`。mod 是独立交付物，不 import 主模块。contract 节点落签名与信箱文件格式。

## 实现决定

- 入口名：「用 Claude Code 坐下」；兜底文案：「复制简报」+「到 Claude 桌面端新建会话后粘贴」；首次拉起提示「如弹出信任文件夹，点信任，再按发送」。禁用态原因逐字来自控制面错误。
- 简报正文（产品决策，contract 落模板）：卡号 / 标题 / 有效基线分支 / 所在会话 id / 项目根目录；三步：读 `handoff` skill → `handoff card bind <卡>` 并带上自己的桌面端会话 id → 一句「之后有事 handoff 会叫醒你，不必挂订阅；推卡按 charter 节点逐节点点火，升级按三档，需要人就 `@user:<群主>`」。不含「一次性回合」。
- mod 行为：`session.start` 后 1.5 秒首查、之后每 5 秒查一次信箱；有信即取走并以本人口吻提交为一轮；另对输入框以 `[handoff]` 开头的预填也替人提交（仅对已有进程的会话有效，是顺手的便利不是依赖）。本轮探针版在 `~/.claude/dev-mods/…/handoff-autosend`，正式版进仓内 `plugins/`，随 `handoff skill install` 安装。
- 拉起器登记：一条 CLI 命令在那场会话里执行（名字归 contract），写入项目级登记；`handoff status` 显示本机各项目的拉起器与其可达性。
- skill 文本：「占座」节补「用 Claude Code 坐下」与拉起器登记；「主 agent 回路」补拉起器职责与 CLAUDE.md 常设授权一行。
- Wave 0 已在 spec 阶段完成（台账）：深链草稿行为、信任一次、`continue` 拉起、mod 信箱活着/回收后两种情形、定时任务开会话。实现前仍需验的只有一条：launchd 托管的 agentd 进程里 `open` 深链是否能到达 GUI 会话（本轮所有探针都从交互会话发出）。
- 三段故事（breakdown 拆子卡候选）：S1 深链创建 + 简报 + 坐席自报桌面端 id + 薄壳通道；S2 信箱 wire + 唤醒路径改接 + mod 正式版 + `skill install`；S3 拉起器登记 + 代开 + `needs_human` 回落 + CLAUDE.md 授权文本。S2 不依赖 S1（席位 id 可先手填）；S3 依赖 S2。
- **定级两问**：① 跨四个子系统；② 动契约层——新增唤醒信箱 wire、席位增桌面端 id、唤醒路径对 bind 席位的语义改变。→ L3。选档：三段故事互相独立、各自可真机验收且合计远超 70 分钟 → 重档。

## 测试决定（接缝清单）

1. **拉起材料入缝（新建）**：控制面导出「按卡产出拉起材料」的方法，被卡的协调者 HTTP 端点与拉起器来信生成处调用；断言：项目无本机位置 → 错误文案；有 → 根目录为本机位置、简报含卡号 / 基线 / 会话 id 且不含「一次性回合」。
2. **深链编码入口（边界型，新建）**：前端把材料编成 `claude://code/new` URL 的入口，被卡页协调者面板调用；表驱动：中文 / 换行 / 引号 / 长度上限拒绝。
3. **薄壳外部 scheme 消息（新建，与存量 `desktop/internal/shell/external_browser.go#HandleExternalBrowserMessage` 同形）**：被 `desktop/main.go` raw message handler 调用；`claude://…` 放行并调 opener；`http://`、`file://`、`javascript:`、控制字符 → 拒绝且不调 opener。
4. **信箱写入与唤醒派发（新建）**：控制面导出「按席位投递一封信并唤醒」的入口，被唤醒消费轮调用；断言：原子写、同席位并发写不丢信；本机席位走本机 `open`，异机席位走转交；深链发送失败 → `needs_human` 且信仍在。
5. **唤醒消费轮对席位种类的分流（存量缝 `internal/agentd/wakeconsumer.go#resolveWakeCard`，调用方唤醒消费循环）**：有桌面端 id 的 bind 席位 → 走信箱；无桌面端 id 的 bind 席位 → 仍跳过；coordinate 席位 → 仍 keystone。
6. **mod 取信提交（边界型，新建；`claude plugin test`）**：信箱有信 → 一次 `prompt.submit`、信被删；空信 → 不提交；两封信 → 两轮不合并；预填 `[handoff]` → 提交并清空输入框。
7. **席位桌面端 id 自报（存量缝 `cmd/card_seat.go#currentSeatIdentity` 的调用方 `card bind`）**：带桌面端 id 的 bind 落账；不带时语义不变。
