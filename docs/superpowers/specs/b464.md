## 问题陈述

B453 把账号做成了「人手填的一条凭据落点」：登记时手填机器、凭据 HOME、凭据条目，HOME 缺省是新空目录 `~/.handoff/home/<账号名>`，登记完要么探测不到，要么要人懂 opencode/codex 的文件布局。载体那边又各自有 HOME 与凭据模式（独立 / 主 HOME 同步），两边不连。用户的原话：「基础功能是都有了，但是还没有像一个好用的产品一样串起来」。

两条根本错位：

1. **账号与凭据混为一谈**。同一个订阅账号可以登录在多台机器、多个 HOME，每份凭据各自刷新、各自过期；B453 一行账号只能表达一份。
2. **凭据被复制**。现状读数：载体检测在 HOME 为空时、协调者每轮启动在文件缺失时，从主 HOME 复制 opencode/codex/grok 的 auth.json 到载体 HOME（`internal/hostapi/probe.go:119-146`、`internal/orchestration/coordinator_home.go:345-389`）。复制出的副本与原件各自刷新，refresh token 轮换的厂商会互相作废。

## 方案

**选：账号是身份，登录是凭据落点，载体选登录。**

- **账号**：一个厂商侧身份（kind + 身份标识），按身份去重。额度读数、预警线、低额度线、探测间隔挂账号。账号名自动起、可改名。
- **登录**：账号在某台机器某个 HOME 下的一份凭据。一个账号可有多条登录（多机，或同机多 HOME）。每条登录各自有状态、凭据来源、指纹、**代理**。
- **发现**：各机 agentd 扫本机主 HOME 与 `~/.handoff/home/*`，按 kind 认出已登录身份，写入账本；同身份归到同一账号下。账号只从发现来，不再手填登记。
- **新增登录**：控制台选机器 + agent → 该机建新 HOME → 给出登录命令，人自己去登录 → 发现后自动挂到对应账号（新身份即新账号）。
- **载体**：选机器 → 选执行器 → 选该机上该执行器可用的账号登录。载体运行 HOME、凭据、代理全由登录决定；同机多个载体可共用一条登录（同一 HOME，如 opencode 不同模型各一个载体）。
- **凭据永不复制**：去掉「主 HOME 同步」模式；任何 HOME 的凭据只由人在该 HOME 登录产生、由该 CLI 自己刷新。

弃选：

- **保留手填登记作为高级入口**：两条入口会产生两种账号形态，去重语义说不清；用户要的是「像产品一样串起来」。删。
- **一条登录只给一个载体**：同账号同机要登录多次，用户已否（「允许共用，比如我在一台机器上用 opencode 的不同模型设置不同的载体」）。
- **代理挂账号、登录可覆盖**：两层配置说不清生效值；代理本质是「这台机器怎么出网」。用户选登录级。
- **handoff 代为刷新 token / 跨机下发凭据**：凭据离开所在机即违反「密钥不离机」，刷新逻辑各厂商不同。永不做。

## 落位三问

① **读写谁的权威数据**：账号（身份、名、阈值、探测间隔）与登录（机器、HOME、来源、指纹、状态、代理）归编制域账本 registry，同属账号领域；登录行由所在机 agentd 的发现写入、代理由人经控制台写；额度读数照 B453 由探测机写入。载体对登录的引用归载体记录（`architecture-law` 第五条）。
② **谁消费**：调度准入、任务启动与协调者 HOME 供给在 agentd 进程内经编制域导出符号读账号/登录（第四条第 1 档）；控制台与 CLI 经 agentd HTTP 契约面 + client（第四条第 3 档）；跨机「在某机建 HOME / 立即发现」经目标机 agentd 的 HTTP 接口。
③ **同步还是异步**：发现与探测是各机定时任务，写账本即事实，最终一致（第十二条三问全否）；「新增登录」的建 HOME、立即检查是同步调用（控制台要等结果）；载体保存对登录的引用是同步写。

## 全部必交用户故事

### S1 各机自动发现已登录账号
各机 agentd 定时（随账号探测节拍，且启动时一次）扫本机主 HOME 与 `~/.handoff/home/*` 下每个目录，对 opencode、codex、grok、agy、claude 五种 CLI 判定是否已登录并读出身份标识（opencode 的 `auth.json` 里除 opencode-go 外的第三方 provider API key 也逐个认成登录，见 S7），写成登录行；同 kind 同身份的登录归到同一账号，账号不存在则新建并自动起名（邮箱优先，否则「kind-身份短哈希」，撞名加后缀）。上次存在、本次扫不到凭据的登录标「已失效」，不删除。
- 身份标识（去重键）按 kind：opencode-go OAuth 登录 = 账号 id + org id（`opencode.db`）；opencode-go API key = key 的短指纹（与 OAuth 身份不互认）；第三方 provider API key = provider + key 短指纹；codex = `auth.json › tokens.account_id`；grok = `user_id`，缺则 email；claude、agy 的离线身份来源现状代码无（取证 §6），**未验证，需真机**——plan 先在真机核 claude（`.claude.json` 账号信息 / macOS 钥匙串）与 agy 的身份来源，取不到离线身份的 kind 由 plan 提出替代判据交主会话裁决。
- 页面顶部显示「上次发现 x 前 · 立即发现」；「立即发现」触发所有在线机器各扫一次。
- 密钥不离机（B453 纪律照旧）：账本、API、日志只出现位置与短指纹。
- 验证：真机三台（隔离 agentd + 测试账本），mac-mini 主 HOME 的 opencode 登录与 linux-01 某 HOME 的同一 opencode 账号登录归并为一个账号两条登录；`handoff account list` 与控制台账号页一致。原型 `pages/accounts.html`。

### S2 控制台新增登录
账号页「＋ 新增登录」（账号卡上「在其他机器登录」预选 agent）三步：
1. 选机器 + agent，显示将新建的 `~/.handoff/home/<自动名>`（目录名可改；已存在的目录拒绝）。确认后由该机 agentd 建目录。
2. 显示在该机执行的登录命令（远端机附 ssh 一行），可复制；对话框每 5 秒请该机检查这个 HOME，另有「我已登录，立即检查」。
3. 识别到身份：「已识别 <身份> → 已挂到账号 <名>（已有 n 条登录）」或「→ 新账号 <名>」，点「完成」。
- 关掉对话框也行：S1 的定时发现会把它挂上。
- 每种 agent 的登录命令由 plan 在真机核实后定（opencode 的 API key 登录与 OAuth 登录、claude/codex/grok/agy 的首次登录方式，**未验证，需真机**）。
- 新 HOME 不预置规则文件与 skills（归 B455）。
- 验证：真机，在 linux-01 新增一条 codex 登录走完三步；关掉对话框再登录另一 HOME，等定时发现挂上。原型 `pages/accounts.html` 新增登录弹窗。

### S3 登录状态与重新登录
每条登录显示：机器、HOME（主 HOME 显示为「~（主 HOME）」）、凭据来源、短指纹、状态（正常 / 已过期 / 已失效）、凭据到期或最近变更时刻、使用它的载体（共用时列出全部）。已过期、已失效的登录行给「复制登录命令」（同 S2 命令，指向原 HOME）。
- 已过期 = 凭据到期时间已过且 CLI 未自行刷新（判据按 kind，由 plan 定）；已失效 = 发现扫不到凭据。
- 验证：真机，删掉某测试 HOME 的凭据文件，下次发现该登录变「已失效」，引用它的载体行同步标红。原型同上。

### S4 代理挂在登录上
每条登录可设代理（空 = 随该机环境）。用这条登录的载体，其任务回合与检测回合走该代理（覆盖执行器 env 与机器环境的代理键，同 B453 S4 规则）；经这条登录做的额度探测也走它。
- 验证：真机，给一条登录填本机代理，派一个任务从任务环境读到该代理；探测日志显示经该代理。原型账号卡登录行「编辑代理」。

### S5 账号管理与额度探测
账号可改名（名字唯一）、改预警线/低额度线/探测间隔（校验同 B453）；删除账号时若有载体引用其登录则拒删并列出载体；删除只删账本记录，不动任何 HOME 与凭据，下次发现若仍登录会重新出现（删除对话框写明这一点）。
- 额度按账号一份：同一时刻只由一台机器探测，取该账号一条正常登录、走那条登录的代理；那条登录失效时换下一条正常登录。B453 的窗口、阈值、底栏、准入跳过、撞额度重跑规则照旧，引用由「账号名」改为账号 id（改名不断引用）。
- 验证：真机，改名后载体、底栏、`handoff account list` 同步显示新名；拔掉探测所用登录的凭据，下一轮探测换到另一条登录成功。

### S6 载体选账号登录
载体登记/编辑：载体名 → 机器 → 执行器 → 账号（只列所选机器上有该执行器兼容登录的账号；执行器→账号 kind：opencode→opencode-go，codex→codex，grok→grok，agy→agy，claude→claude；同机该账号有多条登录时以「账号 · HOME」区分逐条列出；opencode 执行器同时列 opencode-go 账号与第三方 API key 账号；下拉末尾固定「无账号 · 主 HOME」，给不需要凭据的载体如免费模型）→ 模型 → 并发上限。选定后只读显示 HOME、凭据来源、代理，以及「与 X 共用这条登录」。去掉 HOME 输入与凭据模式选择，去掉 B453 的载体指纹比对（载体就跑在登录 HOME 里，不再可能绑错）。
- 该机该执行器无登录：下拉为空，显示「这台机器上还没有 <agent> 登录 → 新增登录」，跳到账号页并预选机器与 agent。
- 载体运行 HOME = 所选登录 HOME；任务启动与检测都用它，不再复制任何凭据。
- 所选登录「已失效」的载体视同不可用（准入跳过，文案「载体 X 的登录已失效：<机器> <HOME>」）；「已过期」不拦（多数 CLI 运行时自行刷新），只标红。
- 存量载体迁移：按「同机 + 同 HOME」自动对上发现到的登录；HOME 为主 HOME 且对不上任何登录的，迁为「无账号 · 主 HOME」；其余对不上的载体标「未选账号登录」，照常可派发（与今天一致），载体行提示去选。今天的 `main_home_sync` 载体，其 HOME 里的副本凭据被发现为同账号的一条独立登录，不再被覆盖。
- 验证：真机，新建 opencode 载体选 mac-mini 主 HOME 登录、派任务成功；同登录再建一个不同模型的载体，两者都显示共用；存量载体升级后自动对上。原型 `pages/settings.html?section=automation`。

### S7 Claude 与第三方 API key 纳入账号体系
**claude** 作为第五种 kind：发现、新增登录、多机多登录、载体选账号全有；没有额度探测，账号卡与底栏显示「不支持额度探测」，准入不因额度拦它。claude 额度探测另开卡。
**第三方 provider API key**（用户 2026-10-22 选 A）：opencode `auth.json` 里 opencode-go 以外的每个 provider key 认成一个账号（kind 记为第三方 key，带 provider 名；身份 = provider + key 短指纹；缺省名 `<provider>-key-<4位>`），同样「不支持额度探测」、不进底栏，可被 opencode 载体选用；同一 HOME 可同时有 opencode-go 登录与第三方 key 登录。
- 验证：真机，mac-mini 与 macbook-pro 主 HOME 的同一 claude 账号归并为一账号两登录；建 claude 载体选其中一条、派任务成功；测试 HOME 放一个第三方 key，发现为账号、opencode 载体可选它；免费模型载体选「无账号 · 主 HOME」派任务成功。

### S8 协调者 HOME 不再复制凭据
协调者在承载载体的登录 HOME 里运行；每轮启动不再从主 HOME 复制凭据；规则文件与 skills 仍按今天从主 HOME 写入该 HOME，但登录 HOME 就是主 HOME 时跳过写入（同源同目标，不自我覆盖）。
- 验证：真机，协调者载体（隔离实例）拉起一轮，日志无凭据复制、HOME 内凭据文件 mtime 不变；主 HOME 登录的协调者载体拉起不改写主 HOME 规则文件。

### S9 CLI
`handoff account list` 每个账号下列出登录（机器、HOME、状态、代理、使用载体）；`handoff account probe <账号>` 照旧；新增 `handoff account discover [--machine <名>]` 立即发现。`handoff squad list` 载体行显示「账号 · 机器 HOME」。
- 验证：README 命令表与 `--help` 一致（finish-check ④）。

## 目标架构与接缝语义

- **账号领域**（`internal/scheduling/accounts`）扩为账号 + 登录两类记录；登录的写入方是所在机（发现）与人（代理）。账号与登录的关系、去重规则、自动起名、改名都在本领域收口，调用方不自行归并。
- **发现器**归 agentd（与账号探测器同处、同一节拍与单飞），按 kind 的身份读取复用 `internal/quota` 已有的凭据/身份解析（opencode-go、codex、grok 已有；claude、agy 新增），不另写一套。
- **建 HOME / 检查 HOME** 是目标机 agentd 的接口；控制台经本机 agentd 转发到目标机（与载体检测同一转发路径），控制台不直连他机。
- **调度准入**仍是 B453 的唯一判据点，增加「登录已失效」一条；不在各准入点各写。
- **HOME 供给**：任务启动、载体检测、协调者供给三处的 HOME 一律取「载体 → 登录 → HOME」，凭据复制代码删除；规则/skills 写入保留在协调者供给一处。
- **账本 schema**：登录是新记录形态；若实现需改表结构须升 `ledgerSchemaVersion`（现状读数 `ledger/schema_version.go`），纯新增 registry kind 则不升。载体对登录的引用字段由 plan 定。

## 首故事（L3）

**S1 + S6 的最薄竖切：mac-mini 主 HOME 的 opencode-go 登录被发现 → 归为账号 → 新建 opencode 载体选它 → 派一个任务在主 HOME 跑通。** 它最早暴露三个承重未知：发现的扫描与身份去重落位、载体引用登录后 HOME 供给三处是否都改到、凭据不再复制后存量载体能否自动对上。claude/agy 身份来源（S1/S7）在首故事并行做真机事实核查，结论决定 S7 能否按原样交付。

## 实现决定

- 用户可见名：控制台「＋ 新增登录」「在其他机器登录」「立即发现」「我已登录，立即检查」「复制登录命令」；登录状态词「正常 / 已过期 / 已失效」；载体「与 X 共用这条登录」；CLI `handoff account discover`。
- 账号名自动起：邮箱优先，否则 `<kind>-<身份短哈希前 4 位>`，撞名加 `-2` 起后缀；可改名，名字全局唯一（与载体、小队是否同名字空间沿用 B453 plan 的定法）。
- 新 HOME 自动名：`<agent 缩写>-<4 位随机>`，可改；只在 `~/.handoff/home/` 下建。
- 扫描范围只有主 HOME 与 `~/.handoff/home/*` 一层，不递归、不扫其他路径。
- 删账号不删 HOME、不删凭据。
- B453 手填登记框、凭据条目字段、载体凭据模式字段、载体指纹比对一并删除（前后端同步删词表）。

## 测试决定

- 竖切：发现 → 账号/登录落账本 → 载体选登录 → 任务启动 HOME，经生产组装测一条（夹具 HOME 目录 + 测试账本）。
- 核心方法：身份去重与自动起名、登录状态转移（正常/已过期/已失效）、准入「登录已失效」、凭据不再复制（断言三处供给不写凭据文件）。
- 序列化边界：登录字段经 API → 前端穿透断言（区分缺失与零值：代理空 vs 未设）。
- 密钥不泄露：发现路径沿用 B453 的泄密测试表，新增 claude/agy 读取加入。
- 真机清单：S1–S9 各条「验证」行；全部在隔离 agentd + 测试账本上做，不动在役 agentd。
- 前端：账号页、新增登录弹窗、载体弹窗单测锁接缝；浏览器熟练工对照确认后的原型做形态验收。

## Out of Scope

本期不做、后续要做（落 roadmap）：
- 新 HOME 的规则文件与 skills 同步——归 B455（已在 B455 记：同步目标按各机登录 HOME 计）。
- claude 额度探测——另开卡。
- 登录 HOME 的清理（删除不再使用的 `~/.handoff/home/*` 目录）。

- handoff 代为登录、代为刷新 token、跨机复制或下发凭据。
