# B392 spec：把 mobile bind 的真实会话核接进生产路径

**状态：已批准**（用户 2026-09-24 批准；D1 锚点与 S1–S3 建议已吸收）
**级别：L3 轻档**（实现并对接既有 gomobile 跨语言契约与平台 cookie jar；契约形状不重开，但按 charter 规则仍算动契约层。范围只有一个适配实现链，低于并行子系统的流程固定成本）
**入口：spec**（根因与冻结边界已由 B369/B369.2/B369.4 闭合，不重开协议设计）
**显式基线：`cards/B233.1-charter-7`（`a8e60208`）
**上游事实源：B369 contract/breakdown、B369.2 已落地 Core 会话 API、B369.4 延后接线计划、B386 后的现行绑定面**

## 1. 问题陈述

移动壳完成配对并选择一台在线机器后，先通过 gomobile 调用 `SwitchMachine` 激活目标机；成功后清理 webview 中的旧 `handoff_session`，再调用 `SessionCookie` 取得应写回 cookie jar 的会话值。只有写入成功，壳才可导航到该机回环源。

当前生产路径不能完成这条链：

- 配对、机器清单和回环源使用真实 `*mobilecore.Core`（现状读数：`mobile/bind/bind.go:34-38`）。
- 会话入口却仍装配为 `notWiredSessions{}`，`SessionCookie` 与 `SwitchMachine` 恒返回“未接线”（现状读数：`mobile/bind/session.go:20-30`）。
- S2 已提供真实的 `Core.Activate`、`Core.Session` 与 `Core.ActiveMachine`（现状读数：`internal/mobilecore/core.go:203-283`），但 S4 当时约定要做的生产适配没有兑现。
- 现有行为测试通过替换 session fake 验证切机语义，默认生产态测试又只要求“未接线时返回错误”；因此 fake 全绿与生产 unwired 可以同时成立（卡面红线）。

用户可观察结果是：壳虽能配对并拿到 loopback origin，却无法获得可用会话，打开控制台会落入未认证路径；切机也无法清核内旧会话并为目标机重兑换。

## 2. 根因与边界

### 2.1 根因

B369.4 开始时 S2 尚未冻结签名，故有意用 fail-closed 占位收敛风险，并明确约定“S2 落地后只替换 `sessions` 的装配”（`docs/superpowers/plans/b369.4-plan.md:82-92`、`:977-982`）。S2 后来落地并通过验收，S4 的装配承诺没有在合流后执行，故不是协议缺陷，而是已知装配漏接。

### 2.2 已冻结、不在本卡重开的事项

1. ticket→302→`Set-Cookie` 兑换由 Go 核程序化完成，绑定层不得重实现协议（`docs/superpowers/specs/b369-contract.md:193-199`）。
2. 每台机器有独立 loopback 端口，但 cookie 不按端口隔离；核内采用单槽会话罐，切机先清旧槽再重兑换（同上 `:248-252`）。
3. 回环反代不注入凭据（`docs/superpowers/specs/b369-contract.md:191`、`:250`）；绑定面不导出 `Token` / `Dial` / `Credential`（`docs/superpowers/specs/b369-breakdown.md:263`，现状读数：`mobile/bind/bind.go:8-9`、`mobile/README.md:25-26`）。
4. B386 后现行壳面是 `Pair`、`MachineCount`、`MachineAt`、`Origin`、`SessionCookie`、`SwitchMachine`、`Close` 七个函数（现行读数：`mobile/README.md:15-38`）；不得按 B369.4 旧计划恢复 `MachineNames` 或旧返回形状。
5. Kotlin/Swift 壳工程不进入本仓；平台 `WKHTTPCookieStore` / `CookieManager` 的实际写入属于外部消费真机接缝（`docs/superpowers/specs/b369-breakdown.md:41-46`、`:253-278`）。

## 2.3 L3 轻档判定

B392 不改七函数签名，但并非“只动内部实现”：它实现既有 gomobile 跨语言契约从 Core 到 Android/iOS 壳的行为，并规定平台 cookie jar 的消费结果。按 charter 定级规则，对接既有跨语言/跨进程契约即便本侧零形状修改也算动契约层，因此不能判 L2。

选轻档的依据：契约已经由 B369 冻结，S2 已提供实现，B392 只有一个有界适配实现链和一组移动真机验收，没有两个可并行开发的子系统工作量，低于 breakdown 扇出的流程固定成本。批准后先走 `contract` 冻结精确适配与接缝，再走 `breakdown` 轻档复核；不拆子卡。

## 3. 目标与非目标

### 3.1 目标

- 用同一个真实 `*mobilecore.Core` 同时服务配对面与会话面。
- 删除生产 `notWiredSessions` 占位及其占位错误。
- 让 `SwitchMachine` 真实完成“目标机激活/切机清槽/重兑换”，只在目标 origin 可用时返回成功。
- 让 `SessionCookie` 只返回所请求机器当前有效会话的真实 cookie 值，拒绝旧机、错机、空值与未激活状态。
- 用真实 Core 的跨绑定竖切和非 fake 生产装配守卫，消除当前假绿。
- 把壳侧调用顺序写成稳定交接契约，供 Android/iOS 壳与移动 CI 消费。

### 3.2 非目标

- 不改变 ticket、pair bundle、agentd 路由、Core 已冻结的 cookie 属性语义或 web 前端协议。
- 不把 `internal/mobilecore` 的协议逻辑上移或下移到绑定层。
- 不新增跨语言 DTO、Token/Dial 出口或根模块对 `mobile/` 的反向依赖。
- 不定义首台机器自动选择策略；本卡仍由壳显式选择机器。
- 不负责吊销旧机器在 agentd 中的服务端会话；本卡只清核内单槽与壳侧旧 cookie。

## 4. 方案

### 4.1 唯一生产组装点

`mobile/bind` 设一个私有默认运行时组合点，只构造一次真实 `*mobilecore.Core`，再从同一实例导出配对视图与会话适配视图。配对面、会话面和 `Close` 必须观察同一机器表、同一活动会话槽与同一生命周期。

禁止另起第二个 Core 给会话使用；两个核会分裂机器表与活动槽，`Pair` 成功也不能保证 `SwitchMachine` 可用。

现有私有 `sessionAPI` 只保留为测试缝；它不是新的跨语言契约，也不得成为生产占位入口。

### 4.2 `SwitchMachine` 语义

1. 串行进入会话适配器。
2. 调用同一 Core 的 `Activate(machine)`；该调用复用 S2 已冻结的“切机先清旧槽、同机可缓存复用、切到别机后重兑换”语义。
3. 验证激活返回的会话值非空；cookie 名称选择仍由 Core 的既有兑换逻辑负责。
4. 调用同一 Core 的 `Origin(machine)`。
5. 只有兑换与 origin 都成功，才返回目标 loopback origin；任一步失败都返回 error，壳不得导航。

现状 `Core.Activate` 的精确方法还带 `context.Context`（`internal/mobilecore/core.go:219`）；本 spec 只冻结上述可观察顺序，不在此替 contract 选择 ctx 来源或取消策略。contract/plan 必须按真实签名调用，不能把本文的 `Activate(machine)` 简写误当精确 Go 签名。

适配器不吞错误、不返回空串 + nil，也不重解释 HTTP 状态或 cookie 协议。若 `Activate` 已成功而随后 `Origin` 失败，`SwitchMachine` 仍返回 error 且不返回 origin；Core 可能已持有目标会话，本卡不伪造回滚，壳也不得导航。

### 4.3 `SessionCookie` 语义

1. 与 `SwitchMachine` 共用一把私有互斥锁，使“校验活动机器 + 读取 cookie”是一个不可交叉的绑定层操作。
2. 校验 `ActiveMachine() == machine`；不等即报错，禁止把当前另一台机器的 cookie 返回给调用者。
3. 调用 `Session()`，校验返回的会话值非空；Core 负责选取 `handoff_session`、维护服务端有效性与缓存到期，壳按 §4.4 的冻结 tuple 写 cookie。
4. 只返回 cookie value，保持现行 string-only 导出面；不返回 token、origin 或完整内部 DTO。

适配器锁覆盖整个会话入口调用，因而会跨过 Core 的网络兑换；它不复制协议，只保证壳看到的“切机完成”和“活动机 + cookie”不会互相穿插。

### 4.4 壳侧完整消费顺序

现行七函数契约不变，壳按以下顺序消费：

1. `SwitchMachine(target)`；
2. 仅在返回成功后，按 `name=handoff_session + host + Path=/` 清理该 loopback host 的旧 cookie；cookie 不按端口隔离，清理必须覆盖该 host 的所有端口；
3. `SessionCookie(target)`；
4. 将返回值写成 host-only `handoff_session`：`Path=/`、`HttpOnly=true`、`SameSite=Lax`、`Secure=false`，不设置持久 `Max-Age/Expires`（进程内会话 cookie；服务端到期仍是最终权威）；
5. 导航到 `SwitchMachine` 返回的 origin。

这些属性沿用 agentd 的现行 `sessionCookie`：`name=handoff_session`、`Path=/`、`HttpOnly`、`SameSite=Lax`，且明文 loopback 下 `Secure=false`（`docs/superpowers/specs/b369-contract.md:46-47`；现状符号 `internal/agentd/authroutes.go#sessionCookie`）。string-only 契约不返回动态 `MaxAge`，因此壳写进程内会话 cookie，不把服务端 TTL 复制成新的客户端持久策略。

任一步失败都不得继续导航。清 jar / 注入失败由壳呈现可行动错误；Go 绑定层不伪装自己能操作平台 cookie store。

### 4.5 弃选方案

- **在 Core 新增面向壳的 `SwitchMachine` / `SessionFor`**：会把壳的 string-only 投影与调用顺序语义塞回提供方，扩大本可由薄适配层收敛的契约；弃选。
- **在 session 路径另建一个 Core**：机器表与 Pair 状态分裂；弃选。
- **保留占位，仅改文档/测试**：生产仍恒失败，不能解除 B369 阻塞；弃选。
- **让 web 前端用 token 或 JavaScript 写 cookie**：突破回环凭据边界，且违反“协议与凭据只在 Go 核”的冻结决定；弃选。

## 5. 用户故事

1. 作为移动壳，我在配对并选择在线机器后能得到一个“会话已就绪”的 loopback origin，而不是一个随后必定 401 的地址。
2. 作为移动壳，我切到 B 后取得的 cookie 一定属于 B；拿 A 的 cookie 必须失败，不能串机。
3. 作为用户，我按 A→B→A 切机时每次都进入所选机器，不被旧 cookie 拉回上一台。
4. 作为维护者，我能用真实 Core 穿过导出绑定面验收；只替换 session fake 的测试不再能证明生产已接线。
5. 作为 Android/iOS 消费方，我有一份稳定的调用顺序，可用真实 cookie 更新 webview jar 而不接触 token。

## 6. 契约语义与接缝

本卡不新增或修改 wire / gomobile 契约；只兑现既有契约的组合与行为。

### 6.1 组装不变量（不单占测试缝）

默认运行时必须只构造一个真实 Core，配对视图、会话视图与 `Close` 共享该实例。它是 6.2 生产路径的装配前置，不是独立测试缝：身份守卫和“生产仍是占位则红”都从 `mobile/bind` 导出缝穿过，不另造只为测试存在的生产 seam。

### 6.2 壳绑定逻辑接缝

- **符号**：`mobile/bind.Pair`、`mobile/bind.SwitchMachine`、`mobile/bind.SessionCookie`、`mobile/bind.Close`（`MachineCount` / `MachineAt` / `Origin` 继续走同一默认运行时）。
- **生产调用方**：gomobile 生成的 Android/iOS 绑定与实际壳。
- **测试调用方**：默认生产组合竖切、真实 Core 竖切与错误/并发测试。
- **断言**：不调用 `swapCore` / `swapSessions` 时生产默认路径仍走同一真实 Core；A→B→A 的 origin/cookie 归属、同机缓存、错机拒绝、导出 `Close` 后拒绝、并发不串机。

### 6.3 平台 cookie jar 边界接缝

- **符号**：上述两个 gomobile 导出方法。
- **外部调用方**：`WKHTTPCookieStore` / `CookieManager`。
- **断言**：这是外部现实接缝，只认真实 AAR/XCFramework + 真机注入与导航结果；仓内 fake 不得冒充该证据。该接缝不占用内部测试缝名额。

## 7. 实现决定

- L3 `contract` 节点只冻结 B392 的私有适配签名、同一 Core 组装不变量、调用顺序、cookie 属性与两条测试接缝；不重开 B369 已冻结的七函数或 HTTP wire。
- 保持 B386 后的七个导出函数及本包 `Machine` 形状不变。
- 生产会话实现直接消费现有 `Core.Activate`、`Core.Session`、`Core.ActiveMachine`、`Core.Origin`；不改这些 Core 方法的精确签名。
- 采用单一默认运行时组合点，消除 `core` 与 `sessions` 各自独立构造/替换的生产状态。
- 私有会话适配器负责：调用顺序、活动机器一致性检查、空值校验、切机与取 cookie 的互斥；不复制 S2 协议。
- 保留结构化日志与凭据卫生：可记录 machine、origin 和 cookie value 长度；不得记录 cookie value、token 或 Authorization。
- `mobile/README.md` 补齐 §4.4 的调用顺序和“Go 返回真实 cookie，平台 jar 由壳写入”的职责边界。
- 本卡限定在 `mobile/bind`、其测试与移动模块交接文档；`internal/mobilecore`、agentd、web、CLI 和 codegraph 冻结物不改。

## 8. 测试决定

### 8.1 接缝覆盖

| 接缝 | 必落测试 | 允许 fake | 禁止替代 |
|---|---|---|---|
| `Pair → SwitchMachine → SessionCookie → Close` | 默认生产组合与真实 `*mobilecore.Core` 跨绑定竖切 | 仅网络对端、relay、agentd HTTP 夹具 | 禁止 fake Core 作为验收集合 |
| gomobile 形状 | 现行七函数冻结 + 真 gobind 无 skipped | 无 | `go build` 或 skipped test 单独通过不算 |
| 平台 cookie jar | AAR/XCFramework 真机清单 | 仓内不可替代 | fake jar 不算真机证据 |

### 8.2 真实 Core 竖切

使用真实 Core 和真实 bind 适配器，网络对端可 fake。`mobile/bind` 测试须自行用 `mobilecore.New` + 可控 `DialFunc` / 本地 HTTP 夹具搭出真实链，不复用 `internal/mobilecore` 同包测试的未导出 helper。夹具必须按目标机器或 ticket 签发可区分的 `handoff_session` 值，使 A/B 差异来自真实 `Set-Cookie` 响应；不得预置一个与响应无关的假值来制造通过。至少覆盖：

1. 配对 A/B 两台在线机器。
2. `SwitchMachine(A)` 返回 A 的 origin，`SessionCookie(A)` 逐字等于 A 对应 `Set-Cookie` 的非空 value。
3. 切到 B 后 origin 改为 B；`SessionCookie(A)` 失败，`SessionCookie(B)` 逐字等于 B 对应 `Set-Cookie` 的 value，且该值由夹具按机器/ticket 签发、与 A 不同。
4. 切回 A 后重新兑换并返回 A 的新会话值。
5. 同机重复调用命中 Core 的现有缓存语义。
6. 未配对、离线、兑换无 cookie、Core 关闭均返回 error，绝不返回空串 + nil。
7. 从绑定导出面调用 `Close` 后，`SwitchMachine` 与 `SessionCookie` 均失败。
8. 并发 `SwitchMachine` / `SessionCookie` 在 `-race` 下通过，且不把 B 的 cookie 返回给 A。

并发适配器可用阻塞式 `sessionAPI` test double 强制制造“已校验 A、尚未读取 cookie、此时切到 B”的交错，证明去掉互斥会确定性返回错 cookie；该 fake 只补并发缝，不能替代上述真实 Core 验收集合。

### 8.3 非 fake 生产守卫

必须有一条不调用 `swapCore` / `swapSessions`、从默认生产组合直接走 `Pair → SwitchMachine → SessionCookie` 的真实 Core 测试；另有身份守卫确认配对、会话与 `Close` 共享同一 `*mobilecore.Core`。若把生产会话重新接成 `notWiredSessions`、另一占位实现或第二个 Core，测试必须失败。验收时至少做以下变异并保存原始红输出：

- 生产恢复 `notWiredSessions` → 生产守卫红。
- 去掉 `ActiveMachine == requested` 检查 → A/B 串机测试红。
- 把任一失败路径改为 `return "", nil` → 失败语义测试红。
- 去掉适配器互斥 → 阻塞式并发测试确定性打红；`-race` 作为附加闸。

## 9. 验收判据

1. **生产接线**：生产代码不再存在或装配 `notWiredSessions`；默认配对面、会话面和 `Close` 共享同一真实 Core。
2. **真实行为**：§8.2 全部通过；测试返回的 cookie 与测试 agentd 的 `Set-Cookie.Value` 对得上，不使用预置假值冒充。
3. **非 fake 守卫**：§8.3 每个变异均实测打红并还原。
4. **失败闭合**：所有未配对、离线、兑换失败、空 cookie、错机关闭路径均返回 error；无空串 + nil、无 token/origin 冒充 cookie。
5. **导出面**：B386 后七个函数与本包 `Machine` 形状不变；无 Token/Dial/Credential 导出；必须实际运行钉版 gobind 并确认产物无 skipped function/field。工具缺失、版本不符或测试 `Skip` 均阻塞验收，不能以退出 0 冒充通过。执行前先按 `mobile/README.md:42-80` 核对 JDK 21、Android NDK `30.0.16248370`、Android SDK platform 36 与钉版 gobind；环境缺失要报告具体前置，不得误报成代码失败。
6. **移动模块**：`cd mobile && go build ./...`、`go test ./... -count=1`、`go test ./bind/ -race -count=1`、`go vet ./...` 全绿，`gofmt -l` 无输出。
7. **根模块**：根 `go build ./...` 与根全量测试不退化；根 `go list ./...` / `go list -deps ./...` 均不含 `github.com/Xsxdot/handoff/mobile`。
8. **交接文档**：`mobile/README.md` 明写“切机成功 → 清旧 jar → 取 cookie → 注入 → 导航”，并说明任一步失败不得导航。
9. **真机证据**：移动 CI/真机可用时，必须重建 Android AAR 或 iOS XCFramework，并验证切机后 API 与 WebSocket 带新 cookie、旧机 cookie 不再发送、无 cookie 仍 401。真机不可用时可由用户明确接受“未验”落账，但不得宣称卡面主路径或 B369 真机门已通过；缺什么必须逐项记录。

## 10. Out of Scope

### 10.1 当前架构与契约永不做

- 在绑定层重实现 ticket、302、cookie 或 relay 协议。
- 向壳暴露 Token、Dial、Credential 或完整内部 cookie DTO。
- 让根模块依赖 `mobile/`，或让 `internal/mobilecore` 依赖 agentd/web/壳。
- 用前端脚本、日志或本地文件传递会话 cookie。
- 在本仓新建或维护 Kotlin/Swift 壳工程；该职责归外部壳项目，本仓只维护 Go 绑定面与交接契约。

### 10.2 本期不做、后续要做

- **mobilecore 图覆盖债**：当前 baseline 未收录 `Core.Pair` / `Core.Activate` / `Core.Session` 等 S2 新符号；另走图债卡重扫或视图 absorb，不在 B392 偷带全图刷新。来源：本文 §11。
