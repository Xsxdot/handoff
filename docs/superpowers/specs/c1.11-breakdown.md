### C1.11-GraphVersion：消费 charter/graph v0.8.0 并对齐 desktop（`d_maintenance`，边界型）

#### ①契约引用

- `c1.11-contract.md` §2“依赖契约”、§4.2“版本与同提交边界”、§5.2“validate 边界缝”、§5.3“回归与不命中项”。

#### ②意图与为什么

让 handoff 根模块和嵌套 desktop 模块在同一实现提交消费精确的 `graph/v0.8.0`，从而让声明迁移使用 best 主词表、宿主使用同一套 `DomainDecl` 行为；同时保持 desktop 通过现有根模块 replace 间接解析，不制造第二份依赖入口。模块版本、声明数据和 host response 必须同提交，避免中间提交先变红再补数据。

#### ③验收

**边界型机内验收（只验契约形状）：**

- 在根模块运行 `GOSUMDB=off GOMODCACHE=<可写任务缓存> go list -m -f '{{.Path}} {{.Version}}' github.com/Xsxdot/charter/graph`，stdout 必须是 `github.com/Xsxdot/charter/graph v0.8.0`；`go.mod`/`go.sum` 中不得残留 `v0.7.0` 的 charter graph 记录，且 `rg -n 'replace .*charter/graph' go.mod` 无输出。
- 在 `desktop/` 运行同一 `go list -m`，stdout 必须同为 `github.com/Xsxdot/charter/graph v0.8.0`；`desktop/go.mod` 仍没有 charter/graph direct require，`desktop/go.sum` 有 v0.8.0 module/hash 记录。
- 在 `desktop/` 运行 `go mod tidy` 后，`git diff --exit-code -- desktop/go.mod desktop/go.sum` 返回 0；根模块的 tidy/依赖升级后，`git diff --exit-code -- go.mod go.sum` 在干净提交上返回 0。
- `go mod download -json github.com/Xsxdot/charter/graph@v0.8.0` 必须解析冻结 tag/hash 和 sum；若 registry/proxy 失败，保留原始错误，不把未验证写成成功。
- 变异复验：将 desktop sum 暂改为 v0.7.0 或加 charter/graph replace 后，上述 resolved-version/no-replace/clean-diff 门至少一项必须失败；证明锁的是调用方依赖形状而不是注释。

**缺陷族对抗审查：**

- 生命周期 / 状态机中断：`go mod tidy`/`go list` 是有限工具流程，不创建 agentd 进程、工单或临时业务目录，因此无业务资源收尾；runner 中途重启后的缓存清理与 desktop CI 工作区行为**未验证，需真机，归协调者执行**。
- 静默失败 / 误导报错：只看 root `go.mod` 绿会掩盖 desktop 仍解析旧版本；双模块 `go list`、两侧 sum、tidy clean 和 v0.8.0 validate 必须同时成立。依赖下载失败必须保留原始 stderr，不报“版本已对齐”。
- 跨平台假设：Linux 本地 module 解析不能证明 Wails/Windows toolchain；Windows 交叉编译、macOS/Linux desktop 构建与 CI 前置 gate **未验证，需真机，归协调者执行**。
- 假红 / 假绿测试：`go mod tidy` 单独通过不是验收；resolved version、无 replace、双侧 clean diff 和后续 CI 不 skipped 才锁调用方依赖。并发不适用，**无，因为本卡不新增运行时并发状态**。
- 门禁绕过：本卡不改 `.github/workflows/ci.yml`、不删除 Windows/install 门、不用 replace 绕过依赖；module clean diff 是现有门的输入。检查与动作之间的真实 runner TOCTOU **未验证，需真机，归协调者执行**。
- 序列化边界：无新增业务 JSON/DTO/CLI 字段，**无，因为本卡只改变 Go module manifest/sum，由 module resolver 消费，不新增手写业务投影**。
- 枚举新值过既有白名单：无新增状态名、事件类型、kind 或 domain 声明值，**无，因为 v0.8.0 是依赖版本而不是业务枚举**；domain id 的白名单核对归 `C1.11-DeclMigration`。
- 承重安全属性有测试锁住：版本一致性、无 replace、tidy clean 是本卡承重门，变异复验必须能红；一次性 token、唯一性、隔离无命中，**无，因为本卡不生成凭据、不创建共享任务资源**。
