# B295：检测改为短超时发一条消息

- **卡**：B295
- **级别与档位**：**L2**。行为改在 `d_execution_host` 的 `Host.WakeHome` 内部（改调同包 `RunTurn`）。`d_gateway` 的 detect 编排形状不改（仍 `WakeHome` → `ApplyDetect`），无新 HTTP/DTO/依赖方向。B293 条 34/36 的语义由本 spec 废止，不新开契约面——先前 L3 是把「改冻结条文」误判成「跨子系统契约」。
- **状态**：已批准（用户 2026-08-29：超时 3 分钟；凭据供给仅 `main_home_sync` + 空目录；定级改 L2）
- **基线**：`acc/b156.2-156.3`
- **发现自**：B293 验收。用户 2026-08-29 原裁决是「检测用隔离 HOME 走执行者真路径发一条简单消息」；B293 把「有时限、别在控制台卡进登录 TUI」写成「禁 RunTurn」，`WakeHome` 落地为 `--version` + 凭据文件。B293 已完成，不 reopen。
- **台账**：`docs/superpowers/specs/b295-ledger.md`

## 问题陈述

谁在什么条件下，通过什么关系，使什么事实变化：协调者对一个**载体**点检测（或创建后自动那一次）时，系统必须用该载体的 HOME 走已有的「喂 prompt、收回合」进程承载，发一条无意义短消息，按这一回合的真实结局写四态。`--version` 和凭据文件在不在，都不能当健康。

载体不分协调者/执行者两种。载体是一种实体（机器 × CLI × HOME × 模型 × 凭据 × 并发上限）；角色在小队上。检测挂在载体上，与它进哪个小队无关。

现状（2026-08-29 读本工作树）：

- `handleCarrierDetect` → `hostapi.Host.WakeHome` → `runWake` 跑 `<cli> --version`（`internal/hostapi/probe.go`）。
- B293 契约条 36：检测不得调用 `RunTurn`。
- 协调者拉起已经走 `coordinatorRunner.Launch` → `Host.RunTurn`（`internal/agentd/server.go`）。B156.3 §4.1：进程承载（无头拉起、喂 prompt、收事件流）是与角色无关的技术能力，禁止另写一套。
- `RunTurn` 目前只实装 opencode（B156.3 岔口一）。未实装 CLI 已有「未实装」错误，不得回落 `--version`。

## 方案

1. 解冻并废止 B293 条 36。检测**必须**走 `Host.RunTurn`，不准再跑 `--version`。
2. `WakeHome` 仍负责创建隔离 HOME，然后用该 HOME 调 `RunTurn`（固定短 prompt、**3 分钟**超时，不得用 30 分钟回合缺省）。**仅当**凭据来源是 `main_home_sync` **且**隔离目录为空时，先把主 HOME 里那一份表内凭据拷进隔离 HOME，再发消息。独立凭据（`standalone`）不拷主 HOME；目录非空绝不覆盖。
3. 成功判据：这一回合正常收回合输出 → 已上线。不核对回复原文是不是 "pong"。登录/鉴权失败 → 未上线；额度 → 限额中；超时/网络/未实装 → 按 B293 四态表（上过线 → 不可达，从未上线 → 未上线）。
4. 不经过 keystone：检测没有卡，不绑会话、不写房间、不落指针。不经过执行派发状态机。
5. 路径探测（改 HOME 时三类提示）仍只看目录，本卡不改。
6. 控制台仍不拉登录 TUI；登不上就在时限内失败，「运行」按钮继续只复制命令。

弃选：

- **继续 `--version` / 凭据文件当健康**：否。用户原裁决。版本号和文件在不在看不见登录失效、免费额度、模型不可用。
- **检测走 keystone.Launch**：否。那一层绑卡、写房间。检测没有卡。
- **检测走执行者 `Manager.Dispatch`**：否。协调者铁律：进程承载不进派发状态机。
- **未实装 CLI 回落 `--version`**：否。假健康。跟协调者拉起同一条失败（「未实装」），载体停在未上线。
- **本卡把 grok/claude/codex 接到 `RunTurn`**：否。那是把 B156.3 推迟的名单一次做完，另开卡。本期跟现役进程承载对齐。
- **把载体分成协调者载体 / 执行者载体、两套检测**：否。角色在小队上。

## 用户故事

1. 作为协调者，我保存一个空 HOME 的载体后，系统自动检测：用该 HOME 发一条短消息；能回话就是已上线，不能就是未上线。
2. 作为协调者，主 HOME 已登录且凭据策略是同步时，检测先把凭据拷进隔离 HOME，再发那条消息——不是只看文件出现了就算上线。
3. 作为协调者，点「检测」重复同一条动作；控制台不会弹出登录 TUI。
4. 作为协调者，一个载体无论进协调者小队还是执行者小队，检测行为相同。
5. 作为协调者，grok/claude/codex 载体在 `RunTurn` 未实装前检测失败、保持未上线，不会被 `--version` 标成已上线。

## 契约语义与接缝

本卡改 B293 已冻的检测语义，不改四态词表、不改 HTTP 路径、不改路径探测。

**检测**：在载体所在机器上，用该载体 HOME 走 `Host.RunTurn` 发一条固定短消息（时限 **3 分钟**）。凭据来源若是「主 HOME 同步」且隔离目录为空，先拷表内那一份凭据再发消息；其它情况直接发。供给仍收在 `WakeHome` 里，不新开端点。

**健康**：最近一次检测的回合结局。凭据文件与 `--version` 退出码不参与 `ApplyDetect`。

**会话**：检测产生的 CLI 会话是一次性的，不绑定任何卡，不得被后续拉起当协调者会话 resume。

接缝（最高可测缝一条，加一条边界）：

1. **`hostapi.Host.WakeHome` → `Host.RunTurn`** — 调用方：`handleCarrierDetect`（本机）/ `handleHomeWake`（`?machine=` 对端）。断言：生产路径不再 exec `--version`；传入的 `TurnRequest` 带载体 `HomeDir`/`CLI`/`Model`、非空 Prompt、超时 3 分钟；成功映射 `ready`，登录/额度/超时按现表；`RunTurn` 报未实装不得变成 `ready`。`main_home_sync` + 空目录时拷贝发生在 `RunTurn` 之前；`standalone` 不拷。
2. **路径探测仍只读文件系统** — 存量 `ProbeHome`。断言：本卡不让探测去发消息。假缝，不占名额，只防回退。

## 实现决定

1. `runWake` 删掉 `--version` argv，改为构造 `TurnRequest` 调 `RunTurn`。检测超时改为 **3 分钟**（废止 B293 条 34 的 30s），显式传入 `RunTurn`，不用 `DefaultTurnTimeout`（30 分钟）。
2. Prompt 固定一句无意义短消息（精确字面归 contract）。成功 = 无错误且 Output 非空，不匹配特定回复。
3. 凭据来源是 `main_home_sync` 且隔离目录为空：先拷主 HOME 表内那一份凭据，再 `RunTurn`。`standalone` 不拷。目录非空不覆盖（B293 occupied 纪律保留）。
4. detect 编排、`ApplyDetect`、四态表、控制台按钮、跨机 wake 转发，本卡不改形状。
5. 空白 HOME 落 CLI 自己的文件，改为这一回合的副作用，不再靠 `--version` 初始化。

## 测试决定（接缝清单）

缝 1 至少一支：`WakeHome` 在夹具里走到 `RunTurn`（可用测试替换），argv/env 不再含 `--version`；未实装 CLI → 非 `ready`；超时为 3 分钟、不调用 30 分钟缺省。`handleCarrierDetect` 的四态映射既有测试保持。

变异靶：把 `RunTurn` 调用改回 `--version`，缝级测试必须红。

真机（归协调者）：本机已登录的 opencode 载体，空白隔离 HOME，点检测 → 已上线，且该 HOME 里不是只靠 `auth.json` 存在。

- **永不做**：未实装 CLI 回落任何「看起来能跑」的旁路。
- **本期不做、后续要做**：把 `RunTurn` 接到 grok / claude / codex（B156.3 岔口一余量）。来源本卡。
- **本期不做**：改路径探测为发消息。
- **本期不做**：检测会话绑定为协调者会话。
- **本期不做**：自动限额查询、派发失败回写状态（仍在 B293 OOS）。
- **本期不做**：设置页形态（检测按钮已在）。
