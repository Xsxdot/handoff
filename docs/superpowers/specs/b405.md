## 定级理由

单子系统（agentd 的配置与审批编排），不实现也不对接任何跨仓/跨进程 wire 契约：`approver.models` 是机器本地 config.yaml 的键，裁决调用是进程内方法调用，OneShot 请求结构与 CLI 通道均不变。plan 写出来不止复述 spec 三行（解析、校验、候选级取值、回归钉）→ 不是 L1。

## 问题陈述

谁：执行机上审批链的每个候选执行者（config.yaml 的 `approver.executor` 有序列表）。

条件：`approver.model` 今天是整条链共用一个名字——留空则每个候选用该执行者自己的默认模型；写上则每个候选都收到同一个模型名（现状读数：`internal/config/config.go:201` `ApproverConfig.Model` 注释「空=用执行者自身默认模型（全候选共用）」；`internal/orchestration/approver.go` `decideWithCandidate` 把 `a.model` 原样塞进每次 `OneShotReq.Model`，不区分候选）。

通道：配置 → `ApproverConfig` → `Approver.model` → 逐候选 `OneShotReq.Model`。

要变的事实：用户要把 linux-01 审批链配成「agy 用自己的默认模型，codex 用 gpt-6-luna」。今天表达不了：写 `model: gpt-6-luna` 则 agy 也被迫收到 gpt-6-luna；留空则 codex 也用默认。

谁能观察到：agy 候选被调用时不带模型名（走 agy 默认），codex 候选带 `gpt-6-luna`；裁决日志与候选尝试记录能看到每个候选实际用的模型。

## 方案

`approver.executor` 有序候选语义不动（标量/序列/块序列均合法，B376 承诺）。新增同层映射键 `approver.models`：**键 = 执行者候选名，值 = 该候选的模型名**。某候选无同名条目、或值留空 → 回落链级 `approver.model`；链级也空 → 用该执行者自身默认。

取值优先级：**候选 models 条目 > 链级 model > 执行者默认**。

目标场景写法：

```yaml
approver:
  executor: [agy, codex]
  models:
    codex: gpt-6-luna
```

弃选与理由：

- **把 `executor` 改成结构化条目**（块序列 `- name: codex` / `model: …`）也能表达，但破坏 B376 的「同键标量/序列都合法」兼容承诺，存量配置要么静默失效要么强制迁移。`models` 映射是纯增量，存量配置行为逐字节不变。弃。
- **链级 `model` 直接废弃**：会让存量 `executor: [a, b]` + `model: x` 配置行为漂移。保留它作为回落默认，零漂移。弃。

## 用户故事

1. linux-01 配 `executor: [agy, codex]` + `models: {codex: gpt-6-luna}`：agy 候选调用不带模型名（agy 默认模型），codex 候选带 `gpt-6-luna`；agy 失败 failover 到 codex 时同样按各自模型。
2. 存量配置零漂移：只配链级 `model`（无 `models`）→ 每候选仍收到同一模型名，与今天一致；只配 `executor` → 每候选各自默认，与今天一致。
3. 错字保护：`approver` 启用时，`models` 的键不在 `executor` 候选列表内 → 配置加载报错，报错文案点名错字键（与 `approver.blacklist` 正则启动期校验同一纪律）。
4. 可观测：每次裁决的日志与候选尝试记录带每个候选实际用的模型名；未指定时显式记「默认」。

## 实现决定

- 配置面只增一个用户可见键 `approver.models`：进未知字段白名单与报错文案的键清单（现状 `internal/config/config.go:630` 的支持键列表）。
- 校验：`approver` 启用（executor 非空）时，`models` 键必须是 `executor` 候选列表成员；值允许空串。**空串与缺条目同义**：先回落链级 `model`，链级也为空才用该执行者自身默认——不是跳过链级回落直接用默认（2026-09-23 批准意见收进）。`approver` 未启用时 `models` 出现与否均不校验（与现有 approver 取值域校验只在启用时生效同款）。
- 链级 `Model` 语义不变，退为回落默认。
- 裁决签名与 OneShot 请求结构不变；候选尝试审计记录增记本候选实际模型（名字落法归 contract/plan，不在此写死）。
- env 注入、timeout、blacklist、failover 顺序一概不动。
- linux-01 上模型留空的临时配置（备份 `config.yaml.bak-approver-20260923`）本卡不动（批准意见重申）；实现完成后是否按新能力重配属真机验收步骤，由人决定。
