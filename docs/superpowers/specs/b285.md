# B285 工作台收口：关分屏、点开新组、拖放示意与顶栏跟焦

状态：已批准（2026-08-28）
定级 **L2**（单子系统 `d_web` / 工作台+壳+左树；不改 agentd 契约。plan 增量非零，不是 L1）
基线：`cards/B281-charter-9`（B281 未合 main）
形态对照：`prototypes/b285-workbench-polish`（fork 自 b264-tab-groups；去掉＋分屏栏、关 tab 收列/收组、拖放半区阴影、顶栏跟焦点、任务行方案 2）
发现自：B281 真机验收

## 问题陈述

B281 把中央改成全局标签组后，真机上分屏和组的生命周期反了直觉：关内容留下空窗格、空窗格删不掉、左栏点击在当前组加列、任务拖不进分屏、拖放几乎没有落点示意。组栏下还有一条「＋分屏」，终端窗格叠了两层标题；顶栏面包屑跟左栏选中目录走，不跟正在看的窗格走。旧桌面里三个 tab，新桌面变成四个分屏加四个标签组。

谁：桌面/浏览器控制台用户，接着 B281 的工作台用。
条件：已经有标签组和分屏，或从旧桌面带过来的终端会话。
变化：关内容就拆分屏；组里没内容就关组；左栏点开未打开项只新建组；加分屏只靠拖放，并画出半区阴影；顶栏跟焦点窗格；任务行按原型方案 2。
观察：关最后一个内容后组一起消失（唯一组重置成空组）；拖任务到窗格右侧出现半透明落点并开出新列。

## 方案

沿 B281 已定的列模型（一列最多上下两格、中间替换、贴边加列/上下），改生命周期和一层视觉。对照 `prototypes/b285-workbench-polish`。弃选：组栏下的「＋分屏」条（原型 layout-strip 一并拿掉）；关 tab 留空窗格（B281 `closeTab` 现状）。

### 关 tab / 空窗格

- 关掉一个有内容的窗格：拆掉这一格；若该列空了就拆列。
- 空窗格也可以关，同样拆格/列。
- 该组不再有任何内容：关掉该组。唯一一组时重置成一个空组（与关组按钮对最后一组的现行为一致）。
- 不再用「留一个 null pane 占着分屏」当默认。

### 左栏点击 vs 拖放

- 左栏点**未打开**的任务，或点机器/目录上的「开终端」：新建一个标签组，不要在当前组加列。
- 点**已打开**项：跳到它所在组的那一格。
- 当前组加分屏只允许拖到中央窗格（任务、目录、已打开窗格标题都要能拖）。任务行必须能开始 HTML5 拖放。
- 组栏上「新建内容」仍写入当前组（这是对着这一组说话，不是左栏打开）。

### 拖放示意

- 拖到窗格上按原型画半区阴影：左/右半幅、上/下半幅、中间。不要只剩一条 1px 彩条。

### 顶栏与窗格标题

- 面包屑（含桌面薄壳标题栏）跟**当前焦点窗格**的目录走，不跟左栏选中态走。没有焦点内容时可以空着或不渲染。
- 每个窗格只留一层标题栏：标题、项目/机器、关闭。终端内容不再画第二道「label + 路径」条。

### 左栏任务行

- 按原型方案 2：左侧类型头像（终端/文件/TUI 各一套 SVG）、右下状态点、右侧机器名。不要用通用 lucide 圆钮冒充。

### 恢复

- 旧按目录存的行继续当 legacy 丢掉，不猜测式迁成全局组。
- 解码后的全局布局先清掉空列/空组。
- 还活着、布局里没有的 PTY 会话：每个开成**独立标签组**（与左栏点击一致），不要填进当前组的空列，也不要既当一列又当一组。

## 用户故事

1. 我关掉一个分屏里的终端，那一列消失；再关到组里最后一个，这个标签组也关掉。只剩一组时中央变成一个空组。
2. 我从左栏点一个还没打开的任务，顶栏多出一个新组，当前组的分屏不动。
3. 我把左栏一个任务拖到当前组窗格右半边，出现半透明落点，松开后右边多一列。
4. 我看着 charter 的终端，顶栏写的是 charter，即使左栏焦点还停在别的项目。
5. 旧桌面里开过的三个终端，新桌面是三个标签组（或解码出的真实全局布局），不会变成「一组四列再复制成四组」。

## 实现决定

- 仍只改 `d_web`。工作台仍用现有 `PUT /api/workbench/state/base` 存一行全局 payload，不新增后端字段。
- 关窗格/关组、左栏打开、拖放置放是同一套布局模型的写入，不在 React 里另做一份。
- 恢复是布局模型的入口之一，必须服从「空列不保留、孤儿会话按新组领养」。
- 现状读数（B281 工作树）：
  - 关 tab 留 null pane：`web/src/app/workbench/tabs.ts` `closeTab`（约 234–246 行）
  - 左栏开终端走加列：`useWorkbench.ts` `openTerminal` → `openTab`（约 102–111、193–216 行）
  - 组栏下＋分屏：`WorkbenchPage.tsx` 约 249–251 行
  - 终端第二层 header：`TerminalTab.tsx` 约 595–605 行
  - 拖放 1px 条：`WorkbenchPage.tsx` 约 204 行
  - 任务行 mousedown 可能挡住拖：`ProjectTree.tsx` `task-row` 约 589 行
  - 面包屑绑 selected：`Shell.tsx` 约 544 行
  - 恢复填空格：`tabs.ts` `appendRestoredTab` 约 414–431 行；legacy 丢弃：`restore.ts` 约 88–91 行

## 测试决定（接缝）

一条缝：全局工作台布局生命周期（关窗格收列/收组、左栏打开新建组、拖放置放、恢复领养）。

调用方：`useWorkbench`（Shell 左栏/抽屉）、`WorkbenchPage`（关窗格、拖放）、`buildRestore`（hydrate）。

覆盖：关最后内容关组、唯一组重置空组、空窗格可关、左栏未打开项新组且当前组列数不变、已打开项只聚焦、任务 MIME 拖到右半区加列、恢复不把孤儿填进空列、面包屑读焦点窗格 base。

变异：把 `closeTab` 改回留 null pane → 「关完列还在」转红。

本节点该干什么一律以注入的纪律块为准。

## Out of Scope

- 不改 agentd / 工作台 state API / PTY 协议。
- 不重做五宫格/六宫格，不恢复窗格内一排文件 tab。
- 不把旧按目录 payload 猜成全局布局（继续丢弃）。
- 文件抽屉里点文件仍写入当前组，不强制新组。
- 桌面壳 WKWebView 专项走查仍跟 B281 合并一起做，不在本卡单开。
- 不为 home 浮窗改白名单。
