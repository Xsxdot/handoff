# 卡号带项目前缀（B178）设计

> 状态：**已批准**（用户 2026-08-23 批准）
> 级别：**L2**（单子系统：账本域 `d_ledger`；CLI 加一个子命令属薄调用方改动，不跨子系统契约）
> 卡：B178 —— 「不要都用B开头，这样不好区分是哪个项目的」

## 1. 问题陈述

卡号是全局单一号段、`B` 前缀硬编码：`nextTopID` 取 `max(现存顶层号, min_b) + 1`
并格式化成 `B%d`（`internal/ledger/cards.go:90`）。于是账本里 `handoff`、`charter`、
`benchmarking` 三个项目的卡混在一条 B 号序列里，光看号分不出归属。

好消息是代码面的耦合极浅——全仓对 `B` 前缀的硬编码只有两处正则：
`topIDPat = ^B(\d+)$`（`cards.go:23`）与 `importIDPat = ^B\d+(\.\d+)*$`（`cards.go:247`）。
前端零硬编码（只有测试数据里的字面量）。分支名 `cards/{cardID}-{purpose}`
（`internal/ledgerstep/dispatch.go:132`）直接拼卡号，会自动跟着变。

真正的约束不在代码里：**账本已有 200 个 B 号，而对它们的引用散布在 `docs/` 下的
spec、历史 commit message、已合并的分支名里**——那些引用改号一个都修不到。

## 2. 承重现状

| 事实 | 出处 | 为什么承重 |
|---|---|---|
| 取号是 `max(现存顶层号, min_b) + 1`，全局单一号段 | `internal/ledger/cards.go:61-90` | 改造的落点就是这里 |
| `B` 前缀硬编码只有两处正则 | `cards.go:23,247` | 代码改动面小，别被「牵一发动全身」的直觉吓退 |
| 子卡号是父号加点号位（`B157.1`） | `cards.go` 的 `nextChildID` | 前缀方案必须让子卡继承父卡前缀 |
| 分支名直接拼卡号 | `internal/ledgerstep/dispatch.go:132,148` | 前缀会渗进分支名，这是**期望行为**不是副作用 |
| `min_b = 173` 是全局水位（导入历史卡时防撞号） | 实测 `ledger_meta` | 语义要跟着号段一起收窄，否则新前缀会莫名其妙从 174 起步 |
| 卡的 `project` 是**自由字符串**，不依赖项目登记表 | 账本 `cards.project` 列；实测 `benchmarking` 卡存在而其登记是 agentd 侧的事 | 前缀映射**必须存在账本自己这一侧**；去读 `project_locations` 会把本卡从 L2 抬成跨子系统 |
| `B191` 属于 `charter` 项目，`B187`（已废弃）属于 `benchmarking` | 实测账本 | 存在「非 handoff 项目却占着 B 号」的活样本，方案必须正面回答它 |
| 卡号永不复用，终止/归档的卡仍占号 | `cards.go:58` 注释 | 前缀分配应继承同一条纪律：分出去的前缀不回收 |

## 3. 方案

### 3.1 前缀是项目的属性，handoff 的值恰好是 `B`

账本侧新增一张 `card_prefixes(project TEXT PRIMARY KEY, prefix TEXT UNIQUE)`，
出厂种入一行 `handoff → B`。

**历史卡一张不动**，所有旧引用继续有效——这是本方案的全部价值所在。代价是
「`B` 这个字母看不出是 handoff」，但它本来就是历史遗留，用一次不可逆的全量改号
去换一个字母的语义整洁，不成比例（用户 08-23 拍板）。

### 3.2 号段按前缀独立

`nextTopID` 改为按**前缀**（而非项目）算水位：`max(该前缀现存顶层号, 该前缀水位) + 1`。
- `handoff` 继续从当前 B 水位往下走（下一个是 B204 一类）。
- `charter` 分到 `C`，第一张卡是 **C1**。
- `min_b = 173` 的语义从「全局水位」收窄为「**`B` 前缀的水位**」，值不变、行为不变；
  其余前缀水位缺省 0。**这条必须显式改**，否则 `C` 前缀会从 174 起步。

**按前缀而不是按项目算**：前缀与项目是一对一，但号的唯一性约束长在前缀上（卡号本身
不带项目名）。按项目算会在「改过前缀」这类边角上算出撞号。

### 3.3 前缀怎么来：自动派生，撞了才要人管

首次给某个项目建卡时分配前缀，规则依次尝试：

1. 取项目名第一个 ASCII 字母，大写（`charter → C`、`sq → S`、`handoff-server → H`）；
2. 该值未被占用 → 落库，建卡继续；
3. **被占用，或项目名里没有 ASCII 字母**（中文名、纯数字名）→ **拒绝建卡**，
   报错说清冲突方与解法：「项目 handoff-server 的自动前缀 H 已被项目 X 占用，
   请先执行 `handoff card prefix handoff-server <前缀>`」。

显式通道：`handoff card prefix <project> <prefix>`。
- 前缀格式：1~4 个大写 ASCII 字母（`^[A-Z]{1,4}$`）。
- **仅当该项目名下还没有任何卡时可设/可改**；已有卡后拒绝——改了前缀，已发出去的
  卡号就成了孤儿，这与「号永不复用」是同一条纪律的两面。

**弃选**：建项目时必须显式指定前缀。理由——卡的 `project` 是自由字符串，可以从未
在任何地方「建」过；把前缀绑到一个不存在的建项目动作上，等于给每次首建卡加一道必填。

**弃选**：用项目名全称当前缀（`handoff-1`）。零歧义零配置，但卡号要频繁手敲
（命令行、分支名 `cards/handoff-1-charter`），日常成本压过收益。

### 3.4 正则放宽

- `topIDPat`：`^B(\d+)$` → `^([A-Z]{1,4})(\d+)$`，捕获前缀与序号两组。
- `importIDPat`：`^B\d+(\.\d+)*$` → `^[A-Z]{1,4}\d+(\.\d+)*$`。
- 子卡号继承父卡前缀（`C1 → C1.1`），`nextChildID` 无需知道前缀是什么——它只在父号
  后面追加点号位，天然正确。

### 3.5 遗留的诚实交代

`B191`（charter 项目）与 `B187`（benchmarking，已废弃）会永久保持 B 号，
而这两个项目的新卡将是 `C1` / `Be1` 一类。**同一个项目下会有两套号**，这是零迁移
方案的已知代价，明写在此，不假装它不存在。查询与展示一律按 `project` 字段判归属，
**任何地方都不许从号前缀反推项目**——那正是 B191 会打脸的地方。

## 4. 用户故事

1. 我看到 `C1` 就知道这是 charter 项目的卡，不用点开看 project 字段。
2. 我给 handoff 建卡，还是拿到 `B204`，我过去所有文档里的 B 号引用照旧有效。
3. 我第一次给 `sq` 项目建卡，什么都没配，直接拿到 `S1`。
4. 我给 `handoff-server` 建卡，它的首字母 H 与 handoff 撞了（若 handoff 已用 H），
   建卡被拒并告诉我该敲哪条命令，而不是悄悄给我一个奇怪的号。
5. 我给 `C1` 拆子卡，拿到 `C1.1`，前缀自动继承。
6. 我派发 `C1`，分支名是 `cards/C1-charter`，一眼看出是哪个项目的分支。

## 5. 实现决定

- `card_prefixes` 表落在账本库，与卡同库同事务：分配前缀与建卡必须在**同一个事务**里，
  否则并发首建两张同项目卡会分出两个前缀。取号本来就在 `mutate` 的全局写锁内，
  把前缀分配放进去零额外代价。
- 前缀分配失败一律**拒绝建卡**，不做任何兜底（不退回 B、不生成随机前缀）。
  静默兜底正是本卡要消灭的那类行为（参见同期 B179：静默取 `cards[0].project`）。
- `min_b` 的键名保留不改，只在注释与读取处写明它现在是「B 前缀的水位」。
  改键名要动迁移脚本，换来的只是名字好看。

## 6. 测试决定（接缝清单）

**接缝就一个：`ledger.Store` 的建卡路径**（`cards_test.go` 已在这个缝上）。

| 判据 | 落点 |
|---|---|
| handoff 建卡仍走 B 号，且续在当前水位之后 | `internal/ledger/cards_test.go` |
| 新项目首建卡自动派生首字母前缀并落库 | 同上 |
| 前缀撞车时**建卡被拒**且错误文案含冲突方与解法 | 同上 |
| 项目名无 ASCII 字母时建卡被拒 | 同上 |
| 号段按前缀独立：新前缀从 1 起步，**不受 min_b=173 影响** | 同上（本设计最容易写错的一条） |
| 子卡继承父卡前缀（C1 → C1.1） | 同上 |
| `card prefix` 在该项目已有卡时拒绝修改 | 同上 |
| import 接受非 B 前缀的显式号 | `cards_import_test.go` |

**变异复验（验收时必做两条）**：把新前缀的水位起点改成读全局 `min_b` →
「新前缀从 1 起步」那条必须转红；把撞车分支改成静默回退 B 前缀 →
「建卡被拒」那条必须转红。

## 7. Out of Scope

**永不做**
- 历史卡改号（§3.1，用户 08-23 拍板）。
- 从卡号前缀反推项目归属（§3.5——B191 会让它出错）。
- 前缀回收与复用（与「号永不复用」同源）。

**本期不做、后续可能要做**
- 控制台上的前缀管理界面（本期只给 CLI；`d_web` 不在本卡范围内，做了就跨子系统）。
- 已有卡的项目下改前缀（现在一律拒绝；真需要时再单独设计迁移）。
- 前缀的多字母智能派生（`handoff-server → HS` 而不是撞车报错）——先让人显式指定，
  等撞车足够频繁再谈自动化。

## 8. 备注

- 本设计不改任何 wire DTO：卡号在协议里一直是 `string`，前缀变化对 agentd 与前端透明。
- 分支名会因此带上项目前缀，这是白赚的收益（`cards/C1-charter`），不需要额外改动。
