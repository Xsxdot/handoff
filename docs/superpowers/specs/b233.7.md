## 用户故事

1. **提问对得上原题。** 引擎用同一个原生问题身份再问一次（常见于「答复没对上选项」）。协调者收到一张**还能答**的新工单；答完后执行侧回到那道原题，而不是对着空身份碰运气。未答的重放仍复用原工单，不刷第二条事件。
2. **批了但没送到，盯卡的人看得到。** 审批决定送回 OpenCode 失败时，任务事件流出现可订阅的投递失败；不得只写日志还让执行者继续卡在原生权限上无声等。
3. **这一票的纪律真的在这一票上。** 普通派发把任务层纪律交给 harness；写入任务/会话层，不覆盖载体全局规则；同一载体两个任务互不污染。Verify 验的是这些内容在不在、对不对，不是「全局 AGENTS.md 文件存在就算准备好」。
4. **diff 对的是那次结果。** 取任务 diff 时，若已得到准确 commit，就用它当 head，不得组装完丢掉再按分支名取。不新加 HTTP 字段。
5. **竖切试卷与产品规则一致。** 小队准入后执行者等于载体 CLI；请求里写另一个执行者不得出现在绑定里。
6. **派发失败不自动再来一次。** 网络失败后协调者先查远端和本地到底有没有任务，再决定要不要重派。skill 写明这条。不保证「再派一次仍是同一个远端任务」。

## 契约语义与接缝

定语义，不定签名。

1. **Ask 身份。** 原生问题身份属于任务问答事实，不随工单主键改写而丢失。协调者工单可以因「旧单已答还要再问」而新建（否则协调者无法再答）；新建工单必须带上同一原生问题身份，回程按该身份投递。没有原生 id 的提问仍允许一次性 uuid（与今日无稳定 id 的路径相同）。
2. **审批投递。** 决定形成与原生投递是两件事实。投递失败保留「已决未送达」，并发布与 Ask 回程失败同类的可订阅事件。恢复时核对原生请求是否还在，不把日志当唯一证据。
3. **任务纪律。** 全局规则属载体 HOME；任务纪律属任务层快照。harness 负责放到原生位置并校验内容。禁止任务纪律覆盖全局同名规则。派发/执行启动必须填任务层内容；只写文件没有读取方不算完成。
4. **结果引用。** `ResultRef.Commit` 非空时，后续定位 diff 的 head 用它。允许 Path 在树已回收时为空（既有约定）。
5. **载体物理身份。** 绑定后的机器 / 执行者 / HOME 与载体一致；请求侧不得覆盖。模型是否可覆盖保持 B233.5 既有规则。
6. **写请求。** 一次调用一次 HTTP，不自动重试。重复派发不在本卡提供「仍是同一任务」的保证。

## 实现决定

- 已答再问：保留「新开可答工单」（现状注释所述，复用已答 id 会把任务卡死）；补上原生问题身份的持久化与回程。禁止把「换 uuid」理解成可以丢掉原题。
- 权限原生投递失败：与 Ask 共用同一类投递失败事实，不另发明事件名。
- Overlay：生产派发/执行启动填任务纪律；Prepare 写入任务层；Verify 断言内容。测试必须用与生产相同的规则文件名证明「不覆盖全局」。
- probe 成功路径不得靠测试里把探针设成恒 true 冒充热加载已发生。
- diff：有准确 commit 就用；没有则保持今日按分支取的降级，并让这条降级可观察（日志即可，不新造用户命令）。
- B350：改测试与竖切注释，使之与 `bindingFor` / `TestAdmitNoLongerOverridesPhysical` 同义。
- R8：改 B233.3 说明书与 roadmap 中「重试仍单任务」的过时句子；`handoff` skill 补「失败先查状态再决定」。

## 测试决定（接缝清单）

每条缝 = 符号 + 调用方。假缝（只为走满分支抽出的纯函数）不占名额。

1. **Ask 重发回程**  
   符号：`handleQuestion`（现状 `internal/agentd/manager.go#handleQuestion`）+ `RespondAsk`  
   调用方：OpenCode 提问事件 → 工单 → `waitQuestion` / `RelayAnswer` → 执行实例  
   断言：已答后再问同一原生 id → 新工单可答 **且** 回程 `QuestionID` 等于原生 id；未答重放不建第二张单、不发第二条 question 事件。必须改掉把「换 uuid 且无原生 id」冻成正确的测试。

2. **权限原生投递失败**  
   符号：`authorizeNativePermission`（现状 `internal/executor/opencode/adapter.go#authorizeNativePermission`）+ `NoteDeliveryFailed`  
   调用方：OpenCode 原生权限事件  
   断言：`RespondPermission` 失败 → 任务事件含 `delivery_failed`；成功路径仍 Ack 已送达。反面：只打日志、事件流没有失败，测试必须红。

3. **任务纪律写入与校验**  
   符号：`Profile.Prepare` / `Profile.Verify` + 派发/执行启动填 `ProfileReq.TaskOverlay` 的生产调用方  
   调用方：普通派发或执行启动（现状 `coordinator_home.Prepare` 只服务协调者拉起，执行入口必须同样填）  
   断言：任务纪律出现在任务/会话层；全局规则文件内容不变；Verify 在 overlay 缺失或内容不符时不得 Verified=true。禁止用 `task-1.md` 这类与生产不同名的文件冒充「不覆盖 AGENTS.md」。

4. **结果引用消费**  
   符号：`assembleResultRef` + `handleTaskDiff`  
   调用方：任务 diff HTTP  
   断言：Commit 非空时 `DiffRange` 的 head 是该 commit，不是组装前的分支名。不新增对外字段。

5. **准入物理身份**  
   符号：`Admit` / `bindingFor`  
   调用方：`TestIgnitionVerticalSlice`（以及已有 `TestAdmitNoLongerOverridesPhysical`）  
   断言：载体 CLI=opencode、请求 Executor=claude 时，绑定 Executor=opencode。

接缝外文档：skill 与 B233.3 说明书的句子级对账，不占缝名额。
