## 3. 宿主响应 wire 契约

### 3.1 顶层形状

当前实现使用 `map[string]any`，不引入新的公共 Go 响应 struct。实现只在成功条件满足时增加这一项：

```go
"decls": map[string]codegraph.DomainDecl
```

`decls` 的 value key 是声明文件名去掉 `.json` 的领域 id；每个 value 必须是 `LoadDomainDecls` 返回的 `codegraph.DomainDecl` 原值。宿主不把声明映射到 best、不从 best 补声明、不改写字符串、不重排任何声明数组、不把缺席值编码为 `nil`。

完整响应键的精确口径如下：

| 键 | Go 值 | 存在条件 |
| --- | --- | --- |
| `baseline` | `*codegraph.Graph` | 基线成功加载；既有必需键 |
| `views` | `map[string]*codegraph.Diff` | 基线成功；既有必需键，坏视图仍按现状跳过并告警 |
| `stale` | `[]codegraph.StaleNode` | 基线成功；nil 已被现状归一为空数组 |
| `best` | `*codegraph.Best` | best 存在且加载成功 |
| `target` | `*codegraph.Target` | best 存在且 target 加载成功 |
| `decls` | `map[string]codegraph.DomainDecl` | 见 3.2；只允许出现，不允许以 `null` 代替缺席 |
| `report` | `*codegraph.Report` | best、target、声明加载均成功；既有语义保持 |

`decls` 是 additive-only：正常响应只是在既有键集合上加一个顶层键；baseline、views、stale、best、target、report 的类型、内容和错误状态不因本卡改写。源码端点、`?machine=` 一跳转发和路由路径也不变。

### 3.2 有/无键判据

实现可把 `LoadDomainDecls` 的调用移到 best/target 分支之外，但对外必须兑现下表；不允许只凭读取代码才能推断的隐式分支：

| 场景 | HTTP | `decls` | 其它约束 |
| --- | --- | --- | --- |
| 基线、best、target 成功，`codegraph/domains/` 存在且所有声明合法 | 200 | 有，逐字段等同文件内容 | `report` 用同一份 `decls` 调 `Check` |
| `codegraph/domains/` 目录缺席 | 200 | 无 | 依赖库虽返回空 map、nil，宿主仍须省略键，不能发 `{}` 或 `null` |
| best 缺席 | 200 | 无 | 既有响应不含 best、target、report；声明不单独升级成响应段 |
| target 加载失败 | 200 | 无 | best 可保留；既有 target/report 缺席行为不变 |
| 单个声明文件解析/读取/校验失败 | 200 | 无 | 告警并省略 `decls`；整图响应不得变成 500，既有 report 条件保持为声明加载失败时不生成 |

目录“存在”必须按实际目录存在性判定，与依赖函数的“目录不存在返回空 map”区分开；实现可用标准库等价检查，不得用 `len(decls) == 0` 偷换语义，因为空目录与目录缺席不是本表同一事实。缺席三态（目录、best、target）和坏单文件都必须各有接缝断言。

### 3.3 精确装配顺序

`internal/agentd/codegraph.go#handleProjectCodegraph` 仍先完成现有基线、视图、stale 装配，再进行 best/target 对照。实现轮应将声明读取结果作为唯一 `decls` 来源：

```go
decls, err := codegraph.LoadDomainDecls(loc.Path)
// err != nil：Warn，后续 response 不写 decls；整图仍 200。
// best/target/目录存在且 err == nil：response["decls"] = decls。
// report 若生成，必须把同一个 decls 传给：
report := codegraph.Check(target, best, codegraph.Merge(g, nil), decls)
```

上段是装配契约的类型与数据流，不要求实现引入同名局部变量以外的新导出符号；目录存在性判定属于实现细节，但上述五种可观测结果不可改变。

## 4. 声明数据迁移契约

### 4.1 文件与 id

同一个实现提交必须同时完成下列数据改写，不能留下 `ValidateDecls` 已按 best 词表执法而声明仍用旧 id 的中间提交：

- 删除 `codegraph/domains/d_coordination_task.json`。
- 新建 `codegraph/domains/d_orchestration.json`，顶层 `domain` 精确为 `d_orchestration`。
- `d_orchestration.json` 保留旧声明的 `responsibility` 原文、lifecycle 原文和三条仍属 d_orchestration 的 invariants（CAS、活跃任务非终态、终态作废工单）；不机械改写职责句或测试文本。
- 从新声明移除不变式「状态只能沿 transitTable 登记的迁移边变化」及其 `TestCanTransit`，并移除整个 `stateMachine` 数组（12 条迁移均属 `d_protocol` 方向）。这些欠账逐条记入 `docs/roadmap.md`，不伪挂到 `d_orchestration`。
- `codegraph/domains/d_workspace.json` 零改动；其 `domain` 已是 best 顶层 id `d_workspace`，其声明文本不在本卡机械重写。
- 其余 21 个 best 域本期不创建空声明文件；覆盖率诚实保持 2/23。

### 4.2 版本与同提交边界

一个实现提交必须同时容纳：根 `go.mod`/`go.sum` 升 v0.8.0、desktop 依赖 tidy、上述声明迁移、宿主 `decls` 响应装配及对应测试。被否掉的过渡方案是让 v0.8.0 的 `ValidateDecls` 同时接受 `d_coordination_task` 和 `d_orchestration` 两套词表；这会把“迁成最优树 id”变成永久兼容而无法收口。

## 5. 接缝与测试契约

### 5.1 主缝：宿主响应装配

在 `internal/agentd/codegraph_test.go` 增加或等价扩展表驱动测试，调用真实 `httptest` agentd 路由，不直接调用一个新造的 handler 外面。每个 case 解码为 `map[string]json.RawMessage` 或等价 map，必须区分“无键”和 `null`：

1. 正常态：`decls` 反序列化后与 `codegraph.LoadDomainDecls(repo)` 逐字段等同，包含 responsibility、invariants 的顺序、lifecycle、stateMachine；响应 200。
2. 删除 `codegraph/domains/` 目录：响应 200 且 `decls` 键不存在。
3. 删除 `best.json`：响应 200 且 `decls` 键不存在。
4. 写入非法 `target.json`：响应 200 且 `decls` 键不存在。
5. 写入非法单个声明文件：响应 200、告警路径可观测、`decls` 键不存在；整图不是 500。

变异复验必须有牙：把缺席分支改成写 `response["decls"] = nil` 时三种缺席断言变红；把正常态改成补默认值或重排/删字段时逐字段等同断言变红。

## 7. 拍板记录

本轮命中三重闸门的一项决定是：把 v0.8.0 词表升级、声明文件迁移与宿主 `decls` 响应放进一个提交，并拒绝让校验器过渡期兼容旧 `d_coordination_task`。这同时跨根模块、desktop 间接依赖、被分析仓声明数据和 agentd wire 响应，回退会让多个子系统重新对账；没有本段上下文，后人会自然尝试“先升库再补数据”；被否掉的双词表方案虽能短期保持绿，却会使最优树 id 迁移无法收口。

本轮另命中一项 wire 取舍：声明缺席统一省略 `decls` 键，而不是发 `null` 或空对象；被否掉的是用一个默认空 map 让客户端永远看到固定键。该差异会被跨进程客户端的键存在性判断长期消费，改变它需要同时调整宿主、前端和测试，且空对象会掩盖“声明目录不存在”与“已加载但为空”的事实；因此本卡冻结“无键”并要求直接断言其非 `null`。

除上述两项外，无其它三重闸门命中；步骤顺序、变量命名和测试夹具选择均由实现轮按本契约落地。
