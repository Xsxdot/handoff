### 1.9 200% 缩放的实际形态（查证）

compact 判据是纯 `window.innerWidth`（`useShellViewport.ts:19-23`，分档 ≤767 phone / ≤1023 pad / >1023 desktop）+ resize 监听（`:37-45`）。据此：

- **桌面浏览器缩放 200%**：缩放以 CSS px 计（设备像素不变、CSS 像素变大），`innerWidth`（CSS px 读数）随之减半——1440 宽窗口 → 720（pad 档）、1280 → 640（phone 档）。即 **200% 下壳会切进 compact 形态并触发 resize 重渲染**；对本产品这是响应式一份产物的预期形态，不是回归。
- **真机捏合缩放**：`web/index.html:5` viewport meta 为 `width=device-width, initial-scale=1.0`，layout viewport 恒 390，捏合只改 visual viewport，`innerWidth` 不变、不触发断点翻转。
- 结论：验收里的「200% 缩放走查」实际形态 = **桌面浏览器 200% 下的 compact 档走查**（预期所见就是本卡修完的移动布局），加上 100% 桌面三栏不回归；不是「200% 下保持桌面布局」。走查时记录实测 `innerWidth` 归档，避免断点翻转被误报为回归。

## 2. 目标

### 2.1 设置两级 IA：Web 设置中心为缺省首屏，执行机与配对降为二级页

- **缺省首屏 = Web 设置中心**，四分区就地呈现（分区标题+内容，不是链接墙）：①**会话打开方式**（新客户端偏好，localStorage，`treePrefs` 先例）：会话列表点开后的落点——群聊态（缺省，现状）/焦点任务现场；②**提醒**（新客户端偏好）：底栏未读/「需要你」角标的开关（角标机制已在 `MobileTabBar.tsx:49-53`）；推送通知是原生壳能力，不在此造（OOS §5）；③**显示与可访问性**：GeneralPage 全部既有项迁入并更名（`GeneralPage.tsx:42-123` 三开关/排序/项目勾选，语义零变更）；不新增 a11y 偏好开关——文本缩放交给系统与浏览器缩放，不造平行机制；④**关于**（只读）：产品名+当前版本（数据源 `useDesktopState`/`useLatest`，`SettingsPage.tsx:52-58` 在用），更新动作留在「更新」二级页。
- **二级页**：「执行机」（MachinesPage 原样承载）与「扫码配对」（本期承载配对语义说明 + `handoff console --qr` 产物指引；原生壳扫码/相机归壳侧，web 侧不接端点不接相机）；「执行纪律」「自动化」「Env 文件」「更新」作为管理面二级入口保留可达，不做布局重构——w-40 挤压随左栏在 compact 移除而消失。

- §1.6 五处 hover 入口在 compact 改触屏可达形态（常驻或行内展开，形状归 plan；桌面形态逐字节保留，B369.7 双档先例 `ProjectTree.tsx:678-688`）。验收口径是「不得依赖 hover」：hover 仍可显形，但触屏与键盘必须有同等可达路径。

### 2.7 a11y 硬闸：覆盖层后的后台内容 aria-hidden + inert

- **机制**：被覆盖的后台内容包 `aria-hidden` + `inert`。仓内先例 = WorkbenchPage 后台组（`WorkbenchPage.tsx:311-313`：`aria-hidden={!visible}` + React 19 boolean `inert` + pointer-events-none），事件层兼容已有（`TerminalTab.tsx:378-380` 尊重 inert 祖先）。
- **覆盖面**：mobile-home 与 mobile-dir 盖住的常驻工作台（`Shell.tsx:911` 外层）；FullPageCover 盖住的工作台（桌面同机制——同一组件缝、布局零变化）；SessionTab 详情态盖住的群聊；CardDrawer 盖住的卡列表。
- **选型理由（排除法）**：`display:none`/卸载破坏 B280 常驻语义（xterm 断 WS、画布捏 0，`Shell.tsx:907-910` 明令禁用）；纯 `aria-hidden` 只摘读屏树、键盘 Tab 仍可入（WCAG 2.4.3/4.1.2 失败）；`inert` 同时断读屏树、Tab 序与指针命中，可随覆盖层生命周期开关，不影响布局与 keep-alive——是唯一同时满足「后台不可达」与「工作台常驻」的选项。inert 自身已阻断指针，pointer-events-none 是否随行沿先例叠加归 plan。
- **焦点移交**：抽屉/详情态打开时焦点移入（`Overlay.tsx:32-33` 先例），关闭归还触发钮；Tab 圈定由 inert 自然实现，不造 focus-trap。
- **自动化边界（如实）**：jsdom 能锁 aria-hidden/inert 属性随覆盖状态翻转、焦点落点、aria-expanded/aria-selected 结构；**真读屏行为**（VoiceOver/TalkBack 对 inert 树的播报、扫焦顺序）只能人工/半人工走查——浏览器读屏（本机 VoiceOver + Chrome/Safari）在本卡走查表内；壳内 TalkBack/VoiceOver 验收 OOS（§5）。

## 3. 与 B369.7 导航模型的接缝（不发明第二套导航模型）

- **设置二级页进 URL 模型**：compact 下 `/settings` pathname 未注册（`Shell.tsx:1014-1019` 门控 `!compact`），设置 tab 挂在 `/?tab=settings`（`useMobileNav.ts:90`）。二级页语义 = 扩展 useMobileNav 语汇，新增 `tab=settings` 专属参数（形如 `sub=<key>`，**参数名归 plan**）——与 `dir`↔projects 同款「参数只在其 tab 有消费者」纪律（`useMobileNav.ts:216-227`）：`openCard` 在既有删参处（`:163-168`）同步删 `sub`；`normalize` ③ 清 `tab≠settings` 的 `sub`；无 `sub` = Web 设置中心缺省首屏。桌面 `/settings` 整页的 `?section=` 机制（`SettingsPage.tsx:42-49`）不动，两套互不感知（SettingsPage 的 window 直读与 router 注入的统一归 plan 岔口）。
- **会话群聊/详情切换不进 URL**：它是会话内容面内的视图切换，不是导航层级——验收不要求「直达某会话的详情态」深链，进 URL 只会膨胀语汇并多一条 normalize 规则。落 SessionTab 内部状态（与桌面 `drawerOpen` 同源换形）。这不违背「URL 唯一事实源」：该模型管的是底栏 tab 与详情层的导航状态（`useMobileNav.ts:1-19` 职责边界），不是一切 UI 状态。
- **卡详情三层 / hover 处置 / a11y 硬闸：零新导航状态**。卡抽屉开关已走 `nav.openCard`/`nav.closeCard`（`Shell.tsx:994`、`CardsPage.tsx:251-263` seam），本卡不新增 URL 参数。

## 5. 非目标

- **B369.9 的终端面**：单焦点终端投影、WorkbenchPage/终端窗格内容形态不归本卡；工作台容器加 inert 是覆盖层 a11y 闸，不是终端面改动。
- **桌面交互形态重构**：设置双栏、卡看板/列表、会话「⋯」抽屉、项目缺省展开全部保留；本卡在桌面侧的净改动只有 FullPageCover 覆盖期 inert（布局无感）。
- **FlowsPage/Codegraph 移动适配**：B369.7 已隐藏+解释，本卡不翻案。

## 6. 风险与开放问题

1. **卡详情分层 vs「重设计」的边界**：验收明文要求「按工作项→当前动作→证据分层」，重排有法定依据、不越界；越界形态是**信息重组到二级视图**（抽屉内再分 tab/折叠导航）——那会引入新导航层级与返回语义。本卡界定：分层 = 同页重排 + 分层标题，全部块单页可达；「三层用分组标题还是折叠组」归 plan 岔口，折叠组若实现必须缺省展开（否则把扫描成本换了个形式）。
2. **compact 隐藏看板/列表切换是可见性收窄**：单列承载全部卡、零信息丢失，但桌面养成「看板」习惯的用户在手机上找不到入口。备选（保留切换、看板容器横滚）与「无页面级横向滚动」的解释弹性有解释空间（容器级 vs 页面级），但审计把「扫描成本高」与横滚并列为病，单列是更贴验收的读法——记开放问题，review 可翻案（翻案代价：看板在 compact 的横滚容器加显式扫描提示）。
3. **inert 的 webview 内核兼容**：iOS Safari/WebView 15.5+、Chrome 102+ 支持；浏览器读屏走查在当前桌面浏览器无风险，壳内 webview 内核版本归真机清单（本卡 OOS 的壳侧验收项，交卡时知会）。降级表现 = 后台重新可达（退回现状），不会白屏。
4. **settings `sub` 参数与桌面 `?section=` 双机制**：语义分工已定（§3），但 SettingsPage 的 window 直读与 router 感知要统一（否则同一组件两种深链来源）。倾向 SettingsPage 改接 props/param 注入、保留独立单测可渲染——归 plan。
5. **项目缺省折叠与 B369.7 成果的叠加**：折叠只改缺省展开态，三段式钉底（B369.7 验收修正的 subjects）不受影响——展开区变短反而强化钉底；测试锁「折叠态下 note 与入口行仍在视口内」。
6. **验收判据与代码现实无根本矛盾**：每条判据都有可达处置（§2），无「无法自圆其说」项；唯一口径风险是 200% 缩放触发断点翻转（§1.9）——已在验收映射中写明预期形态，防止被误报为桌面回归。

## 7. 原型缺失说明

卡上原挂的四个原型 html **已不在盘上**（实测 `prototypes/` 下无 `mobile-app` 目录；`prototypes/base/` 为桌面形态镜像，无移动屏）。形态依据以卡上两份笔记为准：审计笔记（2026-09-21，问题清单与证据）与北极星写回（2026-09-22，形态 canonical 描述——「设置首页改为 Web 设置中心，执行机与扫码配对降为二级页；卡列表保留需要你聚合与单列扫描，会话切换使用语义化按钮」）。北极星笔记自述「已在本地原型浏览器走查设置中心与执行机二级页；**键盘/200%/读屏和桌面回归仍待验收节点完成**」——本卡 §4 走查列即其法定承接。

## 8. 定级结论与落点

**L2**。理由：单子系统（`d_web`，改动集中在 `web/src/app/` 的 shell/settings/cards/rooms/tree 五族 + 各自测试）；无新 wire 契约（`sub` 是页面内导航状态，`/api` 零新增）；a11y 横切面改动面广但每一处都有仓内先例（aria-modal+焦点 `Overlay.tsx`、inert+aria-hidden `WorkbenchPage.tsx:311-313`），无架构级不可逆决策；工作量显著高于流程固定成本（五族文件、桌面/compact 双形态逐字节保持、a11y 与走查测试面），不落 L1 快道。**不升 L3轻**：无跨子系统契约面、无新域、无「做错要回炉方案选型」级的脊柱风险。落点：spec 完稿后卡移 plan 列，plan 接手 §2 形态与三处归 plan 岔口（`sub` 参数名与 SettingsPage 注入统一、三层分组视觉形态、hover 五处的 compact 呈现形状）。
