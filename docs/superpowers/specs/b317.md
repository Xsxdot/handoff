## 问题陈述

B316 linux-01/agy 上 `git grep` / `git show` / `which` 等只读命令每条出工单。B249 白名单只有 `git status|diff|log`、`ls|cat|grep`、`go build|test|vet`。连接符命令故意不进白名单。

廉价审批者三次失败后停用。原文是 opencode + `kimi-for-coding-highspeed` 的 5-hour usage limit，不是代码崩、也不是执行者进程死。`approver_decision.reason` 为空，界面上看不见配额。`OneShotArgs` 不支持 `codex`，只改配置会立刻 `未知执行者`。

## 方案

白名单扩只读形态，连接符仍拒。`go run` 不进（会执行任意程序）。agy `find_by_name` 补 `SearchDirectory`。`OneShotArgs` 登记 `codex exec`（model 空=默认）。裁决失败时把 `Err` 写入 `approver_decision.reason`。linux-01 `approver.executor=codex`、`model` 空——**新二进制部署并重启后再生效**。3-strike 不改。

弃选：`go run` 进白名单；全安全段 `&&`/`||` 放行；配额不当 3-strike。

## 用户故事

1. `git grep` / `git show` / `which` / `pwd` 工作区内 AutoAllow，不建工单。
2. `git show --output=...`、`go run`、`git log || true` 仍 Consult。
3. `approver.executor: codex` 能 one-shot，不报未知执行者。
4. 裁决失败事件能看到 `exit status 1` / 配额原文。

## 测试决定

缝：`permgate.safeCommandID`（经 `Gate.Judge`）、`agy.permTextAndRequest`、`executor.OneShotArgs`、`agentd.consultApprover` 的 `approver_decision.reason`。

## 实现决定（即 plan）

1. `safeCommandID` 增加：`git grep|show|blame|cat-file|rev-parse|ls-files`（`show` 拒绝 `--output`，与 `diff` 同）、`which`/`pwd`/`head`/`tail`/`wc`。
2. `permPathFromInput` 增加 `SearchDirectory`。
3. `OneShotArgs("codex")` → `codex exec --skip-git-repo-check --ephemeral --color never --sandbox read-only --ignore-user-config`；有 model 加 `-m`；prompt 仍末位。
4. `consultApprover` 写事件时 `d.Err != nil` 且 Reason 空则用 `Err.Error()`。

## Out of Scope

- 永不做：`go run` 自动放行；`always-proceed`。
- 本期不做：连接符全安全段放行；`manage_task`/`schedule`；改 3-strike；linux-01 配置进本仓（执行机 `config.yaml`）。
