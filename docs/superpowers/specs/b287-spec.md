## 3. 方案

**①待回复（岔口已裁决，2026-08-28 用户拍板「回复即清提及类」）**
用户消息写入房间时，后端在同一发送路径上把该房间未消费的 @提及消费掉；前端发送
成功后同时刷新收件箱轮询（不再等下一轮 5s）。裁决与工单类继续计入角标、继续要求
显式处理（审批 / 答复），不受本卡影响。

弃选（记录于台账）：
- 角标只看 @提及——裁决/工单失去会话列表里最后一道提醒；
- 按消息流派生——改动面最大，三类事项全部失去提醒，且失去服务端权威聚合。

**②状态唯一化**
看板卡：删除下方标签行中的状态 chip；右上角由纯文本改为 chip（标签样式），文案 =
节点标签（保留 B279「多对一列显形」语义），无节点标签时 = 状态名。卡片抽屉头部：
合并为单枚 chip，同一规则。会话里打开的抽屉是同一组件，随之修复。

**③悬浮球错位**
会话悬浮球上移，与「+」球垂直净距 ≥ 12px，不再叠；不与错误 toast 的常驻列冲突
（细节归 plan）。

**④浮窗拖拽缩放**
照 home 浮窗的既有交互模式给会话浮窗补齐：标题栏拖动移动、右下角拖拽缩放、
最小尺寸下限、几何本机持久化（重开恢复上次位置尺寸，首次默认右下原位）。

**⑤表单对齐原型**
对齐 `settings.html` 原型的用户可见文案与布局：补 label 语义后缀（「载体名（唯一，
登记后不可改）」「模型（留空 = CLI 默认）」「并发上限（0 / 留空 = 不限）」「成员载体
（按勾选顺序解析：第一个健康且有空的载体领活）」「角色（不混编）」）；小队角色选项
显示中文「执行者队/协调者队」（提交值不变，wire 不变）；补 role hint（协调者队成员
必须落在协调机）；表单宽度与两栏栅格对齐原型（载体 480 / 小队 440）。实现保留现有
overlay 形态，不迁移原生 `<dialog>`。

3. 我把会话悬浮窗收起后，悬浮球和「+」新建球错开、互不遮挡。
4. 我可以拖着标题栏移动会话悬浮窗、拖右下角改变它的大小，下次打开还保持我的摆法。
5. 我打开编辑小队/编辑载体表单，看到的字段文案、选项和布局与原型一致。

## 5. 实现决定

- ①的收口层：后端在 collab 服务的发送路径收口（消息落房与提及消费同一事务语义），
  前端只做发送后的即时刷新；不在前端做本地过滤掩盖后端状态。
- ②的文案来源：右上角 chip 与抽屉 chip 都从既有节点标签判定派生，不新造第三种
  状态词。
- ④的交互基准：拖动把手 = 浮窗标题栏；缩放 = 右下角；几何持久化 = 本机（不跨设备
  同步）。
- ⑤的对齐基准 = `prototypes/base/pages/settings.html` 原型；与原型一致但实现更简的
  项（机器/CLI 硬编码选项）不动。

## 7. Out of Scope

- **裁决/工单类待回复的自动清除**——不做（语义裁决：显式事项显式处理，产品翻案另议）。
- **待回复角标只看 @提及 / 按消息流派生**——不做（岔口弃选，2026-08-28 用户裁决）。
- **会话浮窗迁移原生 `<dialog>`、机器/CLI 选项服务端探活**——不做（与原型视觉一致
  即可；探活方向已有 roadmap B279 段条目覆盖）。
- **浮窗几何跨设备同步、WS 长连替代轮询**——不做（本机记忆与 5s 轮询维持现状，
  要做另开卡）。
- **会话消息问题的其余面**——原问题②已由 B289（`24be42238`）修复进本基线；历史
  翻页残余归 B289 记账（roadmap 已登记），本卡不重复承担。
