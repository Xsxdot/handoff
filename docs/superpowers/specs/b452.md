# B452 熟练工派发：按名调用、只读形态、派发并等结果回文

- 状态：**r1.1 待批准**（2026-10-21 主会话出稿；r1.1 同日增补 S7 机器亲和，方向已获用户同意）

- 来源：卡 B452 note（2026-10-21 用户提出「桌面端只做沟通、规划、方案、组织、协调、审核；查逻辑、找调用方、接口测试、页面测试这类普通模型能干的活经 handoff 派发，像用子 agent 一样」）。用户裁定走「熟练工」不走裸派发：每种任务一个有名字的定义，规矩、回文格式、载体都定好，喊名字就用。
- 台账：`docs/superpowers/specs/b452-ledger.md`

## 问题陈述

谁：主会话（Claude 桌面端）作为协调者，想把机械活交给 handoff 执行器，并像用子 agent 那样拿回一段结论文本。

现状（读数，由执行节点复核）：

1. 账本里已有可复用的派发模板 `TemplateDef`：executor、target、purpose、branch_prefix、prompt、discipline、model_by_target（`internal/ledger/templates.go:16-33`），版本不可变，全队共享。但它**只能经卡调用**：`ViaTemplate` 的两个调用点都要一张卡（`internal/ledgerstep/runner.go:344`、`cmd/card_dispatch.go:406`），裸 `handoff dispatch` 从不碰模板（`cmd/dispatch.go`）。
2. 模板没有「在谁身上跑」的字段：receiver（载体/小队）只在工作流节点覆盖项 `NodeOverride` 上（`internal/ledger/types.go:211-228`）；`template put` 强制 executor/prompt/discipline 三项非空（`cmd/template.go:82`）。
3. 没有只读形态。工作区只有「分支 × 工作树」两个维度（`internal/workspace/gitworkspace.go:347-363`）：裸派发缺省**就地**切新分支（`:506-527`），模板派发总是新建工作树并开 `cards/<卡>-<purpose>` 分支（`internal/ledgerstep/dispatch.go:358,470`）。review 的「只读」只靠纪律文字约束（`internal/orchestration/manager.go:1526-1528`）。
4. 执行者的最终文本已经落账：`Result.FinalText`（`internal/executor/executor.go:82-97`，上限 16 KiB 字符）随 `completed` 事件的 `final_text` 持久化（`manager.go:3479-3487`），但**没有任何 CLI 把它打到 stdout**：`wait` 打原始事件 JSON（`cmd/wait.go:163,231-240`），`show` 打快照。
5. 裸派发请求必须发到载体所在机：`handlers.go:585-592` 对非本机载体直接 400。协调者首轮已有「按载体机转发」先例（B448，`internal/agentd/scheddrain.go:458-505`）。顺带一个缺陷：跨机小队被 `Select` 选中远端成员时同样吃 400，不会换本地成员。
6. 协议尾注 `{branch,commit,summary}` 三项任一非空即判完成（`internal/executor/turn/protocol.go:108-193`）；review-generic 模板已用「不提交，收尾行只输出 `{"summary":…}`」形态跑了三个版本。

## 方案

**熟练工 = 账本模板 + 接收者 + 形态。** 不引入新实体，在既有 `dispatch_templates` 上加两个字段，让裸 `handoff dispatch` 能按名取模板。

- `receiver`：载体名或小队名，语义与 `--receiver` 相同；空 = 本机默认载体。模板不配模型：载体自带模型，一载体一账号（用户裁定），任务级 `--model` 仍可覆盖。
- `mode`：`branch`（现状行为，缺省）或 `readonly`。
- `discipline` 在 `mode=readonly` 时允许为空：熟练工的规矩就是模板正文。

调用：`handoff dispatch --template <名字> --prompt "<本次任务>"`，或 plan 文件代替 `--prompt`。提示词 = 模板正文 + `## 本次任务` 小节（沿用 card dispatch 的分节写法，不做占位符引擎）；`{{CARD}}`、`{{TITLE}}`、`{{ACCEPT}}` 在无卡时替换为空串。

跨机：请求仍发本机 agentd；本机 agentd 解析 receiver 所在机，不是本机就把整个派发请求转发过去（B448 的转发面），小队先 `Select` 再转发。机器不可达即报错点名机器，**不换人**——换人是 B453 的调度语义。

机器亲和（r1.1）：有些活只能在调用方所在机跑（只有本机能连手机模拟器、只有本机有某个端口）。亲和写在两处：熟练工定义的 `target` 除机器名外允许特殊值 `here`（调用方所在机）；派发命令 `--here` / `--machine <名>` 覆盖定义。解析顺序是**先定机器、再在 receiver 里只看这台机上的载体**：receiver 是载体而不在这台机，或是小队而没有这台机上的在线成员，一律**硬拒绝**——专用错误文案点名机器与缺的东西、独立退出码，不静默换机。退回本会话子 agent 是主会话的决定，写进 handoff skill，不是 handoff 的行为。配置习惯：常用的几台机各登记一个载体进同一小队，熟练工指小队，`--here` 就能在任一台落地。

只读形态：在接收机以基线提交建一个 **detached 的托管工作树**，不建分支；完成后自动回收，不出 bundle；任务完成即自动归档，不停在 waiting_review。交回物是最终文本。

等结果：`handoff dispatch … --wait [--timeout]` 阻塞到任务终态，把最终文本原样打到 stdout，退出码表成败；`handoff wait <task> --final` 对已在跑的任务做同一件事。

弃选：
- **新命令 `handoff run <名字>`**：与 `dispatch --template` 同一条路径，多一个入口只多一份文档；不做。
- **模板级占位符参数引擎**：当前只需要「本次任务」一段自由文本；YAGNI。
- **只读形态就地跑在接收机主仓**：会和主仓的在跑任务互锁（`manager.go:837-846` busy guard），且主仓有未提交改动时读到的不是基线；弃。
- **CLI 自己解析设备表拨载体机**：撞 B441 残留（`--target` 只认配置 `targets:`，roadmap 933）；转发走 agentd 侧，与 B448 一致。
- **熟练工只能指定小队、不能指定载体**：小队选载体按登记顺序，不认机器，禁止指定载体并不解决本机问题；一个载体等价于一人小队，特例白加。弃。
- **载体能力标签（`ios-simulator`、`chromium`）+ 熟练工 `requires`**：更通用，但本期只需要 `here` 与机器名；记 roadmap，B454 需要时再长。
- **亲和不满足时自动换机或同步凭据到本机**：违背「只能在本机跑」的前提；拒绝即可，不搬账号。

## 落位三问

① 熟练工定义归**卡片账本**领域（既有 `dispatch_templates` 表，加字段）；任务的形态与归档节奏归**任务编排**；detached 工作树的建与收归**项目与工作区**；转发归**控制门面**（架构法第六条：跨机编排在门面收口，不进编排核心）。
② 消费者是**协调者命令面**经 **控制门面** 的 HTTP 派发接口进入；跨进程，所以派发请求的 wire 类型加 `template`、`mode`、`wait` 不进 wire（客户端行为）——按架构法第四条走契约面，plan 列「需冻结的外部承诺」。
③ 派发请求同步返回任务 id（现状）；`--wait` 是客户端对既有事件流的轮询（现状 `wait --follow` 机制）；跨机转发同步等待受理机回应（B448 同款）。

## 实现决定

1. 字段加在 `TemplateDef` 上，JSON 键 `receiver`、`mode`；`mode` 缺省 `branch`，非法值在 put 时拒绝。
2. 裸派发带 `--template` 时，`--receiver` 可覆盖模板 receiver；`--branch/--new-branch/--worktree/--new-worktree` 与 `mode=readonly` 互斥，命中即拒绝并说明。
3. 转发在控制门面收口：受理机只做「解析 receiver → 判本机 → 转发或本地创建」，编排核心不感知转发；转发后的任务归载体机，受理机返回载体机的任务 id 与机器名。
4. 只读任务完成时的自动归档走既有 `Done` 路径，`MayRecycle` 对 detached 托管工作树同样生效；`Stop` 保持现状（保留工作树）。
5. `--wait` 的超时缺省由 plan 定；超时只结束等待，任务照跑，stderr 打任务 id 供 `wait --final` 接着等。
6. 协议不改：只读熟练工的模板正文自行要求「不提交，收尾行只输出 `{"summary":…}`」，解析侧三项任一非空即完成（现状）。
7. 亲和解析在受理机（本机 agentd）做：`here` 解析为受理机自名；机器过滤发生在小队 `Select` 之前，是过滤不是排序，不引入「本机优先」的软偏好。`--here` 与 `--machine` 互斥；命令 flag 覆盖定义的 `target`。拒绝的退出码与文案是用户可见名，plan 定值并写进 handoff skill「收到即退回子 agent」。

## 测试决定

- 真实入口：`template put/show` 往返；`dispatch --template` 组装出的 `StartReq.PlanContent` 含模板正文与 `## 本次任务`；转发路径用 B448 的测试桩同款方式钉「非本机载体 → 转发、不可达 → 错误不建任务」；只读工作树用真 git 仓钉「detached、无新分支、done 后工作树不存在」；`--wait` 用事件流桩钉「只打 final_text、退出码」。
- 风险：①转发后的任务 id 归属两机，`wait` 要能跟到载体机——复用 B448 转发后「人刷新可见」的同一通道，plan 核。②`FinalTextLimit` 16 KiB 字符截断长报告，S6 的模板正文要求结论控制篇幅；更长的产物走 B454 的产物通道。③真机不得替换在役 agentd：单机只读链路在 linux-01 隔离实例上验；跨机转发在换版后的 fleet 上验（B448 同法）。

## Out of Scope

**永不做**
- 模板级参数占位符引擎、`handoff run` 别名。
- 熟练工自带模型：载体即模型与账号（用户裁定）。

**本期不做、后续要做**（已落 `docs/roadmap.md`）
- 对本机**未提交**改动做只读调查（就地只读形态）。
- 只读任务的文件产物通道（报告文件、截图、快照）→ B454。
- 载体不可达/满负荷/无额度时顺小队换人 → B453。
- Web 控制台增删改熟练工定义（本期只 CLI + JSON 文件）。
- `NodeOverride.Target` 在小队节点被忽略，与 `ledger/types.go:215-216` 注释矛盾。
- 载体能力标签与熟练工 `requires`（按「哪台机有模拟器/Chromium」调度）。
