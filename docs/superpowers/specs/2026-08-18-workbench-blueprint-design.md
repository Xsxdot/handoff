# Handoff 工作台蓝图：从派发 CLI 到自主推进的多智能体工作平台

> 状态：蓝图（方向性文档，不是单期 spec）。一期 spec 见
> [2026-08-18-workbench-phase1-design.md](2026-08-18-workbench-phase1-design.md)。
> 讨论定案日期：2026-08-18。

## 1. 愿景与问题

handoff 目前是「派发 CLI + 人肉审核回路」：backlog 是 git 里一份 100KB 的
markdown 总账，任务模型是单层的 dispatch→running→waiting_review→done，
协调者回路完全靠人（用户 + 交互主会话）驱动。

真实使用中暴露的核心问题：**人的注意力是系统里唯一没有被管理的资源。**

- 并行开 3–4 个会话时，任务状态散在各会话上下文里，唯一汇聚点是用户的脑子；
- plan 执行期长且信息量大，真正需要用户知道/重视的很少，重要内容常被淹没；
- 「做完了没看到」「忘了合并」「重复开会话把同一件事又做一遍」反复发生；
- backlog.md 多分支分叉，加行要先算 max，已到入库临界点。

目标终态：用户往系统里推一个需求或 bug，系统自主推进——写 spec、拆子任务、
派发、审阅、合并、验收——人只出现在三个位置：**审 spec、看整功能验收结论、
合 main**。中间全程可自动，也全程可人工插手。

## 2. 四层架构

所有功能落在四层上，层间有严格的依赖顺序，分期按层推进：

| 层 | 内容 | 对应分期 |
|----|------|---------|
| **L1 数据层** | 工作项图谱：backlog 条目、子任务、阻塞边、状态、工作流配置、事件流 | 一期 |
| **L2 协作层** | 评论、群聊、跨任务摘要共享、上下文文档实体化 | 二期 |
| **L3 自动化层** | 事件触发、routines、agentd 自主唤醒协调者会话 | 三期 |
| **L4 目标层** | 蓝图（goal）：一个目标挂一串工作项，规则引擎驱动自主推进 | 四期 |

**Keystone 原语**：agentd 能自主唤起「协调者角色」的会话。今天 agentd 只会唤起
executor；协调者只存在于用户面前的交互会话里。一期用「人开一个常驻主会话」作为
它的手动版（协作/无人值守两种坐姿），三期由 agentd 自己拉起，无人值守彻底闭环。

## 3. 核心概念

### 3.1 WorkItem（工作项）

新的一等实体，即现在的 B 号：标题、状态、优先级、project 归属、spec/plan 引用、
验收记录。**全局账本**（不分仓库），存于 agentd store（SQLite），唯一真相源。
spec/plan 仍是 git 里的文件，条目只存引用。后续可加 markdown 导出器做审计快照
（纯增量，不影响架构）。

- **子任务 = 子工作项**（树形 parent 指针）。
- **阻塞 = 工作项之间的有向边**。`blocked` 是由阻塞边推导出的衍生态，不是用户
  手动设置的状态。
- **现有 dispatch task 不动**：它是「一次执行」。一个工作项挂 N 次执行
  （spec 会话、plan 会话、实现派发、修复、审阅、验收各算一次），task 加可选的
  `work_item_id` 回链。工作项的完整历史第一次可被机器查询。

### 3.2 状态机：固定骨架 + 前后插入

骨架状态钉死，用户不可改名不可删除：

```
待办 → 进行中 → 待审阅 → done        （另有「终止」态收纳取消/废弃）
```

用户只能在锚点之间**插入**自定义状态（如「待合并」插在 待审阅 与 done 之间）。
插入位置本身携带语义：系统逻辑（阻塞判定看 done、自动化判「到没到审阅」）只挂
在锚点上，不认自定义名字。`blocked` 为衍生显示态，凌驾于「待办」之上。

### 3.3 工作流（Workflow）

一套命名配置：状态集合（骨架 + 插入的自定义节点）+ 转移关系 + 每个转移上可绑的
**派发模板**（executor 类型、纪律块、prompt 模板、目标机、分支策略）。工作项
创建时绑一套工作流；可按项目设默认；bug 流和 feature 流可以是两套。

**纪律块搬家**：CLAUDE.md §4 的 A 版/B 版纪律块迁入工作流配置，成为产品数据。
迁移完成后 CLAUDE.md §4 退役为指针，handoff 内配置是唯一真相。

### 3.4 节点定义三方共用

「节点」（审阅节点、合并节点等：派谁、带什么 prompt、结论怎么处理）的定义在
三种触发方式之间完全共用，只差触发者：

1. **主会话驱动**（一期主路径）：主会话按工作流配置派发、收事件、裁决、推进；
2. **看板按钮**（一期人工插手通道）：主会话不在或用户想手动干预时点按钮；
3. **事件自动触发**（三期）：agentd 规则引擎替人点按钮。

一期的手工流程就是三期自动化的排练，配置一个字不用改。

### 3.5 事件流与注意力

每个工作项有自己的 append-only 事件流（timeline）：状态转移、派发、审阅结论、
备注（「记一笔」）。**timeline 是账，群聊是播**——二期的群聊只是订阅这些事件
流做聚合广播的平面。一期由 timeline + 看板列承担「需要你」的显性化。

## 4. 推进模型（以标准例走一遍）

需求聊完 → 出一份大 spec → 拆 5 个子任务，依赖图 `1 → 2 → (3 ∥ 4) → 5`：

1. 建 5 个子工作项，挂阻塞边 2←1、3←2、4←2、5←3,4。任务 1 进「待办」，
   其余显示 blocked。
2. 主会话按工作流派发任务 1，挂一个**多路 wait**（按工作项子树聚合全部事件）。
3. 任务 1 执行完成 → 进「待审阅」→ 触发审阅节点：**默认由审阅执行者承担**
   （一次普通 dispatch，带审阅 prompt + diff，返回结构化裁决 pass/fail + 发现项）。
   主会话留给整功能验收——那需要跨子任务全局上下文，才值得动用重原语。
4. 裁决 fail → 自动对任务 1 `continue`，带发现项原文，**回合数封顶（默认 3 轮）**，
   超限自动转「等人」并在看板亮出。这是防无人看管死循环的硬安全阀。
5. 裁决 pass → 合并节点。**合并分两层**：子任务分支自动合入**功能集成分支**
   （冲突则转「等人」）；功能分支合入 **main 永远人工**——既是既有硬纪律，也是
   「忘了合并」痛点的正解：自动化把子任务全收拢，最后看板只剩一张牌等用户。
6. 任务 1 done → 主会话查阻塞图，任务 2 解除 blocked，自动派发。循环至 5 个
   全 done。
7. 整功能验收（主会话/协调者角色）→ 父工作项进「待合并」→ 用户合 main → done。

全程主会话只在出问题时出声：协调、裁决、或转人工。用户看着 = 协作模式；
用户走开 = 无人值守模式。

## 5. 安全阀（不可妥协项）

- **修复回合封顶**：审阅 fail 的自动 continue 默认 3 轮，超限转「等人」。
- **两层合并**：集成分支可自动，main 永远人工。
- **审批硬纪律不变**：破坏性/不可逆/外部可见的 permission_request 一律升级人工；
  自动化推进到「门」为止，人不在场时能推进的都推进，但不是无人监督。
- **等人锚**：任何自动化路径的失败出口都是「等人」状态 + 看板显性化，绝不静默
  吞掉或死循环。

## 6. 分期

### 一期：L1 + 看板 + 主会话驱动（spec 另出）

WorkItem/子任务/阻塞边入库；固定骨架 + 自定义插入状态；工作流配置（含派发模板
与纪律块）；Web 看板（状态分列、多项目过滤、阻塞标识、一键派发/转移）；CLI 对等
能力；多路 wait（按工作项子树聚合，现状 `wait <task>` 是单任务的，需扩展）；
每工作项极简备注流；存量迁移（未完成条目入库，历史 done 归档入库，backlog.md
冻结）。

明确不做：事件自动触发、群聊、富评论、上下文文档实体化、蓝图、自动合 main。

### 二期：L2 协作层

群聊（订阅工作项事件流的聚合广播平面）、富评论（@、线程）、跨任务摘要共享、
上下文文档实体化（类 artifacts：调研记录、决策记录挂在工作项上）。

### 三期：L3 自动化层

agentd 规则引擎（状态事件 → 自动执行节点，替人点按钮）；**keystone：agentd
自主拉起协调者会话**（无人值守彻底闭环，不再依赖用户手动开主会话）；routines
（定时触发，类 Claude Desktop routines：每晨扫账、canary 巡检入 backlog）。

### 四期：L4 蓝图（goal）

蓝图 = 一个目标挂一串工作项 + 一套推进规则。用户设目标与规则，系统在无人介入时
自主推进：前置解除 → 自动开协调会话写 spec/plan → 派发 → 审阅 → 集成 → 验收，
推进到人工门为止。人审 spec、看整功能验收、合 main，其余机器推。

## 7. 与现有纪律/资产的关系

- CLAUDE.md §4 派发决策表与纪律块：迁入工作流配置后退役为指针。
- product-backlog skill（markdown 总账操作规程）：一期迁移完成后由 CLI/看板
  取代，skill 改写为「操作 handoff 账本」的薄指引。
- handoff skill（审核者回路）：主会话驱动模型是它的结构化升级，skill 随一期
  改写，「Monitor 挂 wait --follow」升级为多路 wait。
- 派发硬纪律（探活、git push、干净工作区）：进入派发模板的前置检查，产品化。
