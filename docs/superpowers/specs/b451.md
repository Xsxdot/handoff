# B451 人工清单改走审批链（硬升级不动）

- 状态：**待批准**（r1，2026-10-21 主会话出稿）
- 级别：**L2**。只改权限判据（permgate）一个子系统的判定结果，外加审批者提示词一行；`Verdict` 形状、Consult 出口的既有路由与审批链契约都不变。plan 增量不为零（判定顺序、四处测试反转、真机清单），所以不是 L1。
- 执行形态：**甲 本地盯**（全局 CLAUDE.md §3 形态判决第 1 条）。理由：真机验收要驱动派发系统自身——派一个真任务，看它的权限请求是否经审批链裁决；上线要换在役 agentd。plan 由本会话 subagent 出稿、主会话拍板，implement 与 review 各一个 subagent，主会话验收。
- 来源：卡 B451 note（2026-10-21 用户提出）。
- 撤销记录：本卡撤销 **B383 S4**（2026-09-28 用户裁定）里「人工清单形态在判定层显式 Escalate、不许审批模型直批」这一条。新裁定（2026-10-21 用户原话）：「人工清单改走审批链（硬升级不动）」。理由：审批链实测极少拒绝；人工清单在 E21 实现轮 14 分钟里制造了 21 张人工工单。
- 台账：`docs/superpowers/specs/b451-ledger.md`

## 问题陈述

谁：在任务工作树里跑 bash 的执行者，以及替它裁决权限的全队共享审批链（B437）。

现状（读数，由执行节点复核）：

1. 权限判据有三个出口：AutoAllow（白名单）、Consult（交审批链）和 Escalate（建人工工单）（`internal/orchestration/manager.go:2083-2108`）。Consult 时，如果审批链可用，就由它逐环裁决；它判 escalate，或者整条链不可用、已停用，才建人工工单。
2. B383 S4 定了四种「人工清单」形态。判据命中后直接返回 Escalate，规则名记 `manual-gate`，完全绕过审批链（`internal/permgate/manualgate.go:48-82`，调用点 `internal/permgate/permgate.go:292-298`）：
   - `git checkout -- …` / `git restore -- …`
   - `psql -c` / `--command`
   - 内联 Python：`-c`，含簇形态 `-Sc`；以及标准输入脚本，即裸 `python3`、`python3 -`、heredoc 喂入
   - `rg --pre`
3. 人工清单的检查放在 `judgeCommand` 之前（`permgate.go:295`）。`judgeCommand` 承载自指令、黑名单、执行包装器和 `eval` 等硬升级。以前两边都返回 Escalate，先后顺序无所谓；改成 Consult 以后，顺序就承重了（见实现决定 2）。
4. 审批者拿到的是权限原文 `ev.Text`（`manager.go:2366`）。heredoc 正文只在判据内部被剥掉，审批模型仍能看到完整脚本。
5. 生产读数（E21，任务 `c01a8fb9`，linux-01）：100 个事件里有 21 次 permission_request，其中 20 次的理由都是「人工清单：内联 Python（标准输入脚本）」，全部由人在 8–12 秒内批准。另有 5 次走了 Consult，都由审批链（agy）批准。

要变的事实：人工清单形态从「直接人工」改为「先过审批链」。审批链批准就放行；审批链升级、不可用或停用，才走人工，和其他 Consult 请求完全一样。其余所有硬升级保持原样，优先级也不变。

谁能观察到：执行者不再因为这四种形态停在 `waiting_answer`。任务事件里出现 `approver_decision`，写明哪台机器、哪个执行器做的裁决。人工工单只剩审批链升级上来的那些。

## 方案

**甲（采纳）**：人工清单仍由同一个判据识别，命中后返回 Consult（规则名保留 `manual-gate`，供审计区分），不再返回 Escalate。判定顺序调成：硬升级先判，人工清单其次，白名单最后。另外，审批者提示词加一行，说明怎样审内联代码。

弃选：

- **乙：直接删掉人工清单判据**，让这四种形态落回普通链路。问题在于普通链路的末端是白名单与复合只读静默，这四种形态必须保证永不 AutoAllow；删掉判据，就失去了这道保证和审计规则名。
- **丙：只放开内联 Python，其余三种保持人工**。这不是用户的方向——用户说的是「人工清单改走审批链」，四种一起。
- **丁：只靠纪律块让执行者改用 edit 工具**，判据不动。这依赖模型自觉，并且没有兑现「全部走审批链」的目标；它作为降噪手段列入 roadmap（见 Out of Scope）。

## 落位三问

① **读写谁的权威数据**：判定结果归权限判据领域（permgate）。审批者提示词归编排领域的审批者（orchestration/approver）。两边各改自己的，不新增写入方。
② **谁消费**：Manager 的 `handlePermission` 消费判据结果，属于同进程的既有导出面，签名不变。审批者提示词只由同包的 `Decide` 使用。
③ **同步还是异步**：不变。判据同步；Consult 交审批链，沿用既有的独立 goroutine 异步裁决（`manager.go:2093-2096`）。

## 实现决定

1. **四种形态改为 Consult**：规则名仍是 `manual-gate`，理由文案从「保持人工裁决」改为「交审批链裁决」，例如「人工清单：内联 Python（标准输入脚本）可执行任意代码，交审批链裁决」。命中日志同步改词。识别形态本身一个字不改：哪些形态算人工清单，沿用 B383 的判据及其评审修订。
2. **判定顺序（承重）**：在 bash 判定里，顺序为：落点范围循环 → rm 范围内删除出口 → heredoc 闭集出口 → `judgeCommand`。`judgeCommand` 判出 Escalate 时，原样返回。然后才检查人工清单，命中即返回 Consult，并且**不再进入**安全命令白名单与复合只读静默。前三步与现状逐字一致。rm 出口要求所有段都是 cd/rm，heredoc 闭集出口要求正文只喂给裸 `cat`（`internal/permgate/heredoc.go:303-333`，读数，由执行节点复核），人工清单形态天然进不去，所以它们排在人工清单之前也不会放行这四种形态。
3. **审批者提示词加一行**，加在「生产环境」那一行之后：「权限请求含内联代码或脚本（python -c / heredoc、psql -c、rg --pre）或 git checkout/restore -- 时，读完正文再裁决：只在任务仓库内读写文件、跑测试时批准；写库、联网、改仓库外路径、读密钥的，一律升级。」这一行由主会话提出，**用户批 spec 时可删**。删掉的话，审批模型只按既有的「任务仓库内读写」原则判。
4. **不加新配置开关**：不提供「人工清单仍走人工」的回退开关。要回退，就是还原本卡的提交。

## 测试决定

- **判据层**：把 `manualgate_test` 的期望从 Escalate 改为 Consult，规则名 `manual-gate` 保持不变，覆盖 S2 全部形态。`selfcmd_test` 里「rg --pre 走人工门」那一行同步改期望。新增 S4、S5 的反例表。
- **编排层**：`permgate_wire_test` 里的「人工清单无复用腿」原本断言「不得咨询审批者」，现在反转为：审批者已启用时**必须**被咨询，批准后不建工单（S1）。审批者 escalate 和审批者不可用这两条腿要建工单（S3）。「有复用腿」保持断言不变。
- **提示词**：断言模板包含新增那一行；提示词里 nonce 出现两次、编号对齐等既有断言不动。
- **真机**（本卡由协调者执行，不派发）：在 mac-mini 起隔离 agentd，用独立数据目录、端口和测试账本，配本地审批链。派一个 opencode 任务，让它用 `python3 - <<'PY'` 改工作树内文件，再让它尝试一次 `python3 - <<'PY'` 写 `$HOME` 下的文件。期望：第一次出现 `approver_decision` approve，且无工单；第二次出现审批者 escalate 并建工单。在役 agentd 不动。
- **全量**：review 与 finish 节点跑 `go test ./...`，加上 `gofmt -l`。

## Out of Scope

- **永不做**：放宽硬升级——越界落点、自指令、黑名单包装器、`eval`、截断描述。用户原话「硬升级不动」。
- **本期不做、后续要做**（落 roadmap）：
  - 让执行者改用 edit/write 工具改文件，而不是内联 Python。本卡之后这已不再是阻塞，只是每次多一次 10–15 秒的审批链调用。可在 implement 纪律块或执行者指令里加一句。
- **不在本卡**：E21 任务当前那张待答工单由人处理。上线换版（三台 agentd）在 finish 时另请用户批准。B383 spec 加「S4 已由 B451 撤销」的指针，在 finish 的文档对齐步做。

## 备注

- 安全面的变化：heredoc 正文在判据里看不见，过去靠人工兜底；现在由审批模型读正文兜底。审批模型判断失误的风险，由用户以「审批链极少拒绝、人工往返成本过高」为由接受（2026-10-21）。
- 人工工单不会归零：审批链升级、不可用和硬升级照旧走人工。
