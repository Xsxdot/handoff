# B444 项目内新建会话：会话属项目，驻场者由 handoff 拉起（含原 E11）

- 状态：**已批准**（2026-10-19，用户：「批准 B444 spec，你亲自盯，开始做」）
- 级别：**L3**（跨 账本/协作 · agentd 唤醒与拉起 · Web 三个子系统，新增 HTTP 契约面）；**不扇出**，单卡一轮（新缝先串行长出，见「首故事」）
- 难度与分工（按全局规则「按级分工」）：**高难度**——新增跨子系统接缝（驻场者 push 驱动）与对外契约（建会话/改名 API）→ **主会话亲自盯**，不移交。人可推翻。
- 来源：本会话与人的讨论（2026-10-19）+ 卡 B444（原 erp/E11「新建一个房间，把卡拉进去，任务交给协调者，等完成」，建错项目已废弃重建）

## 问题陈述

人从项目里开一场会话、把这项目的卡拉进去、交给 agent 推进，今天做不到一步完成：

1. 会话没有项目归属。左栏按会话里的卡推算项目（现状读数 `web/src/app/rooms/sessionModel.ts:139-146`、`web/src/app/tree/ProjectTree.tsx:435-437`），新建的空会话落「其他会话」，不在人点的项目下。账本 `sessions` 表无项目列（`internal/ledger/store.go:421-424`）；唯一的项目↔会话映射是项目房间表（`store.go:443-446`，每项目恰一场）。
2. 建会话只收标题（`internal/agentd/sessionsapi.go:57-97`；Web `NewSessionDialog` 单输入框），拉卡、叫 agent 要另做多步。
3. 会话里没有「对人说话的 agent」：agent 只坐卡席位（push 由 handoff 拉起，`internal/agentd/scheddrain.go:241-330`）或项目房间驻场者（桌面会话门铃，`internal/agentd/residentwake.go`）。handoff 拉起的载体不能当驻场者（驻场身份须 `user:`/`agent:`，`internal/collab/sessions.go:221-242`；驻场地址不进 keystone，`wakeconsumer.go:350-354`）。
4. 会话不能改名（无标题更新 API/CLI）。
5. 入口：B442 加的左栏底部与移动端菜单「新建会话」与项目无关，人要求撤掉，入口改到项目上。

## 方案（已与人议定 A′）

**会话的 agent = 该会话的驻场者**，沿用 B435 统一模型，不新增角色：

| 角色 | 谁 | 收什么 | 与 B435 关系 |
|---|---|---|---|
| 会话 agent | 本会话的驻场者 | 本会话里人的无 @ 发言 | 规则不变（`internal/collab/recipients.go:88-125` 有驻场者即归驻场者） |
| 卡协调者 | 各卡席位 | `@卡号` 与卡事件 | 不变，一卡一个 |
| 组织者 | 项目房间驻场者 | 项目级通知 | 不变 |

唯一新增的组合：**驻场者可由 handoff 拉起的载体担任（push 驱动）**——与卡席位 push 同一套拉起/续轮机制，只是挂在会话驻场位上。

**弃选**：B（只给卡叫协调者、会话本身无 agent）——零卡会话无人回话、无人命名，与「发第一条消息后 agent 回话并起名」的期望不符。A（新设「会话协调者」角色）——与刚收敛的协调者模型重复，弃。

## 落位三问

① **权威数据**：会话所属项目、驻场者的驱动形态与载体落点（bearing）、会话标题——均归**协作/账本的会话领域**（`sessions` / `session_residents`）；载体选择与并发名额归**调度领域**（squad/LaunchAdmit）；拉起与续轮执行归 **keystone**。建会话一次写多领域（会话、拉卡、驻场者拉起）→ 由 **agentd 的编排单元**串起，不让 Web 逐步调。
② **谁消费**：Web 经 agentd HTTP 契约面消费（建会话扩字段、改名为新端点）；agentd 的唤醒消费循环在同进程内读驻场者驱动形态，走导出符号。
③ **同步/异步**：建会话（建行、拉卡、拉起驻场者首轮）对人是一次同步请求，首轮执行时长同卡「叫机器人」（现状同步，`coordapi.go:95-170`）；之后人发言 → 驻场者续轮走既有异步唤醒循环；命名在驻场者首轮回话内完成，Web 经既有会话列表刷新看到新标题。

## 目标架构与接缝语义（L3）

- **会话所属项目**：会话领域新增「所属项目」事实（可空，旧会话为空）。建时写入，之后不随卡变化。Web 推算位置的规则改为：**有所属项目 → 以它为主；再并上卡的项目**（并集超过一个 → 跨项目会话，与今天口径一致）。项目房间的现有映射不动（它仍是「每项目恰一场」的特例）。
- **驻场者驱动形态**：驻场者行新增驱动形态（desktop 门铃 / push 载体）与载体落点（载体、CLI 会话 id、机器、home、workdir、模型），与卡席位 bearing 同形；push 驻场者的身份记 `agent:<小队名>`（满足驻场身份 `user:`/`agent:` 约束）。唤醒消费循环对「驻场地址 + push」走 keystone 续轮（与卡席位 push 同路径），对 desktop 驻场者照旧写门铃。驻场者的交付游标沿用 `resident:<会话>/<身份>`（`internal/proto/delivery.go:34-37`），不另起。
- **建会话编排**（agentd）：校验小队 → 建会话（含所属项目、标题）→ 逐卡拉入 → 拉起驻场者首轮（LaunchAdmit + keystone launch，与卡「叫机器人」同一套拉起逻辑抽共用，不复制）→ 写驻场者行。首轮失败：会话与卡保留，会话里落系统提示，驻场位空，可重试「叫驻场者」。
- **改名**：会话领域新增改名动作，群主与本会话驻场者可调；记会话事件。
- **允许的新依赖方向**：agentd 编排 → collab（建会话/拉卡/坐驻场）、→ scheduling（LaunchAdmit）、→ keystone（launch/续轮）——均为既有方向；不新增 collab → scheduling/keystone 的依赖（驻场者 push 唤醒的执行仍在 agentd 层，collab 只存事实）。

## 首故事

**S5 驻场者 push 续轮**最先做（它是唯一的新缝，决定驻场者行要存什么、唤醒循环怎么分流）：隔离靶子上手工给一场会话坐一个 push 驻场者，人发无 @ 消息 → 驻场者续轮回话；反例 `@卡号` 不唤醒驻场者。它成立后 S1/S3/S4 的建会话编排、S7 改名、Web 入口在其上串行完成。

## 实现决定

- 入口：桌面项目行 icon（终端、文件夹之后），提示文案「在 <项目> 新建会话」；移动端项目「操作」面板一项「新建会话」。撤掉 B442 的左栏底部与工作台「⋯」入口。
- 建会话框字段与文案：标题（占位「留空则自动命名」）、卡（多选，空态「本项目没有可拉入的卡」）、驻场小队（必选，预填）。
- 自动命名规则：1 张卡 → 卡标题；多张 → 「<首张卡标题> 等 N 张」；零卡 → 「新会话」，由驻场者首轮回话时改名。
- 小队选择：本期只选**小队**（role=coordinator），不直接选单个载体——拉起名额与并发都按小队管（`scheduling.LaunchAdmit`），绕过小队选载体会绕过名额。今天只有一个协调小队时下拉只有一项。
- CLI：`handoff session create` 增 `--project`、`--card`（可多次）、`--squad`；新增 `handoff session rename`。
- 驻场者简报：push 驻场者首轮简报说明其角色（回人话、按需为卡叫协调者、零卡时首轮改名），沿用协调者简报的组织方式。

## 测试决定

- 真实入口：Web 建会话框 → agentd HTTP → 账本；隔离靶子 M（SQLite）与真载体（linux-01 opencode 免费模型）。
- 竖切：建会话（项目/卡/驻场者）一次请求的生产路径；驻场者 push 续轮穿过唤醒消费循环与 keystone。
- 序列化边界：所属项目、驻场驱动形态与 bearing 穿过 账本 ↔ collab ↔ HTTP ↔ Web 的投影，至少一条断言区分「缺失」与「空值」（旧会话无项目）。
- 反例：`@卡号` 不唤醒驻场者；卡已在别的会话被拒；无协调小队不建会话；非群主/驻场者改名被拒；旧会话位置不变。
- 原型：无已批准原型（人确认 B429 原型不在仓且未定义新建会话），形态按本 spec 文案；完成后回流 `prototypes/base/`。

## Out of Scope

- **永不做**：会话 agent 直接接管卡席位（卡协调者仍一卡一个，B435 不变）。
- **本期不做、后续要做**（落 roadmap）：①建会话时直接选单个载体（绕过小队）；②驻场者换人/换载体的 UI（今天 CLI `session stand` + 重新叫驻场者）；③会话改项目归属；④旧无项目会话的批量归属工具。

## 备注

- 「完成后喊我验收」：卡换列/needs_human 的项目房间通知只寄给项目房间驻场者（组织者）。要让主会话（与人对话的这场）收到验收请求，须把它坐为 handoff 项目房间的组织者（`handoff session sit --project handoff --as agent:<名> --desktop-session <本会话 id>`）。这是使用方式，不在本卡代码范围；批准后由人决定是否这样坐。
