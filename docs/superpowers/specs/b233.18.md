# B233.18 spec：组装上移收尾——SetupAutomation 的房间/keystone/hostapi 构造上移 cmd

## 背景

- 来源：`docs/roadmap.md`「来自 B233.17 spec」；`docs/superpowers/specs/b233.17.md` Out of Scope。
- `SetupAutomation`（`internal/agentd/server.go:931`）是 target.json 登记的组装点，但它同时在
  gateway 前台文件里构造三处域服务：房间（`collab.New` + cursor store）、hostapi
  （`hostapi.NewWithCredentialPathFor`）、keystone（`keystone.New` + `SetSessionRefResolver`）。
  B233.14/17 都把「构造上移 cmd」划出去了，本卡收掉这一条。
- 组装点纪律：assembly 免检豁免的是组装代码；server.go 同时承载运行期 handler，域服务构造
  留在里面等于让 gateway 文件继续兼职组装根。

## 目标

`cmd` 包（cmd/agentd.go 或同包 helper）成为房间 / keystone / hostapi 三处构造的唯一生产组装点；
Server 只持有并消费注入的实例。装配完成后 Server 的字段状态与改前逐字段等价（行为不变）。

## 范围

- 房间：`collab.New(facade)` 与 `SetCursorStore` 的构造上移；Server 侧把现有 `SetRooms`
  测试缝（server.go:1044）升格为生产注入缝（或新增等价 setter，沿 `SetPreview*` 先例）。
- hostapi：`hostapi.NewWithCredentialPathFor(toolchain.CredRelPathFor)` 上移。凭据相对路径表
  仍由 toolchain 唯一维护——组装点注入给 hostapi，hostapi 不得反向 import maintenance 域。
- keystone：`keystone.New(runner, narrator, facade, locator)` 与 `SetSessionRefResolver` 上移；
  其装配辅助（coordinatorRunner / coordinatorHomeSupplier / coordinatorSessionRefResolver /
  roomNarrator / attachLocator）的构造随主构造上移。辅助类型定义留在 agentd 包且被测试大量
  复用时，可导出构造函数、类型不搬家——按最小改动在 plan 定死并如实记录。
- ledger facade（`ledgerapi.New`）、automation cursor 装配、`ptyapi.New`：允许保留在
  SetupAutomation，但收口后 SetupAutomation 里不得再 new 上述三域服务；若收缩后只剩纯赋值，
  整个函数上移 cmd、agentd 包删除该方法。

## 验收

1. `go build ./...` 绿。
2. `go test -p 1 ./internal/agentd/ ./cmd/` 绿（存量红清单除外：TestRepoContractGate、
   TestLegacyNodeEventSequenceUnchanged、TestServePermissionHookDenyWithReasonAndStep0、
   agy permission 族、TestCoordinatorCancelTurnUsesSessionID、hostapi wakehome 两条——归 B233.25）。
3. 生产代码中 `collab.New(` / `keystone.New(` / `hostapi.New` 的调用点只在 cmd 包（测试调用
   逐个列出豁免）；grep 原文进收尾报告。
4. 装配语义等价：SetupAutomation 相关测试（含 `SetupAutomationForTest`）不改断言即通过。
5. 本节点该干什么一律以注入的纪律块为准。
