# B202：PTY 测试的短路径根目录该放哪

> 级别：**L2**　路由：plan → implement → review → acceptance → finish
> 状态：**已批准** —— 2026-08-23 用户授权自主推进。
> 承载卡：B202。

## 问题陈述

PTY 测试要在一个根目录下建 unix socket，这个根目录同时受三条约束挤压：

1. **路径短**：unix socket 路径有 ~104 字节上限（macOS；Linux 108）。
2. **不在任何 Go 包目录内**：否则临时目录会进 `./...` 的包枚举，全量并发跑时偶发
   撞红 `TestWindowsCrossCompiles`（B186 实测过）。
3. **在执行者沙箱内可写**：codex 的沙箱允许写工作区、**不允许写 `/tmp`**。

今天两处代码各满足其中两条、各漏一条：

| 位置 | 现状 | 满足 | 漏 |
|---|---|---|---|
| `internal/ptyhost/client_test.go#shortRoot` | `os.MkdirTemp("/tmp", "ph-")`（B186 的修法） | ①② | ③——在 codex 沙箱里整包 10 条测试全红 |
| `internal/agentd/w3a_testhelpers_test.go` | `os.MkdirTemp(".", "at-pty-")` | ①③ | ②——B186 的清洗漏了这一处 |

所以这不是「把 agentd 那处照抄 ptyhost」就完事：照抄等于把 agentd 也推进第三条的坑，
`internal/agentd` 会在 linux-01 上从绿变红。**两处需要同一个决定。**

## 现状事实（读数，由 implement 对本轮工作树复核）

| 事实 | 出处 / 取证 |
|---|---|
| ptyhost 侧已从包目录搬到 `/tmp`，注释写明了约束①② | `internal/ptyhost/client_test.go#shortRoot` |
| agentd 侧仍在包目录内建根目录 | `internal/agentd/w3a_testhelpers_test.go` 的 `os.MkdirTemp(".", "at-pty-")` |
| 全仓只剩这一处 `MkdirTemp(".")`（判据全量复扫，不是只扫触发它的那个包） | `grep -rn 'MkdirTemp("\.")' --include='*_test.go' .` |
| **linux-01 的 `/tmp` 机器层面可写**，`/` 是 `rw` 的 ext4；`TMPDIR` 未设 | 2026-08-23 协调者经 `handoff run` 实测：`touch /tmp/...` → WRITABLE |
| 因此「/tmp 只读」是 **codex 沙箱**对执行者进程的限制，不是机器属性 | 同上对照：`handoff run` 走 agentd 起 sh、不经沙箱，探到可写；而执行者在沙箱内跑 ptyhost 测试整包红 |
| **Go 的 `./...` 枚举跳过点号开头的目录** | 2026-08-23 本机最小实验：`probe/{root.go, pkga/a.go, .hidden/pkgb/b.go}` → `go list ./...` 只出 `probe`、`probe/pkga` |
| `t.TempDir()` 走 `os.TempDir()`（TMPDIR 或 `/tmp`），因此不构成第三条的退路 | Go 标准库语义 |

## 方案

### 采纳：一个共享的「短根目录」决策，两处共用；按可写性择位，够不到就显式跳过

单一 helper（两个包各有一份等价实现，或沉到一个 `internal/` 测试辅助包——形态归 plan），
按固定顺序择位：

1. **首选 `/tmp` 下的短目录**。它同时满足①②，是绝大多数环境（开发者本机、CI runner、
   `handoff run` 直跑）的最优解。
2. **`/tmp` 不可写时，退到仓库根下的点号目录**（如 `<repo-root>/.pty-test-root/`）。
   点号目录被 Go 的 `./...` 跳过，满足②；工作区在 codex 沙箱内可写，满足③。
   仓库根用 `go env GOMOD` 之类**从测试进程自己算**，不写死相对路径——测试的工作目录
   是包目录，`".."` 的层数会随包深度漂。
3. **两处都够不到、或算出的根目录会让 socket 路径超上限时，`t.Skip` 并在跳过理由里
   写明实测长度与上限**。

第 3 条是本方案的关键取舍：**宁可显式跳过，也不要让它红成一条看不懂的失败**。
今天这一族的代价就是「红了但没人知道是环境还是缺陷」——每次都要人肉分辨。
显式 skip 把环境限制变成可读的一行，而不是一族假红。

### 弃选

| 方案 | 弃选理由 |
|---|---|
| **agentd 照抄 ptyhost 的 `/tmp`** | 把 agentd 也推进第三条的坑，它在 codex 沙箱里会从绿变红。用一个正确性问题换一个环境问题 |
| **两处都退回 `t.TempDir()`** | `t.TempDir()` 走 `os.TempDir()`，在 Linux 上就是 `/tmp`，第三条一样不满足；在 macOS 上还会因 `/var/folders/…` 太长顶爆第一条——两头不讨好 |
| **只改 agentd，ptyhost 不动** | 两处约束完全相同却用两套机制，是下一次「清洗漏一处」的种子。B202 本身就是这么来的 |
| **让根目录完全由环境变量指定，不做择位** | 把负担全推给跑测试的人；CI、本机、沙箱三种环境各要配一次，忘配就红。环境变量可以作为**覆盖**保留，但不能是唯一入口 |

## 用户故事

1. 作为在 mac 本机跑全量的开发者，PTY 测试照常跑绿，且 `git status` 干净、包目录里不留临时目录。
2. 作为 codex 执行者（沙箱内、`/tmp` 不可写），`internal/ptyhost` 与 `internal/agentd`
   的 PTY 测试要么跑绿（退到仓库根点号目录），要么给出一条说明白原因的 skip，
   **不再是整包 10 条看不懂的红**。
3. 作为在很深的 worktree 里跑测试的人，如果路径注定超 socket 上限，我看到的是一条
   写明「实测 N 字节 > 上限 M」的 skip，而不是一条 socket 相关的底层报错。
4. 作为下一个改这块的人，我只需要改一处决策，不会再漏掉第二处。

## 实现决定

- 择位与 skip 判定必须**在建 socket 之前**算完，不能等 socket 创建失败再兜。
- skip 理由里带**实测路径长度与上限**，不写「路径可能太长」这种含糊话。
- 保留一个环境变量覆盖（如 `HANDOFF_PTY_TEST_ROOT`）作为逃生门，但不作为默认路径。
- 两处共用一份决策；是抽到共享测试辅助包还是各留一份带交叉引用注释的等价实现，归 plan。

## 测试决定（接缝清单）

一个缝：那个择位 helper 本身。它是纯函数式的路径决策（输入：候选位置的可写性、
仓库根、上限；输出：选中的根 or skip 理由），可以不起真 PTY 就测：

1. `/tmp` 可写 → 选 `/tmp`；
2. `/tmp` 不可写、仓库根可写 → 选仓库根下的点号目录，且该目录**不出现在 `go list ./...` 里**
   （这条断言可以用一个真实的 `go list` 子进程验，也可以退化成断言目录名以 `.` 开头——
   选哪个归 plan，但**必须有一条断言钉住「不进包枚举」这个意图**，否则下次有人改名成
   非点号目录时没有网）；
3. 两处都不可写或长度超限 → 返回 skip 理由，且理由里含实测长度与上限数字。

既有的 PTY 测试本身不新增用例——它们是这个 helper 的消费方，改对了它们照常绿。

## Out of Scope

| 不做 | 分类 |
|---|---|
| 让 codex 沙箱放行 `/tmp` | 永不做（本卡范围内）——那是执行机配置，不是仓库代码的事；且沙箱限制本身是合理的 |
| B193 族一（临时端口耗尽） | 同属「全量并发下的环境假红」，但机制完全不同，各有各的卡 |
| 把 PTY 测试改成不用 unix socket | 永不做——那是重写 ptyhost 的传输层，代价与收益完全不成比例 |
