## 定级理由

跨子系统、动契约层。要把「各家自己拼 argv / 规则路径 / skill 落点」收成提供方拥有的能力面，消费方只持契约：

- **执行**（`d_execution` 及各 adapter）：执行会话、权限翻译、RespondAsk（接 233.1）
- **协调承载**（现状 `hostapi` / `keysclient.Runner`）：仅 OpenCode 实装，本卡把该能力面从「写死 OpenCode」改为按能力声明
- **一次性调用**（现状 `executor.OneShotArgs` 厂商 switch + `agentd.Approver` 执行）：用途策略与原生能力分开
- **HOME / 规则 / skill**（现状 `coordinator_home`、`skill.Install` 路径表）：载体提期望，harness 写原生位置

选轻档：能力面是一条故事，拆成「一家一张子卡」会把共享契约面拆碎。实现一轮收口。单家工作量若在 breakdown 超过固定成本，按厂商或按能力面迁重档，不重建卡。

## 问题陈述

谁：派普通任务、拉协调者、跑审批一次性调用、准备隔离 HOME 的上层（任务编排、审批服务、载体应用）。

条件：B233.1 把 OpenCode 执行路径接到事件流 / Ask / 审批 client。其余家仍由 Manager 和各包自己拼厂商细节。协调者 HOME 复制写死 `.config/opencode`。`OneShotArgs` 把「grok 一次性 = low effort」编进 argv 映射。

通道：现有生产入口（普通派发、协调者 Launch/Resume、审批一次性、skill 安装、隔离 HOME 准备）改消费统一能力面，不新造一套用户命令。

要变的事实：现有受支持的执行、协调、一次性调用都经对应能力接口真正跑通；某家没有的能力明确报不支持，不准用更宽的原生 allow 或假实现顶上。上层不再自行拼厂商 argv 或规则/skill 路径。隔离 HOME 可准备和验证；全局规则/skills 与任务纪律叠加且互不覆盖。各迁入入口有真实 harness 证据。旧拼装路径按入口退役，不长期两套业务事实。

## 方案

### 1. 五类能力面（提供方拥有，各家实现自己支持的子集）

| 能力 | 最小意图 | 明确不承担 |
|---|---|---|
| 执行会话 | Start、Events、Send、Stop；支持则 Recover；Ask 走 233.1 的 RespondAsk | 卡状态、业务验收、选审批者、调度 |
| 协调会话 | Launch、Resume、CancelTurn；支持则 AttachInfo；问题同样 RespondAsk | 卡下一步、何时唤醒、CEO 业务权力 |
| 一次性调用 | Invoke：运行设置 + 文本 + 限制 → 文本/用量/状态；context 取消 | 把「所有一次性都必须廉价」写死进能力；解析审批 JSON |
| HOME/配置 Profile | Inspect、Prepare、Verify；指定范围的全局规则与原生配置 | 选员工、选角色、决定装哪些制度、复制谁的账号 |
| skill 管理 Skills | Inspect、Install/Update；明确授权时 Remove | 决定协调者/实现者应装哪些业务 skill |

不要求每家实现全部五类。没有的能力：可查询的能力报告 + 调用时报可行动错误，禁止静默兜底到另一家。

执行与协调若共享同一套原生会话机制，底层复用，不复制流程；生命周期或协议不同则分开实现。

### 2. 必须迁入的现有能力（不是「先两家」）

按**今天生产里已经在用的能力**迁，一家不漏：

| harness | 执行会话 | 协调会话 | 一次性 | Profile/HOME | Skills 落点 |
|---|---|---|---|---|---|
| OpenCode | 有（233.1 先切事件/Ask/审批） | 有（唯一实装） | 有 | 有（写死 OpenCode 路径，本卡收回） | 有 |
| Claude | 有 | **无** → 报不支持 | 有 | 本卡按隔离 HOME 通用准备/校验接上；不能装的原生项报不足 | 有 |
| Grok | 有 | 无 → 报不支持 | 有（low effort 是**调用方策略**，不进能力默认） | 同上 | 有 |
| Codex | 有 | 无 → 报不支持 | 有（exec/只读沙箱是 Codex 原生限制，能力报告里声明） | 同上 | 有 |
| AGY | 有 | 无 → 报不支持 | 有 | 同上 | 有 |

审批模型的一次性调用走同一 OneShot 能力，使用审批服务自己的受限配置（接 233.1），不借用被审批任务的会话。

### 3. 上层禁止再拼厂商细节

迁入完成后，任务编排 / 审批 / 协调拉起 / skill 安装这些生产入口只持有能力面。argv、原生 JSONL/SSE、权限配置语法、规则文件位置、skill 目录留在各家包。谁再在 Manager 或 keysclient 里写 `.config/opencode` 或 `switch executor` 拼 argv，就是本卡没退役干净。

跨家免审：各家只把政策快照里能精确表达的部分编译成原生规则；不能精确表达的送审批 client，**不准用更宽原生 allow 代替**（接 233.1）。

### 4. 隔离 HOME

载体提交：哪个 HOME、是否隔离、凭据来源、期望规则与 skills。  
harness Profile：检查已有环境、写入原生位置、返回实际供给/校验结果。

登记成功、文件写成、引擎能启动、满足权限要求是不同事实。失败要可恢复（能重试 Prepare/Verify，不留下半残 HOME 当成功）。

凭据按载体策略（standalone / main_home_sync）。**禁止**复制会话库或整棵 HOME。全局规则是受管环境一部分；任务纪律和临时授权走会话配置或任务目录覆盖，不得反复覆盖载体全局规则（并发两任务会互相污染）。

### 5. 与 233.1 的接缝

执行会话的 Events / Send / RespondAsk / 审批 client 以 233.1 冻结契约为准。本卡不重开交互领域，不改事件总线。OpenCode 执行路径若 233.1 已切，本卡补的是能力报告、Recover 声明、以及把它和协调/一次性/HOME/skill 收成同一提供方面。

实现顺序：233.1 契约冻结并完成执行闭环后，本卡才改生产入口；被阻塞边约束。spec 与 contract 文档可先写。

### 弃选

- **只迁 OpenCode + 第二家作证明、其余留旧路：** 用户纠正：本卡就是把所有 agent 迁过去。那是 233.1 的试点策略，不是 233.2 的范围。
- **逼每家长出协调会话：** 今天只有 OpenCode 有。假实现会把「能协调」变成谎言。
- **把 grok low effort 留在 OneShot 能力默认里：** 那是审批调用的策略，不是 grok 一次性调用的本质。
- **先搬目录再补接口。**
- **本卡做首次安装/自动发现/默认载体。**

## 用户故事

1. 本机用 OpenCode 免费模型派执行任务：走执行能力面，不经过 Manager 里的厂商 argv 拼装；Ask/审批行为与 233.1 一致。
2. 本机用 Grok 派执行任务：同样走执行能力面；一次性调用若被审批服务使用，cheap/low effort 由审批侧限制传入，不写进 grok 能力默认。
3. linux-01 上 AGY 派执行任务：走执行能力面；权限翻译不扩大快照授权。
4. linux-01 上 Codex 在限额恢复后派执行任务：走执行能力面；只读沙箱等原生限制出现在能力报告里，不假装与 OpenCode 同等。
5. 本机 Claude 派执行任务：走执行能力面。调用协调会话 → 明确不支持，不静默改走 OpenCode。
6. 拉起协调者：只通过协调能力面；OpenCode 能 Launch/Resume；其它家报不支持。隔离 HOME 由 Profile 准备，不再 copyCoordinatorRules 写死 OpenCode 目录。
7. 审批一次性调用：五家现有 OneShot 映射都改走 OneShot 能力；未知执行者仍失败并列出支持名单。
8. 同一载体并发两任务：全局规则不被任务纪律覆盖；失败的 HOME 准备能重试且不报成功。
9. skill 安装：各家落点仍按各家目录，但安装入口走 Skills 能力，不再让上层直接认路径表。

## 契约语义与接缝（L3）

1. **能力契约在提供方。** 消费方不得对同一能力二次抽象。
2. **子集合法。** 能力报告是契约的一部分；「CLI 存在」不等于「五类全支持」。
3. **免审 ⊆ 政策快照。** 跨家翻译不得放宽。
4. **HOME 期望属载体，原生写入属 harness。** 跨机由 233.3 的能力 client 选机器，本卡只定义目标机上的 Prepare/Verify。
5. **任务纪律属任务层快照。** harness 只负责放到原生位置。
6. **依赖方向：** 编排/审批/协调应用 → 能力面；各家包实现能力面；组装点绑定。禁止 adapter 直达 `permgate`/`Approver` 具体类型（除组装点）。禁止 `keysclient` / Manager 再 import 某家内部路径知识。

签名、包路径、是否把 hostapi 收进执行域，归 contract。

## 实现决定

- 真机按上表机器与限额；OpenCode 禁止付费会员模型。
- Codex 真机证据可晚于其它家，不得把限额期失败写成「Codex 不支持执行会话」。
- 可共享：进程启停、取消、事件运输、权限桥、文件原子写、受管配置更新。各家保留原生协议与目录。
- 本卡不搬 `internal/` 物理落点作为完成条件。
- 日志可记 harness 名、能力名、HOME 是否隔离、校验结果；不默认记凭据和规则全文。

## 测试决定（接缝清单）

1. **执行能力面**（接 233.1 执行契约，调用方现有 `Manager.Dispatch` / 普通派发）：OpenCode、Grok、Claude 在本机，AGY、Codex 在 linux-01（Codex 限额后），各至少一次真实执行会话跑通；不支持的能力调用失败可行动。假缝禁令：不把「接口编过」当完成。
2. **协调能力面**（存量 `keysclient.Runner`，调用方协调者拉起）：OpenCode Launch/Resume 经能力面；Claude/Grok/Codex/AGY 调用 Launch 得到不支持而非 OpenCode 兜底。
3. **OneShot 能力面**（存量 `OneShotArgs` 的生产调用方 `Approver.Decide`）：五家映射迁入后，审批一次性不再直接拼 argv；grok 的 low effort 作为调用限制传入，可被测试断言「策略在调用方」。
4. **Profile/HOME**（现状 `coordinatorHomeSupplier.Prepare`，调用方协调拉起/载体准备）：隔离 HOME 准备+校验；不复制 session db；全局规则与任务纪律两文件/两层共存；失败可重试。
5. **Skills**（存量 `skill.Install`，调用方安装入口）：各家落点仍对，但调用方不再自己列路径；一家失败不把其它家已装改成全盘失败（锁现有「单点失败继续」）。
6. **免审翻译不放宽**（执行权限桥，调用方 233.1 审批 client）：用两家不同原生权限机制（OpenCode 与 Claude 或 AGY）证明无法表达的允许条件不会变成更宽原生 allow。

变异：keysclient 再写死 OpenCode 路径 → 故事 6 转红。OneShot 把 low effort 写回 grok 默认 → 故事 2 转红。Codex 限额期红当能力缺失 → 验收误杀。

本节点该干什么一律以注入的纪律块为准。

## Out of Scope

永不做：

- 没有的能力用另一家静默顶上
- 用更宽原生 allow 代替无法映射的免审
- 复制会话库或整棵 HOME
- OpenCode 真机走付费会员模型

本期不做：

- 跨机传输收口 → B233.3
- 工作区/Git 独立能力 → B233.4
- 默认载体/小队准入 → B233.5
- 工作流接入 → B233.6
- 首次配置与自动发现 → roadmap（B233.1 已记）
- push 归属 → roadmap
- 物理目录搬迁作为完成条件 → 父卡 B233
- 给 Codex/Grok/Claude/AGY 新造协调会话产品
