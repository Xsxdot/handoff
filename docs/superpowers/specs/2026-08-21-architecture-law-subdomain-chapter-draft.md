# 架构法 · 域与子域章（草案 v0.1，待拍板）

> 分域开发套件的宪法层之一，供 breakdown / plan / implement / review 各节点 skill 引用。
> 立场一句话：**缝是法定的，层是自选的。**
> 写法约定：每条 = 法条正文 + 判据（尽量可机械检查）+ 执行机制（各语言一行）+ 例外出口（凡红线必留正当出口）。
> 零案例引用：判据数字即先例，不引任何真实项目路径。

## 总则（先于一切分条）

1. **缺省合法**：常规形态——单文件小包、entity-per-layer 的层式模块——不因本法产生任何义务。法条只管例外，不给日常开发加过路税。
2. **触发式介入，判据分两类**：「必答题」类（升格、竖切）命中后要求显式回答，答得出即合法；「违法」类（穿透他域内部、二次抽象、逐方法绕层）命中即拒。
3. **不溯及既往**：存量代码绞杀式还债——哪张卡碰到哪个家族，升格随卡走；不立专项重构。

---

## 第一条（域的资格 · 递归不变量）

任何一级的「域」——顶层域、子域、子子域——必须同时满足四条，缺一即不是域，不得按域派卡：

1. 圈得出**有界文件集**（一条路径规则写得出来）；
2. 有**可冻结的契约面**（对外导出面可枚举）；
3. 对同级域的依赖可排 **DAG**（回调用「实现→接口」边表达，call 边不成环）；
4. 有**域类型标注**：逻辑域（接缝对面是自有代码，测试可闭环）或边界域（接缝对面是外部现实，机内只验契约形状、行为走真机清单）。

同一部法在每一级适用一次。子域不满足四条时，它只是一组文件——按文件改，不按域派。

## 第二条（竖切先于横切）

层式模块（每个实体在 controller/service/dao 各持一个文件）是缺省合法形态，本条不对它产生任何义务。本条只规定**升格的方向**：当升格信号触发、一个概念需要户口时，正确动作是竖切成包——把它散在各层的文件收进一个子包，层在包内重组——而不是继续往层目录里加第 N 个前缀文件。

- **判据（层内自我分解信号，触发第三条问答）**：同一前缀家族在**同一层目录内** ≥ **3** 个非测试源文件——说明该概念已经在层内自我分解，层装不下它了。每层各一个文件的常规形态永不触发。
- 小子域允许单文件成包。层在包内按复杂度自然长出，不由模板预铺。
- **执行机制**：Go = 子包；TS = 子目录 + 唯一导出入口。

## 第三条（升格判据 · 户口法）

出现下列任一信号，拆解节点必须显式回答「该家族/该包还能圈出有界文件集吗」，答不出即先插竖切还债卡、再派功能卡：

1. 文件名前缀家族 ≥ **5** 个源文件；
2. 单包源文件 ≥ **40** 且无子包；
3. 单个可派发上下文单元 > **2~3 万行**（源码不含测试；项目实例化清单可覆盖此参数）——此时**拒发功能卡**。

命中判据不等于必须拆，但必须回答；沉默即违法。

## 第四条（契约面唯一 · 隔离三档律）

一个域对外只有一个契约面。隔离机制分三档，**能用低档表达就禁止用高档**：

| 档 | 机制 | 适用 |
|---|---|---|
| 1 | 导出符号（包边界本身） | 子域之间的缺省档 |
| 2 | interface | 存在第二实现，或对面是需要 mock 的边界域 |
| 3 | api/client + facade | 跨大域、可独立部署、跨团队边界 |

- 消费方不得对同一能力二次抽象：一个能力只在提供方声明一次契约，各消费方直接持有。
- **判据**：只有一个实现、对面又不是边界域的 interface → 降回第 1 档；子域之间出现 adapter → 违法。
- **例外出口**：为测试引入的缝属第 2 档正当用途，接口注释须注明「测试缝」。

## 第五条（规则归数据所有者）

一段业务规则只读写一个域的数据 → 写进那个域；跨域 → 归调配单元，且只许经两侧契约面。

- **判据**：某层方法体只有「取参 → 调下层 → 回传」再无语义 → 该规则不属于此层（转第七条处置）；某单元直接读写多个域的内部数据 → 它在偷业务，规则下沉。

## 第六条（调配按用例 · 禁唯一调度器）

跨子域编排按用例成单元：一条流程一个编排单元，只做三件事——调门面、定事务边界、汇聚结果。禁止把编排方法积累到单一对象上。

- **判据**（两条同时命中 = god object，先按用例拆编排、再按第五条下沉规则）：
  1. 单类型方法数 ≥ **20**；
  2. 名字说不出它拥有哪些数据（Manager / Server / App / Helper / Util 类名即嫌疑）。
- 编排单元里出现业务 if/else 分支或字段级计算 → 违反第五条。

## 第七条（透传以层论罪，不以方法论罪）

透传的判定单位是**层/对象，不是方法**。三种情形三种处置：

1. **整层透传**（该层全部方法均为纯转发：参数原样传、结果原样返、无语义增量）→ 假想层，删除整层，调用方改持下一层的契约面。删层是该域**形状的显式决定**（层自选，见第二条）：分层声明随之修订（如「本域无 service 层，编排直接持有持久门面」），从此该域内访问路径仍然唯一。
2. **个别方法透传** → 不删、不绕。它是「一个能力一条访问路径」的正当成本；**逐方法绕层**（编排层因某方法薄就直取持久层）会制造两套访问路径，违法。
3. **多数方法透传但有少数真语义** → 既不删也不绕，触发第五条检查：规则大概率被别的层偷走了（贫血的根因），先下沉规则，再回到情形 1 或 2。

- **例外出口**：横切关注（鉴权、审计、限流、错误转换）不是透传——但横切必须真实存在于方法体内，「将来会加」不算。

## 第八条（组装点唯一）

「谁绑定了谁」只存在于组装点（main / module 的 wire 代码）。组装点持有一切具体类型；其余位置只持有契约面。

- **判据**：组装点之外 new 出别的域的具体实现 → 违法。
- 组装点在目标图（target.json 的 assembly）登记，其出边豁免契约检查。

## 第九条（接口归使用方）

回调/依赖倒置的接口定义在使用方，实现归提供方。「实现→接口」边恰好落在接缝上——它就是契约冻结要冻的对象。

- **执行机制**：Go 惯例即此；TS 中接口放消费方模块并导出。

## 第十条（每级一层地图 · 穿透禁令）

任何一个上下文——一张卡、一份 plan、一次审查——最多展开一层：本级契约 + 直接子域的门面。禁止穿透两级引用他域内部。

- 这是注意力与上下文预算的结构保证：地图逐级展开，永不一次铺满。
- **执行机制**：Go = `internal/` 可见性，跨域 import 他域 internal 即编译期违法；TS = 不从子目录深路径 import，只走导出入口。

## 第十一条（嵌套上限）

域内再分域递归适用本法，嵌套上限 **3** 级。到达上限仍圈不出有界文件集 → 不是继续嵌套，是第三条的竖切没切对，回去重切。

## 附：与对照机制的关系

第一、四、八、十条可由 `graph check` 机械执行——有目标图（`codegraph/target.json`）的项目为硬闸；无图项目降级为 review 节点的人工清单（软依赖：缺图静默降档，不报错）。第二、三、六、七条是拆解与审查节点的人工判据，判据数字使其可复核。
