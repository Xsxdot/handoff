## 定级理由

跨子系统：控制门面（gateway）、任务编排（orchestration）、编制（scheduling）、工作区（workspace）、审批（approval）已经分包、生产字段已是接口，但检查器仍把处理请求的文件当「开机插线」免检，四包也没有编译期门锁，编排那条边的直闯配额还停在 321。本卡动目标图的组装名单与预算，属「动契约层」。同进程、不升 HTTP/MQ。三句收在「检查器看见什么、编译器拦什么」这一条结构缝上，一轮可收口 → **L3 轻档**。不把全仓按最优图重排、不把 keystone/房间/hostapi 的构造再搬一次。

覆盖入口预判：卡标题已是这三句。按定稿范围维持 L3 轻档——判据是跨域 + 动 `target.json`，不是「只改名单所以像 L1」。

## 问题陈述

谁：agentd 还是一个进程。HTTP 前台要把一次请求交给后厨（编排 / 编制 / 工作区 / 审批）；开机时要把后厨插到前台。

条件（功能线 `686d87abf`）：

1. **处理请求的代码在免检名单里。** 目标图 `assembly` 登记了整份 `internal/agentd/server.go`（约 3000 行，含 21 个 `handle*`）和整份 `codegraph.go`（两个只读 handler）。组装点的出边不算跨域直调。开机插线（`cmd/agentd.go` 里 `New` 再注入）免检是对的；用户点了 Done 这种运行中的请求也免检，是错的。12–16 已经把字段改成接口，但检查器还在当没看见。
2. **后厨没有门锁。** `internal/orchestration`、`internal/scheduling`、`internal/workspace`、`internal/approval` 都是普通包。谁都能 `import` 进去拿具体类型。接口是约定，不是锁。仓库里也还没有 `internal/<子系统>/internal/` 这种嵌套目录。
3. **直闯配额还按旧房子。** `d_gateway → d_orchestration` 配额 321，是 Manager 和 HTTP 写在同一个文件里留下的数字。B233.15 把 git 搬走之后，五条边已经超配额（工作区相关），一直没人改配额、也没把不该直连的改成走门面。B233.13 的编排 client 在图里还报 dead-interface（视图没吸进去）。

通道：现有 HTTP/WS 与 `cmd` 启动。不新造跨机协议、端点、命令、事件。

要变的事实：

1. **处理请求的函数不再住在免检文件里。** 免检只留给开机插线：构造、`Set*` 注入、路由表把 URL 接到函数名、`SetupAutomation` 里仍合法的装配。`codegraph.go` 整文件都是 handler，退出名单。
2. **四个已迁出的房间加上编译期门锁。** 实现细节进 `internal/<包>/internal/`；公开包只留构造、给前台用的类型和错误哨兵。`cmd` 只从公开包 `New` 再注入。gateway 生产文件 import 嵌套路径 → 编译失败。
3. **已经有门面的方向，直闯配额降到 0。** 超了的直连先改走门面，不许把配额调大来抹绿。图如果仍把调用画到实现方法上，名单里保留实现容器（与 B233.14 的 `scheduling.Service` 同形），不许靠删容器假绿。

谁能观察到：派发、Done、工作区、审批的行为、文案、HTTP 路径不变。维护者能观察到：`go build` 在 handler 里 import 后厨里间会失败；`codegraph check` 对这几条有门面的边不再用 321 这种旧配额放行。用户（CLI/浏览器）观察不到包名和名单。

## 方案

三句都做（用户 2026-09-12「都做」）。同进程，不升 HTTP/MQ，不改可观察行为。

**1. 处理请求的代码退出免检**

免检名单只覆盖「谁绑定了谁」（架构法第八条）。`handle*` 的定义离开当前登记为 assembly 的文件。`Handler()` 里「URL → 函数名」的登记是前台自己的接线，留下。`NewServer` / `Set*` / `SetupAutomation` 留下。`codegraph.go` 退出名单。`cmd/agentd.go` 与 `main.go` 不动。

`server.go` 若瘦成只剩插线，**可以仍留在名单里**——要免检的是插线，不是文件名。整文件删出名单、却把 `SetManager` 留在里面，插线会被当成违规直调。

**2. 四包编译期门锁**

只封 B233 已经迁出的：`orchestration`、`scheduling`、`workspace`、`approval`。公开包：构造、DTO、错误哨兵、实现消费方接口所必需的导出。炒菜进嵌套 `internal/`。`cmd` 只 import 公开包。gateway 生产不得 import 嵌套路径，也不得再 import 具体 `*Manager` / 里间类型去绕过接口。

DTO 与错误哨兵留在公开包（B233.14：编制包的 `Binding` / `ErrInvalid` 前台可以 import 类型，字段必须是接口）。

**3. 配额降到门面**

本卡只动 12–16 交出来的边：

- `d_gateway → d_orchestration`：321 → 0；接口已在。图若仍画到 `*Manager` 方法，entries 保留实现容器（14 同形）。
- B233.15 留下的工作区超配额：不该直连的改走具名能力 / `Capability`；该直连的（公开能力、词表 `proto`）写成 entries，配额按门面口径，**只降不抬**。
- B233.16 点名的 `d_policy` / `d_maintenance → d_transport`：逐条看是否含执行面消费点，有则收口，没有则注明「本卡核实、不动数字」。
- B233.13 absorb 拒收留下的 OrchestrationClient dead-interface：本卡视图补符号，让棘轮后的检查器看见接口。
- B233.16 守卫扫描的包级漏判：修扫描，不让白名单函数后面的包级聚合漏过去。

超配额的直调先改走门面。**不许抬配额把红灯抹掉。**

## 契约语义与接缝

**允许的依赖方向变更**（语义，数字与条目归 contract 落地）：

- 组装名单：只保留开机插线文件；handler 定义所在文件不在名单上。
- `d_gateway → d_orchestration`：配额 0；接口 `OrchestrationClient`；需要时 entries 保留实现容器。
- 工作区相关超限边：按门面口径只降不抬；`d_workspace → d_protocol` 是词表直引，允许保留 entries，配额不得高于真实门面边。
- `d_policy` / `d_maintenance → d_transport`：复核，不预写数字。
- **禁止**：新开顶层域；新开跨机协议；抬任何本卡方向的配额；把 keystone/房间/hostapi 的构造算进本卡必做。

**语义规则**：

1. 免检只覆盖绑定（谁 `New`、谁 `Set`、路由表把 URL 接到已有函数）。请求处理不是绑定。
2. 行为跨缝走已经存在的使用方接口或具名能力；类型跨缝走词表包（`proto`）直引。实现细节不出现在别的子系统的 import 里。
3. 配额棘轮：有门面的方向直调预算为 0。删 entries 但图仍落到实现方法 = 假棘轮（B233.14 先例）。
4. 迁移是结构闸：错误哨兵、文案、超时、HTTP 路径、事件类型不变。
5. 公开包导出面由 contract 核验与本节语义边界一致，核不上退回 spec，不许落地时顺手改缝。

**接缝（符号 + 调用方）**：

1. **免检名单不再覆盖 handler 定义** — 调用方是 `codegraph check`（机械）与本仓守卫测试。存量：`codegraph/target.json` 的 `assembly`；`internal/agentd/server.go#Server.handleDispatch`（及同文件其余 `handle*`）；`internal/agentd/codegraph.go#Server.handleProjectCodegraph`。最高结构缝。
2. **四包里间对 gateway 生产不可见** — 调用方是 `go build ./internal/agentd`（生产文件）。存量公开构造：`internal/orchestration/manager.go#NewManager`、`internal/scheduling/scheduling.go#New`、`internal/workspace/capability_impl.go#NewCapability`、`internal/approval/client.go#NewClient`。变异：handler 文件加上嵌套 `internal/` 的 import，必须无法编译。
3. **有门面方向直闯配额为 0** — 调用方是 `codegraph check`。存量：`d_gateway → d_orchestration` 的 `OrchestrationClient`；工作区超限边；B233.16 点名的传输边复核。变异：非免检文件增加一条对编排实现的直调，check 必须红。

假缝禁令：纯把函数挪到另一个文件名、不改变「是否免检」——不占接缝名额（那是手段）。包内白盒测试随搬迁不占名额。B233.16 守卫漏判是缝 3 的锁，不另开第四条缝。

## 实现决定

- 命令名、HTTP 路径、事件类型、日志字段名不变。
- 免检文件可以仍叫 `server.go`，只要里面不再定义 `handle*`。新文件名归 plan，本节点不写死。
- 四包公开包保留 `New`；`cmd/agentd.go` 继续只碰公开包。嵌套目录的内部名字归 contract/plan。
- 目标图本卡改：`assembly` 名单、上列方向的配额与 entries、本分支视图补 OrchestrationClient 等本卡符号。
- `SetupAutomation` 里 `collab.New` / `keystone.New` / `hostapi.New…` 留下，不搬。
- 全仓 `internal/` 按 `best.json` 重排不在本卡。
- B233.16 `executionSurfaceViolations` 的函数名跨函数不重置：本卡随守卫收口修掉。

## 测试决定

1. **handler 不在免检文件**（缝 1）：守卫读 `target.json` 的 assembly 与源码，断言这些文件里没有 `func (s *Server) handle`。变异：把一个 `handle*` 搬回 assembly 文件，测试必须红。`codegraph check` 在本卡视图下，handler 对后厨的调用不再被整文件豁免。
2. **里间不可 import**（缝 2）：守卫断言 gateway 生产 `.go`（非测试）不 import `internal/{orchestration,scheduling,workspace,approval}/internal/`。变异：加一条这样的 import，测试或 `go build` 必须红。`cmd` 经公开 `New` 的组装测试保持绿。
3. **配额到门面**（缝 3）：本卡方向 `legacyBudget` 为 0（或 contract 核过的词表 entries + 0 直调）；`codegraph check` 对这些方向不超配额。变异：非免检文件直调编排实现，check 必须红。B233.16 守卫漏判：包级聚合写在白名单函数之后必须红。
4. **行为不回退**：`TestB23313ConcurrentDoneReleasesOnce`、B233.12 AutoAllow 钩子、B233.14 空 HOME×纪律、工作区既有 HTTP 级测试保持绿。
