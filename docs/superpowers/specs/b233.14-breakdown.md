### P3｜非空 `~` 前缀 HOME 的 overlay 落点：本卡顺带修正，还是冻结现状

实测（台账 §3 探针 A/B）：
- 现状 `prepareTaskProfile`（`internal/orchestration/manager.go:1073-1077`）把 `Task.HomeDir` **原样**放进 `ProfileReq.HomeDir`；非空值 `"~/.handoff/home/muse"` 时 `ProfileReq.HomeDir` 原样为相对串（探针 A 原始输出：`ProfileReq.HomeDir="~/.handoff/home/muse" Isolated=true`）。
- 五家 `Profile.Prepare` 用 `filepath.Join(req.HomeDir, ".handoff","task-overlay", …)` 落盘（`opencode/profile.go:125-138` 等），对 `~…` 得**相对路径**（探针 B：`IsAbs=false`），于是 overlay 落在 `<cwd>/~/.handoff/...`——正是 `expandCarrierHome`（`manager.go:1120-1124`，注释记录 2026-09-04 实测 2.2G 垃圾目录）在环境变量 `HOME=` 上已修的同一个坑，只是 overlay 路径没走该助手。
- contract 同时写了 §2.3「`taskProfileHome`：非空则 `expandCarrierHome` 展开 `~` 前缀后返回」与 §5.2 #18「`Task.HomeDir` 非空时写入点 = `Task.HomeDir`、Isolated=true（**现状不回退**）」。**两者对 `~` 前缀 HOME 相互矛盾**：按 §2.3 实现即改变现状（修正为绝对路径），按 #18 字面则冻结现状（相对路径缺陷留存）。
两选一：
- **方案 A（推荐）｜按 §2.3 实现：非空 HOME 的写入点也过 `expandCarrierHome`。** 空 HOME 展开主 HOME、非空 `~` 前缀展开为绝对路径，二者统一为「写入点恒绝对」；`ProfileReq.HomeDir` 因此对非空 tilde HOME 由相对变绝对。优点：修正既有相对路径缺陷，且契约 §2.3 与 #14/#18 口径统一（写入点是**落盘点**，不是身份快照）；`Task.HomeDir` 仍存原值（#15 不受影响）。代价：非空 tilde HOME 的行为有可观察变化（overlay 从 cwd 移位到主 HOME），须回写 #18 措辞并在验收里锁绝对路径。
- **方案 B｜只把空 HOME 分支接上 `taskProfileHome`，非空分支保持原样透传（冻结相对路径缺陷）。** 优点：字面满足 #18「现状不回退」，改动面最小。代价：`taskProfileHome` 冻结签名（contract §2.3）本要求非空走 `expandCarrierHome`，B 与冻结签名冲突；且把已知 2.2G 级坑留在非空路径。
- **推荐 A。请拍板。** 无论 A/B，contract §5.2 #18 与 §2.3 的措辞必须对齐（见 §2.3 C-1）。

### P4｜空 HOME×纪律的写入点在 `ProfileReq` 与日志中的呈现（`Isolated=false` 已冻结，仅确认）

contract #14 已冻结空 HOME 分支 `Isolated=false`、`ProfileReq.HomeDir` 为主 HOME 绝对路径。此条**无第二做法**，列此只为把「`Isolated` 语义 = 是否隔离 HOME（空 HOME 沿用主 HOME，故 false）」与「写入点是否绝对」两件事分开——避免实现节点把「展开的绝对路径」误当成「隔离 HOME」而把 `Isolated` 置 true。**建议直接按 #14 落实，不另裁决**；若协调者认为需在 contract 明写一行语义，随本节点回写。

### P5｜是否把门面/组装与空 HOME 拆成两张 handoff 子卡并行

两项工作物理独立：W1（`d_gateway` 持门面 + `d_cli` 组装迁移）体量大（57 测试消费点、11 装配文件），W2（`d_orchestration` 空 HOME×纪律）体量小且行为独立。两选一：
- **方案 A（推荐）｜单卡 `B233.14-impl` 收口。** 与 B233.13/B233.16 的 L3 轻档先例一致；contract §9「直通竖切：L3 轻档不做」；两项共享同一批编译门与图对账，拆卡的协同成本高于收益（两张卡都要动 `server.go` 与 `cmd/agentd.go` 的测试装配）。
- **方案 B｜拆 `B233.14-impl-w1`（门面）/ `w2`（空 HOME）两子卡。** W2 可先独立落地并先出红绿。代价：引入子卡编号（与「本卡禁嵌套子卡 B233.14.x」的 spec 不冲突但偏离轻档先例）；两卡都要改测试装配，需协调依赖。
- **推荐 A。请拍板。** 若裁 B，依赖方向 W2 无前置、W1 无前置，二者可并行；但同一 `Manager`/`Server` 文件并改需协调者指定合并序。

- **假红 / 假绿测试**：源码扫描守卫（不含 `scheduling.New`）有假绿风险（扫注释、扫 `_test.go`），须跳过注释与测试文件并配**可变红**守卫（人为插入非白名单用法 → 红）。接口测试须用**只为接口实现 18 方法**的 fake 注入，不得只断言类型存在；`Scheduling()` 返回接口后，测试若仍打具体 `*Service` 会掩盖「生产字段是否真为接口」——必须有一条**经 `Server` 字段**的断言。装配测试不得用 `Server{scheduling: ...}` 字面量绕过 `SetScheduling` 语义来验证接口化。

## §6 真机清单（未验证，需协调者执行）

凡结论依赖**行为事实**（真实 harness 落盘、真实 HOME 环境）而非可 grep 的 API 事实，均列此：

1. **空 HOME 载体 + 非空纪律的真机启动（承重）**：在目标机登记 `HomeDir=""` 的载体，派发一个带非空纪律的任务，确认：任务能起、纪律在任务级可见（overlay 落 `<主HOME>/.handoff/task-overlay/<task>/discipline.md`）、`<主HOME>/.config/<harness>/AGENTS.md` 与 skills 树未被改写、`Task.HomeDir` 仍空。五家 harness 各抽一家或全跑。
2. **非空 `~` 前缀 HOME 的 overlay 落点（P3 裁 A 时）**：登记 `~/.handoff/home/<name>` 载体 + 非空纪律，确认真实 overlay 落在展开后的绝对主 HOME 下、**未**在 agentd 工作目录下建出 `./~/.handoff/...`。本节点机内已证现状透传相对串（台账 §3），真机确认端到端行为。
3. **主 HOME 不可得的拒派**：以无法解析用户主目录的环境启动 agentd（或注入失败源），确认派发空 HOME + 非空纪律时任务落 `failed` 且报文可行动，无静默吞纪律。
4. **跨平台矩阵**：Linux/macOS/Windows 执行机各启动一次并完成一轮空 HOME 带纪律派发；一个平台绿不得推广为全平台结论。
5. **真实 agentd 重启后编制服务重建**：重启后 `SetKnownMachines` 经 `Conf()` 读活配置的行为保持（控制台改机器清单不必重启）；此条机内已有 schedapi 用例，真机做一次端到端确认。
6. **基线存量红（非本卡引入，待协调者归档）**：本节点跑到的以下存量红不在本卡验收范围内（以协调者对账为准）：`internal/agentd` 与 `cmd` 的既有基线红需在实现节点复跑时逐条区分（本节点本轮只跑了定向绿，未全量跑 agentd/cmd 以省时）。
