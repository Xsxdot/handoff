## 问题陈述

会话房间用传输层临时脸（`cli:<user>@<host>`、`web:<host>`）同时干：证明你是谁、决定能不能说话、决定 @ 叫谁、记录谁干的。一张脸漂了，四件事全错位。本卡定义「人是谁」：权力与 @ 只认固定人名；端只做落款；解析失败拒收；卡进群后协调者必须在场可 @。

承重歧义（已消除）：控制台点发送的人与命令行侧身份，是一个人还是两个人？——一人多名端（见决定）。一端已读是否另一端也已读？——按人合并（见决定）。

## 冻结决定（2026-09-17；含群内改口径）

1. **一名多端**：进门（写权限）、@ 路由、成员名单只认人名；每条发言附带端戳，**只用于落款显示**，不参与权力判定、不参与 @、不参与已读。
2. **已读按人合并**：一端已读＝此人各端都已读。端不拆红点。（作废「分端已读」旧口径）
3. **人的固定名**：用户指定全局名，各机器配同一个。`user:sycm`（2026-09-17 批准）。配置键 `console_user`（2026-09-17 批准）。**端戳来源＝本次登录会话登记的设备名**（`handoff console --device`／桌面壳登记 + 浏览器名；不设配置）——换设备换端，"我"始终是同一个人；端戳缺失不拦门（少的是落款，不是权力）。
4. **主 agent 名＝启动身份**：外部 CLI 自建会话/进成员 → 成员名 `agent:<启动身份>`（它自己出示；自选、会话内唯一），缺则 fail-closed。**不查执行器词表**——handoff 认不认识它的执行器只决定投递方式，不决定身份合法性（未接执行器的 harness——command code、pi 之类——照常可进）。一个会话一个主 agent 实例、只在一台机器上、无跨会话记忆（实例即身份）。
5. **卡进群 → 协调者跟进（首卡必含；判为现状已成立）**：拉卡进群后，协调者必须在成员里、可 @、能回话。**实现按既有派生**：协调者＝该卡当前席位，席位成员随卡出入群自动进成员投影（`SessionMember{Kind: seat}`）、自动进写者集（`sessionWriters`＝显式成员 ∪ 卡席位）、`@卡号` 由寻址解析到当前席位；**席位不落成员表**（成员表只放人与主 agent；写入会随换绑留脏行）。本卡对这条的工作＝验收回归，不是新增写入；若验收发现派生缺失，按缺陷修。不另开拉人入口、不另造特权说话旁路。
6. **owner 保持现状**：owner＝创建者＝升级终点；与本卡正交，不扩展拉人/说话特权。
7. **不搬家**：老会话原样不动；经 B366「以当前身份加入会话」点一次加入；已读按新人名自然重建。不写搬家工具。
8. **解析失败 fail-closed**：认不出人名（未配名／CLI 未出示身份）→ 拒绝 + 可行动报错；**禁止旧脸回落**。拒绝理由只有「没出示／配不出身份」这一种——不得以「执行器不在支持清单」拒绝；端戳缺失不属于失败。

## 本卡不做（另开 / 非本卡）

- **拉权对称**（群内任一成员可拉新人、群主零审批）：另开子卡；本卡不落地新拉人政策 op。另开时**须与 B366 自助加入保持两条语义**——自助加入（成员恒取服务端解析身份、body identity 被忽略）是决定 7 老屋恢复路径，不许被拉人语义吞掉。
- **handoff 拉起的会话级主 agent（拉起 + @ 唤醒绑定）**：另开子卡（用户拍板"先只跑通外部自理"）。本卡只保证外部自理这条：它自己建会话、自己 `session wait` 订阅、自己发言；@ 到它时 handoff 不叫醒，订阅从流尾起、不补历史。
- **成员说话权对称**作为独立政策：不做。协调者能说话＝已是成员 + VerifyWriter，不是对称专项。
- 搬家工具：永不做。
- 第二人类（陌生人）模型：永不做。

## 方案（含弃选）

- 采用：人名收口 + 端只落款 + 已读按人 + 卡进群协调者跟进（派生）。
- 弃选：一端一名；分端已读；旧脸回落；半新半旧键并行判定；为协调者单写成员行／特权说话旁路；名字锚在执行器词表上；本卡落地「群内任意拉人」。

## 用户故事

- U1 配好全局人名后，控制台发言落款为人名+端，不是 `web:主机`。
- U2 多端同配置：@ 人名，各端都响；一端标已读，各端红点都清。
- U3 故意不配名／CLI 无身份 → 发不出，报错写清缺什么。
- U4 agent 从外部 CLI 建会话（或以启动身份进成员）→ 成员名 `agent:<启动身份>`，可 @、能说话；缺则拒收。
- U5 外部主 agent 自理：自己订阅（`session wait`）、自己发言；@ 到它＝它自己的订阅收到（流尾起、不补历史）；handoff 不负责叫醒（另卡）。
- U6 拉卡进群 → 协调者自动在成员里，可 @、能回话；无需另点「拉协调者」。
- U7 老屋经 B366 点一次加入能说话；无迁移动作。

## 契约语义与接缝（L3：定语义，不定签名）

**干净切法（架构师，2026-09-17）**

- 身份解析**只在 agentd 一处**：`transport 事实 → 人名`（缺则拒）。控制台取配置名、端戳取登录会话设备名；CLI/主 agent 取启动身份（自报）；端戳只附发言。
- VerifyWriter：只认成员集里的**人名键**；发话路径先解析再过它；禁止路径里再写 `web:`／`cli:` 分支。
- 已读游标：键＝人名；旧键（旧 `web:`／`cli:` 脸）随解析改造自然弃用——游标是纯缓存非权威（`internal/collab/cursor/cursor.go` 包注释：重启丢失无害、开房自愈），无迁移与共存义务；禁止半新半旧并行判定。
- 协调者跟进：走既有派生（席位随卡出入群进出成员投影与写者集），不写成员表、不走新拉人 op。
- 投递：@ 到外部主 agent＝事件订阅（`session wait --follow`），handoff 不唤醒；订阅流尾起、不补历史。

测试接缝（符号 + 调用方；签名归 contract）：

1. agentd 身份解析（新建：transport→人名+端；调用方 sessions/rooms 各端点）——一名多端 + fail-closed 收口。
2. collab 写者判定（存量 `VerifyWriter`／`sessionWriters`，调用方 room send 路径）——人名键执法；含卡席位派生（协调者能说话）。
3. 游标换键（存量符号 contract 钉；调用方 readmodel/cursors）——已读按人（键＝人名）。
4. 控制台身份读缝（新建：返回本请求人名+端名；调用方 控制台会话页／新建会话表单）——owner 预填、落款显示、缺名可行动提示的数据来源（今天 status 无身份字段）。
5. CLI 出示主 agent 身份（新建：`agent:<启动身份>` 的出示路径；调用方外部 harness 的 session create/wait/send）——今天 `--cli/--session` 只产席位串 `cli:<cli>#<session_id>`，而写权是字符串等值，`agent:*` 成员因此发不出话。

## 实现决定（决策级）

- 用户可见名：`user:sycm`（2026-09-17 批准）、`agent:<启动身份>`（自选、会话内唯一，不锚载体词表）；落款含人名+端名（形态 plan 定）。
- 配置键：`console_user`（2026-09-17 批准）；端戳＝本次登录会话登记的设备名（不设配置）。
- 控制台：配名后发言／@／已读按上列语义；缺名拒收（可行动报错）。新建会话表单只有标题（owner 不再手输，服务端按解析出的人名落——决定 6）。
- CLI：以启动身份进成员集并出示 `agent:<启动身份>`（出示方式 contract 定）；本卡**不**新增「拉人」命令。
- 拉卡进群：协调者按派生自动在成员里、可 @（不写成员表）。

## Out of Scope

- 拉权对称与新拉人 op：另卡（另开时保持 B366 自助加入语义不变）。
- handoff 拉起的会话级主 agent 的拉起与 @ 唤醒绑定（身份→机器/执行器/实例）：另卡（本卡只跑通外部自理）。
- 搬家工具：永不做。
- 登录/鉴权体系改 ticket：不动。
- 端名自定义：不做。
- CLI 人裸发言：用户不用命令行当人说话；须出示身份走既有语义（与 agent 启动身份说话无冲突）。
