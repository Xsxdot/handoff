# B358.9 会话身份本质重做：成员对称、一名多端、拉权对称

- 父卡：B358（B358.8 走查暴露本质缺失：控制台无稳定身份，一切补丁都绕"用户是谁"转）
- 级别：**L3（重档）**——跨 collab 会员/写者语义、agentd 接入身份解析、控制台会话面、CLI 会话面四个契约面；既有端点的 actor 语义属 wire 相邻，按动契约层计。档位 breakdown 可纠。
- 状态：**待用户批准**（批准后回写本行并交棒 contract）
- 基线：B358.9 分支切出点（contract 节点执行 merge-base 核对并记录 pin）

## 问题陈述

会话房间用传输层临时脸（`cli:<user>@<host>`、`web:<host>`）同时干四件事：证明你是谁、决定你能不能说话、决定 @ 叫谁、记录谁干的。一张脸漂了，四件事全错位。过去所有修复（owner 记忆预填、候选过滤、建后自动补员）都在没定义"用户是谁"的前提下绕行，是补丁。本卡一次性定义清楚。

承重歧义（已消除）：控制台点发送的人与命令行发消息的身份，是一个人还是两个人？——一人多端（见决定 4）。

## 冻结决定（2026-09-17 用户逐条拍板；9 条）

1. **成员对称**：人、主 agent、卡的协调者，全是平等的群成员，说话权一样。谁创建只是谁先动手（顺序），不附带特权。
2. **拉权对称**：群里任何成员都能把新身份拉进群；群主无审批特权。
3. **人的固定名**：用户直接指定一个全局名，各机器配同一个。不搞默认规则。拟定 `user:sycm`（待批准）。
4. **一名多端**：进门（写权限）、@ 路由、名单只认人名；每条发言/已读附带端戳，只用于落款显示与分端记状态，不参与权力判定。@ 人名则其所有端都响，各端已读各算各的。
5. **主 agent 名 = 载体名**：`agent:<载体名>`（如 `agent:opencode`）。载体每次由用户显选，不存在认不出的问题；换载体即换名，历史按名归属。
6. **卡协调者自动跟进**：卡被拉进群那一刻，其协调者自动成为群成员（可见、可 @、能说话），不另点。
7. **owner 保持现状**（协调者推导，未单独拍板，待批）：owner = 创建者，仍是升级终点（escalation sink）。与成员对称正交：owner 无额外说话权、无拉人特权（拉权人人有）。含义见契约语义 owner 行。
8. **不搬家**：老会话原样不动；每间老屋经 B366「以当前身份加入会话」一键点最后一次加入（人走控制台）；已读按新名自然重建——游标是进度水位、只读推进，不改写成员与事件，与"不碰历史账"一致。不写搬家工具。
9. **解析失败 fail-closed**：认不出人名（控制台未配名、CLI 未声明载体）→ 拒绝 + 可行动报错（缺什么说什么）；不用旧脸回落。

## 方案（含弃选与理由）

- 采用：一名多端（决定 4）。权力与名字归人，落款与已读归端；记法规矩本身不改（B358.4 拍板①是 owner 取统一记法，本卡类推到全体成员名）。
- 弃选：一端一名（`user:sycm@macbook` 式）。@ 时要选端、名单臃肿、且需改统一记法规矩，得不偿失。
- 采用：主 agent 名跟载体（决定 5）。
- 弃选：`agent:main` 角色名。用户每次显选载体，"换引擎认不出"的前提不存在；跟载体走更贴用户心智（"我选载体把它拉起来"）。
- 采用：不搬家（决定 8）。
- 弃选：搬家工具。改历史账风险高，老屋是少数，成熟路径（点一次加入）成本极低。

## 用户故事

- U1 我建群拉主 agent：控制台新建（owner 自动预填=我，仅输标题）→ 经控制台拉人入口选载体拉 agent → agent 能说话；成员区见 `agent:<载体>`；@ 它它响。
- U2 agent 建群拉我：agent 建群（owner=`agent:<载体>`，创建即成员）→ 经 CLI 拉人命令写入 `user:sycm`（以 `agent:<载体>` 身份执行；拉入即成员）→ 我打开就能说话，零点击（新模型无 B366 一键环节）；@ 我全端响。
- U3 卡协调者跟进：拉卡进群（拉卡权限保持现状，与拉人权正交）→ 协调者以席位身份自动成成员（只能以席位说话，别无他形）→ 可 @、能说话、落款含人名+端名（示例，形态 plan 定、acceptance 真机核）。
- U4 多端：多端并存使用（无"在线状态"含义）→ 一端已读不影响另一端（各端游标）；落款分得清哪端发的；@ 我各端都响。
- U5 老屋：一间老会话经 B366 一键点最后一次加入后可说话；各端红点重看一圈即清；无任何迁移动作。
- U6 拉权：群内任一成员（控制台拉人入口 / CLI 拉人命令，以出示方当时身份执行）可拉新身份；被拉即成员，无需确认。

## 契约语义与接缝（L3：只定语义，不定签名）

- 收口层：成员/写者判定在 collab 层唯一收口；传输身份→人名+端的解析在 agentd 接入层收口；控制台/CLI 只传递通道事实（哪端、哪载体），人名永不自报（通道事实纪律沿 roomsapi 服务端注入门禁，B358.4/B366）。
- 依赖方向：web/CLI → agentd 身份解析 → collab 成员集；不新增反向依赖。
- 数据语义：发言带人名+端戳；已读游标与 @ 消费按（人，端）记；@ 人按人扇出到其各端。
- 身份映射（语义级）：控制台通道→配置人名（缺配置即决定 9）；CLI 主 agent→其声明的载体（载体由调用方声明，方式 contract 定；未声明即决定 9）；卡席位→席位自身（稳定，无需映射）；未知端不拦门（端只影响落款/游标，不影响权力——决定 4），端来源 contract 定。
- 失败语义（决定 9）：解析不出人名→拒绝 + 可行动报错；不用旧脸回落。
- owner 语义冻结：创建者=owner=升级终点，不扩展。

测试接缝清单（符号 + 调用方；新建符号只声明调用方与导出层，签名归 contract）：

1. collab 写者判定（存量符号 `VerifyWriter`/`sessionWriters`，调用方 room send 路径；出处以 contract 复核时工作树为准）——成员对称的最终执法点。
2. agentd 身份解析（新建：transport→人名+端；调用方 sessions 各端点；导出到 agentd 接入层）——一名多端的收口；映射与失败语义见上。
3. 拉人 op（新建：成员集合写入；调用方 CLI 拉人命令 + 控制台拉人入口 + 拉卡自动跟进；导出到会话域 collab 会员语义面）——拉权对称的收口。
4. 游标/消费重键（存量符号待 contract 钉；调用方 readmodel/cursors；新（人，端）键与老成员名键共存：老键冻结只读——不搬家，新键写入）——多端已读独立的落点。

## 实现决定（决策级落点；内部符号与路径归 contract/plan）

- 用户可见名：`user:sycm`（拟定待批）、`agent:<载体名>`；落款含人名+端名（示例，形态 plan 定、acceptance 真机核）。
- 配置键：人名指定键（非拍板的新增命名，拟 `console_user`，待批）；端名来源拟机器名（contract 定，不设配置）。
- 控制台新建会话 owner 自动预填=我（仅输标题）；建后免加入（创建即成员——现状 `Members=[owner]`（`internal/ledger/sessions.go:50-53`）语义不变）。
- CLI 新增拉人命令（名待定，contract 定）；agent 建群后拉我走该命令。
- 控制台新增拉人入口（形态 plan 定）。

## Out of Scope（必写；无拍板的条目标注待批）

- 搬家工具：永不做（决定 8）。
- 登录/鉴权体系（非拍板的新增说明，待批）：ticket 制不动；身份≠登录态。
- 新人范围（非拍板的新增说明，待批）：新人指本用户名下的人/agent/协调者身份；第二人类（陌生人）模型永不做。
- CLI 人发言（非拍板的新增说明，待批）：用户不用命令行说话；裸 CLI 人发言恒 403（须出示席位走既有席位语义），与决定 2/U2 无冲突（那是 agent 身份说话）。
- 端名自定义（非拍板的新增说明，待批）：不做。
