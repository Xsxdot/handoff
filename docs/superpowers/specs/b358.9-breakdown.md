### 3.1 S1（d_gateway）：会话/房间端点换脸 + fail-closed + 端戳 + owner 缺省

**② 意图与为什么**：把 Ticket 0 已落、但只有测试单点保护的 `resolveConsoleIdentity` 接进**所有**会话/房间端点，退役 `roomUserActor()="web:"+hostOnly` 旧脸；发话时把登录会话设备名装进 `RoomMessage.Device`（只落款）；缺名 fail-closed（绝不回落旧脸）；建会话 owner 缺省为解析人名。**这是 spec 决定 1/3/6/8 的核心行为，空壳不具备。**

**③ 验收（行为化，边界型——机内验契约形状，真实端归真机）**：

1. `go build ./...` 退出 0；`go test ./internal/agentd/ -count=1` 全量绿（换脸后的既有夹具同步）。
2. **配名路径**（`ConsoleUser="sycm"`）：
   - `POST /api/rooms/session:N/messages` → 账本 `actor=="user:sycm"`（非 `web:`），且该消息 `payload.device == 该登录会话 DeviceName`（cookie 路径；条 17）。

## 5. 缺陷族对抗审查（通用五族 + 追加设问，逐族正面回答）

**族 1 生命周期 / 状态机中断**
- S1/S4 是请求内解析与纯渲染；S2 是纯投影；S3 是一次性进程。**无新增后台 goroutine、临时目录、工单或锁**，中途重启无残留。
- 游标键换名（`web:`→`user:<name>`）在 `room-cursors.json` 留下旧键孤儿：**纯缓存非权威**（`cursor.go:1-5` 包注释：重启丢失无害、开房自愈），无迁移/共存义务（契约 §3.7）。无回收责任、无孤儿资源。
- 结论：**无风险，因为**本卡不新增任何生命周期对象；旧缓存键的「不回收」是有意冻结的语义。

**族 2 静默失败 / 误导报错**
- **最高危**：未配名时若某写面漏判 `Configured`，直接用 `Member==""` 调 `Send`/`AddSessionMember`，会被 `VerifyWriter` 以 `ErrNotWriter`（403「非成员」）或 Store 的「身份不能为空」误报——**报错说错原因**（解法完全不同）。堵法：S1 每个写面**显式判 `Configured`** 并给含 `console_user` 的文案；验收含「未配名 ≠ 非成员」反例。
- `handleSessionsList`/`handleRoomsList` 未配名行为（P-2）：若降级放行会静默报「未读 0」；本稿推荐同门拒收。
- S1 换脸若留 `web:` 回落，既有测试仍绿而 fail-closed 承诺死（族 4 温床）——须独立断言。
- S4 `fetchIdentity` 失败/非 2xx 必须渲染可行动错误态；`configured=false` 是提示不是崩溃；fixture 缺 `device` 键 ≠ `device:""`。
- 结论：每条有明确堵口，逐条入 S1/S4 验收栏。

**族 3 跨平台假设**
- 无新增路径/进程组/权限模型/webview API 假设；端戳入库前已 `sanitizeDeviceName`（`authroutes.go:67`），读侧不再加工。Windows/macOS/Linux 差异只落在真实浏览器渲染（真机）。
- 结论：**无，因为**改动是身份字符串与 HTTP wire，纯 Go/TS，无平台专属面。

**族 4 假红 / 假绿测试**
- 温床 1：`roomUserActor` 保留 `web:` 回落 → 既有 `webUserMember` 测试全绿、fail-closed 死。堵：未配名端点反例 + 源码零 `web:` 回落审查。
- 温床 2：`sessionMembers` kind 修正若无 `agent:` 成员断言 → 改回 `cli:` 分支不会红。堵：双向 kind 断言。
- 温床 3：`isSelfActor` 改判据后若测试数据仍用 `web:` → 改与不改都绿。堵：反例断言 `web:` 不再判自方。
- 温床 4：device 落款若只测 fixture 不经真实 handler → 落账路径无测试。堵：一条 handler→账本 payload 断言 + Go/TS 共用同一 `RoomsFixture.json`。
- 「两端各自有测试」≠「链路有测试」：Go 金样本与 TS 孪生同源 JSON，改键漏一处即红。
- 既有夹具换脸后，断言锁的是**产品行为**（actor 是人名、未配名拒收），换实现不改需求不会无意义红。
- 结论：逐条有能变红的反例；无「一句话无风险」带过项。
