## 2. 冻结后的精确形状

### 2.1 编制 client 接口（gateway 侧，使用方）

接口定义在 gateway 包（架构法第九条：接口归使用方）；实现是 `internal/scheduling` 的 `*Service`（不迁包）。Ticket 0 已落可编译空壳：`internal/agentd/scheduling_client.go`。

```go
type SchedulingClient interface {
	DefaultCarrier() (string, error)
	Carrier(name string) (scheduling.Carrier, error)
	Squad(name string) (scheduling.Squad, error)

	AdmitCarrier(name string) (scheduling.Binding, error)
	Admit(req scheduling.IgnitionRequest) (scheduling.Binding, error)
	AdmitFrozen(binding scheduling.Binding) (scheduling.Binding, error)
```

- `SetupAutomation`（gateway）不再 `scheduling.New`；账本门面 `ledgerapi.New`、rooms、hostapi、keystone 装配照旧。

### 2.3 空 HOME × 非空纪律（行为缝）

删除 `prepareTaskProfile` 的「无 HomeDir 则拒绝非空纪律」门。精确语义：

- 纪律 `TrimSpace` 为空 → 跳过 overlay（现状不变）。
- 纪律非空且 `Task.HomeDir` 非空 → 现有路径不变（`HomeDir=Task.HomeDir`，`Isolated=true`）。
- 纪律非空且 `Task.HomeDir` 为空 → 计算**写入点** = 该 agentd 的主 HOME（`os.UserHomeDir()`，失败则拒派并带原错误）；`ProfileReq.HomeDir` = 写入点、`Isolated=false`；overlay 落在 `<主HOME>/.handoff/task-overlay/<taskID>/discipline.md`（`TaskOverlay`，非 `Rules`/`Skills`）。
- **`Task.HomeDir` 保持空串**，永不回写；不把空 HOME 改写成绝对路径写进 `Task` 身份快照（B347）。
- **不写载体全局规则**：`prepareTaskProfile` 只设置 `TaskOverlay`，`Rules`/`Skills` 恒空 → 不触碰 `<home>/.config/<harness>/AGENTS.md` 或 skills 树。

写入点提取为具名助手（签名冻结）：`func taskProfileHome(taskHome string) (string, error)`——非空则 `expandCarrierHome` 展开 `~` 前缀后返回；空则 `os.UserHomeDir()`；主 HOME 不可得时返回错误。

## 4. 依赖库既成行为（契约的一部分）

空 HOME × 纪律的行为依赖以下**库默认行为**，逐条读源码钉死：

1. **五个 harness 的 `Profile.Prepare` 都拒绝空 `HomeDir`**：`internal/executor/opencode/profile.go:77`、`claudecode/profile.go:77`、`codex/profile.go:77`、`grok/profile.go:77`、`agy/profile.go:77`，均 `if req.HomeDir == "" { return rep, errors.New("Profile.Prepare 缺少 HomeDir") }`。因此空 HOME 分支必须先算出非空写入点，不能把空串直接传给 `Prepare`。
2. **overlay 落点在写入点之下**：`Profile.Prepare` 把 `TaskOverlay` 写到 `filepath.Join(req.HomeDir, ".handoff", "task-overlay", Clean(o.Name))`（opencode/profile.go:126-138；其余四家同形）。文件名含 `..` 即拒绝（`:128`）。
3. **overlay 与载体全局规则分离**：`Rules` 写 `<home>/<RulesRelFile>`、`Skills` 写 `<home>/<SkillsRelDir>`，仅当 `req.Rules`/`req.Skills` 非空（opencode/profile.go:88-123）。`prepareTaskProfile` 只填 `TaskOverlay` → 载体全局规则与 skills 树不被本次 overlay 触碰。
4. **`expandCarrierHome` 对空串是 no-op**：`internal/orchestration/manager.go:1125` 只在 `homeDir == "~"`/`~/`/`~\` 前缀时展开；空串原样返回。故空 HOME 分支不能复用它兜底，必须显式 `os.UserHomeDir()`。
5. **`IdentityOf` 空 HOME 是合法身份值**：`internal/scheduling/receiver.go#IdentityOf` `:148` 原样保留 `c.HomeDir`；`BindPhysical` 空 HOME 与请求显式空串相等即通过（`:161`）。显式空串覆盖非空身份必须拒绝（`receiver_test.go:215`），本卡不改这条规则。
6. **`normalizeCoordinatorSpec` 空 HOME 展开为 `~` 再展开主 HOME**（`internal/agentd/coordinator_home.go:242-256`，B347 已冻）：本卡不改协调者路径，空 HOME 的协调者语义沿用。

## 5. 原子冻结清单

每条可独立判 pass/fail，失败可定位。骨架期无实现的条目标「实现期判据」，本节点不宣称已通过。

### 5.1 接口边界与持有（缝 1）

1. `SchedulingClient` 定义在 gateway 包（使用方），方法集恰为 §1 表 18 个方法的闭包：不新增生产未调用的能力（尤其不含 `SetDefaultCarrier`/`SetKnownMachines`），不遗漏任一生产调用。
2. `SchedulingClient` 方法签名与 §1 表中 `*Service` 现有签名逐字一致（参数/返回类型、命名返回 `PopReady`）。
3. `Server` 生产字段类型是 `SchedulingClient`，不再是 `*scheduling.Service`。
4. `SetScheduling` 注入参数类型是 `SchedulingClient`，方法名保留。
5. gateway 生产源文件中不再出现 `scheduling.New`（`go vet`/编译期源码断言均可判）；`scheduling.New` 只出现在 `cmd` 组装点。
6. `SetupAutomation` 不构造 `*scheduling.Service`；账本门面/rooms/keystone 装配不变。
7. `Server.SchedulingRegistry()` 返回 `schedclient.Registry` 适配；`cmd/agentd.go#setupLedger` 用它构造 `*scheduling.Service` 并 `SetScheduling`。
8. `SetKnownMachines` 闭包经 `Server.Conf()` 读活配置，保留控制台改机器清单不必重启 agentd 的行为。
9. `facadeAsRegistry` 与 `translateRegistryErr` 仍留 gateway，签名与翻译链不变。
10. 编译期断言 `var _ SchedulingClient = (*scheduling.Service)(nil)` 存在；把任一声明方法改名/改签名即编译失败。
11. `Scheduling()` 返回 `SchedulingClient`（测试缝）；生产代码不消费它。
12. 生产字段可赋只实现 `SchedulingClient` 的 fake（不需要具体 `*Service`）。

### 5.2 空 HOME × 非空纪律（缝 2）

13. `Task.HomeDir` 为空、`Discipline` 非空时，`prepareTaskProfile` 成功（不再返回「无法准备非空纪律 Profile overlay」）。
14. 该情形下传给 `Profile.Prepare` 的 `ProfileReq.HomeDir` 是该机主 HOME 的绝对路径（非空、`filepath.IsAbs`），`Isolated=false`。
15. 该情形下 `Task.HomeDir` 仍为空串（未被写入自 `manager.go` 派发路径或 overlay 路径）。
16. 该情形下 overlay 只出现在 `TaskOverlay`；`ProfileReq.Rules`/`Skills` 恒空，载体全局规则/skills 文件不被写。
17. 纪律 `TrimSpace` 为空时仍跳过 `Profile.Prepare`（现状不回退）。
18. `Task.HomeDir` 非空时写入点 = `Task.HomeDir`、`Isolated=true`（现状不回退）。
19. 主 HOME 不可得时拒派并返回带 task/executor 上下文的错误，任务落 `failed`（不得静默吞纪律）。
20. 变异：把「空 HOME 直接 return error」加回，针对 #13 的测试必须红。
