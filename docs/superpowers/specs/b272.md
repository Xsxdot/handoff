## 定级理由

本卡要新增一条「把文件字节写到某台机器 `$HOME/.handoff/drop/`」的跨进程能力：控制台消费它，本机 agentd 在 `?machine=` 时原样搬到对端，对端 agentd 落盘并回报写成的绝对路径。这是新 wire，不是既有 `PUT /api/workspaces/file` 的延伸（那条只改工作树里已存在的文本、拒二进制、1 MiB）。跨 `d_web` + `d_gateway`，类型进 `d_protocol`，故 L3。工作是一条竖切，不值得扇出子卡，轻档；轻档仍走契约冻结。

不是 L2：前端自己把文件经 PTY 灌进 shell（`cat >file`）会污染终端、撑不住 32 MiB 二进制，且绕开 agentd 落盘。不是 L1：plan 写出来不会只复述本页（唯一名、转发体上限、同机/跨机分流都是实现步骤）。

## 问题陈述

谁：在本机（桌面壳或浏览器）操作控制台的人。
条件：把本机文件或图片拖到一台**文件并不在其上**的机器的终端。
通道：HTML5 `File` 内容 → 本页 origin 的 agentd →（若终端挂了登记机器则 `?machine=` 转发）→ PTY 所在 agentd 写盘。
要变的事实：对端 `$HOME/.handoff/drop/` 里出现该文件（同名不覆盖）；终端命令行被插入写成的绝对路径（带 shell 引号，尾随空格），和本机终端拖文件插路径的手感一致。
谁能观察到：对端 `ls ~/.handoff/drop/` 看得到文件；终端输入区看得到**对端回报的**那条路径，没有本机访达路径。

现状（2026-09-04 读数）：桌面壳原生拖放只把本机绝对路径 `term.input` 进终端（`web/src/app/lib/desktopFileDrop.ts`、`web/src/app/workbench/TerminalTab.tsx`）；WKWebView 能拿到 `File` 内容但没有路径。远程终端因此插的是对端不存在的本机路径。工作树写入接不住二进制/新文件。本机→远端 HTTP 转发体上限 1 MiB（`internal/agentd/forward.go` `forwardBodyLimit`）；通用 `forwardTo` 用 `LimitReader` **截断体、不拒绝**（同文件）。PTY 不跟踪后续 `cd`。B300 剪贴板复制已拆走，不并入本卡。

## 方案

跨机拖放改为**传文件**：内容落到 PTY 所在机器的 `$HOME/.handoff/drop/`，成功后再把实际绝对路径敲进该终端。本机桌面壳 + 本机终端保持今天的「插入访达真实路径」，不拷贝。PTY 里无论是不是 TUI（grok/opencode），成功后都插路径，与本机一致；不检测、不改走任务对话页。

判定「跨机」看**文件所在电脑 ≠ PTY 所在电脑**。下面三条 **按 1→2→3 先命中先用**，不可并行解释：

1. 终端 `machine` 非空 → PTY 在该登记机上 → 传到那台（本机 agentd 转发）。**不论 origin 是否 loopback。**
2. 第 1 条未命中，且页面 origin 不是 loopback（host 不是 `127.0.0.1` / `localhost` / `::1` / `[::1]`）→ 当前 agentd 就是远端 → 传到 origin，不带 `machine`。
3. 其余（本机 UI + 本机终端）→ 桌面壳走原生路径插入；浏览器没有路径，维持现状（不传、不插）。

收件箱固定在 `$HOME/.handoff/drop/`，不跟 shell cwd、不跟工作树、不跟自定义 `DataDir`。只写 basename；同名则 `photo.png` → `photo-2.png` → `photo-3.png`。单文件 **未编码内容** 32 MiB，超过或失败都不插路径，并给出可见错误。从松手到写完之间能看出「正在传」。目录及非普通文件可见拒绝：不落盘、不插路径，不得当成空文件成功。

### 弃选

- **落到 shell cwd / 工作树**：否。用户明确会污染工作区、弄脏 `git status`。
- **覆盖同名文件**：否。用户要保留上次拖进去的东西。
- **单文件 1 MiB（复用现成转发上限）**：否。卡点名了图片，截图/照片经常超过 1 MiB。
- **只认 `machine` 非空**：否。浏览器直连远端 agentd 时 `machine` 为空，文件却在笔记本上——用户要这条也传。
- **经 PTY 灌 `cat`/`base64`**：否。污染终端、二进制与体积都不稳，且绕开落盘契约。
- **复用 `PUT /api/workspaces/file`**：否。只改已存在文本、拒二进制、要哈希前置条件。
- **桌面壳读盘再上传**：否。薄壳不承载业务、不读用户磁盘（ADR-0009）。跨机传文件走页面里已经能拿到的 `File` 内容。

## 用户故事

1. 作为用户，我在桌面壳打开远程机器的终端，把一张本机截图拖进去：对端 `~/.handoff/drop/` 里出现该文件，命令行插入它的绝对路径，我能立刻当参数用。
2. 作为用户，我再拖一个同名文件：对端写成 `photo-2.png`，插入的是这个新路径，旧文件还在。
3. 作为用户，我用浏览器直接打开远端 agentd，从笔记本把文件拖进那里的终端：文件同样出现在那台机器的 `~/.handoff/drop/`，并插入路径。
4. 作为用户，我在桌面壳把文件拖进**本机**终端：行为与今天相同，插入访达真实路径，不拷贝。
5. 作为用户，我拖一个超过 32 MiB 的文件：看到失败提示，命令行不变。
6. 作为用户，我一次拖多个文件：每个独立传、独立插路径；其中一个失败不影响已经成功的。
7. 作为用户，我拖一个文件夹进去：看到拒绝，命令行不变，收件箱不出现空文件。

## 契约语义与接缝

规则归 **PTY 所在那台机器上、拥有 drop 目录的导出符号**：只有它碰那台机器的磁盘、决定改名与上限。本机门面在跨登记机时只搬运字节，不落盘、不改名、不做唯一名。不新增依赖方向（控制台 → 门面 HTTP → 既有 `?machine=` 转发）。精确路径、请求字段、状态码归 contract。

**落盘**

1. 目录是该进程用户的 `$HOME/.handoff/drop/`（`os.UserHomeDir`，不是 `DataDir`）。不存在则创建。取不到 HOME 则整次拒绝，不回退到 cwd。
2. 只接受单层文件名。任何含路径分隔或 `..` 的名字，先取 basename；取完仍不合法则整次拒绝。
3. 目标名：从**被拖文件的 basename** 起找空位。原名未被占用则用之；否则在扩展名前加 `-2`、`-3`…（无扩展名加在末尾；`.env` 这类点开头、没有第二个点的，整个 basename 当 stem）。已有 `photo-2.png` 再拖 `photo-2.png` → `photo-2-2.png`，不并进 `photo.png` 家族。
4. 上限按 **未编码文件字节** 计 32 MiB。传输编码不得把一份合法内容挤出上限。超过则整次拒绝，禁止把超限体截断后当成功。
5. 写入是完整成功或整次失败：成功前对用户不可见（临时文件点开头，不算占用、不能当成品）。失败、客户端断开、agentd 重启，都不得留下可当成品的目标名；失败即删临时文件。崩溃残留的点开头临时文件不算占用，不阻塞下次同名写入。
6. 成功回报**实际写成的绝对路径**（已解析 `HOME`，不是 `~` 字面量）。调用方拿它去插终端。
7. 本期不列目录、不删。不覆盖：创建必须在「未被占用」上成立（占用则改后缀重试）；不得先看见空位再写成别人刚占用的名字。
8. 目录与非普通文件：拒绝，不落盘。

**搬运**

9. 终端 `machine` 非空时，本机门面把该能力的请求转到那台机器，**不论 origin 是否 loopback**。这条请求必须把 ≤32 MiB 的未编码内容完整交到对端缝 1；**其它转发路径仍 1 MiB**，不得为了本卡抬全球上限。本能力超限必须拒绝，不得走通用 `forwardTo` 那种截断体当已转发。
10. 仅当第 9 条未命中且 origin 非 loopback 时，请求打在 origin 上，不带 `machine`。
11. 鉴权与其它控制台 API 相同。控制台会话能力上等价于主令牌（W4 已定），本卡不另开权限模型。

**终端侧**

12. 跨机：传成功才 `term.input` 插 `shellQuote(绝对路径) + 空格`，并 focus；与本机原生拖放同一套引号规则（现状 `desktopFileDrop.ts` `shellQuote`）。插入的必须是对端回报的路径。
13. 同机桌面：不调用本能力，仍走原生路径通道。
14. 跨机桌面：原生 `handlePlatformFileDrop` 的 `accept` **不得**再插本机路径（只走上传）。同一手势不得既插本机路径又上传。
15. 失败、超限、目录/非普通文件：不插路径，可见错误。进行中可见「正在传」。

**接缝（每条符号 + 调用方）**

- 缝 1（新建符号，在 drop 目录的所有者侧导出，**不是**门面层、**不**并入工作树 `WriteFile`）：「按规则写入 `$HOME/.handoff/drop/`，回报绝对路径」。调用方：该能力的 HTTP 处理函数。钉：合法 basename 落盘、同名加后缀、路径逃逸拒、>32 MiB 拒且无半截成品、缺目录则创建、并发抢名不覆盖、目录/非普通文件拒。
- 缝 2（边界型）：该能力的 HTTP 请求/响应，含 `?machine=` 转发。调用方：控制台上传。钉：本机直写与转发两条都能把 ≤32 MiB **未编码字节**完整交到缝 1（到达字节与拖入文件一致）；超限整次拒绝、不得截断当成功；其它 API 转发仍 1 MiB；金样本钉成功时响应里有实际绝对路径。
- 缝 3：`TerminalTab` 的拖放分流。调用方：`web/src/app/shell/Shell.tsx` 工作台 `renderContent` 与 HomeDock `renderTab` 两处挂载。钉：跨机走缝 2 成功后插入对端回报的引号路径；跨机桌面原生 `accept` 不插路径；同机桌面不走缝 2、仍插入原生路径；失败/目录不插入。

假缝：后缀数字的纯函数若抽出，只作缝 1 的内部锁，不占接缝名额。检测 loopback 的小函数同理，从缝 3 走过去。

## 实现决定

1. 远程传文件用 HTML5 `File`（桌面壳 WKWebView 与系统浏览器同一条）。原生 `handlePlatformFileDrop` 只服务同机桌面终端。
2. 一次拖入的多个文件在同一台目标机上**串行**落盘；跨手势/跨标签的抢名靠落盘 7 的不可覆盖创建，不靠「只有一次拖入会串行」。
3. 进行中状态不挡终端输入；成功后消失并插路径。
4. 本机浏览器 + 本机终端：不在本卡补路径插入。
5. 不经 PTY 写文件，不往工作树写，不改 OSC/剪贴板。

## 测试决定（接缝清单）

1. 缝 1：表驱动——新文件、同名加 `-2`、已有 `photo-2.png` 再写 `photo-2.png` → `photo-2-2.png`、`.env` stem、basename 逃逸、刚好 32 MiB、超过 32 MiB 无半截成品、缺目录则创建、并发/抢名不覆盖、目录拒。走导出符号，不测未导出 helper。
2. 缝 2：本机 handler + `?machine=` 转发各一条 ≤32 MiB **字节 roundtrip** 成功、一条超限拒绝（不得截断成功）；一条既有转发 API 仍按 1 MiB。金样本含成功路径字段。
3. 缝 3：jsdom 下跨机 drop 调上传并 `term.input` 对端路径；跨机桌面原生 `accept` 不 `term.input`；同机桌面 drop 不调上传、走原生 accept；上传失败与目录均无 `input`、有错误。分流覆盖：`machine` 非空（含非 loopback origin）走转发；`machine` 空 + 非 loopback 走 origin；`machine` 空 + loopback 走同机。

真机（acceptance）：桌面壳拖图片到登记远程机终端 → 对端 `ls` 看得到、命令行插入**对端回报的绝对路径**（可与 `ls` 对上）且**没有**本机访达路径、对端 checksum 与源文件一致；同名再拖一次是 `-2`；本机终端拖文件仍是访达路径且远端 drop 目录不新增；>32 MiB 与拖目录失败可见。浏览器直连远端 agentd 再拖一次。

## Out of Scope

- **永不做：** 把拖入文件写进项目工作树或当前 cwd（污染工作区正是本卡要避开的）。
- **本期不做、后续要做：** 收件箱自动清理（含崩溃残留的点开头临时文件）；拖入目录的递归上传；剪贴板粘贴图片到远程终端；本机浏览器对本机终端的拖放（没有文件系统路径）。
- **本期不做：** 改本机桌面「插真实路径」的既有行为；经 PTY 传文件；列出/删除 drop 目录的 UI；为其它转发 API 抬体上限。
