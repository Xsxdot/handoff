## 1. 背景与问题

### 1.1 两个状态源的死结：URL 与 mobileTab/mobileDetail 各说各话

紧凑视口的移动内容面由三块 React 状态驱动：`mobileTab`（底栏当前页，`web/src/app/shell/Shell.tsx:135`）、`mobileDetail`（是否处于工作台下钻态，`Shell.tsx:139`）、`fileDrawer`（目录覆盖层，`Shell.tsx:159`）。它们是 `useState`，从不与 URL 同步；而 URL 一侧的整页路由（`/cards`、`/flows`、`/settings`、`/codegraph`）全部被 `!compact` 门控（`Shell.tsx:967-985`），`fullPageRoute` 在紧凑视口恒假（`Shell.tsx:537`）。结果是紧凑视口里 URL 改了没有任何消费者：

1. **会话→卡身份（审计原文复现）**：会话顶部「⋯」→ 会话详情抽屉「会话卡」行（`web/src/app/rooms/SessionDetail.tsx:36-46`，`data-testid="session-card-row"`）→ `onOpenCard` → `Shell.tsx:955` `navigate('/cards?card=<id>')`。紧凑视口下 `/cards` 路由未注册（`Shell.tsx:967`）、`mobileTab` 仍是 `'sessions'`、`CardsPage` 只在 `mobileTab==='cards'` 时挂载（`Shell.tsx:1015`）——URL 变成 `/cards?card=B369`，界面停在会话。
2. **直达深链死**：紧凑视口初次加载 `/cards?card=<id>`，`mobileTab` 落默认值 `'sessions'`（`Shell.tsx:135`），URL 不驱动任何渲染，深链不可达。
3. **意图与行为的文档漂移**：`Shell.tsx:534-536` 注释声称「移动下 /cards?card=X 这类深链……由 S9 的 CardsPage 覆盖层消费 query」——`CardsPage` 确实消费 `card` 参数开抽屉（`web/src/app/cards/CardsPage.tsx:107`、`:213-216`），但那只在该组件已被挂载时成立；没有任何机制从 URL 把 `mobileTab` 切到 `'cards'`。注释描述的是意图，不是行为。

### 1.2 返回语义缺失：任务现场回不到来源

卡详情到任务现场的两条出口在紧凑视口**行为通、语义断**：

- 出口一：卡抽屉「关联执行」行的 ↗（`web/src/app/cards/CardDrawer.tsx:866-880` → `CardsPage.jumpToTask`，`CardsPage.tsx:254-257` → `/tasks/:id`）。该路由无条件注册（`Shell.tsx:987`），`TaskDeepLink` → `openTaskTui`（`Shell.tsx:588-601`）→ `openMobileDetail` 进下钻态开 TUI tab——能到现场。但 ① `TaskDeepLink` 最后 `navigate('/', { replace: true })`（`Shell.tsx:1259`），任务现场期间 URL 是 `/`，无状态；② 返回条只会 `setMobileDetail(false)`（`Shell.tsx:1044-1048`），回到底栏当前 tab 的**首页**——下钻期间 mobile-home 整层卸载（`Shell.tsx:993`），`CardsPage` 与卡抽屉的选中态随之丢失，回不到「来源卡」；从会话侧进入的同样回不到「来源会话」。
- 出口二：卡抽屉协调者面板「打开终端」（`CardDrawer.tsx:643` → `web/src/app/cards/CoordinatorPanel.tsx:147` → `Shell.openCoordinatorTerminal`，`Shell.tsx:150-154`）。该回调 compact-aware，但同样不带来源、返回同理。

北极星（2026-09-22 原型写回）要求「from/card 深链决定稳定返回来源」，现状 `from` 参数全仓不存在（实测 grep 无消费方）。

## 2. 目标

### 2.1 紧凑导航统一模型：URL 是唯一事实源

390×844 紧凑视口下，**单一导航状态**（落在 URL 上）驱动三件事：底栏 tab 高亮、详情层（卡抽屉/目录覆盖层/工作台下钻态）、任务现场进出。React 侧不再持有与 URL 平行的导航状态；任何导航动作 = 写 URL，任何 UI 呈现 = 读 URL。

### 2.2 北极星流程（逐步骤，形态基准见 §7）

1. 用户在会话 tab 进入某会话（工作台下钻态）。
2. 点会话顶部卡身份（真实 UI 对应物：会话详情抽屉「会话卡」行）→ **进入「卡」tab 的对应卡详情**（不直接跳任务现场）：底栏「卡」高亮、卡抽屉打开、来源会话记入 URL。
3. 卡详情里用户点**明确的进入现场动作**（「关联执行」行 ↗、协调者面板「打开终端」）→ 进入任务现场（工作台下钻态）。
4. 任务现场点返回 → **回来源**：从卡来则重开来源卡抽屉，从会话来则回到来源会话；无来源则按现状回底栏对应 tab 首页。

### 2.3 深链语义

- `/cards?card=<id>` 直达与从会话进入得到**同一状态**：卡 tab 高亮 + 该卡抽屉打开。差异只在 `from` 参数：会话进入带 `from`（来源会话），直达不带（无来源，返回走现状）。
- 卡详情深链**保留 card id 与来源**：`card=<id>` 与 `from=<来源>` 都在 URL 上，刷新/分享不丢。
- `from` 的取值域本卡两态：来源会话（`session-<sessionId>`）与来源卡（`card-<cardId>`，为卡→卡跳转如 `CardDrawer.tsx:793/806/816` 的关联卡行留位）。任务现场期间 URL 必须能表达返回来源（宿主路径的确切形状归 plan，见 §3.3 开放问题）。
- 桌面语义零变更：`/cards?card=` 桌面行为（整页 + 抽屉）不动，`from` 参数桌面不消费、不渲染、不报错。

### 2.4 死入口处置（逐个给决定）

处置原则：**要么给移动端可达结果，要么紧凑视口主动隐藏并给出解释；不允许既渲染又无效**。

| 入口 | 处置 | 理由 |
|------|------|------|
| 底栏「流程」 | 紧凑视口**隐藏** + 一行解释 | FlowsPage 是工作流形状/派发模板管理整页，移动端可达需整页适配，超出本卡边界；流程属低频管理面。解释文案落点归 plan（倾向项目 tab 底部入口行旁一行 muted 文案，仅紧凑视口渲染） |
| 底栏「代码图」 | 紧凑视口**隐藏** + 同一解释 | `/codegraph` 的 viewer 唯一来源是同源 iframe（`Shell.tsx:979` 注释），紧凑视口无承载面 |
| 项目行「工作项」 | **给移动可达结果** | 卡 tab 已挂 `CardsPage` 且它本就消费 `project` 参数过滤（`CardsPage.tsx:85`、`:126`），零新页面即达。须同时解决 hover-only 在触屏不可达的问题（紧凑视口改为触屏可达的呈现形态，形态归 plan） |
| 项目行「代码图」 | 紧凑视口**隐藏** | 同「代码图」 |

「解释」不是道歉文案堆砌：紧凑视口隐藏的每个入口，用户都能在同一视口内读到一句它为什么不在、去哪用（桌面宽屏）。

### 2.5 桌面不回归的边界

- `fullPageRoute` 机制（`Shell.tsx:537`）、`<Routes>` 注册（`Shell.tsx:966-988`）、`openCardsSurface`/`openSettingsSurface` 桌面分支（`Shell.tsx:491/495`）、`SessionTab onOpenCard` 桌面分支（`Shell.tsx:955`）全部不动。
- 统一导航 hook 只在 `compact` 分支生效；桌面走既有 useState 路径（或 hook 内部对桌面为直通实现），保证「桌面路由行为不回归」可被既有测试直接锁住。

## 3. 方案骨架（plan 可直接接手的粒度，不含具体代码实现）

### 3.1 状态模型落点

- 新建 `web/src/app/shell/useMobileNav.ts`（非 `terminal*` 前缀，不碰 P3 约束的文件族）：以 `useSearchParams` 为存储的紧凑导航 hook，派生 `{ tab, detail, dir, card, from }` 及对应 setter；setter 只写 URL，消费方从返回值读。`Shell` 现有三个导航 useState（`mobileTab`/`mobileDetail`/`fileDrawer`）改由它供给，全部旁路写点收编：
  - `MobileTabBar onSelect`（`Shell.tsx:1021-1028`）→ 写 `tab` 参数（保留 `backToWorkbench` 的桌面分支语义与 `console.debug` 事件）；
  - `openMobileDetail` 及其全部调用方（`openSession`/`openTaskTui`/`openWorkbenchItem`/`openTerminalAt`/`openMobileFile`/`openMobileTerminal`/`openCoordinatorTerminal`）→ 写 `detail`；
  - 目录覆盖层开/关（`Shell.tsx:1060-1085`）→ 写 `dir`；
  - 账本未启用首屏退「项目」effect（`Shell.tsx:173-177`）→ 改为对 URL 的规范化修正（replace 语义，避免历史堆积）。
- URL 参数形状（紧凑视口专属；桌面忽略这些参数）：
  - `tab` ∈ `sessions|cards|projects|settings`（缺省 `sessions`）；
  - `detail=1` 表示工作台下钻态（返回条清它）；
  - `dir=<baseKey>` 目录覆盖层；
  - 卡详情沿用 `/cards` 路径既有 query：`card=<id>`（`CardsPage.tsx:107` 现状）、新增 `from=<session-<id>|card-<id>>`。
- 埋点沿仓库惯例：导航迁移点统一 `console.debug('shell.mobile_nav.*', {...})` 事件（替换/扩展现有 `shell.mobile_tab.select`/`shell.mobile_detail.back`）。

### 3.2 组件与回调改线

- **会话侧入口**（`Shell.tsx:955` `onOpenCard`）：compact 分支改为统一导航写法——落 `/cards?card=<id>&from=session-<sessionId>` 并使卡 tab 高亮、退出下钻态；桌面分支原样。
- **`CardsPage`**：结构零改动（`card`/`project` 参数消费已有）；`jumpToTask`（`CardsPage.tsx:254-257`）在 compact 下把当前 `from`/来源随行带到任务现场。卡抽屉在 compact 下由 mobile-home 覆盖层内挂载（`Shell.tsx:1015`），选中态由 URL 的 `card` 参数恢复——直达与会话进入由此同状态。
- **返回条**（`Shell.tsx:1037-1055`）：按 `from` 分派——`from=session-<id>` → 切 `sessions` tab 并 `wb.openOrFocus` 该会话 tab（`openSession` 的去重语义复用）；`from=card-<id>` → 切 `cards` tab 并以 `card=<id>` 重开抽屉；无 `from` → 现状行为。恢复承诺止于「回到来源 tab/抽屉」，不承诺复活已关闭的 workbench tab（见 §6）。
- **`ProjectTree`**：紧凑视口下 ①「流程」「代码图」底栏钮与项目行「代码图」hover 钮不渲染（注入方式参照既有 `onOpenProjectCards={ledgerEnabled ? … : undefined}` 的条件注入先例，`Shell.tsx:784`）；②项目行「工作项」入口改触屏可达形态并接统一导航（`tab=cards` + `/cards?project=<name>`）；③紧凑视口渲染一行解释文案。`ProjectTree` 需要 compact 入参或等价信号，形态归 plan。
- **`TaskDeepLink`**（`Shell.tsx:1241-1263`）：行为保留（书签/通知兼容），compact 下的 URL 终态从「恒 `/`」改为携带统一导航参数（含来源）。

### 3.3 归 plan 的开放岔口（spec 只定语义不定形状）

1. 统一导航参数的宿主路径：全部挂 `/` 的 query，还是 `detail=1` 等随 `pathname` 分散（`/cards` 上的 `card`/`from` 已是既有事实）。倾向：`/cards` 维持既有 query，其余导航参数挂 `/`。
2. 项目行「工作项」在紧凑视口的触屏可达形态（行内常驻 vs 展开区内）。
3. 解释文案的确切落点与措辞。

## 5. 非目标

- **原生 Android/iOS 壳**：卡上明文排除；webview 容器与 cookie 桥接归 B369 S4/壳侧。
- **桌面路由重构**：`fullPageRoute`/整页路由机制不动，桌面仅免疫不受益。
- **pad 展开态分栏**：父卡 story 6（对话/终端分栏）不在本卡；本卡统一模型对 pad 视口（768–1023 同属 compact，`useShellViewport.ts:13-14/26-28`）自然生效，但 pad 专属优化不做。
- **新路由树**：P1=A 拍板「一份 Shell 条件渲染」，不开 `/m` 树。
- **账本写入面**：P2=A，卡详情操作复用既有 move/评论/裁决入口，零新增端点。
- **FlowsPage/CodegraphFrame 的移动端整页适配**：本卡处置是隐藏+解释，不是适配。

## 6. 风险与开放问题

1. **来源恢复不等于 tab 复活**：`from` 恢复只保证回到来源 tab/抽屉；若来源会话的 workbench tab 已被用户关闭，会话分支用 `openOrFocus` 重建（幂等），卡分支重开抽屉不依赖 workbench tab——无死局，但「返回后焦点内容与离开时逐像素一致」不承诺，测试断言按「tab/抽屉在场」口径写。
2. **`?from=` 是新 query 参数**：桌面 `CardsPage` 不消费它即天然免疫；无 wire 影响（纯页面内导航状态，不新增 `/api` 面）。风险在参数名与未来桌面语义撞车——plan 落名时 grep 全仓确认无占用（本轮实测 `from` 无任何消费方）。
3. **URL 化后浏览器返回键语义变化**：现状 compact 导航不写 URL，返回键离开站点；URL 化后返回键开始逐级回退导航。这是改善而非回归，但与「返回条」形成两条返回路径，行为一致性归 plan 用例覆盖。
4. **验收判据与代码现实无根本矛盾**：四类死入口都能给出「可达」或「隐藏+解释」处置（§2.4），不存在「既不可达又不可隐藏」的入口；本节不设「无法自圆其说」项。

## 7. 原型缺失说明与形态依据

卡上原挂的三个原型文件 `prototypes/mobile-app/pages/mobile-{session,card,task}.html` **已不在盘上**（实测 `prototypes/` 下无 `mobile-app` 目录；`prototypes/base/` 为桌面形态镜像，无移动屏）。形态依据以卡上**北极星写回笔记（2026-09-22）为准**：「会话顶部卡身份先进入卡详情；卡详情的明确『进入现场』动作才进入任务现场；from/card 深链决定稳定返回来源。已实走『会话→B233.17 卡详情→任务现场→返回』」。`prototypes/base/README.md:20` 保留的 fork 行记录了十一屏形态走查史，可作背景不作依据。北极星笔记中「会话顶部卡身份」在当前真实 UI 的对应物是会话详情抽屉「会话卡」行（`SessionDetail.tsx:36-46`）——本卡修导航语义，不新增/迁移该呈现面（P2=A 边界）。

## 8. 定级结论与落点

**L2**。理由：单子系统（web 前端 `d_web`，改动集中在 `web/src/app/shell/` + `web/src/app/tree/ProjectTree.tsx` 的 props + 新 hook 文件）；无新 wire 契约（URL query 是页面内导航状态，`/api` 零新增）；有明确验收判据与原型走查记录（北极星 2026-09-22 实走）；工作量显著高于流程固定成本（状态模型重构 + 四入口改线 + 测试面），不落 L1 快道。落点：spec 完稿后卡移 plan 列，plan 接手 §3.1–§3.3 骨架与三个开放岔口。
