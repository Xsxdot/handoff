# B233.6 工作流接入共享派发：事件转发与旧执行编排退役

状态：**已批准**（2026-09-06，用户原话「按这个推进吧」）  
定级：**L3**　档位：**轻档**  
卡：B233.6（被 233.5 阻塞）  
日期：2026-09-06  
台账：`docs/superpowers/ledgers/2026-09-06-b233.6-spec-ledger.md`  
背景：过程图 7；233.1 事件流。暂不开发 spec 后全自主推进。

## 定级理由

卡/工作流应用消费共享派发与事件流，动 ledgerstep 与执行/审批事实的接缝。轻档：复用 ledgermirror，不新造总线。

## 问题陈述

一条卡工作流通过统一派发推进节点。监听者在工作流事件流看到所属执行的 Ask/待审批/结果，经原有类型化入口回复。重连重放、节点重试、迟到旧事件不串尝试、不重复推进。执行完成不冒充业务验收。工作流不再自造 HOME、harness 参数、审批或纪律注入。

## 现状事实

`ledgerstep` 节点 runner 自拼运行字段、节点 pass 后 task run 推分支。`ledgermirror` 把 task 事件镜像进卡流。工作流有自己的节点/轮次/路由。

## 方案

工作流只编排业务：组装与 233.5 相同的派发输入（目标、材料、纪律选择、接收者名称），调用共享派发，可靠关联节点尝试与任务身份。派发事件流产生后订阅并转发到工作流事件流，补充卡、节点、attempt、源事件身份。Ask/授权/执行事实仍由原领域拥有，不复制第二套权威。

回复仍走 RespondAsk / 审批 client，不在工作流里 Send 答问。复核 ledgermirror：去重、游标、尝试身份。迟到旧事件不得推进新 attempt。

执行完成 ≠ 节点业务 pass ≠ 卡验收。全自主推进不做。

### 弃选

工作流自造 HOME/审批链；执行完成自动当验收。

## 用户故事

1. charter 某一派发列走共享派发，卡 wait 仍能看到 Ask 并 reply。
2. 节点失败重试开新 attempt 时，旧 Ask 答案到不了新任务。
3. 重连按工作流游标补拉，不重复移列。
4. 旧拼 harness 参数的路径不再被节点 runner 使用。

## 契约语义

源任务与审批状态是权威；工作流只持关联与业务路由。依赖：ledgerstep → 233.5 派发 → 233.1 执行/审批；镜像转发不得写回那些权威表。

## 测试决定

1. **节点派发**（ledgerstep Dispatcher，调用方 card dispatch --step）：产生任务并关联 attempt。
2. **转发**（ledgermirror）：Ask 出现在卡流且 ticket 可 reply。
3. **attempt 隔离**：旧事件不推进新尝试。
4. **退役**：节点路径不再拼 HOME/executor argv。

## Out of Scope

全自主推进；B225 环节恢复若已覆盖的不重复造；push 归属。
