# B356：`card wait --subtree` 建连对账子卡未决工单，唤醒冒泡到有席位的祖先

状态：**已批准**（2026-09-11 用户「开卡修吧」；方案即前一轮排查给出的两处收口）
级别：**L2**（两处独立收口：CLI stdout 快照 / agentd 席位解析；不新增跨进程契约。stdout 快照是 CLI 产品线格式，与 B253 同级。）
卡：B356

## 问题陈述

协调者按 skill 只挂一条 `handoff card wait <父> [--subtree]`，不再叠 task 级 `wait --follow`。子卡上的 `permission_request` / `question` 镜像进子卡 `card_id`，但：

1. `runCardWait` 用全局 `MaxSeq()` 做排他起点，建连前已镜像的工单永不出现。
2. `automationWakeEvent` 用事件自己的 `card_id` 找席位；子卡空座则 no-op，父卡 coordinate 协调者不会被叫醒。bind 席位本就不走自动唤醒（靠 CLI wait）。

活库旁证（2026-09-11）：`Subtree(B233)` 含全部点号子卡；B233.10 有 8 条未决 `permission_request` 镜像，父卡 B233 自身 0 条。`Follow` 的成员集过滤是对的，缺的是建连对账和席位冒泡。

## 方案

**选定：两条独立通道一起补齐，事件 `card_id` 仍是子卡。**

1. **CLI 建连快照**：`card wait` 进入 Follow 之前，对当时成员集吐一行 `type=card_snapshot` JSON（`--subtree` 时成员=子树）。`actionable` 列出未决工单（含 `card_id` / `source_target` / `source_task` / `ticket_id` / `task_type` / 原 payload），`needs` 列出成员上未清的 `needs_human`。空数组也要出这一行，让「建连了但没欠单」和「管道把输出吞了」可区分。
2. **唤醒冒泡**：事件卡自己有席位 → 维持现状（coordinate 唤醒本卡，bind 跳过）。事件卡空座 → 沿 `parent_id` 上走，第一个 **coordinate** 席位的祖先接手（`WakeEvent.Card` 改写成祖先，同祖先事件合并为一回合）。祖先是 bind 则继续上走。环/深度上限 32。不要把子卡事件改写成父卡 `card_id` 落账。

弃选：

- 把子卡 `task_mirrored` 再写一份到父卡：双写、card_id 说谎，后续对账必乱。
- 给 `card wait` 加持久 cursor 回放：B253 已裁，子树成员集会漂；快照覆盖「建连前欠什么」。
- 叫醒 bind 席位：bind 的法定通道是 CLI wait；快照就是给它看的。

## 用户故事

1. 父卡上挂 `card wait --subtree` 时，子卡已经有未答复工单：stdout 第一行 `card_snapshot.actionable` 带 `ticket_id` 和 `source_task`，可直接 `handoff show` / `reply --target`。
2. 建连之后新出现的子卡工单：仍走 Follow 的 `task_mirrored`（现状，不改事件形状）。
3. 父卡 coordinate、子卡空座：子卡工单唤醒父卡协调者回合，briefing 摘要含 `permission_request`/`question`。
4. 子卡自己有 coordinate 席位：仍只叫醒子卡，不抢给父卡。
5. 父卡 bind、子卡空座：不自动唤醒（现状）；靠故事 1 的快照。

## 实现决定

- 快照行走 stdout，与事件行同流，靠 `type` 区分。字段名是产品决策：`type`=`card_snapshot`，`card_id`=wait 参数，`subtree` 布尔，`from_seq` 为随后 Follow 的排他水位，`members` 为建连时刻成员，`actionable` / `needs`。
- 未决工单与看板 `OpenTicketCounts` 同一把尺：镜像流回放 创建→答复/作废。
- 唤醒改写只发生在 agentd 消费循环里，不改账本事件。
- bind 不唤醒这条不变。

## 测试决定（接缝清单）

1. **`cmd/card_wait.go#runCardWait`**（边界型：CLI stdout 线格式）。调用方：协调者 Monitor / 脚本。缝级：`--subtree` 建连时，子卡已有 `permission_request` 则第一行 `type=card_snapshot` 且 `actionable` 含该 `ticket_id`+子卡 `card_id`；已答复的工单不出现；无欠单也有一行快照。
2. **`internal/agentd/wakeconsumer.go#consumeAutomationEventsOnce`**（生产调用方：自动化消费循环）。缝级：子卡空座+父卡 coordinate → Resume 打在父卡；子卡自己 coordinate → 不打父卡；父卡 bind → 不 Resume。

## Out of Scope

- 永不做：把子卡事件改写成父卡 `card_id` 落账。
- 本期不做：`card wait` 持久 cursor / 逐条回放（仍在 roadmap 的 B253 残余口径）。
- 本期不做：父卡 `open_tickets` 徽标汇总子树（看板另一条通道）。
- 本期不做：inbox `Watchers>0` 藏工单。
- 不叫醒 bind 席位。
