## 2. 依赖与版本契约

实现节点必须把 `go.mod` 的直接依赖从：

```text
github.com/Xsxdot/charter/graph v0.6.0
```

改为：

```text
github.com/Xsxdot/charter/graph v0.7.0
```

并新增以下别名导入；别名是为避免与 handoff 自有包同名：

```go
charterwebui "github.com/Xsxdot/charter/graph/webui"
```

依赖边界冻结为：

- `charterwebui.FS` 的精确签名是 `func FS() fs.FS`；调用方只得到 `fs.FS`，不得要求 charter 提供 handler、路由、鉴权或网络客户端。
- `FS()` 返回的 FS 根是 `dist` 子树，根项含 `index.html`；宿主不得再拼接 `dist/`，否则静态资源路径会多一层。
- `v0.7.0` 的 viewer dist 已随依赖提交；handoff 不复制 `graph/webui/src` 或 dist，不在本仓再建第二份查看器。
- 不写 `replace`。本地缓存能编译但消费方无法按同一 tag 解析的做法不构成契约完成。
- 本卡不为 `graph/codegraph` 增加新 wire 类型；版本升迁的响应体仍由现有 `handleProjectCodegraph` / `handleProjectCodegraphSource` 透传。

## 3. Go 静态挂载签名

### 3.1 mux 组装

在 `internal/agentd/server.go#Server.Handler`（现状静态装配点 `:539-542`）新增专属前缀，并保留 handoff 根静态树：

```go
mux := http.NewServeMux()
mux.Handle("/api/", api)
mux.Handle("/ws/", api)
mux.Handle(
	"/codegraph/app/",
	http.StripPrefix("/codegraph/app", newSPAHandler(charterwebui.FS(), s.log)),
)
mux.Handle("/", newSPAHandler(webui.FS(), s.log))
```

这里的精确约束是：

1. `"/codegraph/app/"` 是 charter FS 的唯一宿主前缀；`"/"` 继续只承载 handoff 自有 `internal/webui.FS()`。
2. `http.StripPrefix("/codegraph/app", ...)` 的前缀不带末尾 `/`，这样 `/codegraph/app/` 被下游看到为 `/`，`newSPAHandler` 才按根请求读取 charter FS 的 `index.html`；`/codegraph/app/assets/x` 被下游看到为 `/assets/x`。
3. 专属前缀注册在根 SPA fallback 之前；Go `ServeMux` 选择更具体的模式，未知 `/codegraph/app/...` 不得落到 handoff 根 index。
4. 该 handler 仍位于 `root.Handle("/", s.auth(mux))` 之内；未登录访问 charter 静态资源必须在 handler 之前收到现有鉴权响应，不得把登录失败回落成 HTML。
5. 不新增 CORS、`postMessage`、第二端口、独立 listener、静态资源 token 或另一套 handler。依赖库边界与静态行为均由 `webui.FS`、标准库 `http.StripPrefix`、现有 `newSPAHandler` 共同承载。

### 3.2 路由行为清单

| 请求 | 冻结结果 |
| --- | --- |
| `GET /codegraph/app/` | 通过 auth 后由 charter FS 返回 charter `index.html` |
| `GET /codegraph/app/<deep-path>` | 通过 auth 后由同一个 charter `newSPAHandler` 回退 charter `index.html` |
| `GET /codegraph/app/assets/<hashed>` | 命中 charter FS 真实资源并沿用现有 hash 缓存策略 |
| `POST /codegraph/app/` | 405；不得被 SPA 回退吞成 200 |
| 未登录 `GET /codegraph/app/` | 现有 `s.auth` 的鉴权响应；不得返回 handoff 或 charter HTML |
| `GET /` 或 handoff 其它静态路径 | 继续使用 handoff `internal/webui.FS()`，行为零改动 |
| `GET /api/projects/{name}/codegraph` | 继续进入现有 API handler；响应体不改 |
| `GET /api/projects/{name}/codegraph/source` | 继续进入现有 API handler；响应体不改 |

现有 `newSPAHandler` 的读方法集合、index 缺失错误、缓存头、`fs.ValidPath` 处理不在本卡重定义；实现只复用，不复制。`http.FileServerFS` 的依赖事实为 `/usr/local/go/src/net/http/fs.go:975-985`，`http.StripPrefix` 的事实为 `/usr/local/go/src/net/http/server.go:2328-2344`。

## 4. iframe 薄壳签名

### 4.1 新文件与导出

新建 `web/src/app/codegraph/CodegraphFrame.tsx`，冻结导出签名：

```tsx
export interface CodegraphFrameProps {
  project: string
}

export function CodegraphFrame({ project }: CodegraphFrameProps): JSX.Element
```

实现语义只有两件事：

```tsx
const src = `/codegraph/app/?project=${encodeURIComponent(project)}`
return <iframe title="代码图" src={src} />
```

其中 `project` 是当前 `BaseDir.projectName`；空串仍是合法薄壳输入，viewer 已冻结为空项目跳过请求。`encodeURIComponent` 必须作用于项目名本身，空格、斜杠、中文不得直接拼入 path。不得把 `machine`、token、cookie 或 host 写入 src；`?machine=` 的 API 转发仍由宿主现有 API handler 负责，本卡不伪造 viewer 侧新输入。

### 4.2 薄壳边界

`CodegraphFrame` 不得：

- import handoff `web/src/api/client` 或调用 `fetchCodegraph` / `fetchCodegraphSource`；
- 读取 `document.cookie`、Authorization、localStorage token 或宿主 auth 状态；
- 读取 `useProjectTree`、复制项目下拉、复制 viewer 的 graph state；
- 直接渲染旧 `CodegraphPage` 或旧副本下的 `DetailPanel`、`FocusGraph` 等组件；
- 另建 fetch、轮询、跨窗口消息或项目选择器。

### 4.3 Shell 接线

在 `web/src/app/shell/Shell.tsx#Shell` 的现有 route（`:491`）把：

```tsx
<Route path="/codegraph" element={<CodegraphPage />} />
```

替换为：

```tsx
<Route
	path="/codegraph"
	element={<CodegraphFrame project={wb.base?.projectName ?? ''} />}
/>
```

并删除 `CodegraphPage` 的 handoff import。项目树入口 `onOpenCodegraph={() => navigate('/codegraph')}`（`web/src/app/shell/Shell.tsx#Shell`，`:461`）不改；入口仍是既有入口，当前选中工作区决定 `projectName`。

## 5. fullPageRoute 修复

`web/src/app/shell/Shell.tsx#Shell` 的现状布尔表达式（`:391`）只需把 `'/codegraph'` 加入白名单：

```tsx
const fullPageRoute = ['/cards', '/flows', '/settings', '/machines', '/codegraph']
	.some((path) => location.pathname.startsWith(path))
```

同一个 `fullPageRoute` 必须继续同时约束：

```tsx

```

（`web/src/app/shell/Shell.tsx#Shell`，`:478`）与：

```tsx

  <div className="w-[280px] shrink-0">...</div>
```

（`web/src/app/shell/Shell.tsx#Shell`，`:567`）。`/codegraph` 时两者都不渲染；回到 `/` 或选中工作台时两者按既有条件恢复。不要分别重写两处条件，也不要改 `ProjectTree` 左栏入口。

## 6. 原子冻结清单

每行是一条独立 pass/fail 断言：

- `go.mod` 直接依赖精确为 `github.com/Xsxdot/charter/graph v0.7.0`。
- `go.mod` 不含该依赖的 `replace`。
- 宿主通过 `charterwebui.FS() fs.FS` 消费 viewer，不消费 charter handler 或路由。
- charter FS 只挂在 `/codegraph/app/` 前缀。
- handoff 自有 `internal/webui.FS()` 仍挂在 `/` 根 fallback。
- charter 前缀 handler 注册在根 SPA fallback 之前。
- charter 前缀 handler 位于 `s.auth(mux)` 之内。
- `/codegraph/app/` 的 FS 根请求读取 charter `index.html`。
- `/codegraph/app/<deep-path>` 回退 charter `index.html`。
- `/codegraph/app/` 的 POST 返回 405。
- `/api/projects/{name}/codegraph` 的 HTTP 方法与路径保持不变。
- `/api/projects/{name}/codegraph/source` 的 HTTP 方法与路径保持不变。
- `CodegraphFrame` 导出 props 只有必填 `project: string`。
- `CodegraphFrame` 的 src 精确使用 `/codegraph/app/?project=${encodeURIComponent(project)}`。
- `CodegraphFrame` 不请求两条 API。
- `CodegraphFrame` 不读取 token、cookie 或宿主项目树。
- `Shell` 的 `/codegraph` route 把 `wb.base?.projectName ?? ''` 传给 `CodegraphFrame`。
- `/codegraph` 不再 import 或渲染 handoff 旧 `CodegraphPage`。
- `/codegraph` 被 `fullPageRoute` 判为 true。
- `/codegraph` 时 Breadcrumb 不渲染。
- `/codegraph` 时右栏 FileTree 不渲染。
- 离开 `/codegraph` 后 Breadcrumb 按既有条件恢复。
- 离开 `/codegraph` 后 FileTree 按既有条件恢复。
- handoff `web/src/app/codegraph/` 最终只保留 `CodegraphFrame.tsx`。
- handoff 旧副本不再残留 `fetchCodegraph` 引用。
- 本卡不新增 `graph/codegraph` wire 字段或响应体变化。
- 本卡不创建第二个静态 viewer 源码副本。

## 8. 拍板记录

本轮命中三重闸门的一项决定是：宿主采用 charter `graph/v0.7.0` 的 `webui.FS()` 作为唯一 viewer 来源，并把它放在 auth 内的 `/codegraph/app/` 专属前缀；被否掉的是继续钉 `v0.6.0`（只能展示一期旧形态）与把两棵 FS 混在根前缀（深路径会把错误的 index 作为回退）。该决定同时跨 go.mod、agentd mux、前端 iframe 与部署换装，后人若只看单仓旧副本会自然想“先复用旧页面”，故记录。

本轮另一项不可逆取舍是：`CodegraphFrame` 只负责把 `BaseDir.projectName` 编码进 iframe src，不在 handoff 复制 viewer 的 API 客户端、项目选择器或 graph state；被否掉的是在宿主保留可调试的旧 19 文件副本。该决定使源码归属跨仓冻结，后续形态变化必须随 charter 发 tag 后由宿主升版；本卡显式不做 `?machine=` 新 viewer 输入、不做第二端口、不做 CORS/postMessage。
