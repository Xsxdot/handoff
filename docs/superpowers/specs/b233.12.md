## 定级理由

跨子系统：审批 client 现状图归属仍是 `d_orchestration`（未单列审批域），原生投递在 `d_execution` adapter，非 OpenCode 旧路径同在编排。动的是已冻结的 Ack 阶段语义（B233.7 第 58 条），不是新 HTTP。跨编排与执行的一条投递缝、一轮可收口 → L3 轻档。不把 Manager 迁包、不把五家 harness 权威迁移塞进本卡。

## 问题陈述

谁：一次 OpenCode 原生权限请求，经 `ApprovalClient.Request` 得到决定后回到 harness。

条件：B233.8 已把生产实现迁出 `agentd` 包，但组装时把 `Manager.autoAllowPermission` 配成 `Hooks.AutoAllow`。该钩子自己 `RespondPermission`。OpenCode adapter 在 `Authorize` 返回 allow 后再回传一次。`consult()` 在返回 allow **之前**就把工单标成已送达。B233.7 冻过：`delivered` 只能在真实原生回传成功后发出。

通道：现有 `ApprovalClient`（`Request` / `Acknowledge`）和 OpenCode `RespondPermission`。不新造 HTTP、CLI、事件类型。

要变的事实：

1. **原生投递只有一处。** OpenCode 路径上，只有 adapter 对一次权限请求调用一次 `RespondPermission`。`Hooks.AutoAllow` 只允许写审计（及既有自动放行计数），禁止回传。
2. **送达确认只在原生回传成功之后。** `Request`（含审批者 allow 的 `consult`）返回时，工单可以已有 `answer`，`DeliveredAt` 必须仍为空。只有 `Acknowledge(AckDelivered)` 在 `RespondPermission` 成功之后才写 `DeliveredAt`。
3. **失败的批准不得冒充已送达。** 原生回传失败：工单进「已决未送达」，resume 的 `UndeliveredAnswers` 能看见；`FindReusableGrant` 不得命中。不得因此打出「投递失败」却其实第一次已经送到、第二次才失败的假事件。

谁能观察到：免审命令只被 harness 应答一次；审批者放行后若回传失败，协调者能靠 resume 补投，而不会在下一次等价请求上自动复用一张从未送到的批准。

## 方案

审批 client 拥有**决定**（allow / deny / pending、工单 answer、审计事件）。Harness adapter 拥有**原生投递**。送达时间戳是投递成功的事实，不是决定形成的事实。

OpenCode：

- `Request` 命中 AutoAllow：写审计（可经钩子），返回 allow，**钩子不得 `RespondPermission`**。
- `Request` 命中审批者 allow：落工单 answer=allow，返回 allow，**不得 `MarkTicketDelivered`**。
- adapter 对 allow / deny 终态各 `RespondPermission` 一次；成功后 `Acknowledge(AckDelivered)`。
- **回传失败按有没有工单分叉：** 审批者 allow（有工单）走既有 `NoteDeliveryFailed`，工单保持未送达，resume 的 `UndeliveredAnswers` 能看见。免审 AutoAllow **仍然无工单**（B249），回传失败不产 `delivery_failed`、不进 `UndeliveredAnswers`；P1-1 要消灭的是「钩子先送成功、adapter 再送失败」打出的假 `delivery_failed`，不是给免审补一张工单。

非 OpenCode：

- 本卡不把权威迁到 `ApprovalClient`。
- `handlePermission` 的 AutoAllow 仍必须回传一次（agy 重放等既有行为）。
- 因此「审计」和「非 OpenCode 回传」必须能拆开：OpenCode 的 AutoAllow 钩子只走审计；`handlePermission` 走审计 + 回传。禁止继续共用一个「审计顺带回传」函数给两条路径。

**弃选**

- **删掉 adapter 的 `RespondPermission`，只留钩子回传。** 与 B233.1「harness 负责原生协议转换」相反，且非 OpenCode / OpenCode 会继续两套权威。否。
- **本卡拆掉全部 Hooks（含 Judge / Transit / Store）。** 那是编排迁包（B233.13）和审批不再回调编排的下一步；本卡只断投递与提前送达。否。
- **本卡把 Claude/Codex/Grok/AGY 迁到 ApprovalClient。** B233.8 已裁。否。
- **Continue 热加载 / `AckExecuted` 持久化。** 不是投递唯一归属。否。

## 用户故事

1. OpenCode 任务触发一条白名单命令。harness 只收到一次原生 allow。事件流里有自动放行审计，没有第二次回传失败打出的 `delivery_failed`。
2. 审批者放行一条需审命令。`Request` 返回 allow 时工单已答、`DeliveredAt` 为空；adapter 回传成功后才有送达时间。回传失败则 resume 能列出这张工单并补投；同一指纹的下一请求不得走 reuse。
3. 非 OpenCode 任务的工作区写入免审：仍然只由 `handlePermission` 回传一次，行为不回退。

## 契约语义与接缝

- **决定归审批 client。** allow/deny/pending、工单 answer、自动放行审计事件由审批侧写入。
- **原生投递归持有原生连接的一方。** OpenCode 是 adapter；非 OpenCode 本期仍是 `handlePermission`。
- **`DeliveredAt` 只表示原生回传已成功。** 写入入口是 `Acknowledge(AckDelivered)`。`Request` / `consult` 不得写它。
- **复用只认已送达的 allow。** 已有 `FindReusableGrant` 语义保持；本卡要让它不再被提前标记喂肥。
- 不新增顶层域、HTTP、CLI、事件类型。允许审批包继续经 Hooks 读 Store / 判据 / 审批者；禁止 Hooks 再做原生投递。

接缝（符号 + 调用方）：

1. **`internal/executor/opencode/adapter.go#authorizeNativePermission`** — 调用方 OpenCode 权限事件。最高可测缝：一次原生请求，`RespondPermission` 恰好一次；allow 终态的 `DeliveredAt` 只在该次成功之后出现。
2. **`internal/approval/client.go#Client.Request`**（含 `consult`）— 调用方 `executor.Authorize` / 上一条。AutoAllow 与审批者 allow 返回时不得已送达；不得让 AutoAllow 钩子成为第二条投递路径。

假缝禁令：纯审计 payload 编码、fingerprint 函数不占接缝名额。

## 实现决定

- 命令名、HTTP 路径、事件类型不变。
- OpenCode 免审仍不建人工工单、不发 `permission_request`（B249 噪音约束保持）。
- 非 OpenCode `handlePermission` / `handleQuestion` 权威本卡不迁、不删。
- `AckFormed` / `AckExecuted` 本卡不改持久语义（Executed 仍可不写库）。
- 锁错时序的测试必须改成：`Request` 后 `DeliveredAt == nil`；`AckDelivered` 后非空。
- `consult` 成功路径里「已持久化并送达」这类日志，在去掉提前 `MarkTicketDelivered` 之后必须改成与事实一致（决定已落、尚未送达）。

## 测试决定

1. **免审只回传一次**（缝 1）：必须经生产组装 `bindApproval` 配上的 AutoAllow 实现，再进入 `authorizeNativePermission`。全程 `RespondPermission` 恰好 1 次（adapter），生产钩子次数为 0。禁止只用测试替身钩子冒充。变异：生产 AutoAllow 实现仍 `RespondPermission`，测试必须红。
2. **审批者 allow 未送达**（缝 2）：`Request` 返回 allow 后工单 `answer=allow` 且 `DeliveredAt == nil`；`FindReusableGrant` 未命中。`AckDelivered` 之后才可复用。变异：`consult` 内提前标记，测试必须红。
3. **回传失败可恢复**（仅缝 2，有工单）：审批者 allow 之后 `RespondPermission` 失败，`UndeliveredAnswers` 含该工单，不得被 reuse。免审 AutoAllow 失败不进该列表（无工单）。缝 1 的假事件断言另见测试 1：不得因钩子先回传、adapter 再失败而出现 `delivery_failed`。
4. **非 OpenCode 不回退**：现有 `handlePermission` AutoAllow 测试保持绿（仍回传一次）。此条是兼容回归，不占接缝名额。
