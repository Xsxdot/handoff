## 1. 问题陈述

夜班实测（卡事件 16420）暴露两类成本：**噪声**（opencode 双 WARN 把 agentd.log 冲成噪声场，真实告警被淹；权限门判据假阳性把合法动作升级人工）与**往返**（同类命令反复升级、一次拒绝吃两次人工往返）。四件中两件已修（§2），本 spec 覆盖剩余三块：

1. **opencode 双 WARN**——每张权限工单打两条「未找到工具等待窗口」WARN；
2. **路径/判据假阳性**——黑名单不看 scope、heredoc 写被升级、只读命令旗标内容误判自指令、cd 越界存疑待证；
3. **拒绝双往返与同类重复升级**——被拒后 adapter 主动合成第二张 ask；同类命令没有任务内已批复用之外任何收口。

## 2. 已完成部分（背景，不在本 spec 范围）

- **第 2 项（纪律块 $TMPDIR）**：`d45c078ae`，`internal/discipline/platform.go` 平台不变量加第 4 条 + `TestComposeEnabledCarriesTmpdirRule`。
- **第 3(c) 之主体（import 路径判自指令）**：`4ded5bba1`，自指令判定改「命令位置」判据（`internal/permgate/selfcmd.go` `judgeSegment`：段首或执行包装器之后才算候选，普通参数位放行）；残留 `-c/-e/-E` 旗标 fail-closed，由本 spec WP2.3 承接。

## 3. 工作包与方案

### WP1 第 1 项：opencode 双 WARN（取证结论 + 修复语义）

**现状读数**：

- 请求侧 WARN：`permission.asked` 处理登记 `permTiming` 后调 `Segmenter.PauseWaiting`，0 命中即 WARN（`internal/executor/opencode/adapter.go:1619-1637`）；应答侧 WARN：`RespondPermission` 成功后 `Resume`，0 命中即 WARN（`adapter.go:751-763`）。登记先于判定，故一次落空两处各打一条，恰成对。
- **H3 成因（代码链路已证）**：`acceptForeign`（`adapter.go:1432-1457`）对已认亲子会话只放行 `permission.asked`（:1436-1448），其余事件一律丢弃（:1450-1456）→ 子会话的工具 part 永远开不出段 → 子会话权限的 `PauseWaiting`/`Resume` 双双落空 = 恰两条 WARN，且该等待不被任何段承载。
- **反证（主会话路径干净）**：入库样本 `testdata/spike3-events.jsonl`、`spike5-events.jsonl` 均单会话、无子会话、`permission.asked` 前已有 part 事件；独立评审 harness 实测该序零 WARN（事件 16677）。
- 独立评审另证：主会话内「permission 先于非空 running」的序（B/C）同样能产生成对 WARN，等待被吞进 api/tool 桶——但两份真实样本与常态负载未出现该序。
- 当晚 agentd 日志在远端执行机，本机 `~/.handoff/agentd.log` 无该期间记录（0 命中）→ `is_child` 关联取证不可达；日志不留存即视为不可证。

**方案语义**（两条都做，归属 plan 择机制）：

1. 子会话权限等待必须**显式归属**：要么承载计时（归属可辨），要么单条 Info 声明「子 agent 权限等待不承载计时」——禁止成对 WARN，也禁止静默吞进 api/tool 桶（看板不说谎）。`permission.asked` 归属处已知 `is_child`（`adapter.go:1610-1611` 的 INFO 已带该字段），判别信息现成。
2. 主会话解耦修法（评审方向：首个 part 事件即开段，帧与 Detail 延后到入参就绪）作为序 B/C 的防护，同样以合成回放红证据驱动。**超卡增量标注**：卡面第 ① 项只钉双 WARN 与等待归属；序 B/C 在真实样本与常态负载未出现，本条是评审吸收的预防面，plan 轮可单独裁剪。

**验收形状**：新增子会话合成回放夹具（缝 2）——修前恰 2 WARN + 等待无承载（红），修后零 WARN + 等待归属正确（绿）；spike3/5 原样本回归零 WARN 不变。

### WP2 第 3 项：权限门判据假阳性（判据扩容，分轮落地）

**现状读数**：

- 写命令表 `writeCommands`（`internal/permgate/writeargs.go:44-53`）只收 tee/cp/mv/ln/install/dd/gofmt/git——**无 rm、无 cat**（heredoc/重定向写形态不在提取面）；
- 黑名单判定 `judgeCommand`（`internal/permgate/blacklist.go:133`）整串匹配、**完全不看 scope**；`InScope` 三基准 Workdir/TaskDir/TaskTmpDir（`internal/permgate/path.go:41-68`）；
- 越界判定的入口之一是请求自带 `Paths`（opencode `external_directory`，`internal/permgate/permgate.go:180-238`）；
- 自指令判据已是 B383 3(c) 修后形态（`selfcmd.go` `judgeSegment`），旗标内容仍 fail-closed。

**取证（09-21 两例，卡事件 16971/17074）**：`psql -c "select … id='B390'"`——SQL 字符串里的 handoff 被判自指令；`cd $TMPDIR/cardq && cat > main.go <<'EOF'`——任务临时目录内的 heredoc 写同轮被升级 5+ 次。

**判据扩容清单**（每条成对给出「放宽后仍拦」的反例，先红后绿）：

1. **rm 目标提取器 + scope 感知**（评审裁定的最危险项，**单独一轮**）：rm 目标按解析后 Rel 判，只许落在 `Scope.TaskTmpDir` 与字面 `$TMPDIR`；跨段逐条 rm 逐个目标全过；命令内变量不展开（fail-closed）；包装器维持硬拦。反例集：`$TMPDIR/../../etc`、`rm -rf $TMPDIR/a; rm -rf /etc`、`TMPDIR=/etc rm -rf $TMPDIR/*`、`sh -c "rm -rf …"`。
2. **heredoc/重定向写目标提取**：`cat >`/`<<EOF` 落点纳入写目标提取，落在允许根内放行（与 rm 同一提取器、同轮实现）。
3. **已知只读工具旗标内容作数据**：psql/rg/grep 等白名单工具的 `-c/-e` 内容出现 handoff 不判自指令——与 4ded5bba1 的 fail-closed 残留有张力，放宽面以工具白名单收紧，反例（段首/包装器后的真 handoff）必须保持命中。
4. **cd 越界（3(a)）真机取证先行**：worktree 任务的 `Workdir()` 就是工作树本身，裸 `cd` 本在白名单，触发入口是请求带 `Paths`——本案可能不存在（评审裁定）。证真才修：只加**本任务**精确路径基准、过 `resolveExistingPrefix`、绝不放 `.worktrees` 父目录或通配。

**拆轮纪律**（评审裁定）：rm 相关（清单 1+2）单独一轮，不与清单 3/4 混做。

### WP3 第 4 项：拒绝双往返 + 同类重复升级（含两个拍板点）

**现状读数**：

- 一次拒绝 = 两次人工往返的机制链：deny → opencode 零文本终结回合 → `mapIdle` 识别 `turnRejected`（`adapter.go:2204-2219`）→ adapter **主动合成** question（`rejectedTurnQuestion`，`adapter.go:944-956`、发射点 `:2211-2213`）→ `Manager.handleQuestion` 建 `kind=ask` 工单（`manager.go:2888-2965`）→ 协调者再答一次。零文本→result 是 B21、被拒→question 是 2026-08-08 P0（`adapter.go:2205-2207`）——同一反挂死家族的两条目，后者不是 opencode 行为。**重启对账同形**：`reconcile.go:219-237` 对被拒而终的回合补发同形 question（测试 `reconcile_internal_test.go:294-327`）——拍板 A 无论选谁，对账路径必须与 `mapIdle` 同步改向。
- 拒绝理由对 opencode 是**死存储**：`RespondPermission` 丢弃 reason 参数（`adapter.go:702`）、API 只 POST `{"response"}`（`api.go:549` 起）、带外 guidance 唯一消费点被 `!taskIsOpenCode` 门住（`manager.go:2896-2901`）——`DenyReasonInBand` 仅 claudecode/agy 实现。无论拍 a 还是 b，模型都学不到拒绝理由；本卡不修送达面（§7）。
- 同任务内 allow 复用是 B57② 冻结语义（`manager.go:2552`、`internal/approval/authority.go` `FindReuse:244-261`：只复用 allow、只同任务内、查询失败 fail-closed 到照常问人）；指纹含快照版本 → 跨任务/跨版本必再升级。

**拍板点 A｜被拒回合的终局语义**（三选一，决策人：用户，推荐 b）：

- a. 维持现状 ask（保守；往返成本不变）。
- b. **被拒终止回合转 `result{OK:false, FailReason=被拒描述}` 落 waiting_review**。理由：拒绝本身就是协调者对「这批动作」的一次决策，第二张 ask 是在向**已表达过决策的同一人**重问；`handleResult` 对 `OK=false` 的既有处置（作废挂起工单 → turn_failed 事件 → waiting_review，`manager.go:3414-3530`）正是反挂死要的唤醒面，continue 随时可发。净效果：第二次交互从**必答**变**可选**（拒绝本意就是收尾时零额外交互）；语义代价：拒绝即回合失败终局，想换方式走 continue 并带指导。顺带消除「ask 工单与同回合未应答权限工单并存」的悬挂态。**落地三件**（审计补齐）：① 对账补发与 `mapIdle` 同步改 result 同形（`reconcile.go:219-237`），既有测试 `reconcile_internal_test.go:294-327`、`adapter_test.go:1612-1628` 随改写；② result 必须带 `VoidReasonTurnDiscipline`（`internal/executor/executor.go:108-109`），否则 `handleResult` 缺省记「executor 已终结」（`manager.go:3487-3491`）——审计谎言；③ opencode 现存零文本 result 未设 VoidReason（`adapter.go:2230-2234`），WP3 顺带补齐。
- c. 自动 continue 一次并附带拒绝指导（弃选：无界重试烧额度，模型可能死循环换方式）。

**拍板点 B｜同类重复升级的收口载体**（二选一，推荐 a）：

- a. **静态判据扩容承接**：并入 WP2 清单逐类评估（夜班实测的 `git checkout -- <文件>`、Go 模块缓存只读等），可静态证明只读的进白名单（每类成对反例）；内联 python 无法静态证明只读，维持升级。
- b. **跨任务指纹记忆**：动 schema + 新事件，TTL/版本语义、deny 不可记忆；收益大半被 a 覆盖。若拍 b，语义边界（跨任务同机？跨版本？白名单成员？）须一并拍。

（第 4 项真机验证部分需真机 + 在场 + 烧额度，排 acceptance 轮。）

## 4. 用户故事（验收人视角）

1. 夜班多 plan 节点派发后，agentd.log 不再出现成对「未找到工具等待窗口」WARN；子 agent 权限等待在计时/日志里归属可辨。
2. 执行者在任务临时目录 heredoc 写文件、清场 rm 不再升级人工；越出 `$TMPDIR` 的 rm（含 `../../`、跨段、变量注入、包装器）仍被拦。
3. 协调者拒绝一次权限后，不再收到第二张「换方式/跳过/收尾」提问；任务以失败终局落 review，continue 可续（按拍板 A=b）。
4. psql/rg/grep 等只读命令的旗标内容含 handoff 不再被自指令门误拦；段首/包装器后的真 handoff 调用仍拦。
5. （取证豁免）cd 越界与 `Paths` 场景若被真机取证判不存在，本条关闭并记台账。

## 5. 测试决定（接缝清单）

- **缝 1｜permgate 判据面**：符号 = `InScope`/`WriteArgTargets`/`IsSelfCommand`（导出）与 `judgeCommand`（包内、有生产调用方 permgate 判定路径），调用方 = `internal/approval`（`EscalateLogLevel` 等）与 `internal/orchestration`（`handlePermission` 判定路径）。表驱动单测即缝级断言（边界型例外：判据即解析/判定入口，不占内部锁名额）。
- **缝 2｜opencode SSE 回放**：符号 = `replay_spike_test.go` 既有回放 harness，调用方 = `adapter.streamOnce`。子会话合成夹具与 spike3/5 回归穿过该缝（边界型例外：对面是 opencode wire 格式）。
- **缝 3｜被拒回合终局（实时 + 对账两条腿）**：符号 = `adapter.mapIdle` + `rejectedTurnQuestion` + `reconcile` 被拒补发（`reconcile.go:219-237`），调用方 = `Manager.handleQuestion`/`handleResult`。回合分类单测（question→result 改向，实时与对账同形断言）+ manager 侧既有 `OK=false` 处置测试复用。
- 假缝禁令自查：三缝均为存量符号 + 生产调用方（`judgeCommand`/`mapIdle`/`rejectedTurnQuestion` 未导出、包内测试，但有生产调用链，非假缝）；无为本轮分支覆盖新抽的纯函数。

## 6. 实现决定

- 收口层不变：权限判据全收 `internal/permgate`（adapter 不 import permgate 的既有边界不动）；回合终局语义收在 adapter（`mapIdle`），且**实时路径与对账路径必须同形改向**（`reconcile.go`），manager 只按既有 `handleResult`/`handleQuestion` 消费——不新增跨层通路。
- schema：拍板 A=b + B=a 组合下**零 schema 改动**；拍板 B=b 才引入新表/新事件。
