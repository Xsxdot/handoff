# B383 spec：权限门噪声与重复人工往返

**状态**：v6，已批准（用户批准，2026-09-28）。**已拍板**：A=b，被拒空回合发 `result{OK:false}`，任务落 `waiting_review`，继续工作走 `continue`；B=a，只扩充能静态证明安全的判据，不建跨任务指纹记忆表。
**级别与档位**：L3 重档。改动横跨 `d_policy`（permgate）、`d_execution`（opencode adapter/result）和 `d_orchestration`（工单与任务状态）；仅 policy 的删除、相对路径、heredoc 三项合计已超过约 70 分钟。先做 S3 的 Wave 0，后续按故事分批集成。没有新的对外兼容承诺；只有拆解产生多个共同依赖新接缝的工作单元时才进入 contract 冻结。

## 1. 问题与范围

夜班卡事件 16420 记录每张权限工单成对 WARN、任务临时目录清场反复升级，以及拒绝后 adapter 又合成一张 ask。`$TMPDIR` 纪律块和 import 路径误判已分别在 `d45c078ae`、`4ded5bba1` 修复。本卡交付三件事：

1. 消除已知的子会话 H1 和主会话早到权限 H2 两种双 WARN 事件序，并让等待计时归属可辨。
2. 对确切安全的临时目录删除、heredoc 写入和纯搜索命令减少升级；其他命令沿现有权限门处理。
3. 拒绝导致的空回合不再合成第二张 ask；实时与可辨认的断线对账都产生失败结果。

取证细节、历次反例与代码读数见 [B383 台账](../ledgers/ledger-b383-spec.md)。本稿只保留会改变实现或验收的事实。

## 2. 方案与安全边界

### S1 双 WARN

`permission.asked` 的 `PauseWaiting` 和应答后的 `Resume` 在找不到工具段时各记一条 WARN（`internal/executor/opencode/adapter.go:1619-1637,740-763`）。子会话事件过滤只保留权限请求，丢弃其工具 part（`adapter.go:1432-1457`），所以 H1 的等待没有工具段承载；既有回放还证明主会话「权限早于 running」的 H2 同样双 WARN（卡事件 16677）。

两种事件序都要修：每次等待或计入正确工具段，或只留一条说明不承载的 Info；不能把等待静默计入 api/tool。用 H1、H2 合成回放和现有 spike3/5 序 A 样本判定。下一次真实派发只补充夜班 H1/H2 分布；若未复现，记「未验证」，不据此核销修复。

### S2 静态判据扩容

采用**小型正例闭集**，只认清楚命令形态，不做通用 shell 解释器：

- `rm`：提取每个删除目标；仅任务 `TaskTmpDir` 内的直接目标，或 `cd "$TMPDIR" && rm -rf verify` 这类可证明 cd 已进入该目录的相对目标，才可按 scope 放行。`$TMPDIR` 必须仍是任务注入值。重绑定、`../../`、跨段越界目标、包装器或解析不清时不放宽。rm 目标与现有 `RedirectTargets` 分开判定（`internal/permgate/writeargs.go:44-53`、`redirect.go:48-104`、`path.go:41-68`）。
- heredoc：首批只认卡事件 17074 的 `cd $TMPDIR/cardq && cat > main.go <<'EOF' … EOF` 同构形态：引用的字面定界符、单个 cat 写入 scope 内文件、无管道或执行正文的后继。正文只在**整条命令**符合形态时作为数据跳过；`cat <<'EOF' | bash`、未引用定界符和解析不了的形态均不放宽。裸 `cat` 的消费者身份沿用现有安全命令的信任前提；若执行器的 PATH/函数/alias 能改变其解析，实施节点须先收窄到可信绝对可执行文件，原始案例不得算通过。`cd` 后相对写目标按实际目录判，不再一律按 Workdir（`redirect.go:8-17`）。
- 自指令误判：仅 `grep` 的纯搜索参数和显式 `rg --no-config` 的纯搜索参数可排除参数里的 `handoff` 字样。`rg --pre`、命令替换、执行包装器和真正调用 `handoff` 的形态不享受此例外。`psql -c` 可执行 SQL 或 shell 元命令，不能视为只读搜索词（`internal/permgate/selfcmd.go:85-121`、`blacklist.go:133-165`）。

临时目录写删按上面的 scope 规则；**B=a 的重复升级收口只给可证明只读的搜索正例**。先前用户裁决的人工清单仍须保持 `Escalate`：`git checkout --`、`psql -c`、内联 Python、`rg --pre`，以及以越界 `Paths` 上报的 Go 模块缓存读。仅排除 AutoAllow 不够，因为 `Consult` 可由审批模型直接批准（`internal/permgate/blacklist.go:133-165`、`internal/orchestration/manager.go:2090-2106`）。同任务已有人工 allow 时沿现有复用路径，其他情况建 gate 工单（`manager.go:2127-2137`）；真正的 handoff 自指令和越界路径继续硬升级。跨任务记忆表不做。

### S3 被拒回合终局

现状 `mapIdle` 对被拒空回合发合成 question，`handleQuestion` 因而再建 ask（`adapter.go:2204-2219`、`internal/orchestration/manager.go:2888-2965`）。改为 adapter 发 `result{OK:false, FailReason=被拒描述, VoidReason=权限被拒}`；manager 沿现有 `handleResult` 作废挂起工单、记 `turn_failed` 并落 `waiting_review`，协调者可 `continue`（`manager.go:3414-3530`）。普通零文本失败保留自己的理由，不冒充权限被拒。

拒绝证据必须绑定权限请求及当前父任务回合：API 失败不能记已拒；API 应答与父 idle 先后交错也只能发一次正确终局；子会话 idle 本身不结束父回合；父回合若产出文本，按真实 trailer 分类并清掉拒绝标记；标记不能泄到下一回合。等待 API 结果不能无限挂住任务。`RespondPermission` 当前在 API 成功后才登记拒绝，且 `clearTurn` 不清该标记（`adapter.go:740-789,2376-2380`）；实现节点据此选同步机制，不在 spec 冻结锁或状态结构。

断线对账的 `ToolStatus=error` 同时表示拒绝与普通工具报错（`internal/executor/opencode/reconcile.go:168-169,223-233`）。只有**同一终结工具 part** 的错误精确匹配已验证的拒绝文案，才补同形失败 result；其他情况保留现有 question。`internal/executor/opencode/testdata/session_rejectedend.json` 证明该文案存在，但未记录 opencode 版本；验收须从实际版本新鲜抓包验证。失配不能宣称「断线无第二张 ask」。

## 3. 必交故事与验收

- **S1**：H1、H2 合成回放均不再双 WARN，等待归属正确；spike3/5 回归。夜班原始分布若不可得，单记未验证。
- **S2**：原始 `cd "$TMPDIR" && rm -rf verify` 与卡事件 17074 的 heredoc 命令通过静态门；`../../`、TMPDIR 重绑定、`cat <<'EOF' | bash`、未引用定界符仍升级。纯搜索参数含 `handoff` 不误判；人工清单无同任务 allow 可复用时确实建 gate 工单，不能由模型直批。若裸 cat 的运行环境无法证明，S2 不能通过。
- **S3**：父或子会话权限拒绝使父回合空文本终结时，只有一条失败 result，无合成 ask；任务落 `waiting_review`，`continue` 可用。API/idle 交错、父回合有文本、下一回合及普通工具报错不被误归因。对账只对实测哨兵命中的形态承诺同形结果。

**Wave 0：S3**。以真实拒绝答复穿过 adapter → result → manager → continue，并覆盖子会话与 API/idle 交错；它先验证最危险的回合归属和对账归因。若子拒绝后父回合始终无终局，或当前 opencode 哨兵失配，S3 暂停并回 spec 定恢复/归因，不能用兜底 ask 充数。后续 S1、S2 可独立推进，最终一起集成验收。

**复杂度门**：先复用现有 `mapIdle`/`handleResult`、`idleGen`/`idleTimer` 和 30 秒 API 截止时间。若 plan 仍要新增独立定时器、双份拒绝表或通用 shell 解析器，须指出现有机制无法覆盖的具体红例，以及它能减少哪次真实人工往返；收益不足就保持原有升级路径。不开新 schema、跨任务记忆表或第二套等待计时。

## 4. 架构与验证入口

- `d_policy` 决定静态命令与路径判据；`d_execution` 的 opencode adapter 翻译实时/对账事件，并在执行契约增加准确的 `VoidReason`；`d_orchestration` 消费结果、管理工单与状态、执行已有 allow 复用。adapter 不引入对 policy 的依赖；不改 schema。
- policy 从 `judgeBash` 经 `internal/approval` 到 `Manager.handlePermission` 验证三出口；局部解析测试不能替代生产判定。S1 用真实 SSE 入口的回放，S3 用 adapter 事件到 `handleResult` 的状态/工单断言，并记录 opencode 版本与新鲜拒绝样本。真机验证排 acceptance；单测绿不等于故事通过。

## 5. 本期不做

跨任务指纹记忆表、Go 模块缓存只读范围、opencode 拒绝理由送达模型已记 [roadmap](../../roadmap.md)。`git checkout --`、`psql -c`、内联 Python 不进只读白名单。其他 executor 和 web 审批 UI 不在本卡。卡事件 16420 提到的裸 cd 越界仅在真机证明存在后另裁，不扩大到兄弟 worktree。

**修订留痕**：v1–v5 的裁决和实验逐条保留在台账；v6 按用户「有必要这么复杂吗」收窄正例范围，把实现机制和实验细节归还后续节点，同时保留此前用户裁定的人工审批边界。
