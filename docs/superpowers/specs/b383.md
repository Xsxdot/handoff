## 1. 问题陈述

夜班实测（卡事件 16420）暴露两类成本：**噪声**（opencode 双 WARN 把 agentd.log 冲成噪声场，真实告警被淹；权限门判据假阳性把合法动作升级人工）与**往返**（同类命令反复升级、一次拒绝吃两次人工往返）。四件中两件已修（§2），本 spec 覆盖剩余三块：

1. **opencode 双 WARN**——每张权限工单打两条「未找到工具等待窗口」WARN；
2. **路径/判据假阳性**——rm 黑名单不看 scope（含相对删除目标无判据）、heredoc 正文执行面未定义、只读命令旗标内容误判自指令、cd 越界存疑待证；
3. **拒绝双往返与同类重复升级**——被拒后 adapter 主动合成第二张 ask（实时与断线对账两个面）；同类命令没有任务内已批复用之外任何收口。

## 3. 工作包与方案

### WP1 第 1 项：opencode 双 WARN（结构性修复承诺 + 取证只裁范围与叙事）

**机制事实（已证，与成因无关）**：

- 请求侧 WARN：`permission.asked` 处理登记 `permTiming` 后调 `Segmenter.PauseWaiting`，0 命中即 WARN（`internal/executor/opencode/adapter.go:1619-1637`）；应答侧 WARN：`RespondPermission` 成功后 `Resume`，0 命中即 WARN（`adapter.go:751-763`）。登记先于判定，一次落空必成对。
- **H1（子会话）是结构性成立**：`acceptForeign`（`adapter.go:1432-1457`）对已认亲子会话只放行 `permission.asked`（:1436-1448），其余事件一律丢弃（:1450-1456）→ 子会话的工具 part 永远开不出段（段开启只发生在主会话 `mapPartUpdated`→`ToolStart` 与 `BeginTurn`，均被 acceptForeign 闸住）→ 任何子会话权限请求必然 `PauseWaiting`/`Resume` 双落空、等待不被任何段承载。这是代码结构证明，不依赖现场复现。
- **H2（主会话序 B/C）能产生同形 WARN**：独立评审 harness 实测「permission 先于非空 running」的序同样双 WARN、等待被吞进 api/tool 桶（卡事件 16677）；两份入库样本（`internal/executor/opencode/testdata/spike3-events.jsonl`、`spike5-events.jsonl`，均单会话、序 A、零 WARN）与常态负载未观测到该序。合成反例足以证明现有语义门被破坏，不能因现场频率未知而排除修复。
- 夜班请求的 `is_child` 关联不可得（当晚 agentd 日志在远端执行机，本机 `~/.handoff/agentd.log` 0 命中）。

**修复承诺与取证的角色（v3 收紧）**：

- **H1 修复是本卡承诺**：结构性成因无需现场复现背书，验收主证据 = 子会话合成回放夹具（缝 2）红→绿——修前恰成对 WARN + 等待无承载，修后零 WARN + 等待归属正确；spike3/5 原样本回归零 WARN 不变。
- **H2 修复也是本卡承诺**：以同一等待归属语义消除已知主会话反例；「首个 part 事件即开段、帧与 Detail 延后入参就绪」是可评估方向，由 plan 在不制造空段/错归属前提下定实现。主会话序 B/C 的合成回放须红→绿，序 A 样本回归不变；这不等于断言 H2 是夜班现场根因。
- **取证程序**：下一次真实派发零额外成本挂观测（或一次专用探针任务），留存 `permission.asked` 归属 INFO（`adapter.go:1610-1611` 已带 `is_child`）与成对 WARN 的 permID 关联、对应 SSE 样本（复用既有 probe/抓包机制）。结论只有两种记法：证得分布 → 记录 H1/H2 在现场的分布；**零复现 → 只记「观测窗口内未复现（未验证）」**。现场取证只裁归因叙事，不裁 H1/H2 已证反例的修复范围；故事通过由两类合成回放、原样本回归和语义门裁定。
- **不依赖取证的语义门（无条件生效）**：禁止成对 WARN；每条权限等待必须归属可辨——要么承载计时、要么单条 Info 声明「不承载」；等待不得静默吞进 api/tool 桶（看板不说谎）。

### WP2 第 3 项：权限门判据假阳性（判据扩容，分轮落地）

**现状读数（v3 复核）**：

- 重定向写落点已有提取器：`RedirectTargets`（`internal/permgate/redirect.go:48-104`）摘 `>`/`>>`/`>|`/`n>`/`&>` 落点交 `judgeBash` 落点循环（`permgate.go:225-249`）；其边界明写**不处理 heredoc、不跟 cd**（redirect.go:8），且自记 cd 相对写的误放行残余（redirect.go:15-17：`cd /etc && echo x > passwd` 按 Workdir 拼成范围内）。
- **相对路径解释基准错位**：`InScope` 把相对路径一律按 `scope.Workdir` 解释（`path.go:41-43`）——先 cd 再相对**写**（落点解释错位）与先 cd 再相对**删**（无任何判据，见下条）都悬空。
- **rm 无目标提取器**：`writeCommands`（`writeargs.go:44-53`）无 rm；rm 走 `builtinBlacklist`（`blacklist.go:38`）整串命中即拦（`judgeCommand`，`blacklist.go:133`，不看 scope）。原始场景 `cd "$TMPDIR" && rm -rf verify` 的 `verify` 是**相对删除目标**——v2 的 rm 规则只认临时目录路径、cd 规则只覆盖相对写，相对删除无判据可依（v2 缺口，本稿闭环）。
- **判定次序**：`judgeBash` 落点循环（`permgate.go:242-249`）先于 `judgeCommand` 的安全命令白名单（`safeCommandID`，`permgate.go:267`）——以 `Paths` 上报的越界读在白名单之前就被范围门拦下，白名单扩容救不了这类读。
- 自指令判据已是 3(c) 修后形态（`selfcmd.go` `judgeSegment`），旗标内容仍 fail-closed。

**判据扩容清单**（每条成对给出「放宽后仍拦」的反例，先红后绿；解析不了的形态一律维持升级，fail-closed）：

- **a. rm 目标提取器 + scope 感知**（评审裁定的最危险项，**单独一轮**；**独立造提取器**，不与 RedirectTargets/WriteArgTargets 强制合并——删除目标与重定向写落点语义不同源）：只对可解析的纯字面命令形态放宽；绝对目标解析后必须在 `Scope.TaskTmpDir` 内。`$TMPDIR` 仅可指向本任务注入的 `TaskTmpDir`，不是泛用的 shell 变量展开：命令或可达上下文中有同名赋值、`export`/`env`/`unset`、命令替换、间接展开、子 shell/包装器等会改变其值或无法静态证明绑定的形态，一律升级。**相对删除目标按 cd 解释基准（见 b②，写与删共用）判定**——原始场景 `cd "$TMPDIR" && rm -rf verify`：证明 cd 进入本任务 TaskTmpDir 后，`verify` 按该基准解析，且逐目标检查通过才放行；基准不成立即升级。跨段逐条 rm 逐个目标全过，不局部放行；包装器维持硬拦。反例集：`$TMPDIR/../../etc`、`rm -rf $TMPDIR/a; rm -rf /etc`、`TMPDIR=/etc; cd "$TMPDIR" && rm -rf verify`、`TMPDIR=/etc rm -rf $TMPDIR/*`、`sh -c "rm -rf …"`、cd 出基准后的相对删除。
- **b. heredoc 正文与 cd 相对路径的语义定义（v3 收紧）**：
  - ① **heredoc 豁免只给完整可解析的受限命令形态**：引用的字面定界符（`<<'D'`/`<<"D"`）、一个非执行正文消费者（仅审定的 cat/tee 形态）、无管道/进程替换/命令替换/包装器/执行型后继，且写目标仍过既有 scope 判据，以上全部满足才把该 heredoc 正文当数据从命令判据面剔除。解析对象是**整条命令和所有段**，不是看到 `cat`/`tee` 或引用定界符就删正文；正文外的后继命令、重定向和参数照常判定。`cat <<'D' | bash`、`tee f <<'D' | sh` 即使定界符被引用，正文仍会交给解释器，必须升级；定界符未引用时正文可先被外壳展开执行，也升级。别名/函数/PATH 覆盖等使 cat/tee 实际消费者无法静态证明的形态同样升级。嵌套或解析不了的形态 fail-closed。
  - ② **cd 解释基准（写与删共用）**：相对落点（重定向写、写命令参数位、rm 目标）的解释基准 = 按命令顺序已生效、可静态证明的当前目录；起点为 `scope.Workdir`，每次 `cd` 均须将目标解析到允许基准（Workdir/TaskDir/TaskTmpDir）内，并按解析后目录解释后续相对落点。含未知目录变更、变量重绑定/展开、子 shell 或无法证明路径的命令，不得继续沿用旧基准放行；该条命令升级。`cd /etc && echo x > passwd` 与 `cd /etc && rm -rf verify` 都必须拦住。
  - ③ 09-21 heredoc 升级事件（卡事件 17074）先复现取证、钉住确切触发判据，作为本条红测试来源。
- **c. 自指令匹配面修正（`-c/-e/-E` 旗标内容）**：仅对 `rg`/`grep` 已验证的纯搜索形态，搜索词或 `-e`/`--regexp` 的值含 `handoff` 不作命令位置候选；需验证完整参数形态后才可降噪，未知旗标或不能证明只读的形态维持升级。`rg --pre` 及其他执行型选项、包装器后的真 `handoff`、段首真调用仍走硬门。**`psql -c` 不在例外中**：PostgreSQL 的 `-c` 可执行 `\!` shell 元命令，故即使值看似 SQL/只读也维持人工审批；卡事件 16971 的 psql 假阳性仅记录，不以放宽它收口。本条只缩窄已证明搜索参数的自指令误匹配，不改变路径、写面与其他黑名单判据。
- **d. cd 越界（3(a)）真机取证先行**：worktree 任务的 `Workdir()` 就是工作树本身，裸 `cd` 本在白名单，触发入口是请求带 `Paths`（opencode `external_directory`）——本案可能不存在（评审裁定）。证真才修：只加**本任务**精确路径基准、过 `resolveExistingPrefix`、绝不放 `.worktrees` 父目录或通配。

**拆轮纪律**（评审裁定）：rm（清单 a）单独一轮，不与清单 b/c/d 混做。

### WP3 第 4 项：拒绝双往返 + 同类重复升级（方向已裁定，本节定收口语义）

**现状读数**：

- 一次拒绝 = 两次人工往返的机制链：deny → opencode 零文本终结回合 → `mapIdle` 识别 `turnRejected`（`adapter.go:2204-2219`）→ adapter **主动合成** question（`rejectedTurnQuestion`，`adapter.go:944-956`、发射点 `:2211-2213`）→ `Manager.handleQuestion` 建 `kind=ask` 工单（`manager.go:2888-2965`）→ 协调者再答一次。零文本→result 是 B21、被拒→question 是 2026-08-08 P0（`adapter.go:2205-2207`）——同一反挂死家族的两条目，后者不是 opencode 行为。
- **对账路径是双义面**：row4 判据 `ToolStatus == "error"`（`reconcile.go:168-169`）同时涵盖「权限被拒」与「普通工具报错」，`classifyReconciled` 对 row4 一律补发 question（`reconcile.go:223-233`）。真实抓包夹具 `internal/executor/opencode/testdata/session_rejectedend.json` 里，被拒工具 part 的 `state.error` 为 `"The user rejected permission to use this specific tool call."`；夹具**未记录 opencode 版本**，只能证明这一样本，不能称为跨版本固定协议。实现前提：`SessionMessage` 现只带最后工具 part 的 `state.status`（`api.go:446`），需扩带与该 terminal tool part 对应的 error 文案（adapter 内部模型扩展）。
- **实时拒绝归属有竞态**：`RespondPermission` 在 API 成功后才 `noteRejected`（`adapter.go:740-789`），但 SSE idle 可在另一 goroutine 先经 `mapIdle` 消费空回合（`:2199-2234`），错发普通零文本失败；`clearTurn`（`:2376-2380`）也不清 `turnRejected`，迟到登记可能泄到下一回合。当前 `turnMu` 只保护单次访问，未把 API 结果、回合归属和 idle 分类串成因果序。
- **VoidReason 现两档**（`internal/executor/executor.go:105-110`）：executor 消失 / 回合纪律违规——一次**有意的权限拒绝**两者都不是。另：opencode 现存零文本 result 未设 VoidReason（`adapter.go:2230-2234`），缺省记「executor 已终结」，与其 FailReason「executor 仍在线」自相矛盾（executor.go:99-104 记载的历史审计病）。
- 同任务内 allow 复用是 B57② 冻结语义（`manager.go:2552`、`internal/approval/authority.go` `FindReuse:244-261`：只复用 allow、只同任务内、查询失败 fail-closed）；指纹含快照版本（`fingerprint.go:41-43` + `manager.go:452`）→ 跨任务/跨版本必再升级。

**裁定 A（用户 2026-09-28）：b——被拒终止回合转失败结果**，收口语义如下：

1. **实时路径**：已成功送达 opencode 的拒绝所终结的空回合发 `result{OK:false, FailReason=被拒描述}`，落 waiting_review——拒绝本身就是协调者对「这批动作」的一次决策，第二张 ask 是在重问；`handleResult` 对 `OK=false` 的既有处置（作废挂起工单 → turn_failed 事件 → waiting_review，`manager.go:3414-3530`）负责唤醒，continue 可续。**因果与隔离不变量**：拒绝必须归属发起它的权限请求及回合；API 失败绝不登记为已拒；API 成功但 idle 先到时，终局分类须等到该 API 结果可判定，不能先发泛化零文本结果；终局恰发一次；无论空回合、文本回合、重复 idle 或下一轮开始，旧拒绝标记不得外泄。实现如何在不持 `turnMu` 等网络 I/O 的前提下达成，由 Wave 0 plan 定。既有测试 `adapter_test.go:1612-1628` 随改写，并加可控 API/SSE 交错红测试。
2. **VoidReason 扩档**：被拒终局的 result 必须带**新档作废理由**（语义：「权限被拒，executor 仍在线」）；枚举名归 plan。零文本 B21 路径顺带补 `VoidReasonTurnDiscipline`（消 `adapter.go:2230-2234` 的审计矛盾）。
3. **对账归因（受所测版本约束）**：row4 且**同一 terminal tool part** 的 error 文案精确命中已验证权限拒绝哨兵 → 补 `result{OK:false}` + 同一新 VoidReason 档；哨兵不命中（版本改文案/普通工具报错/文案缺失/part 关联不明）→ 维持 question 现状（fail-closed，绝不误标被拒）。因此「断线后无第二张 ask」只对**已验证哨兵命中的形态**成立，不宣称所有版本无条件成立。验收须记录实际 opencode 版本并从该版本的新鲜拒绝抓包确认哨兵；若失配，明确记故事此分支未达成，回 spec 重定归因，不得把兜底 ask 记作通过。

**裁定 B（用户 2026-09-28）：a——静态判据扩容承接，只收可证明安全的子集**：

- 只读白名单只收**可静态证明只读**的类（如 rg/grep 的搜索词含 handoff 等），每类成对反例。
- **明确维持人工审批的清单**（裁定为终态，不是残余工作）：`git checkout -- <文件>`（写工作树、可覆盖未提交变更）；`psql -c`（任意 SQL，不可笼统认作只读）；内联 python；**Go 模块缓存读**——以 `Paths` 上报时在 `judgeBash` 落点循环（`permgate.go:242-249`）先于安全命令白名单（`permgate.go:267`）被范围门拦下，白名单扩容救不了，承接需 Scope 层「只读基准」语义，另立卡（§8 OOS → roadmap）。
- 跨任务指纹记忆表（原拍板 B 的 b 案）被本裁定否决 → §8 OOS → roadmap 落账。

## 4. 用户故事（验收人视角）

1. 夜班多 plan 节点派发后，已知子会话 H1 与主会话早到权限 H2 两类事件序均不再产生成对「未找到工具等待窗口」WARN；权限等待在计时/日志里归属可辨。两类合成回放红→绿和序 A 原样本回归是主证据；现场未复现只影响夜班归因，不能核销任一已证反例。
2. 执行者在任务临时目录清场 rm（含 `cd "$TMPDIR" && rm -rf verify` 的相对删除）、**整条命令可证明不执行正文**的受限 heredoc 写文件不再升级人工；`cat <<'D' | bash`、未引用定界符、越出基准的 rm（`../../`、跨段、TMPDIR 重绑定、包装器、cd 出基准后的相对删除）仍被拦或升级。
3. 协调者拒绝一次权限后，实时路径不再产生第二张「换方式/跳过/收尾」提问；断线对账在**已验证版本的同一 terminal tool part 哨兵命中时**同样不产生第二张 ask，失配时明确回退且不算此分支通过。API 应答与 idle 的交错不改变该回合归属；普通工具报错不被误标为被拒；作废审计记「权限被拒」新档，不再谎报「executor 已终结」。
4. `rg`/`grep` 经验证的纯搜索参数含 handoff 不再被自指令门误拦；`rg --pre`、段首/包装器后的真 handoff 调用、`git checkout --`、`psql -c`、内联 python 维持人工审批。
5. 取证窗口的结论只记「已证分布」或「未复现（未验证）」两种；H1/H2 的修复通过由各自合成回放红→绿、原样本回归和等待归属语义门裁定。

## 5. 契约语义与接缝（L3）

**职责与权威**（三顶层子系统分立，本卡零转移；域归属按 `codegraph/best.json` 容器映射）：

- **`d_policy`——静态判据权威**：allow/deny/escalate 的命令/路径判据只能从 permgate 产出（`k_permgate_* → d_policy`）；adapter 与 orchestration 不得自设判据（现状不变式：**adapter 不 import permgate**，保留）。
- **`d_orchestration`——工单/状态权威 + 复用判定权威**：`handlePermission`/`handleQuestion`/`handleResult` 消费契约事件、作废挂起工单、迁移 waiting_review，不改写 adapter 已定的终局语义；人工批准复用判定（approval `Authority.FindReuse`，`k_approval_* → d_orchestration`）也在此域——v2 误记其归 policy，更正。
- **`d_execution`——事件语义权威**（`d_execution_adapters`/`d_execution_contract` 为其子域）：SSE 事实 → AdapterEvent（result/question）的翻译只在 adapter（实时 `mapIdle`、对账 `classifyReconciled`），两者的同形/异形状态必须显式声明；契约定义面（`Result.VoidReason` 枚举）在 contract 子域，本卡的枚举扩档是其内部改动，随 implement 落地。
- **依赖方向（现状不变式，本卡零新增跨层通路）**：orchestration（含 approval）→ execution_contract（消费事件）已有；orchestration → policy（判定入口）已有；execution_adapters → execution_contract（产出事件）已有，且**不**依赖 policy。

**事件/数据流（裁定 A=b 后）**：deny API 成功且归属当前回合 → adapter 实时终局 → `result{OK:false, VoidReason=权限被拒档}` → orchestration `handleResult`（作废挂起工单、turn_failed 事件、waiting_review）→ continue 可续。API/idle 顺序不得影响归属；失败或归属不明不得假标拒绝。对账侧经实测版本哨兵归因命中时同形转 result，未命中维持 question。等待计时：adapter `Segmenter` 是唯一计时权威，不产第二计时源。

**Wave 0（重档）**：选 S3 被拒回合竖切：从真实权限拒绝答复，经 adapter 终局事件、manager waiting_review/工单作废，到 continue 入口；覆盖 API 先/idle 先两种交错，并用当前版本抓包验证对账哨兵。它最早暴露「拒绝能否可靠归属回合」和「对账是否有可用归因」两个承重未知。若哨兵失配，暂停 S3 对账分支扇出并回 spec 定归因；H1/H2 与 d_policy 其他独立工作可继续，但最终 S3 不能以 fallback ask 充数。Wave 0 由一个工作单元贯穿既有 adapter/result/manager 缝，当前无独立协作所需的新增冻结契约；后续 breakdown 如形成共同依赖的新接缝，再按条件冻结。

## 6. 实现决定

- 收口层不变：权限判据全收 `internal/permgate`；回合终局语义收在 adapter（`mapIdle` 实时 + `classifyReconciled` 对账归因）；manager 只按既有 `handleResult`/`handleQuestion` 消费。
- schema：裁定 A=b + B=a 组合下**零 schema 改动**（VoidReason 是常量扩档；对账归因是 adapter 内部消息模型扩字段）。

## 7. 测试决定（接缝清单）

- **缝 1｜permgate 判据面（d_policy）**：符号 = `InScope`/`WriteArgTargets`/`IsSelfCommand`（导出）与 `judgeCommand`/`RedirectTargets`（包内、有生产调用方 judgeBash 判定路径），调用方 = `internal/approval`（`EscalateLogLevel` 等）与 `internal/orchestration`（`handlePermission` 判定路径）。表驱动单测断言完整命令形态：quoted heredoc 单消费者可放、引用定界符接 `| bash` 仍升；rm 覆盖任务 TMPDIR 正例、同名变量重绑定、跨段/出界负例；rg/grep 搜索参数正例和 `rg --pre`/psql 负例。边界型判据解析入口可用包内测试，最终仍须穿生产 `judgeBash` 路径。
- **缝 2｜opencode SSE 回放（d_execution）**：符号 = 既有回放 harness 的 wire 输入入口，生产消费者 = `adapter.streamOnce`。子会话 H1、主会话 H2 序 B/C 合成夹具须各自红→绿，spike3/5 序 A 原样本零 WARN 回归；断言等待计时归属，不只数日志（边界型例外：对面是 opencode wire 格式）。
- **缝 3｜回合终局（d_execution ↔ d_orchestration，跨子系统缝）**：符号 = `mapIdle` + `classifyReconciled`/`reconcileTurnEnded`（对账腿），生产消费者 = `Manager.handleQuestion`/`handleResult`。断言：成功拒绝实时改发 result + VoidReason 新档；API 返回/idle 到达交错、API 失败、迟到拒绝登记、下一回合、重复 idle 均恰归属且不泄漏；对账 row4 同一 terminal tool part 哨兵命中转 result、普通工具报错或缺文案维持 question；`session_rejectedend.json` 夹具与记录版本的新鲜抓包；manager 侧 `OK=false` 状态/工单处置及 continue 复用。
- 假缝禁令自查：三缝均须经真实生产消费者；未导出的局部函数只作单测落点，不能单凭其绿灯充当故事验收。无为本轮分支覆盖新抽的纯函数。
