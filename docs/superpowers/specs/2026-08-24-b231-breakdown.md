## 四、缺陷族对抗审查（逐族正面回答）

### 通用五族

**1. 生命周期/状态机中断**
- B231-2 重扫派发中途中断：handoff 任务状态机管（waiting_review/孤儿任务有既有盯法），worktree 由 --new-worktree 机制回收——有既有收尾责任方，本刀不新增孤儿资源类型。
- B231-3 重定标中途中断：target.json 半写状态会让 `codegraph check` 变红（预算数字与留痕不配对）、git 工作区可见——**失败是响的不是静默的**，重跑即收敛。
- B231-1 无长过程。
- 结论：无新增风险，因为三张卡的中断态都落在既有可见机制（handoff 状态机 / git 脏区 / check 红）里，无静默孤儿。

**2. 静默失败/误导报错**
- **本刀最大风险面**：agent 生成式概括伪装成转录——「图里写着一个不存在的意图」，validate/check 全绿也查不出（机内无判据能判 summary 是否来自 doc 注释）。唯一防线是配方红线（B231-1）+ 真机抽查（真机清单第 1 条）。
- 第二风险：B220 本尊——漏文件时 validate 全绿（无盘→图判据）。防线：文件级完整性自检 + 协调者独立重算（真机清单第 4 条）。
- 第三风险：budget-raised 留痕缺条——上调发生了但审计线索没留。防线：B231-3 验收「留痕条数=重定标方向数」两数相等。
- 结论：有风险，三条防线如上，全部落进子卡验收或真机清单。

**3. 跨平台假设**
- 扫描在 linux-01、验收在 mac：wire 内路径全部是仓库内相对路径、`/` 分隔（配方硬纪律），packages key 与 Node.File 目录同构，两平台一致；JSON 无平台相关类型。
- 结论：无，因为接缝上流动的只有仓库相对路径与纯文本，无绝对路径、无平台差异字段。唯一残余（大小写不敏感文件系统撞名）在本仓无实例。

**4. 假红/假绿测试**
- charter 库缝：契约冻结物自带变异复验（TestValidatePackagesDanglingKey 判据反转即红，2026-08-24 跑过）——已锁。
