# B413：下钻 transition 被 usePoll 渲染期 setData 饿死——轮询续帧改非紧急优先级

- **卡**：B413（高优，发现自 B369.9 验收 2026-09-27，根因证据链见卡 note）
- **级别与档位**：**L2**。单子系统（web 前端共享数据层，`d_web_shell` 域内）、不动契约（`PollState` 公开签名零改动、无 wire 变化）。定级两问逐条见 §6。
- **状态**：**已批准**（用户 2026-09-28：spec 摘要过目后答复「继续，派发的节点使用子agent来实现」——批准 spec，并裁决派发节点回落本地 subagent 执行、卡生命周期照走）
- **台账**：`docs/superpowers/specs/b413-ledger.md`（全部现状读数的 `文件:行` 出处与命令原文）

## 1. 问题陈述

compact（390×844）下点击「在此打开终端」下钻：URL 前进到 `detail=1`，但 React transition 永不提交——mobile-home 不卸载、detail-bar 不出现，UI 停留旧态。终端与任务现场路径确定性命中，会话/卡路径当时可用；底栏 tab 切换这类紧急更新能恢复 UI，再点终端又复现。用户不该靠整页刷新换回正确画面——这是本卡的验收底线。

机制类（三条现状读数，出处见台账；卡 note 2026-09-27 为原始证据）：

1. **导航走并发渲染**：`web/src/App.tsx` 用 `BrowserRouter` 且未传 `useTransitions`；react-router-dom 7.18 的 `BrowserRouter` 把 history 驱动的 location setState 缺省包进 `React.startTransition`。compact 全部导航动作（`useMobileNav` 的 enterDetail/setTab/…）= 写 URL = 触发一次可打断的 transition 渲染。
2. **轮询续帧是紧急更新**：`usePoll` 的轮询续帧（`await request` 之后）把 `setData` / `setDisconnected` / `setErrorText` / `setSessionExpired` 全部同步落（默认 sync lane，React 的高优先级）。
3. **流密度与慢源**：Shell 持有八条 usePoll 流（cards/decisions 2.5s、sessions 5s、pty 30s 仅 compact、launchers 30s、tasks 2.5s、tree 30s、previews 等）。任何一条在 transition 渲染的让出窗口解析，sync 更新就打断并重启该渲染；离线机器把 `/api/pty/sessions?scope=all` 扇出拖到 ~3s，拉长命中窗口。终端/任务现场下钻同步改动的状态最多（选基准 + 开新 tab），渲染窗口最长，确定性命中。

A/B 实锤（卡 note ③）：同浏览器 5174 跑 B369.8 基线同样冻结——基线既有 bug，B369.9 的 diff 不是肇因。

## 2. 方案

**usePoll 的轮询续帧状态写入包 `React.startTransition`（非紧急数据语义）；导航侧与 agentd 侧零改动。**

轮询数据天然非紧急：迟一帧提交无用户可感知代价；用户手势与导航是紧急的，保持 sync lane。改后轮询更新进 transition lane，与导航 transition 合并进同一次渲染、一次提交——「sync 更新打断重启 transition」的饥饿回路被拆掉：transition 更新不再打断在跑的 transition 渲染；会重启渲染的只剩真正的紧急更新（用户点击），而点击本来就该重启。

收口在轮询原语一处：usePoll 是全部数据流的共用原语（Shell 五流 + tasks/tree/machines/previews/update 等全部经它），一次修全部流——正中卡上「宜用 usePoll 全局口径，防同类面复发」的指向。

粒度：续帧里 await 之后的**全部**状态写入（含首拉、含断线/会话失效的终止态写入）统一进 transition——断线横幅迟一帧出现可接受，换取所有流同一纪律；不做逐字段的紧急性分类（分类是维护债，且任何一个漏包的写入都保留整条饥饿回路）。用户主动的 `refresh()`（事件处理器上下文）留在 sync，不随续帧降级。

## 3. 弃选与理由

1. **导航侧关 transition**（`BrowserRouter useTransitions={false}` 或 navigate 改写）：不消除干扰源——poll setData 仍是 sync lane，与导航同 lane 的渲染期更新照样触发渲染重启，饥饿机制类原样保留，只是把「transition 被打断」换成「sync 渲染被打断」。且是全局行为翻转（深链/前进后退全部变 urgent），影响面大于收益。
2. **requestIdleCallback / 微任务排队去重**：时序性 band-aid——没有 lane 语义，敏感窗口依旧存在；idle 回调在后台 tab/长任务下不可靠；「去重」对每 2.5s 必变的负载（时间戳、状态集合）无效。
3. **agentd 扇出对不可达机器快速失败、降 deadline**：方向对但层次不对——它缩短的是触发窗口（延迟卫生），机制类（sync 续帧可打断 transition）原样保留，任何一条慢流都能再触发。不进本卡，落 roadmap 作为独立延迟卫生项（见 §8）。

## 4. 全部必交用户故事

- **S1（唯一故事，即卡验收判据的真机走查）**：macbook-pro 离线（ping 100% loss，`/api/pty/sessions?scope=all` 实测 ~3s）状态下，390×844 devtools mobile 模拟：
  - **主走**（确定性命中路径）：mobile-home → 项目详情 → 点「在此打开终端」下钻——URL 前进到 `detail=1` **且 UI 跟随提交**（mobile-home 卸载、detail-bar 出现、工作台露出），全程不使用整页刷新恢复；
  - **补走**（卡判据「任何 compact 下钻路径」）：同一状态下会话下钻、任务现场下钻、文件下钻、目录覆盖层下钻各一次，均 UI 跟随；
  - **桌面反例**：切 ≥1024 宽走同路径，行为不回归。
  - 观察项（非门）：console 不再出现「Cannot update a component (Shell) while rendering a different component (ProjectTree)」——机制类消除的旁证；若仍出现但 UI 全程跟随，以 UI 为准并记录进台账。
  - 验证环境：真机浏览器 + 本机 agentd + 离线 macbook-pro 实况（与卡 note 2026-09-27 的复现环境同款）。

## 5. 实现决定（决策级）

- 收口点：轮询原语的数据写入处（web 共享数据层），现状读数 `web/src/app/data/usePoll.ts:85-97`。落点自查：改「哪个文件哪几行」用户不可察觉，归 plan 细化；本 spec 只定「在原语层收口、消费方零改动、router 与 agentd 零改动」。
- `PollState` 公开签名、轮询节奏参数、三条实时性纪律（document.hidden 停表、断线保留最后数据、401 落终止态不再重试）全部不变。
- 不升级 react-router、不迁移 createBrowserRouter。

## 6. 定级与选档

1. **改动跨几个子系统的契约面？** 1 个——web 前端共享数据层（`d_web_shell` 域内）；不触 agentd、不触 wire。
2. **动不动契约层？** 不动——`PollState` 签名零改动，无跨仓/跨进程契约（含对接）。

单子系统、不动契约。L1 两判据均不中：plan 有真增量（transition 包装的粒度与写点、回归锁形态、桌面回归面核对，spec 末尾三行写不完）；验收非一眼可核（离线真机实走 + 桌面回归）。→ **L2**，路由 plan → implement → review → acceptance → finish。

## 7. 测试决定（真实入口与风险）

- **真实入口**：S1 真机实走是权威验收——本 bug 的本质是 lane 调度时序，mock 与 jsdom 不能完整复现并发渲染的让出窗口，不能替代真机证据。
- **回归锁**：`usePoll` 的测试补一条「续帧更新以非紧急（transition）优先级调度」的行为断言（具体可观测形态归 plan 细化）；既有 tree 186 + Shell 106 全绿是桌面/compact 双路径不回归的结构面证据。
- **风险与降级口子**：transition 化后轮询数据的提交时刻推迟一帧量级——对角标/列表等消费方不可感知；若真机验收发现任何消费方有感知（如断线横幅闪烁），按「终止态横幅类写入单独恢复 sync」的降级口子回 plan 裁决，不动全局口径。

## 8. Out of Scope

- **agentd 扇出快速失败 / 降 deadline**（本期不做、后续要做）：落 `docs/roadmap.md`，来源本 spec §3.3。
- **其他 promise 续帧 setState 源**（WS 消息、createSession 等一次性事件驱动续帧）：机制类相同但非周期性，本卡只收口轮询原语；真机验收若仍见同类症状再立卡。
- **react-router 升级 / 迁移 data APIs**（永不做）：本期无动机。
- **离线机器探活策略与 StateDot 离线口径**：B369 已定，不动。
