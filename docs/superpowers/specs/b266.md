# B266 桌面端从浏览器打开工作项整页

状态：**已批准**（用户 2026-08-29「批准 L2 spec，按这个做」）
定级 **L2**（控制台页面 + 桌面薄壳；不改账本 / agentd HTTP 契约）
卡：B266
日期：2026-08-29

## 问题陈述

谁：在桌面薄壳里同时看工作台 tab 和工作项看板的人。
通道：桌面 webview 里的工作项整页（`/cards`）。
痛点：tab 和工作项页面来回切太麻烦。
要变的事实：工作项页右上角出现「从浏览器打开」；点了之后系统浏览器打开**同一张工作项整页**，桌面仍留在工作项页。浏览器里打开控制台时这个按钮不出现。

## 方案

1. **位置**：`CardsPage` 顶栏右侧（已有健康点的那一行 `ml-auto` 附近）。在 28px 桌面标题栏拖动区**下面**——标题栏里放按钮点下去会变成拖窗口（`DesktopTitleBar` 已写明）。
2. **可见性**：仅 `isDesktopShell()` 为真时渲染。系统浏览器里零改动。
3. **行为**：打开当前工作项整页 URL（控制台同源的 `/cards` 及现有 query，保持当前看板状态）。桌面路由与滚动位置不变。
4. **打开方式**：薄壳用系统浏览器打开该 URL。沿用已有 webkit `external` 通道（与 `requestTitlebarZoom` 同构），Go 侧调系统打开。只允许本控制台同源 http(s) 地址，拒绝其它 URL。
5. **弃选**：放进 `DesktopTitleBar`（点按被拖窗口吃掉）；浏览器里也显示（已经在整页）；点完桌面跳回工作台（用户明确要留在工作项页）。

## 用户故事

1. 桌面打开 `/cards`，右上角看得到按钮。点它，系统浏览器打开同一工作项整页；桌面还停在 `/cards`。
2. 用 Chrome/Safari 打开同一控制台，工作项页右上角没有这个按钮，布局与今天一致。
3. 按钮点在标题栏拖动区之外，第一次按下就是点击，不是开始拖窗口。

## 实现决定

- 探测桌面：已有 `isDesktopShell()`（UA `handoff-desktop`），不新握手。
- 打开浏览器：新增一条与 zoom 同构的宿主消息，由 `desktop/` 打开 URL；消息名与校验在 plan 里钉死。不新增 agentd HTTP。
- 不改账本、不改工作流列、不改 IM/B265。

## 测试决定

接缝：

1. `isDesktopShell` / `CardsPage` 渲染：桌面 UA 有按钮，普通 UA 无按钮。
2. 点击：发出打开当前页 URL 的宿主消息（测 spy，不真开浏览器）。
3. 薄壳侧：同源 URL 打开；非同源 / 非 http(s) 拒绝。
4. 回归：`DesktopTitleBar` 仍无按钮；浏览器布局不变。

## 验收判据（整张卡）

1. 桌面：工作项页右上角有按钮，点了系统浏览器打开同一 `/cards` 整页，桌面仍在该页。
2. 系统浏览器：无此按钮。
3. 相关前端测试与桌面侧校验绿。
4. 本节点该干什么一律以注入的纪律块为准。
