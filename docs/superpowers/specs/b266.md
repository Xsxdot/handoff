# B266 桌面端从浏览器打开工作项整页

状态：**已批准**（用户 2026-08-29「批准 L2 spec 修订，按这个做，走 plan」）
定级 **L2**（控制台页面 + 桌面薄壳 + 既有 `GET /console` 兑换 302 的可选 `next`；不新增路由、不改签发 JSON、不改账本）
卡：B266
日期：2026-08-29

## 问题陈述

谁：在桌面薄壳里同时看工作台 tab 和工作项看板的人。
通道：桌面 webview 里的工作项整页（`/cards`）。
痛点：tab 和工作项页面来回切太麻烦；把当前 URL 丢给系统浏览器会停在登录页（webview 会话是 cookie，系统浏览器带不走）。
要变的事实：工作项页右上角出现「从浏览器打开」；点了之后系统浏览器打开**同一张工作项整页且已有有效会话**（能直接看板，不是登录页），桌面仍留在工作项页。浏览器里打开控制台时这个按钮不出现。

## 方案

1. **位置**：`CardsPage` 顶栏右侧（已有健康点的那一行 `ml-auto` 附近）。在 28px 桌面标题栏拖动区**下面**——标题栏里放按钮点下去会变成拖窗口（`DesktopTitleBar` 已写明）。
2. **可见性**：仅 `isDesktopShell()` 为真时渲染。系统浏览器里零改动。
3. **行为**：打开当前工作项整页（同源 `/cards` 及现有 query，保持当前看板状态）**并且浏览器已登录**。桌面路由与滚动位置不变。
4. **打开方式**：前端仍把当前页 URL 经已有 webkit `external` 通道发给薄壳（协议 `handoff:open-browser:`，不得用 `wails:` 前缀）。Go 侧：
   - 只允许与发送 frame 同源的 http(s) 目标（scheme / host / 有效端口；来源 URL 可能带 ticket，同源判断不比较完整 URL）。
   - **不得**把该 URL 原样交给系统浏览器。
   - 用现有 `IssueAuthTicket` 签一张 60 秒一次性 ticket，把系统浏览器打开到 `/console?ticket=<t>&next=<当前 path+query>`。
   - 签票失败则不打开任何 URL（避免再落到登录页），日志只记 scheme/host/path，**禁止**写完整 URL 或 ticket。
5. **兑换落点**：现有 `GET /console?ticket=` 原子消费 ticket → Set-Cookie → 302。本卡给这个 302 增加可选 `next`：
   - `next` 必须是相对路径：以单个 `/` 开头、不以 `//` 开头、无 scheme、无 host、无 userinfo、无 `\`、无控制字符。
   - path 必须以 `/cards` 开头（本卡按钮只在工作项整页）。
   - 合法则 302 到该 path+query；非法或缺省则仍 302 到 `/`（会话照样建立，只是落点回退）。
   - 不新增路由、不改 `POST /api/auth/tickets` 的响应 JSON。
6. **弃选**：放进 `DesktopTitleBar`（点按被拖窗口吃掉）；浏览器里也显示（已经在整页）；点完桌面跳回工作台；把 webview cookie 共享给系统浏览器；签票失败时回退打开裸 `/cards`。

## 用户故事

1. 桌面打开 `/cards?project=handoff`，右上角看得到按钮。点它，系统浏览器打开同一工作项整页且**已经登录**；桌面还停在 `/cards`。
2. 用 Chrome/Safari 直接打开同一控制台（无桌面 UA），工作项页右上角没有这个按钮，布局与今天一致。
3. 按钮点在标题栏拖动区之外，第一次按下就是点击，不是开始拖窗口。
4. 系统浏览器若拿到非法 `next` 或没有 `next`，兑换成功后落在 `/`，不得出现开放重定向。

## 实现决定

- 探测桌面：已有 `isDesktopShell()`（UA `handoff-desktop`），不新握手。
- 打开浏览器：沿用 `handoff:open-browser:` 与 `HandleExternalBrowserMessage` 的同源校验；在校验通过之后、调用 opener 之前签 ticket 并改写目标。
- agentd：只改 `GET /console` 兑换成功后的 302 目标选择（可选 `next`）。签发、cookie、ticket 寿命（60 秒）不动。
- 不改账本、不改工作流列、不改 IM/B265。
- 定级维持 L2：这是既有控制台入口的延伸（可选 query），不新开契约面。

## 测试决定

接缝：

1. `isDesktopShell` / `CardsPage` 渲染：桌面 UA 有按钮，普通 UA 无按钮。
2. 点击：发出打开当前页 URL 的宿主消息（测 spy，不真开浏览器）。
3. 薄壳侧：同源 URL 才继续；非同源 / 非 http(s) 拒绝；通过后 opener 拿到的是 `/console?ticket=…&next=/cards…`，不是裸 `/cards`；签票失败则 opener 不被调用。
4. agentd 兑换：合法 `next=/cards?project=handoff` → 302 该地址且 Set-Cookie；`next=//evil.test`、带 scheme、非 `/cards` 前缀 → 302 `/`；无 `next` → 302 `/`。
5. 回归：`DesktopTitleBar` 仍无按钮；浏览器布局不变；完整 URL/ticket 不得出现在日志字段。
