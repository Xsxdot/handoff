本节点该干什么一律以注入的纪律块为准。

## 定级理由

跨子系统：HTTP 门面（gateway）与任务编排（orchestration）今日同包 `internal/agentd`，编译器无法封界。本卡只切这一条出站边：gateway 生产持有编排 **client 接口**，`Manager` 迁到自己的包。同进程、不升 HTTP/MQ。单条缝、一轮可收口 → L3 轻档。不把编制门面、工作区 git、`ExecutionClient`、编译期 `internal/` 封界塞进来。

## 问题陈述

谁：agentd 进程里的 HTTP/WS 门面要把一次任务生命周期动作交给编排。

条件：`Server.mgr` 的类型是 `*Manager`，与 `Server` 同包。目标图把 `server.go` 登成组装点，于是 handler 直调 `Manager` 被豁免；`legacyBudget: 321` 锁的是这个现状，不是完成态。并发 `Done`：两个请求都看到 `waiting_review` 后，第二个 `transit` 对已是 `completed` 幂等成功，两边都 `Release`。`Release` 无任务身份；同载体上还有别的非终态任务时会误减。

通道：现有 HTTP dispatch/continue/done/stop 与卡节点 `stepTransport`。不新造跨机协议。

要变的事实：

1. **`Server` 的生产字段不再是 `*Manager`。** handler（不含真组装/wire）持编排 client 接口。`*Manager` 只在组装点 `new`。
2. **`Manager` 不在 `internal/agentd` 包。** 进独立编排包。gateway 不得 import 该包的内部实现（组装点除外）。
3. **终态占用只核销一次。** 只有真正把任务迁到终态的那一次调用 `Release`。`transit` 看到「已经是目标态」只表示幂等成功，不表示「我是释放者」。`Done` 与 `Stop` 同一条。

谁能观察到：gateway 源码（handler）里没有 `*agentd.Manager` 字段；`go build` 在 handler 文件 `import` 编排 `internal/` 时失败（本卡先做到包分离；编译期 `internal/<sub>/internal/` 留给 B233.17）。重复/并发 `Done` 不会把同载体别的任务占用打到 0。

## 方案

同进程走公开 client。接口定义在 **使用方 gateway**（架构法第九条），实现是迁出后的 `Manager`。

- 新包承载 `Manager` 及其仅服务编排的同包文件（状态机、审批组装、卡节点执行侧等）。HTTP/WS handler、`NewServer` 留在 gateway 包（可仍叫 `internal/agentd`）。
- gateway 定义 `OrchestrationClient`（名字以 contract 冻结为准），方法覆盖 handler 今日对 `s.mgr` 的生产调用。测试替身实现同一接口。
- 组装：`main` / 现有 bootstrap 把 `*Manager` 赋给 `Server` 的接口字段。`server.go` 整文件仍在 assembly 名单 **本卡不撤**（撤名单是 B233.17）；本卡做到「字段类型已是接口」。
- `Done`/`Stop`：状态迁移必须 CAS（期望态 → 终态）。只有本次 CAS 成功的调用才 `Release`。已在终态的第二次请求 HTTP 仍可 200（幂等），但不得再 `Release`。

**弃选**

- **只加接口、Manager 留在 `agentd` 同包。** 同包没有内部可见性，client 是戏。否。
- **拆成两个进程或同进程 MQ。** 架构法第四条低档优先。否。
- **本卡撤 `server.go` assembly、落 `internal/<sub>/internal/`。** B233.17。否。
- **本卡改编制 `*Service` 持有、迁 git、换 `ExecutionClient`。** B233.14/15/16。否。

## 用户故事

1. HTTP `POST .../done` 并发两次：任务成为 `completed` 一次；载体占用只减一次。第二次响应仍成功（幂等），占用数字不变。
2. gateway handler 源文件类型上不再出现 `*Manager`。组装点仍能 `new` 编排实现并注入。
3. OpenCode 免审投递行为保持 B233.12：钩子不回传，adapter 回传一次。迁包不得把 `bindApproval` 绑回会 `RespondPermission` 的函数。

## 契约语义与接缝

- 编排是任务生命周期的唯一写入者（dispatch/continue/done/stop/reclaim…）。gateway 只做 HTTP/WS 与注入。
- 占用释放是终态迁移的副作用，凭证是 CAS 赢者，不是 HTTP 成功。
- 不新增顶层域、跨机协议、事件类型。允许目标图本卡把 `d_gateway → d_orchestration` 的 entries 从 `agentd.Manager` 改成 client 接口名，**预算棘轮到 0 留给 B233.17**（本卡 handler 仍与组装同文件，棘轮会假绿或假红）。

接缝（符号 + 调用方）：

1. **gateway 对编排 client 的 `Done`/`Stop`** — 调用方 `handleDone` / `handleStop`。最高可测缝：并发两次 Done，`Release` 恰好一次。
2. **gateway `Server` 持有类型** — 调用方 `NewServer` / `SetManager`（或后继注入）。生产字段类型是接口，不是 `*Manager`。

假缝禁令：纯改包名的 import 重写不占接缝名额。

## 实现决定

- 命令名、HTTP 路径、事件类型不变。
- 编排包路径以 `internal/orchestration` 为默认，contract 冻结。
- `SetManager` 若改成 `SetOrchestration`，所有测试调用点必须改完，不留双注入。
- B233.12 的 `bindApproval` 绑审计函数、adapter 闸门，迁包后行为不变。
- 不改 `Release` 签名去带 task id——赢 CAS 才调用现有 `Release`。

## 测试决定

1. **并发 Done 只释放一次**（缝 1）：两个 goroutine 同时 `Done` 同一 `waiting_review` 任务。任务终态一次；`Release` 调用次数 = 1。变异：第二次 `transit` 幂等成功仍 `Release`，测试必须红。
2. **Server 持有接口**（缝 2）：编译期/测试断言 `Server` 编排字段类型可赋 fake，不能要求具体 `*orchestration.Manager`（组装测试除外）。变异：字段改回 `*Manager`，handler 测试或类型断言必须红。
3. **B233.12 不回退**：`TestApprovalClientAutoAllowProductionHookDoesNotRespond` 与 `TestClientApproverAllowUndeliveredUntilAck` 保持绿。
