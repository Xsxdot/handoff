# B233.14 编制入站封界：gateway 持门面；接收机自证；空 HOME 可带纪律

状态：**已批准**（2026-09-12，用户原话「三句都进，按你建议做。」）  
定级：**L3**　档位：**轻档**　路由：contract → breakdown →（单轮）implement → review → acceptance → finish  
卡：B233.14（父卡 B233）  
日期：2026-09-12  
台账：`docs/superpowers/ledgers/2026-09-12-b233.14-spec-ledger.md`  
基线：功能线 `cards/B233.1-charter-7` @ `148be3a5`（不合 main；含已合的 B233.13/15）  
来源：父卡入站边 `d_gateway → d_scheduling`（预算 0，entries=`scheduling.Service`）；用户确认三句都进本卡，DIP 同 B233.13

本节点该干什么一律以注入的纪律块为准。

## 定级理由

跨子系统：HTTP/WS 门面（gateway）生产持有并在 `server.go` 内 `new` 编制域具体 `*scheduling.Service`；空 HOME 带纪律的失败发生在编排启动装配读到的身份快照上。同进程、不升 HTTP/MQ。三句收在同一张入站缝上，一轮可收口 → L3 轻档。不把 `server.go` 撤出 assembly、不落 `internal/<sub>/internal/`、不棘轮预算到 0（B233.17）。

## 问题陈述

谁：agentd 前台要把「派给谁、占哪个工位、身份是什么」交给编制域；编排启动任务时要用这次冻结的 HOME 去挂任务纪律。

条件：

1. **门面。** `Server.scheduling` 的类型是 `*scheduling.Service`。`SetupAutomation` 在 `server.go` 里 `scheduling.New(...)`。handler / `receiver_bind` / `scheddispatch` / `schedapi` / `scheddrain` / `coordapi` 直调具体服务。目标图这条边预算已是 0、entries 却仍是具体 `scheduling.Service`——「走门面」锁的是现状类型名，不是「gateway 只持使用方接口」。
2. **自证。** 接收者（具名载体或小队）的物理身份（机器、CLI、HOME）权威在载体登记（`IdentityOf` / `BindPhysical`，B233.5/7/10 已冻）。本卡不重写这些规则。缺口是前台仍拿着具体 `*Service` 去查、去占，组装也发生在 gateway 文件里。
3. **空 HOME + 纪律。** 空 HOME 是合法身份（沿用该机主 HOME，B334/B347）。非空纪律必须在启动前交给任务层 Profile overlay。今日 `prepareTaskProfile` 在 `HomeDir == ""` 时直接失败，空 HOME 载体无法带纪律。

通道：现有 HTTP 派发 / 卡节点 / 编制登记与探测 API。不新造跨机协议。

要变的事实：

1. **gateway 生产字段不再是 `*scheduling.Service`。** handler（不含真组装/wire）持编制 client 接口。`*Service` 只在组装点 `new`。
2. **`scheduling.New` 不在 `server.go`。** 与 B233.13 的 `NewManager` 一样，只在 `cmd` 组装。`SetKnownMachines` 同迁。
3. **接收机自证经门面核名与准入。** 身份内容仍来自载体登记；请求不得改写机器/CLI/HOME。gateway 不凭 `--target/--executor` 拼身份。既有 `IdentityOf`/`BindPhysical` 测试保持绿。
4. **空 HOME 不得拒绝非空纪律。** `Task.HomeDir` 身份快照保持空串（不在探测/转发层改写成绝对路径，B347）。任务纪律仍落任务目录；Profile overlay 若需要写入路径，用任务级落点或把空 HOME **临时展开**为主 HOME 作为写入点，不得改写已冻结的身份字段，也不得写入载体全局规则。

谁能观察到：gateway 生产源文件类型上不再出现 `*scheduling.Service` 字段；`scheduling.New` 只出现在组装点。空 HOME 载体派发且纪律非空时任务能启动，不再报「无法准备非空纪律 Profile overlay」。载体登记的机器/CLI/HOME 仍是开工环境。

## 方案

同进程、使用方定义接口（架构法第九条）。编制规则引擎已在自己的包，本卡只收口持有与组装，并补空 HOME×纪律。

- gateway 定义编制 client 接口（默认名 `SchedulingClient`，contract 冻结）。方法覆盖生产路径今日对 `s.scheduling` 的调用。测试替身实现同一接口。
- DTO / 包级纯函数（`Binding`、`Carrier`、`IdentityOf`、`BindPhysical`、`ResolveLookup`…）**留在编制包**。gateway 为用这些类型可以 import `internal/scheduling`；生产字段类型必须是接口，禁止 `*Service`。`Service` 不 import gateway——无环，不必把 DTO 搬进 gateway（与 13 的 D1 不同，因为实现早已不在 gateway 包）。
- 组装：`cmd` 在账本就绪后 `scheduling.New` + `SetKnownMachines` + `SetScheduling`。`SetupAutomation` 不再构造 `Service`。`server.go` 仍在 assembly 名单，本卡不撤。
- 自证：不改 B233.5/7/10 已冻的身份规则。前台只经 client 核名、准入、释放；身份快照写入任务后编排只读快照。
- 空 HOME×纪律：删掉「无 HomeDir 则拒绝非空纪律」这条门。overlay 写入任务级路径；空 HOME 展开主 HOME 只作为写入点，不回写 `Task.HomeDir`。

**弃选**

- **只改 `SetScheduling` 形参、`New` 仍留在 `SetupAutomation`。** 组装仍在 gateway 文件，与 13 已否的「同文件绑定」同类。否。
- **把 DTO 搬进 gateway（照抄 13 D1）。** 实现已在编制包，搬 DTO 制造无环必要之外的搬迁。否。
- **把接口放进 `schedclient`。** 接口归使用方，不归 Registry 端口包。否。
- **拆进程 / 新 HTTP。** 架构法第四条低档优先。否。
- **空 HOME 在探测或转发层改写成绝对路径再送给远端。** B347 永不做。否。
- **本卡撤 assembly、落 `internal/<sub>/internal/`、预算棘轮到 0。** B233.17。否。
- **重写 `IdentityOf`/`BindPhysical`。** 已冻，本卡只经门面消费。否。

## 用户故事

1. 前台生产字段类型是编制 client 接口。组装点仍能 `new` `*scheduling.Service` 并注入。测试可用 fake，不要求具体 `*Service`。
2. 点名已登记载体派发：开工环境等于该载体登记的机器、CLI、HOME。请求里另写一套机器/引擎/HOME 且与登记不同 → 失败（既有）。
3. 载体 HOME 为空（主 HOME），本次派发带非空纪律：任务能启动；纪律在任务级可见；载体全局规则文件不被这次 overlay 改写。`Task.HomeDir` 快照仍是空串。
4. B233.13 并发 Done 只释放一次、B233.12 免审投递，行为不回退。

## 契约语义与接缝

- 编制域仍是名称解析、准入占用、载体/小队登记的唯一权威。gateway 只做 HTTP/WS 与注入。
- 物理身份来自载体登记。空 HOME 是身份值，不是缺字段。
- 任务纪律是任务级 overlay，不是载体全局规则。空 HOME 不构成「不能带纪律」。
- 不新增顶层域、跨机协议、事件类型。目标图本卡把 `d_gateway → d_scheduling` 的 entries 从具体 `scheduling.Service` 改为 client 接口名（外加仍允许的包级纯函数）。**预算保持 0，棘轮不在本卡。**

接缝（符号 + 调用方）：

1. **gateway 对编制 client 的持有与注入** — 调用方 `SetScheduling` / 生产 handler。字段可赋 fake；`scheduling.New` 不在 `server.go`。最高结构缝。
2. **空 HOME × 非空纪律的启动装配** — 调用方编排 `prepareTaskProfile`（由派发启动路径调用）。空 `Task.HomeDir` + 非空 `Discipline` 成功；变异把「空 HOME 直接 return error」加回必须红。最高行为缝。

假缝禁令：纯改字段名的重命名不占接缝名额。`IdentityOf` 既有测试不另占本卡接缝名额（回归）。

## 实现决定

- 命令名、HTTP 路径、事件类型、载体登记 JSON 键不变。
- 接口默认名 `SchedulingClient`，注入名保留 `SetScheduling`（与 13 保留 `SetManager` 同款），contract 可改但须改完全部调用点。
- `facadeAsRegistry` 仍是账本→Registry 适配，留 gateway；组装点把它交给 `scheduling.New`。
- 不改 `Release` 签名。
- 空 HOME overlay 不得写载体 `Rules`/`Skills` 全局文件。

## 测试决定

1. **持有接口**（缝 1）：生产 `Server` 编制字段可赋只实现接口的 fake；断言生产 `server.go` 不含 `scheduling.New`（组装测试除外）。变异：字段改回 `*scheduling.Service` 或 `New` 搬回 `SetupAutomation`，测试必须红。
2. **空 HOME 可带纪律**（缝 2）：构造 HOME 为空的载体身份 + 非空纪律正文走启动装配，`prepareTaskProfile`（或其所在启动路径）成功。变异：恢复 `HomeDir==""` 即失败，测试必须红。
3. **自证不回退**：既有 `IdentityOf` / `BindPhysical` / 显式空 HOME 覆盖非空身份拒绝，保持绿。
4. **出站不回退**：`TestB23313ConcurrentDoneReleasesOnce`、B233.12 AutoAllow 钩子测试保持绿。
