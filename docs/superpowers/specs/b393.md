## 1. 问题

唤醒被正确认领并**正确路由**到承载机后（本次已证实：本机转交、linux-01 走本机分支 ✓），执行阶段失败：

- **resume 挂死**：linux-01 上两个 `opencode run --format json -s ses_f45bc164…` 子进程启动后 12+ 分钟无返回（`STAT Sl / WCHAN ep_poll`），两条认领 `done_at` 至今为 NULL；
- **重建也没兜住**：`keystone.go:159-166` 在 resume 失败后尝试重建，重建也失败 ⇒ 落 `needs_human: 协调者唤醒失败：resume 与重建均不可用`；
- **执行期无可见信号**：5 分钟租约 + 30 分钟回合上界之外，没有任何「正在进行」的读数；缺省日志级别 `warn` 把这条链的 Info/Debug 痕迹全部吞掉（连 ERROR 在 21:46:26 后也缺席——**未解释**，见卡）。

## 2. 本节点（debug）的第一问

**为什么 `opencode run -s <会话>` 会挂死而不是快速失败？** 必须给出根因与可复现的红色回路，候选面（逐一证伪，不要只挑一个）：

1. 会话存储不可达：旧会话由另一 HOME/另一 serve 创建，`-s` 找不到该会话时既不报错也不退出；
2. 协调者路径不启 serve（已核 `internal/executor/opencode/coordinator.go:30-50`），但 CLI 侧可能等待某个不存在的前提（stdin/交互/锁文件）；
3. 回合上界（30 分钟）与租约（5 分钟）不匹配：挂死期间租约已过期，认领可被抢走而回合仍在跑；
4. 缺省 `warn` 级别掩盖了 CLI 侧 stderr 的关键行（`hostapi/driver.go:153-156` 只把 stderr 尾部抛给上层）。

## 3. 范围

**做**：resume 挂死的根因与红色回路；resume 失败→重建这条退化链的真实可用性（`keystone.go:159-166` + `scheddrain.go:295-336`）；唤醒回合的**执行期可见信号**（warn 级日志 + 账本事件 + 「在途」读数）。
**不做**：不动路由与承载记录（已验证正确；`scheduling.go:184` 把字面量 `"local"` 对全机器判本机的隐患单独记账，不在此卡顺手改）；不改宿主会话的存续/回收语义（另议）；不清理线上任何状态。

## 4. 验收判据

1. **根因**：给出挂死的根因（file:line + 实测复现命令与原文）；不做完这步不许提修复。
2. **红色回路**：能复现该挂死或其触发条件（确定性、秒级到分钟级、agent 可跑）；修后能变绿。
3. **可见性**：唤醒回合开始/结束落 ≥WARN 日志 + 一行账本事件；不设 `HANDOFF_LOG_LEVEL` 时也能看到（今天 `driver.go:127` 是 Info ⇒ 该测试今天必红）。
4. **退化链**：resume 失败时，重建要么真的可用，要么给出明确的降级决策并落账（不许"两条路都不通还静默"）。
