### 0.2 待拍板新岔口（本稿拆解中发现，均未覆盖于冻结物）

**P1｜`SetManager(OrchestrationClient)` 后，活配置与工作区兜底注入的落点。**
现状 `Server.SetManager`（`internal/agentd/server.go#Server.SetManager` `:369`）除赋值外还做两件只有包内可见才能做的事：`m.conf = s.conf`（把 Server 的活配置取值函数注入 Manager，B160 §4.2）与 `if m.ws == nil { m.SetWorkspace(NewGitCapability()) }`。参数改成接口后两件都做不了（`conf` 未导出、`ws` 未导出）。两选一：
- **方案 A（推荐）｜组装点接线。** `SetManager` 只保留 `s.mgr = m` + 日志；活配置与工作区兜底移到 `cmd/agentd.go`：新增导出访问器（如 `Server.Conf() func() *config.Config`）交给具体 `*orchestration.Manager`（cmd 持有具体类型，可调导出方法）。优点：不动已冻结接口（§5.1 #3「方法集 = handler 调用闭包，不加 handler 未用能力」）；依赖方向仍 gateway←orchestration。代价：`Server` 新增 1 个导出方法；测试若依赖「SetManager 顺手注入活配置」需改到组装路径。
- **方案 B｜扩接口。** 给 `OrchestrationClient` 加 `SetLiveConfig`/`SetWorkspace` 之类方法。优点：`SetManager` 语义不变。代价：**越界**冻结 §5.1 #3（新增 handler 未使用的编排能力），须退回 contract 重冻。

**裁决：A。** `SetManager` 只赋值 + 日志；活配置与工作区兜底在 `cmd/agentd.go` 组装。`Server.Conf()` 可导出给 cmd。否掉 B（扩接口要退回 contract）。

**P2｜随 Manager 迁包的测试如何归置（import 环约束）。**
`internal/agentd` 现有约 23 个测试文件构造/引用 `NewManager`/`Manager`（`manager_test.go` 11 处、`server_test.go` 16 处、`integration_test.go`、`reclaim_test.go`…），且多数是**内部测试包** `package agentd`（实测 `manager_test.go:15`、`export_test.go:1`）。`internal/orchestration` import gateway 后，`package agentd` 的内部测试若再 import orchestration 即构成 Go import 环、编译失败。归置方案：
- **方案 A（推荐）｜按归属拆两处。** 只测 Manager 的测试整文件迁到 `internal/orchestration`（随实现走，仍可用包内可见）；同时驱动 `Server`+`Manager` 的跨缝测试改写为**外部测试包** `package agentd_test`（`internal/agentd` 已有先例：`server_test.go`/`integration_test.go`/`hub_test.go`/`status_test.go`/`lock_test.go` 均为 `agentd_test`），经导出 API（`agentd.NewServer` + `orchestration.NewManager`）组装。优点：不破 import 环；跨缝测试落在外层天然只依赖导出面。代价：内部测试文件集重排，属既定迁包成本。
- **方案 B｜保留 `package agentd` 内部测试。** 需要 gateway 侧保留 `*Manager` 可引用类型（别名/转发）或让测试不 import orchestration——与本卡「Manager 迁出 agentd」直接冲突，否。

**裁决：A。** Manager 单测随迁 `internal/orchestration`；`Server`+`Manager` 跨缝改 `package agentd_test` 经导出 API 组装。否掉 B。

**P3｜Manager 依赖的 gateway 包内助手：导出 vs 随迁。**
迁包后 orchestration 是独立包，无法访问 `internal/agentd` 的未导出标识符。实测（本工作树）move 集至少依赖以下 gateway 包内符号：`checkProcHeadroom`（`internal/agentd/admission.go:53`）、`recoverTransit`（`internal/agentd/watchdog.go:595`）、`resolveProject`（`internal/agentd/projectresolve.go:67`）、`resolveDispatchBase`（`internal/agentd/workspace.go:1099`）、`truncateRunes`（`internal/agentd/server.go:2624`）、`gitProbe`（`internal/agentd/workspace.go`，`assembleResultRef` 用）、`voidTicketsWithAudit`（`internal/agentd/ticketvoid.go:46`）。两选一：
- **方案 A（推荐）｜只导出必要符号，工作区实现（`workspace.go`）留在 gateway。** spec 明确「本卡不迁工作区 git（B233.15）」，`workspace.go` 整文件留 gateway，仅供迁出代码经导出入口调用。导出面按编译错误收敛到最小集；这是 gateway 包内导出，**不是新增跨域契约边**（域归属不变）。代价：gateway 导出面增加若干符号；需逐条判断是否确无 gateway 内其它实现复用即可导出。
- **方案 B｜把 `workspace.go`/`admission.go`/`watchdog.go` 等随 Manager 迁走。** 与 spec「工作区 git 迁出 = B233.15」「不迁编制/工作区」冲突，越界，否。

**裁决：A。** 工作区实现留 gateway；只导出迁包编译所需最小符号。否掉 B。导出面若超出 `checkProcHeadroom`/`recoverTransit`/`resolveProject`/`resolveDispatchBase`/`truncateRunes`/`gitProbe`/`voidTicketsWithAudit`，先回协调者，不得整文件搬走。

**P4｜DTO 在 gateway 内的物理落点与图归属回写。**
D1 定了 DTO 留 gateway，但未定它落在哪个 gateway 文件、以及 `codegraph/best.json` 的容器归属。现状三个 DTO 物理在 `manager.go`（`DispatchReq:468`、`RecoverReport:3152`）与 `projectadmin.go`（`RegisterProjectReq:80`）——这两文件要迁/拆。两选一：
- **方案 A（推荐）｜新建 gateway 文件承载 DTO（如 `internal/agentd/orchestration_dto.go`），随 `orchestration_client.go` 归 `d_gateway`。** 迁 Manager 时把三个类型声明原样挪出，避免 gateway 文件反向被 orchestration 带走的错觉；`best.json` 新增/移动对应容器到 `d_gateway`。
- **方案 B｜DTO 留在 `orchestration_client.go` 同文件。** 文件职责混合（接口 + 三类 DTO），但少一个文件。
> 无论 A/B，`orchestration_client.go:9-12` 注释与 contract §10.1 必须同步更正（否则 review 对不上账）。

**裁决：A。** 新建 `internal/agentd/orchestration_dto.go` 承载三个 DTO，随接口归 `d_gateway`。否掉 B（接口文件混三类 DTO）。`orchestration_client.go` 顶部「随 Manager 迁走」注释必须改成 D1。

**P5｜接口字段的 typed-nil 防护。**
`Server.mgr` 改为接口后，`s.mgr == nil`（handler 未就绪判据，如 `handleDone` `:1720`）对「接口里塞了 `(*orchestration.Manager)(nil)`」不再成立——typed-nil 陷阱会让 handler 越过 503 检查后空指针。两选一：
- **方案 A（推荐）｜`SetManager` 入口拒绝 typed-nil。** 接参时显式判空并落 `s.mgr = nil`；补一条测试锁「传 typed-nil 后 handler 仍 503」。属 gateway 内部健壮性，不需扩接口。
- **方案 B｜不处理，靠调用方永传非 nil。** 组装点当前只传真实对象；但迁包引入的新组装路径增多 typed-nil 风险，且既有 `if s.mgr == nil` 语义被悄悄改弱，否。

**裁决：A。** `SetManager` 拒绝 typed-nil（落 `s.mgr = nil`）；补测试锁 handler 仍 503。否掉 B。

### `B233.13-impl`｜编排出站封界：Manager 迁出、gateway 只持 client、终态释放凭证是 CAS 赢家

#### ①契约引用

- `docs/superpowers/specs/b233.13-contract.md` §1–§9，冻结清单 §5.1 #1–#6、§5.2 #7–#16、§5.3 #17–#20（重点 §5.2 #8/#9/#12/#13/#14）。

- 协调者 D1/D2 裁决（§0.1，随本节点注入）。
- 执行入口：`internal/agentd/server.go#Server`、`#Server.SetManager`、`#Server.handleDone`、`#Server.handleStop`、`releaseTaskCarrierOccupancy`；`internal/agentd/manager.go#Manager.Done`、`#Manager.Stop`、`#Manager.transit`；`internal/agentd/orchestration_client.go#OrchestrationClient`；`cmd/agentd.go:218-262`。

#### ②意图与为什么（不写实现步骤）

把「出站封界」做成物理事实而非命名游戏：

1. **gateway 生产持有编排 client 接口。** `Server.mgr` 类型改为 `OrchestrationClient`，handler 只依赖接口方法集（= handler 今日对 `s.mgr` 的生产调用闭包）。组装点（`cmd`）构造具体 `*orchestration.Manager` 并注入；gateway 生产文件不 import orchestration（D1）。这样「handler 直调 `Manager`」从被 assembly 豁免的巧合，变成类型上不可表达。
2. **`Manager` 迁出 `internal/agentd`。** 状态机、审批组装、卡节点执行侧的 Manager 同包文件迁入新包 `internal/orchestration`；它 import gateway 仅取共享 DTO/助手（D1）。工作区 git 实现、Hub、HTTP/WS handler、`NewServer` 留 gateway。
3. **终态占用只核销一次。** `Done`/`Stop` 的返回改为 `(TerminalOutcome, error)`；只有本次赢得 `store.UpdateTaskState` CAS 的调用 `Claimed=true`。`transit` 的「已在目标态」幂等分支（`:3731`）只表示成功、不表示「我是释放者」，必须区分返回。handler 仅当 `Claimed==true` 才 `releaseTaskCarrierOccupancy`；第二道已 `completed` 短路仍在 `Done` 之前保留。`Release` 签名不变。

不写实现细节之外的事实：不迁编制（`d_scheduling`）、不迁工作区 git（`d_workspace`）、不换 `ExecutionClient`、不撤 `server.go` assembly、不落 `internal/<sub>/internal/`、不动预算棘轮（全留 B233.14–B233.17）。

#### ③验收（按子系统类型分流 + 缺陷族逐族）

**逻辑型：`d_orchestration`（新包 `internal/orchestration`）**

- `go build ./...` 退出码 0；`go vet ./internal/orchestration/ ./internal/agentd/ ./cmd/` 退出码 0。
- 并发 `Done` 恰释放一次：两条 goroutine 并发对同一 `waiting_review` 任务调 `Done`（经真实 `store`/`Manager`），断言两次返回中 `Claimed==true` 恰一次、任务终态恰一次；配合真实 `scheduling.Service` 或既有占用读数装置断言同载体占用**只减一次**，且同载体上另一非终态任务的占用不变。变异：把 `transit` 幂等分支改回返回 `claimed=true`（或 handler 无条件 `Release`），测试必须红。
- `Stop` 同型：非终态 CAS 成功者 `Claimed=true`；已终态者返回 `store.ErrBadTransit`（HTTP 409）且不释放；成功 Stop `WorktreeRemoved==false`（contract §5.2 #11/#16）。
- 接口形状：编译期断言 `var _ agentd.OrchestrationClient = (*orchestration.Manager)(nil)`；测试注入 fake `OrchestrationClient` 到 `Server.mgr` 后 handler 正常服务，且不要求具体 `*orchestration.Manager`（组装点测试除外）。变异：字段类型改回 `*Manager`，断言/编译必须红。

**边界型：`d_gateway`**

- `go build` 证明 handler 源文件不出现 `*Manager` 生产字段；`rg` 断言 gateway 生产文件不 import `internal/orchestration`（D1）。变异：任一 handler 文件加该 import，构建/静态断言必须红。
- `handleDone`/`handleStop` 释放门：仅 `Claimed==true` 调 `releaseTaskCarrierOccupancy`（contract §5.2 #12/#13）；已 `completed` 的 `done` 仍 200 且不释放（#9 第二道门）。
- P5 若裁 A：传 typed-nil 到 `SetManager` 后，`handleDone` 仍返回 503 而非 panic；补一条能变红的测试。
- `server.go` 仍在 target.json `assembly`（本卡不撤，contract §5.1 #6）。

**依赖型：`d_protocol`/`d_scheduling`/`d_workspace`/`d_cli`**

- 不改 `Release` 签名、不改状态机、不新增事件类型/命令/路径（contract §5.3 #18/#19/#20）。`go build ./...` exit=0 即证。
- B233.12 回归：`go test ./internal/agentd -run 'TestApprovalClientAutoAllowProductionHookDoesNotRespond' -count=1` 与 `go test ./internal/approval -run 'TestClientApproverAllowUndeliveredUntilAck' -count=1` 返回 `ok`（contract §5.3 #17）。

**序列化边界**

- `TerminalOutcome` 是进程内 `{Claimed, WorktreeRemoved}` 布尔结果，**无 wire 编码**（contract §8 无命中）。本卡不新增数据字段、不改任何手写投影/DTO 序列化。若实现给 `TerminalOutcome` 或接口参数引入序列化（JSON/wire），**必须退回 contract**。
- 无 roundtrip 属性测试需求；现有事件/HTTP 响应形状不变，由既有测试覆盖。

**追加缺陷族对抗审查**

- **生命周期 / 状态机中断：** 迁包不改变进程生命周期；agentd 重启后 `cmd` 组装点重建 Manager，`RecoverOnStartup`/watchdog 接线保持。既有窗口——CAS 成功（任务已 `completed`）到 handler `Release` 之间崩溃导致占用泄漏——**不是本卡引入**且 `Release` 无 task id 无法幂等补偿；本卡不扩大该窗口（`Claimed` 门不新增写路径）。孤儿资源：无新临时目录/进程。标注：崩溃点占用状态**未验证，需真机**（见 §6）。
- **静默失败 / 误导报错：** 最大风险是「`Done` 返回 `nil` 但 `Claimed=false`」被 handler 误当失败回 500，或反之无条件释放。契约 §5.2 #9 已冻结「`Claimed=false` 且 `err==nil` → HTTP 200 幂等」。实现须保证 loser 不吞错、不误报。P1-A 下 `SetManager` 不再顺手注入活配置，若遗漏则 Manager 读旧配置快照——**静默降级**，须由组装顺序/测试锁住。typed-nil（P5）若放任会从「503 未就绪」退化成 panic，属误导错误。
- **跨平台假设：无，因为**本卡不改路径解析、进程组、权限模型或 webview；仅为 Go 包边界重排。`internal/agentd` 现有 `_unix`/`_windows`/`_darwin` 文件不属 move 集。跨平台编译（`GOOS=windows/darwin go build ./...`）可机内验，不是真机项。
- **假红 / 假绿测试：** 并发 `Done` 测试必须真并发（非顺序两次）、断言**调用方依赖的行为**（占用计数/终态次数），不得只断言内部 `transit` 返回值；必须有变异（去掉 `Claimed` 门 → 红）。接口测试须用 fake 注入 `Server.mgr` 而非只断言类型存在；避免「只断言方法签名」的稳定假绿。禁止用 `Server{mgr: mgr}` 字面量绕过 `SetManager` 的注入语义来验证 P1/P5。迁包后若测试仍绿但 `package agentd` 内部引用被删——须确认不是「测试没跑」（检查 `go test` 包列表含 `internal/orchestration`）。
- **门禁绕过：** 释放路径的唯一门是 `Outcome.Claimed`。须核对：不存在第二条 handler 释放调用绕过该门；`handleDone` 的已 `completed` 短路（`:1746`）与 `Claimed` 门同向、不互相放行；`releaseTaskCarrierOccupancy` 内 `Carrier==""` 与 `scheduling==nil` 的既有关门不变（contract §4）。检查与动作之间：CAS 已由 store 原子保证，`Claimed` 是 CAS 结果的纯传递，无 TOCTOU。
- **序列化边界：** 见上，无新字段，无命中。
- **枚举新值过既有白名单：无，因为**不新增 `TaskState`/`EventType`/`kind`/CLI 子命令；`completed`/`failed` 既有终态复用。
- **承重安全属性有测试锁住：** 「同一任务终态迁移恰一次」「占用释放恰一次」是一致性承重属性，必须各有一条**能变红**的测试（变异去门 → 红）；「`Release` 签名不变」由编译与既有调用点锁住。不得只靠实现恰好为真。

## §6 真机清单（未验证，需协调者执行）
