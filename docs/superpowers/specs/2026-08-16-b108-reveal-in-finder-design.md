# B108 Reveal in Finder（本机半边）设计

> 状态：已定案，待实现。上游 backlog：B108。
> 前置裁决（08-16 用户）：**Electron 路线不翻**（`archive/desktop-console-2026-08-11`
> 的封存决定继续有效），`Reveal in Finder` 用 agentd 的 `open` 端点做**本机那半边**。

## 1. 这份 spec 纠正/收窄了哪些前提

写在最前面，因为下面每条设计都建立在它们之上，读的人先看到结论比看到推导重要。

**1.1 「`machine` 为空」不等于「人坐在这台机器前」。**
控制台的 Host 白名单**不止回环**：`hostguard.go` 的白名单 = 回环三件套 + `cfg.Listen`
的 host + `cfg.Web.AllowedHosts` + **通配监听时本机网卡的非回环 IP**（B104）。
所以浏览器完全可能在 A 机器上、通过 `http://100.73.238.21:7777` 访问跑在 B 机器上的
agentd，而此时 `base.machine === ''`。B108 原始记载里「本机 location → 可解」那句
**隐含了一个没成立的前提**（把「不转发」当成了「同一台机器」）。本 spec 用
**回环判定**补上这个缺口，见 §3.3。

**1.2 B107 的 `os.OpenRoot` 红线在这里不适用，但必须显式说明，不能沉默地不用。**
B107 §3.2 规定所有变更类操作走 `os.OpenRoot`，因为那些操作的产物是 **jail 内的文件
系统效果**，`os.Root` 能全程不出 jail。本端点的产物是一个**要交给外部进程的绝对路径
字符串**，`os.Root` 给不出这种东西（它给的是 fd，`open -R /dev/fd/N` 没有意义）。
所以这里改用 `EvalSymlinks` + 前缀校验，并**承认残留 TOCTOU 窗口**——理由见 §3.5。
**这段论证必须以注释形式落在代码里**，否则下一个人对照 B107 的红线会认为这里漏了，
然后要么「补」一个不成立的 jail，要么把红线本身当成可选项。

**1.3 「控制台会话是弱凭据」这条前提是假的，第三次重申。**
B109 已查实控制台会话在**能力**上等价于主令牌（`s.auth(mux)` 包住全部路由，
`identityFrom` 的四处非测试使用都不限制路由，`POST /api/tasks/{id}/run` 就是
`sh -c`）。真实差别是**持久性/可吊销性**，不是能力。所以本端点的安全论证
**不得**引用「弱凭据」，也**不得**因此给 reveal 加确认层——它既不可逆也不破坏
任何东西。B108 原始记载里给「原生终端」写的那段提权论证同样受此约束（那一项本期
不做，见 §6）。

## 2. 要解决的问题

文件树右键菜单的 `Reveal in Finder` 现在**恒置灰**（`FileTree.tsx:279`），本机与远程
各给一条不同理由。远程那条是结构性的、永远成立；本机那条写的是「暂未实现」——本期
就是把它实现掉。

## 3. 设计

### 3.1 端点

```
POST /api/workspaces/reveal?path=<工作树绝对路径>&rel=<相对路径>
```

- 复用与 B107 五个端点完全相同的工作树白名单入口 `workspaceRootOrErr`（`path` 不在
  已探测到的工作树里 → 400）。
- `rel` 允许为空串（= 揭示工作树根本身）。这与 `DeleteEntry` 不同——删根是灾难，
  揭示根是正当操作，**不要照抄删除那条「空串按非法名拒」**。
- 成功：200 `{"ok": true}`。

### 3.2 明确**不支持** `machine=` 转发

其余所有 `/api/workspaces/*` 端点都以 `forwardIfRequested` 开头。本端点**故意不接**：
带 `machine=` 参数一律 400，报文说清为什么。

理由不是懒得做，而是转发**正是这个端点要拒绝的那件事**——在 mac-02 上执行 `open -R`
会在 mac-02 的桌面上弹开一个**没有任何人在看**的 Finder 窗口。把它做成「能转发但前端
不用」是把一个语义错误留在服务端等人踩。

这是一条**可测的护栏**，也是变异靶子之一。

### 3.3 调用方必须来自回环

`r.RemoteAddr` 的 IP 不是回环 → 409，报文说明「你在通过网络访问这台 agentd，
访达会开在 agentd 那台机器上」。

这是 §1.1 那个缺口的服务端兜底。前端也会据同一条规则提前置灰（§4.3），但**服务端
必须独立判**——前端的置灰是体验，服务端的拒绝才是结论。

**已知不解的边缘**：SSH 端口转发下浏览器访问 `localhost:7777` 而对端 agentd 在远程，
两侧的回环判定都会通过，Finder 开在远程桌面。这**无解**（隧道在设计上就是要让远程
看起来像本地），且后果有限：弹一个窗，用户自己搭的隧道。**如实写进这里，不假装挡住了。**

### 3.4 平台

仅 macOS。

- `var revealSupportedOS = runtime.GOOS == "darwin"`。**用 var 而非 const 的唯一理由是
  测试缝**（同 `hostguard.go` 的 `nicRefreshGap`、`localIPsFn`）——否则 false 分支只有
  在非 macOS 机器上才跑得到，等于不测。
- 非 macOS → 501，报文「这台机器的系统不支持在访达中显示（仅 macOS）」。
- 不做 Linux 的 `xdg-open`/`nautilus`：那是另一套语义（多数发行版没有「选中并揭示」
  这个动作，只能打开父目录），半做一个形态不同的东西比不做更糟。要做另立条目。

### 3.5 路径遏制与残留 TOCTOU

流程：`workspaceRootOrErr` 拿到 `root` → `filepath.Join(root, rel)` →
`filepath.EvalSymlinks` 解析 → 校验解析结果仍在 `EvalSymlinks(root)` 之下 → 交给
`open -R`。

残留窗口：校验之后、`open` 之前，工作树内的目录组件可能被换成符号链接。
**为什么可接受**（这三条是接受的全部依据，缺一条就该重新论证）：

1. 动作是 **reveal-only**：不执行、不改写、不读内容。上限是「Finder 里选中了另一个文件」。
2. 要利用它，攻击者必须已经能在工作树内写符号链接；而具备该能力的调用方**本来就有
   PTY 全权 shell**（§1.3）。这不构成新增能力。
3. 后果发生在**用户自己的桌面上、用户自己看得见**——它不是一条静默的越权通道。

对比 B107 为什么不能这样论证：那里的动作是 `RemoveAll`/`Rename`，上限是**删掉仓库外的
文件**，且是静默的。两者的可接受性不在同一个量级，**不要把这里的让步反向套回 B107**。

### 3.6 执行

- `exec.CommandContext(ctx, "open", "-R", abs)`，5s 超时。
- 参数**不经 shell**（不用 `sh -c`），路径作为 argv 独立元素传入——路径里的空格、
  引号、`$` 都不构成注入面。
- `open` 的实现是**注入缝**：`var revealOpener = func(ctx context.Context, abs string) error`，
  测试替换它以断言收到的绝对路径，不真的弹 Finder。
- 非零退出 → 500，把 `open` 的 stderr 原文带进报文（与 B107 的错误透传纪律一致：
  **不吞成「操作失败」**）。

### 3.7 日志

按 `instrumenting-code`：

- 进入：`s.log.Info("工作树在访达中显示请求", "path", …, "rel", rel, "remote", r.RemoteAddr)`
- 四条拒绝分支各一条 `Warn`，带 `status` 与判定依据（machine 值 / RemoteAddr / GOOS / 解析后路径）
- 成功：`s.log.Info("工作树在访达中显示完成", "root", root, "rel", rel, "abs", abs)`
  ——成功路径不静默。

## 4. 前端

### 4.1 能力位上线

`StatusResp.RevealSupported *bool` + `MachineStatus.RevealSupported *bool`，
JSON 名 `reveal_supported`，**三态纪律与 `PtySupported` 逐字相同**：
nil = 对端太老没上报（**不许当成 false**），false = 平台不支持，true = 支持。

### 4.2 `usePtySupport` → `useMachineCaps`

现有 hook 已经拉了一次 `/api/machines` 并整理成「机器名 → 能力」的三态查询。
Reveal 需要同一份数据，**不再开第二次请求**：把它泛化成同时返回 `pty` 与 `reveal`
两个查询函数，调用点相应改名。

保留原 hook 的两条既有纪律，不得改动：**不轮询**（能力位是平台属性）；
`cancelledRef`/`ranRef` 跨 effect run（StrictMode 下的坑，注释里已有记载）。

### 4.3 置灰规则与理由（互斥，按此顺序判）

| 顺序 | 条件 | 结果 | 理由文案 |
|---|---|---|---|
| 1 | `base.machine !== ''` | 灰 | `远程目录无法在本机的访达中打开（machine: <name>）`（**沿用现文案，不改**） |
| 2 | `location.hostname` 非回环 | 灰 | `你在通过网络访问这台 agentd，访达会开在 agentd 那台机器上` |
| 3 | `caps.reveal('') === false` | 灰 | `这台机器的系统不支持在访达中显示（仅 macOS）` |
| 4 | 其余（**含三态 null**） | 可点 | — |

第 4 行的 null 走「放行」而不是「置灰」，是**沿用 `usePtySupport` 已经写死的纪律**：
「调用方对 null 的正确反应是『照常放行，出了错再说实话』，不是『禁用』」。
老 agentd 不上报这个字段时，用户点了会拿到服务端的 404/501 原文——这比一个凭空
消失的菜单项好。

失败时的错误落到 FileTree 已有的 `setOpError` 那条路（面板透传服务端原文），
不新开一种错误呈现。

## 6. 明确不在本期范围

- **`open -a Terminal`（原生终端）**：B107 已经用控制台自己的 PTY 实现了「在终端中
  打开」，**并且远程也能用**（终端跑在代码所在那台机器上流到浏览器里）。原生终端反而
  只能覆盖本机、且会跑到 handoff 的观测之外（PTY 会话被 ptyhost 记账、能被
  `handoff status` 数到、能被回收；Terminal.app 里那个不能）。**不做。**
- **新建项目的访达目录选择器**：浏览器里拿不到真实路径（File System Access API
  故意不返回，真实前端 spec §9 的既有决策）。Electron 不翻 → 这一条没有变化，
  仍然只能粘贴路径。**不做**，另立 B110 保留。

## 7. 审核者真机复验（本 spec 的验收门）

实现者跑完测试后，**审核者另跑一遍**，与 B107 §9.7 同款纪律：真二进制 + 临时 datadir +
临时端口 + 临时 git 仓库，**不碰 `~/.handoff`**。

必须实测到的五条：

1. 正常 `rel` → 200，且**真的**弹出 Finder 并选中该文件（这一条要人眼确认，
   注入缝测不到）
2. `rel=""` → 200，Finder 选中工作树根
3. 带 `machine=` → 400
4. 从非回环地址发同一请求 → 409
5. `rel=../../etc/hosts` → 400

前端在浏览器里确认第 1/2/3 条置灰理由**逐字**出现。
