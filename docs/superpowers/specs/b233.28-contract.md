## 4. 依赖库既成行为（契约的一部分）

- `store.UpdateTaskState` 先 `GetTask` 读旧态、`proto.CanTransit` 校验、再 `UPDATE … WHERE id=? AND state=?`（CAS），影响 0 行返回 `ErrBadTransit`；`internal/store/store.go:525-552`。回迁竞争的赢家判定只能在这一层，`ResumeIfIdle` 不得自行推断。
- `store.AnswerTicketApplied` 的 `answer IS NULL` 更新条件即幂等键：`n==1` 才 `applied=true` 且 `touchTaskUpdatedAt`；已答同值 `(false,nil)`；不同值/已作废 `ErrTicketConflict`；不存在 `ErrNotFound`（`internal/store/store.go:1275-1305`）。门面**不得**改这条判据——它同时承载「不可重复回答」与看门狗 `updated_at` 的二次告警信号（`store.go:1306`）。
- `store.GetProjectLocationByName` 不存在时 `fmt.Errorf("项目 %s: %w", name, ErrNotFound)`，`errors.Is` 可判（`internal/store/projects.go:82-90`）。门面直通，不重新包装错误（重新包装会断 `errors.Is` 链）。
- `orchestration` 已 import `store`（`internal/orchestration/manager.go` 的 `m.st *store.Store`、`contracts.go` 的 `store` 引用），故门面签名引入 `store.MirrorTask` **不新增依赖方向**；`d_gateway→d_orchestration` 仍是既存方向。
- 本卡不新增/修改任何库（Go 标准库、SQLite 驱动、websocket）的读限、超时、保活、握手时序——纯同进程 Go 方法收口。

### 5.2 实现与行为（实现期判据，本节点不宣称通过）

8. `AnswerTicket` 在 `applied=true` 路径追加 `proto.EventTypeTicketAnswered` 事件（payload `TicketAnsweredPayload{TicketID, Answer}` 逐字）。
9. `AnswerTicket` 对已答同值返回 `(false, nil)`；不同值/已作废返回 `ErrTicketConflict`；不存在返回 `ErrNotFound`（与 `AnswerTicketApplied` 逐字一致）。
10. `AnswerTicket` 校验工单归属该任务：跨任务工单按不存在处理（不泄露信息），与现状 `handleReply` `tk.TaskID != taskID` → 404 同款。
11. `ResumeIfIdle`：任务非 `waiting_answer` 时不动；`waiting_answer` 且 `PendingTickets` 有未答时不动。
12. `ResumeIfIdle`：`waiting_answer` 且无未答工单时把状态迁 `running`；`ErrBadTransit`（并发赢家已迁移）时重读重试，有界（3 次）后只记日志，不返回错误。
13. `handleReply` 改为只调 `mgr.AnswerTicket` + `hub.NotifyAnswer` / `mgr.RelayAnswer`，不再 `s.st.GetTicket` / `s.st.AnswerTicketApplied` / `s.st.AppendEvent`。
14. `handleReply` 的 HTTP 响应逐字不变：正常 200 `{"ok":true,"relayed":true}`；幂等 200 `{"ok":true,"relayed":true,"idempotent":true}`；中继失败 502 `{"ok":true,"relayed":false,"reason":...}` 且落 `delivery_failed`。
15. `handleReply` 成功后调用 `mgr.ResumeIfIdle`；不再持 `s.resumeIfIdle` CAS 循环（该循环迁入编排侧）。
16. 任务查询/项目位置的 handler 改调 `s.mgr` 后，HTTP 响应体、状态码、错误分流逐字不变（含 404/409/500 与空数组归一化）。
