## 问题陈述

谁：把任务派给 `--executor agy` 的协调者。

agy 1.1.24 headless 对未进 `permissions.allow` 的 `run_command` 做 print-mode soft-deny（`user denied permission`）。B305 用显式首词前缀清单绕过它；新首词（如跑分的 `pwd && git status`）不在名单里就会挂，补词要改 Go、重编译、重启 agentd。

B305 禁止 `command(*)` / `--dangerously-skip-permissions` 的依据是：deny hook 下 `uname -s` 仍输出 `Linux`。2026-09-03 linux-01 隔离 HOME canary（不写用户 `~/.gemini`、不重启生产 agentd）证明那是 `-p` 模型终稿，不是命令 stdout：deny + `command(*)` / deny + skip-permissions 的 `touch` 与 `uname -s && touch` **文件均不存在**，stdout 为 `tool call denied by pre-tool hook`；allow 对照文件存在。`command(.*)` 消不掉 native soft-deny；`command(*)` 作为命名空间通配可以。

## 方案

推荐：**任务 `settings.json` 的 `permissions.allow` 只写 `command(*)`。** 原生不再按首词 soft-deny；PreToolUse `handoff-safety-gate` 仍是否决门，审批走 `perm.sock`。argv **不加** `--dangerously-skip-permissions`（那会自动放行未挂钩的 MCP/browser）。不写 `always-proceed`。

弃选：

- 继续维护前缀清单（本卡第一版 `pwd`/`cd`）：新首词再挂、再重启。
- `--dangerously-skip-permissions`：deny hook 对 `run_command` 仍有效，但会跳过所有工具的原生确认，含 matcher 盖不到的工具。
- `command(.*)` / `command(.+)`：合法 grant，deny 有效，但 1.1.24 上仍 soft-deny RunCommand。

## 用户故事

1. 任意首词的 `run_command`（`pwd && git status`、`touch`、未知二进制）在 hook 批准后不再被原生 soft-deny。
2. hook deny 时命令不执行（无文件系统副作用）。
3. argv 没有 `--dangerously-skip-permissions`；任务 settings 没有 `always-proceed`，allow 不是前缀清单。

## 测试决定

缝：`agy.WriteTaskEnv`（`Adapter.Start` / 冷 Resume）。断言写出的 `permissions.allow` **精确为** `["command(*)"]`；全文无 `always-proceed`。`agyArgv` 仍无 `--dangerously-skip-permissions`（已有测试）。

## 实现决定（即 plan）

1. `nativeCommandAllow` 收成唯一项 `command(*)`；注释写清：消 native soft-deny，否决权在 PreToolUse，不是跳过 hook。
2. 测试锁「精确一项 `command(*)`」，删掉「禁止 `command(*)` / 必须含 pwd、cd」。
3. 双语 README 权限模型段与之一致。不部署、不合 main，除非另说。

## Out of Scope

- 永不做：argv `--dangerously-skip-permissions`；`always-proceed`；写用户全局 hooks。
- 本期不做：matcher 扩到 MCP/browser（B304 OOS）；B306 token 写回；生产换二进制（本卡只出分支）。
- 不 reopen B305；B305 spec 正文保留当时读数，本卡取代其「禁 `command(*)`」约束。
