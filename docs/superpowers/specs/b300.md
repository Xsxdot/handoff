# B300 终端 TUI 复制落到本机剪贴板（OSC 52）

状态：**已批准**（用户 2026-08-29「批准」，L2）
定级 **L2**（单子系统 web；不动契约层——ptyhost wire 零改动，OSC 52 是既有字节流内的载荷语义；plan 有增量：重放门、解码规则、失败反馈需落成可执行步骤；验收需真机逐 TUI 复核，非一眼可核）
卡：B300
日期：2026-08-29

## 问题陈述

用户在本机经 handoff 工作台打开远程开发机的终端（xterm.js 前端 → WebSocket → agentd `internal/ptyhost` → PTY），在 grok / opencode 等 TUI 里选中文字会自动复制，但内容到不了本机剪贴板——本机 ⌘V 粘不出刚选的文字。

用户故事：

1. 在工作台终端里跑 grok / opencode，选中文字（TUI 自动复制）后，在本机任意应用 ⌘V 粘贴出该文字。
2. 复制失败（剪贴板权限 / 缺用户激活）时看到明确提示，不再出现「以为复制了、其实没复制」。
3. 刷新页面或终端重连后，本机剪贴板不被终端历史里的旧复制内容改写。

## 根因

TUI 捕获鼠标后自己实现选中与复制，跨 PTY 的标准做法是发 **OSC 52** 转义序列（`ESC ] 52 ; <selection> ; <base64> BEL/ST`），由「终端模拟器」负责写剪贴板。链路上：

- `internal/ptyhost/wire` 对输出字节流无过滤（现状读数：grep 该目录无 osc/escape/filter 逻辑），OSC 52 原样到达浏览器；
- 工作台前端没有任何剪贴板处理（现状读数：`web/src/app/workbench/` 无 clipboard/copy 实现），xterm.js 默认不注册 OSC 52 处理器，序列到达后被直接丢弃。

即「复制」这最后一公里缺在 xterm.js 前端。

## 方案

`TerminalTab` 挂 xterm 时向 parser 注册 OSC 52 处理器：解码 base64 载荷为 UTF-8 文本，通过浏览器 Clipboard API（`navigator.clipboard.writeText`）写入本机剪贴板。写入受三道门约束（激活态门、积压重放门、载荷语义门），失败给出 toast 提示。仅前端改动，ptyhost / WS 契约零改动。

弃选：

- **远端侧方案**（在开发机起剪贴板服务、X11/Wayland 桥）：要动 agentd 与远端环境，链路重，且远端本没有可写的会话剪贴板；OSC 52 就是为此场景设计的标准机制。
- **终端侧选中复制兜底**（shift+拖选让 xterm 自己选中 + ⌘C 绑定 / 选中即复制）：只解决「终端侧选中」，不解决「TUI 自动复制」这个本卡主诉；且终端侧选中 + 右键复制今天已可用。
- **wire 协议加「重放结束」标记帧**：动跨进程 wire 契约，把 L2 活抬成 L3；`attached` 控制帧已带 `backlog_bytes`（现状读数：`web/src/api/pty.ts:114-121`），前端自己计数即可划出重放边界，不需要协议改动。

## 契约语义与接缝

L2 无跨子系统契约。测试接缝清单（每条缝 = 符号 + 调用方）：

1. **OSC 52 载荷解码函数**（新建符号，导出于 workbench 层）：输入 OSC 52 data（selection 参数 + base64 载荷），输出「应写入的文本」或「不应写入」的判定。调用方：TerminalTab 注册的 handler。这是纯函数缝，表驱动测试。
2. **TerminalTab ↔ xterm parser 的注册与写入门**：断言 xterm 实例上注册了 52 号 handler；handler 在「激活态 + 活流 + 合法写载荷」时调用 clipboard.writeText，在后台态 / 积压重放 / `?` 查询 / 空载荷时不调用，失败时出提示。测试载体：TerminalTab.test.tsx 既有的 xterm 整体替身（jsdom 量不了真实字体，已有整套 mock 惯例）。
3. **真机缝**：远程终端里 `printf` 一条合成 OSC 52 → 本机 ⌘V 验内容；再分别用 grok / opencode 真选中复制复验。此缝穿过「TUI → PTY → WS → 浏览器」全链路，是验收的主缝。

假缝禁令自查：缝 1、缝 2 都有生产调用方（TerminalTab），非为测而抽。

## 实现决定（决策级）

1. **只处理写**：`c`（clipboard）与 `s` / `p`（primary selection）任一 selection 参数都写本机剪贴板——浏览器只有一个剪贴板，用户主诉正是「选中即复制」类行为要落到本机。
2. **`?` 查询一律不回应**：OSC 52 载荷为 `?` 是「读剪贴板」请求，浏览器侧不得把本机剪贴板内容回给远端——这是本功能的安全边界。
3. **空载荷忽略**：OSC 52 空载荷语义是「清剪贴板」，不执行——远端不应能清掉本机剪贴板。
4. **激活态门**：仅该终端 tab 处于激活态时写入。B270 起后台终端 keep-alive 持续解析输出，后台 TUI 的复制不应静默改写用户剪贴板。
5. **积压重放门**：`attached` 后先消费 `backlog_bytes` 字节再放行写入；此间历史里的 OSC 52 不写剪贴板。服务端过旧、控制帧缺 `backlog_bytes` 键时不设门（退化接受：同内容重写概率高，且无更好信号）。
6. **失败反馈**：writeText 失败（权限 / 无激活）→ toast 提示复制失败；成功不提示——TUI 自带复制反馈，再加成功提示是噪声。
7. **解码**：base64 解码容忍缺 padding，UTF-8 解码为文本。

## 测试决定

- 缝 1：表驱动——合法写（c/s/p、带/缺 padding、多字节 UTF-8）、`?` 查询、空载荷、坏 base64，各断言到「写入文本 / 不写入」。
- 缝 2：jsdom xterm 替身下断言注册行为与三道门；含「重放期间收到 OSC 52 不写、活流首条写」一支。
- 缝 3（真机，acceptance 主证据）：远程终端 `printf '\e]52;c;<base64>\a'` → 本机 ⌘V 粘出预期文本；grok、opencode 各做一次真选中 → 本机 ⌘V。桌面壳（WKWebView）与系统浏览器各验一遍写入路径。**若某 TUI 真机不发 OSC 52，如实记录并升级裁决**（是否为它补兜底另开小卡），不静默算过。

## Out of Scope

- **⌘C / 「选中即复制」的终端侧复制绑定**——本期不做。右键复制今日已可用；仅当真机验收发现某常用 TUI 不发 OSC 52 时，另开小卡再议（条件触发，非既定后续，不入 roadmap）。
- **粘贴方向增强、图片粘贴**——未在本需求内。
- **tmux `set-clipboard` 等远端会话层配置**——远端用户自配；真机验收时若用了 tmux 需留意这一层。
- **`handoff attach` CLI 渲染流、TuiTab**——前者是只读渲染流无剪贴板语义，后者是帧流渲染页（非 xterm 终端）。
- **ptyhost wire 与 WS 控制帧协议的任何改动**。

## 备注

- 安全备注：OSC 52 本质是「远端进程可请求改写本机剪贴板」的通道，iTerm2 等标准终端同样默认把关或提示。本卡按「用户自己的开发机会话」接受该语义；读查询拒绝（实现决定 2）是安全下界。
