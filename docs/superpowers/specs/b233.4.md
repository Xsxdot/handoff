## 定级理由

工作区能力从任务编排/卡编排抽出，跨 `d_workspace` 与调用它的任务/卡应用。挂卡仍在应用。轻档：不新建产物平台，只收口已有 PrepareWorkspace / 基线 / diff / 清理。

## 问题陈述

任务要能经独立工作区能力准备基线与隔离、执行后拿到可定位的差异和结果引用。执行结束、业务验收、清理是三件事实。清理不得误删仍待验收的结果或无关用户工作。卡绑定由应用负责。push 本卡不改权限归属。

## 现状事实

`PrepareWorkspace` 在 `internal/agentd/workspace.go#PrepareWorkspace`：repo/task 必填，branch 与 new-branch 互斥，new-worktree 免主仓脏检查。Done 清理 managed worktree（`Manager.Done`）。节点 pass 后有推 origin 的路径（不在本卡改）。

## 方案

工作区能力：解析基线、创建或复用隔离工作区、读文件与 diff、定位准确 commit、结果引用、按规则留存/清理。跨机复用 233.3 传输，本卡不发明第二套 git 协议。

复用 vs 独占：new-worktree = 独占隔离；指定已有 worktree/原地 = 复用，脏检查防污染。基线身份：任务保存实际起点 commit，不事后随默认分支漂。

清理触发：取消/失败可按策略留存现场；归档且满足保留约定才回收 managed 树。用户树与无关工作永不当任务垃圾删。

挂卡：应用在调用工作区能力之后写账本（233.3 已把 forward 挂卡迁出）。

### 弃选

隐式改变 push 谁来执行；「有 commit 字段就可以删工作区」。

## 用户故事

1. 普通派发 new-worktree：得到隔离树与基线 commit；diff/结果可定位。
2. 取消后现场仍在，直到明确清理。
3. waiting_review 时清理不得拆掉待验收树。
4. 带 card_ids 建树：树由工作区能力建，卡由应用挂。

## 契约语义

工作区不宣布业务 pass、不授权 push。结果引用含仓库/分支/commit 或可读路径。依赖：任务/卡应用 → 工作区能力 →（跨机）233.3 传输。

## 测试决定

1. **PrepareWorkspace**（调用方 Dispatch）：new-worktree 与复用用户树两条；互斥参数拒发。
2. **结果引用**：代码结果能对上准确 commit。
3. **清理**：managed 树在未验收时不删；取消留存可查。
4. **不挂卡**：工作区 API 不写 card 附件。

## Out of Scope

push 归属（roadmap）；通用产物平台；233.3 传输本体；首次配置。
