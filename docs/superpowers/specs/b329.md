## 问题陈述

谁在什么条件下成为一张卡的协调者：人已经坐在 grok（或 claude）这场对话里，按「坐下」时，系统却只认 agentd 给机器人注入的 `HANDOFF_SESSION_CLI` / `HANDOFF_SESSION_ID`。人开的 grok 没有这两个键，`handoff card bind` 报「当前会话未出示席位身份」。Pi / Codex Desktop / Kimi / 普通终端同样绑不上。

cli + session id 的本意：关掉主会话之后，人仍可出示**自己的**这一对，把席位恢复回来。现网把它做成了「只能从环境变量读」。B307 弃选的 `rebind --to`（把座位指给**别人的**会话当接班者）与「人出示自己的一对」不是同一件事。

现状读数（2026-09-04，工作树 `main` @ `4e633e9a6`；本场 grok 真机 env）：

- 出示函数：`cmd/card_seat.go#currentSeatIdentity`（图 `n_cmd_currentSeatIdentity`；baseline 域名 `d_coordination_cli`，最优树归 `d_cli`）。只读 `HANDOFF_SESSION_CLI` + `HANDOFF_SESSION_ID`，缺一即失败；不读 `USER` / hostname / PID。图 who-calls 只画出 bind 一条边；其余三处调用方以源码为准，记图覆盖债。
- 调用方（同一函数）：`cmd/card_driver.go` 的 `card bind`、`card rebind --self`；`cmd/card_node.go#runStepDispatch` 在卡已有席位时；`cmd/room.go` 的 `room send` 在 `kind != user` 时。
- `card bind` / `rebind` 无 `--cli` / `--session` flag。
- 机器人 Resume 仍注入那两个 `HANDOFF_SESSION_*` 键（`internal/agentd/server.go` 拼 env；B312 合同 §3 第 3 款）。`buildEnv` 以 `os.Environ()` 为底，只覆盖请求里出现的键和 `HOME`，因此无头回合可以同时带着注入对和父进程的 `GROK_SESSION_ID`。本卡不改 Resume 注入，也不改 `buildEnv`。
- 本场 grok：`GROK_SESSION_ID=01a06a5e-9608-7223-a8e3-0b4ca23c87e6`，`GROK_AGENT=1`，无 `HANDOFF_SESSION_*`。
- 席位编码仍是 `cli:<cli>#<session_id>`（`internal/proto/seat.go#EncodeSeatIdentity`）。`bind` 走本地账本 `Store.BindSeat`，不经新的 HTTP 字段。
- 工作台：空座只有「叫机器人」，没有坐下 / 换绑给我按钮（`CoordinatorPanel.tsx`）。本卡不加填一对表单，也不补画禁用按钮。

## 方案

**出示仍是同一个函数。扩展它怎么得到这一对，不改这一对写进账本之后的任何规则。**

来源算法（唯一读法，禁止第三种）：

1. **先看 flag。** `--cli` 与 `--session` 都非空 → 编码为 flag 对。只非空一个 → 失败，不跟任何环境变量拼。
2. **再看注入。** `HANDOFF_SESSION_CLI` 与 `HANDOFF_SESSION_ID` 都非空 → 编码为注入对。缺一或空串 → **整次出示失败**（不落到宿主、不跟 flag 拼）。文案点名缺哪个键。
3. **否则看宿主**（仅当两个 `HANDOFF_SESSION_*` 都未设或都空）：非空 `GROK_SESSION_ID` → `cli:grok#…`；否则非空 `CLAUDE_CODE_SESSION_ID` → `cli:claude#…`。两个宿主 id 同时非空 → 失败，文案要人去掉其中一个或改用手填。宿主键自身空串当不存在。
4. **仍没有** → 失败。文案同时提到到 grok/claude 对话里重试，以及 `--cli` 与 `--session`。

**冲突只剩一句：** flag 对若存在，且注入/宿主按上面规则也会得出一对，两者编码后不一致 → 失败；一致则通过。完整注入对存在时**忽略**宿主键（机器人回归：从 grok 拉起的 agentd 子进程里可以同时有 `HANDOFF_SESSION_*` 和父进程的 `GROK_SESSION_ID`）。禁止环境源互斥失败。禁止用改 Resume / `buildEnv` 来「清理」宿主键。

`--cli` / `--session` 注册在**该命令自己的** flags 上，不进 `PersistentFlags`（那会变成弃选的本机身份登录）。四条出示命令都要挂：`card bind`、`card rebind`（`--self` 使用；`--launch` 带上这两个 flag 必须语义拒绝）、`card dispatch`（仅当本轮会调用出示函数时才使用；见负例）、`room send`（仅当 `kind != user` 时使用；见负例）。不另做「先在本机登录身份」。`card coordinate` 不注册这两个 flag（未知 flag 即拒绝）。`coordinate` / `rebind --launch` 不读这一对去指定机器人会话——那是已弃选的 `--to`。

负例（带 `--cli` 或 `--session` 必须失败，不得调用出示函数、不得改 actor、不得占座）：空座 `card dispatch --step`；无 `--step` 的 `card dispatch`；`--kind user` 的 `room send`。空座 `--step` 继续今日的 `ledgerActor()` 审计语义。

仍然禁止：从 `USER`、hostname、PID、`ledgerActor()`、`web:<addr>` 推导席位；浏览器页当可坐下的对话；看板上填一对；把子会话 id 映射成父会话（子会话用自己的 id 坐下）。

B312 合同修订范围（实现时改文档，避免两份真相）：§2.1 第 2 款改为禁止 `--to` 式接班者，允许出示自己的 `--cli`/`--session`；§3 第 1 款（出示来源）改为本文算法，第 3 款 Resume 注入键不变。编码语法、`BindSeat`/`RebindSeat` 签名、Resume 注入键、Web 不能坐下、HTTP 换绑不接受 `identity`，都不动。

### 弃选

- **只给 grok/claude TUI 注入 `HANDOFF_SESSION_*`，CLI 出示面不动**：关会话后无法恢复；Pi / Kimi / 普通终端仍绑不上；依赖 grok 产品改动。
- **每次都手填，不认 `GROK_SESSION_ID`**：这场 grok 已经带着会话 id，再强迫人抄一遍。
- **给 Pi / Codex Desktop / Kimi 编宿主键**：这张卡没有可核的键，猜当前会话违反 B307「不从环境边角料推导」。它们走手填。
- **恢复 `rebind --to`**：指定别人的会话当接班者，B307 已否。
- **本机身份文件 / `handoff seat present` / PersistentFlags**：多一份会漂的本地状态；手填就写在命令上。
- **看板上填一对 / 补画禁用的坐下按钮**：浏览器不当席位；工作台继续不提供坐下。
- **flag 只给 `bind`**：坐下之后 `--step` / `kind != user` 的房间发言仍会失败。
- **环境源互斥 fail-closed**（完整注入对与 `GROK_SESSION_ID` 不一致就失败）：会打穿从 grok 拉起的机器人出示。完整注入对忽略宿主键。
- **改 Resume / `buildEnv` 剥掉宿主键**：走进 `d_execution_host`，本卡范围外，会抬 L3。

## 实现决定

- 用户可见 flag 名：`--cli`、`--session`。`--cli` 的值是物种名（`grok` / `claude` / `codex` / `opencode` / `agy` …），不是载体名，也不是 `cli:user@host`。注册在子命令本地 flags，不进 PersistentFlags。
- 物种名：`GROK_SESSION_ID` → 固定 `grok`（不要求 `GROK_AGENT` 才能认；有 `GROK_SESSION_ID` 就够）。`CLAUDE_CODE_SESSION_ID` → 固定 `claude`。不认 `CLAUDE_CODE_REMOTE_SESSION_ID`。键名以本场 grok 真机为准；若产品改名，本卡范围不跟改，走手填。
- 仍然走 `EncodeSeatIdentity`：非法字符、空段、含 `#` 的值失败，与现网编码规则相同。
- 坐下成功不 Resume、不 Launch、不搬 HOME。手填恢复的是账本席位，不把已关的 grok 进程拉起来。
- `currentSeatIdentity` 仍是四个入口共用的唯一出示函数；签名是否加参归 plan，只要四个入口走同一函数、不另抽只给单测用的纯函数占缝。
- `handoff` / `product-backlog` skill 的「未出示席位」排障句随实现改到与新文案一致；不在本节点改 skill。

## 测试决定

缝一条：`cmd/card_seat.go#currentSeatIdentity`（调用方：`card bind`、`rebind --self`、有席位 `--step`、`kind != user` 的 `room send`）。不抽无调用方的纯函数占缝。

出示相关测试必须显式清空未在本支声明的 `HANDOFF_SESSION_*`、`GROK_SESSION_ID`、`CLAUDE_CODE_SESSION_ID`、`CLAUDE_CODE_REMOTE_SESSION_ID`。否则本场 grok 里跑 `go test` 会假绿或假红。

至少覆盖：

1. 仅 `GROK_SESSION_ID` → `cli:grok#<id>`，bind 成功。变异：仍只读 `HANDOFF_SESSION_*` 必须红。
2. 仅完整 `HANDOFF_SESSION_*` → 现网行为保持。负例改为「无任何来源 + `USER` 仍不得回退」，不要依赖进程里碰巧没有 grok。
3. 仅 `CLAUDE_CODE_SESSION_ID` → `cli:claude#<id>`。
4. 无任何来源 → 失败，文案含 `--cli` 与 `--session`。`USER` 仍不得回退。残缺 `HANDOFF_SESSION_*`（只设一个或空串）→ 失败，不落到宿主。
5. `--cli`+`--session` 且无注入/宿主 → 编码后的身份；只给其中一个 → 失败。
6. flag 对与仅有的 GROK 对不一致 → 失败；一致 → 成功。flag 对与注入对不一致 → 失败。
7. 完整 `HANDOFF_*` + 不同的 `GROK_SESSION_ID` → 出示注入对。变异：把这次打成冲突失败的实现必须红。
8. 两个宿主 id 同时非空（无注入、无 flag）→ 失败。
9. 四条出示命令各至少一支真实 CLI 参数把 `--cli/--session` 传到出示函数：`card bind`、`rebind --self`、有席位 `--step`、`kind != user` 的 `room send`。`coordinate` 与 `rebind --launch` 带这两个 flag → 失败。
10. 空座 `--step`、无 `--step` 的 `card dispatch`、`--kind user` 的 `room send`，只要带了 `--cli` 或 `--session` → 失败；席位与 actor 不变。

真机（acceptance，本场 grok）：空座卡上不带 flag 的 `card bind` 成功，席位为 `cli:grok#` 加上本进程 `GROK_SESSION_ID`。合 main 门与实现机相同（CLI 出示，不是某 OS 才红）。

## Out of Scope

- **永不做**：开卡/领卡自动占座；`rebind --to`；浏览器页当席位；从 `USER`/hostname/PID 推导席位；把一个会话钉成全项目唯一协调者。
- **本期不做**：给 Pi / Codex Desktop / Kimi 自动认当前会话；认 `CLAUDE_CODE_REMOTE_SESSION_ID`；本机身份文件；改 grok/claude 产品去注入 `HANDOFF_SESSION_*`；把 `RunTurn` 接到 grok/claude/codex（B307 OOS）；B330 charter 节点绑 runner 小队；人尺度 `takeover`/`release` 与席位合并；改 Resume / `buildEnv` 剥宿主键。

- 不带参数能坐下的：grok；以及进程里确实带着会话 id、且没有另一套宿主 id 的 claude。Pi / Codex Desktop / Kimi、普通终端、会话已关：手填。不给没核过的软件猜当前会话。
- 出示函数仍唯一。工作台不提供坐下 / 换绑给我，不加填一对。不改 grok 去塞环境变量。不另做本机身份登录。
- r1：完整注入对忽略宿主键。残缺注入整次失败。两种宿主 id 同时非空失败。四个出示入口都要真 flag。空座/user/裸 dispatch 带身份 flag 失败。
