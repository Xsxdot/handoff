# B373：OpenCode monitor 插件 + Command Code 一次性 wait

状态：已批准（2026-09-15 会话裁决）
级别：L1（改动面已知、验收一眼可核；spec 末尾即 plan）
选档：快道

## 问题陈述

协调者在 OpenCode 里盯 `handoff wait` / `card wait` 时，没有「stdout 一行叫醒同一会话」的工具，只能前台一轮一轮挂不带 `--follow` 的 wait。Command Code 有 `monitor_command`，但只在定时点/进程退出叫醒，不能当 follow 用。用户裁决：OpenCode 做仓内插件；Command Code 明确走不带 `--follow` 的一次性 wait，每收到一个事件（含工单）就退出再挂。

## 方案

OpenCode 插件（通用 `monitor`：任意命令、stdout 按行叫醒、busy 排队、idle 灌入）放在 handoff 仓内，由 `handoff skill install` 复制到 `~/.config/opencode/plugins/handoff-monitor.ts`。不改 `opencode.json`（OpenCode 自动加载该目录）。skill 文本按工具是否存在分支：有 `monitor` 则挂 `wait --follow`；Command Code / Codex / 未装插件的 OpenCode 走一次性 wait。

弃选：改 OpenCode 上游（无 issue、核心功能要设计评审）；给 Command Code / Codex 做同款插件（前者闭源且无 wake API，后者插件面不能 idle 开回合）。

## 用户故事

1. 本机已装 OpenCode 时，`handoff skill install` 后重启 OpenCode，工具列表出现 `monitor` / `monitor_kill` / `monitor_list`。
2. 协调者用 `monitor({ command: "handoff wait --follow <id> --timeout 3h", description: "…" })` 挂长订阅；事件行叫醒同一会话。
3. Command Code / Codex 读到 skill 后使用不带 `--follow` 的 wait，返回一个事件即退出。

## 实现决定（即 plan）

改：`plugins/opencode-monitor/handoff-monitor.ts`（新）；`internal/skill` 增加插件落点安装/状态；`cmd/skill.go` + `main.go` embed；`skills/handoff/SKILL.md` 分支；README 能力差异一句。

验收：`go test ./internal/skill/ ./cmd/`；有 `.config/opencode` 时 install 写出插件文件且与内嵌一致；无该目录则跳过不造目录；skill 正文含 Command Code 一次性 wait 与 OpenCode `monitor` follow。

## Out of Scope

- Command Code / Codex 插件或上游 PR
- 改 `opencode.json`
- 把 handoff 整本 skill 塞进插件
- 给 Command Code 增加 skill 安装落点
