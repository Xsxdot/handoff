## 定级理由

动跨进程传输契约，且要把「挂卡、事件值不值得唤醒」从传输层迁回应用。涉及：

- **传输**（`d_transport` / targetclient / relay）：选路、连接、认证、超时、取消、重连、字节/事件流
- **能力 client**（执行/审批等提供方 client）：调用哪种能力
- **应用**（账本挂卡、wait 可交付策略）：为什么调用、调用后推进什么

选轻档：不重写隧道协议，只收口调用面与误放在传输上的业务规则。

## 问题陈述

谁：从本机打到 linux-01（直连）以及将来的 relay 目标，跑 233.1 的执行能力（派发、订事件、Ask、审批回程）。

条件：选路和连接池已经集中；转发建树会摘 card_ids 并在本地挂卡；`isDeliverable` 在聚合 client 里过滤唤醒。上层有人拿到 HTTPClient 自己拼请求。

要变的事实：同一执行能力调用在本机、直连远端、relay 远端语义相同。Ask/审批引用和事件游标跨机保持，失联重连不丢待决事实。传输层不更新卡、不选审批者、不裁决哪些业务事件值得处理。写请求不因重试重复派发。生产调用走能力 client。

## 现状事实

| 事实 | 出处 |
|---|---|
| 选路工厂按直连/relay 构造 client | `internal/targetclient/targetclient.go#newWithDialer` |
| 连接池复用，配置变化失效重建 | `internal/targetclient/pool.go`（草案锚点） |
| 建树转发摘 card_ids、远端建树后本地挂卡 | `internal/agentd/forward.go`（草案：forwardWorktreeIfRequested） |
| wait 可交付过滤在聚合 client | `internal/client/client.go#isDeliverable` |
| 本环境 targets：linux-01 / local / mac-02 均为直连 addr，未见 relay 节点 | 本机 `~/.handoff/config.yaml` |

## 方案

保留 targetclient 选路、池、relay 隧道、预热与可达分开、写请求不盲目重试。不重写稳定隧道协议。

三层：

1. **传输**：目标机、连接、认证、超时、取消、重连、字节/事件流。网络认证 ≠ 任务操作授权。
2. **能力 client**：执行（233.1：派发/订阅/Send/RespondAsk/取消）、审批（233.1 client）。本卡把它们接到共用传输；工作区 client 归 233.4。
3. **应用**：挂卡、选审批者、哪些事件唤醒 wait。`isDeliverable` 从传输/通用流迁到任务事件消费策略。建树挂卡从 forward 迁到卡应用。

首批迁入生产调用：执行命令与事件订阅（含 Ask/待审批）。已识别的上层裸 HTTP 改为能力 client。可保留薄聚合门面，但新代码不得再取原始 HTTP 乱拼。

重连：先落请求再通知（233.1）；游标补拉。写请求失败后先查任务状态，再由协调者决定是否重发；客户端不承诺重发与首发绑定为同一远端任务。

真机：本机 ↔ linux-01 直连必做（AGY/Codex 在 linux-01，Grok/OpenCode 在本机）。relay 本环境若无节点，结构测试锁选路/池，连通性记缺口，不发明 relay 拓扑。

### 弃选

- 重写 relay 协议。
- 传输层继续挂卡或过滤业务事件。
- 为跨机另建交互协议栈（233.1 已否）。

## 用户故事

1. 本机经执行能力 client 在 linux-01 上跑一次 AGY（或限额恢复后的 Codex）任务：Ask/审批引用与本机 OpenCode 相同语义。
2. wait 断线重连按游标补拉未决 Ask/待审批，不丢、不重复当新请求。
3. 建树带 card_ids：账本挂卡发生在应用，传输只搬运工作区能力调用（与 233.4 交界：本卡保证 forward 不再写卡）。
4. 写请求（派发）网络重试不产生第二个任务。
5. progress / 审批审计默认仍不唤醒 wait；这条规则不在传输层。

## 契约语义与接缝

1. 传输无业务写入（卡、审批者、可交付集合）。
2. 能力调用语义与本机相同，差异只在失败诊断（目标不可达、隧道断开）。
3. 事件游标与请求身份跨机稳定（接 233.1）。
4. 依赖：能力 client → 传输；应用 → 能力 client。禁止应用为图省事持有裸 HTTP（组装点/网关除外）。

## 实现决定

- 真机以本机和 linux-01 直连为主；OpenCode 免费模型、Codex 限额窗口同 233.2。
- 兼容聚合 `internal/client` 可留，但新路径不扩张它的业务过滤。
- 不改 token/relay 握手字节。

## 测试决定

1. **选路工厂**（`targetclient.New`，调用方 CLI/agentd 池）：直连与 relay 配置各造出对应 client，无端点失败。
2. **执行能力跨机**（233.1 执行 client，调用方 dispatch/wait/reply）：linux-01 直连一次真实执行；引用与游标重连仍在。
3. **写请求失败处置**（派发入口）：失败后先查任务状态，再由协调者决定是否重新派发；不自动认定重派仍是同一远端任务。
4. **forward 不再挂卡**（现状 `forwardWorktreeIfRequested`，调用方建树 API）：传输响应不含「我写了卡」；挂卡在应用侧可测。
5. **isDeliverable 不在传输**（任务事件消费，调用方 wait）：progress 不唤醒与传输实现无关。

relay 无节点时第 1 条用配置夹具；第 2 条直连仍必做。

## Out of Scope

永不做：第三条交互总线；传输选审批者。

本期不做：工作区能力本体 → 233.4；载体准入 → 233.5；工作流转发 → 233.6；新 relay 部署；重写隧道。
