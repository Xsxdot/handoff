# B416：opencode 回合报文 verdict 围栏偶发缺闭合

## 背景与根因

B412 implement 轮（任务 `341d4c0c` @linux-01）裁决被误报「解析失败」并落 needs_human。

debug 定位（详见卡 comment seq 22343）：该轮执行模型是 `mimo-v2.6-flash`，流式输出
只写了开盘 ` ```handoff-verdict `、**漏写收尾围栏**，verdict JSON 后直接接了回合
trailer JSON。`internal/ledgerstep/verdict.go` 的 `verdictBlockPat` 要求闭合围栏，
于是匹配到 0 个块 → 转人工。

取证：拉全量 `frames.jsonl`（5122 帧 / 1074876 B）+ `render.log`，129 条 text 帧拼回
恰好等于 final_text，全文反引号只有开盘那 3 个；render.log 无「已被服务端修订」标记。
agentd/协议层未做任何抹除，候选②「协议层吞围栏」排除。对照 plan 轮
（`deepseek-v4.1-flash`）6 个反引号闭合正常——两轮并非同一模型，卡上「同模型偶发」系误判。

## 修法（L1 · 边界防御）

`internal/ledgerstep/verdict.go`：`ParseVerdict` 在闭合围栏一个都匹配不到时，退化为
「取最后一处 ` ```handoff-verdict ` 开盘标记之后的**第一段完整 JSON 对象**」作为围栏
正文。只取第一段对象、不取「开盘到报文末尾」，是为了不把后随的 trailer JSON / 散文
吞进正文、扩大误读面（审查 I1）。正文仍走同一套严格 JSON 解析 + 逐字段 salvage；
verdict 不可辨认时继续 fail-closed，不猜 pass/fail。不放宽 `turn/protocol.go` 的
trailer 解析（本次故障不在那条路径）。

   未闭合围栏 + trailer 仍抢救出 pass、未闭合且 verdict 不可辨仍报错。
