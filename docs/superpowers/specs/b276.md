## 方案

### B245：探活失败不要冒充「版本太老」

现状读数：

- 拒发文案唯一出口：`internal/discipline/dispatch.go:26` `ErrUnsupportedTarget`（「目标机 agentd 不支持接收下发的纪律正文……请先把目标机升级到同批版本再派发」）。
- 三个调用点都是「`Status` 失败 → 打 Warn → `cap` 保持 nil → 进 `ResolveDispatch`」：
  - `cmd/dispatch.go:193-199` `resolveBareDiscipline`
  - `cmd/card_dispatch.go:207-221` `resolveCardDispatchDiscipline`（取客户端失败同样 cap=nil）
  - `internal/agentd/cardstep.go:145-166` `resolveStepDiscipline`
- fail-closed 本身保留：不知道就按不支持拒发。错的是把网络错误说成升级指引。

推荐（卡上倾向 b，本 spec 采纳）：**探活失败（含取目标机客户端失败）不进 `ResolveDispatch`。** 调用方直接返回一条自带 cause 的错误，文案必须：

1. 含「探活失败」或等价，并嵌入 cause 原文；
2. 指向「先确认目标机可达 / agentd 在跑 / token 一致」；
3. **不得**含「升级到同批版本」。

`Status` 成功但 `DisciplinesSupported` 缺席或 false，仍走今天的 `ErrUnsupportedTarget`（真的是版本/能力位）。

三个调用点同一语义，允许三处各自 `fmt.Errorf` 包一层，不强制抽共享 helper；若抽，helper 只能产错误，不能改 `ResolveDispatch` 的三态。

弃选：给 `ResolveDispatch` 加 `probeErr` 参数（把探活错误塞进能力位三态，语义更脏）；只改裸 `dispatch`、不管 `card dispatch` / `--step`（同一句错话还会从那两条出来）。

### B211：stub 必须出现在 status 和 WARN

现状读数：

- `internal/webui/stub.go` `Embedded() bool` 返回 false（默认构建）；`embed.go` 在 `-tags embedweb` 下返回 true。
- `internal/agentd/server.go:568` 启动只打 `Info("控制台前端", "embedded", webui.Embedded())`。
- `handoff status` 人读输出（`cmd/status.go#renderStatusWithLookup`）没有这个位。
- `proto.StatusResp` 没有对应字段。

推荐（卡上倾向 A+B）：

1. `embedded=false` 时启动日志升为 **WARN**，正文写清后果（桌面端/浏览器控制台是 stub）和修法（用带 `embedweb` 的发布构建，不要裸 `go build` 当生产件）。`embedded=true` 保持 INFO 或更低，不制造噪声。
2. `StatusResp` 增加指针字段，**三态与 `PtySupported` 同纪律**：缺席 = 对端太老未上报，新 CLI **不得**画成 stub；`false` = 未嵌入；`true` = 已嵌入。人读 `handoff status` 只在值为 false 时打一行控制台 stub 标记（含一句处置）。`--json` 原样带这个字段。

弃选：只升日志不改 status（两次事故都是换完二进制必看 status，不看 journalctl）；release CI hash 探针当唯一门（管不住手工 `go build`，两次事故都是手工构建）。

### B256：夹具把「仓内文件」当成稳定路径，Linux `/tmp` 检出上不成立

现状读数：

- `isEphemeralBin`（`cmd/service.go:342-369`）认两类路径：路径分量以 `go-build` 开头，或落在 `os.TempDir()` / `/tmp` / `/var/tmp` 下。
- `TestResolveServiceBinFallsBackFromGoBuildCache`（`cmd/service_test.go:273-291`）把**当前** exe 设成 `/Users/x/Library/Caches/go-build/...`（`go-build` 分量在 Linux 上同样命中），把**回退候选**设成 `filepath.Abs("service.go")`。
- 卡上归因「夹具用 macOS 风格缓存路径，Linux 上回退分支未生效」**不成立**：当前路径在 Linux 上也会被当成临时文件。linux-01 全量跑在 `/tmp/hbfin`，`service.go` 的绝对路径落在 `/tmp/...` 下，被 `isEphemeralBin` 跳过，于是函数返回「当前二进制是 go run / 编译缓存里的临时文件（/Users/x/Library/Caches/go-build/...）」——这正是测试 282 行吃到的错误。darwin 本机仓不在 `/tmp`，所以绿。

推荐：夹具自己造一个**不在临时目录、路径不含 `go-build`** 的稳定候选文件（例如 `$HOME` 下本测试专属文件，测完删），不要用仓内源文件冒充安装路径。`isEphemeralBin` 的 `/tmp` 规则不动——那是生产正确行为。

另补：`TestIsEphemeralBin` 已有 macOS / `/tmp/go-build*` / `~/.cache/go-build` 三条 true。保持跨平台；不把生产判定改成「按 GOOS 选路径前缀」。

弃选：放宽 `isEphemeralBin`、不再把 `/tmp` 当临时（会把真的 go run 产物写进 systemd）；给测试 `Skip` 若仓在 `/tmp`（测试在事故现场直接消失，门牙没了）。

### B259：弃用提示改回「子命令仍可用」

现状读数：`cmd/graph.go:19` 把 Short 改成 `[deprecated：请改用 codegraph 二进制] ` + 原 Short。cobra `Deprecated` 字段故意没用，以免污染 JSON。执行机没有 `codegraph` 二进制是普遍事实，不是某台配置漂移。

推荐：改 Short，**禁止点名「去找 codegraph 二进制」**。必须写明：本子命令在本机仍然完整可用（执行机用 `handoff graph` 或 `go run . graph`）。可以保留 deprecated 意图（canonical 家在 charter 仓），但不能把执行者从「查图」推到「找那个文件」。

`--help` 的测试锁首行/Short：不得含「请改用 codegraph 二进制」；必须含「仍可用」或等价。

弃选：给各执行机装 `codegraph`（版本分叉比没装更坏，两会话已否决）；改纪律块 / CLAUDE.md 补 fallback（实测只说「查图」执行者会自己找到仓内入口，不是本期根治）。

### B258：skill 把 404 写成两义，判据改 `pending_tickets`

现状读数：

- HTTP 层三种情况都回 `{"error":"工单不存在"}` + 404（`internal/agentd/server.go:993-1013`）：库里没有这条工单、工单不属于该任务、工单已被回答。
- skill 至少三处把 404 写成「正常，跳过」：`skills/handoff/SKILL.md` 约 178 行（cursor 语义）、254 行（`stale`）、596 行（排障表）。

推荐：改这三处（及任何并列的「404 即跳过」）。正确纪律：

1. **不要用 404 判断工单是否还欠。** 权威是 `handoff show <task> --target <机器>` 的 `pending_tickets`。
2. 工单还在 `pending_tickets` → 原样重发 reply，不是跳过。
3. 工单不在 → 才是「已消耗 / 从未存在」，跳过。
4. `stale` 的「补 reply 会 404，跳过」只在已经按 `pending_tickets` 确认不在的前提下成立；文案要改成这个顺序，不能让读者先看到 404 就跳过。

仓内 `skills/handoff/SKILL.md` 是真源（`handoff skill install` 同步）。本卡改仓内文件。

弃选：本期把未注册和已消耗拆成 409/425（改的是跨进程工单 API，另开卡）；改镜像延迟本身（B258 笔记里的配套坑，另开卡）。

### B261 方向 1：改判据时若有在飞挂账 task，必须出声

现状读数：

- `internal/ledgerstep/dispatch.go:165` 派发瞬间读 `c.AcceptanceCriteria` 写进 prompt。
- `internal/ledger/cards.go:566-578` `SetAcceptance` 写字段并落 comment `"更新验收判据"`，不问挂账 task。
- 挂账实况：`internal/ledger/taskstate.go` `LatestTaskStates`，`LastType` 空 = 尚无镜像（未知）。

推荐：

1. 写判据的账本 HTTP 路径（CLI `card update --accept` 和同一条 PATCH）在写入之后查 `LatestTaskStates`。
2. **在飞**：`LastType` 不是 `archived` 且不是 `failed`（空 LastType 算在飞——刚派完、镜像还没到，宁可误报）。
3. 有在飞：stderr（CLI）打出「本次修改对正在跑的轮次无效，将从下一轮 `card dispatch --step` 生效」，列出 target/task-id；卡事件从「更新验收判据」改成带同样语义和 task-id 的评论（或额外一条评论，不许只改字段不留痕）。HTTP 200 保留——这是警告不是拒绝。
4. 没有在飞：行为与今天相同（成功、一条普通「更新验收判据」即可）。

弃选：方向 2 中途注入通道、方向 3 让执行者回读卡（见 Out of Scope）；把写入改成 409 拒绝（协调者补判据是正当动作，要的是出声不是禁止）。

## 用户故事

1. 目标机没起来时，`handoff dispatch --target X` 的错误让人去查网络/进程/token，而不是去升级。
2. 真的是老 agentd 缺能力位时，错误仍然叫人升级到同批版本。
3. `card dispatch --step` 和裸 `dispatch` 在探活失败上说同样的话。
4. 裸 `go build` 装上的 agentd，`handoff status` 一眼能看出控制台是 stub。
5. 带 embed 的发布件，status 不出现 stub 行。
6. 仓落在 `/tmp` 的 Linux 全量里，服务二进制回退测试绿。
7. 执行者跑 `handoff graph --help`，不会被打发去找 PATH 上的 `codegraph`。
8. 协调者看到 reply 404 时，先 `show` 看 `pending_tickets`，工单还在就重发。
9. 轮次进行中改验收判据，协调者立刻知道这轮吃不到，且卡时间线上留得下来。

## 测试决定（接缝清单）

1. **B245 拒发文案分流** — 符号：`resolveBareDiscipline` / `resolveCardDispatchDiscipline` / `resolveStepDiscipline`（三处生产调用方，均已存在）。缝上断言：Status 返回 error 时，返回错误含 cause、不含「升级到同批版本」；Status 成功且 cap 缺席时，仍是 `ErrUnsupportedTarget`。
2. **B211 status 投影** — 符号：`StatusResp` 新字段的填充点（agentd 组 `/api/status` 的现有函数）+ `renderStatusWithLookup`。断言：`Embedded()==false` 时人读含 stub 标记；`true` 不含；字段缺席（老对端）不含。启动 WARN 用能注入 logger 的现有 server 测试或抽一层只返回级别+正文的小函数——后者若抽，只为可测，不占新接缝名额。
3. **B256 回退夹具** — 符号：`resolveServiceBinFrom` + `isEphemeralBin`。断言：当前路径含 `go-build`、候选在非 tmp 稳定路径 → 返回候选；候选若在 `/tmp` 下必须被跳过（锁住生产规则，防止有人「修」成放行 `/tmp`）。
4. **B259 help 文案** — 符号：`cmd/graph.go` 挂载的 cobra Short。断言：`--help` / Short 不含「请改用 codegraph 二进制」，含「仍可用」类语句。
5. **B258 skill 正文** — 边界型：`skills/handoff/SKILL.md` 是执行者/协调者读的真源。断言：上述三处不再出现无前提的「404 即跳过」；出现 `pending_tickets` 作为 404 之后的判据。可用测试读文件或 `handoff skill` 嵌入副本，选一处真源即可。
6. **B261 写判据出声** — 符号：`SetAcceptance` 的 HTTP 调用方（`handleCardPatch`）+ CLI `card update --accept`。断言：挂一条 LastType 空或 `completed` 的 task 时，响应/stderr/卡事件含「无效」语义和 task-id；只挂 `archived` 时没有这句警告。

禁止用同一条夹具冒充两条缝（尤其 B245 的探活失败 vs 能力位缺席）。
