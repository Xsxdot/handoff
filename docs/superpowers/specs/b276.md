## 方案

### B245：探活失败不要冒充「版本太老」

现状读数：

- 拒发文案唯一出口：`internal/discipline/dispatch.go:26` `ErrUnsupportedTarget`。
- 三个调用点都是「失败 → Warn → `cap` 保持 nil → 进 `ResolveDispatch`」：
  - `cmd/dispatch.go:193-199` `resolveBareDiscipline`
  - `cmd/card_dispatch.go:207-221` `resolveCardDispatchDiscipline`（取客户端失败同样 cap=nil）
  - `internal/agentd/cardstep.go:145-166` `resolveStepDiscipline`
- fail-closed 本身保留：不知道就按不支持拒发。错的是把网络错误说成升级指引。

推荐：探活失败（含取目标机客户端失败）**不进** `ResolveDispatch`。调用方直接返回自带 cause 的错误，文案必须：

1. 含「探活失败」或等价，并嵌入 cause 原文；
2. 指向「先确认目标机可达 / agentd 在跑 / token 一致」；
3. **不得**含「升级到同批版本」。

`Status` 成功但 `DisciplinesSupported` 缺席或 false，仍走今天的 `ErrUnsupportedTarget`。

三个调用点同一语义，允许三处各自 `fmt.Errorf`。存量 `TestBareDispatchRefusesUnsupportedTarget` 与 `TestStartCardStepRejectsUnsupportedTarget` 锁的是「探活成功 + 能力位缺席/false → 仍含升级」，**不要改这两条的升级断言**；探活失败另加夹具（Status 返回 error 或假目标机关闭）。

弃选：给 `ResolveDispatch` 加 `probeErr`；只改裸 `dispatch`。

### B211：stub 必须出现在 status、WARN 和 JSON

现状读数：`webui.Embedded()` 默认 false；启动只有 `server.go:568` INFO；`StatusResp` 无此位；填充点在 `handleStatus`（`server.go:694-714`），与 `PtySupported` 同层。

推荐：

1. `embedded=false` 时启动升 **WARN**，写清后果（控制台是 stub）和修法（用带 `embedweb` 的发布构建）。`true` 保持 INFO。
2. `StatusResp` 增加 `WebEmbedded *bool \`json:"web_embedded,omitempty"\``。三态与 `PtySupported` 同纪律：缺席 = 对端太老，新 CLI **不得**画成 stub；`false` = 未嵌入；`true` = 已嵌入。
3. **线格式**：`encoding/json` 对指针的 omitempty 只省略 nil；非 nil 的 `false` **必须**出现在 JSON 里。禁止做成值类型 `bool`+omitempty（false 会被省略，看起来像老对端）。
4. 人读 `handoff status` 只在值为 false 时打一行控制台 stub（含处置）。`--json` 原样带该键。
5. 填充点在 `handleStatus`，不要让 Manager import webui。契约样本 `statusSample` 补一个非 nil 的 `false`。

弃选：只升日志；release CI hash 探针当唯一门。

### B256：夹具把「仓内文件」当成稳定路径，Linux `/tmp` 检出上不成立

现状读数：`isEphemeralBin` 认 `go-build*` 分量或 `/tmp` 前缀。当前 exe 的 macOS go-build 路径在 Linux 上**同样**命中 `go-build`。红是因为 linux-01 仓在 `/tmp/hbfin`，回退候选 `filepath.Abs("service.go")` 带 `/tmp/` 被跳过。

推荐：

1. 夹具自己造稳定候选文件：必须是普通文件（`regularFileExists`），构造后先断言 `!isEphemeralBin(path)`，不满足则 **Fatal**（写明路径为何仍算临时），**禁止 Skip**。不要用仓内源文件，也不要假设 `$HOME` 不在 `/tmp`（容器里 `HOME=/tmp` 会再红）。
2. `/tmp` 生产规则不动。
3. 回退成功：当前路径含 `go-build`、候选稳定 → 返回候选。候选若在 `os.TempDir()` / `/tmp` 下必须被跳过。测完删文件。

弃选：放宽 `isEphemeralBin`；仓在 `/tmp` 就 Skip。

### B258：skill 把 404 写成两义，判据改 `pending_tickets --target`

现状读数：`handleReply` 三种成因同一 404「工单不存在」。skill 真源 `skills/handoff/SKILL.md`（`main.go` embed），无前提的「404 即跳过」至少三处：约 178 / 254 / 596 行。

推荐：改这三处。正确纪律：

1. **不要用 404 判断工单是否还欠。** 权威是 `handoff show <task> --target <机器>` 的 `pending_tickets`（任务在哪台机器就打哪台；漏 `--target` 打到本机空表，会当成已消耗而跳过，远程执行者照旧挂死）。
2. 工单还在 `pending_tickets` → 原样重发 reply。
3. 工单不在 → 才跳过。
4. `stale` 段不得让读者先看到「404 跳过」。

不要改「同一 ticket 答两次 404」「resume 后挂起项已无」那些已消耗的正确推论（约 279 / 592 / 622 行）。

只改 skill、不拆 HTTP 状态码。关不掉「工单尚未入库」的竞态，Out of Scope 已记。

### B261 方向 1：改判据时若有在飞挂账 task，必须出声

现状读数：`dispatch.go:165` 瞬间冻结；`continue` 不重读卡。生产写判据两处都进 `SetAcceptance`：CLI `cmd/card.go:179-182`（`openLedger()` 直写，**不经 HTTP**）和 `handleCardPatch`。只改 PATCH 会漏 CLI 主路径。

推荐：

1. 查询收口在 `SetAcceptance`：写入后查 `LatestTaskStates`。有在飞则评论带「本次修改对正在跑的轮次无效，将从下一轮 `card dispatch --step` 生效」+ 在飞的 target/task-id。HTTP 保持 200 `{"ok":true}`。
2. **在飞**：`LastType` 不是 `archived` 且不是 `failed`。空 LastType 算在飞。`completed` / `turn_failed` 算在飞（与 `mirrorTaskTerminal` / `LiveMirrorTargets` 一致）。
3. CLI 在 `SetAcceptance` 之后把同样语义打到 **stderr**（Web 没有 stderr，靠评论；`CardDrawer` 成功后 `load()` 会刷新）。
4. 没有在飞：与今天相同。
5. 同卡一条 `archived` + 一条空/`completed` → 仍警告，只列出在飞那条。

弃选：方向 2/3；把写入改成 409。

## 测试决定（接缝清单）

1. **B245 拒发文案分流** — 符号：`resolveBareDiscipline` / `resolveCardDispatchDiscipline` / `resolveStepDiscipline`。断言：Status 返回 error 时，返回错误含 cause、不含「升级到同批版本」；Status 成功且 cap 缺席时，仍是 `ErrUnsupportedTarget`（存量两条「升级」测试保持）。三处生产函数都要打到。
2. **B211 status 投影** — 符号：`handleStatus` + `renderStatusWithLookup`。断言：GET `/api/status`（或现成 status 测试，禁止只测渲染函数的构造体）在 `Embedded()==false` 时 JSON 含 `"web_embedded":false`；`true` 时键为 true；指针 nil 时键缺席。人读只在 false 打 stub 行。契约样本含非 nil 的 false。
3. **B256 回退夹具** — 符号：`resolveServiceBinFrom` + `isEphemeralBin`。断言：构造候选后 `!isEphemeralBin && regularFileExists`，否则 Fatal。当前路径含 `go-build`、候选稳定 → 返回候选。候选在 `os.TempDir()` 下必须被跳过。
4. **B259 命令删除** — 符号：根命令树 + `Compose` 平台层正文 + `IsSelfCommand`。断言：根命令无 `graph` 子命令；`handoff graph --help` 为 unknown command；组装后的平台层正文不含「handoff graph」作为执行入口，含 `go run github.com/Xsxdot/charter/graph/cmd/codegraph`；`handoff graph resolve` 不再被只读白名单放行。
5. **B258 skill 正文** — 边界型：`skills/handoff/SKILL.md`。断言：约 178 / 254 / 596 三处不再出现无前提的「404 即跳过」；404 之后的判据是 `handoff show <task> --target <机器>` 的 `pending_tickets`；工单还在 → 重发。不要误伤约 279 / 592 / 622。
6. **B261 写判据出声** — 符号：`SetAcceptance`（两处调用方共同写点）。断言必须**真跑** CLI `card update --accept`：有 LastType 空或 `completed` 的挂账 task 时，stderr + 卡事件含「无效」语义和 task-id；只挂 `archived` 时没有警告；同卡一条 `archived` + 一条空/`completed` 仍警告并列出在飞那条。PATCH 路径看卡事件（HTTP 可仍是 `{"ok":true}`）。禁止只测 store、不跑 CLI。
