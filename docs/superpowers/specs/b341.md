# B341 pass 后 push origin 时 task 已被归档

- **卡**：B341
- **级别**：**L1**。plan 增量为零：归档放到发布之后。验收一眼可核：Publish 先于 Done。
- **状态**：**已批准**（2026-09-05；B340 真机；用户授权修到过线）
- **基线**：`origin/main` @ `9e7ea4f2`
- **发现自**：B340 / B335 origin 交接真机。不 reopen B335。

## 问题陈述

B335 要求节点 pass 后在执行机 `git push origin <工作分支>`。生产里 `awaitNode` 取到终态报文就 `Done` 回收 managed worktree，然后 `PublishWorkBranch` 再 `handoff run` 去 push，得到 400「工作目录不存在（managed worktree 可能已被 done/stop 回收）」，卡被 needs_human。B340 上执行者已经自己把 `cards/B340-charter` 推到 origin（`8f42fe3d`），系统二次 push 才失败。

## 方案

`Await` 只取报文，不归档。`RunOnce` 在 pass 发布（或跳过发布）之后再 `Done`。失败路径同样在取到报文后归档，避免泄漏 task。不改 push 命令本身。

弃选：发布失败时若 origin 已有分支就当成功（掩盖时序 bug）。弃选：从主工作树 push（worktree 回收后 ref 可能还在，但是绕开根因）。

## 用户故事

1. 作为 charter implement：pass 后系统 push origin 成功，不因 task 已归档而 needs_human。
2. 作为对照：取到报文后 task 仍会被归档（不泄漏）。

## 测试决定

缝：`NodeStep.RunOnce` ← `StepRunner.Run`：`PublishWorkBranch` 先于 `FinishTask`（Done）。

1. pass + 有工作分支：顺序 `publish` 然后 `done`。
2. 现有本机 runner 接线测试：Done 仍会发生一次。

## L1 plan

1. `awaitNode` 去掉 `cl.Done`。`NodeStep.FinishTask` 在 `Await` 成功后 defer，且在 `PublishWorkBranch` 之后执行。
2. `StepRunner` 把 `FinishTask` 接到 `Clients.Done`。
3. 测试锁顺序；不改 push 命令。

验收：顺序测试绿；变异把 Done 放回 Await 则顺序测试红。本节点该干什么一律以注入的纪律块为准。
