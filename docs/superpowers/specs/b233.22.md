# B233.22 spec：internal/ 按 best.json 重排——错位文件归域，Gateway/编排分家收尾

## 背景

- 来源：`docs/roadmap.md`「来自 B233.10 spec」全仓重排条（「物理搬家仍暂缓，目录是结果不是
  手段」）；B233.17 再确认不做；用户残余清单第 1 类第 5 行，本轮解冻。
- 本卡前序（.18/.19）已把三域构造上移 cmd、项目/镜像/预览实现体迁出 agentd。best.json
  （codegraph/best.json，人工维护应然）是唯一归属判据：`k_agentd_*` 容器分别归
  d_gateway（Server/hostAllowlist/orchestration_client/scheduling_client）与
  d_orchestration（Manager/Hub/Approver/fn/model/DataDirLock/Shutdown/pullTracker 等），
  其余包按域名单对应（d_workspace→internal/workspace、d_scheduling→internal/scheduling、
  d_ledger→internal/ledger*、d_collab→internal/collab、d_keystone→internal/keystone、
  d_execution*→internal/executor*、d_transport*→internal/transport 相关、d_cli→cmd、
  d_web*→internal/webui、d_protocol→internal/proto 等）。

## 目标

internal/ 的目录布局与 best.json 的域归属一致到「文件粒度可执行集」：实现体所在文件落在
其容器的应然域对应的包里；gateway（internal/agentd）只留 HTTP/WS/转发/鉴权门面。
基线图滞后（图里仍有已迁走的 reclaim.go 等）**不作为本卡盘点依据**——盘点以实现时的
真实代码为准。

## 范围

1. **盘点**：产出《域→包→文件》实况表：对每个非测试源文件，按其主容器在 best.json 的
   应然域标注「合位/错位/未登记」。错位清单按三档分级：
   - A 档（本卡必搬）：整文件搬迁即可归位，不涉及新缝设计（如 Hub、纯编排辅助、
     与 Server 无方法绑定的编排类型）；
   - B 档（本卡记延期）：搬迁需要新接口缝或跨包行为拆分（如 Server 方法绑定的编排逻辑），
     逐条给理由；
   - 未登记：best.json 没有该容器（如 preview 族）——记入表，留 B233.23 补登记。
2. **执行 A 档搬迁**：git mv 保 rename；测试随迁；引用改指新包；不改任何行为。
3. **验收口径**：A 档清零；B 档与未登记逐条在卡 note 落账（这是本卡的合法残余，不算失败）。

   三档清晰，A 档全部执行完毕。

5. 本节点该干什么一律以注入的纪律块为准。
