## 定级理由

跨子系统、动已有「什么事件叫醒协调者」的契约语义（不是新开子系统）：

- **协议**（任务事件可交付策略已有名字，卡原生事件要同一口径）
- **协调者命令面**（`handoff wait` / `card wait` 的 stdout 即唤醒）
- **账本 / 镜像**（卡事件流仍落审计，wait 不再把审计打到 stdout）
- **编排 / Keystone**（wakeconsumer 与任务 wait 不再各写一张表）

选轻档：三张卡是同一条唤醒面的三个切口，拆并行子卡会把「表 × 三处消费」拆散。契约冻结与拆解照做，实现一轮收口。

本节点该干什么一律以注入的纪律块为准。

## 问题陈述

谁：功能线上的协调者主会话（以及小队自动化）继续用现有 `wait` / `card wait` / 账本消费者，不新造命令、不新造常驻进程。

条件：B233.7 已并入功能线。`handoff wait` 已有 `WaitDeliveryPolicy`；`card wait` 对每条卡事件无差别打一行；wakeconsumer 另有一张更窄的表，`delivery_failed` 不在其中。grok / Claude Code 有 Monitor（一行一醒）；opencode / Codex 没有，且子 agent 不能在未退出时把一行送回父会话（2026-09-09 实测，见台账）。

通道：现有 `handoff wait` 与 `handoff card wait`。`card wait` **新增**与任务 wait 同款的 `--follow`（用户 2026-09-09 选 B）。不新造第三条命令。

要变的事实：

1. 三处消费者共用一张「可动作 / 纯审计」表。任务事件以现成 `WaitDeliveryPolicy` 为权威：**假集合外全部可交付**（含 `delivery_failed` / `stalled` / `approval_dropped` / `archived` / 压力告警等），三处同值；假集合内一律不叫醒。不是「只补 delivery_failed 两条」。
2. `card wait` 只把可动作打到 stdout：等人、等人被清、开裁决、裁决被答、房间真人消息、以及 `task_mirrored` 且策略为真的任务事件。comment、派发快照、自动审批镜像等审计不打。
3. 小队自动化与任务 wait 同口径（同一张表），`delivery_failed` 会叫醒去 `resume`。
4. `card wait` 做成与任务 wait 同款退出模型（现状没有 `--follow`、挂到卡终态——这是要改的，不是现状）：**默认**吐一条可动作就退出 0；**`--follow`** 才长挂到全员终态。`--timeout`：默认 = 等不到可动作的总时长；`--follow` 下 = 空闲上限（与任务 `wait --follow` 对齐）。
5. skill 写死：grok / Claude Code 挂一条 `card wait --follow`（或任务 `wait --follow`）；opencode / Codex 用默认一次一挂，退出再挂。不把子 agent 或 `write_stdin` 轮询写成 follow 替代。

## 方案

原则：叫醒这件事只承认一张表。过滤发生在**消费**（wait stdout / wakeconsumer），不删账本审计、不扩 `mirrorSkip` 把审计从卡流抹掉（`show` 仍要能对质）。

**任务事件**：不改 `WaitDeliveryPolicy` 的假集合成员。三处都调它（卡侧对 `task_mirrored` 先解 `task_type` 再套）。假集合外全部可交付，不许再开一张「只补 delivery_failed」的白名单。

**卡原生事件（可动作）**：`needs_human`、`needs_cleared`、`decision_opened`、`decision_answered`、房间真人非系统消息。`status_moved` 只给 wait 判断是否该退出，不打 stdout。`review_verdict` 不单列：实现 `completed` 镜像已在任务表内。其余（comment、dispatched、acceptance_recorded 等）纯审计。若以后叫醒过多，再收紧闭集，不在本卡预留第三张表。

**Harness（B355）**：不新做常驻订阅、不用子 agent 挂 follow。

| 主会话 | 任务 wait | card wait（本卡改完后） |
|---|---|---|
| grok / Claude Code | `wait --follow` | `card wait --follow`（一条，活到会话结束） |
| opencode / Codex | 默认一次一挂 | 默认一次一挂（一条可动作即退出） |

两次 wait 之间的真空不另开卡（偶发，用户 2026-09-09 拍板）。

### 弃选

- 三处各打各的补丁：过两周又漂，正是今天的病。
- 扩 `mirrorSkip` 代替 wait 过滤：审计从卡流消失，`show` 对质变差；与 `WaitDeliveryPolicy`「传输仍能见到、应用才过滤」不一致。
- 子 agent 挂 follow：OpenCode 整段 `task_result`；Codex `wait_agent` 阻塞到子 agent 结束才给 `SUBAGENT_WAKE`。父会话要么卡死，要么收不到中途行。
- Codex `write_stdin` 轮询当 follow：把用户已经讨厌的 cron 搬进模型回合。
- 本批做 handoff 常驻订阅者：新生命周期，和分类表抢同一轮；真空已明确不单独立项。
- 保持 card wait 长挂到终态、只过滤行（审核选项 A）：opencode / Codex 当协调者无法用账本外层一次一挂。用户选 B 否决。

## 用户故事

1. 作为 grok 主会话挂 `card wait --follow`，自动审批 / 挂账 comment 不再一行一醒；提问、权限、`delivery_failed`、等人、等人被清、开裁决、裁决被答会醒。
2. 作为小队自动化，权限回传失败出现 `delivery_failed` 时被叫醒去 `resume`，不必人盯 wait。
3. 作为 opencode / Codex 主会话，`handoff wait` 与 `handoff card wait` 默认都是一条可动作即退出；skill 不暗示它们能 `--follow`。

## 契约语义与接缝

- **跨子系统规则**：事件是否叫醒协调者，只由一张消费策略决定；任务侧即 `WaitDeliveryPolicy`；卡侧是「解包 task_mirrored 后套同一策略」+ 卡原生可动作集合。不允许第三张表。
- **流向**：账本/任务事件仍全量落库；镜像仍按现 `mirrorSkip` 入卡流；wait stdout 与 wakeconsumer 只对可动作出行/叫醒。
- **不新增**命令、HTTP 字段、事件类型、事件总线。`card wait --follow` 是既有子命令上与任务 wait 对齐的新产品行为，不是第三条命令。
- **依赖方向**：命令面与编排消费既有协议策略，不把策略抄进 CLI 各写一份。落点（函数名、包）归 contract。

## 实现决定

- 过滤在应用消费点，不在 WS/HTTP 传输、不在镜像 Skip 扩面。
- 用户可见：`handoff wait`、`handoff card wait`；card wait 新增 `--follow`，默认一次一挂。
- `--timeout` 与任务 wait 对齐：默认 = 等不到可动作的总时长；`--follow` = 空闲上限。
- skill / 排障表按两类 harness 改挂法；账本模式「一次工作流只挂一次 card wait」只适用于 `--follow`；一次性挂法退出后由主会话再挂。保留「reply 502 → resume」。

## 测试决定（接缝清单）

1. **`WaitDeliveryPolicy` × `handoff wait` / `Client.FollowEvents`**（`cmd/wait.go`、`internal/client/client.go`）：`delivery_failed` 可交付；`permission_auto_allow` 不可交付。不改假集合成员。
2. **`handoff card wait` × `runCardWait` / `Store.Follow` 回调**（`cmd/card_wait.go`）：可动作才 Encode；comment / dispatched / 被策略判假的 `task_mirrored` 不 Encode；`needs_human` / `needs_cleared` / `decision_opened` / `decision_answered` Encode。默认：一条可动作后退出 0。`--follow`：多条可动作可连续 Encode，全员终态退出。非终态 `status_moved` 不出现在 stdout；终态可退出且 stdout 无该叫醒行（stderr 提示除外）。
3. **`automationWakeEvent` × `Server.consumeAutomationEventsOnce`**（`internal/agentd/wakeconsumer.go`）：`task_mirrored`+`delivery_failed` 唤醒；`task_mirrored`+`permission_auto_allow` 不唤醒；`needs_cleared` / `decision_answered` 唤醒；与缝 1 假集合外同口径。现状已醒 `needs_cleared`、不醒 `decision_opened`/`decision_answered`——本期把后两者补上，并保持 `needs_cleared`。

禁止只测 helper、不穿过对应调用方。
