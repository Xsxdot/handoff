## 定级理由

跨子系统，并对接已有账本事件 wire：

- **协议**：`proto.LedgerEvent` 补镜像 source 三列（omitempty，加列不是新事件类型）
- **账本门面**：进程内投影停止丢列，HTTP 卡详情同一条投影
- **编排 / Keystone**：wakeconsumer 的当前派发闸补 source
- **协调者命令面**：`card wait` 同一道闸决定 stdout 是否叫醒

选轻档：两张卡是同一条消费正确性面的两个切口（身份 + 水位），拆并行子卡会把闸和游标拆散。契约冻结与拆解照做，实现一轮收口。

本节点该干什么一律以注入的纪律块为准。

## 问题陈述

谁：功能线上的小队自动化（wakeconsumer）和协调者主会话（`card wait`）继续消费现有卡事件流，不新造命令、不新造事件类型。

条件：B353 已并入功能线。叫醒类型表三处共用 `WaitDeliveryPolicy`。B233.6 冻过「消费镜像事件必须同时检查 node、attempt 与 source identity」，实现只核了 envelope 的 node/attempt。自动化 cursor 仍在内存，agentd 重启后从 0 重放全流。

通道：现有 `consumeAutomationEventsOnce` 与 `handoff card wait`。不新造第三条消费链。

要变的事实：

1. wire 与进程内投影不再丢掉 `source_target` / `source_task` / `source_seq`。镜像事件：`source_task` 必有；`source_target` 本机可空串；`source_seq` 为源序号，不参与身份匹配。卡原生事件三列仍为零值（`""` / `0`）。
2. `task_mirrored` 要叫醒（wakeconsumer 唤醒，或 card wait 打 stdout），必须两道闸都为真：B353 类型表，以及 **node + attempt + source_target + source_task 对应该节点当前派发**。顺序不承重。旧 attempt、错机器、envelope 与列不一致、没有当前派发快照的，留账本、不叫醒。
3. 自动化消费水位写在这台 agentd 自己的 DataDir，重启从上次 seq 续拉。宕机窗口里新落到账本上的事件仍会叫醒（至少一次）。`automationSeen` 仍内存。

## 方案

原则：身份闸和类型表一样，写在**消费点**，不扩 `mirrorSkip`、不把判定下沉成账本派生查询（P3）。水位是**这台 agentd 的消费进度**，不进共享账本。

**身份（B349，用户 2026-09-09 选 A + card wait 同闸）**

当前派发身份 = 该事件 **`CardID`** 上、envelope.node 对应的、最新一条 `Node!="" && Attempt!=""` 的 `EvDispatched` 快照的 `(snapshot.Target, snapshot.Attempt)`。`Attempt` 即这次 task ID（B233.6 冻结 #7–#10）。`snapshot.TaskID` 必须与 `Attempt` 同值才算当前派发；夹具若把两字段拆开，**以 Attempt 为准**，日志打出两字段。禁止用 `snapshot.TaskID` 替换 Attempt 作为比较键。

取数路径（两处消费点同一条，审查 C1）：当前身份**只**来自上述快照，禁止只比本条 `task_mirrored` 的 envelope 与 source 列是否自洽——旧 attempt 的列与 envelope 本来就是自洽的。`--subtree` 按**事件所属卡**取快照，不用 wait 根卡。没有匹配快照 → 与 wakeconsumer 的 `!found` 相同：不叫醒、不 Encode。

`task_mirrored` 通过身份闸当且仅当：

- envelope 的 node/attempt 均非空，且 attempt 等于当前 `snapshot.Attempt`
- `source_task` 等于当前 `snapshot.Attempt`（列与 envelope 必须同指一个 task；只信列或只信 envelope 都不行）
- `source_target` 等于当前 `snapshot.Target`（两边都空算匹配，本机未填 target；一边空一边非空不匹配）
- `source_seq` 不参与「是不是当前派发」的匹配（它是源事件序号，不是 attempt 身份；与源序号不一致仍可按身份匹配，去重是 store 的事）

缺 `source_task` 的 `task_mirrored` **闭集拒绝叫醒**（记 seen / 当审计，打日志，不把消费循环打死）。缺 `source_target` 单独不构成闭集——走与当前 Target 的相等比较。缺 node/attempt 维持现状：不当当前工作流尝试。卡原生事件（等人、裁决、房间真人消息）没有 source 列，**不走**这道闸，仍只走 B353 类型表。

plain / 旧镜像缺 node/attempt、以及没有任何当前 `EvDispatched` 的 `task_mirrored`：不得猜成当前尝试（B233.6 已冻）。本卡把 card wait 对此类事件从「今日按类型表 Encode」**收紧为不 Encode**。验收不得把无节点直派卡、或未补快照的 B353 夹具当成类型表回退。

两道闸都为真才叫醒；现网是身份闸在类型表之前，顺序不承重。

**水位（B352，用户 2026-09-09 选 A）**

`automationCursor` 只在现网会执行 `s.automationCursor = maxProcessed` 的那些出口**之后**写入这台 agentd 的 DataDir（进程私有，形态与房间游标同类）。禁止在本轮唤醒/跳过之前把 cursor 文件前移——先落盘再唤醒会变成用户否决的「恰好零次」。

读回发生在 `SetupAutomation`（或与之等价、**不依赖** `StartAutomation` 的装配点），使「新 Server + SetupAutomation + `consumeAutomationEventsOnce`」就能续拉。没有文件则从 0——只发生在这台机器第一次跑本卡之后的二进制。`automationSeen` 不落盘：cursor 已经跨过的 seq 不会再读到；自生 `needs_human`（B274）仍在当轮用内存 seen 防自激。

崩溃在落盘前：本轮已读但 cursor 未前进的全部 seq 可能再醒一次（至少一次），包括同一 tick 里已经唤醒成功、随后因另一张卡 attach 暂缓而 early return 的那些。attach 暂缓仍不推进 cursor（现状 early return），重启后这些 seq 会再试——这是对的。

不复用 `$HOME/.handoff/cursors`（那是任务 `wait` 的协调者游标，B233.6 已冻镜像不得抢）。

### 弃选

- **无代码收口**（评估选项 C）：store 去重回答「同一源事件不插两行」，不回答「是不是当前派发」。跨 target 同卡事件按设计可入列。用户否决。
- **绕过 Facade 直读 Store**（评估选项 B）：多一条读事件路径，只为回避 omitempty 加列。用户否决。
- **身份闸只留 wakeconsumer**：主会话 hang 仍会被旧 attempt 叫醒，B353 刚对齐的叫醒面再分叉。用户否决。
- **水位写进共享账本**：多 agentd 共用 PG 时抢同一条进度；ledger 揽消费者状态，逆 P3。用户否决。
- **启动 cursor = MAX(seq)**：实现最少，但宕机窗口里落到账本上的事件永远不醒。用户否决。先落盘再唤醒与此同构，同样禁止。
- **持久化 seen 表**：cursor 推进后 seen 无剩余职责；不为本卡加第二份持久状态。
- **把 source 三列写进 envelope JSON**：列才是权威身份（mirror.go 注释已写明）；重复一份会再漂。
- **控制台做身份闸**：控制台不是叫醒消费者；加列后只读展示。前端不为本卡改交互、不改 TS 类型。

## 用户故事

1. 作为小队自动化，同卡同节点重试后，旧 task 迟到的 `question` / `delivery_failed` 不再拉起新一轮协调者。本机未填 target（两边 `""`）的当前提问仍拉起。
2. 作为 grok 主会话挂 `card wait --follow`，旧 attempt 的镜像提问不打 stdout；当前 attempt 的提问、权限、`delivery_failed` 仍打。无当前派发快照、plain 缺 node/attempt 的镜像不打——这是本卡收紧，不是 B353 回退。
3. 作为本机 agentd，重启后不会把已经叫醒过的占座卡再拉一轮；重启前尚未消费、以及 attach 暂缓导致 cursor 未前进的事件仍会醒。

## 契约语义与接缝

- **跨子系统规则**：`task_mirrored` 是否叫醒，两道闸都为真（B353 类型表 + 本卡身份闸）；两处消费点执行同一条规则正文，当前身份都从该事件所属卡的 `EvDispatched` 取。ledger 不提供「当前 attempt」派生查询。
- **流向**：镜像仍按现 `mirrorSkip` 入卡流；source 三列继续只写在卡事件列上。投影（进程内 Facade 与 HTTP 卡详情）必须带上三列。wait stdout 与 wakeconsumer 按闸过滤，不删账本行。
- **允许的契约增量**：`proto.LedgerEvent` 增加三列，JSON omitempty，旧客户端忽略。不新增命令、事件类型、事件总线、HTTP 路径。不改 `web/src/api/ledger.ts` 类型与控制台交互；现有零值 `LedgerEvent` 金样本不得因加列改字节。
- **冻结物**：不退回 B233.6 contract §2.4，也不退回拆解 P3（闸在消费者，ledger 保持薄）。**本卡废止** B233.6 plan §5.2 约 L493 与 L503 对 S3 的范围限制（不得改 `api.go` / `ledgerapi.go` / `proto/ledger.go`、不得新增 source 字段或 cursor 文件、source identity 只由 store 去重保证）。那两句是当时为收窄 B233.6 实现范围写下的，review-3 指出缺口后由本卡接手。
- **水位**：本机 agentd 进程私有。不进共享账本，不与任务 wait cursor、镜像 watermark 混用。落盘在内存 cursor 赋值之后；读回在 `SetupAutomation`。
- **依赖方向**：命令面与编排都读账本事件上的 source 列 + 派发快照；不把身份规则抄成两份不同的布尔表。落点（函数名、包、DataDir 文件名）归 contract。

## 实现决定

- 过滤仍在应用消费点（与 B353 相同），不在传输层、不在镜像 Skip。
- 用户可见：`handoff card wait` 的 stdout 更安静（旧 attempt、无当前快照的镜像不再出现）；HTTP 卡详情 JSON 的镜像事件多三列。无新 flag。
- 重启后自动化不再全量重放。无用户可见新命令。
- 前端不改 TS 类型、不改交互。

## 测试决定（接缝清单）

1. **`eventWire` / `ledgerEventWire` × `Facade.EventsFromAsc` 与卡详情 HTTP**（`internal/ledger/api/api.go`、`internal/agentd/ledgerapi.go`）：镜像事件投影含 `source_target` / `source_task` / `source_seq`；卡原生 comment / `needs_human` 三列为零值。穿过真实 JSON：缺席 vs `""` vs 非空；`source_seq` 缺席 vs 0。现有零值金样本字节不变。禁止只测 helper 不穿过 Facade 或 HTTP 编码。
2. **`acceptsCurrentWorkflowAttempt` × `Server.consumeAutomationEventsOnce`**（`internal/agentd/wakeconsumer.go`）：当前派发且 source 列一致的 `task_mirrored`+可动作类型唤醒；envelope.attempt 匹配但 `source_task` 或 `source_target` 对不上的不唤醒；缺 `source_task` 的 `task_mirrored` 不唤醒且消费循环继续；旧 attempt 回归不唤醒。正例：当前快照 `Target==""` 且镜像 `source_target==""`、`source_task` 等于当前 Attempt 的可动作类型 → 唤醒。反例：`source_target="linux-01"` vs 当前 `""` → 不唤醒。正例：`source_seq` 与源序号不一致仍按身份匹配则唤醒。
3. **`cardWaitEventActionable` × `runCardWait`**（`cmd/card_wait.go`）：当前身份取自**事件所属卡**上 envelope.node 的最新 `EvDispatched`（`--subtree` 不用根卡）。无匹配快照的 `task_mirrored` 不 Encode；旧 attempt 不 Encode；当前 attempt + 可动作类型 Encode。两边 `Target==""` 的当前可动作 Encode。B353 类型表回归仍成立（`permission_auto_allow` 不 Encode，`needs_human` Encode），**但**可动作 `task_mirrored` 夹具必须补一条匹配的当前派发快照；plain / 缺 node/attempt 的镜像不 Encode 是本卡收紧，不得当 B353 假红。
4. **`Server.consumeAutomationEventsOnce` × `SetupAutomation` 启停**（`internal/agentd/server.go`）：读回不依赖 `StartAutomation`。同一 DataDir 上消费一轮后模拟重启（新 Server、再 SetupAutomation、再 `consumeAutomationEventsOnce`），已推进 cursor 的事件不再唤醒；cursor 之后新写入的可动作事件仍唤醒。落盘发生在内存 cursor 赋值之后（禁止唤醒前把文件前移）。attach 暂缓仍不推进水位（回归）。

禁止只测 helper、不穿过对应调用方。
