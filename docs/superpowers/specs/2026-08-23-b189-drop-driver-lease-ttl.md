# B189：废除驱动租约的 TTL 过期语义

> 状态：**已批准（用户，2026-08-23）** · 级别 **L2** · 档位不适用
> 裁决来源：decision #1（用户 2026-08-23）
> 前置更正：本卡原标题「HeartbeatDriver 无生产调用点」已被证伪（B196 补上了调用点，
> `internal/ledgerstep/runner.go:115`）。卡已改名，原判据作废。

## 问题陈述

卡的驱动身份今天是一份**带 5 分钟 TTL 的租约**：认领时写 `driver_session` 与
`driver_heartbeat_at`，此后任何一次认领都会先算

```go
expired := card.DriverHeartbeatAt.IsZero() || time.Since(card.DriverHeartbeatAt) > driverLeaseTTL
```

过期即放行——另一个会话可以直接接管一张正被驱动的卡。

两处认领点，只有一处在续租：

| 认领点 | 是否续租 | 后果 |
|---|---|---|
| `internal/ledgerstep/runner.go:87`（节点流 `--step`） | 有（B196 加的心跳协程） | 回合内不会过期 |
| `cmd/card_dispatch.go:172`（普通模板派发） | **无** | 5 分钟后必然可被抢占 |

第二处**照抄不了第一处的修法**：`--step` 阻塞在 `StepRunner.Run` 里跑完整个回合，进程
活着才起得了心跳协程；普通 `card dispatch` 派完即退出，进程都没了，谈不上续租。

用户裁决（decision #1）指出前提本身就错：**卡的驱动方是一个有人在后面的会话，不是
会静默死亡的进程**。TTL 买到的是「驱动死了自动可回收」，而这个收益的前提不成立；
付出的代价是——人还在的时候卡被静默接管，两个驱动同时在飞且互不知情。这比卡住更坏，
因为卡住是可见的，双驱动不是。

「租约到期就该被别的会话领走」这条本身也讲不通：**时间流逝不是所有权转移的理由。**

## 现状事实（本轮工作树读数，交 plan 复核）

| 事实 | 出处 |
|---|---|
| `driverLeaseTTL = 5 * time.Minute` | `internal/ledger/tasks.go:15` |
| 过期判据出现且仅出现两处 | `internal/ledger/tasks.go:104`（ClaimDriver）、`internal/ledger/move.go:145`（ClaimCard） |
| `HeartbeatDriver` 只更新自己持有的那份 | `internal/ledger/tasks.go:118` |
| 唯一生产续租点（B196 加的心跳协程，间隔 2 分钟） | `internal/ledgerstep/runner.go:115` |
| `ReleaseCard` 幂等、只动自己那份；派发失败回滚要连它一起退 | `internal/ledger/move.go:164` 及其注释 |
| **B184 指示器的判据是 watchers，不是心跳**；心跳只用于展示文案 | `cmd/status.go:179-186`（`att.Unattended` 来自 watchers；`heartbeatAgeText` 只进字符串） |
| 今天没有任何 `card release` / `card takeover` 子命令 | `handoff card --help` 全量列表 |

**倒数第二条是对我先前说法的更正**：我在 decision #1 的正文与对话中两次说「TTL 废掉后
B184 的指示器得改读 watchers / 会失去数据来源」。查证后不成立——指示器**本来就**以
watchers 为判据，心跳只出现在「心跳 N 分钟前」这句展示文案里。所以本卡对 B184 的影响
只是**一处措辞**，不是判据重做。改动范围比我先前描述的小。

## 方案

### 采纳：认领保留、过期废除、转移显式

1. **保留首次认领**。`ClaimCard` / `ClaimDriver` 的 CAS 与落 `driver_session` 不动——
   它防的是两个会话同时开工，这个价值成立且与 TTL 无关。
2. **删掉过期判据**。两处 `expired` 计算与 `driverLeaseTTL` 常量一并删除。卡上只要有
   非空 `driver_session`，第二个会话的认领**一律拒**，不看时间。
3. **新增显式接管**。会话真的没了，由人一条命令接管，落事件流可审计。
4. **删掉节点流的心跳协程**（`runner.go` 的 `startDriverHeartbeat` 与相关字段）。
   TTL 没了它就没有理由存在。用户明确要求「等本条落地时一并清」，避免中间态
   ——既不续心跳、又还按 TTL 判过期，那是最坏的组合。
5. **`driver_heartbeat_at` 列保留、语义收窄为「认领时刻」**，只在认领时写一次。
   不改 schema（改列名要迁移，收益只有名字好看）；改的是**展示文案**：
   `心跳 N 分钟前` → `认领于 N 分钟前`。

### 弃选 A：租约由订阅者续（`card wait` 期间续心跳）

弃因：它保住了 TTL，于是也保住了「时间到就换主」这个被裁定为错的语义。而且它把
「有没有人在盯」和「谁拥有这张卡」两件事绑死——订阅断一会儿就丢所有权，比今天更脆。

### 弃选 B：降级为「最后驱动者」，并发保护改由卡状态 CAS 承担

弃因：卡状态 CAS 挡不住同态并发。两个会话都对一张「进行中」的卡发 `--step` 派发时，
状态不变，CAS 无从拒绝——`driver_session` 正是为这个场景引入的。丢掉它等于把已经
解决的问题重新打开。

## 用户故事

1. 作为协调者，我领了一张卡去开会/吃饭/思考半小时，回来时它还是我的——没有任何人
   因为我「超时」而拿走它。
2. 作为协调者，第二个会话试图认领我正在驱动的卡时，它必须干净失败并告诉我是谁在驱动，
   而不是等五分钟后悄悄成功。
3. 作为协调者，一个会话确实没了（机器关了、进程崩了），我要能显式接管那张卡，并且
   这次接管在事件流里留下痕迹——谁、什么时候、从谁手里接的。
4. 作为协调者，我从看板上看到「卡 B2 驱动 cli:xxx」时，我要知道那是**认领时刻**，
   不要被「心跳」这个词误导成「它还活着」。

## 实现决定

1. **接管做成 `handoff card takeover <id>`**，不做成 `claim --force`。理由：`--force`
   容易被顺手加在一条本来会正确失败的命令后面；独立子命令是一次独立的决定。
   落 `driver_takeover` 事件，payload 记 `from`（原驱动）与 `to`（新驱动）。
2. **`takeover` 不设二次确认**。它不破坏数据、可再次接管回去；有事件流留痕已足够。
   （与 `close` 那类破坏性操作区别对待。）
3. **顺带补 `handoff card release <id>`**：本人主动交还，比「找个人接管」更常用，
   且库层 `ReleaseCard` 已存在、只差一个 CLI 入口。
4. **删除 `startDriverHeartbeat` 时一并删掉 `StepRunner` 的 `Heartbeat` / `HeartbeatInterval`
   字段与 `defaultDriverHeartbeatInterval` 常量**，不留「暂时不用但先留着」的死代码。
5. **`ReleaseCard` 保留不动**。派发失败的回滚路径依赖它（见该函数注释记录的 08-19 真机
   事故：只退状态会把卡留在「待办但有主」，驱动身份带 pid，本人换个进程重试都被自己
   的旧租约挡住）。TTL 废除后这条回滚**更重要**了——没有 TTL 兜底，漏退的租约会永久
   卡住那张卡。

## 测试决定（接缝清单）

最高可测缝是 **`Store.ClaimCard` / `Store.ClaimDriver` 的返回值**——所有权判定的唯一
收口点，不需要起 agentd、不需要真派发。

必须覆盖：

1. 已有非空驱动、**且心跳是很久以前**时，另一会话认领**被拒**（这条是本卡的核心行为
   反转，今天它会成功）；
2. 同一会话重复认领仍然放行（幂等，回滚重试路径依赖它）；
3. `release` 后另一会话认领成功；
4. `takeover` 后驱动身份变更且事件流里有 `driver_takeover`，payload 带 from/to；
5. `release` 由非持有者调用是无操作而非报错（保持既有语义）。

第 1 条要**显式构造一个远早于 5 分钟的心跳时间戳**，否则测试会在「TTL 还在但恰好没
超时」的情况下假绿——那正是变异测试要打的点：把删掉的 `expired` 判据加回去，第 1 条
必须变红。

## Out of Scope

- **不改 B184 指示器的判据**。它本来就读 watchers，本卡只改一处展示文案（见现状事实
  的更正条）。
- **不做「驱动会话存活性探测」**。那会把 TTL 换成另一种猜测；裁决的方向是显式，不是
  换一个更聪明的自动判断。
- **不动 task 侧的 executor 存活性结论**（`executor 存活 / 已不在 / 未知` 三态）。
  那是另一条轴，与卡的驱动所有权无关。
- **不改 `driver_heartbeat_at` 的列名**。

## 备注

删掉 TTL 后，「一张卡被永久卡在某个已消失的会话名下」成为一个真实可能。这是**刻意的
取舍**：它可见（看板上能看到驱动是谁）、可解（一条 takeover），而它替换掉的那个失败
模式——两个驱动同时在飞且互不知情——不可见也不可解。
