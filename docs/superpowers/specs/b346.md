# B346 review pass 用已归档的 implement worktree 再 push origin

- **卡**：B346
- **级别**：**L1**。plan 增量为零：已发布则跳过再 push。验收一眼可核：review pass 不再 needs_human。
- **状态**：**已批准**（2026-09-05；B345 真机；用户自主推进）
- **基线**：`origin/main` @ `47fa1642`
- **发现自**：B345 review。不 reopen B341。

## 问题陈述

implement pass 会 `PublishWorkBranch` + `RecordWorkBranchPublished` + 归档 task（B341）。`WorkBranch` 仍指向那次 implement 的 target/task/branch。review pass 再读同一条，对已回收的 implement worktree 跑 `git push origin <工作分支>`，400「工作目录不存在」，卡 needs_human「工作分支未能推到 origin」。

B345 真机：implement 已把 `cards/B345-charter` 推到 origin（`47fa1642`，有 `work_branch_published`）。review 仍去 push `/root/.handoff/worktrees/15aa5f7d`。

账本已有 `Store.WorkBranchPublished`。pass 路径没问它。

弃选：origin 上已有分支就当本次 push 成功（掩盖 B341 时序，冻结禁止）。弃选：review 改推当前 review task 的分支（本期只修「已发布还去推死树」）。

## 方案

`verdict.Pass` 且工作分支非空时，先 `WorkBranchPublished`。已发布：打日志，不调用 `PublishWorkBranch`，不 needs_human。未发布：保持 B341 顺序（先 push 再归档当前 task）。

## 用户故事

1. 作为 charter review：implement 已发布 origin 后，review pass 进下一列，不因死 worktree needs_human。
2. 作为对照：从未发布过的 implement pass 仍会 push。
