# B398 spec：冻结物理身份与路由 target 分字段——派发链不得改写 `Carrier.Machine`

**上游状态：已批准**（用户 2026-09-22 批准；根因与修向同日由用户拍板）
**级别：L2 单子系统**（`internal/agentd` 的节点装配与请求准入 + `internal/ledgerstep` 的派发透传；先例：B396「`internal/ledger` + `cmd`/`agentd` 判据面」、B393「`internal/agentd` + `internal/keystone`」同形）
**入口节点**：debug（根因已定位，见卡上 2026-09-22 更正段）；本节点只出 spec，不动实现
**用户裁决指针**：2026-09-22 用户链路分析——「路由可以用 canonical target，但冻结身份必须保留原始 `Carrier.Machine`，两者不能共用一个字段」；并明确**不得**在 `AdmitFrozen` 回落 registry。

---

## 1. 问题陈述

卡的节点派发要经过两级「目标机」处理：一级是**路由**（选哪个 client、探活谁、跨机判据比谁），一级是**冻结物理身份**（这条任务的载体绑在哪台机器，接收端要拿它跟 registry 核）。今天这两级**共用同一个字段**，于是路由侧的归一把身份快照改写成空串。

链路（对着 `9b7f855b` 逐点核过，行号为现状读数）：

1. `Select` 正确冻结 `cmd.machine=linux-01`（`internal/scheduling` 返回 Binding）；
2. 装配点取用冻结值：`internal/agentd/cardstep.go:175-178`（`if binding.Target != "" { target = binding.Target }`）；
3. **丢值点**：`cardstep.go:186` `resolved, target, err := s.resolveStepDiscipline(node, target)`——该函数内部为探活与选 client 调 `CanonicalTarget` 并回落 `isLocalMachine → ""`，**把归一结果回写覆盖**了冻结值；随后 `cardstep.go:220` 把它塞进 `StepRunner.Target`；
4. `Dispatcher`（`internal/ledgerstep/dispatch.go:169-173`）再次归一（`rawTarget` 只用于日志）；
5. 传给 `stepTransport` 的 `DispatchOpts.Target` 已是 `""`——而 `stepTransport`（`cardstep.go:387-398`）本身是**正确**的：`canonical` 只决定 client 走本机直连，`opts.Carrier != ""` 时 wire 仍用 `opts.Target`；它拿到的却已是空串，救不回；
6. 接收端 `internal/agentd/handlers.go:527-531` 用 `req.Target` 重建 `Binding` 交给 `AdmitFrozen`；`internal/scheduling/scheduling.go:667` 比对 `""` 与登记值 `linux-01`，`samePhysicalMachine`（`:701-708`）只认「两边都 IsLocalMachine」或字符串相等，不认配置里的自机别名 ⇒ `ErrRoleMismatch: 冻结物理身份与载体登记不一致`。

**真机后果**（2026-09-22 19:05:25）：B382 的 plan 轮被这条判据拒发，卡停在计划列无出口（B382 由此搁置）。

**覆盖缺口**：`TestLocalStepTransportKeepsFrozenBindingTarget`（`internal/agentd/cardstep_local_test.go:177`）直测 `stepTransport`，绕过了真正丢值的装配/`ViaTemplate` 路径，所以单跑绿——现有绿灯**证明不了**这条链是对的。

## 2. 级别与档位

**L2 单子系统**：改动落在 `internal/agentd`（装配 + 请求准入）与 `internal/ledgerstep`（派发透传），属同一条派发链的两段，不新增子系统、不新增依赖方向。派发请求 wire 增一个**附加字段**（旧发送方不带 ⇒ 接收端回落到今日行为），与 B393/B396 那条「账本事件/卡字段追加」同族。

## 3. 方案（含弃选与理由）

**采用：把「冻结物理身份」与「路由 target」拆成两个字段，各自走各自的通路。**

- 装配点保留冻结值（来自 `binding.Target`），**不再被归一结果覆盖**；归一后的值只服务于探活与 client 选择（它可以只活在局部变量里）；
- 派发请求带一个**冻结身份字段**，原样透传（`internal/ledgerstep` 只透传、不解析——与既有 `Carrier`/`Squad`/`HomeDir` 的定位一致）；
- 接收端在**有冻结身份**时用它建 `AdmitFrozen` 的 `Binding.Target`；字段缺席（旧发送方）时保持今日行为；
- 路由侧一切照旧：`CanonicalTarget` 继续决定 client、探活、跨机判据。

**弃选与理由**

- **A. 在 `AdmitFrozen` 把空值回落当前 registry**（我此前的错误提案）：会掩盖身份快照丢失——判据从此不再回答「快照里是谁」，只回答「现在登记是谁」，冻结语义被掏空；且失败会从可见的错误变成静默的成功。**用户明确否掉，不做。**
- **B. 放宽 `samePhysicalMachine` 认识配置别名**：同一类问题——让判据去猜，而不是让快照保持完整；今天把 `linux-01` 认成 local，明天就会把另一台别名认错。**不做。**
- **C. 只改 `dispatch.go` 的归一顺序**（把归一挪到更后面）：治不了本——丢值发生在装配点（`cardstep.go:186`）就已完成，`stepTransport` 收到的已是空串。
- **D. 只补测试不改代码**：会产出「测试证明现状是对的」的假象；本卡的根因就是代码把两级语义塞进一个字段。

## 4. 用户故事

1. 作为派发方（装配点），当冻结身份的机器名恰好是本机的别名（如 `linux-01` 在 linux-01 上）时，我送出的派发请求里冻结身份仍是**原名**，路由仍走本机直连。
2. 作为接收端，我拿冻结身份字段与 registry 比对通过；且当请求没有该字段（旧发送方）时，行为与今天完全一致。
3. 作为后来人，我看日志能同时看到「路由 target / canonical target / 冻结身份」三个读数，而今天它们被同一个字段吞成一个。
4. 作为审阅者，我能用一条穿过装配路径（而不是绕过它）的测试证明冻结值不再被改写。

## 5. 实现决定

- **两级语义、两个值**：路由值与冻结值在装配点就分开持有；**归一不得回写冻结值**（本卡的一句话契约）。
- **冻结值来源唯一**：冻结身份的机器名只来自 `binding.Target`（`Select` 的产物），不从 registry 现读、不从路由值反推。
- **透传**：`internal/ledgerstep` 对冻结身份字段只透传，不解析、不归一、不校验——与既有 `Carrier`/`Squad`/`HomeDir` 同一定位（该包注释已声明这条边界）。
- **接收端取舍**：有冻结身份用冻结身份建 Binding；缺席时回落 `req.Target`（旧发送方兼容），且**不改** `AdmitFrozen` 与 `samePhysicalMachine` 的任何判据。
- **可观测**：派发日志同时打「路由 target / canonical target / 冻结身份」三个读数（现状只打前两个且常常同值）。
- **命名**：字段名归 contract/plan 落地（用户可见名字无新增——本卡不改任何命令/配置/文案）。

## 6. 测试决定（接缝清单）

**接缝 1（承重缝）**：装配路径——`internal/agentd/cardstep.go` 中「冻结身份已取得 → 归一路由 → 装配 `StepRunner`/`Dispatcher`」这一段（现状入口 `cardstep.go:175-220`）。
调用方（现状）：卡节点派发入口（`Server` 的 step 处理）。
断言：冻结机器名 ∈ 本机别名表（`CanonicalTarget` 会折成 `""`）时——① 送往 transport 的冻结身份字段 == 原名；② 路由字段 == canonical（`""`）。
**这条必须穿过装配路径**，不得像现状那样直测 `stepTransport`。

**接缝 2**：接收端准入——`internal/agentd/handlers.go` 的 step 请求处理（现状 `:527-531`）→ `AdmitFrozen`。
调用方（现状）：HTTP 路由。（`AdmitFrozen` 的**判据**不动，只换喂给它的值来源。）
断言：① 带冻结字段 → Binding.Target == 冻结值 → 准入通过；② 不带该字段 → 与今日行为逐字一致（回归锁）。

**接缝 3（端到端回归锁）**：本机别名 + 冻结载体的最小派发，用既有 `newLocalStepHTTPHarness` 一类夹具从装配跑到接收准入全绿（现状该场景在最后一步被拒）。

**假缝禁令核对**：三条缝都是导出入口或生产路径上的装配/准入点，都有真实调用方；无「未导出、无生产调用方、只为走满分支」的纯函数占名额。既有 `TestLocalStepTransportKeepsFrozenBindingTarget` 保留（它锁的是 `stepTransport` 的单点语义），但**不顶替**接缝 1。

## 7. Out of Scope

- **不做**：`AdmitFrozen` 判据放松、空值回落 registry、`samePhysicalMachine` 认识配置别名（§3 弃选 A/B，用户已否）。
- **不做**：`CanonicalTarget` 自身语义变更（它继续服务路由；今日行为有测试锁 `TestCanonicalTargetLocalMachineAliases`）。
- **本期不做、后续要做**：存量盘点——还有多少卡的冻结绑定受过同类改写（含 B233.27 同族），值得在实现后用只读取数盘一遍；残余落 roadmap。
- **不做**：本卡不引入「冻结身份」的新来源（如承载记录/registry 快照），只修「已有快照被改写」。
