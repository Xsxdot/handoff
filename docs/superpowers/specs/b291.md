# B291 CI: TestDisciplinesListFromLedgerOnly 多返回 review

状态：**已批准**（用户 2026-08-29「批准 L1，派 linux-01 Codex」）
定级 **L1**（单测夹具隔离；不动生产契约；plan 增量近零；验收一眼可核）
卡：B291
日期：2026-08-29

## 问题陈述

GitHub CI 每次 push 必红：

```
--- FAIL: TestDisciplinesListFromLedgerOnly (0.04s)
    ledgerapi_test.go:1317: names = [charter-implement charter-review review], want [charter-implement charter-review]
```

`GET /api/disciplines`（`handleDisciplineNames` → `ListDisciplineNames`）只应返回账本里当时有的名字。这条测试自己 Put 了 `charter-implement` / `charter-review`，并显式把 `review` / `implement` / `disk-only` 列为退役来源，不得出现。

## 根因

不是生产列表逻辑。`newLedgerEnv`（`internal/agentd/ledgerapi_test.go`）给**每一个**账本测试预置：

```
PutDiscipline(discipline.NameReview, "本机测试审阅纪律")
```

B271「补齐共享 ledger 夹具」（`5d733488ee`，2026-08-28）之后，夹具名 `review` 进了账本，下拉接口如实返回，断言必然红。CI 无本地脏目录，所以每次 push 都红。

生产 `ListDisciplineNames` 只 `SELECT DISTINCT name FROM disciplines`，没有把内置名拼回去。不要改它。

## 方案

公共夹具不再预置 `review`。需要审阅纪律正文的测试自己 `Put`（已有 `seedDisciplineOnLedger`，例如约 1076 行那支）。`newNoPTYLedgerEnv` 若仍给自己的调用方预置，保持局部，不要回流到 `newLedgerEnv`。

弃选：

- 把断言改成接受 `review`：这条测试的牙就是拦退役名混进下拉。
- 在 `handleDisciplineNames` 里过滤内置名：生产没做错，过滤会把账本里真叫 `review` 的角色藏掉。

## 用户故事

协调者 push 之后，`go test ./internal/agentd -run TestDisciplinesListFromLedgerOnly` 绿；需要 `NameReview` 正文的其它测试仍绿。

触及包：`internal/agentd`。全量测试不在本节点。
