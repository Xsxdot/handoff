### 2.1 是否发现新接缝

未发现需要新增的跨子系统接缝。真实穿线只复用既有链路：

`ViaTemplate` → 注入 `Transport`/`stepTransport` → `client.Dispatch` →
`POST /api/tasks` → `dispatchRequest` → `Manager.Dispatch` → `resolveDispatchBase`。

需要特别记录的不是新接缝，而是现有手写投影的完整清单：

1. `internal/ledgerstep/dispatch.go`：`DispatchOpts.LocalBaseBranch` 产生点；
2. `internal/agentd/cardstep.go`：ledgerstep opts → client opts；
3. `internal/client/client.go`：client opts → `map[string]any` 的 `local_base_branch`；
4. `internal/agentd/server.go`：JSON → `dispatchRequest` → `DispatchReq`；
5. `internal/agentd/manager.go`：`DispatchReq` → resolver 参数；
6. `internal/ledger/events.go`：事件 JSON 的 `DispatchSnapshot.Target` → `WorkBranchInfo.Target`。

T2 必须有一条真实 HTTP 穿线回归，不能以 client 单测和 manager 单测的拼接代替；断言
字段存在性时使用可空/显式 key-presence 方式区分「键缺失」与 `false`。

### 2.2 不新增枚举值

本次没有新增状态名、事件类型、purpose、attachment kind 或其它枚举取值。`review` 继续
复用现有 `PurposeReview`，并由 T1 的 ledger 测试确认审阅快照仍被跳过；不存在需要登记

### T1 · 账本/编排起点矩阵（`d_ledger` · 逻辑型）

**①契约引用**

- contract §2.1：`WorkBranchInfo` 与同源 `Target` 语义；
- contract §2.2：`LocalBaseBranch` 的布尔语义与 `ResolveDefaultBase` 互斥；
- contract §2.3：首轮、同机、审阅、跨机四态矩阵；
- contract §8 第 1–3 条：`WorkBranchInfo` 包内归属、Transport 为既有适配缝、目标机比较规则；
- 冻结入口：`internal/ledger/events.go#Store.WorkBranch`、
  `internal/ledgerstep/dispatch.go#Dispatcher.ViaTemplate`。

**②意图与为什么**

让节点重跑、审阅和集成节点都从最近一次非审阅产出继续：只有「工作分支存在且上次
`Target` 与本次目标机精确相等」时，派发起点才使用 `WorkBranchInfo.Branch` 并置
`LocalBaseBranch=true`。首轮仍沿卡有效基线/默认基线；跨机或历史目标缺失在 Transport
之前拒绝，不能静默掉回卡基线。

`Branch` 与 `Target` 必须从同一快照读出；`EffectiveBaseBranch` 继续只服务卡上下文的
合并目标。原有非审阅 `-2` 挂号、审阅 `-review-N` 挂号及 `PurposeReview` 跳过规则
保持不变。这样修的是起点来源，不会把审阅分支、合并目标或节点名称重新变成第二真相源。

**③验收**（逻辑型，机内闭环；以下缺陷族结论均属于本卡验收）

行为化判据：

1. 运行 `go test ./internal/ledger ./internal/ledgerstep -run 'TestWorkBranch|TestViaTemplate' -count=1`，命令返回两个包 `ok`；测试用真实 `RecordDispatch` 事件而非只填返回值。
2. 首轮无非审阅快照时，Transport 捕获到的 `Base` 等于卡有效基线；卡基线为空时
   `LocalBaseBranch=false` 且 `ResolveDefaultBase=true`，不存在默认基线误标为本地分支。
3. 同一目标机第二轮时，Transport 捕获到 `Base=WorkBranchInfo.Branch`、
   `LocalBaseBranch=true`、`ResolveDefaultBase=false`；用一个移动/替换 Target 的反面
   夹具证明 `Branch` 与 `Target` 没有来自不同快照。
4. 审阅轮仍生成 `cards/<卡>-review-N`，起点是工作分支，`WorkBranch` 不把审阅快照
   当成下一次工作分支；同时断言本地标记为真且默认基线标记为假。
5. 上次目标机不同或 `Target==""` 时，Transport 调用次数为零，账本没有新增
   `LinkTask`/`EvDispatched`，错误同时包含「工作分支只存在于创建它的那台机器」、
   `git push` 与显式 `--base` 出口；这条反面断言必须在删除跨机门的变异下变红。
6. `go test ./internal/ledgerstep -run TestViaTemplateSecondRoundGetsNumberedBranch -count=1`
   返回 `ok`，以守住既有分支命名与序列化回读行为。

缺陷族对抗结论：

- **生命周期 / 状态机中断**：跨机拒绝发生在 Transport 前，因此本次新增路径不建
  task、worktree 或孤儿账本事件；这是可由上述零调用/零事件测试闭环的部分。若协调者进程
  在 Transport 成功后、`LinkTask` 前崩溃，仍是既有模板派发的回链窗口，本卡不声称修复；
  节点继续/审阅的真实宿主重启收口列入真机清单，不以单测夹具替代。
- **静默失败 / 误导报错**：跨机不能报成功后从卡基线继续，错误必须同时告诉原因与
  `push + --base` 出口；同机必须把真实工作分支名送入 Transport。T1 不负责 JSON，旧
  agentd 忽略新键的静默降级归 T2 的兼容性真机项。
- **跨平台假设**：本卡只比较账本中的目标机标识字符串，不假定 OS、路径或 webview；
  Git 分支名到本地 ref 的平台行为由 T2 验证。无新增跨平台假设，因为 T1 没有直接
  操作宿主文件系统或进程。
- **假红 / 假绿测试**：每态测试都断言 Transport 的完整 opts、负面调用次数和账本
  事件，且用真实事件 JSON 回放 `Target`；不只断言中途变量。跨机门、同源快照和审阅
  跳过都配反面断言，避免把固定字符串夹具误当行为事实。
- **门禁绕过**：T1 没有新增权限、命令或写路径；跨机门位于既有 Transport 之前，
  不能绕过 agentd 的项目注册、工作区或进程准入。无，因为本卡只裁决账本/编排内存与
  既有账本事件，不改变权限门；T2 仍需复核 direct client 请求不能借本地标记绕过服务端门。
- **序列化边界**：`DispatchSnapshot.Target` 的事件 JSON 是本卡唯一已有手写投影，
  测试必须从 `RecordDispatch` 写入后再由 `WorkBranch` 读回；`LocalBaseBranch` 的
  跨进程 JSON 不在本卡伪造覆盖，交给 T2 的真实 HTTP 回归。
- **枚举新值过既有白名单**：无，因为本卡不引入新枚举；`PurposeReview` 仍走既有
  `WorkBranch` 跳过分支，已有 `review` 逻辑测试即为登记核对。
- **承重安全属性有测试锁住**：工作分支跨机隔离是本卡新增承重属性，T1-5 的
  「Transport 零调用 + 无账本副作用」测试能因移除目标机比较而变红；一次性 token、
  唯一性不在本卡新增，故无，因为本次没有产生或消费这类安全凭据。

### T2 · agentd + client 接缝与本地解析（`d_controlplane` 逻辑型 + `d_remote` 边界型）

**①契约引用**

- contract §2.2：四层 `LocalBaseBranch` 字段、JSON 键与互斥/非空/错误语义；
- contract §1.1：`ResolveBaseBranch` 仍无条件补拉、`FetchTimeout` 不改、旧 agentd
  未知键事实不构成兼容成功；
- contract §5：三条后续接缝测试，尤其 client→server→manager 的真实穿线；
- contract §8 第 2、4、5 条：既有 Transport 适配缝、解析规则归 agentd、旧端版本边界；
- 冻结入口：`internal/agentd/workspace.go#resolveDispatchBase`、
  `internal/agentd/manager.go#Manager.Dispatch`、`internal/agentd/server.go#Server.handleDispatch`、
  `internal/agentd/cardstep.go#Server.stepTransport`、`internal/client/client.go#Client.Dispatch`。

**②意图与为什么**

把 T1 的来源标记完整送过既有 HTTP wire，并让 agentd 对本地工作分支走一个明确的
「只读本地 `refs/heads`、转成 SHA、绝不补拉」路径。互斥、空值、分支缺失都必须在建
task、建 worktree、网络 fetch 之前拒绝；拒绝只返回可行动的 `ErrBadWorkspaceReq`，
不落半成品。

普通 `LocalBaseBranch=false` 的三类既有语义必须同时保住：显式普通分支仍走 D2 无条件
fetch；卡空基线仍由 `ResolveDefaultBase` 解析 `origin/HEAD`；普通 CLI 空 `Base` 仍
沿 `ResolveBaseline` 的 HEAD 语义。T2 不通过改写 `ResolveBaseBranch` 全局语义来实现
本地路径。

`d_remote` 是边界域：机内只验证 JSON 键、DTO 透传、HTTP 状态与请求取消契约；目标机
是否真的持有工作分支、旧 agentd 如何处理未知键、fetch 是否接触真实网络，都不由夹具
推断为已验证。

**③验收**（逻辑/边界分流；缺陷族结论均属于本卡验收）

逻辑闭环与契约形状：

1. 实现后运行 `go test ./internal/agentd ./internal/client -run '^(TestResolveDispatchBaseLocalBranchUsesLocalRef|TestResolveDispatchBaseLocalBranchMissingRejects|TestDispatchRejectsLocalBaseBranchInvariant|TestDispatchWireLocalBaseBranchEndToEnd|TestDispatchNormalBaseSemanticsUnchanged|TestDispatchSerializesLocalBaseBranchMarker)$' -count=1`；这些测试名必须真实存在，命令输出不能是 `no tests to run`，且两个包均返回 `ok`。
2. 真 Git 夹具中建立 `refs/heads/work`，把 origin URL 指向不存在位置，调用
   `resolveDispatchBase(ctx, repo, "work", true)` 得到本地分支 SHA、`fetched=false`、
   `err=nil`；若调用仍经 `ResolveBaseBranch`，该测试必须因不可达 origin 变红。
3. 本地 `refs/heads/missing` 不存在时，resolver 返回 `errors.Is(err, ErrBadWorkspaceReq)`；
   错误同时包含「工作分支只存在于创建它的那台机器」和「先 push 到 origin，再用显式
   `--base` 指定」，并断言没有 fetch、task、worktree 或 ledger 记录。
4. `LocalBaseBranch=true && ResolveDefaultBase=true` 与 `LocalBaseBranch=true && Base==""`
   各有一条 manager/HTTP 拒绝测试：返回 400/`ErrBadWorkspaceReq`，且任务表与 managed
   worktree 数量均未增加。manager 的本地标记互斥/空值门必须排在
   `ResolveDefaultBase` 与 `ResolveBaseline` 之前；不能等到 `PrepareWorkspace`、网络 fetch
   或 executor 启动后才报错。
5. `LocalBaseBranch=false` 的普通分支回归：D2 仍 `fetched=true` 并取远端尖端；卡空基线
   的 `ResolveDefaultBase` 仍取 `origin/HEAD`；无该标记的普通空 Base 仍从本地 HEAD 开。
   每条既有测试命令返回 `ok`，且不把新标记误带到普通请求。
6. 通过真实 `httptest` HTTP 链路调用 `client.Client.Dispatch`，请求体用可空布尔/键存在
   性断言 `local_base_branch=true`、`resolve_default_base=false`；server 解码、manager
   接收并最终走本地 resolver。这个测试必须经过 `client.go` map、`server.go` DTO 与
   `handleDispatch` 映射，不能直接调用 manager 造出 `DispatchReq`。
7. 对第 3/4 条的拒绝经 HTTP 返回 400，响应体保留上述可行动原文；没有把
   `ErrBadWorkspaceReq` 扁平成「派发任务失败」，没有成功 task ID。

边界域真机分流：真实目标机行为只进下方真机清单；T2 不自派基础设施、不把手写 mock
   当成对端事实。

缺陷族对抗结论：

- **生命周期 / 状态机中断**：所有本地标记的参数/分支缺失拒绝必须早于 task、worktree、
  executor 和网络副作用；manager 现有 `PrepareWorkspace` 后错误的补偿路径继续负责
  已建 managed tree。agentd 在 resolver 前后重启、executor 已启动后宿主重启的孤儿
  回收事实不是机内 API 可证明项，标「未验证，需真机」并由协调者执行；不把 fake adapter
  的正常返回写成真实收尾结论。
- **静默失败 / 误导报错**：新键到达新 agentd 后必须按本地-only 语义消费；缺失/互斥
  要 400 且给出口，不能报 200 后按 HEAD 或远端旧分支继续。旧 agentd 会静默忽略未知
  键，这是已知的误导窗口：本期不宣称兼容成功，协调者必须在真机确认目标端版本；若要求
  安全兼容，P3 触发 contract 退回。
- **跨平台假设**：`refs/heads/<Base>` 是 Git ref，不把用户路径直接拼进 shell；
  resolver 返回 SHA 后再交给既有工作区准备，避免 Windows/Linux 分支名差异污染
  `PrepareWorkspace`。Windows、不同 shell、真实权限/网络代理对 fetch 与 worktree 的
  行为仍是边界事实，列真机清单；无，因为 T2 不新增 OS 专用实现。
- **假红 / 假绿测试**：解析测试必须把 origin 设为不可用并断言 `fetched=false`，否则
  即使误走 fetch 也可能因本地 ref 先命中而假绿；HTTP 测试必须穿真实序列化边界，并
  同时覆盖键缺失与 `false`，不能只断言 `true`。拒绝测试必须检查 task/worktree 数量
  不变；负面断言删除后应变红。
- **门禁绕过**：`POST /api/tasks` 仍走现有鉴权、项目登记、工作目录占用、进程余量和
  executor 纪律门；LocalBaseBranch 不是权限开关，不新增一条绕过 direct client 的路径。
  resolver 先把本地 ref 固定解析成 SHA，再把同一 SHA 交给 `PrepareWorkspace`，因此
  ref 移动不会把检查到的名字重新解析成另一尖端；这一点应由“移动 ref 后起点仍为已解
  析 SHA”的测试锁住。无，因为本次不改权限规则；但若实现把本地分支直接交给 git
  DWIM，属于门/TOCTOU 回归，验收应拒绝。
- **序列化边界**：本卡必须覆盖 `cardstep.go` 的 opts 投影、`client.go` 的 map 键、
  `server.go` 的 JSON DTO 与 manager 映射，并用一条真实 HTTP 回归穿过全链。使用
  `map[string]*bool` 或显式 `value, ok` 区分键缺失与 `false`；两端各自绿不算这条链路绿。
- **枚举新值过既有白名单**：无，因为 `LocalBaseBranch` 是布尔字段，不新增 enum/kind/
  purpose/state。`PurposeReview` 只在 T1 复用；T2 不添加新的 switch 或白名单分支。
- **承重安全属性有测试锁住**：本地起点隔离与“拒绝缺失分支不留副作用”是本卡新增
  属性，测试 2/3/4/6 在删除 local-only 分支、绕过互斥或延后校验时能变红；一次性
  token、唯一性不在本卡产生，故无，因为本次 wire 字段不承载安全凭据。

## 4. 真机清单（未验证，需真机；归协调者执行）

以下条目不能由仓内夹具证明；在实现与 review 通过后由协调者选择已登记目标机执行，
不要把“测试夹具中 fake 的行为”写成完成结论。

1. **同机接续与审阅**：在同一台目标机上实际完成一次非审阅节点后，再派同一张卡的
   implement 重跑与 review；确认新节点工作树的起点是上一轮工作分支尖端，review 返回
   200/成功且不再出现「基线分支从 origin 补拉失败」；检查 `git rev-parse HEAD` 与上轮
   工作分支尖端一致。
2. **跨机拒发**：先在目标机 A 产生工作分支，再把下一节点指定到不同的已登记目标机 B；
   预期在派发前收到包含创建机原因、`git push` 与显式 `--base` 出口的拒绝，不在 B 创建
   task/worktree，也不静默回卡基线。目标机 A/B 由协调者按现有登记选择，不在本稿假定名字。
3. **旧版 agentd 版本边界**：对一个明确未包含 `local_base_branch` 消费逻辑的旧版
   agentd 实际发请求，记录它是否静默忽略该键；该结果只能用于确认“不可把旧端当兼容
   成功”，不得据此放行本功能。若产品要求旧端安全拒绝/协商，P3 退回 contract。
4. **宿主中断与孤儿回收**：在本地分支解析、worktree 创建前后及 executor 已启动的
   时间窗分别重启/终止目标 agentd，确认既有任务状态、worktree 与进程回收责任符合
   agentd 生命周期文档；本卡新增的硬要求是拒绝路径不留 task/worktree，重启后的真实
   行为仍未验证，不能用单测替代。
5. **跨平台/真实 Git**：至少在协调者可用的非当前开发平台目标机复验本地 Git ref、
   worktree 起点、Windows/Linux 路径与权限差异；确认 local-only 路径不出网，普通分支
   路径仍按既有规则 fetch。行为事实在执行前均标为“未验证，需真机”。
