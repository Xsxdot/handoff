来源：合线 `d9b0228d` 复审 P1「载体机器仍不决定实际执行机器」；用户确认本机身份用 `CanonicalTarget`，不用单独的 `IsLocalMachine`

本节点该干什么一律以注入的纪律块为准。

## 定级理由

只改 gateway 收到派发请求之后、真正开工之前的一道门。不改编制准入契约、不改编排、不新协议。实现决定三行写完，httptest 一眼可核 → **L1**。

## 问题陈述

谁：打到某台机器上的 agentd。

条件（`977720e2c`）：冻结准入只核对「请求里的机器名 / 执行器 / HOME」和「载体登记」是不是同一套（`internal/scheduling/scheduling.go#Service.AdmitFrozen`）。核对通过后，HTTP 处理函数立刻在**本进程**里调用编排开工（`internal/agentd/handlers.go#Server.handleDispatch`）。没有「我这个进程是不是登记的那台机」这一步。

结果：把「登记在 linux-01」的请求打到另一台机器的 agentd 上，只要请求字段抄对了，任务会在错误的那台机器上跑起来，任务记录上的机器名却仍写 linux-01。

要变的事实：本进程发现「这个请求要去的机器不是我」→ **拒绝**，不开工、不转发。调用方应把请求打到登记的那台 agentd。

谁能观察到：打错机器时 HTTP 非 2xx，错误正文能看出登记机；本机别名和配置里指向自己的名字（如 `linux-01` 的地址就是本进程）照常成功。用户点的命令名、URL 不变。

## 现状事实（contract/plan 对本轮工作树复核）

| 事实 | 出处 |
|---|---|
| 冻结准入只核请求 vs 登记 | `internal/scheduling/scheduling.go#Service.AdmitFrozen` 约 `:668` |
| 通过后本机开工 | `internal/agentd/handlers.go#Server.handleDispatch` 约 `:608` |
| `IsLocalMachine("linux-01")` 为假 | `internal/scheduling/status_test.go#TestIsLocalMachine` `:221` |
| 现网登记名常是 targets 键 | `internal/agentd/coordinator_pty.go` `:50-54` 注释 |
| 本机身份 = 别名或配置指向自己 | `internal/agentd/server.go#Server.IsSelfTarget` `:420`；`#Server.CanonicalTarget` `:436`（空串=本机） |
| 编制参数类错误现为 400 | `internal/agentd/handlers.go#Server.writeDispatchError` 对 `scheduling.ErrRoleMismatch` 等 `:686-690` |

## 方案

**做：** 准入（冻结 `AdmitFrozen` 或普通选路）成功之后、`Dispatch` 之前，看 `binding.Target`。`CanonicalTarget` 不是空串 → 这不是本机 → 返回 400，错误正文写清登记机；**不调用** `Dispatch`。

**弃选：**

- 只用 `IsLocalMachine`：会把打到正确机器、只是登记名叫 `linux-01` 的请求打死。用户已否。
- 在本机帮转发到登记机再开工：占用计数和进程生命周期会落在「不是载体」的那台机器上。用户已否。
- 改 `AdmitFrozen` 契约：那条缝已经冻成「请求 vs 登记」。本卡只补「接收进程 vs 登记机」，不动编制契约。

## 用户故事

1. 冻结请求的 `target` 与载体登记一致，但打到另一台 agentd：400，任务未创建，编排开工函数未被调用。
2. 普通派发选到的载体机器不是本机：同一拒绝。
3. 本机别名（空 / `local` / `本机` / hostname）或配置里地址指向本进程的名字：准入通过后照常开工。

## 实现决定（L1，即 plan）

1. 闸加在 `handleDispatch`：准入成功之后、`mgr.Dispatch` 之前；判据 `CanonicalTarget(binding.Target) != ""`。
2. HTTP 400；错误正文含登记机名。哨兵用 gateway 侧 `errReceiverNotCarrierMachine`（不复用 `scheduling.ErrRoleMismatch`），`writeDispatchError` 映射 400。
3. 冻结与普通派发走同一闸。不改 `AdmitFrozen` 签名与物理比对规则。

## 测试决定

一条缝：`Server.handleDispatch`（HTTP 生产调用方：`POST /api/tasks` 路由）。

- 反面：httptest 打 `target=linux-01`，载体登记也是 linux-01，本机配置不把 linux-01 当自己 → 400，假编排对象的开工方法调用次数为 0。
- 正面：本机别名或 `IsSelfTarget` 命中 → 能进到开工（可用既有派发测试，不重复铺一条全路径）。

假缝禁令：不抽未导出的纯函数占缝。
