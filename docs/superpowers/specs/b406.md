# B406 spec：会话面 401 渲染假读数——过期终止态必须有可见错误面

## 背景

用户现场（2026-09-24）：会话页明明有消息，打开一直显示"无消息"。当晚报文记录的故障窗口疑团（查询被阻塞/连接不可用）已由 B409（全账本读路径限域 + U6 诊断闭环 + 双机部署）覆盖；本卡只修取证钉死、与当晚根因无关也无条件成立的**代码级缺陷**：401 家族在会话面的渲染假读数。

## 根因（已确证，file:line）

`usePoll` 遇 401 落 `sessionExpired` 终止态并停表（`web/src/app/data/usePoll.ts:75-79`）——该语义合理，**保留不动**。缺陷全在消费端只认 `disconnected` 不认 `sessionExpired`：

1. `web/src/app/rooms/SessionTab.tsx:108`：`historyError` 只在 `disconnected` 时传给 SessionChat → 401 时 SessionChat 对过期一无所知；`:119` 详情抽屉 401 时永远渲染"正在读取…"。
2. `web/src/app/rooms/SessionChat.tsx:208`：`events.length === 0` 无条件渲染"（还没有消息）"→ 401 时 data 恒 null、events 空 → 假读数"还没有消息"，无错误提示、永不重试。
3. `web/src/app/shell/Shell.tsx:841-842` 与 `:999-1000`（桌面侧栏与移动端两处 SessionSidebar）：`loading={data===null && !disconnected}` → 401 时永远转圈。
4. `web/src/app/rooms/SessionSidebar.tsx:66-67`：`!loading && visible.length===0` 渲染"（暂无会话）"→ 若只收紧 loading，401 时会掉进这个同族假读数，必须一并处理。

现有资产：`SessionExpiredBanner`（`web/src/app/lib/Banners.tsx`）已是会话失效终止态的标准呈现（board/settings 页在用，文案含 cookie 兑换指引），会话面未接线。

## 方案

- **SessionChat**：新增 `historyExpired: boolean` prop。expired 时消息区渲染 `SessionExpiredBanner`（复用现成组件），不渲染"（还没有消息）"；footer 不显示"消息流已断开"（那是断线语义，不与过期混用）。
- **SessionTab**：`historyPoll.sessionExpired` 接进 `historyExpired`；详情抽屉 expired 时渲染过期提示（SessionExpiredBanner），不再"正在读取…"。
- **SessionSidebar**：新增可选 `expired?: boolean` prop。expired 时渲染 `SessionExpiredBanner`（替代断线行与空态），`loading` 与"（暂无会话）"空态都被 expired 抑制。
- **Shell** 两处 SessionSidebar 调用点：`loading` 收紧为 `data===null && !disconnected && !sessionExpired`，并把 `sessionsState.sessionExpired` 传给新 prop。
- usePoll、api 层、agentd 端点零改动。

## 验收（红→绿）

1. SessionTab.test.tsx 新增 401 场景：`fetchRoomMessages` mockRejected `ApiError`（status 401）→ 断言不出现"还没有消息"、出现"会话已失效"文案（先红后绿）。
2. SessionSidebar（或 Shell 层）401 场景：不出现"暂无会话"、不再永转圈、过期横幅可见。
3. 全量回归：`npm test -- --run`、`npm run typecheck`、`npm run build` 全绿。
