## 方案

隔离实例参数（两侧同构，端口错开）：

- 二进制：从功能线 `b1873d4c` 编译的 `handoff`/`agentd`
- DataDir：本机 `~/.handoff-b2339`，linux-01 `/tmp/handoff-b2339`
- 端口：本机 `7788`，linux-01 `7789`
- 仓库：独立 clone，不指向生产 DataDir 的 worktrees
- 配置：自带 config.yaml，targets 只含这两台隔离实例
- 生产 7777 的 pid 与 `~/.handoff` 前后对照，必须一致

验证项：

1. **共享派发**：本机隔离 CLI `dispatch --target linux-01-iso --new-worktree` 能在 linux-01 隔离 agentd 上建出 running 任务；`wait`/`show`/`done` 走通。
2. **B351 孤儿**：Transport 成功后本地挂账失败（写闸或注入冲突）时，远端任务被 Stop，managed worktree 被 force Reclaim；同卡同 purpose 重试分支名为 `-2`，不要求删旧分支。
3. **B233.8 组装**：隔离实例上 OpenCode（若本机/linux-01 有二进制）派发注入 ApprovalClient 不 panic；若无 OpenCode，用现有单测真 HTTP 对隔离 agentd 打 Stop/Reclaim 作为传输腿，并在证据里写明「无 OpenCode 真 harness」。

**弃选**：复用生产 agentd；ssh 进生产 DataDir；在本卡修功能代码。
