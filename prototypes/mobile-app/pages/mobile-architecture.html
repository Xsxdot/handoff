移动端方案一图流

2026-09-13 · 对应 spec docs/superpowers/specs/2026-09-13-mobile-app-design.md(待批准)

一句话:手机上装一个很薄的 App,里面是一个 webview;webview 显示的页面和你电脑浏览器里打开的控制台是同一份——区别只在于,这份页面是手机先问「手机里的 Go 模块」要,Go 模块再穿过一条加密隧道,从执行机的 agentd 那儿取回来的。

你在 4G/咖啡馆 Wi-Fi 下打开 App —— 数据从左到右走一个来回。整条路上只有 relay 那一段出手机,而它全程是密文。

响应沿同一条路流回手机。今天 CLI 走的就是 Go 连接核 → relay → agentd 这一段(协调机远程派发形态,已上线); 移动端唯一新的事情,是把这一段从「你电脑上的 CLI」搬进「手机里的 Go 模块」,再在头顶加一个 webview。

Q:webview 地址栏里到底是什么?

http://127.0.0.1:端口/ —— 手机自己的回环地址,壳里的 Go 核在那儿起监听。
页面内容不是 relay 供的(relay 只搬字节,不供任何页面),也不是打包进壳的——是 agentd 供的,而且前端资产编译进 agentd 二进制(发布构建带 embedweb tag)。所以 agentd 一升级,所有端的页面一起新,壳永不更新。
为什么不直接填 agentd 的地址?relay 形态下根本没有可直连的地址;统一回环源后,relay/LAN 两种形态对页面和 cookie 完全同构。

Q:relay 的 host 去哪找?

从配对 QR 里来,手机永远不用发现或输入。
relay 地址(wss://你的VPS/relay)在你当初按 README 配 relay 时就写在电脑的 handoff 配置里;handoff console --qr 打包 bundle 时把它装进去。
没有「默认 relay host」——项目不运营公共 relay(无中心哲学)。你的 relay 就是你自己的 VPS;没配 relay,外出形态就不存在,手机只剩 LAN 直连。
Q:所以 App 里装的是一个 Go?一个 agentd?它算另一台协调机吗?
带 Go,对——仓库里现成的几个 Go 包(relay 拨号、HTTP 反代、会话存取)经 gomobile 编成一个库塞进壳,不是通用 Go 环境。
是 agentd,错——agentd 管任务、拉起执行器、托管 PTY、供页面、落账本,这些事手机里一样都没有;App 只带客户端那一小半:拨隧道 + 回环反代 + 存凭据。
算另一台协调机,也不算——它在「协调者 vs 执行者」模型里站在协调者一侧,但它不是一台「机」:不持有账本、不存配置、不发起派发,每个动作都只是 API 调用、由 agentd 落账。它的正确定位是桌面端控制台的孪生兄弟(桌面端 = wails 壳 + Go + webview;手机 = Swift/Kotlin 壳 + Go + webview)。「第二台协调机」在 roadmap 上是推迟项(B156.1 双协调机对等),本方案不复活它——手机丢了是丢一台客户端,不是丢半个协调权。

②relay 到底是怎么连上的(拆开看)

最常见的误会先拆掉:手机不去 relay「登录」、relay 也不发任何钥匙。钥匙只在你自己的设备之间经 QR 拷贝;relay 对这次拷贝全程无感。

⚠ 不是这个模型:手机 → relay 登录 → relay 发 token → 手机凭 token 连机器
relay 没有账号体系,它谁也不认识,也没有什么可发。如果 relay 能发钥匙,它就成了「能授权访问你所有机器」的信任锚——谁攻破 relay 谁就能给自己发一把,整个设计最值钱的那条性质(下面第 4 步)当场死亡。 所以配对不走网络、不找 relay:是从你自己的电脑,把钥匙经 QR 物理拷到手机。
钥匙都住在哪(四种,两种 relay 永远碰不到)
钥匙 干什么用 relay 持有? agentd 持有? 电脑 CLI 持有? 手机(扫码后)?
管道 credential 挂上 relay / 经 relay 找机器——只证明「我有资格用这根管道」 ✅(它只认识这个) ✅ ✅ ✅(QR 拷入)
node token(每台机器一把) Noise 握手的密钥源——「你凭什么连这台机器」的全部证明 ❌ 永远没有 ✅ ✅ ✅(QR 拷入,存 Keychain)
一次性 ticket 找 agentd 换登录会话(cookie),用完即弃 ❌ ✅(它签发) ✅(代领) ✅(QR 拷入)
登录 cookie 之后每次 HTTP/WS 请求的会话凭据,可吊销 ❌ ✅(它校验) — ✅(ticket 换来)
步 谁 → 谁 干什么 用什么凭据
1 agentd → relay 注册「我是 linux-01」,并一直保持这条长连接(断了自动重连)。执行机主动拨出来,所以它在 NAT 后无所谓。 管道 credential
2 手机 Go 核 → relay 「我要找 linux-01」。手机也只出站,4G/咖啡馆 Wi-Fi 都行。注意:这一步 relay 只是传话,不是审批——它无权决定你能不能连。 管道 credential + 节点名
3 relay 配对两头 给这次「找」开一条字节流,之后 relay 只搬字节,不理解内容。 —
4 手机 ⇄ agentd(在流里) Noise 握手:双方各自用「node token + 账号 + 节点名」导出同一把会话密钥,对上才通。「你有权连这台机器」的证明在这一步现场算出来,不是任何人发的票。 node token
relay 没有 → 它冒充不了手机,也读不了内容
5 加密流之上 yamux 多路复用:一条物理连接里并发多条流——页面请求、事件推送、终端 PTY 各占一条,互不堵。 —
6 — 此后就是普通 HTTP/WS:/console 页面、/api、/ws 事件,和桌面端同一套。 ticket → cookie 会话
这套流程今天就在跑:CLI 远程派发走的就是第 2~6 步(只是第 2 步的发起者是你电脑,不是手机)。
那「连一台机器不就够了」吗?——状态层是的,动作层按需
执行机之间不是网状互联:是各机把任务事件镜像到协调机的账本里。所以——
· 状态层(会话列表 / 需要你 / 卡动态):连协调机一台就够,账本上已汇总了全部机器。这条连接常挂着。
· 动作层(开 linux-01 的终端、看它的任务现场、读它的文件):按需经 relay 拨到那台。跨机 REST/WS 转发面其实是存量(桌面控制台经协调机 ?machine= 取数在用),但手机不押给协调机中转——但不用逐台扫码:
· 一次扫码配全部(bundle):QR 里装 relay 地址 + credential + 每台机器的 node/token + 各机一张 ticket(协调机配置里本来就全有)。扫一次,所有机器到位;用哪台连哪台。
· 被砍的替代:枢纽机转发(手机只连协调机、由它代理)——转发面虽是存量,但把手机的一切远程可达性押给协调机在线:笔记本一合盖,所有远程机跟着失联,尽管它们自己活着;逐机直连则合盖无感。不取。

⑤这期到底要造什么:六件新的,其余全是复用

「App」听起来很大,拆开看:协议、加密、页面、鉴权全都已经在仓库里跑着,新活集中在壳和形态。

新建本项目的活

  • iOS 壳 Swift,只有 webview + 扫码 + 安全存储
  • Android 壳 Kotlin,同上
  • Go 核打包 gomobile 把现有 Go 代码编成 AAR/XCFramework
  • 配对载体 + QR 扩展已设计未实现的 console --qr
  • web UI 响应式 手机竖屏 / 折叠展开 / pad 断点谱系
  • 移动终端输入层 Esc/Ctrl/Tab/方向键条 + 输入法组合

存量零改动复用

  • relay 隧道 Noise E2E + yamux,已上线(远程派发在跑)
  • agentd 与 /console 页面、API、WebSocket 原样
  • web UI 本身 同一份代码,桌面/手机永不漂移
  • ticket → cookie 鉴权 当初就是为手机设计的
  • 会话吊销 handoff sessions revoke 管手机丢失
  • relay 服务器 哑管道,不碰它

⑥这样设计换来的四条性质

🔒 加密一路到手机
E2E 隧道终点在手机的 Go 核里,不在任何中间机器。relay(你的 VPS)全程只见密文——这是密钥位置决定的硬属性,不是运维承诺。
📄 UI 永远只有一份
手机看到的页面就是桌面那份,agentd 升级即全端升级。不会出现「手机版落后于桌面版」。
🤏 壳薄到没有协议
Swift/Kotlin 代码只管窗口、扫码、存凭据;讲协议的代码一行都不重写——重写协议才是这类项目真正烧钱的地方。
🔔 通知随时能长出来
一期你主动打开 App 才看到「等待审批」;壳里预留了推送注册位,以后接 APNs/FCM 不用推翻任何东西(已记 roadmap)。

⑦路过但不走的两条路

云端网关(手机浏览器直接开网页):能免安装,但得有个服务器替你终结 HTTPS 再转发——明文落在那台机器上,且与「要 App」的决定冲突。→ 砍,未来若要「免安装」再单独立项。
浏览器里重新实现隧道协议(JS/WASM):浏览器说不出 Noise/yamux,得把整套加密协议移植进网页;而「谁下发这份加密代码,谁就能动手脚」——等于信任锚又绕回服务器,白烧一份协议实现。→ 砍。
