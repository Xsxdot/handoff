图 3升级三档（协调者什么时候必须开口）

判据写死，不由频率兜底；「每轮都 @」是反模式——那等于协调者没有实权。

档什么情况谁拍 / 谁醒
填补级
不出声		 spec 没覆盖的实现选择；顺手小修；发现的新问题落新卡；测试策略微调 协调者自己拍，落进卡的账。一个 @ 都不发。
推翻级
@ 主 agent		 实测证伪了 spec 的商定；要动范围 / 验收判据 / 契约语义；超轮僵局；不可逆动作的提案 停卡（在飞的那轮跑完，不推进下一节点），发一条带「商定 vs 实测 / 影响半径 / 选项与推荐 / 停在哪」的简报，只唤醒主 agent。
人工门
@ 人		 spec 批准；验收结论确认；合 main 协调者把机械证据摆好，结论由人点；主 agent 也可以把「自己拍不了」的往上 @ 人。
推 vs 拉：推只发生在上面三类时刻；拉随时可行——主 agent 定时巡场看有没有跑偏（会话列表标签 → 详情页任务节点 / timeline → 卡抽屉）， 它不需要被每个动作叫醒。人看的是「需要你」标签与收口摘要，不是节点流水。

席位权威在卡上：(cli, session_id) + 来源（我来坐 / 叫机器人）。会话里的「人」是投影，不是第二份真相。
